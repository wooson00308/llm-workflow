# TASK-S076-02 개발 보고서

## 결정권자 요약

기획서 검토 화면의 결정 보드에서 현재와 변경 후와 비용과 위험 세 항목의 글이 제안과 같은 15픽셀,
같은 행간으로 그려진다. 비용과 위험 상자는 원문 보기 본문과 같은 620픽셀 안에서 왼쪽에 붙고
오른쪽에 빈 자리가 남는다. 앱이 실제로 쓰는 웹킷 화면에서 재니 바꾸기 전 세 항목은 12픽셀이었고
비용과 위험의 글 폭이 680픽셀이었는데, 바꾼 뒤에는 네 항목이 모두 15픽셀이고 그 상자의 글 폭이
590픽셀이 되었다. 접기와 더 보기와 말줄임은 어디에도 생기지 않았고 네 항목의 글이 끝까지 보인다.
좁은 화면에서 한 열로 쌓이는 동작과 원문 보기 토글은 그대로이며, 옛 일곱 제목 규격으로 쓰인
SPEC-057도 같은 모양으로 열리고 요약 절이 없는 SPEC-012는 지금처럼 문서 전문으로 열린다. 시험
582건과 타입 검사와 생산 빌드가 격리 사본과 통합 커밋에서 모두 통과했다. 이 결과는 GROUP-076의
사용자 확인 가운데 글자 크기와 줄 길이와 접힘 없음과 좁은 화면 항목을 뒷받침한다.

## 바꾼 파일과 모듈

- `src/App.css` — 두 곳이다. 514행 `.decision-summary-risk`에 `max-width: 620px`과
  `justify-self: start`를 더했고, 515행 다음에 규칙 하나를 새로 더했다. 새 규칙의 선택자는
  `.decision-summary-before .markdown-body p`, `.decision-summary-after .markdown-body p`,
  `.decision-summary-risk .markdown-body p` 셋을 묶고 선언은 `font-size: 15px`과
  `line-height: 1.65` 둘뿐이다. 색 선언은 담지 않아 세 상자의 글자 색은 520행 기본값 그대로다.
  505행 제안 문단 선언, 497행 보드 폭, 507행 좌우 배치, 1287행 좁은 화면 규칙은 손대지 않았다.
- `src/features/projects/components/decisionSummaryBoardLayout.test.ts` — 검사 세 건을 새 서술
  묶음으로 더했다. 기존 검사 셋과 4행의 판독기는 한 줄도 고치지 않았다. 첫째는 새 규칙의 크기와
  행간을 제안 문단 선언에서 읽은 값과 맞춰 보고, 둘째는 비용과 위험의 최대 폭을 `.markdown-body`
  선언의 값과 맞춰 본 뒤 왼쪽 정렬을 확인하며, 셋째는 보드와 네 자리에 줄 수 상한과 높이 상한과
  말줄임 선언이 없음을 확인한다.

기존 판독기는 선택자를 정규식으로 만들어 첫 일치를 잡는다. `.markdown-body`를 그대로 넘기면 501행
`.decision-summary-board .markdown-body`가 먼저 걸려 읽기 폭 해제값을 읽으므로, 선택자 앞에 줄바꿈을
붙여 줄 머리에 선 516행 규칙을 집었다. 판독기 자체는 바꾸지 않았고 그 이유를 검사 옆 주석에 적었다.

## 검증 단계와 결과

- 격리 사본에서 `npm run check` 통과. 시험 582건 통과·42건 건너뜀, 타입 검사와 생산 빌드 정상.
  대상 시험 세 파일만 따로 돌린 결과도 21건 전부 통과다(C1, C2, C3, C4, C9).
- `DocumentReader.test.tsx`와 `DecisionSummaryBoard.test.tsx`를 고치지 않은 채 통과시켰다. 두 파일이
  원문 보기 토글과 요약 절 폴백과 값 배치를 확인하므로 여기서 C5와 C7이 확인된다.
- 웹킷 실측. 앱과 같은 3열 배치 안에 실제 스타일 파일과 SPEC-071의 요약 네 값을 넣어 그리고,
  macOS 웹뷰에서 계산값을 읽었다. 1728픽셀 창에서 바꾸기 전은 제안 15픽셀·나머지 셋 12픽셀,
  비용과 위험 상자 710픽셀·글 폭 680픽셀이었다. 바꾼 뒤에는 네 항목이 모두 15픽셀·행간 24.75픽셀,
  상자 620픽셀·글 폭 590픽셀이고 상자의 왼쪽 끝이 현재 상자와 같은 512픽셀이라 오른쪽에 90픽셀이
  남는다(C1, C2, C3). 2200픽셀 창에서 보드가 상한 860픽셀에 닿아도 상자는 620픽셀 그대로다.
- 같은 실측에서 네 자리의 줄 수 상한과 말줄임 속성이 모두 없음, 보드와 상자의 넘침 없음, 보드 안
  버튼 0개, 화면에 말줄임표 없음을 확인했다(C4). 640픽셀 창에서는 전후 열이 한 열로 쌓이고 화살표가
  90도 돌며, 그 상태에서도 네 항목이 15픽셀이고 잘리지 않는다(C6).
- 옛 일곱 제목 규격인 SPEC-057을 같은 방식으로 그려 네 항목이 모두 15픽셀, 상자 620픽셀임을
  확인했다. SPEC-012에는 요약 절 제목이 없어 보드 없이 문서 전문으로 열린다(C7).
- 통합. 격리 사본의 변경 커밋 c8efb8b는 기준 46d41c4에서 출발했는데 통합 직전 공유 기준이
  726f86d로 옮겨져 있어, 그 커밋 위로 옮긴 뒤(5d4f4ca) 격리 검사를 다시 돌려 통과시켰다.
  `.workflow` 밖에 수정된 추적 파일이 없어 충돌 없이 빨리 감기로 통합했고, 통합 커밋에서
  `npm run check`를 다시 돌려 같은 결과를 얻었다.
- 변경 파일은 `git diff --name-only 726f86d..5d4f4ca` 기준 선언한 두 파일뿐이다. 기획서와 작업
  문서는 한 건도 바뀌지 않았다(C8).

## 남은 위험

- 웹킷 실측은 앱 실행 파일이 아니라 같은 스타일 파일과 같은 DOM 구조를 웹뷰에 올려 잰 것이다.
  조판 값은 이 방식으로 충분히 잡히지만, 앱 창에서 사용자가 직접 보는 확인은 GROUP-076의 사용자
  확인 절차가 맡는다.
- 글자가 커져 같은 글의 줄 수가 늘었다. 실측에서 현재 상자가 9줄에서 11줄, 비용과 위험이 4줄에서
  6줄이 되었다. 보드를 담은 종이 영역은 최대 높이 570픽셀과 기존 스크롤을 그대로 두었으므로,
  요약이 긴 문서는 지금보다 더 스크롤된다. 분량 상한은 TASK-S076-01이 맡는다.
- 새 규칙은 문단만 대상으로 한다. 앞으로 요약 값에 목록이 실리면 그 목록은 12픽셀로 남는다. 지금
  저장소의 문서에는 그런 값이 없어 작업 문서가 범위 밖으로 둔 그대로 두었다.
