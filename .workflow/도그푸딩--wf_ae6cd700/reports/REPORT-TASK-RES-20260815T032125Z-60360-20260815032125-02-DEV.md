## 변경한 파일과 모듈

`src-tauri/src/infrastructure/reservation_helper.rs` 한 파일만 고쳤다. 태스크가 선언한 범위와 같다.

- `RESERVATION_HELPER_SH`에 격리 준비 함수 세 개를 넣었다. `prepare_isolation`이 Git 작업 트리 확인과
  기준 커밋 확정, 경로와 브랜치 이름 조립, 준비 기록 작성, `git worktree add`를 순서대로 수행한다.
  `write_isolation_record`가 준비 기록을 쓰고, `discard_isolation`이 실패 시 사본과 브랜치를 지운다.
- 사본은 `.workflow/.runtime/worktrees/<대상>/<lease>`, 브랜치는 `wf-iso/<대상>/<lease>`다. 두 이름은
  대상 식별자와 lease 식별자만으로 조립하므로 prompt 원문·인증 값·환경 변수 값이 들어가지 않는다.
- 준비 기록은 `.workflow/.runtime/isolation/<대상>.yml`에 남고 대상·lease·기준 커밋·브랜치·사본 경로·
  제어 문서 정본·준비 시각·단계 이름 여덟 값을 담는다. 첫 줄 주석이 앱 소유 상태임을 밝힌다. 단계 값은
  `preparing`에서 시작해 `ready` 또는 `failed:worktree`·`failed:record`로 끝난다.
- 본문 흐름에서 `expires_at` 확인 직후, 역할이 `developer`일 때만 준비를 실행한다. 실패하면 기존

  네 값은 개발 역할의 출력에만 붙는다.
- `prompt_for`에 개발 역할 문장을 넣어 사본에서만 코드를 쓰고 검사하며, 제어 문서는 정본 경로에만
  쓴다는 사실을 전달한다. 인자를 여섯 개로 늘렸고 provider별 지시는 넣지 않았다.
