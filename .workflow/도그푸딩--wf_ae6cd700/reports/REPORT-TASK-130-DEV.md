# TASK-130 개발 보고서

## 결정권자 요약

에이전트가 작성하는 한국어 문서에 자연스러운 실무 문체 기준을 추가했다. 모호한 비유를 정확한 행위와
결과로 바꾸고, 표준적인 한자어와 기술 용어를 어색한 고유어로 바꾸지 않도록 했다. 영문식 긴 대시로
문장을 습관적으로 나누지 않는 기준도 포함했다.
기존 문서를 문체의 본보기로 삼지 않으며, 인용 없이도 현재 문서를 이해할 수 있어야 한다. 기획자,
아키텍트, 개발자는 각자 작성한 문서를 제출하기 전에 이 기준을 확인한다.
기존 문서는 수정하지 않았고 자동 검사나 앱 화면 변경도 추가하지 않았다. Rust 테스트 539개와 프런트
테스트 705개가 통과했고 타입 검사와 빌드도 성공했다. 지금 요청하는 것은 TASK-130의 사용자 확인이다.

## 변경 내용

변경한 제품 파일은 `src-tauri/src/infrastructure/project_instructions.rs` 하나다.

1. 공통 규칙 마지막에 9번 문체 규칙을 추가했다.
   - 주체, 행동, 결과를 구체적으로 적는다.
   - 한 문장에는 주요 주장 하나를 담는다.
   - 한국 기획·개발 문서에서 일반적으로 사용하는 문어체를 쓴다.
   - 표준적인 한자어와 기술 용어를 억지로 쉬운 표현으로 바꾸지 않는다.
   - 영문식 긴 대시를 마침표, 접속 표현, 괄호 대신 습관적으로 사용하지 않는다.
2. `착지`, `닫다`, `원천`을 문맥에 맞는 구체적인 표현으로 바꾸는 최소 예시를 넣었다. 예시는 금지어
   목록이 아니며, 의미가 명확한 기술 용어는 대상을 밝히고 사용할 수 있다.
3. 기존 문서는 사실과 결정을 확인하는 자료로만 사용하고 문체의 본보기로 복제하지 않도록 했다.
4. 요약 외 본문의 현재 문체를 정확성이라고 인정하던 문장을 삭제했다. 작업자용 본문도 읽을 수 있어야
   하며 9번 규칙을 따라야 한다는 문장으로 교체했다.
5. 역할별 완료 조건에 자기검토와 문서 목적을 추가했다.
   - 기획자: 문제, 결정, 요구사항
   - 아키텍트: 범위, 완료 조건, 검증
   - 개발자: 변경, 검증, 위험, 사용자 확인
6. 공통 규칙 버전은 13으로 올렸다. 역할 버전은 기획자 8, 아키텍트 7, 개발자 8이며 역할 버전 상수는
   8이다.

- `git diff --check`: 오류 없음.
- 기존 항목 참조 개수 유지: 4번 11개, 5번 2개, 6번 3개, 8번 7개. 새 9번 참조는 5개다.
- 제품 변경 범위: 선언된 파일 하나만 수정했다. 작업 상태와 보고서, 개발 로그는 워크플로 기록이다.

## 남은 작업과 위험

- TASK-131이 한국어 파일 계약 문서에 확장 용어 예시와 전후 문장을 추가한다. 이 작업은 TASK-130을
  선행 작업으로 참조한다.
- 문체 규칙은 자동 판정이 아니다. 실제 문서가 좋아졌는지는 이후 생성되는 문서를 표본으로 읽어 확인해야
  한다.
- 사용자 확인 뒤 앱이 설치본을 다시 생성해야 현재 프로젝트의 규칙 파일에 버전 13과 새 항목이 나타난다.
