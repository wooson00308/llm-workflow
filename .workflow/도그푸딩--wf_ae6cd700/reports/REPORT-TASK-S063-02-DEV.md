# TASK-S063-02 개발 보고서

## 결정권자 요약

실행 화면이 보고 없이 끝난 실행을 정상 완료와 구분해 보여준다. 끝난 실행의 보고서 판정을 실행 목록을
읽을 때마다 함께 받아 두고, 그 값을 최근 종료 구역과 전체 기록 서랍 두 자리에 짧은 문구로 놓는다.
문구는 보고 없음으로 확정된 실행에만 붙고, 확인하지 못한 실행과 판정 대상이 아닌 실행, 아직 판정을
받아 오지 못한 실행, 진행 중인 실행에는 붙지 않는다. 상세에서는 결과 보고서 항목이 더 이상 사라지지
않고, 보고서를 남기지 않았다는 사실과 확인하지 못했다는 사실을 각각 문장으로 말한다. 보고 없이 끝난
실행에 끊긴 이유 값이 없으면 확인하지 못했다고만 적고 원인을 지어내지 않는다. 판정 자체는
TASK-S063-01이 만든 것을 읽기만 하며 이 작업은 화면과 그 값을 받아 두는 자리만 바꿨다. 화면 검사
513건과 백엔드 검사 884건, 통합 시험 28건이 격리 사본과 통합 후 모두 통과했고 생산 빌드도 통과했다.
이 결과는 GROUP-063의 자동 검증 가운데 화면 표시에 해당하는 부분을 뒷받침한다.

## 바꾼 파일과 모듈

선언한 일곱 파일만 바꿨다.

- `src/features/projects/domain/types.ts`: 판정 값 형과 판정 결과 형을 더하고, 게이트웨이 인터페이스에
  판정 조회 하나를 더했으며, 화면 상태에 실행 식별자별 판정 자리를 더했다.
- `src/features/projects/infrastructure/tauriProjectGateway.ts`: 백엔드 판정 명령 호출을 더했다. 넘기는
  값은 프로젝트 경로와 끝난 실행 행뿐이고 파일 이름이나 경로를 만들지 않는다.
- `src/features/projects/application/useProjectWorkspace.ts`: 실행 목록을 읽은 뒤 끝난 실행들의 판정을
  이어서 조회한다. 답이 온 실행만 판정을 갖도록 매번 새 지도를 세우므로, 조회가 실패하거나 실행이
  목록에서 사라지면 그 자리가 비고 직전 값이 남지 않는다. 프로젝트를 바꿀 때 화면 상태를 통째로
  되돌리는 기존 경로가 판정도 함께 비운다.
- `src/features/projects/components/agents/AgentRunDashboard.tsx`: 최근 종료 구역과 전체 기록 서랍의
  실행 줄에 보고 없음 문구를 더하고, 상세의 결과 보고서 항목과 사유 항목을 판정에 따라 그리도록
  바꿨다. 사유 값을 문장으로 옮기는 기존 변환을 그대로 쓴다.
- `src/App.css`: 목록 줄 안에 서는 표시 규칙 하나를 더했다.
- `src/features/projects/application/useProjectWorkspace.test.ts`,
  `src/features/projects/components/agents/AgentRuntimeView.test.tsx`: 시험 대역을 새 모양에 맞추고
  검사를 더했다.

상세가 열릴 때 보고서 목록을 읽는 기존 경로는 손대지 않았고, 보고서 바로가기는 지금과 같은 값으로
그려진다.

격리 사본과 통합 커밋에서 같은 검사를 두 번 돌렸고 결과가 같다.

- `npm run build`: 성공. 격리 사본과 통합 후 모두 성공했다.

  백엔드를 바꾸지 않았고 결과도 바뀌지 않았다.

통합 시점에 공유 기준이 후보를 만든 기준보다 두 커밋 앞서 있었다(둘 다 문서 커밋이다). 후보를 현재

겹치는 경로가 없어, 남의 변경을 건드리지 않고 반영했다. 통합 커밋은 4cc1ef5이고 기준은 5dd9419다.

## 남은 위험

- 판정 조회는 실행 목록 갱신마다 함께 돈다. 에이전트 화면을 열어 두면 2.5초 주기이고, 끝난 실행이
  많은 프로젝트에서는 그만큼 파일 확인이 반복된다. 조회 자체는 백엔드가 목록 전체를 한 번에 답하므로
  실행 수에 비례해 호출이 늘지는 않는다.
- 화면 자동 검사만으로 확인했고 실제 앱을 띄워 눈으로 본 확인은 하지 않았다. 표시가 목록을 훑는 동안
  눈에 들어오는지는 작업 그룹의 사용자 확인이 판단할 몫이다.
- 판정이 보고 없음인데 같은 대상의 보고서 바로가기가 상태에 남아 있으면 상세는 판정을 따라 문장만
  보여준다. 바로가기를 감추는 이 우선순위는 인수 조건 2를 따른 것이지만, 앞선 세션의 보고서를 상세에서
  열 길이 그 실행에서는 없어진다.

## 후속 작업

- 아키텍트 확인 요청 하나. 작업 문서의 완료 조건 C9는 기존 검사 하나의 단언을 바꾸라고 하고, 검증 절차
  4항은 기존 검사에서 바뀐 줄이 그 단언 하나뿐이어야 한다고 적었다. 그런데 같은 문서의 C5가 판정을
  받아 오지 못한 실행에서는 항목이 자리를 비운다고 정했으므로, 그 검사가 보고서 없음 문장을 확인하려면
  실행 하나에 보고 없음 판정을 넣어 주는 입력 한 줄이 함께 필요하다. 그래서 그 검사에서 바뀐 줄은
  단언 하나와 입력 하나 둘이다. 검사가 함께 지키던 다른 실행의 목록을 빌려 쓰지 않는다는 단언은 그대로
  두었고, 다른 기존 검사의 단언과 기대값은 바꾸지 않았다.
- 작업 문서만으로 판단이 서지 않아 SPEC-063을 열었다. C5가 결과 보고서 항목이 "언제나 자리를 지킨다"고
  적으면서 마지막 갈래에서는 "자리를 비운다"고 적어 두 문장이 그대로는 함께 성립하지 않는다. 기획서
  R-08이 금지하는 것은 보고서가 없다는 사실을 항목이 사라지는 방식으로 말하는 것이므로, 확정된 판정이
  없는 실행에서는 항목을 두지 않는 것으로 읽고 구현했다. 다음 작업 문서에서는 이 갈래를 한 문장으로
  적어 주는 편이 좋겠다.
- 공유 작업 트리에 이 작업과 무관한 미완 변경이 있다. 백엔드 저장소 파일 하나와 다른 작업 문서 하나이며
  건드리지 않았다.
