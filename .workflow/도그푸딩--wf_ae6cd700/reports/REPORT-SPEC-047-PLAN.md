# SPEC-047 기획 보고서

## 결정권자 요약

기존 프로젝트의 관리 규칙이 앱보다 낮은 버전에 머무는 원인과 실제 발생 순서를 확인했다.
프로젝트를 열 때와 사용자가 새로 고침을 누를 때만 규칙을 갱신하고, 자동 조회는 읽기 전용으로
유지하는 기획서를 작성했다.
충돌이 있어도 프로젝트는 계속 열어 두고 설정 화면에서 설치 상태와 실패 이유를 확인하게 한다.
사용자 정의 가드레일은 범위가 큰 별도 기능으로 분리했다.
지금 요청하는 것은 SPEC-047의 승인 여부다.

## 대상과 순서

- 앱 인박스에 등록된 두 아이디어 중 등록 시각이 빠른 IDEA-954B53EA를 처리했다.
- IDEA-655ADA04는 사용자 정의 가드레일 기능으로 별도 유지했다.
- 기획자 대기열에는 회수 대상이나 미답변 수정 요청이 없었다.

## 확인 결과

1. 프로젝트의 설치 규칙은 버전 12이고 앱 소스와 현재 개발 바이너리는 버전 13이다.
2. TASK-130과 TASK-131의 QA 결정은 새 백엔드가 시작되기 약 51초 전에 기록됐다. 구버전 백엔드가
   승인을 처리해 버전 12를 다시 설치했다.
3. 프로젝트 조회는 관리 규칙을 갱신하지 않는다. 규칙 설치는 새 워크플로 생성, 기획 결정, 작업 QA
   기록에서만 실행된다.
4. 프로젝트 열기, 수동 새로 고침, 2.5초 자동 조회가 같은 조회 기능을 사용한다. 이 기능에 쓰기를 바로
   추가하면 자동 조회까지 2.5초마다 파일을 건드리게 된다.
5. 설정 화면에는 프로젝트와 문서 규격, 파일 감시 상태만 있고 관리 규칙 버전은 표시하지 않는다.

## 기획 결정

- 최초 열기와 수동 새로 고침을 명시적인 동기화 시점으로 정했다.
- 자동 조회는 계속 읽기 전용으로 둔다.
- 현재 설치 절차의 낮은 버전 갱신, 같은 버전 무변경, 충돌 방어를 재사용한다.
- 동기화 실패와 프로젝트 조회 실패를 나눠, 규칙 충돌이 프로젝트 접근까지 막지 않게 한다.
- 설정 화면에서 설치 버전, 앱 제공 버전, 마지막 결과와 적용 시점을 보여준다.
- 커스텀 가드레일의 저장 방식과 편집 UI는 IDEA-655ADA04에서 따로 결정한다.

## 검증

- 새 아이디어 두 건의 생성 시각과 참조 기획서 부재를 확인했다.
- 실행 중인 개발 바이너리와 설치 규칙의 버전을 직접 확인했다.
- 프로젝트 저장소, 프런트엔드 조회 주기, 설정 화면, 규칙 설치기의 현재 동작을 코드에서 확인했다.
- SPEC-047의 결정권자 요약은 빈 줄을 제외하고 여덟 줄이며 요약 형식 제한을 지킨다.
- `git diff --check`에서 오류가 없었다.

## 다음 단계

사용자가 SPEC-047을 승인하면 아키텍트가 백엔드 동기화와 설정 화면을 안전하게 나눠 개발 작업으로
만든다. 승인 전에는 앱 코드와 규칙 설치 동작을 변경하지 않는다.
