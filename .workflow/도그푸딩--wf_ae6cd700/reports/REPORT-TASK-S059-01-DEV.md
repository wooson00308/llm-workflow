# TASK-S059-01 개발 보고서

## 결정권자 요약

개발 작업 화면의 세 목록과 화면 위 수치가 이제 같은 기준으로 끝난 작업 그룹의 작업을 제외한다.
작업 그룹별 보기에만 있던 감춤을 평면 보기와 리스트, 진행 중·막힘·완료 수치와 표시 건수로 넓혔다.
소속 그룹을 확정할 수 없는 작업은 감추지 않으므로, 사용자가 확인해야 할 구성 오류는 화면에 남는다.
감춘 그룹이 있으면 그 개수와 기록 화면을 알리는 안내가 목록 아래에 정확히 한 번 나온다.
타임라인 보기와 기록 화면, 작업 상세 화면은 변경 전과 같고 문서 파일은 이 변경으로 바뀌지 않았다.
격리 사본과 공유 작업 공간 양쪽에서 자동 검사가 모두 통과했다.
이 결과는 GROUP-059가 사용자 품질 확인을 받을 준비가 되었다는 근거다.

## 변경한 파일과 모듈

- `src/features/projects/components/DevelopmentBoard.tsx`
  - `isFinishedWorkGroup`을 더해 `displayStatus`가 `completed`이거나 `automatic_completed`인 그룹을
    끝난 그룹으로 판정한다. 백엔드가 넘겨 주는 값을 그대로 읽고 새 판정 규칙을 만들지 않았다(C2).
  - 항등 함수였던 `tasksForDevelopment`가 작업 그룹 목록을 함께 받아, 끝난 그룹에 속한 작업을 빼고
    돌려준다. 소속 확정은 기존 `matchingWorkGroup`을 그대로 호출하므로 그룹을 찾지 못하거나 출처가
    어긋난 작업은 남는다(C1·C3). `scopedTasks` → `filteredTasks` 파생 관계는 그대로 두어 검색과 상태
    필터가 좁혀진 범위 안에서만 동작한다.
  - 화면 머리의 진행 중 수치와 요약 띠의 세 수치가 `workflow.items.tasks` 대신 `scopedTasks`를
    센다(C4). 표시 건수는 `filteredTasks` 파생을 통해 함께 좁혀졌다(C5).
  - `WorkGroupLaneBoard`에 넘기는 `allTasks`를 `scopedTasks`로 바꿨다(C6).
  - `WorkGroupLaneBoard` 안에 있던 `activeGroups` 계산과 `completedCount`를 화면 본체로 올리고, 레인
    보드는 이미 걸러진 그룹 목록을 받는다. 안내 문단도 본체로 옮겨 `viewMode`가 타임라인이 아닐 때만
    그린다. 그래서 작업 그룹별 보기·평면 보기·리스트에서 각각 한 번씩 나오고 타임라인에는 붙지
    않는다(C8). 문구와 `task-lane-note task-lane-completed-note` 클래스는 그대로 두어 스타일 파일은
    건드리지 않았다.
  - `timelineTasks`는 계속 `workflow.items.tasks`에서 파생된다(C7).
- `src/features/projects/components/DevelopmentBoard.test.tsx`: 검사 8개를 더했다. 평면 보기·리스트의
  감춤, 네 수치와 표시 건수, `qa_ready` 그룹의 잔류, 소속 미확정 세 경우의 잔류, 검색으로도 나오지
  않음, 안내가 세 보기에서 한 번씩만 나오고 감춘 그룹이 없으면 사라짐, 타임라인 집계와 전체 이력
  건수 불변을 각각 확인한다. 기존 검사는 하나도 고치거나 지우지 않았다.

선언한 범위 밖의 파일은 바꾸지 않았다. 범위 사전 검사가 지목한 네 값의 경로를 현재 코드에서 다시
따라가 확인했고, 문서가 적은 행 번호와 소비 지점이 모두 그대로였다.

## 남은 위험

- 감춤은 표시 범위만 좁힌다. 문서와 백엔드 판정은 그대로이므로 되돌릴 때는 이 표시 규칙만 되돌리면
  된다.
- 작업마다 그룹 목록을 훑어 소속을 확인하므로 계산량이 작업 수와 그룹 수의 곱이다. 현재 규모(작업
  186건, 그룹 56개)에서는 문제가 없지만, 목록이 크게 늘면 조회 구조를 다시 볼 여지가 있다.
- 사용자가 최근에 끝낸 작업을 개발 작업 화면에서 찾다가 못 찾을 수 있다. 감춘 개수와 기록 화면을
  알리는 안내 한 줄이 그 대응이며, 실제로 충분한지는 GROUP-059의 사용자 품질 확인에서 판단된다.
- 자동 확인으로 닫힌 그룹은 확인 이후 코드 변경이 있으면 백엔드가 개발 중으로 되돌린다. 그때는 그
  그룹의 작업이 다시 화면에 나타난다. 의도한 동작이지만 사용자에게는 목록이 늘어난 것으로 보인다.
