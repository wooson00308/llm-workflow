## 핵심 결정과 근거

1. 커밋 모드는 `git ls-tree -r -l -z <rev> -- .workflow` 한 번으로 관리 디렉터리 전체의 blob 크기를 읽는다. 파일마다 `git show`를 부르면 문서 500여 개에 서브프로세스 500번이 된다. `-z`는 한글 디렉터리(`도그푸딩--wf_ae6cd700`)가 따옴표로 인용되는 것을 막기 위해 필수다. 등록 문서만 내용이 필요해 `git show`로 읽는다.
2. 착수 비용과 대조 비용을 나눠 출력한다. 합계 하나만 내면 "문서 수와 무관한 고정 비용"과 "문서 수에 비례하는 비용"을 구분할 수 없고, SPEC-049가 줄이려는 것은 후자다. 변경 후 비교의 해석이 여기에 걸린다.
3. JSON에 실행 시각을 넣지 않았다. 완료 조건 4(같은 입력 → 같은 값)를 값뿐 아니라 출력 전체가 바이트 단위로 같게 만들어 만족시킨다.
4. 표와 JSON을 한 번에 낸다(구분선 `--- JSON ---`). 플래그를 두지 않았다 — 작업 문서가 "함께 낸다"고 요구했고, 옵션을 늘리면 실행 방법 문서화만 복잡해진다. JSON만 저장하는 한 줄 명령을 문서에 적었다.
5. 측정값이 상한이라는 점을 문서에 명시했다. 대조 문서를 전부 끝까지 읽는다고 가정해 바이트를 합산하므로 실제 세션 소비량과 같지 않다. 작업 문서가 정한 계산법(두 묶음 합산, 2바이트=1토큰)을 그대로 따르되, 해석을 문서가 책임지게 했다.
6. `reports/`는 어느 역할의 대조 대상도 아니라 역할 합계에서 뺐지만, 문서군 표에는 냈다(216건 2.2MB로 가장 큰 문서군이라 성장 위치를 보여준다). 문서에 "역할 합계에는 들어가지 않는다"고 적었다.
