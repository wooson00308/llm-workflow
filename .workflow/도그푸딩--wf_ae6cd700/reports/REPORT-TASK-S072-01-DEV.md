# TASK-S072-01 개발 보고서

## 결정권자 요약

확인 동선을 사용자 확인 절차로 인정하는 낱말 대조가 어미가 달라진 형태도 같은 낱말로 읽게 고쳤다.
지금까지 하던 글자열 대조를 먼저 그대로 하고, 걸리지 않을 때만 어미 변화를 견디는 대조를 덧붙이는
두 단계로 바꾸었으며 화면과 행동과 결과 세 낱말 목록에 모두 적용했다. 결과 낱말 여섯 개도 더했다.
이 저장소의 실제 문서로 확인한 결과 GROUP-070은 변경 전에 구성 확인 필요였고 변경 후에 사용자 QA
대기가 되었다. 문서를 한 글자도 고치지 않고 품질 확인이 열린 것이다. 개발자용 절차 차단과 빈 본문
거절과 세 조건을 모두 만족해야 한다는 규칙은 그대로 두었다. 백엔드 시험 892건과 통합 시험 28건,
화면 시험 535건이 통합 전후로 모두 통과했다. 이 결과는 GROUP-072의 사용자 확인 준비를 뒷받침한다.

## 바꾼 파일과 모듈

- `src-tauri/src/infrastructure/fs_project_repository.rs` — 선언한 파일 하나만 고쳤다.
  - 한글 음절을 초성·중성·종성으로 푸는 `SyllablePart`와 `decompose_hangul`을 더했다. 초성과 종성을
    다른 변형으로 구분해 두어 글자 경계가 한 번 더 지켜진다.
  - `contains_token_ignoring_ending`을 더했다. 낱말이 본문의 글자 경계에서 시작해 조각이 끊기지
    않고 이어지는지를 보고, 낱말이 끝나는 글자에 종성만 남으면 같은 낱말로 인정한다. 중성이 남으면
    인정하지 않는다.
  - `scenario_mentions_token`을 더해 두 단계 대조를 한 자리에 모았다. 앞 단계가 기존
    `lowered.contains(token)` 그대로라서 지금 인정되던 문장의 판정은 달라지지 않는다.
  - `scenario_describes_user_observable_flow`의 화면·행동·결과 세 대조식을 모두 이 함수로 바꿨다.
    결과 낱말 목록에 적혀, 열리, 나오, 바뀌, 같아지, 남아 여섯을 더했다.
  - 같은 파일의 시험 모듈에 시험 셋을 더했다. 세 목록의 어미 변화 대조를 각각 확인하는 시험,
    글자 경계를 확인하는 시험, GROUP-070 본문을 그대로 옮겨 담은 기능이 사용자 QA 대기가 되는지
    확인하는 시험이다.
  - `scenario_is_user_safe`와 `contains_internal_qa_instruction`과 기능 표시 상태 계산은 읽기만 하고
    고치지 않았다. 기존 시험도 한 건도 고치지 않았다.

## 검증 절차와 결과

격리 사본에서 실행한 결과다.

- `cargo test --manifest-path src-tauri/Cargo.toml` — 892건과 통합 28건 통과, 실패 없음. 새 시험 셋이
  완료 조건 C1부터 C4까지와 C8을 덮는다.
- 기존 시험 `nondeveloper_scenarios_accept_visible_ui_flows_and_reject_cli_instructions`를 한 글자도
  고치지 않고 통과시켜 C5, C6, C7을 확인했다.
- `cargo fmt --check` — 처음 검사에서 세 자리가 걸려 `cargo fmt`로 정리한 뒤 다시 통과했다.
- `cargo clippy --all-targets -- -D warnings` — 경고 없이 통과.
- `npm run check` — 화면 시험 535건 통과, 타입 검사와 빌드 통과. 화면을 고치지 않았으므로 기존
  시험이 그대로 통과한다. C9와 C10을 함께 확인했다.

실제 문서로 확인한 결과다. 작업 문서의 검증 절차 7단계는 앱을 띄워 눈으로 확인하라고 적었는데, 이
실행 환경은 화면 갈무리 권한이 없어 창을 열어 보는 확인을 수행할 수 없었다. 대신 앱이 실제로 쓰는
조회 경로에 이 저장소 경로를 그대로 넣어 GROUP-070의 표시 상태를 변경 전후로 각각 읽었다. 변경 전
코드로는 구성 확인 필요였고 변경 후 코드로는 사용자 QA 대기였다. 확인에 쓴 임시 시험은 격리 사본
안에서만 돌리고 지웠으며, 통합한 커밋에는 들어 있지 않다.

통합 후보와 통합 결과다.

- 변경 커밋 `d00bbdd`, 통합 직전 공유 기준 `eda5997`, 바뀐 파일 하나.
- 통합 직전 공유 기준이 후보의 기준과 두 번 어긋나 그때마다 후보를 현재 커밋 위로 옮기고 격리
  검사를 처음부터 다시 돌렸다. 세 번의 검사 결과가 모두 같다.
- 공유 작업 공간에 `.workflow/` 밖 미커밋 변경이 없어 충돌 없이 통합했다.
- 통합한 커밋에서 공유 기준으로 다시 돌린 백엔드 시험 892건과 통합 28건, 화면 시험 535건이 모두
  통과했다. 격리 결과와 통합 결과가 같다.

## 남은 위험

- 판정이 넓어진 만큼 덜 다듬어진 확인 동선이 통과할 여지가 생긴다. 기능 문서가 비용으로 인정한
  변화이며, 사용자는 확인 화면에서 수정 요청으로 되돌릴 수 있다.
- 어미 변화 대조는 낱말 뒤에 종성이 하나 붙은 형태를 모두 같은 낱말로 읽는다. 명사에서는 준말이
  그 자리에 걸린다. 예를 들어 화면 낱말 카드가 카든에 걸린다. 뜻이 맞는 자리여서 이번에는 문제가
  되지 않았지만, 앞으로 낱말을 더할 때는 이 성질을 함께 보아야 한다.
- 영어 낱말은 한글이 아닌 글자를 하나씩 그대로 맞추므로 판정이 달라지지 않는다. 기존 영어 문장
  시험이 그대로 통과해 확인했다.
- 창을 열어 눈으로 본 확인은 수행하지 못했다. 화면이 이 값을 어느 목록으로 가르는지는 기존 화면
  시험이 덮고 있고, 실제 화면 확인은 GROUP-072의 사용자 확인에서 사용자가 직접 보게 된다.

## 후속 작업

- 아키텍트에게 넘기는 발견 하나다. 작업 문서의 검증 절차 7단계는 앱을 띄워 눈으로 확인하고 그
  화면을 보고서에 적으라고 요구하는데, 개발 세션의 실행 환경에는 화면 갈무리 권한이 없어 어느
  세션도 이 단계를 그대로 수행할 수 없다. 완료 조건에는 들어 있지 않은 단계여서 이번 작업을 막지는
  않았다. 앞으로 같은 성격의 확인은 사용자 확인 동선에 두는 편이 맞다고 본다.
- 작업 문서 밖으로 나간 읽기는 기능 문서 GROUP-070의 확인 동선 본문 하나다. 작업 문서가 그 본문을
  완료 조건 C4의 대상으로 지목하면서 본문 자체는 싣지 않아, 옮겨 적으려면 원본을 열어야 했다.
  기획서와 결정 문서는 대상 적격을 판단하는 데 필요한 앞머리만 읽었고 구현에는 쓰지 않았다.
