# TASK-S063-01 개발 보고서

## 결정권자 요약

대상을 배정받고 끝난 실행마다 그 실행이 결과 보고서를 남겼는지 앱이 판정하는 명령이 생겼다. 답은
보고서 있음, 보고 없음, 확인 불가, 판정 대상 아님 넷 중 하나이며 실행 상태와 따로 매긴다. 이름만
보던 기존 조회와 달리 파일 시각을 함께 보므로, 같은 대상을 앞서 다룬 세션의 보고서는 이번 실행의
답에 들어가지 않는다. 찾는 범위는 프로젝트에 등록된 모든 워크플로우다. 보고 없음으로 판정한 실행은
앱만 쓰는 자리에 기록 하나로 남으며, 같은 실행을 다시 판정해도 기존 기록을 덮지 않고, 판정이 서기
전에 끝난 실행은 소급해 기록되지 않는다. 확신이 서지 않는 경우를 모두 확인 불가로 답해 정상 완료된
실행을 끊긴 것으로 올리지 않는다. 자동 검사는 격리 사본과 통합 후 모두 백엔드 881건, 화면 505건이
통과했고 형식 검사와 빌드도 통과했다. 이 결과는 GROUP-063의 자동 검증 완료를 준비하는 증거이며,
사용자가 지금 확인할 것은 없다.

## 판정과 기록의 요점

- 시간대는 시작 시각부터 종료 시각까지이고 뒤쪽에 60초를 더 준다. 파일 시각은 생성 시각을 먼저
  쓰고, 플랫폼이 주지 않으면 수정 시각을 쓴다.
- 기록은 `.workflow/.runtime/silent-runs/<실행 id>.json`이고 규격은 `workflow-labs/silent-run@1`이다.
  기준 시각은 같은 디렉터리의 `baseline.yml`에 담긴다. 실행 기록 이름은 항상 `.json`으로 끝나므로 이
  이름을 실행 하나가 가져가는 일이 없다.
- 실행 식별자가 `A-Za-z0-9`, `_`, `-` 밖의 문자를 담으면 기록을 만들지 않고, 판정 값은 그대로 보고
  없음이며 결과의 `recorded`가 거짓으로 온다.

격리 작업 사본과 통합 후 공유 기준에서 같은 네 가지를 각각 돌렸다. 격리 검사는 기준 커밋을

   통합 후 같은 856건과 25건 통과, 실패 0. 새 검사 일곱 개가 모두 통과했다.
2. `cargo fmt --manifest-path src-tauri/Cargo.toml --check` — 격리 사본과 통합 후 모두 통과.
3. `npm run test` — 격리 사본과 통합 후 모두 505건 통과, 42건 건너뜀, 실패 0.
4. `npm run build` — 격리 사본과 통합 후 모두 성공.
5. `git diff`로 기존 검사에서 바뀐 줄이 없음을 확인했다. 저장소 파일에서 지워진 줄은 형식 검사가
   다시 감은 `use` 열한 줄뿐이고 단언과 기대값은 그대로다.
6. `git status`로 바뀐 파일이 선언한 네 개뿐임을 확인했다. 화면 파일과 문서 파일은 바뀌지 않았다.

통합은 `fb5bef6` 하나이며 시작 기준은 `8678888`이다. 공유 작업 공간에 `.workflow` 밖의 미커밋 변경은
없었으므로 사용자 파일과 겹치지 않았다.

## 남은 위험

- 파일 시각은 파일 시스템이 주는 값이다. 보고서를 옮기거나 복사한 프로젝트에서는 시각이 다시 찍혀
  그 실행의 답이 보고 없음으로 바뀔 수 있다. 판정을 상태 값과 따로 매긴다는 요구 때문에 이 값 말고
  실행과 보고서를 잇는 근거가 지금 없다.
- 기준 시각 파일을 사람이 지우면 다음 판정이 그 순간을 기준으로 다시 세운다. 이때 그 사이에 끝난
  실행은 기록되지 않는다. 앱만 쓰는 자리라 형상 관리로는 되돌릴 수 없다.
- 판정 결과를 아직 아무 화면도 부르지 않는다. TASK-S063-02가 배선하기 전까지 이 경로는 돌지 않는다.
