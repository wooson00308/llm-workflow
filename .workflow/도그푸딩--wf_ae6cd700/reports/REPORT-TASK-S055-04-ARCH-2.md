# TASK-S055-04 두 번째 정의 수정 보고서

## 결정권자 요약

TASK-S055-04는 현재 범위 선언을 화면에 전달할 응답 구조가 범위에 빠져 다시 시작할 수 없었다.
기존 작업에 필요한 Rust 도메인 범위 하나를 추가했다.
정상 목록과 선언 없음과 형식 오류를 서로 다른 화면 값으로 전달하도록 작업 정의와 검증을 보완했다.
기존 식별자와 승인과 선행 관계와 이력과 막힌 사유는 그대로 보존했다.
작업은 개발 준비 상태로 돌아갔고 사용자 재개 이력은 추가하지 않았다.
제품 코드는 변경하지 않았다.

## 수정 근거

- `blocked_kind: definition_error`와 현재 `## 막힌 사유`를 읽고, `REPORT-TASK-S055-04-DEV-2.md`가
  기록한 두 번째 차단 근거를 확인했다.
- 앞선 `REPORT-TASK-S055-04-ARCH.md`가 추가한 목록 조회 범위와 사건 근거는 완료 조건 9를 위해 필요하므로
  보존했다. 이번에는 그 수정으로도 충족할 수 없었던 완료 조건 2의 응답 경로만 추가로 고쳤다.
- 앱 소유 수정 요청 기록은 없었다. 공통 규칙이 허용한 정의 오류 작업 자체의 막힌 사유와 개발 보고서를
  근거로 수정했고 `revision_request_id`는 추가하지 않았다.
- SPEC-055 R2의 현재 범위 표시를 위한 응답 확장이며, 승인된 제품 범위를 추가하거나 제거하지 않는다.

## 수정 내용

- 상태를 `blocked`에서 `todo`로 돌렸다. 아키텍트의 정의 수정 복귀이므로 `history`는 추가하지 않았다.
- `scope_files`에 `src-tauri/src/domain/project.rs`를 추가했다. 기존 선행 관계와 나머지 범위는 그대로다.
- 범위 사전 검사에 작업 상세 응답 소유자와 기존 범위 파서를 추가했다. 정상 빈 목록, 선언 부재,
  형식 오류를 겹치지 않는 상태 계약을 SPEC-032 R1과 공통 규칙 6절에서 가져왔다.
- 변경 범위와 완료 조건 2에 응답이 현재 선언을 싣고 화면이 세 상태를 추측 없이 구분하는 조건을 추가했다.
- 검증 절차 1에 Rust 상세 응답과 화면의 세 상태 대조를 추가했다. 나머지 조건과 검증 절차는 보존했다.

## 범위 사전 검사

- `src-tauri/src/domain/project.rs`의 `TaskDocument`는 현재 선행 판정, 겹침 근거와 수정 요청은 싣지만
  현재 `scope_files` 선언을 싣지 않는다. `read_markdown_document`가 프론트매터를 제거한 본문을 돌려주므로 화면은 현재
  응답없이 선언을 복원할 수 없다.
- `src-tauri/src/infrastructure/fs_project_repository.rs`의 `ScopeDeclaration`과 `parse_scope_declaration`은 정상 목록,
  선언 부재, 형식 오류를 이미 구분한다. 이 결과를 상세 응답에 싣으면 새 파서나 원격 호출을 만들지 않고 완료 조건 2를
  충족할 수 있다.
- 정상 빈 목록은 수정 파일이 없다는 유효한 선언이다. 선언 부재는 빈 목록이 아니고, 형식 오류는 판정할 수 없는 선언이다.
  이 차이는 SPEC-032 R1, 공통 규칙 6절과 기존 파서 검사가 직접 고정한다.
- 조건 스크립트와 자격 판정 구현도 같은 선언을 읽지만 응답 형식을 소유하지 않고 이 작업이 판정을 바꾸지도 않으므로 범위에서
  제외했다. 최상위 조립 파일과 전역 스타일 파일을 제외한 앞선 판정도 유지했다.

## 검증 결과

- YAML 파서로 작업 문서의 상태, 차단 분류, 식별자, 승인 참조, 선행 관계, 선언 범위와 이력을 확인했다.
- 기존 이력 다섯 개와 `## 막힌 사유` 절이 바뀌지 않았고 `revision_request_id`와 `resumed` 이력이 없음을 확인했다.
- 완료 조건은 1부터 14까지, 검증 절차는 1부터 10까지 중복과 누락 없이 유지됐다.
- `git diff --check`를 실행해 문서 형식을 확인했다.

## 남은 위험과 인계

- 응답 필드의 구체적인 Rust·TypeScript 모양은 구현자가 기존 직렬화 스타일에 맞춰 정한다. 다만 세 선언 상태와 정상 빈 목록을
  겹치게 표현하면 완료 조건 2를 충족하지 못한다.
- 정상 목록의 경로 문자열과 순서는 문서에 적힌 그대로 응답과 화면에 남겨야 한다. 정규화, 글롭 확장과 대소문자 변환은 계약 밖이다.
