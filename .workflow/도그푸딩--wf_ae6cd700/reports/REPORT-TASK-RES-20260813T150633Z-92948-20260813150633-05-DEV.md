## 결정권자 요약

모든 항목에 결과를 남기면 제출 전 검토 화면으로 넘어가고, 최종 버튼 한 번으로 각 작업에 확인 완료와
재작업 요청을 나눠 기록하도록 만들었다. 검토 화면은 두 대상을 건수와 함께 구획으로 나눠 보여 주고,
각 항목의 결과와 메모를 그 자리에서 고치거나 항목 확인 화면으로 되돌아가 고칠 수 있다. 최종 버튼 문구에는
기록할 건수가 들어 있고, 확정 전에 같은 버튼을 다시 누르라고 요구하지 않는다. 일부만 성공하면 화면을
닫지 않고 항목마다 성공과 실패를 갈라 말하며, 성공한 항목은 임시 검토에서 빠져 다시 제출해도 중복
기록되지 않는다. 검토를 시작한 뒤 작업이 바뀐 항목이나 사유가 빈 재작업 요청이 있으면 제출을 막고 그
자리로 초점을 옮긴다. 검토 화면 검사 9건, 대기열 화면 검사 18건, 항목 확인 화면 검사 13건, 껍데기 화면
검사 31건이 통과했고 저장소 전체 검사 570건과 타입 검사와 배포 빌드도 통과했다. 사용자는 대기열에서
기능을 열어 항목마다 결과를 남긴 뒤 두 구획과 건수, 최종 버튼 문구, 기록 뒤 대기열 복귀를 확인하면 된다.

## 남은 위험

- 완료 조건 6의 상태와 이력 변화는 앱 백엔드가 하는 일이라 이 작업에서 실제 파일로 확인하지 못했다.
  화면이 보내는 요청이 앞선 작업이 정한 계약과 같은지를 단언하는 데까지가 여기서 닿는 범위다.
- 일부 실패 뒤 성공한 항목을 지우는 것은 기기 저장소가 살아 있을 때만 성립한다. 저장이 막힌 기기에서는
  저장소 모듈이 실패를 삼키므로, 화면을 떠났다 오면 실패한 항목의 결과와 메모가 남지 않는다.
- 항목 확인 화면의 진행률 문구는 다시 확인 필요 항목을 남은 것으로 세고, 검토로 넘어가는 조작은 결과를
  골랐는지로만 센다. 두 수가 갈리는 경우가 있으며, 문구를 달리 써서 뜻이 섞이지 않게 했다.
