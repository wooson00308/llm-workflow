# TASK-S065-03 개발 보고서

## 결정권자 요약

혼자 실행해야 하는 작업이 차례를 기다리는 동안, 에이전트 화면의 배정 대기 자리에서 어떤 작업이
무엇을 기다리는지 한 문장으로 읽을 수 있게 했다. 그 작업이 실제로 시작해 혼자 도는 동안에는 같은
자리에서 다른 작업이 왜 시작되지 않는지 읽힌다. 문장은 읽기만 하는 것이라 누를 것도, 사용자가 할
일도 없다. 판정이 아직 그 사유를 만들지 않은 상태에서는 화면이 지금과 똑같고, 조용한 한 줄이 나오는
조건도 그대로다. 자동 검사 504건이 실패 없이 통과했고 타입 검사와 빌드도 통과했다. 판정 자체를
바꾸는 일은 TASK-S065-01이 맡고 있어 이 작업은 이미 화면에 온 값을 읽기만 했다. 이 결과는
GROUP-065의 자동 검증 완료를 준비하는 증거이며, 사용자가 지금 확인할 것은 없다.

## 바꾼 파일과 모듈

- `src/features/projects/components/agents/AgentRunDashboard.tsx`. 모듈 수준에 사유 상수 두 개
  (`solo-run-wait`, `solo-run-active`)와 판정 함수 `soloRunNotice`를 더했다. 세 역할의 후보를 모두
  모아 사유를 정확히 일치로 비교하고, 기다리는 후보가 있으면 그 작업을 먼저 말하는 문장 하나를,
  없고 단독 실행만 있으면 다른 작업이 왜 서 있는지를 돌려준다(C1, C2, C3, C4). 배정 대기 구역의
  렌더 조건을 `queueItems.length > 0 || soloNotice`로 넓혀 자격 후보가 하나도 없어도 문장이
  남게 했고, 머리글의 개수 배지와 목록은 자격 후보가 있을 때만 그린다. 조용한 한 줄의 조건에는
  `soloNotice === null`을 더해, 기다린다는 문장과 새 작업이 없다는 문장이 같이 나오지 않게 했다.
- `src/features/projects/components/agents/AgentRuntimeView.test.tsx`. 파일 중간의 조종석 검사
  묶음 끝에 검사 4건과 보조 함수 `soloProject`를 더했다(C8). 기존 줄은 하나도 고치지 않았다.
- `src/App.css`. `.agent-queue-notice` 선택자와 목록과의 경계선 규칙 하나만 더했다. 기존 구역과
  목록 규칙의 값은 그대로 두었다(C9).

## 구현에서 고른 자리

- 문장 문자열을 화면 안에서 만들고 밖으로 내보내지 않았다. 이 값은 화면에서 시작해 화면에서 끝나며,
  검사도 화면에 그려진 글을 읽는다. 타입이나 도메인 계층에 새 자리를 만들 이유가 없었다.
- 사유 비교는 문자열 일치 하나로 두고 정규식을 쓰지 않았다. 완료 조건이 두 값을 정확히 못 박았고,
  다른 표기를 함께 받으면 뜻이 다른 사유가 같은 문장을 켜게 된다.
- 개수 배지를 자격 후보가 있을 때만 그리도록 했다. 자격 후보가 0인데 배지가 0을 달고 서 있으면
  기다리는 작업이 있다는 문장과 어긋나 읽힌다. 두 사유가 없을 때는 구역 자체가 자격 후보가 있을
  때만 그려지므로 배지가 사라지는 경우가 생기지 않고, 화면은 종전과 같다(C7).
