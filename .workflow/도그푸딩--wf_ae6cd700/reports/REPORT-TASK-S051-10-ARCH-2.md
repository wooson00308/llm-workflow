# TASK-S051-10 두 번째 아키텍트 수리 보고서

## 결정권자 요약

종료된 실행의 시간이 계속 늘어나는 원인을 런타임 응답부터 화면까지 다시 추적했다.
런타임의 고정 종료 시각을 앱이 버리지 않도록 필수 실행 요약 타입을 작업 범위에 추가했다.
실행 중에는 분 단위 진행 시간, 종료 뒤에는 늘지 않는 소요 시간이라는 사용자 기준을 작업에 명시했다.
기존 실행 제어와 TASK-S055-04 구현은 바꾸지 않았고 작업은 다시 개발 가능한 상태다.

## 잘못된 정의

런타임 v0.8.3 상태 응답은 종료된 실행에 `finishedAt`을 제공하지만 앱은
`src-tauri/src/domain/agent_runtime.rs`의 `RunSummary`에서 이 필드를 선언하지 않았다. 상태 서비스는
응답을 해당 타입으로 역직렬화하므로 프런트 범위만 수정하면 종료 시각이 사라지고 사용자 수정 요청을
충족할 수 없었다.

## 수정 내용

- `scope_files`에 `src-tauri/src/domain/agent_runtime.rs`를 추가했다.
- 완료 조건 11·12를 실행 중 `진행 시간`과 종료 뒤 고정 `소요 시간`으로 구분했다.
- 실행 중에는 초를 세지 않고 분 단위로, 1분 미만 종료만 초 단위로 표시하도록 명시했다.
- 종료 시각이 없는 구형 기록에 현재 시각을 대입하지 않고 기록 없음으로 고정하도록 명시했다.
- Rust 선택 필드 호환, 가짜 시각 전진, 구형 기록 fixture 검증 절차를 추가했다.
- 범위 사전 검사에 `startedAt`과 `finishedAt`의 런타임부터 화면까지 실제 값 경로를 기록했다.
- 기존 식별자, 승인 참조, 선행, 이력, `blocked_kind`와 막힌 사유를 보존하고 상태만 `todo`로 돌렸다.

## 범위 판정

상태 서비스는 raw 상태 행을 `RunSummary`로 generic 역직렬화하고 Tauri 명령은 `QueueSnapshot`을 그대로
직렬화하므로 새 필드 소유 타입만 Rust 편집 범위에 필요하다. 프런트 게이트웨이와 훅도 typed 응답을
그대로 큐 상태로 전달한다. 실제 변경은 Rust·TypeScript 요약 타입과 대시보드 및 기존 화면 검사에서
닫히며 런타임 dispatcher, 상태 서비스, 명령 조립은 수정하지 않는다.
