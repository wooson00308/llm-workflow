# TASK-S051-06 개발 보고서

## 결정권자 요약

TASK-S051-06은 런타임 계약이 부족해 구현을 시작한 뒤 차단 상태로 전환했다.
현재 계약은 프로젝트 하나의 설정과 상태만 읽을 수 있어 서비스 상태와 실행 중 버전을 확인할 수 없다.
업데이트 전에 전체 실행 영향도 계산할 수 없으므로 사용자 확인을 안전하게 만들 수 없다.
사용자는 필요한 조회와 복구 계약을 런타임에 추가한 뒤 이 작업을 다시 요청해야 한다.

## 변경 파일과 모듈

- 제품 코드와 배포 구성은 변경하지 않았다.
- TASK-S051-06의 상태와 이 보고서만 갱신했다.

## 검증 절차와 결과

- 외부 런타임의 계약 조회를 실행했다. 구현된 명령은 계약 조회, 프로젝트별 설정 검증·저장·조회와 프로젝트별 상태 조회뿐이었다.
- 런타임의 상태 조회 구현을 읽었다. 요청마다 하나의 프로젝트 식별자가 필요하며, 전체 프로젝트의 실행 중 작업 수나 서비스 상태를 돌려주는 명령은 없었다.
- 독립 실행형 런타임의 배포 계약을 읽었다. 무결성 검증과 stable launcher 전환은 제공하지만 서비스 등록 상태와 실제 실행 버전을 기계가 읽는 응답은 제공하지 않았다.

## 남은 위험

- 앱이 현재 계약 밖의 상태 파일이나 운영체제 서비스 파일을 직접 읽으면 런타임의 저장소·서비스 소유 경계가 깨진다.
- 사람이 읽는 상태 출력의 문장을 해석하면 플랫폼과 버전 변화에 따라 설치·복구 판단이 잘못될 수 있다.

## 후속 작업

- 런타임에 설치된 버전, 실행 중 버전, 서비스 상태, 복구 가능 여부를 한 JSON 응답으로 돌려주는 조회 명령을 추가한다.
- 업데이트 계획에 전체 실행 중 작업 수와 프로젝트 목록을 제공하고, 서비스 재등록·복구 결과를 구조화해 반환한다.
- 위 계약이 버전과 자동 검사로 고정되면 TASK-S051-06을 다시 todo로 돌려 구현과 사용자 QA를 진행한다.
