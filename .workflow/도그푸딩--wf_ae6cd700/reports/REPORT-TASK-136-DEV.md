# TASK-136 개발 보고서

## 결정권자 요약

프로젝트를 열거나 수동 새로 고침할 때 관리 규칙 동기화가 끝난 뒤 사용자 정의 규칙을 읽도록 연결했다.
2.5초 자동 조회는 사용자 규칙을 읽기만 하고 미리보기나 저장 명령을 호출하지 않는다.
미리보기 준비 시점의 파일 식별값을 저장 기준으로 보존해, 외부 변경을 뒤늦게 읽어도 자동 덮어쓰지 않는다.
저장 성공, 외부 변경 충돌, 잠금 재시도와 명령 오류를 서로 다른 상태로 유지한다.
프로젝트를 바꾸거나 닫은 뒤 이전 프로젝트의 늦은 응답은 현재 상태를 덮어쓰지 못한다.
사용자 규칙 파일이 없거나 잘못됐거나 미래 형식이거나 안전하지 않아도 프로젝트 탐색은 유지된다.
프런트엔드 전체 검사 741개와 타입 검사, 배포 빌드, 변경 공백 검사가 통과했다.
이 작업에는 화면이 없으며 실제 편집 화면은 TASK-137에서 연결한다.

## 구현 내용

- 사용자 규칙 문서, 초안, 역할별 미리보기, 저장 요청과 결과, 작업 공간 상태와 동작을 도메인 타입으로
  정의했다.
- Tauri 게이트웨이에 조회, 미리보기 준비, 저장 명령을 백엔드 인자 이름 그대로 연결했다.
- 프로젝트 열기와 수동 새로 고침은 관리 자산 동기화 뒤 사용자 규칙을 읽고, 자동 조회는 읽기만 한다.
- 같은 내용 식별값이면 기존 문서와 미리보기·저장 알림을 유지하고, 값이 달라지면 디스크 상태만 갱신한다.
- 미리보기 준비 시점의 내용 식별값을 별도로 보관해 외부 변경 감지 뒤 저장도 충돌로 판정되게 했다.
- 조회, 미리보기, 저장마다 요청 번호와 프로젝트 경로를 확인해 늦은 이전 프로젝트 응답을 버린다.
- 명시적 다시 불러오기는 미리보기와 저장 임시 상태를 비우고, 알림 지우기는 디스크 문서를 유지한다.
