# TASK-135 개발 보고서

## 결정권자 요약

프로젝트별 사용자 정의 규칙 파일을 안전하게 읽고 저장하는 백엔드 계약을 추가했다.
저장 전에 실제 파일 내용과 세 역할의 규칙 출처를 백엔드에서 같은 기준으로 미리 계산한다.
파일 전체 해시를 비교해 외부 생성, 수정, 삭제, 교체를 감지하며 기존 내용을 자동 병합하지 않는다.
심볼릭 링크와 잘못된 형식은 사용자 규칙만 비활성화하고 프로젝트 조회와 관리 규칙 동기화는 유지한다.
공통 규칙과 세 역할 계약에는 사용자 규칙의 적용 조건과 우선순위를 명시했다.
전체 Rust 테스트 574개와 정적 검사, 포맷 검사, 변경 공백 검사가 통과했다.
설정 화면 연결은 TASK-136과 TASK-137에서 진행하며 이 작업은 백엔드 계약 확인을 기다린다.

## 구현 내용

### 파일 조회와 검증

- `.workflow/rules/custom.md` 한 파일을 `absent`, `valid`, `invalid`, `future_schema`, `unsafe_file`로
  구분한다.
- 정상 문서는 사용 여부, 적용 역할, 본문, 수정 시각, 파일 원문과 파일 전체 SHA-256 식별값을 반환한다.
- 알 수 없는 필드와 역할, 중복 역할, 잘못된 시각과 스키마를 임의로 보정하지 않는다.
- 본문은 LF로 정규화하고 UTF-8 64 KiB 제한과 제어문자 제한을 적용한다.
- 심볼릭 링크나 일반 파일이 아닌 항목은 대상 내용을 읽지 않는다.

### 미리보기와 저장

- 미리보기 명령은 고정된 수정 시각을 포함한 저장 파일 전체와 그 SHA-256 식별값을 반환한다.
- 기획자, 아키텍트, 개발자별로 공통 규칙, 해당 역할 계약, 사용자 본문을 읽는 순서대로 제공한다.
- 꺼진 규칙과 적용 대상이 아닌 역할도 사용자 출처를 생략하지 않고 비활성 사유를 반환한다.
- 저장 명령은 같은 초안과 수정 시각을 다시 직렬화해 미리보기 식별값을 확인한다.
- 마지막 조회의 파일 식별값과 현재 값을 비교한다. 값이 다르거나 심볼릭 링크로 교체되면 기존 파일을
  보존하고 충돌 결과를 반환한다.
- 관리 자산 동기화와 같은 프로젝트 쓰기 잠금을 사용한다. 잠금을 얻지 못하면 재시도 결과를 반환한다.
- 같은 디렉터리에 배타적으로 만든 임시 일반 파일을 동기화한 뒤 원자적으로 교체한다.

### 규칙 우선순위와 공개 명령

- 공통 규칙 버전을 14로, 기획자·아키텍트·개발자 계약을 각각 9·8·9로 올렸다.
- 공통 규칙과 세 역할 계약에 사용자 규칙보다 앱 규칙과 역할 계약이 우선한다는 조건을 추가했다.
- AGENTS는 같은 `custom.md` 경로를 안내하고 CLAUDE는 기존처럼 AGENTS를 불러오므로 두 도구가 같은
  사용자 본문을 읽는다.
- 도메인, 저장소, 서비스, Tauri 명령과 명령 등록에 조회, 미리보기, 저장 계약을 연결했다.
- 사용자 파일은 관리 자산 목록과 버전 비교에서 제외했다.

## 검증 결과

- 파일 없음, 정상, 꺼짐, 역할 제외, 형식 오류, 미래 스키마, 심볼릭 링크를 검사했다.
- 64 KiB 경계, 초과 입력, C0과 DEL 제어문자, 중복 역할과 알 수 없는 필드를 검사했다.
- 저장 파일 미리보기와 실제 저장 바이트가 같은지 비교했다.
- 외부 생성, 수정, 삭제, 심볼릭 링크 교체에서 충돌을 반환하고 외부 내용을 보존하는지 확인했다.
- 공용 잠금 경합과 임시 파일 생성 실패에서 기존 파일이 바뀌지 않는지 확인했다.
- 잘못된 사용자 파일이 있어도 프로젝트 조회와 관리 자산 동기화가 성공하고 파일 내용과 수정 시각이
  유지되는 저장소 통합 검사를 추가했다.
- `cargo test --manifest-path src-tauri/Cargo.toml`: 574개 통과, 실패 0개.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`: 통과.
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`: 통과.
- `git diff --check`: 통과.

## 남은 위험과 후속

- 이 작업은 화면을 추가하지 않는다. TASK-136이 프로젝트 상태와 명령 호출을 연결하고 TASK-137이 편집과
  확인 화면을 제공한다.
- 파일 저장은 같은 디렉터리의 원자적 교체를 사용하지만, 운영체제가 여러 외부 쓰기 주체를 하나의
  트랜잭션으로 묶어 주지는 않는다. 저장 직전 재확인과 전체 해시 비교가 이 범위의 동시 수정 방지 수단이다.
- 버전 증가에 따라 관리 자산 회귀 검사의 기대값도 14·9·8·9로 갱신했다.
