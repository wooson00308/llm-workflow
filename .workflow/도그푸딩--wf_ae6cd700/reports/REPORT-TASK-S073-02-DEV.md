# TASK-S073-02 개발 보고서

## 결정권자 요약

아키텍트 역할 계약과 공통 규칙에, 구성 확인 필요 상태의 기능을 아키텍트가 자동으로 맡는 절차를
적었다. 이 대상은 사용자 확인 반려 다음, 작업 정의 수정 앞 순서로 잡히고, 선점이 걸린 기능은
대상이 아니다. 세션은 같은 기능 식별자와 같은 구성 버전을 유지한 채 기능 문서와 그 기능의 작업
문서만 고치며, 사용자 결정 문서와 승인 기록과 판정 조건은 바꾸지 않는다. 문서 쪽에 고칠 곳이
없으면 그 판단을 기능 문서와 보고서에 남기고, 그 표시가 있는 동안 같은 구성 버전의 같은 기능은
다시 자동 대상이 되지 않는다. 공통 규칙 판 번호는 32로, 아키텍트 계약 판 번호는 21로 올랐고
기획자와 개발자 계약은 그대로다. 백엔드 시험 889건과 통합 시험 28건이 통합 전후로 모두 통과했다.
이 결과는 GROUP-073의 자동 검증 가운데 아키텍트 대상 절차 부분을 뒷받침한다.

## 바꾼 파일과 모듈

- `src-tauri/src/infrastructure/project_instructions.rs` — 설치되는 규칙 본문 하나만 고쳤다.
  - `ARCHITECT_RULES`: 대상 조건 한 항목, 대상 순서 한 문장, 선점 대상 지정, 새 절
    `## Repairing a group the app reports as a configuration error`, 마무리 절의 대상별 문장,
    역할 한 줄 요약을 더했다.
  - `WORKFLOW_RULES`: `### Work groups and group QA`에 두 항목, `## 6. Preserve the file contract`에
    한 항목을 더해 선택 필드 `configuration_unresolved_revision`과 본문 절
    `## 사람의 판단이 필요한 이유`를 적고, 둘 다 없는 기존 기능 문서가 그대로 유효하다고 밝혔다.
  - `WORKFLOW_RULES_VERSION` 31→32, `ARCHITECT_RULES_VERSION` 20→21. 두 본문 프론트매터의 같은
    값도 함께 올렸다. 기획자 12와 개발자 23은 건드리지 않았다.
  - 같은 파일의 시험: 설치된 본문을 읽어 완료 조건 C1부터 C9까지의 문장을 대조하는
    `records_the_configuration_error_repair_contract_in_the_installed_rules`를 새로 넣고, 판 번호를
    글자와 수로 대조하던 기존 시험 값을 새 판 번호에 맞췄다.

## 검증 절차와 결과

격리 사본에서 실행한 결과다.

- `cargo test --manifest-path src-tauri/Cargo.toml project_instructions` — 27건 통과. 새 시험이
  C1부터 C9까지를 덮고, 앞 판 갱신 시험 두 건과 내려쓰기 거부 시험이 함께 통과해 C10을 확인했다.
- `cargo test --manifest-path src-tauri/Cargo.toml` — 889건과 통합 28건 통과, 실패 없음.
- `cargo fmt --manifest-path src-tauri/Cargo.toml --check` — 통과. 처음 검사에서 새 시험 한 줄이
  걸려 `cargo fmt`로 정리한 뒤 다시 통과했다.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` — 경고 없이 통과.

통합 후보와 통합 결과다.

- 변경 커밋 `4d31794`, 바뀐 파일 하나(`project_instructions.rs`).
- 통합 직전 공유 기준이 후보의 기준과 두 번 어긋나 그때마다 후보를 현재 커밋 위로 옮기고 격리

- 통합 커밋에서 다시 돌린 백엔드 전체 시험도 889건과 28건 통과다. 격리 결과와 통합 결과가 같다.

## 남은 위험

- 이 작업은 규칙 본문만 바꾸므로 앱 화면과 상태 계산과 대상 판정은 그대로다. 계약이 말하는
  `configuration_unresolved_revision`을 실제로 읽는 쪽은 TASK-S073-01과 TASK-S073-03이며, 그
  두 작업이 끝나기 전까지 이 필드를 적어도 상태가 달라지지 않는다. 계약 문장이 먼저 서고 판정이
  뒤에 오는 것은 기능 문서가 정한 순서다.
- 이미 설치된 프로젝트의 규칙 파일은 아직 앞 판이다. 갱신은 앱의 관리 자산 동기화가 프로젝트를
  열 때 수행하며, 이 저장소 자신의 `.workflow/rules/`도 그때 새 판으로 바뀐다.
- 새 시험은 설치된 본문에서 문장을 찾는 방식이라, 뒤에 같은 문장을 다른 표현으로 다듬으면 시험이
  먼저 걸린다. 기존 계약 시험들과 같은 성질이다.

## 후속 작업

- 작업 문서 밖으로 나간 읽기는 없다. 기획서와 결정 문서를 열지 않고 작업 문서만으로 구현했다.
- 역할 밖 발견 사항 하나를 아키텍트에 넘긴다. 아키텍트 계약의 `## Completion` 절은 대상 종류마다
  마무리를 적는데 이번 대상이 그 목록에 없어 문장을 한 줄 더했다. 이 한 줄은 기능 문서의 변경
  범위 목록에 없는 편집이며, 대상을 더하면서 마무리 절만 비워 두면 계약이 서로 어긋나 넣었다.
  같은 이유로 역할 한 줄 요약에도 이 대상을 넣었다. 두 자리 모두 새 대상을 가리키는 문장이고
  기존 대상의 처리를 바꾸지 않는다.
