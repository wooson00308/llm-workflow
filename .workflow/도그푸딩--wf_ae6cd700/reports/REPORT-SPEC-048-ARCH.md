## 핵심 아키텍처 판단

### 사용자 파일은 관리 자산과 분리한다

`.workflow/rules/custom.md`는 앱이 형식을 검증하고 사용자의 명시적인 저장 요청에서만 쓰는 파일이다.
관리 규칙 설치 계획과 버전 갱신 대상에는 넣지 않는다. 이 경계가 있어야 앱 업데이트가 사용자 본문과
수정 시각을 바꾸지 않는다.

정규 형식은 스키마, 사용 여부, 적용 역할, 수정 시각과 Markdown 본문으로 제한한다. 역할은 세 값으로
닫고 순서를 정규화한다. UTF-8 본문은 64 KiB로 제한하며 탭과 줄바꿈을 제외한 제어문자를 거부한다.
첫 버전에 여러 파일을 암시하는 식별자나 이름 필드는 추가하지 않았다.

### 미리보기와 실제 저장 바이트를 같게 만든다

화면이 프론트매터나 최종 규칙을 조립하면 백엔드 저장 형식과 달라질 수 있다. 백엔드 미리보기 준비
명령이 고정된 수정 시각을 포함한 파일 전체를 만들고 SHA-256 미리보기 식별값을 반환한다. 저장 명령은
같은 구조화된 초안과 시각으로 다시 직렬화해 식별값을 확인한 뒤 그 바이트를 쓴다.

역할별 최종 규칙 미리보기도 백엔드가 설치된 공통 규칙, 해당 역할 계약, 사용자 규칙의 정확한 원문을
출처별로 반환한다. 사용자 규칙이 비활성화됐거나 역할에 적용되지 않아도 출처를 숨기지 않고 제외 이유를
표시한다. 읽는 순서와 우선순위가 다르다는 설명도 결과 계약에 포함한다.

### 동시 수정은 파일 전체 내용으로 판정한다

수정 시각만 비교하면 같은 시각의 변경이나 Git 교체를 놓칠 수 있다. 조회는 파일 전체 바이트의 SHA-256
식별값을 반환하고 저장 시 현재 파일과 다시 비교한다. 파일이 없던 상태도 하나의 기준으로 취급하므로,
조회 뒤 새 파일이 생긴 경우 저장이 거부된다.

형식이 잘못됐거나 더 새로운 스키마인 파일도 원문 식별값을 계산할 수 있으면 같은 보호를 받는다. 화면의
명시적인 덮어쓰기 확인은 동시 수정 검사를 생략하는 권한이 아니다. 확인 뒤에도 기준이 달라졌으면 다시
읽어야 한다.

### 마이그레이션과 저장을 같은 잠금으로 보호한다

사용자 파일 저장은 TASK-132의 공용 마이그레이션 잠금을 사용한다. 잠금을 얻지 못하면 재시도 가능한
결과를 반환하고 기존 파일을 유지한다. 저장은 같은 디렉터리의 새 일반 임시 파일과 원자적 교체를
사용한다. 심볼릭 링크와 일반 파일이 아닌 대상은 따라가지 않는다.

읽기는 마이그레이션 잠금 중에도 프로젝트를 막지 않는다. 저장만 잠금 획득에 실패한다. 잘못된 사용자
파일도 해당 규칙만 비활성으로 표시하며 관리 규칙 동기화와 프로젝트 문서 조회는 계속 동작한다.

### 편집 초안과 디스크 상태를 분리한다

작업 공간 훅은 디스크 상태와 명령 결과를 보존하지만 편집 초안은 설정 카드가 소유한다. 2.5초 자동
조회에서 내용 식별값이 바뀌어도 사용자의 입력을 교체하지 않는다. 카드가 편집 시작 때의 식별값과 최신
디스크 식별값을 비교해 저장을 막고, 사용자가 다시 불러오기를 선택할 때만 초안을 교체한다.

초안이 바뀌면 이전 미리보기를 무효화하고 새 미리보기를 준비해야 저장할 수 있다. 이 절차는 저장 전에
실제 파일과 역할별 최종 규칙을 확인한다는 요구를 화면 동작으로 보장한다.

### 관리 규칙이 항상 우선한다

TASK-135는 TASK-132의 파일별 버전 모델 위에서 공통 규칙을 14, 역할 계약을 기획자 9, 아키텍트 8,
개발자 9로 올린다. 공통 규칙과 세 역할 계약에 사용자 파일의 읽기 조건과 우선순위를 적는다. AGENTS와
CLAUDE는 같은 사용자 파일을 안내한다.

사용자 규칙은 작업 문서보다 높은 프로젝트 지시지만 앱 소유 상태, 승인 기록, 선점, 역할 분리, 한 세션
한 대상과 승인 전 구현 금지를 완화할 수 없다. 앱은 자연어 의미를 자동 판정했다고 주장하지 않는다.

## 남은 위험

1. 자연어 규칙의 의미 충돌은 자동 판정하지 않는다. 화면과 관리 규칙이 우선순위를 명시하지만, 외부
   에이전트가 그 지시를 어길 가능성까지 앱이 제거할 수는 없다.
2. SHA-256 식별값은 동시 수정 판정에 충분하지만 Git 작업이 같은 바이트로 되돌아오면 변경 이력을
   구분하지 않는다. 저장 결과가 같으므로 첫 버전에서는 허용한다.
3. 여러 파일을 하나의 파일 시스템 연산으로 저장하지 않는다. 사용자 파일 하나는 원자적으로 교체하고,
   관리 규칙 동기화는 TASK-132의 별도 계획을 따른다.
4. 2.5초 읽기 중 외부 파일이 계속 바뀌면 설정 카드가 반복해서 외부 변경을 알릴 수 있다. 자동 병합을
   하지 않는 대신 사용자가 안정된 시점에 다시 불러와야 한다.
5. 심볼릭 링크 대상은 안전을 위해 읽지 않으므로 오류 화면에서 원문을 제공할 수 없다. 사용자가 파일
   시스템에서 링크를 제거한 뒤 다시 불러와야 한다.
