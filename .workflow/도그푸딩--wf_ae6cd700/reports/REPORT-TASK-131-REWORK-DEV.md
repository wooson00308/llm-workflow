# TASK-131 QA 재작업 보고서

## 결정권자 요약

QA 의견에 따라 한국어 문체 안내를 다시 작성했다. 계약서처럼 보이던 표현을 일반적인 기획·개발 문서
표현으로 바꾸고, 어색한 비유를 허용하던 예외 조건을 삭제했다.
표 제목은 표현별 대안으로 변경했다. 공통 규칙의 세 가지 예시와 기존 문서에서 자주 발견된 네 가지
표현은 유지하되 설명을 자연스럽게 고쳤다.
전후 예문 세 쌍은 QA 의견에 따라 유지했다. 프런트 테스트 705개와 타입 검사, 빌드가 모두 통과했다.
지금 요청하는 것은 수정된 TASK-131의 사용자 확인이다.

## QA 의견 반영

최신 QA 결정은 QA-AFB67132이며 요청 사항 다섯 가지를 모두 반영했다.

1. `바꿔 쓸 낱말 대응표`를 `표현별 대안`으로 변경했다. 새 문체 안내에서는 `낱말`을 사용하지 않는다.
2. `문언`, `단일 정의`, `하한`, `되짚다` 같은 표현을 제거했다. 공통 규칙이 기준이라는 내용을 일반적인
   문장으로 다시 작성했다.
3. 대상을 명시하면 `표면`을 그대로 쓸 수 있다는 설명을 삭제했다. `데몬 인터페이스`와
   `데몬이 노출하는 API`처럼 구체적인 대안을 제시했다.
4. 예외 조건을 좁혔다. 한국의 기획·개발 문서에서 통용되는 표준 기술 용어이며 문장에서 정확한 의미로
   사용된 경우에만 원래 표현을 유지할 수 있다.
5. TASK-131의 결정권자 요약과 확인 절차도 현재 결과에 맞게 다시 작성했다. 기존 전후 예문 세 쌍은
   그대로 유지했다.

## 변경 결과

제품 문서 변경은 `docs/file-contract.md`의 `## 문서 문체` 섹션에 한정했다.

- 문체 기준을 짧고 직접적인 설명으로 교체했다.
- 표 제목과 열 이름을 `표현별 대안`, `피할 표현`, `문맥에 맞는 대안`, `사용 기준`으로 정리했다.
- 공통 규칙과 일치해야 하는 세 항목의 대안과 순서는 유지했다.
  - 착지: 구현, 반영, 병합, 배포
  - 닫다: 해결, 충족, 완료
  - 원천: 데이터 출처, 원본 문서, 판단 기준
- 자리, 몫, 어법, 표면의 대안은 더 구체적인 표현으로 정리했다.
- 표가 금지어 목록이 아니라는 점은 유지하되, 어색한 비유를 허용하는 근거로 사용하지 못하게 했다.

## 검증

- `npm run check`: 타입 검사 통과, 23개 파일의 프런트 테스트 705개 통과, 빌드 성공.
- `git diff --check`: 오류 없음.
- 새 문체 안내에서 QA가 지적한 `낱말`, `문언`, `하한`, `되짚다`를 설명 문장으로 사용하지 않음을 확인했다.
- 영문식 긴 대시를 사용하지 않았음을 확인했다.
- 제품 변경 범위는 `docs/file-contract.md` 하나다. 작업 문서, 보고서, 개발 로그는 워크플로 기록이다.
