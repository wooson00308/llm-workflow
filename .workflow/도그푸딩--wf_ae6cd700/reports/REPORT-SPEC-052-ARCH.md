# SPEC-052 아키텍트 인계 보고서

- 프로젝트: workflow-labs / 활성 워크플로: 도그푸딩
- 역할: 프로젝트 아키텍트
- 대상 승인: DECISION-F5091138, SPEC-052
- 산출 작업: TASK-S052-01부터 TASK-S052-04까지 4건, 모두 todo
- 제품 코드와 테스트 구현: 수행하지 않음

## 아키텍처 결정

1. 구조화 요약은 기존 `## 결정권자 요약` 안의 정확한 `###` 제목 순서와 영향 표식으로 판정한다.
   문장 의미, 비슷한 제목과 누락 값은 추측하지 않는다.
2. 완전한 구조만 값 모델로 분리한다. 평문·무요약·불완전 구조는 현재 Markdown 요약 또는 전체 원문
   경로로 폴백하고 오류나 부분 보드를 만들지 않는다.
3. 보드는 제안, 현재→변경 후→사용자 결과, 변경·유지 영향, 선택적 위험, 결정 요청 순서의 DOM을
   사용한다. 넓은 화면의 칸 배치는 CSS만 바꾸며 좁은 화면은 같은 순서로 한 열에 쌓는다.
4. 원문 토글은 보드의 대체 정본이 아니다. 열면 구조화 요약을 포함한 전체 Markdown 원문을 기존
   안전한 렌더러로 그대로 표시한다.
5. 새 기획서와 개발 작업의 구조는 현재 10줄 상한과 양립하지 않는다. 구조화 문서는 항목별 간결성
   규칙을 적용하고, 기존 평문 요약과 개발 보고서는 10줄 계약을 유지하도록 규칙 갱신 작업에 적었다.
6. 앱 내장 규칙만 버전 갱신한다. 설치된 `.workflow/rules/`, 문서 스키마, 결정 기록, 저장 HTML,
   요약 캐시, 네트워크와 LLM 경로는 만들거나 수정하지 않는다.

## 의존 관계

```text
TASK-S051-01 ─ TASK-S052-01

TASK-S051-10 ─┐
               ├─ TASK-S052-03 ─ TASK-S052-04
TASK-S052-02 ─┘
```

- TASK-S052-02는 즉시 시작할 수 있다. TASK-S052-01과 범위가 겹치지 않지만 기존 진행 작업과 같은
  규칙 소스를 수정하므로 TASK-S051-01 뒤에 선다.
- TASK-S052-03은 파서 모델을 사용하므로 TASK-S052-02 뒤에 선다.
- TASK-S052-03의 `src/App.css`는 TASK-S051-09와 TASK-S051-10의 범위와 겹친다. 둘의 기존 사슬
  마지막인 TASK-S051-10 뒤에 두어 앞선 화면 변경을 보존한다.
- TASK-S052-04는 제품 파일을 건드리지 않는 두 검토 화면의 종단 회귀 검사이며 보드 구현 뒤에 선다.

## 작업 문서 작성 계약에 대한 판단

이 세션에 적용되는 공통 규칙은 결정권자 요약을 빈 줄 제외 10줄 이하의 평문 절로 요구한다. 새 구조는
필수 하위 제목과 값만 세어도 그 상한을 넘으므로, 이번에 만든 네 작업의 요약을 구조화 형식으로 쓰면
상위 계약을 위반한다. 따라서 네 작업 자체는 현재 평문 형식을 따랐다. TASK-S052-01이 앱 내장 계약을
갱신한 뒤 새로 작성되는 기획서와 개발 작업부터 구조화 형식을 사용한다. 기존 문서 소급 수정 금지와도
같은 경계다.

## 병렬 안전과 범위

- 네 작업의 `scope_files`는 모두 한 줄 flow sequence이며 허용 문자만 사용한다.
- 새 작업끼리 겹치는 범위 파일은 없다. TASK-S052-03이 TASK-S052-02의 새 API를 사용하고
  TASK-S052-04가 TASK-S052-03의 공개 동작을 검증하는 기능 선행만 있다.
- 기존 미완료 작업과의 겹침은 규칙 소스 한 건과 CSS 두 건이다. 존재하는 마지막 작업 id를 선행에
  넣어 교차 승인 작업도 동시에 수정되지 않게 했다.
- 백엔드 문서 payload, gateway, 저장소, 기획서·작업 원문 쓰기 경로는 범위에서 제외했다. 현재 body
  문자열만으로 구조를 판정하고 표시할 수 있기 때문이다.

## 검증

- 최초 `sh .workflow/rules/wf-eligible.sh architect`는 `eligible`, 종료 코드 0이었다.
- `wf-claim.sh acquire SPEC-052 codex-architect-a-2 30`은 종료 코드 0으로
  `lease-33348-20260807080416`을 발급했고, 쓰기 전에 같은 lease를 30분으로 갱신했다.
- 네 작업은 schema, id, todo 상태, SPEC-052와 DECISION-F5091138 출처, created 이력, RFC3339
  시각과 요약의 첫 절·4줄 상한을 모두 통과했다.
- 전체 153개 작업의 의존 그래프에서 참조 누락과 순환이 없었다. 기존 미완료 작업과 겹치는 세 범위는
  TASK-S051-01·TASK-S051-09·TASK-S051-10의 선행 사슬로 모두 정렬됐다.
- 네 새 작업 사이에는 `scope_files` 중복이 없고 모든 선언은 설치본 판정 스크립트의 한 줄 형식과
  허용 문자 규칙을 따른다.
- 분해 뒤 architect 자격 검사는 `no-target`, 종료 코드 1이다. lease는 이 보고서를 완성한 뒤 helper로
  반납한다.

## 보호 상태와 인계

project manifest, workflow manifest, decisions, migration lock, 스키마 버전과 승인된 SPEC-052는
변경하지 않았다. 기존의 미커밋 제품 변경과 SPEC-051 산출물도 수정하지 않았다.

개발자는 각 작업 문서의 완료 조건과 검증 절차를 그 문서만으로 수행해야 한다. TASK-S052-04에서
보드 구현 결함을 발견하면 테스트 범위를 넓혀 제품 코드를 고치지 말고 TASK-S052-03의 수정으로
돌려보낸다.
