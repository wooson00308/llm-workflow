## 아키텍처 판단

### 조회 명령에 쓰기를 넣지 않는다

현재 `inspect_project`는 최근 프로젝트 열기, 폴더 열기, 상단 새로 고침, 2.5초 자동 조회가 함께 쓴다.
여기에 설치를 추가하면 자동 조회도 쓰기 동작이 된다. TASK-132가 별도 동기화 명령을 만들고,
TASK-133이 명시적인 열기와 수동 새로 고침에서만 호출한다.

### 선점 헬퍼까지 한 번에 사전 검사한다

현재 공통 규칙 묶음과 선점 헬퍼는 별도 설치 호출이다. 규칙을 쓴 뒤 헬퍼 충돌을 발견하면 일부 자산만
갱신된다. TASK-132는 공통 규칙, 세 역할 계약, 두 진입 안내, 현재 운영체제의 선점 헬퍼를 하나의
계획으로 검사한다. 검증 충돌이나 계획 뒤 외부 변경이 있으면 저장을 시작하지 않는다.

### 역할 계약은 각자 제공 버전을 사용한다

현재 설치 판정은 세 역할 계약에 공통 기준 버전 8을 적용한다. 실제 제공 버전은 기획자 8, 아키텍트 7,
개발자 8이다. 이 상태에서는 설치된 아키텍트 버전 8을 앱보다 새로운 파일로 보호하지 못한다.
TASK-132가 자산 서술에 각 버전을 넣고 결과에도 설치·제공 버전을 각각 반환한다.

### 동기화와 마이그레이션이 같은 잠금을 획득한다

잠금 파일 존재를 먼저 확인하는 방식만으로는 확인 직후 시작되는 마이그레이션과의 경합을 막을 수 없다.
두 쓰기 경로가 같은 배타 잠금 구현을 사용하고 계획부터 마지막 저장까지 잠금을 유지한다. 마이그레이션이
먼저 실행 중이면 동기화는 재시도 가능한 결과를 반환한다. 파일 충돌과 잠금 경합은 다른 상태다.

### 동기화 상태는 프로젝트 오류와 분리한다

동기화 충돌이 일반 프로젝트 오류가 되면 읽을 수 있는 프로젝트까지 닫힐 수 있다. 반대로 한 상태에
섞으면 2.5초 자동 조회가 오류를 지울 수 있다. TASK-133은 프로젝트 조회 결과를 먼저 보존하고
동기화 진행·결과·호출 오류를 별도 상태로 유지한다. TASK-134는 그 상태를 설정과 공통 알림에 표시한다.

## 남은 위험

1. 여러 파일의 원자적 교체를 파일 시스템 하나의 연산으로 묶을 수는 없다. 이 분해는 모든 검증 충돌과
   기준 변경을 쓰기 전에 발견하고 각 파일을 원자적으로 교체한다. 저장 도중 기기 전원이 꺼지는 경우까지
   전체 파일 묶음의 원자성을 보장하지는 않는다.
2. 공용 잠금 파일은 기존 이름을 유지한다. 동기화 중에도 짧게 마이그레이션 잠금으로 보일 수 있다.
   화면은 이를 재시도 상태로 설명해야 한다.
3. SPEC-048 분해가 이번 작업 범위를 읽지 않고 독립적으로 시작하면 설정과 규칙 설치기에서 충돌할 수
   있다. TL이 SPEC-048 아키텍트에게 TASK-132부터 TASK-134까지의 선행 조건을 전달해야 한다.
4. 설치 버전이 없는 두 진입 안내에는 숫자 상태를 표시할 수 없다. 관리 블록의 정상·변경 필요·충돌만
   표시하고 버전을 추정하지 않는 것이 의도한 동작이다.
