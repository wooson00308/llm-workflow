- QA를 개발 상태 확인의 부속 조작이 아니라 사용자 결정 과업으로 분리했다. 주요 메뉴의 `품질 확인`과 오늘
  화면의 기능 QA 항목이 같은 전용 작업대로 이어진다.
- 대기열의 판단 단위를 작업 문서가 아니라 기능으로 정했다. 같은 기획서의 QA 대기 작업이 여러 건이어도
  사용자는 하나의 기능 흐름으로 시작한다. 준비되지 않은 묶음은 남은 작업 수만 보여 주고 시작시키지 않는다.
- 기능 세션은 모든 QA 대기 작업을 목록에 남긴다. 평문 표현을 추측해 자동 근거 항목을 숨기지 않으며,
  자동 근거는 시각적 무게만 낮추고 제목과 상태와 건수는 유지한다.
- 결과는 항목에서 즉시 쓰지 않고 보류 중 검토로 모은다. 마지막 검토 화면이 오클릭 방지 단계이므로 시간
  제한 이중 클릭은 쓰지 않고, 최종 버튼이 완료와 재작업 요청 건수를 직접 말하게 했다.
- 기능 단위 입력이 파일 계약을 바꾸지 않게 했다. 제출 시 기존 결과 어휘와 작업별 QA 결정과 상태 전이를
  그대로 사용하고, 합쳐진 새 결정 문서나 새 작업 상태는 만들지 않는다.
- 사용자 이탈을 실제 사용 흐름으로 취급했다. 제출 전 임시 검토는 기기에 보존하지만 정식 문서에는 쓰지
  않으며, 작업이 바뀌면 다시 확인 필요로 표시해 오래된 판단의 제출을 막는다.
- 혼합 결과와 부분 실패를 명시했다. 한 세션에서 일부는 완료하고 일부는 재작업 요청할 수 있으며, 기록
  실패가 생기면 성공과 실패를 건별로 보여 주고 실패 항목의 입력만 재시도할 수 있게 했다.

  규칙을 재사용하면서 중복 제출을 막고 건별 결과를 돌려줘야 한다.

- 현재 자동 근거 분류는 평문 표현에 의존한다. 새 기획은 항목을 숨기지 않는 것으로 오분류의 사용자 영향을
  줄이지만, 새 분류 필드나 규칙 계약을 도입하지 않는다.
- 승인 전에는 아키텍처 분해나 구현을 진행하지 않는다.
