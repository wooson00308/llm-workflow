## 이 기획서가 정한 것

아이디어가 사용자 결정 셋(앱 LLM 호출 기각, 파일 하나·독자별 양식, 역할별 면제 없음)을 못박아 두었으므로
그 셋은 되묻지 않고 전제로 깔았다. 기획 판단으로 정한 것은 다음과 같다.

1. **요약 절의 자리를 본문 맨 앞으로 고정.** 근거는 `markdown_excerpt`가 본문 앞 세 줄에서 미리보기를
   만든다는 실측이다(확인 사실 10). 자리를 맨 앞에 두면 표시 코드를 한 줄도 고치지 않고 아이디어 카드·
   작업 카드·검색 결과의 미리보기가 요약으로 바뀐다. 즉 이 계약 변경은 IDEA-61927447(표시)의 착지를
   기다리지 않고 값을 낸다.
2. **절 이름을 문서 종류 전체에서 하나로.** 후속 표시 기획서가 찾을 토큰이 하나여야 한다는 이유이고,
   구체적 문자열은 사용자 취향이 걸리므로 확인 필요 4번으로 뺐다.
3. **검사 장치는 만들지 않는 쪽을 제안.** 이 저장소에 문서 본문을 읽는 자동 장치가 하나도 없고
   (확인 사실 12), 검사를 만들면 실행 자리와 실패 처리를 함께 정해야 하며 R8(요약 없는 옛 문서 355건이
   그대로 유효)과 충돌 지점이 생긴다.
4. **자격 판정 불변을 명시적 제외 범위로.** 요약이 없다고 세션이 못 뜨거나 작업이 닫히는 상태를 만들지
   않는다는 것을 요구사항(R8)과 제외 범위 양쪽에 적었다.
5. **아이디어 문서는 대상에서 뺀 쪽을 제안.** 사용자가 앱에서 직접 쓰는 자리라(확인 사실 18) 계약을
   걸면 사용자 문서가 위반이 된다. 확인 필요 3번.

## 사용자 결정이 필요한 자리

확인 필요 넷 중 1번이 가장 크다. **QA 동선 절을 작업 문서에 쓸지 보고서에 쓸지**이고, 실측 근거는
"앱이 보고서를 열지 못한다"(개수만 세고 읽기 경로가 없다, 확인 사실 7)와 "QA 화면에 이미 작업 문서
본문이 펼쳐져 있다"(확인 사실 6)다. 보고서 쪽을 고르면 사용자가 그 절을 읽는 시점이 IDEA-61927447의
보고서 읽기 경로 신설 이후로 미뤄진다. 나머지 셋은 검사 장치 여부, 아이디어 문서 포함 여부, 절 이름이다.
