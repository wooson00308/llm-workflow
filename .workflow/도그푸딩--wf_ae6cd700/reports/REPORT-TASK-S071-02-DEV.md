# TASK-S071-02 개발 보고서

## 결정권자 요약

자동으로 세션을 시작하는 두 경로가 모두 지나는 조건 검사 자리에, 실행 도구가 사용 한도로 대기 중이면
그 도구를 쓰는 역할에 배정할 대상을 내주지 않는 관문을 세웠다. 관문은 후보를 하나도 보기 전에 서고,
대상이 비어 나가므로 예약도 서지 않는다. 다른 실행 도구를 쓰는 역할은 평소대로 배정된다. 재개 시각이
지나면 사용자가 아무 조작을 하지 않아도 배정이 저절로 돌아온다. 판정에 필요한 값을 하나라도 읽지
못하면 보류를 걸지 않고 지금과 똑같이 배정하므로, 확인 실패가 배정을 멈추는 일은 없다. 역할과 실행
도구의 대응은 프로젝트 안 파일로 남기고, 역할 설정을 읽거나 저장할 때 갱신한다. 백엔드 888건과 통합
시험 28건, 화면 시험 520건이 통과했고 형식 검사와 정적 분석, 생산 빌드도 통과했다. 이 결과는
GROUP-071의 자동 검증 가운데 배정을 멈추는 부분을 뒷받침한다.

## 이어받은 자리와 잔여물 판단

이 작업은 상태가 이미 in_progress였고, 앞 세션의 선점은 이 세션에 그대로 넘어왔다. 남은 잔여물을
다음과 같이 갈랐다.

- 이어받은 것: 작업 문서의 in_progress 전이 한 건뿐이다. 이력에 2026-08-18T11:11:30Z 항목이 있고,
  이 세션이 시작할 때는 아직 공유 저장소에 커밋되지 않은 상태였다(뒤에 다른 세션의 문서 전용 커밋이
  함께 실었다). 유효한 전이 기록이므로 그대로 두고 인계 항목을 덧붙이지 않았다 — 상태가 바뀌지
  않았고 이력은 상태 전이에만 항목을 더한다.
- 버린 것: 없다. 격리 사본은 작업 트리가 깨끗했고 브랜치가 기준 커밋과 같아, 앞 세션이 남긴 제품
  코드가 한 줄도 없었다. 시험을 지우거나 고친 것도 없다.
- 새로 쓴 것: 완료 조건 C1부터 C19까지의 구현 전부다. 앞 세션은 코드를 시작하기 전에 멈췄다.
- 작업 문서의 본문(범위와 완료 조건)은 손대지 않았다.

## 바꾼 파일과 모듈

- `src-tauri/src/infrastructure/provider_hold.rs` — 역할·실행 도구 대응표를 쓰는 함수와 그 형식을
  더했다. 이름 안전 집합 판정을 기존 기록 경로 조립과 함께 쓰도록 한 자리로 뺐다.
- `src-tauri/src/commands/agent_runtime.rs` — 정책을 읽는 커맨드와 저장하는 커맨드가 각자의 블로킹
  구간 안에서 대응표를 갱신한다. 쓰기 실패는 두 커맨드의 응답을 바꾸지 않는다.
- `src-tauri/src/infrastructure/heartbeat_condition.rs` — 셸·PowerShell 두 본문에 한도 대기 관문을
  더하고 판 번호를 22에서 23으로 올렸다. 사유 코드 목록과 시나리오 표, 판 번호를 대조하는 시험을
  함께 고쳤다.
- `src-tauri/src/infrastructure/role_eligibility.rs` — 모듈 주석의 알려진 차이 목록에 여섯째 항목을
  더했다. 판정 코드는 고치지 않았다.
- `docs/file-contract.md` — 디렉터리 그림에 대응표를 넣고, 대응표와 기기 단위 보류 기록의 자리·본문
  형식·시각 표기·읽지 못했을 때의 처리를 본문 절로 적었다.

설계 판단 두 가지를 적어 둔다. 시각 비교는 새로 만들지 않고 lease 만료 판정을 그대로 썼다. 셸은
기존 `lease_unexpired`를 부르고, PowerShell은 `Test-Leased` 안에 있던 비교를 `Test-StampAhead`로
빼서 두 자리가 함께 쓴다. 그리고 시나리오 러너가 프로젝트 루트 아래 `.test-home`을 사용자 홈으로
물려 주게 했다 — 관문이 홈 아래에서 기록을 찾으므로, 그러지 않으면 검사를 돌리는 사람의 기기에 남은
보류 기록 하나가 표 전체의 답을 바꾼다.

## 검증 절차와 결과

격리 사본과 통합 후 결과를 함께 적는다. 통합 직전에 공유 기준이 312d7c3에서 d3b497c로 바뀌어 있어,
변경을 그 커밋 위로 옮기고 아래 검사를 다시 돌린 뒤 통합했다. 아래 숫자는 옮긴 뒤의 값이다.

1. `cargo test --manifest-path src-tauri/Cargo.toml heartbeat_condition` — 55건 통과. 새 사유 코드와
   시나리오 여섯 행이 들어 있다.
2. `cargo test --manifest-path src-tauri/Cargo.toml provider_hold` — 통과. 대응표 검사 네 건이
   들어 있다.
3. `cargo test --manifest-path src-tauri/Cargo.toml role_eligibility` — 99건 통과. 판정 결과가
   변하지 않았다.
4. `cargo test --manifest-path src-tauri/Cargo.toml` — 888건 + 통합 28건 통과, 실패 0.
5. `cargo fmt --manifest-path src-tauri/Cargo.toml --check` — 통과.
6. `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` — 통과.
7. `npm run check` — 시험 파일 29개, 520건 통과(42건 건너뜀). 형식 검사와 생산 빌드도 통과.
8. `git status` — 변경 파일이 선언한 다섯 개뿐이다. `.workflow` 아래 변경은 없다.

통합은 411d6f0으로 빨리 감기 병합했다. 통합 후 검사는 그 커밋과 같은 자리에서 작업 트리가 깨끗한
격리 사본으로 돌렸고, 위 1번부터 7번까지가 모두 그 커밋의 결과다. 격리와 통합에서 갈라진 결과는 없다.

## 남은 위험

- PowerShell 본문은 이 기기에서 실행 검증을 하지 못했다. PowerShell이 설치되어 있지 않아 문자열
  대조 시험만 통과했고, 실행 결과 대조는 Windows 러너에서 처음 선다. 두 본문이 갈라지면 그 러너가
  실패한다. 이 파일의 기존 조건과 같은 상태다.
- 대응표는 사용자가 설정 화면을 한 번도 열지 않은 프로젝트에는 생기지 않는다. 그 상태에서는 관문이
  서지 않고 지금과 같이 배정되므로 회귀는 아니지만, 한도 보류도 걸리지 않는다.
- 대응표의 정본은 실행 환경의 정책이고 이 파일은 사본이다. 실행 환경에서 정책이 바뀌고 앱이 그것을
  아직 읽지 않은 구간에는 옛 대응이 남는다. 그 구간에 잘못 걸린 보류는 재개 시각이 지나면 풀린다.
