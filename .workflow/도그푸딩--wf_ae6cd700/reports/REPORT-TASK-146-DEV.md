# TASK-146 개발 보고서

## 결정권자 요약

provider 실행을 시작, 감시, 종료, 취소, 복구 다섯 단계로 나눈 수명 계약을 구현했다.
실행 핸들은 예약한 대상과 lease를 함께 담아, 끝난 실행이 예약한 작업과 같은지 대조할 수 있다.
런타임이 다시 시작돼도 프로세스 생성 신원을 대조해 같은 프로세스만 이어받고, 마지막으로 읽은 위치부터 이벤트를 중복 없이 이어 읽는다.
프로세스 번호만 같거나 신원을 확인할 수 없으면 실행 중으로 채택하지 않고 복구 필요로 분류한다.
취소는 자식 프로세스까지 사라진 것을 확인해야 완료로 보고하고, 확인하지 못한 단계와 남은 lease 정리를 함께 돌려준다.
예약이 실패했거나 요청이 예약과 다르면 provider를 한 번도 시작하지 않는다.
전용 자동 검사 12건을 추가했고 기존 검사는 하나도 고치지 않았다.
사용자는 작업 문서의 확인 동선에 적힌 세 명령의 수치를 확인하면 된다.

## 인계받은 상태와 이번 범위

작업 문서의 "현재 상태" 절은 TASK-S051-03 재작업 이전 기준이라 실제와 다르다. 재작업은 이미 시작
즉시 핸들 반환, 실행별 append-only JSONL 이벤트 파일, byte offset 감시, 단계별 취소, 기존 동기식
호환 경로를 구현해 두었다. 그래서 이번 작업은 그 부분을 검사로 확인만 하고, 빠져 있던 예약 대조,
핸들의 예약 대상·lease, 복구 경로, 정리 단계 보고를 구현했다.

## 변경 파일과 모듈

- `src/heartbeat/providers/lifecycle.py`: 새 모듈. 예약 응답 읽기, 예약과 요청 대조 후 시작,
  종료·취소 결과와 남은 정리 단계, 복구 판정을 담는다. provider 프로세스 세부 구현에 의존하지
  않고 공통 인터페이스만 사용한다.
- `src/heartbeat/providers/process.py`: 실행 요청과 실행 핸들에 lease 식별자를 추가하고 시작이
  이를 핸들에 옮긴다. PID 관측을 생존 여부와 생성 신원으로 나눠 돌려주는 함수를 추가했고, 기존
  신원 조회 함수는 그 함수를 쓰도록 바꿨다. 반환값과 기존 동작은 같다.
- `src/heartbeat/providers/__init__.py`: 새 수명 타입과 함수, 계약 버전을 공개했다.
- `tests/test_agent_provider_lifecycle.py`: 새 검사 12건. 가짜 CLI를 실제 Claude·Codex provider
  클래스에 연결해 정규화까지 실제 코드로 검사한다.
- `docs/provider-lifecycle-contract.md`: 새 계약 문서. 시작 실패 단계, 핸들 필드, offset 규칙,
  정리 단계, 복구 판정, 예약 응답 필드를 표로 정리했다.

## 설계 판단

- 예약 대조는 provider 밖 수명 계층에서 한다. 대상·lease·역할이 하나라도 다르면 provider를
  건드리기 전에 거절하므로 "시작 호출 0회"가 구조로 보장된다.
- 이벤트 마감 여부는 이벤트 파일의 마지막 완결 이벤트가 종료 종류인지로 판정한다. 실행을 시작한
  객체가 사라진 뒤에도 같은 판정을 내릴 수 있어야 복구 경로에서 쓸 수 있기 때문이다.
- lease 반납은 이번 범위 밖이므로 실행에 lease가 있으면 항상 남은 단계로 표시만 한다. 수명 모듈은
  lease 파일을 읽지도 쓰지도 않는다.

  확인했다.

## 작업 문서 밖에서 확인한 것

작업 문서는 예약 성공 응답의 대상, lease, 결과 식별자 접두어와 역할 인계문을 "변경하지 않고
사용한다"고만 적어 실제 필드 이름과 종료 코드가 없었다. 그래서 SPEC-054의 R4와 workflow-labs의
예약 헬퍼 구현·검사를 읽어 필드 이름 여덟 개와 종료 코드 0·1·2의 의미를 확인한 뒤 계약 문서에
그대로 옮겼다. 실행 계약을 다루는 작업 문서에는 소비할 응답의 필드 이름을 처음부터 적어 두면
좋겠다.

## 남은 위험

- 검증은 macOS에서만 실행했다. Windows와 Linux는 실측하지 않았다.
- 복구 성공은 "같은 프로세스임을 확인하고 남은 이벤트를 이어 읽는다"는 뜻이다. 이벤트를 기록하던
  감시 스레드가 죽으면 새 이벤트는 더 쌓이지 않으며, 이 한계는 계약 문서에 적었다. 감시 프로세스
  종료는 새 provider 객체로 대체해 재현했고 실제 런타임 강제 종료는 재현하지 않았다.
- 예약 실패·경합·마이그레이션 잠금은 예약 헬퍼를 직접 실행하지 않고 헬퍼가 내는 종료 코드와
  출력으로 재현했다. 헬퍼 자체의 동작은 workflow-labs의 기존 검사가 보증한다.
- 종료 확인 실패 검사는 프로세스 트리 종료 함수가 "확인하지 못함"을 돌려주도록 주입해 재현했다.
  실제로 살아남는 자손 프로세스를 만든 것은 아니다.

## 후속 작업

- TASK-S051-04의 dispatcher는 이 핸들을 저장하고, 종료 결과의 남은 단계를 보고 lease를 반납하며,
  복구한 실행을 정지시킬 방법을 정하면 된다.
- 작업 문서의 "현재 상태" 절이 선행 작업 재작업 이전 기준으로 남아 있다. 본문은 아키텍트 소유라
  고치지 않았고 인계 사항으로 남긴다.
- 기존 격리 실패 1건의 잡 디렉터리 격리는 여전히 별도 작업이 필요하다.
