# TASK-S066-01 개발 보고서

## 결정권자 요약

앱이 기능 설명으로 읽어 오던 값을 기능 소개 문단 하나로 좁혔다. 지금까지는 문서 제목과 소개 절
제목만 걷어내고 나머지를 전부 실었기 때문에 작업 분해 근거와 품질 확인 방식 설명까지 딸려
왔는데, 이제는 소개 절이 있으면 그 절의 본문만, 없으면 제목 다음부터 첫 절 제목 앞까지만 읽는다.
문단 안에서 나뉜 줄은 공백 하나로 이어 붙이고 문단 사이는 빈 줄 하나로 남겨, 이 값을 쓰는 화면이
문단을 살려 그릴 수 있게 했다. 저장소의 기능 문서 67건에 새 규칙을 적용해 확인한 결과 소개가
비는 문서는 없었고, 소개 길이는 33자에서 852자 사이였다. 사용자 확인 플로우 시나리오를 뽑는
동작과 시나리오 식별자 판정은 시험으로 같은 답을 확인했다. 문서 파일은 한 건도 바뀌지 않았다.
자동 검사는 백엔드 866건과 통합 시험 25건, 화면 시험 505건이 모두 통과했고 형식 검사와 정적
분석도 통과했다. 격리 사본에서 통과한 뒤 공유 기준으로 통합했고, 통합한 커밋을 깨끗한 사본에서
다시 검사해 같은 결과를 얻었다. 이 결과는 GROUP-066의 사용자 확인을 준비하는 증거다.

## 변경한 파일과 모듈

`src-tauri/src/infrastructure/fs_project_repository.rs` 하나만 바꿨다. 선언한 범위 밖의 파일과
`.workflow` 아래 문서는 건드리지 않았다.

- `parse_work_group_body`에서 기능 설명을 모으던 마지막 분기와 `description_lines` 누적을
  걷어냈다. 시나리오를 모으는 분기와 `structure_valid` 계산은 문장 그대로 두었다(C6).
- 소개를 뽑는 `parse_work_group_description`을 새로 넣었다. `## 기능 설명` 절이 있으면 그 절의
  본문을, 없으면 문서 제목 줄 다음부터 첫 절 제목 앞까지를 쓴다(C1, C2). 절 제목은 우물 정 기호
  두 개 이상으로 시작하는 줄로 판정하므로 시나리오 절 제목도 소개를 끝낸다(C3). 문단 안의 줄은
  공백 하나로 잇고 문단 사이는 빈 줄 하나로 남기며 값 전체의 앞뒤 공백을 잘라 낸다(C4). 뽑을
  내용이 없거나 공백뿐이면 빈 문자열을 준다(C5).
- `parse_work_group_body`의 반환 타입과 호출부, `WorkGroupSummary`의 필드 이름과 타입은 그대로
  두었다(C7). 이번 변경은 그 필드에 담기는 문자열만 바꾼다.
- 시험 네 건을 새로 넣고, 시험 모듈의 `use super` 목록에 `parse_work_group_body`를 더했다(C8).

## 남은 위험

- 소개 안에 목록이나 인용, 표를 쓴 기능 문서가 나오면 줄이 공백 하나로 이어 붙어 모양이
  깨진다. 지금 저장소에는 그런 문서가 없다.
- 문서 제목 줄을 `# `로 시작하는 줄로 판정한다. 제목을 밑줄 방식으로 쓴 문서는 소개가 본문
  처음부터 잡히므로 제목이 값에 섞인다. 지금 저장소에는 그런 문서가 없다.
- 이번 변경은 값만 좁힌다. 화면의 줄 수 상한과 문단 그리기는 TASK-S066-02가 맡았고 이미
  verified 상태다.
