# TASK-132 개발 보고서

## 결정권자 요약

TASK-132의 관리 자산 동기화 백엔드와 세 차례의 QA 재작업을 완료했다.
복원 대상은 같은 파일시스템에 먼저 격리하고 대상 경로가 비었을 때만 검사 전 내용을 복원한다.
따라서 동시에 새로 쓴 사용자 파일을 덮거나 삭제하지 않으며 격리본의 복구 위치도 결과에 남는다.
한 자산의 복원이 실패해도 나머지를 모두 처리하고 최초 충돌과 자산별 실패 사유를 함께 반환한다.
기존 생성·결정·단건 QA·일괄 QA 경로의 충돌 오류에도 보존된 복구 위치가 빠지지 않는다.
역할 계약은 각자의 실제 제공 버전으로 판단해 더 새로운 설치본을 보호한다.
동기화와 마이그레이션은 같은 배타 잠금을 쓰고, 문서 조회는 계속 읽기 전용이다.
Rust 테스트 562개와 포맷·정적 검사가 통과했다. 화면 변경은 없으며 사용자 확인을 기다린다.

## 구현 내용

### 전체 사전 검사와 저장

- `src-tauri/src/infrastructure/managed_project_assets.rs`에 일곱 종류의 관리 자산을 하나의 계획으로
  조정하는 모듈을 추가했다.
- 공통 규칙, 세 역할 계약, AGENTS와 CLAUDE 진입 안내, 현재 운영체제의 선점 헬퍼를 모두
  읽은 뒤 충돌이 없을 때만 저장을 시작한다.
- 계획을 만들 때 읽은 바이트와 저장 직전의 파일을 대조한다. 기준이 달라지면 해당 파일을 덮어쓰지 않고
  충돌 결과를 반환한다.
- 순차 저장 중 후속 자산의 변경을 보면 이미 교체한 자산을 역순으로 모두 복원한다. 하나가 실패해도
  나머지 자산 처리를 계속한다.
- 복원 대상을 같은 부모 디렉터리 아래의 고유한 복구 디렉터리로 원자적 이동한 뒤, 대상 경로가 없을 때만
  검사 전 내용을 복원한다. 대상 경로에 새 파일이 생기면 조건부 이동이 실패하므로 사용자 내용을 덮어쓰지 않는다.
- 격리한 파일은 안전하게 삭제할 수 있는 시점을 OS 공통 인터페이스로 증명할 수 없다. 열린 핸들이 격리 후에 같은
  파일에 쓸 수 있으므로 복구 디렉터리를 남기고, 동기화 결과에 자산별 복구 위치를 담는다.
- 원래 없던 파일은 격리로 앱 파일을 제거한다. 격리 후 외부 파일이 새로 생기면 그 파일을 삭제하지 않고 복원 실패로
  기록한다.
- 규칙과 역할 계약, 두 진입 안내, 현재 운영체제의 선점 헬퍼가 UTF-8이 아니면 자산 식별자와 이유를
  담은 구조화된 충돌로 분류한다. 손상된 바이트는 변경하지 않는다.
- 저장은 파일별 임시 파일과 원자적 교체를 사용한다. 같은 내용은 다시 쓰지 않는다.

## 남은 위험과 후속

1. 파일 시스템은 여러 파일의 교체를 하나의 원자적 트랜잭션으로 제공하지 않는다. 이 구현은 저장 전
   전체 충돌과 기준 변경을 검사하고 파일별 원자적 교체를 사용한다. 그래도 파일 교체 사이에 기기 전원이
   끊기면 전체 파일 묶음이 모두 이전 상태이거나 모두 새 상태임을 보장할 수 없다. 다음 동기화가 남은 낮은
   버전을 다시 갱신할 수 있다.
2. 복원이 실행되면 각 자산 옆에 복구 디렉터리가 남는다. 이는 격리 파일을 열어 둔 외부 프로세스의 후속 쓰기를
   보존하기 위한 의도된 동작이다. 결과가 자산별 복구 위치를 제공하며, 자동 정리는 이 작업 범위에 포함하지 않았다.
3. 대상 격리는 같은 부모 디렉터리 안의 이동이라 같은 파일시스템에서 원자적이다. 조건부 복원은 지원 OS에서 덮어쓰기 금지
   이동을 사용하고, 그 기능이 없는 파일시스템은 기존 대상 생성을 실패시키는 하드링크로 대체한다. 이 대체 경로는
   비정상 종료 시 복구 위치에 추가 링크를 남길 수 있지만 기존 파일을 덮어쓰지는 않는다. 이 제약은 백엔드 안전성을 막는
   요소가 아니라 복구 위치에 보수적으로 파일을 더 남길 수 있는 제약이다.
4. TASK-133이 별도 동기화 명령을 프로젝트 열기와 수동 새로 고침에 연결한다. TASK-134가 화면에 결과를
   표시한다.
