## 대상 도구 실측 확인

기획서 R2~R5의 근거로 실제 설치본(`~/Git/claude-heartbeat`, `~/.claude/`)을 읽어 확인한 사실이다. 추정으로 쓴 항목은 없다.

- 파서는 `## `로 시작하는 줄과 `- `로 시작하는 줄만 읽는다(`src/heartbeat/core.py`). 그래서 HTML 주석 마커 블록을 넣어도 잡 파싱이 깨지지 않는다. 관리 블록 방식의 전제가 실제로 성립한다.
- 전역 설정(`tick`)은 첫 `##` 헤더 앞에서만 읽힌다. 관리 블록을 파일 앞쪽에 삽입하면 사용자의 `- tick:` 줄이 관리 잡의 필드로 흡수돼 조용히 무력화된다. R2에 "항상 파일 끝에 붙인다"를 넣은 이유다.
- 같은 이유로, 관리 블록 종료 마커 뒤에 사용자의 `- key: value` 줄이 이어지면 그 줄은 블록의 마지막 잡에 흡수된다. 마커만 검사해서는 못 잡는 손상 형태라 R2에 별도 실패 조건으로 넣었다.
- `condition`은 프로젝트 cwd에서 10초 타임아웃으로 실행되고 exit 0일 때만 잡이 돈다. 상대 경로 조건 명령이 성립한다.
- 상태는 `~/.claude/heartbeat/state.json`에 **잡 이름을 키로** 기록된다. 프로젝트가 달라도 잡 이름이 같으면 `last_run`과 `max_per` 쿼터가 섞인다. R2의 "잡 이름은 프로젝트마다 달라야 한다"는 여기서 나왔다.
- `slug` → 경로 역변환은 실제 디렉터리를 탐색하는 그리디 추정이다(하이픈 포함 폴더명 때문). 앱은 정변환만 하고 결과를 사용자에게 보여주는 쪽이 안전하다.
- 기본값 표(R3)는 현재 도그푸딩 `~/.claude/HEARTBEAT.md`에서 실사용 중인 값을 그대로 옮긴 것이다.

2. **Windows 지원**: 조건 검사 실패는 하트비트에서 skip으로 처리된다. Windows에 `sh`가 없으면 증상이 "에러"가 아니라 "아무 일도 안 일어남"이라 사용자가 원인을 못 찾는다. 그래서 무시하지 않고 명시적 결정 항목으로 올렸다.
