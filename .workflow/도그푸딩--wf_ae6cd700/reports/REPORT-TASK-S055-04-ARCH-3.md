# TASK-S055-04 세 번째 정의 수정 보고서

## 결정권자 요약

TASK-S055-04는 요청 조작의 최상위 화면 조립 파일이 빠져 세 번째로 막혔다.
실제 코드의 값 경로를 원천부터 최종 화면까지 다시 대조해 누락 파일을 범위에 추가했다.
값을 그대로 소비하는 활동 화면 구현은 과대 선언에서 제외하고 소비 검사는 보존했다.
완료 조건 열네 개를 값 경로 열한 줄로 닫고 식별자, 승인, 선행, 이력과 막힌 사유를 보존했다.
작업은 개발 준비 상태로 돌아갔고 사용자 재개 이력과 수정 요청 식별자는 추가하지 않았다.
제품 코드는 변경하지 않았다.

## 수정 근거

- 현재 `blocked_kind: definition_error`, `## 막힌 사유`, DEV-3과 앞선 DEV·ARCH 보고서 전부를 읽었다.
- DEV-3가 `useProjectWorkspace` 반환값을 `src/App.tsx`가 `WorkspaceShell`의 개별 속성으로 열거한다고 확인했다.
  기존 사전 검사의 "훅을 통째로 넘긴다"는 판정은 현재 코드와 달랐다.
- 승인 DECISION-22C3CC2F와 SPEC-055를 대조했다. 앱 소유 수정 요청은 없어 `revision_request_id`를 넣지 않았다.

## 수정 내용

- 상태를 `blocked`에서 `todo`로 돌렸고 정의 수정 복귀이므로 `history`는 추가하지 않았다.
- `scope_files`에 `src/App.tsx`를 추가하고, 일반 사건 배열을 이미 소비하는 `ActivityView.tsx`는 제외했다.
- 범위 선언, 기존 요청과 처리 여부, 활성 선점, 요청 callback, 실패 뒤 재조회, 범위 사전 검사 본문,
  상태 불변, 활동 사건과 접근성·회귀 값을 `- 값 경로:` 열한 줄로 기록했다.
- 완료 조건 4에 작업 공간 callback 경로를, 조건 9에 두 사건 종류와 화면 이름을 명시했다.
- TASK-149와 TASK-S055-02 선행을 보존했다. 겹치는 다른 작업은 모두 품질 확인 대기이고 활성 선점이 없다.

## 검증 결과

- YAML로 `status: todo`, `blocked_kind`, 식별자·승인, 선행 두 건, scope 15개와 기존 이력 8개를 확인했다.
- `revision_request_id`와 `resumed`가 없고 막힌 사유 제목과 네 표식이 각각 한 번임을 확인했다.
- 완료 조건 1~14, 검증 절차 1~10, `- 값 경로:` 11개와 모든 변경 파일의 scope 포함을 확인했다.
- `git diff --check`가 통과했다.

- 화면은 요청 저장 때문에 상태를 바꾸지 않고 백엔드가 돌려준 실제 상태를 그대로 표시해야 한다.
- 조건 10은 이전 처리 요청과 새 미처리 요청이 함께 있는 재차단 시점으로 검증한다. 다중 처리 연결은 범위 밖이다.
