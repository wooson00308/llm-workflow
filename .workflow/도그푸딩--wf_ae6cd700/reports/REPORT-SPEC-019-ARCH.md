## 기획서가 아키텍트에게 맡긴 결정

R2가 "저장 수단은 아키텍트가 정한다. 카드 접힘이 쓰는 저장소를 넓힐지 별도의 키를 둘지"를 남겼다.
**별도 키**로 정했다.

- 키: `workflow-labs.heartbeat-setup-guide-collapse.v1`, 값은 펼침 여부 `boolean` 하나.
- 근거 1: 카드 접힘 맵은 연동 id를 키로 하는 `Record<string, boolean>`이다. 가이드 상태를 같은 맵에
  넣으면 그 이름이 언젠가 생길 연동 id와 같은 이름 공간에서 부딪힌다.
- 근거 2: 완료 조건 6("가이드를 접어도 카드 접힘 기억이 바뀌지 않는다")이 축을 나누면 저절로
  성립한다. 한 맵에 두 축을 담으면 그 성질을 계속 테스트로 지켜야 한다.
- 기본값(`true` = 펼침)은 저장소가 들고 있게 했다. 값 없음·파싱 실패·타입 불일치·접근 실패가 전부
  한 자리로 모여, 완료 조건 4·7·8이 저장소 단위 테스트로 닫힌다.
- 두 저장소를 아우르는 공통 계층은 만들지 않는다. 지금 필요가 없고, 기획서가 요구한 것도 아니다.

확인 필요 1번(앱 전체 하나)과 2번(마법사가 돌아와도 유지)은 승인된 제안대로 반영했다. 키에 프로젝트
식별자를 넣지 않고, `if (!remaining) return null` 경로에서 저장소를 건드리지 않는다.
