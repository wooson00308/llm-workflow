# TASK-S051-04 개발 보고서

## 결정권자 요약

프로젝트별 배정과 반복 실행, 병렬 상한, 공정성, 복구를 provider 중립 dispatcher로 구현했다.
실행은 예약 도구가 lease를 만든 뒤에만 시작하며, 예약 실패는 종료 코드에 따라 서로 다른 실패 단계로
남는다.
런타임이 다시 시작해도 살아 있는 프로세스를 중복 실행하지 않고 이벤트를 마지막 위치부터 이어 읽는다.
실행 중 lease 소유권이 역할 세션으로 넘어가면 갱신만 멈추고 프로세스는 끊지 않는다.
앱이 쓰는 실행 명령 여덟 개를 구현했고 계약 조회와 계약 문서가 같은 목록을 알린다.
전용 자동 검사 41건과 알려진 기존 실패 한 건을 제외한 전체 회귀 검사를 통과했으므로 사용자의 확인을
요청한다.

## 변경 파일과 모듈

- `src/heartbeat/agent_dispatch.py`: 새 모듈이다. 예약·선점 도구 호출과 종료 코드 해석, 계획 계산,
  실행 시작, 복구 대조, 취소·재시도, 프로젝트 순회를 담는다.
- `src/heartbeat/agent_store.py`: 큐·실행·이벤트·오류의 쓰기 경로를 채웠다. 계획 저장과 일회 소비,
  반복 실행 지시, 실행 행 upsert, cursor 기반 이벤트 읽기, 일시 정지 플래그 갱신을 추가했다.
- `src/heartbeat/agent_cli.py`: 실행 명령 여덟 개를 구현하고 계약 조회가 이를 구현된 명령으로
  반환하도록 했다.
- `src/heartbeat/cli.py`: `agent plan`, `agent run start|cancel|retry`, `agent project pause|resume`,
  `agent logs`, `agent provider diagnose` 하위 명령을 연결했다.
- `src/heartbeat/core.py`: 데몬 루프 끝에 에이전트 tick 한 번을 붙였다. 어떤 예외도 잡아 로그로만
  남기므로 기존 잡 스케줄은 영향을 받지 않는다.
- `docs/agent-runtime-contract.md`: 실행 명령, 예약 도구 종료 코드 해석, lease 갱신·반납 규칙, 취소
  단계, 복구 필드를 설명하는 절을 추가했다.
- `tests/test_agent_dispatch.py`, `tests/test_agent_recovery.py`, `tests/test_agent_cli.py`: 가짜 예약
  도구와 가짜 provider로 41건을 고정했다.

## 설계 판단

- 계획과 시작을 나눴다. 계획은 예약을 하지 않으므로 실제로 예약 가능한 대상 수는 시작 단계에서만
  드러난다. 계획의 `granted`는 상한들의 최솟값이고, 예약 도구가 종료 코드 1을 내면 그보다 적게
  시작된다. 완료 조건 1의 "두 실행만 시작" 은 이 경로로 성립한다.
- 실행 감시는 `wait`가 아니라 저장된 핸들 복구로 한다. 제어 CLI는 시작한 뒤 종료하므로 provider의
  활성 목록에 기대면 재시작 뒤 아무것도 이어받을 수 없다. tick마다 provider 객체를 새로 만들고 버리며
  상태는 SQLite와 이벤트 파일에만 둔다. 그래서 활성 목록이 쌓이는 문제도 생기지 않는다.
- 수동 배정은 예약 도구가 대상 인자를 받지 않는다는 제약을 그대로 반영했다. 요청한 대상과 다른 대상이
  예약되면 그 lease를 즉시 반납하고 슬롯을 거절한다. 지정한 대상을 예약하도록 강제할 방법은 현재
  도구 계약에 없다.
- 완료·거절 대상 판정은 런타임이 하지 않는다. 예약 도구는 자격 있는 대상만 고르므로 완료·거절 대상은
  절대 예약되지 않고 위 경로로 거절된다. 워크플로 문서를 런타임이 다시 해석하지 않기 위한 선택이다.
- 계약 조회의 구현된 명령 목록은 명령 계층에서 만든다. `agent_contract.py`는 이 작업의 scope_files
  밖이라 그 파일의 하드코딩된 목록은 그대로 두었다.

## 기존 검사 수정 한 건

`run.start`가 미구현임을 확인하던 매개변수 한 줄을 실제로 존재하지 않는 명령 이름으로 바꿨다. 그
명령을 구현했으므로 예전 값은 더 이상 미구현 경로를 검사하지 못한다. 알 수 없는 명령이 실패 봉투를
낸다는 원래 의도는 그대로다. 검사를 지우거나 약화하지 않았다.

  검사 한 건이 간헐 실패해, 대기 후 단언하도록 고쳤다.
- `python -m compileall -q src/heartbeat` 통과. 새로 추가한 파일에 대한 `ruff check` 통과.
- 검사 종료 뒤 가짜 provider 프로세스가 남지 않는 것을 확인했다.

## 남은 위험

- 검증은 macOS에서만 실행했다. 가짜 예약 도구가 POSIX 셸 스크립트라 해당 검사들은 Windows에서
  건너뛴다. Windows 경로의 실행은 확인하지 못했다.
- 실제 예약 자산과 실제 CLI를 쓰는 종단 확인은 하지 않았다. TASK-S051-11의 범위다.
- 데몬 루프의 tick은 매 주기마다 실행 중인 프로젝트를 순회한다. 프로젝트 수가 많아지면 주기 안에서
  걸리는 시간이 늘 수 있으며, 부하 측정은 하지 않았다.
- 계획 만료는 2분 고정값이다. 앱의 확인 화면이 더 오래 열려 있으면 새 계획을 다시 읽어야 한다.

## 후속 작업

- `agent_contract.py`의 구현된 명령 목록과 예약된 명령 목록이 실제 구현과 어긋난 채 남아 있다. 그
  파일을 범위에 포함하는 작업에서 명령 계층과 한 곳으로 모아야 한다.
- 예약 도구에 대상 인자가 없어 수동 배정이 정확한 대상을 보장하지 못한다. 도구 계약을 바꿀지, 수동
  배정의 의미를 좁힐지는 기획 판단이 필요하다.
- TASK-S051-08의 앱 화면은 계획·시작·취소·로그 응답을 이 문서의 모양대로 소비하면 된다.
- quota 검사 격리는 여전히 별도 작업이 필요하다.
