# TASK-S082-02 개발 보고서

## 결정권자 요약

아이디어 화면이 재반영중을 다섯 번째 상태로 그린다. 목록 줄과 오른쪽 미리보기가 같은 표를 읽으므로
두 자리의 문구가 같고, 배지 색은 보라 계열이라 반영중의 파랑과 갈린다. 중단 의심이 붙은 재반영중
아이디어는 목록에서 두 배지를 나란히 보이고 미리보기에서도 배지와 안내가 함께 뜬다. 중단 의심
안내는 걸린 기획서 번호를 그대로 짚되, 사용자가 직접 확인해야 한다는 문장을 빼고 다음 기획자
세션이 그 문서를 이어받는다는 사실로 바꿨다. 수집됨, 반영중, 채택, 종결 네 상태의 문구와 아이콘과
색은 그대로이고, 알 수 없는 값을 수집됨으로 읽는 동작도 바뀌지 않았다. 격리 사본과 통합
커밋에서 시험과 타입 검사와 생산 빌드가 모두 통과했으며, 웹킷 화면에 다섯 상태를 나란히 띄워
눈으로 확인했다. 이 결과는 GROUP-082의 사용자 확인 가운데 재반영중 표기와 중단 의심 안내 항목을
뒷받침한다.

  C1·C2(목록 줄과 미리보기 문구 일치), C3(두 클래스 훅과 반영중과 같은 아이콘 도형), C4(재반영중
  배지와 중단 의심 배지·안내 동시 표시)를 확인한다.
- 기존 단언 수정 둘. 103행 미리보기 배지 정규식에 재반영중을 더했다(작업 문서 검증 절차 2번). 이는
  기대값 변경이 아니라 집는 범위를 넓힌 것이고, 네 기존 상태의 기대 문구는 그대로다. 149~150행에서
  `/직접 확인해야 합니다/` 단언을 지우고 새 문장 단언과 옛 문장 부재 단언으로 바꿨다(C5).
- 기존 시험 회귀. 69행·92행·206행·240행·257행의 시험을 기대값 수정 없이 통과시켰다(C6). 알 수 없는

  통과하므로 C7도 확인된다.
- 격리 사본 `npm run check` 통과. 시험 파일 30개·시험 592건 통과·42건 건너뜀, 타입 검사와 생산
  빌드 정상(C9). 아이디어 화면 시험 파일만 따로 돌린 결과도 40건 전부 통과다.
- 웹킷 눈 검수. 공유 작업 폴더가 1420 포트를 쓰고 있어 격리 사본의 개발 서버를 5199 포트로 띄우고,
  실제 스타일 파일과 실제 화면 컴포넌트에 다섯 상태 픽스처를 넣어 macOS 웹킷으로 그렸다. 계산값은
  재반영중 rgb(84,80,143)/rgb(230,228,243)으로 C3이 정한 색과 같고, 반영중 rgb(63,97,132),
  채택 rgb(40,96,66), 종결 rgb(138,63,56), 수집됨 rgb(154,107,61)은 변경 전과 같다(C3, C6). 캡처
  세 장은 `~/Documents/workflow-labs-shots/TASK-S082-02/`에 있다. 목록 캡처에서 다섯 배지가 나란히
  서고 재반영중이 반영중과 구분되며, 중단 의심 캡처에서 두 배지와 새 안내 문장이 함께 보인다.
  검수용 임시 HTML 한 장은 촬영 뒤 지웠고, 커밋과 작업 폴더 어디에도 남지 않았다.

## 남은 위험

- 백엔드가 아직 `redrafting`을 실어 보내지 않는다. 그 판정은 TASK-S082-01이 맡고 있으므로, 두 작업이
  모두 들어가기 전까지 사용자 화면에서 실제로 달라지는 것은 중단 의심 안내 문장뿐이다(C7).
- 눈 검수는 앱 실행 파일이 아니라 같은 스타일 파일과 같은 화면 컴포넌트를 웹킷에 올려 확인한 것이다.
  색과 배치는 이 방식으로 잡히지만, 앱 창에서 보는 최종 확인은 GROUP-082의 사용자 확인이 맡는다.
- 재반영중 배지가 늘면서 목록 줄 오른쪽에 배지가 둘 서는 경우가 한 종류 늘었다. 캡처에서 넘침은
  없었으나, 제목이 아주 긴 아이디어에서의 줄바꿈은 이번 시험 범위 밖이다.
