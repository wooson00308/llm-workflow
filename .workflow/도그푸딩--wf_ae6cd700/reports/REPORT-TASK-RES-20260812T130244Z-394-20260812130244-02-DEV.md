읽기 전용 조회를 백엔드에 만들었다. 연결 근거는 실행 기록의 대상 문서 식별자와 예약 결과 접두어
두 값뿐이며, 두 값이 모두 비어 있으면 아무 보고서도 돌려주지 않는다. 다른 실행의 보고서를 대신
채우는 경로는 만들지 않았다. 보고서를 읽는 조회는 파일을 쓰지 않고 어떤 문서의 상태도 바꾸지 않으며,
워크플로우 디렉터리 밖을 가리키는 파일 이름은 읽지 않고 거절한다.

이 작업은 화면을 만들지 않는다. 사용자가 눈으로 볼 결과는 다음 작업에서 붙으므로, 이번 확인은

## 남은 위험

- 목록 조회는 개수 집계와 어긋나지 않기 위해 심볼릭 링크도 파일로 세는 개수 집계와 같은 판정을
  쓴다. 반면 본문 조회는 심볼릭 링크를 거절한다. 따라서 보고서 디렉터리에 심볼릭 링크를 두면
  목록에는 보이지만 열리지 않는다. 안전한 쪽으로 어긋나 있으나 화면이 이 경우의 오류를 사용자에게
  어떻게 말할지는 다음 작업이 정해야 한다.
- 연결 판정은 파일 이름에 값이 들어 있는지만 본다. 한 실행의 대상 식별자가 다른 실행의 대상
  식별자의 앞부분과 같으면 두 실행이 같은 보고서를 연결로 인정한다. 현재 식별자 생성 규칙에서는
  접두어에 시각과 난수가 들어가 이 조합이 나오지 않지만, 규칙이 바뀌면 다시 확인해야 한다.
- 명령 계층은 검사로 덮지 못했다. 검사는 모두 저장소 계층을 직접 부른다. 명령은 인자를 옮겨
  저장소를 부르는 것 외에 하는 일이 없다.
