# TASK-S064-02 개발 보고서

## 결정권자 요약

규약 문서 두 건에 통합 대기 표시를 언제, 어떤 경로로 남기는지를 적었다. 개발자 세션은 실제
충돌을 확인해 통합을 미루고 끝낼 때, 공유 작업 공간에 남기는 마지막 커밋 뒤이자 선점 반납
직전에 예약 헬퍼 명령을 한 번 부른다. 통합에 성공한 세션과 다른 이유로 막힌 세션은 부르지
않는다. 공통 규칙에는 준비 기록의 단계 값을 바꾸는 경로가 이 호출 하나뿐이고 세션이 그 파일을
직접 만들거나 고치거나 지우지 않는다고 적었다. 호출이 실패해도 보고서 작성과 반납은 그대로
진행하며 실패 사실을 보고서에 남긴다. 실제 충돌의 정의와 판정 코드와 작업 상태 전이는 한 줄도
건드리지 않았다. 자동 검사는 백엔드 862건과 화면 검사가 모두 통과했고 형식 검사, 정적 분석,
빌드도 통과했다. 격리 사본에서 통과한 뒤 공유 기준으로 통합했고, 통합한 커밋을 깨끗한 사본에서
다시 검사해 같은 결과를 얻었다. 이 결과는 GROUP-064의 자동 검증 완료를 준비하는 증거이며
사용자가 지금 확인할 것은 없다.

## 변경한 파일과 모듈

`src-tauri/src/infrastructure/project_instructions.rs` 하나만 바꿨다. 선언한 범위 밖의 파일과
`.workflow` 아래 설치본은 건드리지 않았다.

- 공통 규칙 본문 `WORKFLOW_RULES`의 `### Runtime reservation handoff` 절에 항목 하나를 더했다.
  준비 기록이 lease 파일과 같이 앱 소유이고, 단계 값을 바꾸는 경로가
  `sh .workflow/rules/wf-reserve.sh wait-integration <target-id> <lease-id>` 하나뿐이며, 명령이
  없거나 호출이 실패하면 보고서에 적고 끝내되 파일을 직접 써서 우회하지 않는다는 내용이다(C5).
- 개발자 계약 본문 `DEVELOPER_RULES`의 `## Leave the user's own work alone` 절에 항목 셋을
  더했다. 호출 시점(C1), 마지막 문서 커밋 뒤라는 순서와 그 이유(C2), 성공 경로와 다른 이유로
  막힌 세션의 제외(C4), 호출 실패와 무관하게 마무리가 진행된다는 것(C6)이다. 실제 충돌 세
  가지를 정의한 기존 항목은 문장 그대로 두었다(C3).
- 같은 계약의 `## Completion` 절에 호출 시점을 한 줄로 다시 적어, 마무리 순서를 읽는 세션이
  놓치지 않게 했다.
- 판 번호를 올렸다(C7). 공통 규칙 30에서 31로, 개발자 계약 22에서 23으로 바꾸면서 상수, 본문
  frontmatter, 판 번호를 문자열로 대조하는 시험, 네 상수를 직접 대조하는 시험을 함께 올렸다.
  기획자 계약 12와 아키텍트 계약 20은 본문과 판 번호를 그대로 두었다(C8).
- 시험 `records_the_integration_waiting_mark_in_the_installed_rules`를 새로 넣었다(C9). 설치를
  수행한 뒤 읽은 설치본 두 건이 새 문장과 새 판 번호를 담는지 확인한다.
