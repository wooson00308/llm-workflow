# SPEC-059 기획 보고서

## 결정권자 요약

IDEA-A4F61778을 SPEC-059로 구체화하고 사용자 검토 대기 상태로 올렸다.
아이디어가 말한 감춤은 개발 작업 화면의 작업 그룹별 보기 한 곳에만 이미 구현돼 있었다.
평면 보기와 리스트, 화면 위 수치는 끝난 그룹의 작업을 그대로 세고 있어서 보기를 바꿀 때마다 목록이 달라진다.
2026-08-16 기준 작업 186건 중 129건이 이미 끝난 그룹에 속한다는 사실을 문서에서 직접 세어 근거로 실었다.
타임라인은 기록형 보기라 감춤 대상에서 빼는 것을 기본 판단으로 정하고, 이견이 있으면 수정 요청으로 돌릴 수 있게 문서에 적었다.
지금 요청하는 것은 SPEC-059의 승인 여부다.

## 대상과 예약 절차

- 역할은 planner이고 대상은 IDEA-A4F61778 하나다.
- 런타임이 넘긴 lease-56109-20260816070856을 wf-claim renew로 갱신해 종료 코드 0을 확인했다. 같은
  대상에 acquire는 실행하지 않았다.
- 결과 접두어 RES-20260816T070856Z-56109-20260816070856은 이 보고서에서만 인용하고 문서 식별자에는
  넣지 않았다. 기획서 식별자는 계보 규칙대로 정했다.
- 기존 기획서는 SPEC-058까지 연속으로 존재했고 001부터 훑어 빈 번호가 없음을 확인한 뒤 SPEC-059를
  택했다. 쓰기 직전에 해당 경로가 비어 있음을 확인했다.
- 소유 확인 직후 status draft와 source_idea_id를 가진 기획서 골격을 먼저 만들고, 본문을 작성한 뒤
  같은 문서를 status user_review로 전환했다.
- 마이그레이션 잠금은 없었다. 사용자 정의 규칙 파일도 없어서 공통 규칙과 planner 역할 계약만
  적용했다.
- 인수한 잔여물은 없다. 이 아이디어를 참조하는 기획서가 하나도 없었고, lease 디렉터리에는 이 세션의
  lease 하나만 있었다.

## 자격 판정

- IDEA-A4F61778을 source_idea_id로 참조하는 기획서가 없어 미처리 아이디어 조건을 만족했다.
- 이 대상에 다른 lease는 없었다. 회수 대상이나 미응답 수정 요청을 먼저 볼 필요가 없었고, 런타임이
  예약해 준 대상 하나만 처리했다.

## 확인한 근거

- 아이디어 원문은 "개발뷰에서 작업 그룹이 품질확인까지 끝나면 감추는게 어떤지"라는 질문 한 줄이다.
  감출지 여부와 감추는 범위를 기획서에서 판단해야 한다고 읽었다.
- 개발 작업 화면 구현에서 작업 그룹별 보기가 완료와 자동 완료 상태의 그룹을 이미 목록에서 빼고,
  "완료된 작업 그룹 N개는 기록 화면에 있습니다"라는 안내를 한 줄 두고 있음을 확인했다. 이 처리는
  결정권자 중심 화면 개편 커밋에서 들어왔다.
- 같은 화면의 평면 보기, 리스트, 타임라인은 그룹을 보지 않고 작업 전체를 대상으로 그린다. 화면
  머리의 진행 중 수치와 요약 띠의 진행 중·막힘·완료 수치, 표시 건수도 작업 전체를 센다.
- 작업 그룹 상태 판정에서 사용자 확인 통과와 자동 확인 완료가 서로 다른 값이며, 자동 확인 완료는
  확인 시점 이후 코드가 바뀌면 개발 중으로 되돌아간다는 조건을 확인했다. 그래서 문서로 센 값과
  화면에서 실제로 감춰지는 수가 다를 수 있다는 사실을 기획서에 적었다.
- 기록 화면이 완료와 자동 완료 그룹의 정본 목록을 이미 가지고 있고, 그룹을 열면 확인 방식, 구성
  버전, 사용자 확인 플로우, 포함된 작업 목록까지 보여준다는 사실을 확인했다. 감춰도 사용자가 잃는
  정보가 없다는 판단의 근거다.
- 2026-08-16 기준 실측: 작업 그룹 56개 중 자동 확인 방식 36개, 사용자 확인 방식 20개이고, 사용자
  확인을 통과한 그룹은 2개다. 끝난 그룹은 38개, 남은 그룹은 18개이며 모두 사용자 품질 확인 대기
  상태다. 작업은 186건 전부 완료 상태이고 그중 129건이 끝난 38개 그룹에 속한다.

## 기획서에서 내린 판단

- 자동 확인으로 닫힌 그룹도 감춘다. 아이디어의 표현은 사용자 품질 확인만 가리키지만, 두 상태 모두
  사용자가 더 할 일이 없고 기록 화면의 완료 목록에 함께 들어간다. 여기서 기준을 가르면 보기마다
  목록이 달라지는 지금 문제가 형태만 바꿔 남는다.
- 사용자 품질 확인 대기 그룹과 아키텍트 재분류 대기 그룹은 감추지 않는다. 사용자 결정이나 후속
  작업이 남아 있는 일이다.
- 타임라인은 감춤 대상에서 뺐다. 전체 이력을 보여주는 기록형 보기라 완료 사건을 빼면 목적이
  사라진다. 이것을 기본 판단으로 명시하고 이견이 있으면 수정 요청으로 돌릴 수 있게 문서에 적었다.
- 소속 그룹을 확정할 수 없는 작업은 감추지 않는다. 끝났다고 판단할 근거가 없고, 감추면 사용자가
  확인해야 할 구성 오류가 화면에서 사라진다.
- 감춤 설정 스위치, 개발 작업 화면 안의 완료 목록 영역, 안내 문구의 입구화는 범위 밖으로 뒀다.
  지금 결정할 것은 감출지 여부이며, 설정을 먼저 만들면 결정을 미루는 것이 된다.

## 자기 검토

- 결정권자 요약을 현행 구조화 형식으로 썼다. 제안, 현재, 변경 후, 비용과 위험 순서로 각각 한 번씩
  두었고 요약 안에 파일 경로, 식별자 표기, 코드 이름을 넣지 않았다.
- 비용과 위험에 승인하지 않을 때 유지되는 것과 되돌리는 비용을 함께 적었다.
- 요구사항 10개와 검수 기준 10개가 서로 대응하는지 확인했다. 검수 기준 3번에는 실측값을 넣어
  판정이 가능하게 했다.
- 한국어 문체 규칙에 따라 영어 대시를 문장 구분으로 쓰지 않았고, 은유 대신 실제 동작을 가리키는
  말로 썼다.
