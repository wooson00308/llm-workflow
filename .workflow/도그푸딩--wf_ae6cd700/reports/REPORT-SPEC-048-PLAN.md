# SPEC-048 기획 보고서

## 결정권자 요약

프로젝트별 사용자 정의 규칙을 앱 설정에서 관리하는 첫 버전을 기획했다.
규칙 문서 하나에 사용 여부와 적용 역할, Markdown 본문을 저장하고 역할별 최종 규칙을 미리 보여준다.
앱 기본 규칙과 역할 계약이 항상 우선하며 사용자 규칙은 필수 안전 경계를 완화할 수 없다.
외부 변경과 동시 수정을 자동 병합하지 않고 사용자가 다시 읽고 저장하게 한다.
변경 내용은 앱 재시작 없이 다음 에이전트 세션부터 적용된다.
지금 요청하는 것은 SPEC-048의 승인 여부다.

## 대상 선택

- 사용자가 앱 인박스에 등록한 IDEA-655ADA04를 처리했다.
- 다른 미답변 수정 요청과 중단된 기획 초안이 없어 이 아이디어가 기획자 대상이었다.
- IDEA-655ADA04만 선점하고 SPEC-048을 작성했다. 앱 코드와 다른 기획서는 변경하지 않았다.

## 조사와 반영

TL이 현재 규칙 설치 구조와 설정 화면을 확인했고, 서브에이전트가 저장과 보안 경계를 읽기 전용으로
검토했다. 다음 내용을 기획서에 반영했다.

- 앱 기본 규칙과 분리된 프로젝트 파일 하나를 사용한다.
- 공통 규칙과 역할 계약이 사용자 정의 규칙보다 우선한다.
- 세 역할의 적용 범위와 켜기, 끄기를 제공한다.
- 저장 파일 미리보기와 역할별 최종 적용 규칙 미리보기를 구분한다.
- 저장 요청은 마지막으로 읽은 내용 식별값을 확인해 외부 변경을 덮어쓰지 않는다.
- 심볼릭 링크, 잘못된 형식, 더 새로운 스키마, 길이와 제어문자 오류를 안전하게 표시한다.
- Markdown 미리보기는 HTML을 실행하거나 링크를 자동으로 열지 않는다.
- 이미 실행 중인 에이전트에는 규칙을 다시 주입하지 않는다.

## 범위를 줄인 결정

첫 버전은 프로젝트 규칙 문서 하나에 집중한다. 역할별 적용은 지원하지만 여러 규칙 묶음, 전역 규칙,
조건식, 템플릿, 마켓, AI 충돌 판정은 넣지 않는다. 외부 편집은 정상 입력으로 받아들이되 자동 병합은
하지 않는다.

자연어 규칙의 충돌을 앱이 완전히 판정할 수 없으므로 금칙어 검사로 안전을 보장한다고 주장하지 않는다.
고정된 우선순위와 기존 앱 명령 경계를 유지하고, 사용자에게 적용 순서와 한계를 보여주는 방식으로
정했다.

## 검증

- 기존 관리 규칙, 역할 계약, AGENTS와 CLAUDE 진입 방식, 설정 화면, 프로젝트 조회 주기를 확인했다.
- 사용자 정의 규칙 파일이 없으면 기존 동작을 유지할 수 있는 선택 파일 구조인지 확인했다.
- SPEC-048의 결정권자 요약은 빈 줄을 제외하고 여덟 줄이며 요약 형식 제한을 지킨다.
- 기획서와 보고서에서 사용자가 지적한 문체 문제와 영문식 긴 대시가 없는지 확인했다.
- `git diff --check`에서 오류가 없었다.

## 다음 단계

SPEC-047과 SPEC-048이 모두 승인되면 관리 규칙 동기화 작업을 먼저 진행해야 한다. 두 기능이 설정 화면과
규칙 진입 안내를 함께 수정하므로, 아키텍트는 겹치는 파일을 동시에 개발하지 않도록 순서를 선언해야
한다. 승인 전에는 구현하지 않는다.
