# TASK-S066-02 개발 보고서

## 결정권자 요약

품질 확인 대기 목록의 기능 카드가 소개를 최대 세 줄까지만 보여주고, 넘치면 끝을 말줄임으로
끊는다. 카드 높이가 기능마다 같아져서 목록을 위에서 아래로 훑는 것만으로 몇 개가 올라와 있는지
셀 수 있다. 시작을 눌러 들어간 확인 화면과 완료 기록 화면의 기능 상세는 소개를 자르지 않고 전부
보여주며, 문단이 여럿이면 문단 사이가 벌어져 보인다. 화면 구조와 확인 동선은 한 곳도 바꾸지
않았고 스타일 규칙 두 줄만 고쳤으므로, 되돌리기는 그 두 줄을 되돌리는 것으로 끝난다. 자동 검사는
화면 시험 505건이 모두 통과했고 빌드도 통과했다. 이 결과는 GROUP-066의 사용자 품질 확인을
준비하는 증거이며, 세 줄이라는 상한이 실제 화면에서 적당한지는 그 자리에서 판단하면 된다.

## 바꾼 파일과 모듈

- `src/features/projects/components/qa/QaWorkbench.css` 16행 `.qa-queue-goal`. `display: block`을
  `display: -webkit-box`로 바꾸고 `overflow: hidden`, `-webkit-box-orient: vertical`,
  `-webkit-line-clamp: 3`을 더했다(C1). 줄바꿈을 보존하는 선언은 넣지 않아 카드에서는 값 안의
  줄바꿈이 공백으로 접힌다(C2). 선언 순서는 같은 어법을 쓰는 `src/App.css` 640행을 따랐다.
- 같은 파일 31행 `.qa-feature-goal`. `white-space: pre-line`을 더했다(C4). 줄 수 상한도 높이 상한도
  넣지 않았다(C3).
- 두 선언 모두 색, 글자 크기, 줄 간격, `word-break: keep-all`, `max-width: 62ch`, 바깥 여백은
  그대로 두었다(C5).
- `src/features/projects/components/qa/qaWorkbenchAlignment.test.ts`. 항목 하나를 뒤에 더해
  `.qa-queue-goal`의 `display`·`-webkit-line-clamp`·`overflow`와 `.qa-feature-goal`의
  `white-space`, 그리고 `.qa-feature-goal`에 줄 수 상한 선언이 없다는 것을 확인한다(C8). 기존 세
  항목은 한 줄도 고치지 않았다(C9).

## 검증 절차와 결과

격리 사본(기준 커밋 2730117, 후보 커밋 880e7fe)에서 실행했다. 착수 시점의 공유 기준과 후보의
기준이 같은 커밋이라 후보를 옮길 일은 없었다.

1. `npm run test -- qaWorkbenchAlignment` — 4건 통과, 실패 0. 기존 3건에 이번 1건이 더해진 수다.
2. 같은 시험이 실제로 이번 변경을 본다는 것을 확인했다. 스타일 파일만 원상태로 되돌려 다시 돌리니
   새 항목이 `expected 'block' to be '-webkit-box'`로 실패하고 기존 3건은 통과했다. 확인 뒤
   변경을 되돌려 놓았다.
3. `npm run test` — 파일 29개, 505건 통과·42건 건너뜀, 실패 0.
4. `npm run build` — 성공. 산출된 스타일 시트에 `line-clamp:3`과 `white-space:pre-line`이 각각
   한 번씩 남아 있어, 번들러가 두 선언을 지우거나 바꾸지 않는다는 것도 확인했다.
5. `npm run typecheck` — 통과.
6. `git status` 확인 — 변경 파일은 선언한 두 개뿐이다. 화면 구성 파일과 Rust 파일은 한 줄도
   바뀌지 않았다(C10).

통합은 공유 작업 공간의 미커밋 변경이 전부 `.workflow` 아래 제어 문서뿐이고 후보가 바꾸는 두
파일과 겹치지 않는 것을 확인한 뒤 진행했다. 통합 커밋은 bdc9e47이다. 그 커밋으로 옮긴 깨끗한
사본에서 다시 실행했다.

- `npm run test` — 29개 파일 505건 통과·42건 건너뜀, 실패 0.
- `npm run test -- qaWorkbenchAlignment` — 4건 통과.
- `npm run build` — 성공.

작업 문서의 검증 절차 4번 `npm run lint`는 실행하지 못했다. 이 저장소에 `lint` 스크립트가 없고
정적 검사 도구 설정도 없어 `Missing script: "lint"`로 끝난다. 이 절차가 노리는 정적 검사는 빌드가
포함하는 `npm run typecheck`가 대신 수행했고, 위 5번이 그 결과다.

검증 절차 5번(앱을 띄워 카드와 상세 화면을 눈으로 확인)은 실행하지 않았다. GROUP-066은 사용자
품질 확인 모드이므로 화면을 눈으로 확인하는 일은 그룹 경계의 사용자 확인에서 이루어진다.

## 남은 위험

- 세 줄이라는 상한이 적당한지는 자동 검사로 판정할 수 없다. 소개가 긴 기능에서 잘린 뒷부분은
  시작을 눌러 들어가면 전부 보이므로 읽을 방법이 사라지지는 않지만, 상한이 짧다고 판단되면
  품질 확인에서 수정 요청으로 돌려보내면 된다.
- `-webkit-line-clamp`는 WebKit 계열 어법이다. 이 앱은 Tauri의 WebView로 그리므로 대상 환경에서
  동작하고, 같은 어법을 이미 쓰는 자리가 `src/App.css`에 둘 있다.
- 지금 시점에서는 소개 값에 절 제목과 작업 분해 근거가 함께 들어 있어 세 줄이 소개로만 채워지지
  않는다. 그 값을 정리하는 일은 TASK-S066-01이 맡으며, 두 작업의 순서와 무관하게 화면이 지금보다
  나빠지지는 않는다.

## 후속 작업

- 아키텍트 인계 하나. 이 작업 문서의 검증 절차 4번이 이 저장소에 없는 `npm run lint`를 지정한다.
  이 워크플로우의 다른 작업 문서와 보고서에는 이 명령을 쓴 선례가 없다. 뒤에 오는 작업 문서에는
  `npm run typecheck` 또는 `npm run check`처럼 실제로 있는 명령을 적는 편이 낫다.
- 아키텍트 인계 둘. 같은 절차 5번이 앱을 띄워 눈으로 확인하는 단계를 작업 문서에 담고 있다.
  사용자 품질 확인 시나리오는 작업 그룹이 갖는 것이므로, 개발 작업의 검증 절차에서는 빼는 것이
  일관된다.
