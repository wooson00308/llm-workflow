사용자 위임(2026-08-04 TL 세션)으로 대리 기록한 승인. 원천 아이디어(IDEA-A61F6A81)의 두 요구 — 크로스 프로젝트 잡 증발의 앱측 수정과 두 번째 slug 회귀 테스트 — 가 모두 반영되었고, 확인 사실 18개가 전부 작업 트리 라인 앵커로 실증된 것을 확인했다. 같은 날 실측 사고(15:15 증발, 개발 로그 기록)와 전수검수 결과("증발 버그 테스트 0")가 기획 근거로 정확히 인용되었다.

확인 필요 1~3번은 모두 기획서의 제안대로 진행한다.

- 1번(지금 고친다): jobs.d 전환(IDEA-CAB890F1)은 아직 미처리 아이디어 단계라 승인·구현·검증까지의 창이 열려 있고, 이 기기 밖의 HEARTBEAT.md 사용 환경에서는 결함이 그대로 살아 있다. R4의 회귀 테스트는 전환 뒤에도 같은 계약을 검사하므로 이번 작업의 절반은 버려지지 않는다는 근거를 수용한다.
- 2번(남의 잡은 원문 문자열 그대로 보존): 렌더러 통과 시 "지워지지 않았는데 값이 달라진" 상태가 새로 생기는 문제를 피하고, 해석하지 않음으로써 R2(남의 잡이 저장을 막지 않음)가 저절로 따라온다는 설계를 수용한다.
- 3번(확인 화면 세 문장에 다른 프로젝트 잡 보장을 명시): 동작만 고치고 문구를 두면 보장이 어디서 오는지 화면에 남지 않는다는 근거를 수용한다.

아키텍트 분해 시 유의 사항을 남긴다.

- jobs.d 전환(IDEA-CAB890F1)이 곧 파이프라인에 들어온다. 이번 수정의 보존 로직이 전환 기획서에서 대체될 수 있음을 작업 문서에 사실로 남겨, 전환 분해 시 중복 구현이 아니라 대체 관계로 읽히게 해 달라.
- R4의 회귀 테스트(두 번째 slug 픽스처)는 전환과 무관하게 계약 테스트로 살아남는 자산이다. 보존 구현과 같은 작업에 묶지 말고 테스트가 먼저 실패를 재현하는 순서(재현 → 수정)를 권장한다.
- heartbeat_service.rs·heartbeat_jobs.rs는 미커밋 v0.1.8 후보 변경이 얹혀 있는 파일이다. 병행 금지 대상을 확인해 달라.
