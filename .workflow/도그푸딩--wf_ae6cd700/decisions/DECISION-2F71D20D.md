사용자 지시로 대리 기록한 수정 요청. 기획서의 방향과 확인 필요 1~4번 제안(실행 정책 비의존 호출 형태, Windows 러너에서 판정 일치 테스트, dream 함께 열되 비보증 명시, skipped 문구 수정 포함)은 모두 동의하며 그대로 유지한다. 확인 필요 5번만 전제가 바뀌어 결론을 바꾼다. 다음을 반영한 개선 기획서를 작성해 달라.

- 선점 헬퍼의 Windows 지원을 포함 범위에 넣는다. 이 기획서가 작성되기 직전 SPEC-013이 승인되었고(DECISION-73D4BC1B, 04:18:48Z — 작성 시점의 "user_review, 미결정" 전제가 더 이상 사실이 아니다), 그 결정은 "Windows 대응 시 선점 헬퍼 포함 의무를 IDEA-54B29779 범위에 부채로 명시"를 기록했다. 기획서 자신이 확인 필요 5번 반대 근거에 적은 세 번째 선택지 — 승인 순서가 정해지면 뒤에 오는 쪽이 앞의 결과를 흡수한다 — 가 성립한 상태다.
- 헬퍼의 PowerShell 구현과 두 구현의 판정 일치 고정을 조건 스크립트와 같은 방식(R3의 시나리오 표 방식)으로 범위에 넣되, 그 작업의 실행 순서는 SPEC-013의 헬퍼(sh)가 존재한 뒤가 되도록 SPEC-013이 도입하는 depends_on 선언 또는 실행 순서 명시로 아키텍트가 걸게 한다. 구현 시작이 다른 기획서에 묶인다는 원안의 우려는 승인이 이미 났으므로 해소되었다.
- 사실 갱신 하나: 확인 필요 2번의 반대 근거가 "이 저장소는 단일 플랫폼 검증으로 굴러 왔다"고 전제하나, CI 워크플로우는 이미 ubuntu·windows·macos 3 러너 매트릭스를 돌리고 있다(v0.1.6 핫픽스 2건이 Windows 러너 실패의 수습이었다). 제안대로 Windows 러너에서 돌리는 것은 새 러너 추가가 아니라 기존 러너 활용이므로, 개선판에서 이 전제를 현행 사실로 바로잡아 달라.
