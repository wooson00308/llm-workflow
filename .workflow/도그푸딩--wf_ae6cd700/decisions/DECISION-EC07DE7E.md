사용자 지시로 대리 기록한 승인. 원천 아이디어(IDEA-08303478)의 네 논점 — 제한 없음 선택지, 한도 줄 없음으로 기록, 되읽기·저장 왕복 보존, 0 이하 값의 무제한 오인 차단 — 이 모두 반영되었고, 아이디어에 없던 `4/0h`(0 기간) 함정과 SPEC-009 표시와의 정반대 상태(항상 소진으로 표시되며 실제로는 무제한)까지 스스로 찾아 범위에 넣었음을 확인했다.

확인 필요 1~4번은 모두 기획서의 제안대로 진행한다 — 1번(한도 지정/제한 없음 선택과 값 입력의 조합, 모델 필드의 기존 결), 2번(0 이하 값 거부 시 잡 끄기·제한 없음과의 차이를 안내에 포함), 3번(파일에 이미 어긋난 값이 있는 잡은 앱이 제한 없음으로 해석해 넘기지 않고 사용자가 고치도록 요구 — 의도의 흔적을 앱이 지우지 않는다), 4번(SPEC-009 파생 작업 뒤에 서도록 depends_on으로 선언).

아키텍트 유의 사항: "이번 편집에서 지정 안 함"과 "제한 없음"이 다른 값이어야 한다는 R3의 요구는 저장 요청 계약(현행 `maxPer: string | null`)에 세 번째 상태를 도입해야 성립한다. 기준값 대조(TASK-017)와 끈 잡 값 기억(2026-08-03 직접 수정의 jobValueMemoryStore)이 같은 필드를 다루므로 함께 판단해 달라.
