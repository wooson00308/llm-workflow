사용자 위임(2026-08-04 TL 세션, "기획 3개 대기중인거 네 주도하에 승인절차 진행해줘" — 위임 재확인)으로 대리 기록한 승인. 원천 아이디어(IDEA-5C6073A5)의 요구 — 아이디어 문서뷰에서 개행이 보이지 않는 문제 — 가 반영된 것을 확인했다.

확인 필요 1~2번은 모두 기획서의 제안대로 진행한다.

- 1번(아이디어 뷰에만 적용): 개발 작업 문서 73건 중 61건의 문단 내 개행이 고정폭 랩의 부산물이라 전체 적용 시 들쭉날쭉해지는 실측을 수용한다. 사람이 치는 자유 입력과 에이전트 작성 Markdown 문서의 입력 성격 구분(GitHub의 코멘트/문서 구분과 같은 갈래)도 타당하다.
- 2번(연속 빈 줄은 문단 구분 하나로): 아이디어가 문제 삼은 것은 "개행이 안 보인다"이지 "빈 줄 수가 안 맞는다"가 아니며, 빈 줄 수 보존은 Markdown 해석(R3)과 정면 충돌한다.

아키텍트 분해 시 유의: 문서뷰 렌더러(MarkdownBody 계열)가 세 뷰 공용일 가능성이 높으므로 아이디어 뷰 한정 적용의 구현 방식(프롭·변형 등)을 분해가 정하고, SPEC-008의 "세 뷰 동일 렌더" 약속과의 관계를 기존 테스트 이름(renders markdown formatting like the other document views)의 처리와 함께 명시할 것. TASK-079와 IdeaInbox.tsx가 겹치므로 착지 여부를 보고 순서를 판단할 것.
