사용자 위임(2026-08-04 TL 세션)으로 대리 기록한 승인. 원천 아이디어(IDEA-19843535)의 요구 — 아이디어 인박스·오늘 화면의 입력이 화면을 떠나도 남는 것 — 가 반영되었고, 원인(IdeaComposer 지역 상태 + 조건부 렌더 언마운트)과 현행 불일치(인박스는 워크플로 전환 시 초안 소멸, 오늘 화면은 잔존)가 실측으로 확정된 것을 확인했다.

확인 필요 1~4번은 모두 기획서의 제안대로 진행한다.

- 1번(두 입력창의 초안은 하나로): 두 입력창이 동시에 보이는 일이 없고, 따로 두면 신고된 증상("오늘에서 쓰다가 인박스 열었더니 없다")이 그대로 남는다.
- 2번(초안은 워크플로 단위): A에 쓰던 글이 B 선택 상태에서 제출되는 사고를 막고, 인박스의 현행 동작과도 가깝다.
- 3번(저장 실패는 알리지 않음, 선례 동일): 수용하되 기획서가 명시한 한계(접힘과 달리 사용자 저작물)를 인지한다. 실패 표시가 필요해지면 별도 아이디어로.
- 4번(초안 수명 없음): 제출 또는 직접 삭제 때만 소멸.

아키텍트 분해 시 유의 사항을 남긴다.

- 확인 필요 1·2번의 결론(통합 초안, 워크플로 단위)이 저장 키 구조를 직접 결정한다 — 이 결정 위에서 설계할 것.
- 저장 수단(선례 저장소 확장 vs 새 키)은 기획서가 구현에 위임했다. SPEC-019 선례(browserSetupGuideCollapseStore)의 실패 삼킴 규칙을 재사용하되, R4(기억 실패에도 입력 정상)가 요구하는 것은 동작 보장이지 수단이 아니다.
- 이 두 입력창에는 자동화 테스트가 전무해 완료 조건 대부분이 새 테스트다. IdeaInbox의 key={workflow.directory} 언마운트 동작(확인 사실 8)이 R3 구현의 실질 대상임을 분해에 반영할 것.
