# 앱이 실행 환경의 동의 상태를 함께 읽고 동의와 철회를 전달한다

## 결정권자 요약

### 제안

앱이 프로젝트 설정을 읽을 때 실행 권한 동의 상태를 함께 받아 오고, 사용자의 동의와 철회를 실행 환경에
전달하는 통로를 만든다.

### 현재

앱은 실행 환경에서 설정과 진단과 실행 상태만 받아 온다. 동의를 물어볼 통로도, 사용자가 동의했다는
사실을 실행 환경에 남길 통로도 없다.

### 변경 후

설정 조회 응답에 동의 여부와 동의 시각과 고지 버전이 함께 실린다. 화면이 사용자의 동의와 철회를
전달할 수 있고, 상태를 읽지 못하면 동의한 것으로 보지 않는다.

### 사용자 결과

이 작업만으로는 화면이 달라지지 않는다. 사용자가 만나는 동의 화면과 상태 표시는 뒤따르는 작업이
붙이며, 이 작업은 그 화면이 읽고 쓸 값을 준비한다.

### 영향 범위

- 변경: 설정 조회 응답에 실리는 값, 앱이 실행 환경에 보내는 명령 목록, 앱과 실행 환경의 경계 문서
- 유지: 기존 설정 저장과 진단, 실행 계획과 시작과 취소, 호환되지 않는 실행 환경에 쓰지 않는 규칙

### 비용과 위험

동의 상태를 읽지 못한 것을 동의로 접으면 관문이 무너진다. 읽기 실패와 실행 환경이 이 명령을 모르는
경우를 서로 다른 값으로 남겨, 화면이 각각 다르게 안내할 수 있게 한다.

### 결정 요청

이 작업 자체로는 눌러 볼 화면이 없다. QA에서는 아래 자동 검사가 동의 상태 전달과 두 통로의 동작,
그리고 읽기 실패를 동의로 바꾸지 않는다는 사실을 확인했는지를 본다.

## 범위 사전 검사

이 작업이 다루는 값은 하나의 묶음이다. 실행 환경이 답한 동의 상태가 앱의 설정 조회 응답까지 오는
경로와, 화면이 누른 동의와 철회가 실행 환경까지 가는 경로다. 앱 저장소의 현재 코드를 열어 각 자리를
확인했다.

- 값 경로: 완료 조건 1의 동의 상태는 실행 환경의 동의 확인 명령이 만든다. 앱에서 그 값이 처음 들어오는
  자리는 `src-tauri/src/infrastructure/agent_runtime_process.rs`이며, 이 파일은 명령 인자 배열 상수와
  호출 함수를 짝으로 두는 구조라 같은 방식으로 셋을 더한다. 그다음 자리는
  `src-tauri/src/application/agent_runtime_config_service.rs`의 `read`이고, 이 함수가 돌려주는
  `PolicySnapshot`에 동의 값을 실을 필드가 없으므로 그 구조체를 편집한다. 같은 파일에 이미 있는
  `DeviceCapacity`가 조회 응답에만 쓰이는 값을 이 파일에서 정의한 선례이므로 동의 값의 타입도 여기 둔다.
  마지막 자리는 `src-tauri/src/commands/agent_runtime.rs`의 `read_agent_runtime_policy`인데, 이 커맨드는
  `PolicySnapshot`을 통째로 돌려주므로 필드를 고르지 않는다. 따라서 편집 없이 새 필드를 나른다.
- 값 경로: 완료 조건 3의 읽기 실패 처리 자리는 같은 `read` 함수다. 이 함수는 지금 설정 조회 실패는
  전체 실패로 올리고, 진단 조회 실패는 빈 값으로 낮춰 설정만 계속 보이게 한다. 동의 조회는 뒤쪽과 같은
  성격이므로 실패를 전체 실패로 올리지 않고 동의 값 안의 상태로 옮긴다.
- 값 경로: 완료 조건 2의 지원하지 않는 실행 환경 판정은 실행 환경이 모르는 명령에 돌려주는 거절
  응답에서 온다. 같은 파일의 `decode_envelope`가 그 거절을 `RuntimeCallFailure::Rejected`로 바꾸며 사유
  코드를 그대로 보존하므로, 사유 코드가 `unsupported_command`인 경우만 지원하지 않음으로 옮기고 나머지는
  확인 불가로 옮긴다. 이 판정을 위해 두 파일 모두 편집한다.
- 값 경로: 완료 조건 4·5·6의 동의와 철회는 화면에서 시작해 `src-tauri/src/commands/agent_runtime.rs`의
  새 커맨드 둘을 지난다. 이 파일의 커맨드는 `src-tauri/src/lib.rs`의 명령 등록 목록에 올라야만 호출되므로
  그 파일도 편집한다. 두 커맨드는 설정 저장 커맨드와 같은 방식으로 실행 환경 호환을 먼저 확인한 뒤
  호출 계층을 지난다.
- 검토했으나 제외한 것: `src-tauri/src/domain/agent_runtime.rs`는 열지 않는다. 이 작업은 실행 가능
  판정과 지원 버전 범위를 바꾸지 않으며, 동의 값은 조회 응답에만 실리는 값이라 위에서 확인한 선례대로
  응용 계층에 둔다.
- 검토했으나 제외한 것: `src-tauri/tests/agent_runtime_e2e.rs`는 열지 않는다. 이 통합 검사는 배포
  manifest와 지원 버전 범위와 상태 해석을 고정하는데, 이 작업은 그 셋 중 어느 것도 바꾸지 않는다.
- 검토했으나 제외한 것: 앱의 화면과 화면 호출 계층은 넣지 않는다. 이 작업의 완료 조건은 모두 백엔드
  응답으로 확인할 수 있고, 화면은 같은 파일 묶음을 뒤따르는 작업이 함께 고친다.

## 현재 상태

앱은 프로젝트 설정을 읽을 때 실행 환경에 설정 조회와 provider 진단을 보내고, 그 결과를 실행 가능 여부와
호환 판정과 함께 하나의 응답으로 화면에 준다. 저장은 읽을 때 받은 revision이 같을 때만 쓰고, 호환되지
않는 실행 환경에는 쓰지 않는다. 동의와 관련된 값은 이 응답에도, 앱이 보내는 명령 목록에도 없다.

## 변경 범위

1. 호출 계층에 동의 확인·동의·철회 세 호출을 더한다. 명령 인자와 요청 본문은 앞 작업이 고정한 계약을
   그대로 따른다.
2. 설정 조회 응답에 동의 값을 더한다. 필드 이름과 값을 다음으로 고정한다. 화면이 이 이름으로 읽는다.
   - `status`: `granted`, `required`, `unsupported`, `unreadable` 중 하나
   - `noticeVersion`: 기록된 고지 버전 또는 없음
   - `grantedAt`: 동의 시각 또는 없음
   - `requiredNoticeVersion`: 실행 환경이 요구하는 고지 버전 또는 없음
   - `detail`: 확인하지 못한 사유 또는 없음
3. 실행 환경의 응답을 위 값으로 옮기는 규칙을 정한다. 유효한 동의는 `granted`, 기록이 없거나 고지 버전이
   낮으면 `required`, 실행 환경이 명령을 모르면 `unsupported`, 그 밖의 실패는 `unreadable`이며 사유를
   함께 싣는다. 어떤 실패도 `granted`로 바뀌지 않는다.
4. 동의 조회 실패가 설정 조회 전체를 실패시키지 않게 한다. 설정과 진단과 실행 가능 여부는 그대로 온다.
5. 동의와 철회 커맨드를 더하고 명령 등록 목록에 올린다. 동의 커맨드는 프로젝트 식별자와 고지 버전을
   받고, 철회 커맨드는 프로젝트 식별자를 받는다. 둘 다 갱신된 동의 값을 돌려준다.
6. 두 커맨드는 설정 저장과 같은 규칙으로, 호환되지 않는 실행 환경에는 요청을 보내지 않는다.
7. 앱과 실행 환경의 경계 문서에 실행 권한 동의 절을 더한다. 앱이 화면을 담당하고 실행 환경이 시작 직전
   확인을 담당한다는 분담, 동의 상태를 읽지 못하면 동의로 추정하지 않는다는 규칙을 적는다.

## 범위 밖

- 동의 화면, 고지 문구, 화면 호출 계층
- 실행 가능 판정과 지원 런타임 버전 범위의 변경
- 실행 환경 쪽 기록과 집행
- 설정 저장 규칙, 진단, 실행 계획과 시작과 취소의 의미 변경

## 완료 조건

1. 설정 조회 응답에 동의 값이 실린다. 유효한 동의가 있는 프로젝트에서는 상태가 `granted`이고 고지
   버전과 동의 시각과 요구 고지 버전이 채워진다.
2. 실행 환경이 동의 명령을 모른다고 거절하면 설정 조회는 성공하고 동의 상태만 `unsupported`가 된다.
   설정과 진단과 실행 가능 여부는 평소와 같이 실린다.
3. 그 밖의 이유로 동의 확인이 실패해도 설정 조회는 성공하고 동의 상태가 `unreadable`이 되며 사유가
   함께 실린다. 어떤 실패도 `granted`가 되지 않는다.
4. 동의 기록이 없는 프로젝트의 설정 조회에서 동의 상태가 `required`가 되고, 요구 고지 버전이 실린다.
5. 동의 커맨드가 프로젝트 식별자와 고지 버전을 실어 보내고, 갱신된 동의 값을 돌려준다.
6. 철회 커맨드가 프로젝트 식별자를 실어 보내고, 돌려준 값의 상태가 `required`가 된다.
7. 두 커맨드가 앱의 명령 등록 목록에 있어 화면에서 호출할 수 있다.
8. 호환되지 않는 실행 환경에서는 두 커맨드가 요청을 보내지 않고 호환 오류로 끝난다.
9. 경계 문서에 실행 권한 동의의 분담과 읽기 실패 처리 규칙이 적혀 있다.

## 검증 단계

1. 동의 확인 응답을 흉내 내는 호출자로 설정 조회 검사를 추가하고 실행한다. 완료 조건 1부터 4까지의 네
   경우를 각각 확인한다. 명령: `cargo test --manifest-path src-tauri/Cargo.toml`
2. 동의와 철회 커맨드가 보내는 명령 인자와 요청 본문을 고정하는 검사를 추가하고 실행한다. 호환되지 않는
   실행 환경에서 아무 요청도 보내지 않는 것을 함께 확인한다.
   명령: `cargo test --manifest-path src-tauri/Cargo.toml`
3. 명령 등록 목록에 두 커맨드가 있는지 확인한다.
   명령: `cargo test --manifest-path src-tauri/Cargo.toml`
4. 정적 검사와 서식 검사를 실행한다.
   명령: `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`
   명령: `cargo fmt --manifest-path src-tauri/Cargo.toml --check`

## 확인 동선

이 작업에는 눌러 볼 화면이 없다. 여기서 만든 것은 앱이 실행 환경과 주고받는 값과 두 개의 호출 통로이며,
그 값을 읽어 보여 주는 동의 화면은 뒤따르는 작업이 만든다. 따라서 이 작업은 자동 검사로 닫았고, 확인
도장은 아래 수치를 신뢰한다는 뜻이다.

앱 저장소 루트에서 실행한다. `cargo`가 없다는 오류가 나면 `export PATH="$HOME/.cargo/bin:$PATH"`를
먼저 실행한다.

- `cargo test --manifest-path src-tauri/Cargo.toml` → 747 passed, 0 failed (통합 검사 20 passed 별도)
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` → 경고 없이 종료
- `cargo fmt --manifest-path src-tauri/Cargo.toml --check` → 출력 없이 종료

첫 수치가 이 작업의 핵심이다. 변경 전 같은 명령은 738 passed, 0 failed였다. 늘어난 9개가 이 작업이 더한
검사이고 실패는 없다. 즉 새 동작이 검사로 고정되었고 기존 동작은 하나도 깨지지 않았다.

완료 조건과 검사의 대응은 다음과 같다. 조건 1은 `a_valid_consent_rides_along_with_the_configuration`,
조건 2는 `a_runtime_that_does_not_know_the_command_leaves_the_rest_of_the_read_intact`, 조건 3은
`a_consent_read_that_fails_for_another_reason_never_reads_as_granted`, 조건 4는
`a_project_without_a_consent_record_is_asked_for_one`, 조건 5는
`granting_consent_sends_the_project_and_the_notice_version`, 조건 6은
`revoking_consent_leaves_the_project_asking_for_consent_again`, 조건 7은
`the_consent_commands_are_registered_where_the_screen_can_call_them`, 조건 8은
`an_incompatible_runtime_is_never_asked_about_consent`가 각각 확인한다. 화면이 읽을 필드 이름과 상태
문자열은 `the_consent_value_reaches_the_screen_under_the_agreed_names`가 함께 고정한다. 조건 9는
`docs/agent-runtime.md`의 "실행 권한 동의" 절을 읽어 확인한다.

다음 한 줄로 이 작업이 더한 검사만 따로 볼 수 있다.

```sh
cargo test --manifest-path src-tauri/Cargo.toml consent
```

`8 passed, 0 failed`가 나온다. 아홉 개 중 이름에 consent가 없는
`a_runtime_that_does_not_know_the_command_leaves_the_rest_of_the_read_intact` 하나만 이 필터에 걸리지
않으므로, 그 하나는 위 전체 실행의 747에 포함된 것으로 확인한다.
