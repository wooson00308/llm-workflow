# 실행 환경에 프로젝트별 실행 권한 동의 기록과 확인·동의·철회 명령을 만든다

## 결정권자 요약

### 제안

앱을 닫아도 살아 있는 실행 환경이 프로젝트마다 실행 권한 동의를 직접 보관하고, 그 상태를 확인하고
동의하고 철회하는 세 가지 조작에 답하게 만든다.

### 현재

실행 환경에는 동의를 적어 둘 자리가 없다. 앱이 무엇을 묻고 무엇을 확인받든 실행 환경은 그 사실을
알 수 없고, 앱이 닫히면 확인한 내용도 함께 사라진다.

### 변경 후

실행 환경이 프로젝트 식별자와 사용자가 읽은 고지 버전과 동의 시각을 보관한다. 앱은 그 기록을 읽고,
동의를 남기고, 철회할 수 있다.

### 사용자 결과

이 작업만으로는 화면이 달라지지 않는다. 동의를 묻는 화면과 동의 전 실행 차단은 뒤따르는 작업이
붙이며, 이 작업은 그 두 가지가 딛고 설 기록을 만든다.

### 영향 범위

- 변경: 실행 환경이 보관하는 프로젝트별 동의 기록, 실행 환경이 답하는 명령 목록, 실행 환경 계약 문서
- 유지: 기존 설정과 실행 큐와 실행 이력, 자동 배정과 직접 배정의 현재 동작, 사용자 승인과 품질 확인 관문

### 비용과 위험

동의 기록은 권한을 제한하는 장치가 아니라 사용자가 전제를 읽었다는 사실의 기록이다. 여기에 실행 도구
인증 정보나 작업 지시를 함께 넣으면 기록의 성격이 바뀌므로 보관 값을 세 가지로 제한한다.

### 결정 요청

이 작업 자체로는 눌러 볼 화면이 없다. QA에서는 아래 검증 단계의 자동 검사가 동의 기록의 저장과
확인과 철회, 그리고 고지 버전이 올라갔을 때의 무효 판정을 확인했는지를 본다.

## 범위 사전 검사

이 작업이 만드는 값은 셋이다. 동의 기록 자체(프로젝트 식별자, 고지 버전, 동의 시각), 실행 환경이
요구하는 고지 버전, 그리고 그 둘을 앱에 전달하는 세 명령이다. 실행 환경 저장소의 현재 코드를 열어
각 값이 어디서 생기고 어디까지 가는지 확인했다.

- 값 경로: 완료 조건 2·3·6의 동의 기록은 지금 어디에도 없으므로 저장 계층부터 만든다. 값을 만드는
  자리는 `../../Git/claude-heartbeat/src/heartbeat/agent_cli.py`의 `run_agent_command`에 붙일 동의
  명령 처리이고, 보관하는 자리는 `../../Git/claude-heartbeat/src/heartbeat/agent_store.py`의
  `AgentStore._initialize`가 만드는 표 하나다. 같은 파일의 `save_configuration`과 `get_configuration`이
  프로젝트 식별자를 열쇠로 쓰는 선례이므로 같은 열쇠를 쓴다. 응답까지 나르는 마지막 자리는
  `../../Git/claude-heartbeat/src/heartbeat/agent_contract.py`의 `envelope`이며, 이 함수는 전달받은
  데이터를 그대로 싣기만 하므로 편집하지 않는다. 세 파일 중 앞의 둘은 편집 대상이고 계약 파일은
  아래 두 항목 때문에 함께 편집한다.
- 값 경로: 완료 조건 1의 요구 고지 버전은 `agent_contract.py`의 상수로 새로 만든다. 이 값을 읽는 곳은
  같은 파일의 `contract_description`(계약 조회 응답)과 `agent_cli.py`의 동의 확인 처리 두 곳이며, 둘 다
  이 상수 하나만 읽게 해 요구 버전이 두 곳에서 갈라지지 않게 한다.
- 값 경로: 완료 조건 1의 명령 이름 세 개는 `agent_contract.py`의 `AGENT_COMMANDS`에 더한다. 이 목록은
  계약 조회가 알리는 목록이면서 동시에 `agent_cli.py`의 `run_agent_command`가 요청을 거절할지 판정하는
  기준이다. 목록에만 더하고 처리를 붙이지 않으면 계약이 알린 명령이 실행되지 않으므로 두 파일을 같은
  변경에서 편집한다.
- 값 경로: 완료 조건 7의 기존 데이터베이스 호환은 `agent_store.py`의 `_initialize`가 담당한다. 이 함수는
  파일을 열 때마다 표 생성문을 다시 실행하므로 새 표는 기존 파일에서도 생긴다. 기존 행을 고쳐 쓰는
  마이그레이션이 없으므로 같은 파일의 `AGENT_SCHEMA_VERSION`은 올리지 않는다. 이 값을 읽는 검사는
  `../../Git/claude-heartbeat/tests/test_agent_store.py`가 저장된 값과 상수를 대조할 뿐이라 값을 그대로
  두면 통과한다.
- 검토했으나 제외한 것: `../../Git/claude-heartbeat/src/heartbeat/agent_dispatch.py`는 이 작업에서 열지
  않는다. 이 작업의 완료 조건은 모두 기록과 세 명령의 응답으로 확인할 수 있고, 실행 경로에서 동의를
  집행하는 것은 다음 작업의 완료 조건이다. 같은 파일을 두 작업이 함께 고치면 겹침만 늘어난다.
- 검토했으나 제외한 것: 앱 저장소의 파일은 넣지 않는다. 이 작업의 어떤 완료 조건도 앱 화면이나 앱
  백엔드를 지나지 않으며, 앱이 이 명령을 부르는 경로는 별도 작업이 만든다.

## 현재 상태

실행 환경은 프로젝트별 설정, 실행 큐, 실행 이력, 자동 배정 의도, 감시 상태를 하나의 데이터베이스에
보관하고, 앱에는 버전이 붙은 JSON 명령으로만 답한다. 설정에는 자동 배정 여부와 역할별 정책이 있지만
사용자가 실행 권한과 무인 동작을 이해했다는 기록은 없다. 계약이 알리는 명령 목록에도 동의를 다루는
명령이 없다.

## 변경 범위

1. 계약 파일에 요구 고지 버전 상수를 만든다. 첫 값은 1이다. 이 상수는 "지금 유효하다고 인정하는 고지
   버전의 아래 끝"을 뜻하며, 고지 문구의 의미가 바뀔 때만 올린다. 맞춤법이나 배치 수정으로는 올리지
   않는다.
2. 계약이 알리는 명령 목록에 `consent.read`, `consent.grant`, `consent.revoke` 세 이름을 더하고, 계약
   조회 응답이 요구 고지 버전을 함께 알리게 한다.
3. 저장 계층에 프로젝트별 동의 표를 만든다. 열은 프로젝트 식별자(기본 열쇠), 고지 버전, 동의 시각
   셋이다. 조회, 저장, 삭제 메서드를 같은 파일의 기존 메서드와 같은 방식으로 더한다.
4. 명령 처리 세 개를 더한다.
   - `consent.read`는 프로젝트 식별자만 받는다. 기록이 없어도 실패가 아니라 "동의 없음"으로 답한다.
   - `consent.grant`는 프로젝트 식별자와 고지 버전을 받아 기록하고, 저장된 값을 응답에 싣는다. 동의
     시각은 실행 환경이 정하며 요청에서 받지 않는다.
   - `consent.revoke`는 프로젝트 식별자를 받아 그 프로젝트의 기록만 지운다.
   세 명령 모두 저장된 프로젝트 설정을 요구하지 않는다. 사용자가 자동 배정을 처음 켜는 순간에는 아직
   설정이 저장되기 전일 수 있기 때문이다.
5. 세 명령의 응답에 담는 동의 값의 모양을 다음으로 고정한다. 앱이 이 이름으로 읽는다.
   `{"consent": {"projectId": 문자열, "granted": 참거짓, "valid": 참거짓, "noticeVersion": 정수 또는 null,
   "grantedAt": 문자열 또는 null, "requiredNoticeVersion": 정수}}`
   `granted`는 기록이 있는지, `valid`는 기록이 있고 그 고지 버전이 요구 버전 이상인지를 뜻한다.
6. 요구 버전보다 낮은 고지 버전으로 온 동의 요청은 기록하지 않고 `consent_notice_outdated` 사유로
   거절한다. 고지 버전이 정수가 아니면 기존 요청 검사와 같은 방식으로 거절한다.
7. 계약 문서에 세 명령의 요청과 응답, 유효 판정 규칙, 고지 버전을 올리는 기준과 올리지 않는 기준을
   적는다.

## 범위 밖

- 실행 경로에서 동의를 확인해 실행을 막는 판정
- 앱 화면, 앱 백엔드, 앱과 실행 환경을 잇는 호출 계층
- 고지 문구 자체의 작성
- 기존 설정 명령의 필드 추가나 의미 변경
- 실행 큐, 실행 이력, 자동 배정 의도, 감시 상태의 구조 변경

## 완료 조건

1. 계약 조회 응답이 알리는 명령 목록에 동의 확인·동의·철회 세 이름이 모두 있고, 같은 응답이 요구
   고지 버전을 함께 알린다.
2. 동의 기록이 없는 프로젝트에 동의 확인을 보내면 실패가 아니라 성공으로 답하며, 응답의 동의 여부와
   유효 여부가 모두 거짓이고 고지 버전과 동의 시각이 비어 있으며 요구 고지 버전이 실려 있다.
3. 동의 요청이 프로젝트 식별자와 고지 버전만으로 성공하고, 응답에 동의 시각과 저장된 고지 버전이
   실린다. 그 프로젝트에 저장된 설정이 없어도 성공한다.
4. 요구 버전보다 낮은 고지 버전으로 동의를 보내면 기록이 생기지 않고 `consent_notice_outdated` 사유로
   거절된다. 그 뒤 동의 확인을 보내면 여전히 동의 없음으로 답한다.
5. 요구 고지 버전을 올린 상태에서 이전 버전으로 기록된 동의를 확인하면 동의 여부는 참이고 유효 여부는
   거짓으로 답한다. 기록 자체는 지워지지 않는다.
6. 철회 요청은 그 프로젝트의 기록만 지운다. 같은 데이터베이스에 있던 다른 프로젝트의 동의는 그대로
   남고, 그 프로젝트의 동의 확인은 여전히 유효로 답한다.
7. 이 변경 이전에 만들어진 데이터베이스 파일을 열어도 동의 표가 생기고, 기존 설정과 실행 이력과 자동
   배정 의도가 그대로 읽힌다.
8. 동의 기록에 저장되는 값이 프로젝트 식별자와 고지 버전과 동의 시각뿐이다. 인증 정보, 비밀값, 작업
   지시가 저장되는 자리가 없다.
9. 계약 문서에 세 명령의 요청과 응답 모양, 유효 판정 규칙, 고지 버전을 올리는 기준이 적혀 있다.

3. 세 명령의 응답 검사를 추가하고 실행한다. 완료 조건 2부터 6까지를 각각 확인한다.
   명령: `python -m pytest tests/test_agent_cli.py`
4. 저장소 전체 검사를 실행해 기존 동작이 유지되는지 확인한다. 명령: `python -m pytest`
5. 완료 조건 8은 저장된 행 전체를 문자열로 만들어 요청에 없던 값이 섞이지 않았음을 검사 코드 안에서
   단언해 확인한다.

## 확인 동선

이 작업에는 눌러 볼 화면이 없다. 동의 기록과 세 명령은 앱이 부르는 실행 환경의 내부 계층이고, 그 계층을
쓰는 화면은 뒤따르는 작업이 만든다. 따라서 이 작업은 자동 검사로 닫았으며, 확인 도장은 아래 수치를
신뢰한다는 뜻이다.

확인하는 수치는 다음과 같다. `../../Git/claude-heartbeat`에서 실행한다.

- `python -m pytest tests/test_agent_contract.py` → 13 passed
- `python -m pytest tests/test_agent_store.py` → 17 passed
- `python -m pytest tests/test_agent_cli.py` → 27 passed
- `python -m pytest` → 353 passed, 8 skipped

마지막 수치가 이 작업의 핵심이다. 변경 전 저장소 전체 검사는 343 passed, 8 skipped였다. 늘어난 10개가
이 작업이 더한 검사이고, 건너뛴 8개는 그대로이며 실패는 없다. 즉 새 동작이 검사로 고정되었고 기존 동작은
하나도 깨지지 않았다.

완료 조건과 검사의 대응은 다음과 같다. 조건 1은 `test_contract_announces_the_three_consent_commands_and_the_required_notice_version`,
조건 2는 `test_consent_read_answers_absent_consent_with_success_not_failure`, 조건 3은
`test_consent_grant_succeeds_without_a_stored_configuration_and_stamps_the_time`, 조건 4는
`test_consent_grant_below_the_required_notice_version_records_nothing`과
`test_consent_grant_rejects_a_notice_version_that_is_not_an_integer`, 조건 5는
`test_raising_the_required_notice_version_invalidates_without_deleting_the_record`, 조건 6은
`test_consent_revoke_clears_only_the_named_project`, 조건 7은
`test_database_written_before_consent_existed_gains_the_table_and_keeps_its_rows`, 조건 8은
`test_consent_round_trips_and_stores_only_the_three_recorded_values`가 각각 확인한다. 조건 9는
`docs/agent-runtime-contract.md`의 "실행 권한 동의" 절을 읽어 확인한다.

직접 눈으로 보고 싶다면 아래 한 줄로 계약 조회 응답에 세 명령과 요구 고지 버전이 실렸는지 볼 수 있다.

```sh
cd ../../Git/claude-heartbeat && python -c "import json;from heartbeat.agent_contract import contract_description as d;c=d();print(c['requiredNoticeVersion'], [x for x in c['implementedCommands'] if x.startswith('consent')])"
```

`1 ['consent.grant', 'consent.read', 'consent.revoke']`가 나오면 맞다.
