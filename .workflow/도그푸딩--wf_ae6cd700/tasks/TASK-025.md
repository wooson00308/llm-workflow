# 날짜를 선택해 그날 이벤트를 보고 빈 상태를 구분해 알린다

SPEC-007 R7, R9, 그리고 R5의 화면 부분을 구현한다. TASK-024가 만든 집계 칸을 눌러 그날 이벤트를
시간순으로 보고 작업 상세로 갈 수 있게 하고, 이력이 없어 타임라인에 한 번도 나타나지 않는 작업의
존재를 알리고, 이벤트가 없는 달과 필터 때문에 비어 보이는 달을 구분한다.

## 의존성

- **선행 필수: TASK-024.** 집계 칸과 이벤트 묶기가 있어야 그 위에 선택을 얹는다.
- TASK-024와 병행 금지. 같은 컴포넌트와 같은 CSS 블록을 만진다.

## 범위

- `src/features/projects/components/DevelopmentBoard.tsx` — 날짜 선택 상태, 상세 패널, 안내 문구.
- `src/App.css` — 상세 패널과 안내 스타일.
- `src/features/projects/components/DevelopmentBoard.test.tsx` — 선택·상세·접근성·빈 상태 테스트.
- 그 외 파일은 건드리지 않는다.

## 작업 내용

### 0. 먼저 읽을 제약

- 상세를 여는 동작이 달 이동이나 필터 상태를 바꾸지 않는다(R7). 선택 상태는 타임라인 안에만 둔다.
- 작업 상세 화면의 구조는 바꾸지 않는다(기획서 제외 범위). 이벤트 항목에서 여는 화면은 지금
  `onOpen(item)`이 여는 그 화면이다.
- 얻지 못한 시각을 채우지 않는다(R5). 이력이 없는 작업은 타임라인에 나타나지 않는 것이 맞고, 대신
  그런 작업이 있다는 사실을 알린다.

### 1. 날짜 선택

이벤트가 하나 이상 있는 날 칸만 누를 수 있게 한다. 이벤트가 없는 날은 지금처럼 비어 있고 조작 대상이
아니다. 42칸을 전부 탭 정지로 만들면 키보드 이동이 길어지기만 한다.

- 이벤트가 있는 칸은 `<button>`으로 만든다. 기본 키보드 조작(Tab 이동, Enter·Space 실행)이 그대로
  따라온다. 별도 키 처리를 만들지 않는다(R7의 키보드 요구).
- 접근성 이름에 날짜와 이벤트 수를 담아, 칸 안의 숫자·칩 글자만 읽히지 않게 한다.
  예: `8월 2일, 이벤트 5건`.
- 지금 선택된 날짜를 `aria-pressed`로 노출한다. 보조 기술이 어느 날짜가 선택됐는지 읽을 수 있어야
  한다(R7, 기획서 완료 조건 18).
- 선택 상태는 `CalendarView` 안의 `useState` 하나다. 값은 날짜 키(`YYYY-MM-DD`) 또는 `null`이다.
- 달을 옮기면 선택을 해제한다. 다른 달의 날짜가 선택된 채로 남으면 패널 내용과 그리드가 어긋난다.
- 필터가 바뀌어 선택한 날의 이벤트가 사라지면 패널은 "이 날짜에 표시할 이벤트가 없습니다"로 둔다.
  선택을 강제로 풀지 않는다. 필터를 되돌리면 그대로 돌아온다.

### 2. 상세 패널

그리드 아래, TASK-024가 비워 둔 자리에 그린다. 그리드는 그대로 남는다. 이렇게 하면 달 이동 버튼과
필터가 계속 보이고, "상세를 닫아도 달 이동·필터가 바뀌지 않는다"가 구조적으로 성립한다.

- 선택된 날짜가 없으면 패널을 그리지 않는다.
- 패널 머리에 선택한 날짜와 이벤트 수, 닫기 버튼을 둔다. 닫으면 선택이 풀리고 그리드만 남는다.
- 항목은 그날 이벤트를 시각 오름차순으로 늘어놓는다. 항목 하나에 시각·종류 이름·작업 id·작업 제목을
  담는다(R7).
- 항목은 `<button>`이고 누르면 그 작업의 상세 화면을 연다. 지금 캘린더 칩이 하는 것과 같은 경로
  (`onOpen(item)`)다.
- 같은 작업이 하루에 전이를 두 번 남겼으면 항목도 둘이다. `key`를 작업 파일 이름만으로 만들지 않는다.

### 3. 기록 없는 작업 안내

타임라인에 한 번도 나타나지 않는 작업이 있다는 사실을 알린다(R5, 기획서 완료 조건 13).

- 대상은 지금 필터를 통과한 작업 중 이벤트가 하나도 없는 작업이다.
- 표시는 한 줄이다. 건수와 이유를 담는다. 예: `기록이 없어 타임라인에 표시되지 않는 작업 21건`.
- 작업 목록을 늘어놓지 않는다. 지금 캘린더가 아래에 목록을 쌓아 두는 모습이 기획서가 문제 삼은 그
  모습이다. 그 작업들은 보드·리스트에서 볼 수 있다.
- 그런 작업이 없으면 이 줄을 그리지 않는다. 시간이 지나 모두 이력을 갖게 되면 안내가 자연히 사라진다
  (기획서 완료 조건 13 후반).

### 4. 빈 달 구분

기록된 이벤트가 하나도 없는 달에 빈 그리드만 두지 않는다(R9).

`CalendarView`가 `hasFilters`를 props로 받는다. `DevelopmentBoard`에 이미 있는 값(`:54`)을 넘긴다.

- 이 달에 이벤트가 없고 필터가 없으면: `이 달에 기록된 전이가 없습니다.`
- 이 달에 이벤트가 없고 필터가 걸려 있으면: `필터 조건에 맞는 기록이 이 달에 없습니다.`
- 두 문구가 달라야 사용자가 "원래 없는 것"과 "내가 좁혀 놓은 것"을 구분한다(기획서 완료 조건 22).
- 이전 달·다음 달·오늘 이동은 그대로 둔다.

### 5. 테스트

`DevelopmentBoard.test.tsx`:

- 이벤트가 있는 날을 누르면 그날 이벤트가 시각 오름차순으로 나오고, 각 항목에 작업 id와 제목,
  종류 이름이 있다. (기획서 완료 조건 17)
- 항목을 누르면 `onReadTask`가 그 작업의 파일 이름으로 불린다. (기획서 완료 조건 17)
- 이벤트가 없는 날은 버튼이 아니다.
- 키보드로 날짜 버튼에 포커스를 두고 Enter로 열 수 있고, 선택된 날짜 버튼의 `aria-pressed`가 `true`,
  나머지가 `false`다. (기획서 완료 조건 18)
- 상세를 열고 닫아도 표시 중인 달과 검색어·상태 필터가 그대로다. 열기 전후로 달 제목과 입력값을
  대조한다. (기획서 완료 조건 19)
- 하루에 같은 작업의 이벤트가 둘이면 항목이 둘 나온다.
- 이벤트가 없는 작업이 섞여 있으면 안내 줄이 그 건수로 나오고, 모든 작업에 이벤트가 있으면 안내 줄이
  없다. (기획서 완료 조건 13)
- 이벤트가 없는 달로 이동하면 "기록된 전이가 없습니다" 계열 문구가 나온다. 검색어를 넣어 결과가 빈
  경우에는 필터 쪽 문구가 나온다. 두 문구가 서로 다르다. (기획서 완료 조건 22)
- 달을 옮기면 선택이 풀려 상세 패널이 사라진다.

## 완료 조건

1. 날짜를 선택하면 그날 이벤트가 시간순으로 나오고, 각 항목에서 작업 상세로 갈 수 있다.
   (기획서 완료 조건 17)
2. 날짜 선택과 상세 열람을 키보드로 할 수 있고 선택 상태가 보조 기술에 노출된다.
   (기획서 완료 조건 18)
3. 상세를 열고 닫아도 달 이동과 필터 상태가 바뀌지 않는다. (기획서 완료 조건 19)
4. 이력이 없어 타임라인에 나타나지 않는 작업의 존재가 표시되고, 그런 작업이 없으면 표시도 사라진다.
   (기획서 완료 조건 13)
5. 이벤트가 없는 달에서 그 사실이 안내되고, 필터로 비어 보이는 경우와 문구가 구분된다.
   (기획서 완료 조건 22)
6. 이전 달·다음 달·오늘 이동이 그대로 동작한다.
7. TASK-024의 완료 조건이 그대로 성립한다. 집계 칸과 요약줄 문구가 유지된다.
8. `npm run check`가 통과한다. (기획서 완료 조건 23)

## 범위 밖

- 작업 상세 화면의 구조 변경. 기획서 제외 범위다.

- 이벤트 종류별 필터 신설. 필터는 기존 검색어·상태 두 개다.

## 참고 사실

확인 시점 2026-08-02. 추정 없이 파일에서 읽은 값이다.

- `hasFilters`는 `DevelopmentBoard.tsx:54`에 이미 있고 지금은 필터 초기화 버튼(`:105`)만 쓴다.
- 캘린더 칩이 작업을 여는 경로는 `onOpen(item)`(`:423`)이고, 그것이 `openTask`(`:56`)를 거쳐
  `onReadTask`를 부른다.
- 달 이동은 `onCursorChange`(`:402`~`:404`)로 `DevelopmentBoard`의 `calendarCursor`(`:42`)를 바꾼다.
  선택 상태를 `CalendarView` 안에 두면 달이 바뀔 때 `cursor` prop 변화로 초기화 시점을 잡을 수 있다.
- 접근성 단정에 쓸 선례가 저장소에 있다. `qa-panel-resize`(`:242`~`:255`)가 `role`·`aria-*`·
  `tabIndex`를 직접 붙이고 `DevelopmentBoard.test.tsx`가 그 값을 확인한다.
- `.unscheduled-tasks` CSS는 TASK-024가 지운다. 이 작업은 그 자리에 새 규칙을 쓴다.
- 그리드 칸은 `.calendar-grid > div`(`App.css:449`)이고 `min-height: 102px`다. 칸을 `<button>`으로
  바꾸면 브라우저 기본 스타일(테두리·배경·글꼴)이 붙으므로 초기화가 필요하다.
