# 아이디어 미리보기가 요약 대신 전문을 문서 뷰어로 보여준다

SPEC-008 R1·R2·R4·R5·R6을 구현한다. TASK-026이 만든 읽기 경로를 화면에 붙여, 아이디어를 고르면
미리보기 패널이 요약 대신 원문 전체를 기획서·개발 작업과 같은 문서 뷰어로 보여준다. 목록 행(R3)은
건드리지 않는다.

## 의존성

- **선행 필수: TASK-026.** 읽기 경로와 `IdeaDocument` 타입이 있어야 한다.
- TASK-026과 병행 금지.
- **TASK-019(SPEC-006, 연동을 사이드바 독립 메뉴로)와 병행 금지.** `WorkspaceShell.tsx`와
  `App.css`를 같이 만진다. TASK-020·021도 `App.css`를 만지므로 같은 시각에 돌리지 않는다.

## 범위

- `src/features/projects/components/IdeaInbox.tsx` — 전문 조회, 세 상태 표시, 문서 뷰어 사용.
- `src/features/projects/components/IdeaInbox.test.tsx` — 전문·전환·로딩·실패·정보 유지 테스트.
- `src/features/projects/components/WorkspaceShell.tsx` — `IdeaInbox`에 조회 함수 전달.
- `src/features/projects/components/WorkspaceShell.test.tsx` — 새 prop 반영.
- `src/App.tsx` — 훅의 `readIdea`를 셸에 전달.
- `src/App.css` — 미리보기 본문 영역 스크롤·높이.
- 그 외 파일은 건드리지 않는다.

## 작업 내용

### 0. 먼저 읽을 제약

- 목록 행은 그대로다(R3). `excerpt`를 두 줄 말줄임으로 보여주는 표시, 상태 아이콘, 날짜,
  `기획 반영` 표시 어느 것도 바꾸지 않는다. `IdeaInbox.tsx:46`~`:65`는 이 작업에서 손대지 않는다.
- 미리보기의 제목·상태 배지·문서 ID·업데이트 시각·파일명은 계속 목록 요약(`item`)에서 그린다(R4).
  전문을 못 읽어도 이 정보는 남아 있어야 하므로, 조회 결과에 의존시키지 않는다.
- 실패했을 때 요약을 대신 보여주지 않는다(R5, 확인 필요 2번의 확정 사항). 사용자가 잘린 요약을
  전문으로 오인하는 것이 이 기획서가 막으려는 상태다.
- 별도 화면·모달을 만들지 않는다. 지금의 목록·미리보기 2단 구조 안에서 끝낸다(기획서 제외 범위).

### 1. 조회 배선

`WorkspaceShell.tsx`에서 `IdeaInbox`(`:356`~`:364`)에 `onReadIdea` prop을 넘긴다. 모양은
`DevelopmentBoard`가 받는 `onReadTask`(`:377`)와 같다 — 파일명 하나만 받고 워크플로우 디렉터리는
셸이 채운다.

```
onReadIdea={(fileName) => onReadIdea(workflow.directory, fileName)}
```

`WorkspaceShell`의 Props에 `onReadIdea(workflowDirectory, fileName): Promise<IdeaDocument | null>`를
더하고, `App.tsx`가 훅의 값을 셸에 넘기는 방식(`App.tsx:59`~`:60`의 `onReadSpec`·`onReadTask`)을
그대로 따라 `onReadIdea={workspace.readIdea}` 한 줄을 더한다. `src/App.tsx`도 이 작업의 범위다.

`IdeaInbox`는 `onReadIdea(fileName): Promise<IdeaDocument | null>`을 필수 prop으로 받는다.

### 2. 선택된 아이디어의 전문 조회

`IdeaInbox` 안에 조회 상태를 둔다. 값은 세 가지다: 불러오는 중 / 본문 있음 / 실패.

조회는 **클릭 핸들러가 아니라 선택된 파일명을 보는 `useEffect`로 건다.** 화면에 처음 들어와 첫
항목이 자동 선택된 경우(`IdeaInbox.tsx:14`, `:18`~`:22`)에도 전문이 보여야 하고(R1), 목록이 바뀌어
선택이 옮겨 간 경우도 같아야 한다. 클릭 핸들러에 걸면 두 경우가 빠진다.

효과의 의존성은 **선택된 항목의 `fileName` 문자열 하나뿐이다.** 조회 함수를 의존성에 넣으면 안
된다. 이유는 폴링이다 — `useProjectWorkspace`가 2.5초마다 `inspect`를 다시 불러
(`useProjectWorkspace.ts:305`~`:308`) `project` 객체가 새로 만들어지고, `readIdea`의 `useCallback`
의존성에 `project`가 있어 함수 정체성도 2.5초마다 바뀐다. 그 함수를 효과 의존성에 넣으면 2.5초마다
다시 조회하게 되어 화면이 로딩으로 깜빡이고 읽던 스크롤 위치가 사라진다.

조회 함수는 `useRef`에 담고 효과 안에서 `ref.current`로 부른다. ref 갱신은 별도 `useEffect`로
하고, 그 효과를 조회 효과보다 **먼저** 선언한다(같은 렌더에서 앞선 효과가 먼저 실행된다).

늦게 도착한 응답이 다른 문서를 덮어쓰지 않게 막는다. 효과의 정리 함수에서 취소 표시를 세우고,
응답 처리 시 취소되었으면 상태를 쓰지 않는다. 목록을 빠르게 오갈 때 이전 문서의 본문이 남으면
R1이 깨진다.

선택된 항목이 없으면(`selected === null`) 조회하지 않고 상태를 비운다. 이때 화면은 지금의 안내
화면 그대로다(`IdeaInbox.tsx:81`~`:90`, R1).

### 3. 미리보기 본문

`IdeaPreview`의 본문 영역(`IdeaInbox.tsx:103`~`:105`)을 바꾼다. 머리(`:94`~`:102`)와
바닥(`:106`~`:110`)은 그대로 둔다(R4).

- 본문 있음: `<MarkdownBody body={...} />`로 그린다. 기획서·개발 작업이 쓰는 그 컴포넌트다
  (`MarkdownBody.tsx`, `SpecWorkspace.tsx:144`). 새 뷰어를 만들지 않는다(R2).
- 불러오는 중: 불러오는 중임을 알리는 문구를 본문 자리에 둔다. 문구는 기획서 화면의 현행 방식에
  맞춰 `아이디어를 불러오는 중…`으로 한다(`SpecWorkspace.tsx:131`이 `기획서를 불러오는 중…`).
- 실패: 실패 사실을 본문 자리에 남긴다. 예: `아이디어 전문을 불러오지 못했습니다.` 요약을 대신
  그리지 않는다(R5). 실패해도 다른 아이디어를 선택하는 동작은 그대로 살아 있어야 한다 — 목록은
  이 상태와 무관하므로 상태를 목록 밖으로 새게 하지 않으면 자연히 성립한다.

`.idea-preview-body` 안의 기존 `<p>` 한 문단 표시는 사라진다. 세 상태 어디에도 `item.excerpt`를
쓰지 않는다.

### 4. 긴 본문 (확인 필요 1번의 확정 사항)

패널 안에서 본문만 스크롤한다. 화면 전체를 늘리지 않는다.

`App.css`의 `.idea-preview-body`(`:259`)에 높이 상한과 자체 스크롤을 준다. 왼쪽 `.idea-list`(`:242`)가
`max-height: 430px; overflow: auto;`이므로 같은 값을 기준으로 잡아 두 패널의 아래 끝이 크게 어긋나지
않게 한다. `flex: 1`을 유지한 채 스크롤이 실제로 걸리려면 `min-height: 0`이 함께 필요하다.

- 머리와 바닥은 스크롤 밖에 남는다. 본문을 내려도 제목·상태·문서 정보가 계속 보인다(R4).
- 기존 `.idea-preview-body p`의 서체·`white-space: pre-wrap` 규칙은 더 이상 쓰이지 않는다. Markdown
  본문은 `.markdown-body`(`:297`~) 규칙을 탄다. 이 작업 때문에 쓰이지 않게 된 규칙만 정리하고,
  주변 규칙은 손대지 않는다.
- 짧은 아이디어에서 빈 공간이 어색하게 남지 않아야 한다(R6). 패널 `min-height: 360px`(`:236`)는
  그대로 두고 본문 영역이 남는 높이를 채우게 한다.
- 다른 아이디어로 옮기면 본문이 처음부터 보여야 한다(R6). 스크롤 컨테이너에 `key={item.fileName}`을
  주어 문서가 바뀔 때 다시 마운트되게 한다. 스크롤 위치를 직접 되감는 코드보다 짧고, 조회 중·실패
  상태에서도 같은 결과가 나온다.

### 5. 테스트

`IdeaInbox.test.tsx`. 지금 두 테스트는 `onReadIdea` 없이 렌더하므로 새 prop을 넘기도록 함께 고친다.
기존 단정 중 `expect(screen.getAllByText("떠오른 생각을 바로 기록한다.")).toHaveLength(2)`(`:25`)는
목록과 미리보기가 같은 요약을 쓰던 시절의 단정이다. 미리보기가 더 이상 요약을 쓰지 않으므로 목록
쪽 하나만 남도록 고친다. 이 변화 자체가 이 기획서가 노린 것이다.

- 네 줄 이상인 본문을 돌려주는 조회로 렌더하면, 요약에 없는 뒷부분 문자열이 화면에 있다.
  (기획서 완료 조건 1)
- 화면에 처음 들어왔을 때 첫 항목의 파일명으로 조회가 불린다. 사용자가 아무것도 누르지 않은
  상태다. (기획서 완료 조건 2)
- 두 아이디어를 번갈아 선택하면 각 문서의 본문이 나오고 이전 문서의 본문 문자열이 화면에 없다.
  (기획서 완료 조건 3)
- 아이디어가 없는 워크플로우로 렌더하면 기존 안내 화면(`아이디어를 선택하세요`)이 나온다.
  (기획서 완료 조건 4)
- 본문에 frontmatter 문자열이 섞여 오지 않는다는 전제 아래, 화면에 `schema:` 같은 문자열이 없다.
  (기획서 완료 조건 5)
- 불릿·강조·링크가 있는 본문을 넣으면 목록 항목(`listitem`)과 링크가 요소로 나오고, 링크가
  `target="_blank"`과 `rel="noopener noreferrer"`를 갖는다. 평문 한 문단이 아니다.
  (기획서 완료 조건 6)
- 목록 행은 여전히 요약을 보여준다. (기획서 완료 조건 7)
- 조회가 어떤 상태이든 제목·상태 배지·문서 ID·업데이트 시각·파일명이 화면에 있다. 실패 상태에서도
  같다. (기획서 완료 조건 8)
- 조회가 끝나지 않은 상태에서 불러오는 중 문구가 보인다. 해소되지 않는 Promise로 재현한다.
  (기획서 완료 조건 9)
- 조회가 `null`을 돌려주면 실패 문구가 보이고, 그 아이디어의 요약 문자열이 미리보기에 나오지
  않는다. (기획서 완료 조건 10)
- 실패한 뒤 다른 아이디어를 선택하면 그 문서의 조회가 불리고 본문이 나온다. (기획서 완료 조건 11)

`WorkspaceShell.test.tsx`: 렌더 지점 여섯 곳(`:45`, `:94`, `:128`, `:176`, `:208`, `:237` 부근)에
`onReadIdea={vi.fn().mockResolvedValue(null)}`를 더한다. `onReadSpec`·`onReadTask`와 같은 방식이다.

## 완료 조건

1. 아이디어를 선택하면 미리보기에 본문 전체가 보이고, 자동 선택된 첫 항목도 같다.
   (기획서 완료 조건 1, 2)
2. 다른 아이디어로 옮기면 그 문서의 전문으로 바뀌고 이전 본문이 남지 않는다. (기획서 완료 조건 3)
3. 선택된 아이디어가 없으면 기존 안내 화면이 그대로 나온다. (기획서 완료 조건 4)
4. 화면에 frontmatter가 보이지 않는다. (기획서 완료 조건 5)
5. 전문이 기획서·개발 작업과 같은 문서 뷰어로 그려지고 링크 동작이 같다. (기획서 완료 조건 6)
6. 목록 행의 두 줄 말줄임 요약과 행 높이가 지금과 같다. (기획서 완료 조건 7)
7. 미리보기의 제목·상태 배지·문서 ID·업데이트 시각·파일명이 조회 상태와 무관하게 보인다.
   (기획서 완료 조건 8)
8. 불러오는 중과 실패가 각각 화면에 표시되고, 실패 시 요약이 전문 자리에 나오지 않는다.
   (기획서 완료 조건 9, 10)
9. 실패한 뒤에도 다른 아이디어를 이어서 선택할 수 있다. (기획서 완료 조건 11)
10. 긴 본문에서 2단 구조가 유지되고 본문 끝까지 스크롤로 읽을 수 있다. (기획서 완료 조건 12)
11. 다른 아이디어로 옮기면 본문이 처음부터 보인다. (기획서 완료 조건 13)
12. `npm run check`가 통과한다. (기획서 완료 조건 16)
