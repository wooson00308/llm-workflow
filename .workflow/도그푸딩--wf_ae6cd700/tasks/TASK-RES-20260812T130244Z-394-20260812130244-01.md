# 런타임 도구 이벤트에 도구 이름만 싣는다

## 결정권자 요약

### 제안

실행 기록의 도구 사용 항목에 어떤 도구를 썼는지 이름 하나만 남긴다.

### 현재

도구 사용은 종류만 반복해서 쌓이고, 실행이 파일을 고쳤는지 명령을 실행했는지 구분할 근거가 없다.

### 변경 후

도구 사용 기록마다 도구 이름이 함께 남는다. 도구에 넘긴 값과 도구가 돌려준 내용은 남기지 않는다.

### 사용자 결과

실행이 어떤 성격의 작업을 했는지 구분할 근거가 생긴다. 화면에 집계로 보여 주는 일은 다음 작업이 맡는다.

### 영향 범위

- 변경: 실행 기록에 남는 도구 사용 항목의 정보 범위
- 유지: 작업 지시와 인증 값을 보존하지 않는 원칙, 실행 배정과 취소와 재시도, 이름이 없는 기존 기록의 읽기

### 비용과 위험

이름 외의 값이 함께 실리면 민감정보 비보존 경계가 넓어진다. 가짜 인증 값과 가짜 명령 문자열을 넣은 이벤트를 저장한 뒤 저장 내용과 이벤트 파일과 데이터베이스 원본을 검색해 그 문자열이 없음을 확인했다.

### 결정 요청

QA에서는 도구를 섞어 쓴 실행을 만든 뒤, 기록에 도구 이름만 남고 도구에 넘긴 값과 돌려받은 내용이 어디에도 없는지 확인한다.

## 확인 동선

이 작업에는 눈으로 볼 화면이 없다. 도구 이름을 화면에 집계로 보여 주는 일은 다음 작업이 맡고, 이 작업은
런타임 기록에 이름을 남기는 데까지만 책임진다. 그래서 확인은 자동 검사로 닫았고, 확인 도장은 아래 숫자를
믿는다는 뜻이다.

직접 다시 돌려 보려면 `../../Git/claude-heartbeat`에서 다음을 실행한다.

- `python -m pytest tests/test_agent_providers.py` → 34개 통과. Claude와 Codex 양쪽에서 도구 이름이
  뽑히는지, 이름이 없으면 필드가 비는지, 이름이 있는 이벤트와 없는 이벤트가 섞여도 정규화가 실패하지
  않는지 확인한다.
- `python -m pytest tests/test_agent_dispatch.py` → 32개 통과. 이벤트를 저장하고 다시 읽었을 때 도구
  이름이 보존되는지, 이름이 없는 기록도 그대로 읽히는지 확인한다.
- `python -m pytest` → 343개 통과, 8개 건너뜀. 건너뛴 검사는 이번 변경과 무관한 운영체제 조건이며 변경
  전과 같다.

민감정보가 남지 않는지는 `test_stored_events_keep_the_tool_name_and_nothing_the_tool_was_given`가 확인한다.
이 검사는 도구 사용 블록의 입력에 가짜 인증 값과 가짜 명령 문자열을 넣고 저장까지 지나게 한 뒤, 저장된
이벤트 전체와 이벤트 파일과 데이터베이스 파일 원본에서 그 문자열과 블록 식별자를 찾아 없음을 단언한다.

## 범위 사전 검사

이 작업이 다루는 값은 하나다. provider가 준 도구 사용 블록의 이름이 공통 이벤트를 거쳐 앱이 읽는
로그 응답까지 도달해야 한다. 그 경로를 실제 코드에서 끝까지 따라 확인했다.

- 값 경로: 완료 조건 1·2·3·4의 도구 이름은 `src/heartbeat/providers/claude.py`의 `ClaudeProvider.normalize_line`과
  `src/heartbeat/providers/codex.py`의 `CodexProvider.normalize_line`이 만든다. 두 함수는 현재 이름을 추출하지 않으므로
  편집한다. 값은 `src/heartbeat/providers/process.py`의 `NormalizedLine`으로 옮겨지는데 이 데이터클래스에는 이름 필드가
  없으므로 편집한다. 같은 파일의 `_SupervisedRun._consume`이 `NormalizedLine`을 `_append`로 넘기면서 현재 `kind`와
  `raw_id`와 `detail`만 전달하므로 편집한다. `_append`는 `build_event`를 부르고, `build_event`는 `ProviderEvent`를
  만든다. 세 자리 모두 이름을 받지도 싣지도 않으므로 편집한다. `_append`의 JSONL 기록은 `asdict`로 데이터클래스 전체를
  직렬화하므로 `ProviderEvent`에 필드가 생기면 편집 없이 그대로 파일에 실린다.
- 값 경로: 완료 조건 5의 저장된 이벤트는 `src/heartbeat/agent_dispatch.py`의 `_drain_events`가 만든다. 이 함수는
  `ProviderEvent`에서 여덟 개 키를 손으로 골라 담는 명시적 목록이라 새 필드를 자동으로 통과시키지 않는다. 이름이 저장까지
  도달하려면 이 자리를 반드시 편집해야 하며, 이 작업의 다른 어떤 편집도 이 자리를 대신하지 못한다.
- 값 경로: 완료 조건 5의 저장과 조회 이후 구간은 편집하지 않는다. `src/heartbeat/agent_store.py`의 `append_events`는
  받은 사전을 그대로 직렬화해 넣고 `read_events`는 그대로 되돌리며, `src/heartbeat/agent_cli.py`의 `logs.read` 분기는
  그 목록을 손대지 않고 응답에 싣는다. 세 자리 모두 키를 고르지 않으므로 이름을 이미 변경 없이 나른다. 앱 쪽
  `src-tauri/src/domain/agent_runtime.rs`의 `RunLogPage`도 이벤트를 해석하지 않는 JSON 값 배열이므로 이 작업의 범위 밖이다.
- 값 경로: 완료 조건 6의 계약 문서는 `docs/agent-runtime-contract.md`의 로그 절이 담당한다. 이 문서는 앱과 런타임이
  함께 읽는 규격이고 새 선택 필드를 적지 않으면 앱 쪽 작업이 근거 없이 필드를 가정하게 되므로 범위에 넣는다.
- 검토했으나 제외한 것: 앱 저장소의 `src-tauri/runtime/`에 들어 있는 런타임 묶음과 `runtime-manifest.json`은 이 작업이
  건드리지 않는다. 이름 필드는 선택 사항이고 없는 기록도 그대로 읽히므로 지원 런타임 버전의 아래 끝을 올릴 이유가 없다.
  묶음 갱신은 릴리스 절차의 일이며 완료 조건 어디에도 필요하지 않다.
- 검토했으나 제외한 것: `tests/test_agent_store.py`는 저장 계층이 임의의 사전을 그대로 넣고 빼는지만 확인한다. 이름
  필드는 그 계층에서 특별 취급을 받지 않으므로 검사를 고칠 필요가 없다.

## 현재 상태

`NormalizedLine`은 이벤트 종류와 provider 원본 식별자와 상세 문장과 상태만 담는다. Claude 경로는 도구 사용 블록을
찾으면 종류만 도구로 표시하고 이름을 버린다. Codex 경로는 항목 유형이 명령 실행이나 도구 호출이면 종류만 도구로
표시하고 역시 이름을 버린다. 그 결과 실행 하나가 도구를 스물두 번 써도 저장된 기록은 같은 줄 스물두 개다.

## 변경 범위

1. 공통 이벤트 어휘에 도구 이름을 담는 선택 필드를 하나 추가한다. 값이 없으면 비운다. 필드 이름은 계약 문서와 구현이
   같은 이름을 쓴다.
2. Claude 정규화 경로는 provider가 준 도구 사용 블록에서 이름 값만 읽는다. 블록의 입력, 인자, 결과 본문, 식별자는
   읽지 않는다. 이름이 없으면 필드를 비우고 종류는 지금처럼 도구로 남긴다.
3. Codex 정규화 경로는 같은 필드를 쓴다. 항목이 이름 값을 직접 담고 있으면 그 값을 쓰고, 담고 있지 않으면 항목 유형을
   쓴다. 어느 쪽도 확인되지 않으면 필드를 비운다. 실제 Codex 이벤트 모양을 확인한 뒤 결정하고, 확인하지 못한 모양을
   가정해서 값을 만들지 않는다.
4. 이름 값에는 사용자 입력, 경로, 인자, 명령 문자열을 넣지 않는다. provider가 고정 어휘로 주는 이름만 옮긴다.
5. 저장 경로가 새 필드를 실제로 나르도록 이벤트 저장 직전의 항목 구성을 함께 고친다.
6. 계약 문서의 로그 절에 이 선택 필드와 그 값 범위, 그리고 필드가 없는 기존 기록도 유효하다는 사실을 적는다.

## 범위 밖

- 도구 인자, 입력, 표준 출력, 결과 본문을 새로 저장하는 일
- 기존에 저장된 이벤트에 이름을 소급해서 채우는 일
- 도구 이름을 사용자 유형으로 묶어 화면에 보여 주는 일. 이 작업은 이름을 남기는 데까지만 책임진다.
- 런타임 묶음 재생성, 릴리스 버전 변경, 지원 버전 범위 변경

## 완료 조건

1. 공통 이벤트 어휘에 선택적 도구 이름 필드가 있고, 값이 없는 경우와 있는 경우가 모두 정상으로 처리된다.
2. Claude의 도구 사용 이벤트를 정규화하면 도구 이름이 필드에 담기고, 같은 이벤트의 인자와 입력과 결과 본문은
   정규화 결과 어디에도 없다.
3. Codex의 도구 사용 이벤트를 정규화하면 같은 필드에 값이 담기고, 이름을 확인할 수 없는 항목에서는 필드가 비어 있다.
4. 도구 이름이 없는 이벤트와 이름을 담은 이벤트가 섞여 들어와도 정규화가 실패하지 않는다.
5. 이벤트를 저장하고 다시 읽으면 도구 이름이 보존된다. 저장 직전에 항목을 구성하는 자리를 고치지 않으면 이 조건이
   충족되지 않으므로, 저장과 조회를 함께 지나는 검사로 확인한다.
6. 계약 문서의 로그 절이 이 선택 필드를 설명하고, 필드가 없는 기존 기록이 계약 위반이 아님을 밝힌다.
7. 가짜 인증 값과 가짜 인자 문자열을 넣은 provider 이벤트를 정규화하고 저장한 뒤 저장된 내용을 통째로 검색해도
   그 문자열이 없다.

## 검증 단계

1. `../../Git/claude-heartbeat`에서 도구 이름 추출 검사를 Claude와 Codex 양쪽에 추가하고 실행한다.
   명령: `python -m pytest tests/test_agent_providers.py`
2. 저장과 조회를 함께 지나는 검사를 추가하고 실행한다. 명령: `python -m pytest tests/test_agent_dispatch.py`
3. 저장소 전체 검사를 실행해 기존 동작이 유지되는지 확인한다. 명령: `python -m pytest`
4. 완료 조건 7의 문자열 주입 검사를 검사 코드 안에서 수행하고, 저장된 이벤트 전체를 문자열로 만들어 주입한 값이
   없음을 단언한다.
