# 설정에서 사용자 정의 규칙을 편집하고 최종 적용 내용을 확인한다

## 결정권자 요약

설정 화면에서 프로젝트 사용자 규칙을 작성하고 켜거나 끌 수 있게 한다.
기획자, 아키텍트, 개발자 중 적용할 역할을 고르고 저장 전 실제 파일과 최종 규칙을 확인한다.
외부 변경이 감지되면 사용자의 입력을 유지한 채 다시 불러오도록 안내한다.
잘못된 파일과 더 새로운 형식은 자동으로 고치지 않으며 명시적인 확인 없이는 덮어쓰지 않는다.
규칙 변경은 다음에 시작하는 에이전트 세션부터 적용된다고 분명히 알린다.
HTML이나 링크가 미리보기에서 실행되지 않고, 비밀 값을 적지 말라는 안내도 제공한다.

## 목적

SPEC-048의 R2, R5, R6 화면 부분과 완료 조건 1부터 17까지의 사용자 확인 동선을 완성한다. TASK-134가
추가한 관리 규칙 카드와 알림을 유지하고, TASK-136이 제공하는 사용자 규칙 상태와 동작을 설정 화면에
연결한다.

## 설정 카드

설정 화면에 `사용자 정의 규칙` 카드를 추가한다. 다음 편집 값을 한 초안으로 다룬다.

- 사용 여부
- 기획자, 아키텍트, 개발자 적용 여부
- Markdown 본문

파일이 없으면 꺼진 새 초안으로 시작한다. 정상 파일은 저장 값을 복원한다. 켜려면 역할을 하나 이상
선택해야 한다. 끄더라도 역할과 본문은 지우지 않는다. 저장된 값과 초안이 다르면 저장하지 않은 변경을
표시한다. `변경 취소`는 마지막으로 사용자가 불러온 저장 상태로만 돌아가며 디스크를 다시 읽지 않는다.

본문을 완전히 비우는 저장은 별도 확인을 거친다. 형식 오류나 미래 스키마 파일은 원문과 오류를 먼저
보여주고, 사용자가 `새 형식으로 덮어쓰기`를 확인한 뒤에만 안전한 초안 편집으로 전환한다. 이때도 마지막
조회의 내용 식별값을 사용한다. 심볼릭 링크와 일반 파일이 아닌 항목은 앱에서 덮어쓰기를 제공하지 않고
사용자가 파일 시스템에서 정리한 뒤 다시 불러오게 한다.

카드에는 다음 안내를 항상 확인할 수 있게 둔다.

- 사용자 규칙은 앱 기본 규칙과 역할 계약을 완화할 수 없다.
- API 키, 비밀번호와 다른 비밀 값을 입력하지 않는다.
- 저장은 실행 중인 에이전트에 규칙을 다시 넣지 않으며 다음 세션부터 적용된다.
- 활성 lease가 있으면 해당 세션은 이전 규칙을 사용하고 있을 수 있다.

## 저장 전 미리보기

초안이 바뀌면 이전 미리보기를 즉시 무효화한다. 사용자는 `미리보기 준비`를 눌러야 저장할 수 있다.
백엔드가 반환한 다음 내용을 가공하지 않고 보여준다.

1. 고정 프론트매터와 본문이 포함된 저장 파일 전체
2. 선택한 역할의 공통 규칙, 역할 계약, 사용자 규칙
3. 각 출처의 읽는 순서, 적용 여부, 적용되지 않는 이유
4. 앱 기본 규칙과 역할 계약이 우선한다는 설명

저장 파일은 줄바꿈까지 확인할 수 있는 읽기 전용 원문으로 표시한다. 역할별 최종 규칙은 기획자,
아키텍트, 개발자 탭으로 전환한다. 사용자 본문의 Markdown 미리보기는 원시 HTML을 실행하지 않으며
링크를 눌러도 외부 페이지를 열지 않는다. 스크립트, 이벤트 속성, 위험한 URL을 DOM에 넣지 않는 것을
컴포넌트 검사로 확인한다.

## 외부 변경과 저장 결과

편집을 시작할 때의 내용 식별값과 작업 공간이 최근 읽은 값이 다르면 외부 변경 알림을 표시하고 저장을
막는다. 자동 조회가 초안이나 열린 미리보기를 바꾸면 안 된다. 사용자가 `다시 불러오기`를 누를 때만
디스크 상태로 초안을 교체하며, 저장하지 않은 변경이 있으면 먼저 확인한다.

저장 요청에서 `conflict`가 반환돼도 같은 방식으로 초안을 유지하고 다시 불러오기를 안내한다.
`retry_required`는 마이그레이션이 끝난 뒤 다시 시도할 수 있다고 표시하며 자동 재시도하지 않는다. 저장
성공 뒤에는 반환된 저장 상태를 새 기준으로 사용하고, 저장된 시각과 현재 적용 상태를 갱신한다.

사용자 파일 오류와 저장 오류는 TASK-134의 관리 규칙 동기화 오류와 구분한다. 어느 오류가 있어도 다른
프로젝트 열기, 설정 이동, 문서 탐색을 계속 사용할 수 있다.

## 변경 범위

- `CustomRulesCard.tsx`: 편집 초안, 역할 선택, 확인 동작, 미리보기, 외부 변경과 저장 결과 표시.
- `SettingsView.tsx`: 관리 규칙 카드와 별도로 사용자 정의 규칙 카드 배치.
- `WorkspaceShell.tsx`, `App.tsx`: TASK-136의 상태와 동작 전달.
- 각 컴포넌트 검사: 편집, 미리보기 필수 절차, 충돌 보존, 안전한 Markdown, 적용 시점 안내.
- `App.css`: 기존 설정 화면 디자인 체계 안에서 편집기, 역할 선택, 출처 탭, 경고 상태 스타일.

## 손대지 않는 것

- 백엔드 파일 파싱과 저장
- 여러 규칙 묶음, 이름, 정렬, 폴더 관리
- 개인, 앱 전체, 조직 전체 규칙
- 경로, 브랜치, 작업 종류, 모델 조건
- 템플릿, 마켓, 가져오기와 내보내기
- 자연어 품질 평가와 의미 기반 충돌 검사
- 실행 중인 에이전트 세션 재주입
- Codex 승인 정책과 Claude 권한 설정

## 완료 조건

1. 파일이 없는 프로젝트는 사용자 규칙이 꺼진 상태로 보이고 정상 파일은 저장 값을 복원한다.
2. 본문, 사용 여부, 세 역할을 편집하며 켠 상태에는 역할을 하나 이상 선택한다.
3. 규칙을 꺼도 본문과 역할을 보존하고 다음 세션의 적용 대상에서는 제외한다.
4. 저장하지 않은 변경과 저장된 값을 구분하고 변경 취소로 마지막 불러온 상태를 복원한다.
5. 현재 초안과 일치하는 미리보기를 준비하기 전에는 저장할 수 없다.
6. 저장 파일 미리보기와 역할별 최종 규칙 미리보기가 백엔드 원문, 세 출처의 순서, 적용 여부를 그대로
   보여준다.
7. 사용자 규칙보다 앱 기본 규칙과 역할 계약이 우선한다는 설명이 편집과 최종 미리보기에 있다.
8. 본문 전체 삭제, 형식 오류나 미래 스키마 덮어쓰기는 각각 명시적인 확인을 거친다.
9. 심볼릭 링크와 일반 파일이 아닌 항목은 앱에서 덮어쓰지 않고 다시 불러오기 절차를 안내한다.
10. 편집 중 외부 변경과 저장 충돌에서 초안을 유지하고 자동 병합이나 자동 덮어쓰기를 하지 않는다.
11. 활성 lease가 있으면 실행 중 세션이 이전 규칙을 사용할 수 있음을 알리되 저장을 막지 않는다.
12. 변경은 앱 재시작 없이 저장되고 다음 에이전트 세션부터 적용된다고 표시한다.
13. Markdown 미리보기는 HTML을 실행하지 않고 링크를 열지 않는다.
14. API 키와 비밀번호 같은 비밀 값을 입력하지 말라는 안내가 보인다.
15. 사용자 규칙 오류 중에도 프로젝트 전환, 설정 이동, 문서 탐색과 관리 규칙 상태 확인이 가능하다.
16. 여러 규칙 문서, 전역 규칙, 조건부 적용, 템플릿, 의미 기반 충돌 검사 화면이 없다.
17. 기존 자동 검사를 삭제하거나 약화하지 않고 프런트엔드 전체 검사가 통과한다.

## 검증 절차

1. 파일 없음과 정상 파일을 렌더링해 초기 초안, 저장 시각, 적용 상태를 확인한다.
2. 각 역할 선택과 켜기, 끄기, 본문 편집, 변경 취소를 사용자 동작 검사로 확인한다.
3. 초안을 바꿀 때 이전 미리보기가 무효화되고 새 미리보기 전 저장 버튼이 비활성인지 확인한다.
4. 저장 파일 원문과 세 역할의 출처 탭이 백엔드 결과를 그대로 표시하는지 확인한다.
5. 원시 HTML, 스크립트, 이벤트 속성, 일반 링크와 위험한 URL을 넣어 실행 요소와 외부 링크가 생기지
   않는지 확인한다.
6. 전체 삭제와 잘못된 파일 덮어쓰기에서 확인 전에는 저장 요청이 없는지 확인한다.
7. 자동 조회와 저장 충돌로 내용 식별값을 바꾸고 초안이 유지되며 다시 불러오기 전 저장이 막히는지
   확인한다.
8. 활성 lease, 잠금 재시도, 저장 성공을 각각 표시해 적용 시점 문구와 후속 행동을 확인한다.
9. 기존 설정 카드, 관리 규칙 알림, 프로젝트 전환과 탐색 검사를 함께 실행한다.
10. `npm run check`를 실행한다.
11. 개발 앱에서 저장 미리보기와 실제 파일을 비교하고, 새 에이전트 세션이 선택된 역할에서만 사용자
    규칙을 읽는지 확인한다.

## 범위와 선행

TASK-134가 먼저 완료돼야 한다. 이 작업은 같은 설정 화면, 작업 공간 전달 경로, 스타일 파일을 수정하며
관리 규칙 상태 카드와 알림을 보존해야 한다.

TASK-136도 먼저 완료돼야 한다. 이 작업은 TASK-136의 사용자 규칙 상태와 동작만 소비하고 화면에서 파일
형식, 내용 식별값, 역할별 최종 규칙을 다시 계산하지 않는다.

## 확인 동선

1. 개발 앱에서 이 저장소를 열고 사이드바 `설정`을 누른다. 기존 `관리 규칙` 카드 아래에 `사용자 정의
   규칙` 카드가 따로 보이고, API 키·비밀번호를 입력하지 말라는 안내와 다음 세션 적용 안내가 보인다.
2. `사용자 규칙 사용`을 켠 뒤 기획자·아키텍트·개발자 중 한 역할을 선택하고 Markdown 본문을 적는다.
   `저장하지 않은 변경이 있습니다`가 보이며 아직 `저장` 버튼은 비활성 상태여야 한다.
3. `미리보기 준비`를 누른다. 저장 파일 원문에 프론트매터와 본문이 함께 보이고, 역할 탭을 바꾸면 공통
   규칙, 해당 역할 계약, 사용자 정의 규칙이 1·2·3 순서와 적용 여부, 제외 사유를 함께 보여야 한다.
4. 미리보기에 일반 링크, `javascript:` 링크, HTML 태그와 외부 이미지를 본문으로 넣어도 클릭 가능한
   링크, 스크립트, 이미지가 생기지 않는지 확인한다. 미리보기를 준비한 뒤에만 `저장`이 활성화된다.
5. 본문을 완전히 비우고 `미리보기 준비`를 누르면 빈 본문 확인이 먼저 나오며, 확인 전에는 미리보기가
   바뀌지 않아야 한다. `변경 취소`는 파일을 다시 읽지 않고 마지막으로 불러온 값으로 돌아간다.
6. 저장한 뒤 앱을 재시작하지 않아도 카드의 마지막 수정 시각과 적용 상태가 갱신되고 `다음 에이전트
   세션부터 적용` 안내가 보여야 한다. 활성 lease가 있으면 이전 규칙을 사용할 수 있다는 안내가 추가되지만
   저장은 막히지 않아야 한다.
7. 편집 중 `.workflow/rules/custom.md`를 외부 편집기에서 바꾸고 약 2.5초 기다린다. 입력 중인 본문은
   유지되고 외부 변경 알림과 `다시 불러오기`가 나타나며 저장은 비활성화돼야 한다. 다시 불러오기는
   저장하지 않은 변경을 버릴지 한 번 더 확인해야 한다.
8. 형식이 잘못됐거나 더 새로운 스키마인 파일은 오류와 원문을 먼저 보여주고 `새 형식으로 덮어쓰기`
   확인 전에는 편집기를 보여주지 않아야 한다. 심볼릭 링크라면 덮어쓰기 버튼 없이 파일 시스템에서
   정리한 뒤 다시 불러오라고 안내해야 한다.
