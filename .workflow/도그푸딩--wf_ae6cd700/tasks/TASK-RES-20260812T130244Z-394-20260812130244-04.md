# 실행 요약에서 결과 보고서를 열어 읽는 길을 만든다

## 결정권자 요약

### 제안

실행 요약 카드에서 그 실행이 남긴 결과 보고서를 바로 열어 읽게 한다.

### 현재

실행이 무엇을 남겼는지 확인하려면 앱을 벗어나 파일을 직접 찾아야 한다.

### 변경 후

실행이 남긴 보고서가 확인되면 요약 카드에 바로가기가 생기고, 선택하면 앱 안에서 읽기 전용으로 열린다.

### 사용자 결과

실행 결과를 확인하는 경로가 앱 안에서 끝난다. 연결을 확인할 수 없으면 아무 보고서도 보여 주지 않는다.

### 영향 범위

- 변경: 실행 요약 카드의 바로가기, 앱 안의 보고서 읽기 화면
- 유지: 보고서 파일의 내용과 상태, 실행 배정과 취소와 재시도, 문서 승인과 품질 확인 관문

### 비용과 위험

연결이 틀리면 다른 실행의 결과를 그 실행의 결과로 읽게 된다. 확인된 연결만 표시하고 나머지는 비워 둔다. 대상 문서가
워크플로 목록에서 사라진 실행에서는 보고서가 남아 있어도 바로가기를 만들지 않는다.

### 결정 요청

QA에서는 보고서를 남긴 실행에서 바로가기가 열리고 본문이 읽기 전용으로 보이는지, 남기지 않은 실행에서 다른 실행의
보고서가 나타나지 않는지 확인한다.

## 확인 동선

1. 에이전트 화면에서 보고서를 남긴 실행을 선택해 상세를 연다. 요약 카드에 「결과 보고서」 항목이 나타나고 그 실행이
   남긴 보고서 제목이 단추로 보이면 맞다. 이 저장소에서는 최근 종료 목록의 개발 작업 실행이 그런 실행이다.
2. 그 보고서 제목을 누른다. 앱 안에 보고서 화면이 열리고 파일에 적힌 본문이 그대로 보이면 맞다. 화면에 입력 칸과
   저장·수정·삭제 단추가 하나도 없어야 한다. 본문을 아직 읽는 중이면 「보고서를 읽는 중입니다」가, 읽지 못했으면
   「보고서를 읽지 못했습니다」와 그 사유가 보인다. 어느 경우에도 빈 본문이 대신 보이지 않는다.
3. Escape를 누른다. 보고서 화면만 닫히고 실행 상세는 그대로 열려 있으면 맞다. 한 번 더 누르면 상세가 닫힌다.
4. 보고서를 남기지 않은 실행의 상세를 연다. 「결과 보고서」 항목 자체가 나타나지 않고, 방금 본 다른 실행의 보고서
   제목이 이 카드에 남아 있지 않으면 맞다.
5. 보고서를 열어 본 뒤 파일이 그대로인지 확인한다. 프로젝트 루트에서 `git status`를 실행했을 때 `.workflow`의
   보고서 파일이 변경 목록에 새로 올라오지 않으면 맞다.
6. 화면을 띄우지 않고 숫자로 확인하려면 `npm run typecheck`, `npm run test`, `npm run build`를 실행한다.

## 범위 사전 검사

이 작업이 다루는 값은 둘이다. 실행에 연결된 보고서 목록과 보고서 본문이다. 두 값 모두 앞선 작업이 백엔드에 만들어
두므로, 그 값이 화면까지 오는 경로만 확인하면 된다.

- 값 경로: 완료 조건 1·2의 연결된 보고서 목록은 앞선 작업이 만든 백엔드 판정에서 나온다. 판정 입력인 실행의 대상 문서
  식별자와 예약 결과 접두어는 앞선 작업이 실행 요약에 실어 두므로 이 작업에서 다시 만들지 않는다. 값이 화면으로 오려면
  `src/features/projects/infrastructure/tauriProjectGateway.ts`에 호출을 더해야 한다. 이 파일은 백엔드 명령을 부르는
  유일한 자리이므로 편집한다. 그 호출의 형태와 반환 형태는 `src/features/projects/domain/types.ts`가 선언하므로 함께
  편집한다. 받은 값을 화면 상태로 들고 있는 자리는 `src/features/projects/application/useProjectWorkspace.ts`이므로 편집한다.
  표시는 `src/features/projects/components/agents/AgentRunDashboard.tsx`의 실행 요약 카드가 맡으므로 편집한다.
- 값 경로: 완료 조건 3·4의 보고서 본문도 같은 네 자리를 지난다. 호출 계층에 본문 읽기를 더하고, 형태를 선언하고, 상태로
  들고, 읽기 전용 화면으로 보여 준다. 본문을 읽는 백엔드 명령은 앞선 작업이 만들어 두므로 이 작업은 새 명령을 만들지 않는다.
- 값 경로: 완료 조건 2의 연결 없음 처리는 화면에서 값을 지어내지 않는 것으로 충족한다. 백엔드가 빈 목록을 주면 바로가기를
  만들지 않고, 다른 실행의 목록을 대신 쓰지 않는다. 실행 식별자별로 상태를 나누어 보관해 한 실행의 결과가 다른 실행의
  카드에 나타나지 않게 한다.
- 값 경로: 완료 조건 5의 읽기 전용은 화면이 본문을 편집 가능한 입력으로 두지 않고 저장 경로를 만들지 않는 것으로
  충족한다. 앱에는 보고서를 쓰는 명령 자체가 없으므로 화면에서 편집 수단을 만들지 않으면 파일이 바뀔 경로가 없다.
- 검토했으나 제외한 것: `src-tauri`의 어떤 파일도 이 작업에서 편집하지 않는다. 필요한 명령과 판정은 앞선 작업이 모두
  만들고, 이 작업의 완료 조건은 그 명령을 부르고 결과를 보여 주는 것으로 전부 충족된다.
- 검토했으나 제외한 것: 기획서와 개발 작업을 읽는 기존 문서 화면은 건드리지 않는다. 보고서는 앞머리 메타데이터가 없는
  평범한 문서라 그 화면들의 구조와 다르고, 그 화면을 고치면 승인 범위 밖의 문서 표시까지 함께 바뀐다.

## 현재 상태

실행 상세에는 결과 보고서로 가는 길이 없다. 프로젝트 요약은 보고서 개수만 싣고, 화면은 어떤 실행이 어떤 보고서를
남겼는지 알지 못한다. 사용자는 실행이 끝난 뒤 결과를 확인하려면 앱 밖에서 파일을 찾아야 한다.

## 변경 범위

1. 실행에 연결된 보고서 목록을 읽는 호출을 더한다. 입력은 그 실행의 대상 문서 식별자와 예약 결과 접두어이며, 화면이
   파일 이름이나 경로를 만들어 넘기지 않는다.
2. 실행 상세가 열릴 때 그 실행의 연결된 보고서를 읽는다. 결과는 실행 식별자별로 나누어 보관한다.
3. 연결된 보고서가 있으면 요약 카드에 바로가기를 보여 준다. 여러 개면 모두 보여 준다. 없거나 확인하지 못하면 바로가기를
   만들지 않고, 다른 실행의 보고서를 대신 보여 주지 않는다.
4. 바로가기를 선택하면 앱 안에서 본문을 읽기 전용으로 연다. 본문을 읽는 동안과 읽지 못했을 때의 표시를 함께 만든다.
5. 보고서 화면에는 편집 입력과 저장 수단을 두지 않는다.
6. 보고서 읽기 화면에 필요한 화면 규칙을 `src/App.css`에 더한다.

## 범위 밖

- 보고서 본문 편집, 삭제, 상태 변경
- 보고서 목록을 실행과 무관하게 전체로 보여 주는 화면
- 실행 요약 카드의 다른 항목 변경
- 진단 번들 저장과 복사
- 실행 배정, 취소, 재시도, 문서 승인과 품질 확인의 의미 변경

## 완료 조건

1. 보고서를 남긴 실행의 상세를 열면 요약 카드에 그 보고서 바로가기가 나타난다.
2. 보고서를 남기지 않은 실행과 연결을 확인하지 못한 실행에서는 바로가기가 나타나지 않고, 다른 실행의 보고서가 노출되지
   않는다. 한 실행에서 읽은 목록이 다른 실행의 카드에 남지 않는다.
3. 바로가기를 선택하면 앱 안에서 본문이 열리고 파일 내용이 그대로 보인다.
4. 본문을 읽지 못하면 그 사실을 표시하고, 빈 본문이나 다른 문서를 대신 보여 주지 않는다.
5. 보고서를 연 뒤에도 보고서 파일과 다른 워크플로 문서가 변경되지 않는다. 화면에 편집 입력과 저장 수단이 없다.
6. 화면이 보고서 파일 이름이나 경로를 스스로 만들어 호출하지 않는다.
7. 기존 실행 상세의 요약 카드 표시와 실행 제어 검사가 변경 전과 같은 결과로 통과한다.

## 검증 단계

1. 연결된 보고서가 있는 경우와 없는 경우를 모두 넣어 화면 검사를 더하고 실행한다. 완료 조건 1, 2를 확인한다.
   명령: `npm run test`
2. 바로가기 선택에서 본문 열림과 읽기 실패 표시를 확인하는 검사를 더한다. 완료 조건 3, 4를 확인한다.
   명령: `npm run test`
3. 호출 계층 검사로 화면이 넘기는 입력에 파일 이름과 경로가 없음을 확인한다. 명령: `npm run test`
4. 형식 검사와 빌드를 실행한다. 명령: `npm run check`
