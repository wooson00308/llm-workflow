# 개발 보드 카드가 컬럼 경계를 넘지 않게 하고 선언을 회귀 검사로 고정한다

SPEC-021 R1~R6 전부를 닫는다. 개발 보드의 카드가 자기 컬럼을 뚫고 옆 컬럼 위에 그려진다. 원인은
CSS 두 갈래이고 기획서 확인 사실 1~4가 경로를 이미 확정해 두었다.

- `.task-stack`에 트랙 정의가 없어(`src/App.css:420`) 암시적 `auto` 열 트랙이 만들어지고, 그 트랙의
  최소 크기가 안에 놓인 카드의 min-content가 된다.
- `.task-card`(`:421`)와 `.task-column`(`:410`)에 `min-width` 선언이 없어 그리드 아이템의 초기값
  `auto`가 콘텐츠 기반 최소 크기로 해석된다. 카드의 min-content가 컬럼까지 그대로 올라온다.
- `.task-board`의 트랙은 `repeat(5, minmax(178px, 1fr))`(`:407`)이라 최소 함수가 고정값이다.
  트랙이 콘텐츠로 넓어지지 못하므로 초과분이 트랙 밖으로 나간다.
- 상자를 넓히는 것은 요약문 안의 줄바꿈 불가 ASCII 런이다. `.task-card > p`가 두 줄에서 잘리지만
  (`:426`) `overflow: hidden`은 min-content 기여를 줄이지 않아, 안 보이는 글자가 계속 상자를 넓힌다.

## 승인된 확인 필요 3건

DECISION-C9B1C1D5는 본문 없이 승인만 기록했다. 아키텍트 유의 사항이 없으므로 기획서의 세 제안을
그대로 따른다.

1. **긴 토큰은 접는다.** 잘라내지 않는다. 요약문에 이미 두 줄 클램프가 걸려 있어 접어도 카드 높이가
   변하지 않고, 잘라내기를 고르면 요약문이 한 줄로 줄어 지금 보이던 정보가 실제로 줄어든다.
2. **회귀 검증은 스타일 규칙을 문자열로 읽는 자동 검사로 한다.** 확인 사실 15~17대로 jsdom은
   레이아웃을 계산하지 않고 컴포넌트 테스트에는 스타일시트가 실리지도 않아, 실제로 재는 검증은 지금
   스택에서 성립하지 않는다.
3. **처방은 보드에만 건다.** 카드 계열 공통 규칙을 세우지 않는다. 나머지 네 자리는 이미 막혀 있고
   각자 한 줄 말줄임이라는 다른 어법을 쓴다(확인 사실 13).

## 작업 내용

### CSS 수정

- `.task-stack`에 트랙을 명시해 암시적 `auto` 트랙 경로를 끊는다. 확인 사실 1이 지목한 지점이다.
  같은 처방이 이 저장소에 이미 있다 — `.idea-list > button`이 `grid-template-columns: 32px
  minmax(0, 1fr) auto`를 쓴다(`:246`). 새 어법을 들이는 일이 아니다.
- `.task-card`와 `.task-column`의 콘텐츠 기반 최소 크기를 해제한다. 확인 사실 2~3의 지점이다.
  `.search-result-copy`가 같은 목적으로 `min-width: 0`을 쓴다(`:557`).
- 카드 텍스트가 긴 토큰을 접게 한다. **대상은 요약문과 제목 둘 다다**(R2). 지금 재현된 것은
  요약문이지만 제목도 같은 값을 받는 자리이고 아무 장치가 없다.
- 접기 선언의 선택에 주의할 점이 하나 있다. 이 저장소가 쓰는 기존 어법은 `word-break: break-word`
  세 자리다(`:648`, `:683`, `:716`, 확인 사실 14). 다만 `overflow-wrap: break-word` 계열이 만드는
  줄바꿈 기회는 min-content 내재 크기 계산에 **반영되지 않는** 반면 `overflow-wrap: anywhere`는
  반영된다. R2가 요구하는 것이 "긴 토큰이 카드의 최소 폭을 정하지 않는다"이므로 `anywhere` 쪽이
  요구사항을 직접 만족시킨다. 원천 아이디어가 지목한 처방도 `overflow-wrap: anywhere`다.
  트랙·최소폭 처방과 함께 걸면 둘 중 무엇이든 화면상 접히지만, 한 겹이 빠졌을 때도 버티는 쪽을
  권한다. 무엇을 골랐든 그 이유를 보고서에 한 줄 남긴다.
- 클램프를 건드리지 않는다. `.task-card > p`의 `-webkit-line-clamp: 2`와 `display: -webkit-box`,
  `overflow: hidden`이 그대로 남아야 한다(R4, 완료 조건 6).
- `.task-board`의 `min-width: 950px`과 `overflow-x: auto`, `.task-board.columns-1`의 트랙을
  그대로 둔다(완료 조건 10). 컬럼 하나만 남은 상태(`:408`)도 R1의 대상이지만, 그 트랙을 고쳐서가
  아니라 스택·카드·컬럼 쪽 처방으로 성립해야 한다.
- `word-break: keep-all`이 걸린 두 자리(`:50`, `:572`)를 건드리지 않는다(완료 조건 8).

### 회귀 검사

- `src/App.css`를 문자열로 읽어, 넘침을 막는 선언이 해당 규칙에 남아 있는지 검사한다. 규칙을 하나씩
  집어 그 선언의 존재를 단언한다. 파일 전체에서 문자열을 찾는 방식은 쓰지 않는다 — 다른 규칙에 같은
  선언이 있으면 통과해 버린다.
- 지키는 선언과 함께 **깨지면 안 되는 선언**도 같이 검사한다. `.task-card > p`의 클램프(완료 조건 6),
  `.task-board`의 `min-width`·`overflow-x`(완료 조건 10), `word-break: keep-all` 두 자리
  (완료 조건 8)다. 이 검사 하나가 R4의 회귀도 같이 잡는다.
- **검사가 무엇을 보장하고 무엇을 보장하지 못하는지를 검사 파일 안에 적는다**(완료 조건 12).
  이 검사는 레이아웃을 재지 않는다. "그 선언이 그 규칙에 있다"까지만 보장하고 "그래서 카드가 안
  넘친다"는 보장하지 못한다. 확인 사실 15~16이 그 이유다. 이 문장을 파일 머리 주석에 남긴다.
- 검사가 CSS 포매팅에 취약하다는 점을 감안한다. 선언 하나를 정확한 공백까지 맞춰 찾기보다 규칙 본문을
  뽑은 뒤 그 안에서 속성과 값을 확인하는 편이 낫다. 구체적인 모양은 구현이 정한다.

### 재현 데이터 검사 (R6)

- 확인 사실 10의 실제 문자열을 검사 입력에 넣는다(완료 조건 11). 지어낸 긴 문자열을 쓰지 않는다.
  33자 무공백 런은 정확히 이것이다.

  ```
  (`HeartbeatCard.tsx:246`~`:252`).
  ```

  이 런이 실린 TASK-049의 실제 요약문은 143자이고 160자 컷에 걸리지 않아 런이 온전히 살아 있다.

  ```
  SPEC-016 R2·R4·R7·R8·R9·R10·R11을 구현한다. TASK-048이 스냅샷에 실어 둔 단계 목록을 화면이 처음으로 읽는다. 지금 안내는 명령 두 줄이고 미설치 분기에만 붙어 있다(`HeartbeatCard.tsx:246`~`:252`).
  ```

- 이 요약문을 가진 작업을 `DevelopmentBoard.test.tsx`의 시나리오에 실어, 그 문자열이 카드까지
  도달하는지 확인한다. jsdom이 레이아웃을 재지 않으므로 이 시나리오가 보장하는 것은 "이 데이터가
  카드에 실린다"까지다. 상자 크기를 묻지 않는다 — 물으면 전부 0이 돌아와 통과하는 것처럼 보이는
  거짓 검사가 된다. 이 한계도 함께 적는다.

8. `word-break: keep-all`이 걸린 두 자리(`:50`, `:572`)가 그대로다. 검증: 회귀 검사가 확인하고

11. 확인 사실 10의 실제 문자열이 검사 입력에 있다. 검증: 검사 코드에서 그 문자열을 확인한다.

12. 검사가 무엇을 보장하고 무엇을 보장하지 못하는지가 검사 파일에 적혀 있다. (완료 조건 12, R5)

- 요약문 생성 규칙. `markdown_excerpt`(`src-tauri/src/infrastructure/fs_project_repository.rs:1458`
  ~`:1471`)의 세 줄·160자 규칙과 백틱·코드 위치 표기를 그대로 둔다. 화면 문제를 데이터로 우회하지

- 카드에 실리는 정보 항목의 추가·삭제와 카드 디자인 변경. 상태 알약, 식별자, 제목, 두 줄 요약,

  않는다.

- 브라우저 기반 레이아웃 검사 도구 도입. 확인 필요 2번의 대안 (가)였고 승인되지 않았다.
