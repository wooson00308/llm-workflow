# 설치 마법사가 실행 버튼을 갖고 버전 어긋남이 화면에 보인다

SPEC-037의 화면 쪽 나머지다. R2와 확인 필요 1·2번의 승인안, 완료 조건 5를 닫는다. TASK-114·TASK-115가
만든 두 커맨드를 화면까지 잇는다.

두 가지가 한 작업인 이유는 파일 하나다. 둘 다 `HeartbeatCard.tsx`의 같은 자리(설치 마법사와 카드 머리)
를 만지고, TASK-116과도 같은 파일을 공유한다. 셋을 병렬로 두면 같은 파일을 세 세션이 동시에 고친다.

## 설치 실행 버튼 (R2)

- **실행 버튼이 붙는 단계는 백엔드가 정한다.** TASK-114가 `HeartbeatSetupStage`에 실은 실행 가능 표식을
  화면이 읽는다. 화면이 단계 종류를 보고 스스로 갈리지 않는다 — 갈림이 둘로 늘면 백엔드와 화면이 다른
  답을 낼 자리가 생긴다.
- 실행 대상이 아닌 단계(1·4단계)는 **지금 그대로** 명령 원문과 복사 버튼을 유지한다. 실행형이
  들어왔다고 해서 남은 단계의 안내가 사라지지 않는다.
- 실행 대상인 단계도 명령 원문과 복사 수단을 잃지 않는다. 실행이 실패한 자리에서 사용자가 손으로 끝낼
  수 있어야 한다(R6과 같은 계열).
- **확인 화면을 거친다.** 두 명령은 파일을 쓴다 — `heartbeat init`은 하트비트 홈에 문서를 만들고,
  `heartbeat install-service`는 서비스 등록물을 만들고 데몬을 띄운다. 무엇이 만들어지는지 알린 뒤
  실행한다(SPEC-020 R2가 세운 어법). 단계의 `evidence` 경로가 그 고지의 재료다.
- 실행 중에는 그 단계의 버튼이 눌리지 않고 진행 표시가 보인다. 겹쳐 누를 수 없다.
- 결과는 종료 코드와 stdout·stderr다. **앱이 실패 사유를 지어내지 않는다** — 두 명령의 종료 코드
  의미는 계약에 없으므로(TASK-112의 인용 절이 판단 기준이다) 성공/실패와 원문까지가 화면의 몫이다.
- 실행 뒤에는 연동 조회를 다시 불러 단계 상태를 갱신한다. 화면이 단계 상태를 스스로 바꾸지 않는다.
- 실행 수단을 찾지 못하면 그 사실과 본 후보, 명령 원문이 나온다(R5). TASK-116의 실패 표시와 같은
  모양을 쓴다.

## 버전 어긋남 표시 (확인 필요 2번)

TASK-115의 커맨드가 낸 값을 카드 머리 자리에 그린다.

- **부를 때** — 하트비트 카드가 펼쳐지는 순간 한 번, 그리고 업데이트가 끝난 뒤 한 번. **자동 새로고침
  주기에는 절대 부르지 않는다.** 이 호출은 프로세스를 하나 띄우는 조작이다.
- **어긋남** — 도는 데몬과 디스크의 버전이 다르면 두 값과 함께 경고 한 줄이 뜬다. 그 상태의 뜻은
  "코드는 갱신됐는데 도는 프로세스는 옛 코드"이고, 업데이트 버튼이 그 자리에서 다음 행동이다.
- **판정 불가** — 아는 값만 말하고 사유를 밝힌다. 실행 파일을 찾지 못한 경우, `state.json`이나
  `_daemon`이 없는 경우, 출력이 계약 밖 형식인 경우는 서로 다른 문장이다. 한쪽만 아는 상태를
  "같다"로도 "다르다"로도 접지 않는다(SPEC-034 R2).
- 084 경고의 판정은 건드리지 않는다. SPEC-024 R4가 정한 자리이고 기획서가 제외 범위로 적었다. 버전
  표시가 그 경고를 대체하거나 숨기지 않는다.

## 완료 조건

1. 설치 마법사의 2·3단계에 실행 버튼이 있고, 1·4단계에는 없으며 그 둘의 명령 원문과 복사 버튼이
   변경 전과 같다. (기획서 완료 조건 5)
2. 버튼이 붙는 단계는 백엔드가 실은 실행 가능 표식으로 정해진다. 화면에 단계 종류로 가르는 분기가
   없다.
3. 실행 전에 무엇이 만들어지는지 알리는 확인 화면이 있고, 취소하면 아무것도 실행되지 않는다.
4. 실행 중에는 그 단계의 버튼이 눌리지 않고 진행 표시가 보인다.
5. 결과에 종료 코드와 stdout·stderr 원문이 남고, 앱이 실패 사유를 지어내지 않는다.
6. 실행 뒤 연동 조회가 다시 불려 단계 상태가 갱신된다.
7. 실행 수단을 찾지 못하면 그 사실과 본 후보, 명령 원문이 나온다.
8. 도는 데몬과 디스크의 버전이 다르면 두 값과 경고가 보인다.
9. 판정 불가일 때 아는 값만 나오고 사유가 셋으로 갈린다.
10. 버전 조회가 자동 새로고침 주기에 불리지 않는다. 조회 주기가 도는 동안 호출 수가 늘지 않는 것이
    검사로 남는다.
11. 설치 판정·잡 저장·"지금 실행"·084 경고의 기존 동작이 달라지지 않는다. (R9, 완료 조건 7)
12. 기존 자동 검사가 삭제되거나 비활성화되지 않고, `npm run check`가 통과한다.

## 검증 절차

1. `npm run check`.
2. 화면 검사는 `IntegrationsView.test.tsx`에 세운다. 단계 픽스처는 실행 가능 표식이 참인 것과 거짓인
   것을 함께 두고, 버튼이 참인 단계에만 붙는지 확인한다.
3. 버전 표시는 판정 넷(같음·다름·실행 파일 없음·`_daemon` 없음)을 각각 세운다.
4. 조회 주기와 버전 호출이 섞이지 않는 것은 가짜 시간으로 주기를 여러 번 돌린 뒤 호출 수가 늘지
   않는 것으로 세운다.
5. 앱을 띄워 2·3단계 버튼과 버전 표시를 실제로 확인하고, 이 기기에서 무엇으로 끝났는지 보고서에
   적는다.
