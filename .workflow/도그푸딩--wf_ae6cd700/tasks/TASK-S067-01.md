# 에이전트 화면이 남은 준비 단계를 하나의 안내로 보여준다

## 결정권자 요약

### 제안

에이전트 화면 위쪽에 남은 준비 단계만 담은 안내를 하나 세우고, 지금 흩어져 있는 서비스 안내와
동의 안내를 이 안내가 대신하게 한다.

### 현재

준비 과정은 관리형 서비스 연결, 실행 권한 동의, 자동 배정 켜기로 이어지는 하나의 절차인데,
화면은 이것을 서로 모르는 안내 두 개와 토글 하나로 흩어 놓았다. 동의 안내는 자동 배정이 켜져
있을 때만 나타나고, 새 기기는 서비스가 연결되지 않아 자동 배정을 켤 수 없으므로 동의 안내가
나타날 조건 자체를 만들 수 없다. 그래서 새 기기에서 동의에 닿는 길은 직접 배정을 하나 만들어 그
흐름 안에서 동의를 만나는 역순뿐이다.

### 변경 후

화면 제목 아래, 자동 배정 토글 위에 안내 하나가 선다. 연결, 동의, 켜기 순서로 서 있고, 마친
단계는 완료로 표시되며 진행할 수 있는 단계는 그 자리에서 실행하는 버튼을 준다. 자동 배정이 꺼져
있어도 동의를 이 안내에서 열 수 있으므로 새 기기 사용자가 일감을 먼저 만들지 않고 순서대로
준비를 끝낸다. 세 단계가 모두 끝나면 안내가 통째로 사라지고 화면은 지금과 같은 구성으로 돌아간다.

### 비용과 위험

준비가 끝나지 않은 기기에서만 안내가 화면 위쪽을 차지하고, 끝나면 사라진다. 지금도 같은 자리를
안내 두 개가 쓰고 있어 늘어나는 세로 길이는 단계 하나 분량이다. 동의 관문 자체는 손대지 않는다.
고지 문구와 버전 판정, 동의 없이는 세션을 시작하지 않는 실행 조건, 직접 배정 흐름 안의 동의,
동의 철회, 자동 배정 토글의 자리와 켜기 확인 창은 그대로 둔다. 화면 표시 규칙만 바꾸므로 이전
표시로 되돌릴 수 있다. 고급 설정에서 동의를 기록하는 버튼은 TASK-S067-02가 맡는다.

## 현재 코드 상태

에이전트 화면은 `src/features/projects/components/agents/AgentRuntimeView.tsx`의
`AgentRuntimeView`가 그린다. 130행의 머리말 다음에 145행의 자동 배정 토글 구역이 오고, 그 뒤에
안내 두 개가 이어진다.

- 150~155행: 동의 안내. 조건은 `automationEnabled && consent?.status === "required"`다. 버튼은
  `setConsentOpen(true)`로 231행의 `ExecutionConsentDialog`를 연다.
- 157~163행: 실행 환경 안내. 조건은 `readiness.tone !== "ready"`다. `readiness.operation`이 있으면
  그 값으로 `actions.plan(...)`을 부르는 버튼을 `readiness.actionLabel` 문구로 그리고,
  `operation`이 없고 제목이 `자동 배정 서비스 전환 필요`인 경우에만 고급 설정을 여는 `전환 준비`
  버튼을 그린다.

세 단계의 판정 재료는 이미 이 컴포넌트 안에 모두 있다.

- 연결 단계: 71행 `readinessOf(state)`가 `tone`, `title`, `detail`, `operation`, `actionLabel`을
  낸다. 새 기기의 미등록 상태는 82행에서 `자동 배정 서비스 연결 필요`로 판정되어 `tone`이
  `attention`이다.
- 동의 단계: `state.policy.consent`가 `AgentProjectConsent`이고, 상태 값은
  `src/features/projects/domain/types.ts` 1510행 부근에 `granted`, `required`, `unsupported`,
  `unreadable` 네 가지로 정의돼 있다. 36행 `consentBlockMessage`가 뒤의 두 상태에 대한 사용자
  문구를 이미 낸다.
- 켜기 단계: `policy?.automationEnabled`와 147행 토글의 비활성 조건
  `!policy || state.saving || (!automationEnabled && !automationReady)`가 그대로 재료다.
  토글이 켜질 때 여는 창은 193행의 `AutomationConfirm`이고 `setEnableConfirmOpen(true)`로 연다.

동의 기록 경로는 이미 정책 저장과 분리돼 있다. `src/features/projects/application/useProjectWorkspace.ts`
1051행 `changeAgentRuntimeConsent`는 동의를 남긴 뒤 설정을 다시 읽기만 하고 저장을 부르지 않는다.
백엔드도 자동 배정 여부와 무관하게 동의를 읽는다
(`src-tauri/src/application/agent_runtime_config_service.rs` 184행). 그래서 이 작업은 새 동의
기능을 만들지 않고 기존 동의 화면을 여는 입구만 옮긴다.

스타일은 `src/App.css`에 있다. 42~45행의 `.agent-runtime-attention`은 이 화면 말고
`src/features/projects/components/WorkspaceShell.tsx` 562행의 첫 화면 동의 알림도 쓰므로 선언을
지우면 안 된다.

첫 화면 동의 알림은 413행에서 `view !== "agents"`를 조건에 두고 있어 에이전트 화면을 보는 동안에는
그려지지 않는다. 이 판정은 이번 변경 뒤에도 그대로 옳다. 다만
`src/features/projects/components/WorkspaceShell.test.tsx` 1900~1906행의 검사가 에이전트 화면에서
`실행 권한 동의 필요`라는 문구가 정확히 하나 보인다는 방식으로 그 사실을 확인하고 있어, 안내의
문구가 달라지면 이 검사가 함께 조정되어야 한다.

이 작업은 `AgentRuntimeView.test.tsx`와 `src/App.css`를 TASK-S063-02와 함께 건드리므로 그 작업
뒤에 온다.

## 완료 조건

- C1. 화면 제목 구역 다음, 자동 배정 토글 구역 앞에 준비 안내 하나를 그린다(R-01). 안내는 관리형
  서비스 연결, 실행 권한 동의, 자동 배정 켜기를 항상 이 순서로 담는다. 150~155행의 동의 안내와
  157~163행의 실행 환경 안내는 이 안내가 대신하므로 그 자리에서 없앤다.
- C2. 각 단계는 무엇을 하는 단계인지와 지금 상태를 함께 보여준다(R-02). 진행할 수 있는 단계만
  실행 버튼을 갖는다. 지금 진행할 수 없는 단계는 왜 진행할 수 없는지를 그 자리에 적고 버튼을 갖지
  않으며, 어떤 경우에도 완료로 표시하지 않는다.
- C3. 연결 단계는 `readinessOf`가 낸 값을 그대로 쓴다(R-03). `title`과 `detail`을 그 단계의 제목과
  설명으로 삼고, `operation`이 있으면 `actions.plan(operation)`을 부르는 버튼을 `actionLabel`
  문구로 제공한다. `operation`이 없고 제목이 `자동 배정 서비스 전환 필요`인 경우에는 지금과 같이
  고급 설정을 여는 `전환 준비` 버튼을 제공한다. 그 밖에 `operation`도 `actionLabel`도 없는 확인 중
  상태는 문구만 보여주고 버튼을 두지 않는다. 설치, 연결, 복구, 재시작, 업데이트, 전환 준비가 이
  한 단계에서 상황에 따라 갈린다.
- C4. 연결 단계는 `readiness.tone`이 `ready`일 때만 완료로 표시한다(R-06).
- C5. 동의 단계는 `automationEnabled` 값과 무관하게 안내에 나타난다(R-04). `consent.status`가
  `required`이면 231행의 `ExecutionConsentDialog`를 여는 버튼을 제공하고, `granted`이면 완료로
  표시하며 버튼을 제공하지 않는다.
- C6. `consent.status`가 `unsupported`이거나 `unreadable`이면 36행 `consentBlockMessage`가 낸 사유를
  동의 단계에 보여주고, 동의 버튼을 제공하지 않으며, 완료로 표시하지 않는다(R-08).
- C7. 켜기 단계는 `automationEnabled`가 거짓일 때 남은 단계로 나타나고, 147행 토글이 여는 것과 같은
  `AutomationConfirm` 창을 여는 버튼을 제공한다(R-05). `automationEnabled`가 참이면 완료로 표시한다.
  147행 토글이 눌리지 않는 조건(`!policy || state.saving || !automationReady`)에서는 C2에 따라
  버튼을 제공하지 않고, 앞 단계를 먼저 마쳐야 한다는 사유를 그 자리에 적는다.
- C8. 세 단계가 모두 완료면 안내 전체를 그리지 않는다(R-07). 이때 화면은 머리말, 자동 배정 토글,
  실행 목록으로 이어지는 지금과 같은 구성이 된다.
- C9. 자동 배정 토글은 지금 자리에 그대로 두고 동작도 바꾸지 않는다. 토글의 활성 조건, 켤 때 여는
  확인 창, 끌 때의 저장 동작이 하나도 달라지지 않는다.
- C10. 실행 환경 상태를 읽지 못했을 때의 오류 문구와 계획·적용 실패 문구는 164~166행의 지금 자리에
  그대로 둔다(R-11).
- C11. 동의만 기록하는 경로는 정책을 저장하지 않는다(R-10). 안내의 동의 단계로 동의를 기록해도
  `actions.save`가 불리지 않는다.
- C12. 안내가 더하는 모든 문구는 비개발자가 읽고 무엇을 해야 하는지 알 수 있는 말로 쓴다. 명령어,
  파일 경로, 코드 식별자를 화면에 내지 않는다.
- C13. 새 표시에 필요한 스타일만 `src/App.css`에 더한다. `.agent-runtime-attention` 선언은 첫 화면
  동의 알림이 계속 쓰므로 지우거나 바꾸지 않는다.
- C14. 다음 검사를 `AgentRuntimeView.test.tsx`에 더한다.
  - 서비스 미등록, 동의 없음, 자동 배정 꺼짐 상태에서 세 단계가 선언된 순서로 하나의 안내에 보인다.
  - 자동 배정이 꺼져 있어도 동의 단계의 버튼으로 동의 화면이 열리고, 동의를 기록하면
    `grantConsent`가 불리고 `save`는 불리지 않는다.
  - 실행 환경이 정상이고 동의만 없는 상태에서 연결 단계가 완료로 표시되고 버튼이 없다.
  - 동의 상태가 `unsupported`일 때와 `unreadable`일 때 동의 단계에 각각의 사유가 보이고 동의
    버튼이 없으며 완료로 표시되지 않는다.
  - 실행 환경이 정상이고 동의가 있으며 자동 배정이 꺼진 상태에서 켜기 단계의 버튼이 자동 배정 켜기
    확인 창을 연다.
  - 세 단계가 모두 끝난 상태에서 안내가 화면에 없다.
  - 외부 서비스 전환이 필요한 상태에서 연결 단계가 고급 설정을 여는 `전환 준비` 버튼을 제공한다.
- C15. 기존 검사 중 없어진 안내 두 개를 전제하던 것을 새 안내에 맞춘다. 특히
  `AgentRuntimeView.test.tsx` 994행 부근의 자동 배정이 켜진 상태의 동의 검사와
  `WorkspaceShell.test.tsx` 1900~1906행의 검사를 조정한다. 뒤쪽 검사가 확인하던 사실, 곧 에이전트
  화면을 보는 동안에는 첫 화면의 동의 알림이 그려지지 않고 그 화면의 안내 하나만 남는다는 것은
  그대로 확인해야 한다.
- C16. 기존 시험의 검증 의도를 약화시키지 않는다. C15가 조정하는 것 말고 기존 단언을 지우거나
  느슨하게 바꾸지 않는다.
- C17. 선언한 네 파일 밖의 파일은 바뀌지 않는다. `src-tauri` 아래와 `.workflow` 아래에는 변경이
  없다.

## 범위 밖

  화면을 보는 동안에는 그려지지 않는다는 판정이 이번 변경 뒤에도 그대로 옳다.
- 운영체제별 처리. 기획서가 제외 범위로 적었다.

## 범위 사전 검사

이 작업이 만드는 값은 화면에서만 계산되는 준비 단계 목록 하나다. 새 데이터가 백엔드에서 오지
않고, 세 단계의 재료가 이미 화면 컴포넌트 안에 도착해 있다는 것을 각 hop의 현재 코드로 확인했다.

- 값 경로: 연결 단계의 상태와 조치(C3, C4). 출처는 실행 환경 점검 결과
  `AgentRuntimeState.inspection`이고, 판정하는 자리는
  `src/features/projects/components/agents/AgentRuntimeView.tsx` 71행 `readinessOf`다. hop은 셋이다.
  (1) `readinessOf`는 `tone`, `title`, `detail`, `operation`, `actionLabel`을 이미 내고 있고 새
  단계 표시에 필요한 값이 모두 여기에 있으므로 편집하지 않는다. 82행이 새 기기의 미등록 상태를
  `attention`으로 판정하는 것도 그대로 쓴다. (2) 같은 파일의 화면 조립부. 지금 157~163행이 이 값을
  읽어 안내를 그리고 있고, 이 작업이 그 자리를 안내의 첫 단계로 옮기므로 편집이 필요하다.
  선언에 들어 있다. (3) 조치 버튼이 부르는 `actions.plan`. 서명과 인자
  (`AgentRuntimeOperation`)가 그대로이고 호출하는 자리만 옮기므로 편집이 필요 없다.
- 값 경로: 동의 단계의 상태와 사유(C5, C6). 출처는 실행 환경의 동의 조회이고, 만드는 자리는
