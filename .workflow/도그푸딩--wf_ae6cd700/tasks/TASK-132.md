# 모든 관리 자산을 검사한 뒤 한 번의 명령으로 동기화한다

## 결정권자 요약

TASK-132의 세 번째 QA 수정 요청까지 반영했다. 복원 대상을 먼저 같은 파일시스템에
격리하고 대상 경로가 비었을 때만 복원해, 경합 중 새로 쓴 사용자 내용을 덮거나 삭제하지 않는다.
열린 파일 핸들이 격리 뒤에 쓴 내용도 복구 위치에 남기고, 결과가 자산별 복구 위치를 알려 준다.
한 자산의 복원이 실패해도 나머지 자산을 모두 처리하고, 최초 충돌과 자산별 복원 실패를 함께 반환한다.
기존 생성·결정·단건 QA·일괄 QA의 오류에도 보존된 복구 위치가 빠지지 않는다.
공통 규칙과 세 역할 계약의 버전은 파일별 실제 버전으로 판단해 더 새로운 설치본을 보호한다.
동기화는 문서 조회와 분리된 명령이며, 마이그레이션과 같은 잠금을 사용해 두 쓰기가 겹치지 않는다.
충돌이나 잠금이 있어도 프로젝트 문서는 계속 읽을 수 있다. Rust 검사 562개와 포맷, 정적 검사가 모두 통과했다.
이 작업은 화면을 바꾸지 않으며 사용자 재확인을 기다린다.

## 목적

SPEC-047의 R3, R4 백엔드 부분과 완료 조건 3, 5, 7, 9, 10의 백엔드 근거를 만든다. 기존
`inspect_project`에는 쓰기를 추가하지 않는다. 별도 동기화 명령이 관리 자산의 상태와 동기화 결과만
반환한다.

## 아키텍처 계약

### 1. 모든 관리 자산을 한 계획에서 검사한다

동기화 대상은 다음 일곱 종류다.

1. 공통 규칙
2. 기획자 역할 계약
3. 아키텍트 역할 계약
4. 개발자 역할 계약
5. AGENTS 진입 안내
6. CLAUDE 진입 안내
7. 현재 운영체제의 선점 헬퍼

각 자산은 경로, 표시 이름, 관리 여부, 설치된 버전, 앱 제공 버전, 변경 필요 여부를 하나의 계획에
담는다. 버전이 없는 두 진입 안내는 버전을 추정하지 않고 관리 블록의 상태만 기록한다. 선점 헬퍼는
자체 버전 축을 사용한다.

세 역할 계약은 실제 제공 버전인 기획자 8, 아키텍트 7, 개발자 8을 각각 사용한다. 현재의 공통 기준
8을 세 파일에 적용하지 않는다. 따라서 아키텍트 계약의 설치 버전 8은 앱 제공 버전 7보다 새로운
파일이며 충돌이다.

계획 단계에서 하나라도 다음 상태면 전체 계획을 충돌로 끝낸다.

- 일반 파일이 아닌 경로
- 관리 표기나 버전을 읽을 수 없는 파일
- 앱이 관리하지 않는 같은 이름의 파일이나 손상된 관리 블록
- 앱 제공 버전보다 새로운 설치본

충돌 계획은 쓰기 단계를 호출할 수 없어야 한다. 앞에서 검사한 자산만 갱신되는 중간 상태를 만들지
않는다. 파일마다 쓰기 직전에 계획을 만들 때 읽은 기준이 그대로인지 확인해, 검사 뒤 외부에서 바뀐
파일도 덮어쓰지 않는다. 저장이 필요한 파일은 각각 임시 파일과 원자적 교체를 사용한다.

### 2. 마이그레이션과 같은 잠금을 사용한다

마이그레이션과 관리 자산 동기화가 `.workflow/.runtime/migration.lock`을 배타적으로 획득하는 공용 잠금
구현을 사용한다. 파일 존재를 확인한 뒤 쓰는 방식은 검사와 쓰기 사이의 경합을 막지 못하므로 사용하지
않는다.

- 동기화가 먼저 잠금을 잡으면 마이그레이션은 시작하지 않는다.
- 마이그레이션이 먼저 잠금을 잡으면 동기화 결과는 `retry_required`가 된다.
- 잠금은 계획 작성부터 마지막 저장까지 유지한다.
- 예상된 잠금 경합과 파일 충돌은 서로 다른 결과다.
- 예기치 않은 입출력 실패에도 잠금은 해제된다.

기존 마이그레이션은 같은 공용 잠금 구현으로 옮기되 백업, 문서 규격 변경, 활성 lease 차단 동작은
바꾸지 않는다.

### 3. 조회와 동기화 결과를 분리한다

새 Tauri 명령은 현재 문서 규격인 초기화된 프로젝트에서만 동기화를 시도한다. 초기화되지 않은
프로젝트, 마이그레이션이 필요한 프로젝트, 앱보다 새로운 문서 규격은 파일을 쓰지 않고 기존 호환성
판정을 따른다.

반환값은 최소한 다음 사실을 구조화해 제공한다.

- 전체 결과: `current`, `updated`, `retry_required`, `conflict`
- 자산별 결과와 표시 이름
- 버전이 있는 자산의 설치 버전과 앱 제공 버전
- 갱신된 자산 목록
- 재시도 또는 사용자 확인이 필요한 이유와 해당 자산

충돌과 잠금은 예상된 결과로 반환한다. 프로젝트 문서 조회 실패와 섞지 않는다. 호출 계층이 이 결과를
화면 상태로 보존할 수 있어야 한다.

### 4. 기존 설치 경로도 같은 조정 계층을 사용한다

새 워크플로 생성, 기획 결정, 작업 QA의 기존 설치 동작은 공통 규칙과 역할 계약을 먼저 쓰고 선점
헬퍼에서 뒤늦게 실패하는 순서를 유지하면 안 된다. 이 경로도 전체 자산 계획과 공용 잠금을 사용한다.
기존 명령의 반환형과 사용자 동작은 유지하며, 충돌이면 기존처럼 쓰기 요청을 실패시킨다.

## 변경 범위

- `project_instructions.rs`: 규칙과 역할별 정확한 버전 서술, 계획 가능한 자산 인터페이스.
- `claim_helper.rs`, `managed_script.rs`: 선점 헬퍼를 전체 계획에 포함할 수 있는 읽기 전용 계획과
  기준 대조 인터페이스.
- `managed_project_assets.rs`: 모든 자산의 사전 검사, 결과 모델, 일괄 저장 조정.
- `project_write_lock.rs`: 동기화와 마이그레이션이 공유하는 배타 잠금.
- `fs_project_repository.rs`: 별도 동기화 진입점과 기존 설치 호출의 공통 조정 계층 사용.
- 서비스, 도메인, 명령, 앱 등록 계층: 동기화 결과의 공개 계약과 별도 명령 연결.

새 모듈 이름은 위 경계를 드러내기 위한 기준이다. 같은 책임을 기존 모듈에 더 명확히 배치할 수 있다면
파일을 추가하지 않아도 되지만, 이 작업의 `scope_files` 밖으로 책임을 옮기지는 않는다.

## 손대지 않는 것

- `inspect_project`의 읽기 전용 동작과 반환형
- 프로젝트 열기, 수동 새로 고침, 2.5초 자동 조회의 프런트엔드 호출 순서
- 설정 화면
- 사용자 정의 규칙 파일과 우선순위
- 실행 중인 에이전트 세션

## 완료 조건

1. 별도 동기화 명령이 있고 `inspect_project`는 관리 자산을 만들거나 수정하지 않는다.
2. 공통 규칙, 세 역할 계약, 두 진입 안내, 선점 헬퍼를 모두 검사한 뒤에만 저장을 시작한다.
3. 어떤 자산에서 검증 충돌이 발생해도 일곱 종류의 대상 파일이 모두 검사 전 상태로 남는다.
4. 계획 뒤 외부 변경이 확인되면 어떤 자산도 덮어쓰지 않고 충돌을 반환한다.
5. 공통 규칙, 역할별 8·7·8, 선점 헬퍼의 설치 버전과 앱 제공 버전을 각각 정확히 반환한다.
6. 아키텍트 계약의 설치 버전이 8이면 앱 제공 버전 7보다 새롭다고 판단하고 덮어쓰지 않는다.
7. 파일이 없으면 설치하고, 낮은 관리 버전이면 갱신하며, 내용이 같으면 쓰지 않고 수정 시각도
   유지한다.
8. 동기화와 마이그레이션이 같은 잠금을 놓고 경합할 때 하나만 쓰며, 동기화 쪽은 재시도 가능한 결과를
   반환한다.
9. 충돌과 잠금이 있어도 별도의 프로젝트 조회는 성공할 수 있다.
10. 기존 워크플로 생성, 기획 결정, 단건 QA, 일괄 QA의 관리 자산 설치가 같은 사전 검사 규칙을
    사용하고 기존 성공 동작을 유지한다.
11. 현재 운영체제와 다른 선점 헬퍼 파일은 읽거나 수정하지 않는다.
12. 기존 자동 검사를 삭제하거나 약화하지 않고 Rust 전체 검사가 통과한다.

## 검증 절차

1. 임시 프로젝트에 일곱 종류의 최신 자산을 설치하고 동기화 전후 내용과 수정 시각이 같은지 확인한다.
2. 각 자산을 차례로 미관리 파일, 손상된 표기, 더 새로운 버전으로 만든 표 기반 검사에서 전체 무쓰기를
   확인한다. 선점 헬퍼도 반드시 표에 포함한다.
3. 기획자 8, 아키텍트 7, 개발자 8의 정상·낮은 버전·높은 버전을 각각 검사한다.
4. 마이그레이션과 동기화를 동시에 시작하는 검사에서 하나의 잠금만 성공하고 파일이 섞이지 않는지
   확인한다.
5. `inspect_project`를 여러 번 호출해 관리 자산의 내용과 수정 시각이 바뀌지 않는지 확인한다.
6. 기존 생성·결정·QA 설치 검사를 포함해 `cargo test --manifest-path src-tauri/Cargo.toml`을 실행한다.

## 범위와 선행

선행 작업은 없다. 이 작업이 끝나야 TASK-133이 별도 동기화 명령을 프로젝트 열기와 수동 새로 고침에
연결할 수 있다.

SPEC-048도 규칙 설치기와 진입 안내를 수정한다. 그 기획서에서 파생되는 작업이 이 문서의
`scope_files`와 겹치면 TASK-132가 완료되기 전에 시작하지 않는다.

## 확인 동선

이 작업은 화면 변경이 없는 백엔드 계약 작업이다. 별도 동기화 명령의 화면 연결과 상태 표시는
후속 TASK-133과 TASK-134가 담당한다.

1. 자동 검사에서 전체 Rust 테스트 562개가 통과했는지 확인한다.
2. 포맷 검사와 모든 대상의 정적 검사가 경고 없이 통과했는지 확인한다.
3. 순차 저장 중 후속 변경 복원과 일곱 자산의 비 UTF-8 충돌 회귀 검사가 계속 포함됐다.
4. 열린 파일 핸들의 격리 후 쓰기, 원래 없던 경로의 외부 재생성, 두 복원 실패 후의 나머지 복원을 자동 검사가 재현한다.
5. 열린 핸들 경합으로 남긴 복구본의 위치가 기존 생성·결정·단건 QA·일괄 QA 오류에도 전달되는지 확인한다.
6. 사용자 확인 도장은 이 수치와 백엔드 계약을 승인한다는 뜻이다.
