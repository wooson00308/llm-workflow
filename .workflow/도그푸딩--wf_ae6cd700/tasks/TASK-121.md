# QA 대기에서 무엇을 확인할지가 도장 옆에서 읽힌다

## 결정권자 요약

이제 QA 확인 도장을 찍는 자리에서 무엇을 어떻게 확인해야 하는지가 바로 읽힌다. 지금까지는 확인
메모 입력칸 옆에 "테스트한 순서와 결과를 남기면"이라는 안내만 있고, 정작 무엇을 확인해야 정상인지는
왼쪽 본문을 뒤져야 나왔다.

개발자가 적어 둔 확인 동선이 도장 버튼과 같은 자리에 온다. 어느 화면에서 무엇을 누르면 무엇이
보여야 하는지가 그 자리에 있다.

동선이 적히지 않은 옛 작업은 지금과 똑같다. 본문이 있던 자리에 그대로 있고, 없다는 문구도 붙지
않는다. 레인을 통째로 확인하는 일괄 화면도 바뀌지 않았다.

자동 검사는 전부 통과했다. 앱을 띄워 눈으로 보는 확인만 남았고, 그 순서가 아래에 있다.

---

SPEC-039의 R7이다. 기획서 완료 조건 11을 이 작업이 닫는다.

**이 작업이 성립한다는 것이 먼저 확인됐다.** R7은 조건부 요구사항이었다 — SPEC-038이 확인 동선
절을 개발 작업 문서에 두기로 착지할 때만 성립하고, 보고서로 착지하면 앱에 읽기 경로가 없어
(확인 사실 3) 미뤄질 몫이었다. SPEC-038은 DECISION-BCACD11B로 승인됐고 TASK-118이 그 착지를
`## 확인 동선`을 **개발 작업 문서**에 쓰는 의무로 고정했다. 그래서 미뤄지지 않고 이 작업이 선다.
기획서 R7이 "분해 시점에 기록한다"고 한 사실이 이 문단이다.

## 확인 동선

1. 앱을 띄우고 개발 작업 화면을 연다.
2. QA 대기 열에서 확인 동선 절을 가진 작업을 연다. 지금 이 저장소에서는 TASK-120·TASK-125·TASK-127,
   그리고 이 작업 자신이다.
   - 정상: 오른쪽 QA 패널의 "테스트한 순서와 결과를 남기면…" 안내와 확인 메모 입력칸 사이에 옅은
     상자가 서고, 그 안에 문서가 쓴 `확인 동선` 제목과 그 아래 문장이 그대로 보인다.
   - 정상: 왼쪽 본문(기본 뷰)에는 같은 문단이 보이지 않는다. 한 화면에 같은 문단이 두 번 뜨면
     회귀다.
   - 정상: 왼쪽 위 "원문 전문 보기"를 누르면 왼쪽에도 동선 절이 나타난다. 원문은 자르지 않은 본문
     그대로라 그렇다.
3. 같은 열에서 동선 절이 없는 옛 작업을 연다(TASK-022 또는 TASK-119).
   - 정상: 오른쪽 패널이 지금까지와 똑같다. 상자도 서지 않고 "동선이 없다"는 문구도 붙지 않는다.
4. QA 대기가 아닌 작업을 연다(준비 열의 TASK-122 등).
   - 정상: 오른쪽 패널이 지금까지와 똑같이 "QA 대기 상태가 되면 확인 도구가 활성화됩니다."만
     보여 준다.
5. "기획서별 묶기"를 켜고 레인 헤더에서 일괄 QA를 연다.
   - 정상: 일괄 QA 다이얼로그가 지금과 똑같다. 이번 범위 밖이라 동선이 뜨지 **않는** 것이 정상이다.

이 세션이 하지 못한 것: 위 1~5는 화면을 눈으로 보는 확인인데 이 세션에는 화면이 없어 수행하지
못했다. 자동 검사는 통과했다 — `npm run check`(646건)와
`npx vitest run src/features/projects/components/DevelopmentBoard.test.tsx`(79건). 도장은 위 눈
확인까지 마치고 찍어 주기 바란다.

## 아키텍트가 고정하는 값

### 1. 찾는 문자열과 찾는 방법

- 절 이름은 `## 확인 동선`이다. TASK-118이 계약에 박은 문자열 그대로이고, 이 하나만 찾는다.
- 찾는 도구는 TASK-120이 만든 `src/features/projects/domain/documentSections.ts`다. 같은 어법을
  두 벌 만들지 않는다. 이 작업은 그 모듈을 고치지 않고 부르기만 한다.
- 절을 찾는 대상은 이미 읽어 온 작업 문서 본문이다. 문서를 다시 읽지 않는다.

### 2. 표면화하는 자리는 단건 QA 패널뿐이다 (승인된 확인 필요 1번)

- 대상은 `TaskDetail`의 `task-qa-panel`, 즉 확인 메모 입력과 확인·반려 버튼이 있는 오른쪽 패널이다.
- **일괄 QA 다이얼로그(`LaneQaDialog`)는 이번 범위 밖이다.** 목록 payload에 본문이 없어(확인 사실
  10) 대상 건수만큼 문서를 더 읽어야 하고, 그 읽기의 비용과 실패 처리는 이 기획서가 정하지 않았다.
- 그 비용은 기획서가 이미 적었다 — 레인 통째 QA를 쓰는 사용자는 동선을 읽지 못한 채 도장을 찍고,
  두 입구의 정보량이 갈린다. 승인된 선택이므로 여기서 뒤집지 않는다.

### 3. 언제 보이는가

- 이 절은 `qa_waiting` 작업, 즉 확인 도구가 활성화된 상태에서 읽힌다. 계약이 이 절을 거는 대상도
  `qa_waiting`으로 넘어가는 작업이다(TASK-118 고정값 4).
- `qa_waiting`이 아닌 작업 상세에서 이 자리는 지금 그대로다. 확인 도구가 없는 자리에 확인 동선만
  띄우지 않는다.

### 4. 동선 절이 없는 문서 (R7)

- 지금과 같다. 본문이 그 자리에 그대로 있고, 패널은 지금 모습 그대로다.
- **없다는 문구를 붙이지 않는다.** 승인된 확인 필요 2번이 요약 절에 대해 정한 것과 같은 판단이고,
  근거도 같다 — 이 저장소의 기존 작업 121건에 그 절이 0건이라 문구를 붙이면 거의 모든 화면에 같은
  줄이 뜬다.
- 폴백은 오류가 아니다. 읽기 실패 문구를 쓰지 않는다.

### 5. 본문에서 옮기는 것이지 복제하는 것이 아니다 (R4)

- 동선 절이 패널에 오면 그 절이 왼쪽 본문의 기본 뷰에도 그대로 남을지를 정해야 한다. 같은 문단이
  한 화면에 두 번 보이는 것은 R3이 상수 흡수에서 금지한 것과 같은 종류의 중복이다.
- **패널로 옮기고 기본 뷰에서는 빼는 쪽으로 고정한다.** 원문 토글에는 남는다 — 원문은 자르지 않은
  본문이라는 것이 TASK-120 고정값 3의 결정이고, 그 결정을 이 작업이 뒤집지 않는다.
- 앱이 이 절의 문장을 조립하지 않는다. 문서가 쓴 문장을 본문에서 그대로 가져온다(R4).

### 6. 넘지 않는 선

- 일괄 QA 다이얼로그를 건드리지 않는다.
- 문서를 다시 읽는 경로를 만들지 않는다. 목록 payload에 본문을 싣지 않는다.
- 보고서를 앱에서 읽는 경로를 만들지 않는다(제외 범위, 확인 사실 3).
- QA 기록 동작을 바꾸지 않는다. 확인·반려가 지금과 같은 값을 같은 자리에 쓴다.
- 앱이 문서 파일을 쓰지 않는다.
- `documentSections.ts`를 고치지 않는다. 고쳐야 할 이유가 생기면 그것은 TASK-120의 결함이고,
  보고서에 적어 넘긴다.
- Rust를 고치지 않는다.
- 기존 자동 테스트를 지우거나 비활성화하지 않는다.

## 완료 조건

1. 단건 QA 패널에서 `qa_waiting` 작업의 확인 동선이 확인·반려 버튼과 같은 자리에서 읽힌다.
   검증: 동선 절을 가진 픽스처로 `DevelopmentBoard.test.tsx`. (R7 / 기획서 완료 조건 11)
2. 동선 절이 없는 문서에서 패널이 지금과 같고 어떤 문구도 붙지 않는다. 검증: 그 절이 없는
   픽스처로 같은 테스트. (R7 / 기획서 완료 조건 11)
3. 절을 `## 확인 동선` 하나로 찾고 다른 후보를 추측하지 않는다. 검증: 다른 이름의 절만 가진
   픽스처로 같은 테스트. (고정값 1)
4. 같은 문단이 한 화면에 두 번 보이지 않는다. 기본 뷰에서 빠지고 원문 토글에는 남는다. 검증:
   같은 테스트. (고정값 5 / R4)
5. `qa_waiting`이 아닌 작업 상세에서 이 자리가 달라지지 않는다. 검증: 같은 테스트. (고정값 3)
6. 일괄 QA 다이얼로그가 달라지지 않는다. 검증: 기존 테스트가 수정 없이 통과하고, 변경분에 그
   컴포넌트가 없다. (승인된 확인 필요 1번)
7. QA 기록·문서 읽기·검색·목록 미리보기가 달라지지 않고 아이디어 화면도 그대로다. 검증: 기존
   테스트가 수정 없이 통과한다. (R9 / 기획서 완료 조건 15)
8. 앱이 문서 파일을 쓰지 않고 문서를 다시 읽는 경로도 늘지 않는다. 검증: 변경분 확인. (R9 /
   기획서 완료 조건 13)
9. 기존 자동 테스트가 삭제되거나 비활성화되지 않는다. 검증: 테스트 목록 변경분 확인. (기획서
   완료 조건 16)
10. `npm run check`가 통과한다. Rust 변경이 없으므로 `cargo test`는 이 작업의 완료 조건이 아니다.
    (기획서 완료 조건 17)
