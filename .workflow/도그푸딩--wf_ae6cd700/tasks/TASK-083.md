# 화면이 가리키는 파일을 실제로 쓰는 파일로 바꾼다

SPEC-024 R7과 완료 조건 10을 닫는다. TASK-081이 쓰는 파일을 옮겼으므로, 이 작업 전까지 확인 화면은
쓰지도 않는 파일을 "확인 후 이 파일을 씁니다"라고 말하고 있다.

## 아키텍트가 정한 것: 경로를 화면 상수로 두지 않는다

확인 사실 11이 적은 상태가 이 사고의 원인이다. `HeartbeatCard.tsx:57`과 `DreamCard.tsx:33`이 각각
`const heartbeatFilePath = "~/.claude/HEARTBEAT.md"`를 들고 있어, 백엔드가 대상 파일을 바꿔도 화면은
옛 값을 계속 보여준다. 새 경로에는 slug까지 들어가므로 화면이 문자열을 조립하면 갈라질 자리가 하나 더
생긴다.

그래서 **경로를 payload로 내린다.** 백엔드가 실제로 쓰는 경로를 그대로 실어 보내고 화면은 그 값을
그리기만 한다. `condition_command`(`DreamIntegration`)와 `condition_script_path`
(`HeartbeatIntegration`)가 이미 같은 이유로 그렇게 되어 있다 — 화면이 문자열을 다시 조립하지 않게
한다는 규칙이다.

값의 모양은 백엔드가 계산한 절대 경로다. 지금 화면의 `~/.claude/...` 표기는 화면이 손으로 적은
축약이고, 실제 홈을 아는 것은 커맨드 계층뿐이다. 절대 경로를 그대로 보여주면 사용자가 파일 탐색기나
터미널에 그대로 붙여 쓸 수 있고, 읽기 실패 목록이 이미 절대 경로를 보여주고 있어(payload의
`readFailures[].path`) 한 화면 안에서 표기가 갈라지지 않는다.

두 카드가 같은 파일을 쓰므로 값은 연동별이 아니라 섹션 공통이다. `slug`·`managedBlockFailure`가
있는 자리에 나란히 둔다.

## 의존성

- **선행 필수: TASK-082.** 앞선 전환 세 작업이 모두 끝난 뒤라야 화면이 가리킬 사실이 확정된다.
  `heartbeat_service.rs`도 함께 고친다.
- **선행 필수: TASK-065.** 이 작업이 고치는 확인 화면 세 문장을 그 작업이 먼저 고친다. **그 작업이
  넣는 "다른 프로젝트의 잡은 그대로 둔다"는 보장 문장은 전환 뒤 이 자리에서 사실이 아니게 된다** —
  앱이 쓰는 파일에는 애초에 다른 프로젝트의 잡이 들어올 수 없기 때문이다. 이 작업이 그 문장을 지우는
  것이 아니라 더 강한 사실로 갈아 끼운다는 점을 보고서에 적는다.
- **선행 필수: TASK-092.** TASK-065가 손대지 않은 네 번째 문장(dream 잡 기본값 재설정 확인 화면)에
  같은 보장을 넣는 작업이다(DECISION-4E8C1D67). 위 TASK-065와 같은 이유로 이 작업이 뒤에 온다 —
  전환 뒤에는 그 문장도 사실이 아니게 되므로 이 작업이 더 강한 사실로 갈아 끼운다. 순서가
  뒤집히면 TASK-092가 이미 지나간 전제를 다시 넣는다.
- **선행 필수: TASK-072·TASK-073.** 같은 두 카드 파일을 고친다. 구간은 다르지만 병행하면 충돌한다.

  전환의 영향을 받지 않는다(확인 사실 9, TASK-081 완료 조건 13). 문장은 지금도 참이다.

**줄 번호는 작업 트리 기준이고 선행 작업 넷이 모두 이 파일들을 민다.** 줄 번호가 아니라 문장 원문과
식별자 이름으로 찾는다.

## 작업 내용

- 확인 화면이 쓰는 파일 목록을 사실에 맞춘다. 역할 잡 저장은 여전히 두 파일(잡 파일과 프로젝트 로컬
  조건 스크립트)을 쓰고, dream 저장은 잡 파일 하나만 쓴다. 잡 파일 설명은 "전역 파일입니다. 이
  컴퓨터의 모든 프로젝트가 함께 씁니다"에서 "이 프로젝트 전용 파일입니다"로 바뀐다. 파일이 갈렸다는
  것이 이번 전환의 사용자 가치이므로 그 사실이 문장에 남아야 한다.
- 역할을 전부 끈 저장의 안내도 사실에 맞춘다. 지금은 "관리 블록 전체를 제거합니다"이고, 실제로는
  이 프로젝트의 잡 파일이 사라진다.
- 중복 잡 경고 문구는 두 가지를 모두 설명해야 한다. 사용자가 손으로 적은 잡과, 전환 전에 앱이 옛
  파일에 써 둔 잡이 같은 통로로 올라온다. 데몬이 jobs.d를 이기게 한다는 사실(확인 사실 13)과 앱에서
  한 번 저장하면 앱이 쓴 정의가 정리된다는 사실(TASK-082)이 문구에 담긴다.
- "못 읽음"과 "잡 없음"을 구분하는 화면 동작은 그대로다. 근거 파일만 바뀌었으므로 기존 동작이 새
  경로에서도 성립하는지 테스트로 확인한다(완료 조건 7의 프론트엔드 쪽).

## 완료 조건

1. 스냅샷이 앱이 실제로 쓰는 잡 파일 경로를 싣는다. Rust 테스트에서 임시 홈과 slug로 계산한 값과
   대조한다.
2. 역할 잡 설치 확인 화면, 역할 잡 기본값 재설정 확인 화면, dream 잡 설치 확인 화면 셋이 모두 그
   경로를 보여준다. 화면 어디에도 잡 파일 경로를 손으로 적은 상수가 남지 않는다. (완료 조건 10)
3. 세 확인 화면의 파일 설명이 "이 프로젝트 전용 파일"이라는 사실을 밝힌다. 두 카드의 같은 문장이
   글자까지 같다.
4. 역할을 전부 끈 저장의 안내가 잡 파일이 사라진다는 사실을 말한다.
5. 중복 잡 경고 문구가 "관리 블록 밖"을 전제하지 않는다. 문구가 데몬 우선순위와 정리 시점을 밝힌다.
6. 잡 파일을 읽지 못한 상태와 잡이 없는 상태가 화면에서 구분된다. 두 상태를 만드는 프론트엔드
   테스트가 있다. (완료 조건 7의 프론트엔드 쪽)
7. `installationNote`와 설치 마법사 단계 문구에 변경분이 없다. `git diff`로 확인해 보고서에 적는다.
8. 기존 자동 테스트가 삭제되거나 비활성화되지 않았다. 경로 문자열이 바뀌어 단언값을 고친 테스트는
   무엇을 왜 고쳤는지 보고서에 나열한다. TASK-065·TASK-092가 넣은 문장을 대체한 자리도 함께 적는다.
   (완료 조건 16)
9. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`이 통과한다. (완료 조건 18)
