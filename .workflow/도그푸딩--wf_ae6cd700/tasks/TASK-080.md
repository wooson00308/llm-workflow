# 프로젝트 잡 파일 하나를 통째로 쓰는 인프라를 만든다

SPEC-024 R1의 바닥을 깐다. 이 작업은 배선하지 않는다. `heartbeat_jobs.rs`에 "이 프로젝트의 잡
파일 하나를 통째로 쓴다"는 동작만 만들고, 서비스가 그것을 부르게 하는 일은 TASK-081이 한다.

지금 이 모듈이 아는 쓰기는 마커 블록 부분 교체 하나뿐이다(`install_managed_jobs`
`heartbeat_jobs.rs:144`). 그 함수는 남과 한 파일을 나눠 쓰는 전제 위에 서 있고(확인 사실 5·7),
전환 뒤에도 옛 파일 정리에 그대로 필요하다(TASK-082). 그래서 고치지 않고 옆에 새 경로를 만든다.

## 아키텍트가 정한 것 (R1이 위임한 두 항목)

### `- slug:` 줄은 계속 쓴다

확인 사실 14대로 jobs.d 파일 안에서 이 줄은 필요 없고, 파일 이름과 다르면 경고 후 파일 이름이
이긴다. 그래도 남기는 근거는 셋이다.

1. 앱이 쓰는 값은 언제나 파일 이름과 같은 slug다. 어긋날 자리가 없으므로 경고가 나지 않는다.
2. 렌더 규칙이 두 파일에서 갈라지지 않는다. `ManagedJob`과 잡 렌더가 그대로 공유되므로, 전환이
   "어디에 쓰는가"만 바꾸고 "무엇을 쓰는가"는 건드리지 않는다.
3. 이 기기의 `~/.claude/heartbeat/jobs.d/-Users-catze-project-workflow-labs.md`는 데몬의
   `heartbeat install`이 쓴 파일이고 그 안에 `- slug:` 줄이 있다(확인 사실 3). 같은 표기를 쓰면
   앱의 첫 저장이 사용자 눈에 값 변경으로만 보이고 표기 변경으로는 보이지 않는다.

### 잡이 하나도 안 남으면 파일을 지운다

빈 파일을 남기지 않는다. R2가 "파일이 없는 상태는 잡이 없는 것으로 읽는다"고 정했으므로 없는 파일이
곧 잡 없음의 정규 표현이고, 지금 블록을 마커째 지우는 동작(`:283`~`:285`)과 같은 모양이다.

## 의존성

- **선행 필수: TASK-064.** 같은 파일을 고친다. 그 작업이 `render_block`(`:179`)과
  `foreign_job_texts`(`:217`)를 새로 넣었고, 이 작업은 그 렌더를 나눠 쓴다. 병행하면 충돌한다.

## 범위

- `src-tauri/src/infrastructure/heartbeat_jobs.rs` — 새 공개 함수 둘과, 잡 렌더 구간을 두 쓰기가
  나눠 쓰게 하는 추출. `mod tests`(`:497`)에 이 함수들의 테스트.
- 그 외 파일은 한 줄도 고치지 않는다. 서비스·상태 조회·프론트엔드는 다음 작업들의 몫이다.

**줄 번호는 작업 트리 기준이다.** TASK-064의 변경이 이미 얹혀 있고 HEAD와 다르다.

## 작업 내용

- 경로를 만드는 함수를 이 모듈에 둔다. `<heartbeat_home>/heartbeat/jobs.d/<slug>.md`이고
  (확인 사실 17), 인자는 하트비트 홈과 slug다. **경로 정의는 이 한 곳에만 둔다.** 확인 사실 11이
  적은 사고(같은 경로가 상수로 네 곳에 흩어져 화면과 실제가 갈라지는 것)를 새 경로에서 반복하지
  않기 위해서다. 뒤 작업들은 이 함수를 부른다.
- 잡 목록 하나를 파일에 통째로 쓰는 함수를 만든다. 반환값은 `install_managed_jobs`와 같은 규칙으로
  "실제로 썼는가"다.
  - `validate_managed_jobs`(`:172`)를 먼저 통과시킨다. 검증에 걸린 요청은 파일을 만들지 않는다.
  - 목록이 비면 파일을 지운다. 파일이 이미 없으면 아무것도 하지 않고 "쓰지 않았음"이다.
  - 부모 디렉터리가 없으면 만든다(확인 사실 15, 완료 조건 3). 계약 19~21줄이 쓰는 쪽의 몫으로
    정했다.
  - 렌더 결과가 지금 파일 내용과 같으면 쓰지 않는다(완료 조건 12). 줄바꿈 표기를 어떻게 다룰지는
    구현이 정하되, 같은 저장을 두 번 했을 때 두 번째가 쓰지 않는 성질로 고정한다.
  - 쓰기는 `write_text_atomically`(`:484`)를 그대로 쓴다. 대상이 일반 파일이 아닌 경우의 거부
    (`ensure_regular_file` `:475`)도 유지한다.
- 잡 렌더를 두 쓰기가 나눠 쓰게 한다. `render_block`(`:179`)은 지금 마커·구분 빈 줄·보존 원문까지
  한 함수 안에서 만든다. 잡 목록을 줄로 바꾸는 구간만 함수로 빼고, 블록 렌더는 그것을 마커로
  감싸게 한다. **블록 렌더의 결과 문자열은 한 글자도 달라지면 안 된다** — 달라지면 TASK-063·064의
  픽스처 대조 테스트가 깨진다.
- 마커·흡수 줄·부분 병합 로직은 그대로 둔다(R6). 새 파일에는 그 전제가 없지만, 옛 파일 정리
  경로에서 계속 필요하다(TASK-082). `plan_block`(`:258`)·`ensure_no_absorbed_line`(`:305`)·
  `foreign_job_texts`(`:217`)의 판정을 약하게 만들지 않는다.
- 새 쓰기 경로에는 마커가 없다. 파일 전체가 앱 소유이므로 부분 교체·보존·흡수 줄 검사를 넣지
  않는다. 사용자가 손으로 고친 값을 지키는 방어는 저장 직전 baseline 대조이고 그것은 서비스에
  있다(R6, TASK-081).

## 완료 조건

1. 경로 함수가 `<heartbeat_home>/heartbeat/jobs.d/<slug>.md`를 낸다. (확인 사실 17)
2. 잡 목록을 쓰면 계약 23~40줄의 잡 문법으로 기록된다. 잡 헤더 다음에 `slug`·`model`·`prompt`·
   `interval`·`timeout`·`condition`·`notify` 일곱 줄이 오고, 제한 없음이 아닌 잡만 `max_per` 줄이
   붙는다. (R1)
3. `jobs.d` 디렉터리가 없는 홈에서 저장하면 디렉터리를 만들고 파일을 쓴다. (완료 조건 3)
4. 같은 목록을 두 번 쓰면 두 번째는 "쓰지 않았음"이고 파일 내용이 그대로다. (완료 조건 12)
5. 빈 목록을 쓰면 파일이 사라진다. 파일이 없는 상태에서 빈 목록을 쓰면 아무 일도 일어나지 않는다.
6. 검증을 통과하지 못하는 잡이 하나라도 있으면 파일을 만들거나 고치지 않는다.
7. 대상 경로가 일반 파일이 아니면 지금 블록 쓰기와 같은 오류로 거부한다.
8. 블록 렌더 결과가 이 작업 전후로 같다. TASK-063·064가 남긴 테스트가 **수정 없이** 통과한다.
   (완료 조건 16)
9. 잡 이름 규칙과 slug 생성 규칙에 변경분이 없다. `heartbeat_jobs.rs:128`~`:135`를 `git diff`로
   확인해 보고서에 적는다. (완료 조건 14)
10. 기존 자동 테스트가 삭제되거나 비활성화되지 않았다. (완료 조건 16)
11. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`이 통과한다. (완료 조건 18)

- 서비스 배선. 이 작업이 만든 함수를 부르는 것은 TASK-081이다. 이 작업이 끝난 시점에 앱의 동작은
  한 가지도 바뀌지 않는다.
- 옛 마커 블록 정리(R3). TASK-082가 한다.
- 읽기 경로 전환(R2)과 화면 문구(R7). TASK-081·TASK-083이 한다.

  "남기고 이유를 적는다" 쪽이다.
- 하트비트 데몬(claude-heartbeat) 저장소의 변경. 기획서 제외 범위다.
