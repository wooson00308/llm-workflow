# 좌측 메뉴에 활성 세션 축약 표시를 상시 노출한다

## 결정권자 요약

에이전트 세션이 도는 중인지 알리는 축약 표시를 좌측 메뉴 하단에 상시로 추가했다.
좌측 메뉴는 화면 전환과 무관하게 항상 그려지므로 기획서를 검토하는 동안에도 작업 보드를 보는
동안에도 표시가 그대로 남는다.
표시에는 세션이 도는지 알리는 점과 활성 세션 수만 담았고, 담당 에이전트 이름과 대상 문서는 오늘
화면의 상세 카드와 활동 화면이 그대로 맡는다.
누르면 활동 화면으로 이동하며, 이미 활동 화면일 때 눌러도 그대로 머문다.
활성 세션이 하나도 없으면 요소를 아예 그리지 않아 빈 자리가 남지 않는다.
새 조회나 백엔드 명령은 만들지 않았고 프로젝트 조회 결과에 이미 있는 값을 그대로 읽는다.
프런트엔드 타입 검사와 테스트와 빌드가 모두 통과했다. 사용자 확인은 확인 동선 절을 따르면 된다.

## 목적

SPEC-050의 R1부터 R6까지를 구현한다. 활성 세션 표시가 오늘 화면에만 있어서 다른 화면에 머무는 동안
세션 진행 여부를 알 수 없는 문제를 해결한다. 표시가 쓰는 값은 프로젝트 조회 결과에 이미 들어 있으므로
새 조회나 백엔드 명령을 만들지 않는다.

## 현재 상태

착수 전에 확인한 값이다. 모두 `src/features/projects/components/WorkspaceShell.tsx` 기준이다.

- 화면 전환 상태는 123행의 `view`와 `setView`가 들고 있다. 값에는 `today`, `ideas`, `specs`, `tasks`,
  `archive`, `activity`, `integrations`, `help`, `settings`가 있다.
- 좌측 메뉴는 242행의 `<aside className="sidebar">`다. 이 요소는 화면 전환 분기 바깥에 있어서 어떤
  `view` 값에서도 항상 그려진다. 여기에 표시를 넣으면 R1의 "어느 화면에서도 보인다"가 배치만으로
  충족된다.
- 좌측 메뉴 하단은 279행의 `<div className="sidebar-footer">`이고, 그 안에 업데이트 조작 요소와
  연동·도움말·설정 버튼 세 개가 들어 있다. 기획서가 지정한 "연동이나 설정으로 가는 자리 근처"가 여기다.
- 오늘 화면의 기존 상세 카드는 349행부터 356행이다. `project.activeLeases.length > 0`일 때만 그려지고,
  `<button className="agent-activity">`가 `setView("activity")`를 호출한다. 내부에는 `pulse` 점, 담당
  에이전트 이름과 대상 문서와 마이그레이션 보호 안내, `agent-activity-count`의 활성 수,
  `agent-activity-more`의 이동 안내가 들어 있다.
- 활성 세션 값은 `project.activeLeases`이며 프로젝트 요약이 이미 들고 있다. 이 작업에서 새로 만들지
  않는다.

`src/App.css` 기준이다.

- 86행에 `.sidebar`, 114행에 `.sidebar-footer`가 있다. 후자는 `display: grid; gap: 4px; margin-top: auto`다.
- 155행부터 164행이 오늘 화면 카드의 스타일이다. 펄스 점 스타일은 157행의 `.agent-activity .pulse`로
  오늘 화면 카드 안에 한정돼 있다. 새 표시는 이 선택자에 걸리지 않으므로 자기 펄스 스타일이 필요하다.

`src/features/projects/components/WorkspaceShell.test.tsx` 기준이다.

- 24행의 공용 픽스처가 `activeLeases: []`를 기본값으로 둔다.
- 476행, 781행, 999행이 활성 세션이 있거나 없는 상태를 이미 다루고 있다. 이 검사들을 지우지 않는다.

## 변경 범위

- `WorkspaceShell.tsx`: 좌측 메뉴 하단에 활성 세션 축약 표시를 추가한다.
- `App.css`: 새 표시의 스타일을 추가한다.
- `WorkspaceShell.test.tsx`: 노출 조건, 정보량, 이동 동작, 프로젝트 전환 반영을 고정하는 검사를 더한다.

## 설계 지침

- 표시는 `sidebar-footer` 안에 둔다. 연동·도움말·설정 버튼과 같은 자리에 있어야 기획서가 정한 배치와
  맞고, 좌측 메뉴가 화면 전환 분기 바깥에 있으므로 별도 처리 없이 모든 화면에서 보인다.
- 노출 조건은 오늘 화면 카드와 같은 `project.activeLeases.length > 0`을 쓴다. 조건이 거짓이면 요소
  자체를 그리지 않는다. 빈 상태 문구나 자리 차지용 여백을 남기지 않는다.
- 표시에 담는 것은 세션이 도는지 알리는 시각 요소와 활성 세션 수뿐이다. 담당 에이전트 이름, 대상 문서
  식별자, 마이그레이션 보호 안내는 넣지 않는다. 이 세부 정보는 오늘 화면 카드와 활동 화면에 이미 있다.
- 누르면 `setView("activity")`를 호출한다. 오늘 화면 카드와 같은 동작이다. 이미 활동 화면일 때 눌러도
  같은 값을 다시 넣는 것이므로 오류가 나지 않아야 한다.
- 오늘 화면 카드의 마크업과 스타일은 고치지 않는다. 오늘 화면에서는 두 표시가 함께 보이는 것이
  기획서가 정한 결과다.
- 새 조회 함수, 새 백엔드 명령, 새 폴링 주기를 만들지 않는다. `project.activeLeases`를 그대로 읽는다.
  값 갱신 시점은 지금 프로젝트 조회가 갱신되는 시점을 그대로 따르고 이 작업에서 바꾸지 않는다.
- 새 표시는 버튼이므로 접근성 이름을 갖게 한다. 아이콘과 숫자만으로는 읽어주는 이름이 비어 있을 수
  있다. 기존 좌측 메뉴 버튼들이 쓰는 방식을 따른다.
- 펄스 점 스타일은 오늘 화면 카드의 것을 재사용하지 말고 새 표시용 선택자로 따로 적는다. 기존 규칙이
  오늘 화면 카드 안으로 한정돼 있어서 그대로는 적용되지 않는다.

## 손대지 않는 것

- 오늘 화면의 기존 상세 카드와 그 스타일
- 활동 화면의 내용과 동작
- 활성 세션 값을 만드는 백엔드와 프로젝트 조회 경로
- 활성 세션 값의 갱신 주기
- 세션별 목록 펼치기, 알림음, 배지 같은 기획서 제외 범위 항목

## 완료 조건

1. 활성 세션이 하나 이상일 때 오늘이 아닌 화면(아이디어, 기획서, 개발, 기록, 활동, 연동, 도움말,
   설정)에서도 좌측 메뉴에 축약 표시가 보인다.
2. 활성 세션이 하나도 없으면 어느 화면에서도 축약 표시가 보이지 않고, 자리 차지용 빈 요소도 남지
   않는다.
3. 축약 표시에는 세션이 도는지 여부와 활성 세션 수만 보인다. 담당 에이전트 이름, 대상 문서 식별자,
   마이그레이션 보호 안내는 보이지 않는다.
4. 축약 표시를 누르면 활동 화면으로 이동한다.
5. 이미 활동 화면을 보고 있을 때 축약 표시를 눌러도 오류 없이 활동 화면에 머문다.
6. 오늘 화면에서는 축약 표시와 기존 상세 카드가 함께 보인다. 기존 카드의 내용은 그대로다.
7. 활성 세션 값이 다른 프로젝트로 바꾸면 축약 표시가 바뀐 값을 따른다.
8. 새로 만든 조회 함수, 백엔드 명령, 폴링 주기가 없다.
9. 기존 검사를 삭제하거나 약화하지 않고 프런트엔드 전체 검사가 통과한다.

## 검증 절차

1. 활성 세션이 하나 이상인 상태로 화면을 아이디어, 기획서, 개발, 기록, 활동, 연동, 도움말, 설정으로
   각각 바꾸면서 축약 표시가 계속 보이는지 확인한다.
2. 활성 세션이 빈 목록인 상태에서 축약 표시가 문서에 없는지 확인한다. 숨김 스타일이 아니라 요소가
   그려지지 않는 것을 확인한다.
3. 축약 표시 안에 담당 에이전트 이름과 대상 문서 식별자가 없는지 확인한다. 오늘 화면 카드에는 그
   값들이 그대로 있는지 함께 확인해 두 표시가 뒤바뀌지 않았음을 고정한다.
4. 축약 표시를 눌러 활동 화면으로 이동하는지 확인한다. 활동 화면에서 한 번 더 눌러 오류 없이 활동
   화면에 머무는지 확인한다.
5. 오늘 화면에서 축약 표시와 기존 상세 카드가 동시에 보이는지 확인한다.
6. 활성 세션 값이 서로 다른 두 프로젝트를 차례로 넘겨 축약 표시의 활성 수가 각각을 따르는지 확인한다.
7. 변경한 코드에서 새 조회 호출이 늘지 않았는지 확인한다. 게이트웨이 호출 기록을 쓰는 기존 검사가
   그대로 통과하면 된다.
8. `npm run check`를 실행한다. 타입 검사와 테스트와 빌드가 모두 통과해야 한다.

## 확인 동선

좌측 메뉴에서 눈으로 확인하는 작업이다. 축약 표시는 활성 세션이 하나 이상일 때만 나오므로, 다른
에이전트 세션이 문서를 선점하고 있는 동안 확인한다. 프로젝트 조회는 2.5초마다 갱신되므로 세션이
시작되거나 끝나면 표시도 곧 따라온다.

1. 앱을 실행해 이 프로젝트를 연다. 활성 세션이 하나 이상이면 좌측 메뉴 맨 아래, 연동·도움말·설정
   버튼 위쪽에 초록 점과 "세션 실행 중" 문구와 활성 수가 있는 줄이 보인다.
2. 좌측 메뉴에서 아이디어, 기획서, 개발, 기록, 활동, 연동, 도움말, 설정을 차례로 눌러 화면을 바꾼다.
   어느 화면에서도 그 줄이 사라지지 않아야 한다.
3. 오늘 화면으로 돌아온다. 축약 표시와 기존 상세 카드가 함께 보여야 한다. 상세 카드에는 담당
   에이전트 이름과 대상 문서 식별자가 전과 같이 남아 있고, 축약 표시 줄에는 그 두 값이 없어야 한다.
4. 축약 표시를 누르면 활동 화면으로 이동한다. 활동 화면에서 한 번 더 누르면 오류 없이 활동 화면에
   머물러야 한다.
5. 모든 에이전트 세션이 끝나 활성 세션이 0이 되면 그 줄이 통째로 사라지고, 자리 차지용 빈 여백이
   남지 않아야 한다. 남은 세션이 있는지는 활동 화면에서 함께 확인한다.

러스트 코드를 고치는 다른 세션이 진행 중이면 데스크톱 앱 빌드가 실패할 수 있다. 그때는 아래 검사로
같은 항목을 확인한다. 저장소 루트에서 실행한다.

```sh
npx vitest run src/features/projects/components/WorkspaceShell.test.tsx
```

`WorkspaceShell 활성 세션 축약 표시` 묶음의 다섯 항목이 위 1번부터 5번까지에 각각 대응한다.

## 범위와 선행

선행 작업은 없다. 지금 바로 착수할 수 있다.

같은 파일을 선언한 다른 작업이 없다. 이 작업이 건드리는 세 파일을 마지막으로 수정한 TASK-134와
TASK-137은 둘 다 사용자 확인까지 끝난 상태라 되돌아올 여지가 없다. 진행 중인 TASK-139, TASK-140,
TASK-141은 러스트 코드와 신규 문서·스크립트만 건드리므로 이 작업과 겹치지 않는다.

이 작업을 하나로 둔 이유는 R1부터 R6까지가 같은 구성 요소 하나와 그 스타일, 그 검사 파일에서만
이뤄지기 때문이다. 나누면 세 파일을 모두 공유하게 되어 병렬로 진행할 수 없으면서 인수인계 비용만
늘어난다.
