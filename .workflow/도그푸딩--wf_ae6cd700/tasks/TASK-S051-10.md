# 에이전트 화면에서 실행 계획과 큐를 확인하고 제어한다

## 결정권자 요약

실행 전에 역할별 유료 세션 수와 실제 시작 대상과 제한 요인을 확인할 수 있다.
자동 배정과 직접 지정, 한 번 실행과 반복 실행을 구분해 선택한다.
실행 중과 대기와 최근 종료 항목이 프로젝트별로 보이고 앱을 다시 열어도 이어진다.
프로젝트의 새 배정을 멈추거나 재개하고 개별 실행을 명시적으로 취소하거나 재시도할 수 있다.
대상 없음과 사용 한도와 인증 문제와 복구 필요가 서로 다른 상태로 안내된다.

## 목적

TASK-S051-08의 실행 plan·start·status·pause·cancel·retry·logs 계약을 에이전트 화면에 연결한다.
사용자가 유료 CLI 세션이 몇 개 시작되는지 확인한 뒤에만 실행하고, runtime의 영속 상태를 프로젝트별
운영 대시보드로 보여준다.

## 시작 흐름

1. 역할마다 자동 배정 또는 수동 배정을 고른다. 자동이 기본이다.
2. 수동 배정은 슬롯을 추가하고 역할과 대상 문서를 선택한다. 자유 입력만 제공하지 않고 runtime이
   반환한 후보와 제외 사유를 함께 보여준다. 잘못된 식별자는 실행 전에 막는다.
3. 자동 배정 결과가 0건이면 제외 사유를 보여주고 같은 역할의 수동 배정 진입점을 제공한다. 수동
   배정은 안전 규칙을 우회하지 않는다는 설명을 함께 둔다.
4. 한 번 실행과 반복 실행을 명확히 구분한다. 반복 수동 배정은 지정 목록 이후 자동으로 바뀌지 않는다는
   설명을 붙인다.
5. `계획 확인`을 누르면 provider, 역할별 최대 인원, 프로젝트·기기 제한, 실제 시작 수, 대상 목록,
   반복 여부, 적용 프로젝트, 동시에 여러 유료 세션이 시작될 수 있음을 보여준다.
6. Claude API 과금 경로 위험이 있으면 확인 항목을 별도로 요구한다. 토큰이나 키 값은 보여주지 않는다.
7. 최신 plan의 확인 버튼만 start를 호출한다. stale plan 응답은 실패로 끝내지 않고 최신 계획을 다시
   확인하도록 유도한다.

## 상태 대시보드

- 상단에는 프로젝트의 새 배정 활성·일시 정지, 실행 중 수, 대기 수, 최근 결과, 기기 슬롯 사용량을
  보여준다.
- 세 역할 행은 설정값과 함께 현재 실행 수, 대기 수, 마지막 결과를 보여준다. 설정 표와 상태 표가
  서로 다른 역할 순서나 provider를 표시하지 않는다.
- 목록은 예약 중, 대기, 실행 중, 일시 정지, 성공, 실패, 취소됨, 복구 필요를 구분한다.
- 실행 중 항목은 프로젝트, 역할, provider, 대상 문서, 시작 시각, 경과 시간, 취소 행동을 보여준다.
- 최근 종료 항목은 결과, 소요 시간, 종료 원인, 이전 실행과의 재시도 연결, 로그 진입점을 보여준다.
- 대기 사유는 대상 없음, 마이그레이션 잠금, 실행 한도 소진, 역할·프로젝트·기기 슬롯 부족,
  provider 인증·사용 제한, 프로젝트 일시 정지를 구분한다.
- 구조화 이벤트가 도착하면 cursor 기반으로 진행 상황을 갱신한다. 전체 prompt와 비밀값은 표시하지
  않는다.

## 제어 흐름

- 프로젝트 일시 정지는 새 배정만 멈춘다는 문구를 확인한 뒤 실행한다. 실행 중 항목은 그대로 남는다.
- 취소는 대상, 역할, provider, 프로세스 트리와 lease 정리 영향을 보여주는 plan을 먼저 연다. 사용자
  확인 뒤에만 적용한다.
- 취소 결과는 프로세스 종료와 상태 정리 결과를 따로 보여준다. 일부 실패를 성공 배지로 접지 않는다.
- 재시도는 이전 실패를 보여주고 새 plan 확인을 거친다. 같은 실행 식별자를 재사용하지 않는다.
- 다른 프로젝트의 실행은 현재 화면 목록과 제어 대상에 섞이지 않는다. 기기 전체 사용량은 별도 요약으로
  구분한다.

## 상태 소유와 갱신

- 실행 계획, 실행 요청 진행, 마지막 오류, 취소 plan, 로그 cursor는 `useProjectWorkspace`가 프로젝트
  식별자별로 소유한다.
- 상태 조회는 앱이 열려 있을 때 주기적으로 수행하고 프로젝트 전환 시 즉시 새 프로젝트를 조회한다.
  앱을 다시 열었을 때는 메모리 복원 없이 runtime 상태를 첫 원천으로 사용한다.
- 화면을 떠났다가 돌아와도 앱이 시작한 조작의 진행 상태가 사라지지 않는다.

## 손대지 않는 것

- 런타임 dispatcher와 provider 프로세스
- 역할 설정 저장과 runtime 설치
- Dream 큐와 Dream 실행 UI
- 자유 대화와 원격 실행
- 실행 중 작업의 무확인 자동 취소

## 완료 조건

1. 자동·수동 배정과 한 번·반복 실행의 네 조합을 선택하고 서로 다른 의미를 확인할 수 있다.
2. 시작 확인 화면이 provider, 역할별 최대 인원, 실제 시작 수, 대상 목록, 반복 여부, 적용 프로젝트,
   유료 세션 위험을 보여준다.
3. 역할 상한 3, 프로젝트 상한 5, 기기 남은 슬롯 4, 대상 2의 plan에서 실제 시작 수 2와 대상 둘이
   보인다.
4. 대상 없음이나 마이그레이션 잠금에서는 확인 화면에 시작 수 0과 사유가 보이고 provider 시작 버튼이
   실행되지 않는다.
5. 자동 배정 대상이 0건이면 제외 사유와 수동 배정 진입점이 보이며, 수동 대상도 같은 안전 검증을
   통과해야 한다.
6. 같은 수동 대상 중복, 활성 lease, 완료·거절 대상, 잘못된 식별자는 실행 전에 막히고 사유가 보인다.
7. stale plan은 provider를 시작하지 않고 최신 계획 재확인을 요구한다.
8. 한 번 실행은 최초 목록 뒤 종료되고 반복 자동 실행은 빈 슬롯에 새 대상을 보충하는 상태 변화가
   화면에 반영된다.
9. 프로젝트 일시 정지는 새 배정만 멈추며 실행 중 항목과 다른 프로젝트 상태는 유지된다.
10. 각 역할 행이 provider, model, 실행 방식, 최대 인원, 현재 실행 수, 대기 수, 마지막 결과를 함께
    표시한다.
11. 실행 중 항목이 프로젝트, 역할, provider, 대상, 시작 시각, 경과 시간, 취소 행동을 표시한다.
12. 성공, 실패, 취소됨, 복구 필요와 실행 한도·인증·사용 제한·대상 없음 사유가 서로 다른 문구다.
13. 취소는 확인 전 실행되지 않고 부분 정리 실패를 성공으로 표시하지 않는다.
14. 재시도는 이전 실패와 새 실행을 함께 보여주며 중복 실행을 만들지 않는다.
15. 앱을 닫았다 다시 열면 runtime의 실행 중·대기·최근 종료 상태와 로그 cursor에서 복원된다.
16. 구조화 이벤트를 표시해도 인증 토큰, API 키, 전체 prompt가 화면과 브라우저 로그에 나타나지 않는다.
17. Dream이 실행 모드와 provider와 큐 목록에 나타나지 않는다.
18. 기존 화면 검사를 삭제하거나 약화하지 않는다.

## 검증 절차

1. 자동·수동, 한 번·반복, 상한 최솟값, 대상 0, 마이그레이션 잠금 plan fixture를 각각 렌더하고
   start 호출 여부를 검사한다.
2. 수동 중복·lease·완료·거절·잘못된 식별자와 stale plan을 사용자 이벤트로 재현한다.
3. 모든 상태와 대기 사유 payload를 표 기반 검사로 렌더해 문구와 행동이 섞이지 않는지 확인한다.
4. 프로젝트 둘을 전환하며 pause·resume·cancel·retry를 수행해 게이트웨이 요청의 project ID를
   대조한다.
5. 화면을 언마운트·재마운트하고 앱 초기 상태를 다시 만들어 runtime 조회 결과가 상태를 복원하는지
   확인한다.
6. 비밀 문자열과 전체 prompt가 든 가짜 이벤트를 주입해 DOM과 console 출력에서 검색되지 않는지
   확인한다.
7. `npx vitest run src/features/projects/components/agents/AgentRuntimeView.test.tsx src/features/projects/application/useProjectWorkspace.test.ts`를 실행한다.
8. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`을 실행한다.
