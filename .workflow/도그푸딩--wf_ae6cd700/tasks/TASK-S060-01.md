# 자동 확인 그룹의 완료 판정을 판정 시점의 기준 커밋에서 내린다

## 결정권자 요약

### 제안

자동 확인 방식의 작업 그룹이 새 커밋이 들어왔다는 이유만으로 완료되지 못하고 개발 중에 남는 상태를
없앤다.

### 현재

자동 확인 그룹은 속한 작업이 모두 검증 완료가 되는 시점에 확인 대상 코드 상태를 한 번 고정한다. 그
뒤 새 커밋이 하나라도 들어오면 고정한 값과 지금의 코드 상태가 다르다는 이유로 완료 대신 개발 중으로
되돌아간다. 고정한 값을 다시 잡는 길이 없어서, 한 번 어긋난 그룹은 개발이 진행될수록 영영 완료되지
않는다. 지금 이 저장소에도 작업 여섯 건이 모두 검증 완료인데 이 이유로 개발 중에 남아 있는 그룹이
하나 있다.

### 변경 후

자동 확인 그룹은 판정하는 시점의 코드 상태에서 완료 여부를 정한다. 검증이 끝난 그룹은 그 자리에서
완료로 표시되고, 개발 작업 화면의 목록과 진행 중 수치가 실제로 남은 일만 가리킨다. 지금 갇혀 있는
그룹도 사용자가 화면을 다시 열면 별도 조작 없이 완료로 정리된다.

### 비용과 위험

사용자가 직접 확인하는 작업 그룹의 동작은 이 작업에서 하나도 바뀌지 않는다. 확인 도중 코드가 바뀐
제출을 기록하지 않는 보호도 그대로 남는다. 검증이 끝난 뒤 들어온 커밋이 이미 끝난 검증을 깨뜨렸는지는
앱이 판단하지 않으며, 이 점은 변경 전과 같다. 작업 문서와 결정 기록은 이 작업으로 바뀌지 않고,
되돌리면 지금 동작으로 그대로 복귀한다.

## 현재 코드 상태

관련 코드는 모두 `src-tauri/src/infrastructure/fs_project_repository.rs` 안에 있다.

- `QaBasePin`(2864~2908행)이 확인 대상 기준 커밋을 다룬다. `current()`(2880~2884행)는
  `current_base_commit`(3011~3022행)으로 `git rev-parse HEAD`를 한 번만 읽어 캐시하고, Git 작업
  트리가 아니면 `None`이다. `pin()`(2888~2907행)은
  `.workflow/.runtime/qa-base/<group-id>-<revision>.yml`을 읽어 값이 있으면 그대로 돌려주고, 없을
  때만 현재 커밋을 적는다. 주석에도 "이미 있으면 그대로 읽어 돌려주며 다시 쓰지 않는다"라고 적혀
  있다. 경로 조립은 `qa_base_pin_path`(2910~2921행), 읽기는 `read_qa_base_pin`(2923~2927행)이다.
- 저장된 고정 값을 갱신하거나 삭제하는 경로는 저장소에 없다. `QA_BASE_DIRECTORY`(52행)를 쓰는
  생산 코드는 위 경로 조립 한 곳뿐이다.
- `parse_work_group`(3063~3208행)이 표시 상태를 파생한다. 3127~3172행의 분기가 완료·재작업·준비·
  막힘·개발 중·구성 오류를 차례로 판정하고, 사용자 모드는 `QaReady`, 자동 모드는
  `AutomaticCompleted`로 끝난다. 3176~3181행이 그 두 상태에서만 `pin()`을 불러 고정 값을 싣는다.
- 3184~3190행이 이 작업이 바꾸는 자리다. 표시 상태가 `AutomaticCompleted`이고 고정 값이 지금
  기준 커밋과 다르면 `Developing`으로 되돌린다. 되돌린 뒤 다시 판정하는 처리는 없다.
- 제출 판정(755~761행)은 같은 고정 값을 읽어, 지금 기준 커밋과 다르면
  `ProjectError::WorkGroupQaBaseChanged`(130~131행)로 거절한다. 이 경로는 사용자 모드 그룹만
  지나간다(778~783행이 `QaReady`인 사용자 모드 그룹만 통과시킨다).
- `integration_waiting_tasks`(2941~2979행)도 같은 `QaBasePin`을 받지만 `current()`만 쓰고 고정
  파일은 읽지 않는다.
- 실제로 갇힌 그룹의 기록은 `GROUP-RES-20260815T032125Z-60360-20260815032125-1.yml`이며 기준
  커밋이 2026-08-15의 값으로 남아 있다. `.workflow/.runtime/`은 Git 추적 대상이 아니므로 격리된
  작업 사본에는 이 파일이 없다. 이 작업의 검증은 시험 픽스처로 하고, 실제 그룹의 회복은 그룹 품질
  확인에서 사용자가 확인한다.

## 완료 조건

- C1. 자동 확인 그룹의 표시 상태를 고정 값 불일치 때문에 `Developing`으로 되돌리는 처리를 없앤다.
  3184~3190행의 되돌림이 이 작업으로 사라져야 하며, 자동 확인 그룹은 기준 커밋이 전진한 뒤 다시
  읽어도 `AutomaticCompleted`를 유지한다.
- C2. 자동 확인으로 완료를 판정한 그룹은 판정 시점의 현재 기준 커밋을 확인 대상 기준으로 기록한다.
  저장된 값이 현재 커밋과 다르면 현재 값으로 갱신하고, 그룹 요약의 `qa_base_commit`에도 갱신한 값을
  싣는다. `QaBasePin`에 이 갱신 동작을 더하되, 사용자 모드 판정이 쓰는 한 번만 고정하는 동작은 이
  작업에서 그대로 남긴다. 두 동작을 별도 메서드로 나눌지 인자로 가를지는 구현자가 정한다.
- C3. 완료 판정 조건 자체는 바꾸지 않는다. 3127~3172행 분기의 순서와 조건을 그대로 두어, 검증
  완료가 아닌 작업이 하나라도 있는 그룹, 구조나 작업 유효성 검사를 통과하지 못한 그룹, 사용자 확인
  항목이 들어 있는 자동 확인 그룹은 기준 커밋 전진 여부와 무관하게 완료로 넘어가지 않는다.
- C4. 사용자 확인 모드는 이 작업에서 바뀌지 않는다. `QaReady` 그룹의 고정은 지금처럼 한 번만
  잡히고, 제출 판정(755~761행)과 거절 오류 종류도 그대로 둔다. 확인 도중 코드가 바뀐 제출을
  기록하지 않는 보호가 이 작업 전후로 끊기지 않아야 한다.
- C5. Git 작업 트리가 아닌 프로젝트의 동작은 변경 전과 같다. `current()`가 `None`이면 기록 파일을
  만들지 않고, 표시 상태 판정에도 고정 값이 실리지 않는다.
- C6. 기록 파일의 경로 규칙과 형식은 그대로 둔다. 열쇠는 그룹 식별자와 구성 버전이고, 필드는
  `schema_version`, `group_id`, `group_revision`, `base_commit`, `pinned_at`이다. 갱신은 같은
  경로에 같은 형식으로 쓰고 `pinned_at`은 갱신 시점 값으로 다시 적는다. 쓰기가 실패하면 지금처럼
  고정 값이 없는 것으로 다루어 판정이 흔들리지 않게 한다.
- C7. 이 작업으로 `.workflow` 아래의 문서 파일, 규칙 문언, 역할 계약, 규칙 버전은 하나도 바뀌지
  않는다. 다른 프로젝트 소스 파일도 바뀌지 않는다.
- C8. `automatic_work_group_does_not_complete_when_the_base_commit_moves`(11855~11884행)를 새
  규칙에 맞춰 다시 쓴다. 이 시험이 고정한 규칙이 바로 이 작업이 바꾸는 규칙이므로 지우지 말고
  기대값과 이름을 함께 고쳐 쓴다. 새 기대는 두 가지다. 기준 커밋이 전진한 뒤 다시 읽어도 표시
  상태가 `AutomaticCompleted`로 남는다. 그리고 그룹 요약과 기록 파일의 기준 커밋이 모두 전진한
  현재 커밋과 같다.
- C9. 자동 확인 그룹에 검증 완료가 아닌 작업이 있으면 기준 커밋이 전진해도 완료로 넘어가지 않는
  시험을 새로 더한다(수용 기준 4). 자동 모드 픽스처와 기준 전진 도우미가 이미 있으므로 그 둘을
  쓴다.
- C10. 나머지 기준 커밋 관련 시험 다섯 개는 수정 없이 통과한다.
  `work_group_pins_its_qa_base_commit_when_qa_can_open_and_never_repins_it`(11709행),
  `work_group_qa_rejects_a_submission_after_the_base_commit_moves`(11762행),
  `work_group_qa_records_on_the_pinned_base_and_replays_a_recorded_request`(11791행),
  `each_work_group_revision_pins_its_own_base_commit`(11814행),
  `work_group_qa_keeps_its_previous_behaviour_outside_a_git_work_tree`(11889행)이다. 앞의 넷은
  사용자 모드 픽스처를 쓰므로 C4가 지켜지면 그대로 통과하고, 이 중 하나라도 손대야 한다면 C4를
  넘은 것이므로 구현을 다시 맞춘다.

- 화면 코드 변경. 자동 완료 표시 상태는 화면이 이미 완료로 다루고 있다.
- 통합 대기 판정 변경.

   한다(C7).

## 범위 사전 검사

선언한 파일은 `src-tauri/src/infrastructure/fs_project_repository.rs` 하나다. 판정 분기, 기준
커밋 고정, 그 시험이 모두 이 파일 안에 있어서 완료 조건이 요구하는 편집 지점이 이 파일에서 닫힌다.
아래 값의 경로를 실제 코드에서 따라가 확인했다.

- 값 경로: 자동 확인 그룹의 표시 상태(C1·C3). 원천은 `parse_work_group`의 3127~3172행 파생이고,
  편집이 필요한 hop은 3184~3190행의 되돌림 분기 하나다. 그 값은
  `src-tauri/src/domain/project.rs` 300행 `WorkGroupSummary::display_status`로 실려 나가고,
  `src/features/projects/domain/types.ts` 168행이 `automatic_completed`를 이미 선언하고 있다.
  최종 소비자는 `src/features/projects/components/DevelopmentBoard.tsx` 698행
  `isFinishedGroup`과 `src/features/projects/components/WorkspaceShell.tsx` 659·685행의 완료
  수치이며, 둘 다 `completed`와 함께 `automatic_completed`를 이미 끝난 그룹으로 다룬다. 라벨도
  `DevelopmentBoard.tsx` 518행, `QaWorkbench.tsx` 162행, `SpecWorkspace.tsx` 384행에 이미 있다.
  자동 완료라는 값 자체는 새로 만드는 값이 아니고 이 작업은 그 값이 나오는 조건만 바꾸므로, 도메인·
  타입·화면 hop은 값을 무변경으로 나른다. 그래서 그 파일들을 선언에서 뺐다.
- 값 경로: 확인 대상 기준 커밋의 기록(C2·C6). 원천은 `current_base_commit`(3011~3022행)이고
  `QaBasePin::current`(2880~2884행)가 캐시한다. 편집이 필요한 hop은 `pin`(2888~2907행)과 그
  호출부(3176~3181행) 둘이며 같은 파일이다. 기록 파일은
  `.workflow/.runtime/qa-base/<group-id>-<revision>.yml`이고 경로 조립
  `qa_base_pin_path`(2910~2921행)와 읽기 `read_qa_base_pin`(2923~2927행)은 형식이 그대로여서
  편집이 없다. 이 값의 다음 소비자는 `WorkGroupSummary::qa_base_commit`(도메인 312행)과 제출
  판정(755~761행)이다. 제출 판정은 사용자 모드 그룹만 지나가고 C4가 사용자 모드 고정 동작을 그대로
  두므로, 이 hop은 이 작업에서 값이 무변경으로 통과한다. 화면에는 이 값을 읽는 코드가 아직 없다
  (`types.ts` 183~197행의 그룹 요약 타입에 해당 필드가 선언되어 있지 않다). 그래서 도메인 파일과
  화면 타입 파일을 선언에서 뺐다.
- 값 경로: 통합 대기 판정과의 공유(무변경 확인). `integration_waiting_tasks`(2941~2979행)는 같은
  `QaBasePin`을 받지만 `current()`와 격리 기록만 읽고 고정 파일은 읽지 않는다. `current()`의
  의미와 캐시 방식을 바꾸지 않으므로 이 판정은 편집 없이 그대로 동작한다.
- 값 경로: Git 작업 트리가 아닌 프로젝트(C5). `current_base_commit`이 `None`이면 `current()`도
  `None`이고, 고정과 갱신 모두 값을 만들지 못해 표시 상태 판정에 아무 값도 실리지 않는다. 이 경로는
  `work_group_qa_keeps_its_previous_behaviour_outside_a_git_work_tree`(11889행)가 고정하고 있어
  C10이 그 불변을 확인한다.

선언에서 뺀 파일과 그 근거를 다시 정리하면 다음과 같다.

- `src-tauri/src/domain/project.rs`: 표시 상태와 기준 커밋 필드가 이미 있고 모양이 바뀌지 않는다.
- `src/features/projects/domain/types.ts`: 자동 완료 표시 상태가 이미 선언되어 있고, 기준 커밋
  필드는 이 작업에서 화면이 읽지 않는다.
- `src/features/projects/components/DevelopmentBoard.tsx`,
  `src/features/projects/components/WorkspaceShell.tsx`: 위 값 경로에서 확인한 대로 자동 완료를
  이미 끝난 그룹으로 소비한다. 이 작업은 그 판정에 도달하는 그룹의 수만 달라지게 한다.
