# 설정에서 관리 규칙 버전과 마지막 동기화 결과를 보여준다

## 결정권자 요약

설정 화면에 관리 규칙 카드를 추가했다. 공통 규칙과 세 역할 계약의 설치 버전, 앱 제공 버전, 마지막
동기화 결과를 한곳에서 확인할 수 있다.
현재 상태, 갱신됨, 재시도 필요, 충돌을 서로 다른 문구와 후속 행동으로 표시하고, 문제가 있는 자산의
이름과 이유도 함께 보여준다.
재시도 필요와 충돌, 동기화 명령 실패는 프로젝트 오류와 분리된 관리 규칙 알림으로 올린다. 알림이
있어도 사이드바와 문서 화면, 설정 화면은 그대로 사용할 수 있다.
버전을 쓰지 않는 진입 안내에는 숫자를 만들지 않고, 설치 버전을 읽지 못한 경우도 그대로 표시한다.
규칙 변경은 다음에 시작하는 에이전트 세션부터 적용된다고 안내하고, 실행 중인 세션에 적용됐다는
보장은 표시하지 않는다.
사용자 정의 규칙 편집 화면은 추가하지 않았다. 프런트엔드 검사 728개와 타입 검사, 배포 빌드가 통과했다.

## 목적

SPEC-047의 R4 화면 부분, R5, R6과 완료 조건 6, 8, 11을 처리한다. TASK-133이 제공하는 관리 규칙
동기화 상태를 사용하며, 화면에서 파일을 다시 읽거나 버전을 계산하지 않는다.

## 화면 계약

### 설정 카드

현재 프로젝트 카드와 별도로 `관리 규칙` 카드를 둔다. 카드에는 다음 내용을 표시한다.

- 전체 상태: 현재, 갱신됨, 재시도 필요, 충돌
- 공통 규칙의 설치 버전과 앱 제공 버전
- 기획자, 아키텍트, 개발자 역할 계약 각각의 설치 버전과 앱 제공 버전
- 버전이 없거나 읽을 수 없는 경우의 명시적인 상태
- 마지막 동기화를 실행한 계기와 결과
- 문제가 있는 자산의 표시 이름과 백엔드가 제공한 이유
- 변경 내용은 다음에 시작하는 에이전트 세션부터 적용된다는 안내

기획자, 아키텍트, 개발자 버전을 하나의 공통 숫자로 합치지 않는다. 앱이 제공하는 실제 값 8, 7, 8이
각 행에 표시돼야 한다. 선점 헬퍼와 진입 안내는 문제 원인을 설명할 때 자산 이름으로 표시하되, 버전이
없는 진입 안내에 숫자를 만들지 않는다.

첫 동기화를 아직 시도하지 않은 호환성 제한 프로젝트에서는 왜 상태가 없는지 설명한다. 화면이 자체로
현재 여부를 추정하지 않는다.

### 공통 오류 영역

`retry_required`와 `conflict`, 명령 호출 오류는 기존 프로젝트 오류와 다른 관리 규칙 알림으로
표시한다. 사용자가 어느 자산을 확인하거나 언제 다시 시도해야 하는지 알 수 있어야 한다. 이 알림이
있어도 사이드바, 문서 화면, 설정 화면은 계속 사용할 수 있다.

자동 조회로 알림이 사라지지 않는다. 다음 명시적 열기나 수동 새로 고침 결과가 이전 결과를 교체한다.

### 표시하지 않는 주장

- 실행 중인 에이전트가 새 규칙을 읽었다고 표시하지 않는다.
- 충돌을 앱이 자동 해결했다고 표시하지 않는다.
- 사용자 정의 규칙의 사용 여부나 우선순위를 표시하지 않는다.

## 변경 범위

- `App.tsx`: 관리 규칙 상태를 작업 공간에 전달한다.
- `WorkspaceShell.tsx`: 공통 알림과 설정 화면 전달.
- `SettingsView.tsx`: 관리 규칙 상태 카드.
- 각 컴포넌트 검사: 네 결과 상태, 역할별 버전, 프로젝트 접근 유지, 다음 세션 안내.
- `App.css`: 카드와 알림의 기존 디자인 체계 안에서 필요한 스타일.

## 완료 조건

1. 설정 화면에 현재 프로젝트 카드와 별도의 관리 규칙 카드가 있다.
2. 공통 규칙과 기획자 8, 아키텍트 7, 개발자 8의 설치·제공 버전을 각각 표시한다.
3. `current`, `updated`, `retry_required`, `conflict`가 서로 다른 한국어 상태와 후속 행동으로 보인다.
4. 충돌 자산과 이유가 설정 카드와 공통 알림에서 확인된다.
5. 재시도 가능한 잠금 상태와 사용자가 파일을 확인해야 하는 충돌 상태를 같은 문구로 합치지 않는다.
6. 동기화 실패 중에도 프로젝트 탐색과 설정 화면을 사용할 수 있다.
7. 규칙 변경은 다음에 시작하는 에이전트 세션부터 적용된다고 명시한다.
8. 실행 중인 에이전트에 적용됐다는 보장은 표시하지 않는다.
9. 자동 조회 결과가 관리 규칙 알림을 지우지 않는다.
10. 기존 설정 카드, 프로젝트 전환, 새로 고침 진행 표시가 유지된다.
11. 커스텀 가드레일 편집이나 저장 기능을 추가하지 않는다.
12. 기존 자동 검사를 삭제하거나 약화하지 않고 프런트엔드 전체 검사가 통과한다.

## 검증 절차

1. 네 전체 상태를 각각 렌더링해 상태 이름, 후속 행동, 다음 세션 안내를 확인한다.
2. 역할별 서로 다른 제공 버전이 각 행에 그대로 표시되는지 확인한다.
3. 선점 헬퍼 충돌과 아키텍트 역할의 더 새로운 설치본 충돌을 넣어 정확한 자산 이름과 이유를
   표시하는지 확인한다.
4. 공통 알림이 있는 상태에서 설정 이동과 다른 프로젝트 열기 버튼이 동작하는지 확인한다.
5. 기존 설정 화면과 새로 고침 컴포넌트 검사를 함께 실행한다.
6. `npm run check`를 실행한다.
7. 개발 앱에서 프로젝트를 연 뒤 설정 카드와 수동 새로 고침 결과를 직접 확인한다.

## 확인 동선

1. 개발 앱에서 이 저장소를 연 뒤 사이드바 아래 `설정`을 누른다. `현재 프로젝트` 카드와 별도로
   `관리 규칙` 카드가 보이고, 상태 줄에 `현재 상태` 또는 `갱신됨`이 표시된다.
2. 카드의 자산 목록에서 역할 계약 세 줄이 각자의 숫자를 그대로 보여주는지 확인한다. 이 커밋 시점의
   앱 제공 값은 공통 규칙 14, 기획자 9, 아키텍트 8, 개발자 9다. 세 역할을 하나의 숫자로 합쳐 보이면
   잘못된 것이다. `AGENTS 진입 안내`와 `CLAUDE 진입 안내`는 숫자 대신 `버전을 쓰지 않는 자산`으로
   표시돼야 한다.
3. 상단 새로 고침 버튼을 누른다. 카드의 `마지막 동기화` 값이 `수동 새로 고침`으로 바뀐다.
4. 충돌 재현: 편집기로 `.workflow/rules/roles/architect.md`의 `rules_version: 8`을
   `rules_version: 99`로 바꾸고 저장한 뒤 상단 새로 고침을 누른다.
   - 화면 위쪽에 `관리 규칙 충돌: 아키텍트 역할 계약` 알림이 뜨고, 프로젝트 오류 배너와 다른 색·다른
     문구로 보인다.
   - 알림이 있는 상태에서 사이드바의 `아이디어`, `개발`, `설정` 이동과 설정 카드의
     `다른 프로젝트 열기` 버튼이 그대로 동작한다.
   - 설정의 관리 규칙 카드에서 아키텍트 행이 `충돌`로 표시되고 백엔드가 준 이유 문장이 함께 보인다.
   - 알림이 뜬 채로 10초 이상 그대로 둔다. 2.5초 자동 조회가 여러 번 돌아도 알림과 카드 내용이
     사라지지 않아야 한다.
   - 확인이 끝나면 `rules_version: 99`를 원래 값 `8`로 되돌리고 새로 고침을 눌러 상태가 정상으로
     돌아오는지 본다.
5. 카드 아래 안내 문장이 "다음에 시작하는 에이전트 세션부터 적용된다"고 말하는지, 실행 중인 세션에
   적용됐다는 문장은 없는지 확인한다.
6. 자동 검사로 확인한 항목: 네 결과 상태의 문구 구분, 역할별 버전 표시, 충돌 자산 이름과 이유,
   명령 실패와 프로젝트 오류의 분리, 커스텀 규칙 편집 요소가 없다는 점. `npm run check`로
   728개 검사와 타입 검사, 배포 빌드가 통과한다.
