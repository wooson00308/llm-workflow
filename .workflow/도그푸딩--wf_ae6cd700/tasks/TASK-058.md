# 아이디어 인박스가 종결된 아이디어를 구분해 보여주고 재진입 경로를 알린다

SPEC-018 R6의 화면 몫을 구현한다. TASK-057이 파생한 네 번째 상태를 인박스가 구분해 보여주고, 사용자가
다음에 무엇을 하면 되는지 화면에서 알 수 있게 한다. 계약이 정한 재진입 경로는 "새 아이디어로 다시
요청"이고 앱에는 그 입구가 이미 있다(인박스 상단 작성 칸).

판정은 하지 않는다. 화면은 백엔드가 실어 보낸 값을 그대로 읽는다(SPEC-012 R6).

## 의존성

- **선행 필수: TASK-057.** 화면이 읽을 네 번째 상태 값을 그 작업이 만든다. 코드 의존이다.
  **선행이 반영되지 않은 상태에서 이 작업을 시작하지 않는다.**
- 인박스 화면을 만지는 다른 `todo` 작업은 없다. TASK-036(SPEC-012)이 지금 형태를 만들었고
  `qa_waiting`이다.

## 범위

- `src/features/projects/domain/types.ts` — `status` 주석(파생값이 넷이 된다).
- `src/features/projects/components/IdeaInbox.tsx` — 상태 유니온, 라벨·아이콘·pill, 종결 안내.
- `src/features/projects/components/IdeaInbox.test.tsx` — 테스트.
- `src/App.css` — 종결 상태의 색.
- 그 외 파일은 건드리지 않는다. 특히 백엔드·`role_eligibility.rs`·다른 화면은 이 작업에서 바뀌지
  않는다.

## 작업 내용

### 1. 네 번째 상태를 화면 어휘에 더한다

- `IdeaState` 유니온과 `ideaState`의 좁히기에 `closed`를 더한다. 지금 함수는 아는 값이 아니면 `inbox`로
  떨어뜨린다 — 그 폴백은 유지한다. 모르는 값을 종결로 읽으면 화면이 없는 사실을 말한다.
- 라벨은 "종결"이다. 아이콘은 `archive`를 쓴다(`Icon.tsx`에 이미 있다). pill은 기존
  `status-rejected`(`App.css:231`)를 쓰고, 목록 태그·목록 아이콘 색만 `App.css`에 더한다. 새 색을
  만들지 않는다 — 반려 계열 색이 이미 있다.
- 목록 행은 지금 `inbox`가 아닐 때만 태그를 단다. 종결도 태그가 붙는다.

### 2. 다음 행동을 알린다

미리보기에 종결 안내를 둔다. 중단 의심 안내(`idea-stall-note`)와 같은 자리, 같은 모양을 쓰고 문구만
다르다.

- 담을 사실은 둘이다. 이 아이디어에서 나온 기획서가 모두 반려로 끝났다는 것과, 다시 진행하려면 새
  아이디어를 만들어야 한다는 것.
- 자동으로 다시 잡히지 않는다는 사실을 함께 적는다. 중단 의심 안내가 같은 문장을 쓰고 있어 두 안내의
  결이 맞는다.
- 재큐 버튼·복사 액션을 만들지 않는다. DECISION-1224D86C가 확인 필요 1번을 "구분만 한다"로 확정했다.
- 종결과 중단 의심은 함께 뜨지 않는다. `stalled_spec_ids`는 `drafting`에서만 채워지기 때문이다. 그
  전제를 화면 코드가 다시 확인하지 않는다.

### 3. 테스트

`IdeaInbox.test.tsx`에 더한다.

- 종결 아이디어의 목록 행에 "종결" 태그가 뜬다. (기획서 완료 조건 18)
- 종결 아이디어를 선택하면 미리보기 pill이 "종결"이고 재진입 안내가 보인다.
- 채택 아이디어에는 종결 태그도 안내도 없다. (기획서 완료 조건 19)
- 반영중·수집됨 아이디어의 기존 표시가 그대로다. 기존 테스트가 수정 없이 통과한다.
- 알 수 없는 상태 문자열은 수집됨으로 읽힌다(기존 폴백 유지).

## 완료 조건

1. 참조 기획서가 모두 반려로 끝난 아이디어가 목록과 미리보기에서 다른 아이디어와 구분되어 보인다.
   (기획서 완료 조건 18)
2. 살아 있는 기획서가 하나라도 있는 아이디어에는 종결 표시가 뜨지 않는다. (기획서 완료 조건 19)
3. 화면이 상태를 다시 판정하지 않고 백엔드 값을 읽는다. 모르는 값은 수집됨으로 떨어진다.
4. 종결 안내가 재진입 경로(새 아이디어)를 문장으로 알린다.
5. 기존 자동화 테스트가 삭제되거나 비활성화되지 않는다. (기획서 완료 조건 22)
6. `npm run check`가 통과한다. (기획서 완료 조건 23)
