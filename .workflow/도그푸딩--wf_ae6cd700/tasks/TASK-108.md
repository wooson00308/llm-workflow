# 084 경고 자리에서 갱신 절차를 읽고 복사한다 — 공용 안내와 역할 잡 카드

SPEC-034의 R1~R6·R8을 역할 잡 카드에서 닫고, 두 카드가 함께 쓸 안내 컴포넌트를 만든다. dream 카드
배선과 R7의 최종 확인은 TASK-109다.

## 의존성

`depends_on: [TASK-107]`.

- **계약이 그쪽에서 온다.** 이 작업이 그리는 명령 원문은 전부 TASK-107이 payload에 싣는 값이고,
  R3이 화면에서 문자열을 만드는 것을 금지한다. 107이 서기 전에는 그릴 값이 없다.
- 파일은 겹치지 않는다(107은 `src-tauri/`만, 이 작업은 `src/`만). 순서를 정하는 것은 계약이다.

## 승인된 확인 필요가 이 작업의 경계다

- 1번(갈래를 보인다) → **명령 하나로 단정하지 않는다.** pip 갈래·소스 갈래·공통 재시작 셋이 보이고,
  그 앞에 "어느 쪽인지 확인하는 방법"이 온다. 대안 A(한 줄로 단정)도 대안 B(README를 가리킨다)도
  아니다.
- 2번(버전 표시는 뺀다) → **버전을 읽거나 보여주는 코드가 없다.** "업데이트가 필요합니다" 같은 판정
  문구도 만들지 않는다.
- 3번(마법사 1단계는 다루지 않는다) → 설치 마법사의 문구·단계·상태를 **건드리지 않는다.**
- 4번(경고가 뜰 때만) → **상시 표시가 아니다.** 084 경고 안에서만 그린다. 설치 마법사 옆이나 접힌
  영역에 두지 않는다.

## 만들 것

### 1. 공용 안내 컴포넌트

`src/features/projects/components/integrations/HeartbeatUpdateGuide.tsx`를 새로 만든다.
`JobChanges.tsx`가 두 카드가 함께 쓰는 하위 블록의 선례다. `IntegrationCard.tsx`에 넣지 않는다 —
그 파일은 연동 골격이고, 하트비트 전용 블록을 거기 두면 층이 섞인다.

- props는 payload의 갱신 안내 값 하나다. **문구를 props로 받지 않는다** — 두 카드가 다른 문구를
  넘길 수 있는 자리를 만들면 R7이 화면 테스트로 내려간다.
- **복사 상태를 컴포넌트가 스스로 든다.** 역할 잡 카드는 이 안내를 역할마다 그릴 수 있어(경고가
  역할별이다) 상태를 카드가 들면 한 화면에 "복사됨"이 여러 자리에 뜬다. 인스턴스가 각자 들면 그
  분리가 구조로 보장된다. 마지막으로 복사한 명령 하나만 표시하는 것은 마법사와 같다
  (`HeartbeatCard.tsx:507` 주석).
- 복사는 `../../infrastructure/clipboard`의 `copy`를 부른다. 화면이 플러그인을 직접 import 하지
  않는다.

### 2. 안내가 말하는 것

문구는 개발자가 쓰되 아래를 모두 담고, 아래 밖의 사실을 지어내지 않는다.

1. **원칙 한 줄.** 설치한 방법 그대로 갱신한다. 갈래가 둘인 이유가 이 문장이다.
2. **갈래 판별.** `identifyCommand`(`pip show claude-heartbeat`)를 명령 원문으로 싣고,
   `Editable project location`이 나오면 소스 체크아웃, 안 나오면 pip 설치라고 말한다.
   확인 필요 1번의 승인된 제안이 지정한 방법이다.
3. **pip 갈래.** `packageCommand`.
4. **소스 갈래.** `sourceCommand`. **앱이 체크아웃 디렉터리를 알지 못한다는 사실을 함께 말한다.**
   명령이 `git pull` 한 줄인 이유가 그것이다(R2).
5. **재시작.** `serviceLookupCommand`로 라벨을 찾고 `serviceRestartCommand`로 재시작한다.
   `<라벨>`이 사용자가 바꿔 넣는 자리라는 것을 문구가 말한다. **앱이 이 기기의 라벨을 알지 못한다는
   사실을 감추지 않는다**(R4·확인 사실 11).
6. **재시작이 필요한 이유.** 코드를 갱신해도 도는 프로세스는 옛 코드를 들고 있다(확인 사실 6).
   이 문장이 없으면 사용자는 갱신했는데 아무것도 달라지지 않는 상태를 만난다.
7. **두 재시작 값이 없을 때.** payload가 `null`이면(macOS 밖) 명령을 지어내지 않고, 앱이 이
   플랫폼의 재시작 방법을 알지 못한다고 말한다. 마법사 3단계가 같은 상태를 같은 어법으로 말한다.

**084 문구와 어긋나지 않는다**(R2·완료 조건 3). 084는 "앱은 하트비트 버전을 판정하지 않으므로 둘 중
어느 쪽인지 알지 못합니다"로 끝난다. 안내가 "갱신하면 해결됩니다"처럼 원인을 단정하면 그 문장과
모순된다. 안내는 **"갱신하기로 했다면 이렇게 한다"**를 말하는 자리다.

### 3. 복사 어법

마법사(`HeartbeatCard.tsx:589`~`:612`)와 실행 실패(`:1245`~`:1267`)가 이미 쓰는 모양을 그대로
따른다. **새 어법을 만들지 않는다.**

- 명령 원문은 `<pre><code>{...}</code></pre>`로 화면에 남는다. 복사 버튼이 원문을 대체하지 않는다.
- 버튼 글자는 `명령 복사`, `aria-label`은 `<그 걸음 이름> 명령 복사`.
- 결과 문구는 글자까지 같다 — 성공 `복사됨`, 실패
  `복사하지 못했습니다 — 위 명령을 직접 선택해 복사하세요.`
- 확인 대화상자를 끼우지 않는다. 한 번의 조작으로 끝난다.

### 4. 역할 잡 카드 배선

`HeartbeatCard.tsx:1176`~`:1180`의 084 경고 안, `<p>{noRunEvidenceNote}</p>` 다음에 그린다.

- **표시 조건을 새로 만들지 않는다.** `missingRunEvidence(Boolean(job), run)`이 이미 그 자리의
  조건이고, 안내는 그 안에 들어간다. 확인 필요 4번이 그것이다.
- **`bodyWarning`(`:432`~`:439`)을 고치지 않는다.** 접힘 요약의 동작은 084가 정했고 R7 둘째 줄이
  "새 규칙을 만들지 않는다"로 못 박았다.
- **어떤 버튼도 비활성화하지 않는다.** 저장·재설정·"지금 실행"의 `disabled` 조건을 건드리지 않는다
  (R8·완료 조건 13).

### 5. 화면 계약과 픽스처

- `src/features/projects/domain/types.ts` — `IntegrationsSnapshot`에 필드 하나와 새 인터페이스.
  Rust 쪽 이름을 camelCase로 그대로 옮긴다.
- 필드가 필수라 **기존 스냅샷 픽스처 셋이 함께 움직인다.** 값이 없으면 타입 검사가 깨진다.
  - `IntegrationsView.test.tsx:177` 근처
  - `DreamCard.test.tsx:108` 근처 — **이 작업이 픽스처만 채운다.** dream 카드의 시나리오는
    TASK-109다.
  - `useProjectWorkspace.test.ts:38` 근처
- 게이트웨이는 그대로다. `tauriProjectGateway.ts`는 `invoke<IntegrationsSnapshot>`로 통과시킬 뿐
  필드를 옮겨 적지 않는다.

## 검사

`IntegrationsView.test.tsx`에 넣는다(역할 잡 카드의 시나리오가 사는 자리다). **기존 검사는 이름도
내용도 고치지 않는다** — 픽스처에 필드를 더하는 것은 제외한다.

1. 084 경고가 뜨는 픽스처(잡은 설치됐고 `lastRun`이 없는 역할)에서 같은 경고 안에 갱신 절차가 있다.
   `IntegrationsView.test.tsx:1271`이 그 상태를 이미 만든다.
2. 경고가 없는 상태에서는 안내도 없다. 실행 기록이 있는 잡, 잡이 꺼진 역할, 미설치, 잡 파일 읽기
   실패 넷에서 안내 문구가 화면에 없다(확인 필요 4번).
3. 명령 원문 다섯이 payload 값 그대로 화면에 있다. 픽스처 값을 알아볼 수 있게 바꿔 두고 그 값이
   나오는지 본다 — 화면이 조립하면 이 검사가 깨진다(R3).
4. 복사. 걸음마다 복사 버튼이 있고 누르면 `copy`가 그 걸음의 원문 그대로 불린다.
   `clipboard` mock은 이 파일 첫 `vi.mock`(`:31`~`:33`)에 이미 있다.
5. 복사 실패. `copy`가 거짓을 돌려주면 실패 문구가 뜨고 **원문은 화면에 그대로 남는다**(R1 셋째 줄).
6. 재시작 값이 `null`인 픽스처에서 명령이 그려지지 않고, 앱이 방법을 알지 못한다는 문구가 대신 온다.
   지어낸 라벨이 화면에 없다.
7. 두 역할이 동시에 084 경고를 받는 픽스처에서 한쪽의 복사 결과가 다른 쪽에 뜨지 않는다.
8. 버튼이 늘지 않는다. 안내에는 복사 버튼만 있고 갱신을 실행하는 버튼이 없다(R5). 마법사 단계 복사
   버튼 넷을 세는 기존 검사(`:2737`~`:2747`)가 **수정 없이** 통과한다.
9. 저장·재설정·"지금 실행" 버튼의 `disabled`가 안내 유무로 달라지지 않는다(R8).

## 완료 조건

괄호 안은 SPEC-034의 완료 조건 번호다.

1. 084 경고가 뜬 자리에서 갱신 절차를 읽을 수 있다. 다른 탭이나 외부 문서로 보내지 않는다.
   검증: 검사 1. (1)
2. 명령 원문마다 복사 수단이 있고, 복사에 실패해도 원문이 화면에 남는다. 검증: 검사 4·5. (2)
3. 안내가 084 문구와 모순되지 않는다. 검증: 두 문구를 나란히 보고서에 옮겨 적고, 안내가 원인을
   단정하지 않음을 밝힌다. (3)
4. 안내에 설치 경로·launchd 라벨·파이썬 환경이 사실처럼 적혀 있지 않다. 검증: 검사 6과, 컴포넌트
   문구 상수 전문을 보고서에 인용한다. (4)
5. 갈래 판별·pip 갈래·소스 갈래·재시작 넷이 모두 있고 명령을 하나로 단정하지 않는다.
   검증: 검사 3. (5)
6. 명령 문자열을 화면이 조립하지 않는다. 검증: 검사 3과, 컴포넌트에 문자열 결합·템플릿 리터럴로
   만든 명령이 없음을 보고서에 밝힌다. (6)
7. 재시작 걸음이 있고 라벨을 앱이 지어내지 않는다. 검증: 검사 6. (7)
8. 갱신을 실행하는 버튼이 없다. 검증: 검사 8. (8)
9. 안내가 상시로 뜨지 않는다. 검증: 검사 2. (승인된 확인 필요 4번)
10. 데몬 버전을 읽거나 보여주는 코드가 이 변경분에 없다. 검증: 변경분에 버전 조회·표시가 없음을
    보고서에 밝힌다. (11)
11. 설치 마법사의 문구·단계·상태가 그대로다. 검증: `heartbeat.setupStages`를 읽는 자리가 착수
    시점과 같음을 밝히고 검사 8을 인용한다. (9·12)
12. 어떤 버튼도 비활성화되지 않는다. 검증: 검사 9. (13)
13. 기존 자동 테스트가 삭제되거나 비활성화되지 않았다(`.skip`·`.todo` 신규 0건). 착수 시점
    `IntegrationsView.test.tsx`의 검사 개수를 세어 보고서에 적는다. (14)
14. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`이 통과한다. (15)
