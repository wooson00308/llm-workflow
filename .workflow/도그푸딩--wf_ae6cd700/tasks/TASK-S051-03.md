# Claude와 Codex CLI를 같은 실행 결과로 정규화한다

## 결정권자 요약

Claude와 Codex 명령행 도구가 같은 실행 계약과 종료 결과를 사용하도록 구현됐다.
설치와 로그인과 권한과 지원 버전 문제를 구분하고, 진행과 도구와 종료 정보를 공통 이벤트로 바꾼다.
사용자 QA 수정 요청에 따라 실행 중 프로세스 핸들을 추가했다.
실행을 시작하면 종료를 기다리지 않고 프로세스 식별자와 시작 시각과 이벤트 파일 위치를 돌려준다.
그 핸들만으로 실행 도중 취소할 수 있고, 취소는 자식 프로세스 종료를 확인한 뒤에만 성공으로 보고한다.
이벤트는 실행마다 별도 파일에 한 줄씩 쌓이므로 종료 뒤에도 마지막 위치부터 이어 읽을 수 있다.
작업 지시와 인증 정보는 실행 인자와 이벤트 기록과 결과에 남지 않는다.
전용 자동 검사 19건과 알려진 기존 격리 문제를 제외한 전체 회귀 검사를 통과했다.
사용자는 아래 확인 동선의 자동 검사 결과를 검토한 뒤 QA를 확정할 수 있다.

## 목적

Claude Agent SDK, Codex SDK, Codex App Server 없이 두 비대화형 CLI를 provider 구현으로 분리한다.
런타임의 dispatcher는 provider별 명령과 출력 형식을 알지 않고 공통 진단, 이벤트, 종료, 취소 계약만
사용한다.

## 실행 계약

### Claude

- 비대화형 실행은 `claude -p --output-format stream-json --verbose`를 사용한다. 모델이 설정됐을 때만
  `--model`을 추가한다.
- prompt는 표준 입력으로 전달하고 명령줄, 상태 데이터베이스, 일반 진단 로그에 적지 않는다.
- 설치·버전은 `claude --version`, 인증은 `claude auth status --json`의 종료 코드와 구조화 출력을
  사용한다.
- Claude Agent SDK를 import하거나 선택 경로로 두지 않는다.

### Codex

- 비대화형 실행은 `codex exec --json --sandbox workspace-write -C <project-root> -`를 사용한다.
  모델이 설정됐을 때만 `--model`을 추가한다.
- prompt는 표준 입력으로 전달한다. `--json`의 JSONL 이벤트 중 thread, turn, item, error와 usage를
  공통 이벤트로 정규화한다.
- 설치·버전은 `codex --version`, 인증은 `codex login status`의 종료 코드를 사용한다.
- Codex SDK와 App Server가 없어도 모든 경로가 동작해야 한다.

### 공통

- 명령은 셸을 거치지 않고 인자 배열로 시작한다. 작업 디렉터리는 설정의 실제 경로를 사용한다.
- 프로세스 그룹을 분리하고 취소·시간 초과 때 전체 트리를 종료한다. 종료를 확인하기 전에는 취소
  성공을 반환하지 않는다.
- 이벤트는 started, progress, tool, completed, failed, cancelled, timed_out와 provider 원문
  식별자를 담되 전체 prompt와 비밀값은 제외한다.
- stdout·stderr 파서가 깨진 한 줄을 만나도 프로세스 감시를 중단하지 않는다. 원문은 민감정보
  필터를 거친 실행 전용 로그에 남기고 결과는 off_contract로 구분한다.

## 진단 상태

provider 진단은 최소한 다음 상태를 구분한다.

- ready
- executable_missing
- login_required
- permission_denied
- unsupported_version
- billing_route_acknowledgement_required
- unavailable

Claude 프로세스에 `ANTHROPIC_API_KEY`처럼 API 과금 경로를 바꿀 수 있는 환경 변수가 상속될 때는
변수의 존재와 과금 경로 위험만 알리고 값을 읽거나 저장하지 않는다. 사용자가 실행 요청에서 그 위험을
명시적으로 확인하기 전에는 Claude를 시작하지 않는다. Codex와 Claude의 저장된 CLI 인증은 각 CLI가
소유하며 런타임은 토큰 파일을 열지 않는다.

## 손대지 않는 것

- 역할 후보 판정, lease, 큐 공정성
- 프로젝트 설정과 실행 이력 스키마
- 운영체제 서비스와 패키징
- 앱 화면과 Tauri 명령
- Dream provider

## 완료 조건

1. Claude와 Codex provider가 같은 진단·시작·이벤트·취소·종료 인터페이스를 구현한다.
2. Claude 명령은 비대화형 stream JSON 출력만 사용하고 Agent SDK를 import하지 않는다.
3. Codex 명령은 `codex exec --json`을 사용하고 SDK·App Server를 요구하지 않는다.
4. provider와 model 값은 고정 인자 배열에만 들어가며 prompt는 표준 입력으로 전달된다.
5. CLI 미설치, 로그인 필요, 권한 부족, 지원하지 않는 버전이 서로 다른 진단 상태로 나온다.
6. Claude API 과금 경로 환경 변수가 있으면 값은 노출하지 않은 채 확인 필요 상태가 되고, 확인 없는
   실행은 프로세스를 만들지 않는다.
7. 성공, 일반 실패, 사용 제한, 시간 초과, 사용자 취소, 계약 밖 출력이 서로 다른 종료 결과다.
8. 취소와 시간 초과 뒤 자식 프로세스가 남지 않는다.
9. 두 provider의 구조화 이벤트에서 프로젝트, 역할, 대상, 시작 시각, 경과 시간, 진행 상태를 만들 수
   있다.
10. 상태 저장소와 일반 로그에 인증 토큰, API 키, 전체 prompt가 남지 않는다.
11. provider 하나만 설치된 환경에서는 설치된 provider만 ready이며 다른 provider의 실패가 실행
   가능한 쪽을 막지 않는다.
12. 기존 Claude Heartbeat 잡 실행 검사가 변경 전과 같이 통과한다.

## 검증 절차

1. 가짜 `claude`와 `codex` 실행 파일로 성공 JSONL, 실패, 깨진 줄, 느린 출력, 인증 실패를 재현한다.
2. 실행 인자와 표준 입력을 기록하는 가짜 실행 파일로 prompt가 명령줄에 없고 모델 인자만 조건부로
   붙는지 확인한다.
3. 자식 프로세스를 하나 더 만드는 가짜 provider를 취소하고 시간 초과시켜 전체 트리가 사라지는지
   확인한다.
4. 가짜 API 키와 토큰 문자열을 환경과 이벤트에 넣고 응답·상태·일반 로그에서 검색되지 않는지
   확인한다.
5. SDK 모듈이 설치되지 않은 격리 환경에서 두 provider 성공 픽스처를 실행한다.
6. `pytest tests/test_agent_providers.py -v`를 macOS·Linux·Windows에서 실행한다.
7. `pytest tests/ -v`를 실행한다.

## 확인 동선

화면 확인 대상은 없다. 이 작업은 provider 실행 계약과 프로세스 감시 로직만 바꾸므로 자동 검사
결과를 근거로 확인한다. QA 확정은 아래 숫자를 직접 확인한 뒤 그 결과를 신뢰한다는 뜻이다.

1. `claude-heartbeat` 저장소에서 `pytest tests/test_agent_providers.py -v`를 실행한다.
2. 19개 검사가 모두 통과하는지 확인한다. 기존 13건은 명령 인자·표준 입력·진단·구조화 이벤트·
   민감정보 제거·취소와 시간 초과 뒤 자식 프로세스 정리를 그대로 검증한다.
3. QA 수정 요청으로 추가한 6건은 다음 이름으로 확인한다.
   - `test_start_returns_a_running_handle_with_pid_start_time_and_event_file`: 실행이 끝나기 전에
     PID·시작 시각·이벤트 파일 경로를 담은 핸들이 돌아온다.
   - `test_start_failures_separate_the_diagnostic_stage_from_the_spawn_stage`: 진단 실패와 실행 파일
     생성 실패가 서로 다른 단계로 구분된다.
   - `test_watch_resumes_from_the_last_offset_and_withholds_a_partial_line`: 같은 offset 재요청이
     같은 결과를 내고, 완결되지 않은 마지막 줄은 노출되지 않는다.
   - `test_cancel_through_the_handle_stops_the_child_process_tree`: 핸들만으로 취소하면 손자
     프로세스까지 사라지고 종료 결과가 cancelled가 된다.
   - `test_event_file_never_contains_the_prompt_or_environment_secret`: 이벤트 파일과 핸들에서
     prompt와 가짜 API 키가 검색되지 않는다.
   - `test_cancelling_a_run_this_provider_does_not_own_is_not_reported_as_success`: 이 프로세스가
     시작하지 않은 실행의 취소는 성공으로 보고되지 않는다.
4. `pytest tests/ -q -k 'not test_parse_heartbeat_md_max_per_field'`를 실행해 193 passed, 7 skipped,
   1 deselected를 확인한다. 제외한 한 검사는 이번 범위 밖의 기존 jobs.d 격리 문제다.
