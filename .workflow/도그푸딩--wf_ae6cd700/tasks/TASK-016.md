# 쓰기 전 확인 화면을 값 나열에서 차이 표시로 전환

SPEC-005 R4를 구현한다. 확인 화면이 쓰게 될 값만 나열하는 현행을, 파일의 현재 값과 쓰게 될 값을 함께
보여주고 달라지는 값을 구분해 표시하는 형태로 바꾼다.

나열은 사용자가 파일의 현재 값을 외우고 있을 때만 검증 수단이 된다. 관측된 사고에서는 확인 화면을
지나갔는데도 아무도 알아채지 못했다.

## 의존성

- **선행 필수: TASK-014.** "쓰게 될 값"이 미지정 필드에 대해 파일 값으로 해석된다는 계약이 먼저 있어야
  이 화면이 사실을 보여준다.
- **선행 권장: TASK-015.** 관리 블록을 못 읽은 상태에서는 "파일의 현재 값"이 없다. TASK-015가 그
  상태의 저장을 막아 두면 이 작업이 그 경우를 따로 처리하지 않아도 된다. 순서를 뒤집는다면 못 읽은
  상태에서 확인 화면을 어떻게 그릴지 이 작업이 정해야 한다.
- TASK-017·TASK-018과 병행 금지. 두 작업 모두 여기서 만드는 차이 표시를 재사용한다.

## 범위

- `src-tauri/src/application/heartbeat_service.rs` — 관리 블록 잡의 앱 소유 필드가 앱 값과 다른지
  판정해 스냅샷에 담는다.
- `src/features/projects/domain/types.ts` — 위 값의 프론트 짝.
- `src/features/projects/components/integrations/` — 잡별 차이 표시 요소. 두 카드가 함께 쓰므로
  카드 파일이 아니라 이 디렉터리 안의 공용 자리에 둔다.
- `src/features/projects/components/integrations/HeartbeatCard.tsx`,
  `src/features/projects/components/integrations/DreamCard.tsx` — 확인 화면 본문.
- `src/features/projects/components/SettingsView.test.tsx`,
  `src/features/projects/components/integrations/DreamCard.test.tsx`, 필요하면 새 요소 전용 테스트.
- 스타일이 필요하면 기존 확인 화면 클래스(`heartbeat-confirm`)가 있는 스타일시트에만 더한다.
- 그 외 파일은 건드리지 않는다.

## 작업 내용

### 0. 먼저 읽을 제약

- 확인 절차 자체는 그대로다(SPEC-002 R6). 확인 없이 쓰는 경로를 만들지 않고, 확인 단계를 건너뛰는
  옵션도 만들지 않는다. 이 작업은 그 화면에 담기는 정보만 바꾼다.
- 확인 화면의 접근성 이름을 바꾸지 않는다. 기존 테스트가 `역할 잡 설치 확인`·`dream 잡 설치 확인`으로
  이 영역을 찾는다.
- 대상 파일 경로 안내(`~/.claude/HEARTBEAT.md`가 전역 파일이라는 문구, 조건 스크립트 경로)와 "관리 블록만
  다시 쓴다"는 문구는 그대로 남긴다. 지금 있는 정보를 빼는 작업이 아니다.
- 앱 소유 필드를 사용자 편집값으로 보존하지 않는다. 이 작업은 되돌아간다는 사실을 밝히기만 한다.
  기획서 제외 범위다.

### 1. 잡별 차이 표시 (R4)

- 확인 화면은 잡마다 편집 가능 값 세 개(`interval`·`maxPer`·`model`)에 대해 파일의 현재 값과 쓰게 될
  값을 함께 보여준다.
- 달라지는 값을 구분해 표시한다. 값이 텍스트로 읽혀야 한다. 색만으로 구분하지 않는다.
- 파일에 그 잡이 없으면(새로 설치되는 잡) 현재 값 자리에 "없음"에 해당하는 표시를 두고, 잡이 새로
  추가된다는 사실이 읽히게 한다.
- 아무 값도 달라지지 않으면 그 사실을 밝힌다. 파일이 바뀌지 않는다는 것을 사용자가 확인 화면에서 알 수
  있어야 한다.
- 표시 요소는 하트비트와 dream이 함께 쓴다. 잡 종류를 알지 못하는 형태로 만든다. 두 카드가 각자 만들면
  같은 화면이 갈라진다.

### 2. 앱 소유 필드가 되돌아간다는 고지 (R4)

- 관리 블록 안 잡의 앱 소유 필드(`prompt`, `timeout`, `condition`, `notify`, `slug`)가 앱이 다시 쓸 값과
  다르면, 그 필드가 앱 값으로 되돌아간다는 사실을 확인 화면에 밝힌다. 어느 필드인지 이름이 보여야 한다.
- 판정은 백엔드가 한다. 앱이 쓸 잡은 `role_managed_jobs`·`heartbeat_dream::dream_job_with`가 만들고,
  파일의 잡은 `parse_heartbeat`가 준다. 두 값을 필드 단위로 대조해 다른 앱 소유 필드 이름을 모아
  `ManagedRoleJob`·`ManagedDreamJob`에 담는다. 편집 가능 세 필드는 대조에서 뺀다.
- 화면이 원문 값을 다시 조립해 비교하지 않는다. 화면이 앱 소유 필드의 값을 알아야 할 이유가 없고,
  잡 정의가 바뀌면 두 곳이 갈라진다.
- 값 자체는 보여주지 않아도 된다. 요구는 "되돌아간다는 사실"과 그 대상이다.

### 3. 잡이 제거되는 경우의 고지 (R4)

- 토글을 끈 잡은 관리 블록에서 사라진다. 확인 화면의 제거 목록에 그 잡의 현재 편집값과, 그 값이 함께
  사라진다는 사실을 함께 적는다.
- 지금은 필드 옆 안내 문구(`HeartbeatCard.tsx:326`, `DreamCard.tsx:318`)에만 있어 확인 단계에서 다시
  보이지 않는다. 그 안내 문구는 그대로 두고 확인 화면에 더한다.
- 활성 역할이 하나도 없어 관리 블록 전체를 제거하는 경우의 현행 문구도 유지하되, 사라지는 잡들의 값이
  함께 보여야 한다.

### 4. 테스트

- 한 필드만 바꿨을 때 확인 화면에 그 필드가 달라지는 것으로, 나머지 두 필드가 그대로인 것으로 표시된다.
  역할 잡과 dream 잡 각각.
- 아무 값도 바꾸지 않고 확인 화면을 열면 파일이 바뀌지 않는다는 사실이 표시된다.
- 관리 블록에 없던 잡을 켜면 확인 화면에 새로 추가되는 잡으로 표시된다.
- 앱 소유 필드가 앱 값과 다른 스냅샷에서 확인 화면에 되돌아갈 필드 이름이 표시된다.
- 편집값이 있는 잡을 끄면 확인 화면에 그 값과 함께 사라진다는 사실이 표시된다.
- 백엔드: 관리 블록의 `timeout`을 앱 값과 다르게 적어 둔 문서에서 스냅샷의 해당 잡에 그 필드 이름이
  담긴다. 손대지 않은 문서에서는 비어 있다.

## 완료 조건

1. 확인 화면에 잡별 현재 값과 쓰게 될 값의 차이가 표시된다. (기획서 완료 조건 8 앞부분)
2. 달라지는 것이 없으면 그 사실이 표시된다. (기획서 완료 조건 8 뒷부분)
3. 관리 블록 안의 앱 소유 필드를 손으로 고친 상태에서 저장하면, 그 필드가 앱 값으로 되돌아간다는
   사실이 확인 화면에 표시된다. (기획서 완료 조건 9)
4. 잡을 끄고 저장할 때 그 잡의 편집값이 함께 사라진다는 사실이 확인 화면에 표시된다.
   (기획서 완료 조건 10)
5. 차이 표시가 하트비트 카드와 dream 카드에서 같은 요소로 동작한다. 두 카드 각각에 대한 테스트가 있고
   통과한다.
6. 확인 절차와 확인 화면의 접근성 이름이 그대로다. 확인 없이 쓰는 경로가 생기지 않았다.
7. 같은 상태로 다시 저장하면 파일이 변하지 않는다. (기획서 완료 조건 13)
8. SPEC-002·SPEC-003·SPEC-004의 완료 조건에 대응하는 기존 자동화 테스트가 모두 통과하고, 삭제되거나
   비활성화된 케이스가 없다. (기획서 완료 조건 16)
9. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`이 통과한다.
   (기획서 완료 조건 17)

```sh

# 2) 개발자 잡의 주기만 바꾸고 저장 버튼 → 그 줄만 달라지는 것으로 보여야 한다
# 3) 관리 블록 안 개발자 잡의 `- timeout: 30m`을 `- timeout: 5m`으로 손수 바꾼다
#    → 확인 화면에 timeout이 앱 값으로 되돌아간다는 사실이 보여야 한다
# 4) 편집값이 있는 잡의 토글을 끈다 → 확인 화면에 그 값과 함께 사라진다는 사실이 보여야 한다
# 위 확인은 모두 "취소"로 끝낸다. 아무것도 쓰지 않는다.
diff /tmp/HEARTBEAT.md.bak ~/.claude/HEARTBEAT.md   # 비어 있어야 한다
```

## 참고 사실

확인 시점 2026-08-02. 추정 없이 실측한 값이다.

- 역할 잡 확인 화면은 `HeartbeatCard.tsx:359`, dream은 `DreamCard.tsx:349`다. 접근성 이름은 각각
  `역할 잡 설치 확인`, `dream 잡 설치 확인`이다.
- 지금 쓰게 될 값만 나열하는 줄은 `HeartbeatCard.tsx:371`
  (`기록: wf-{role}{slug} — {interval} · {maxPer} · {model}`)와 `DreamCard.tsx:359`다.
- 제거 목록은 `HeartbeatCard.tsx:378`(`제거: ...`)과 `DreamCard.tsx:362`다. 값은 적히지 않는다.
- 잡을 끌 때의 안내는 필드 아래 `HeartbeatCard.tsx:326`, `DreamCard.tsx:318`에만 있다. 확인 단계에서는
  다시 보이지 않는다.
- 파일의 현재 값은 스냅샷의 `heartbeat.managedJobs`(`types.ts:111`)와 `dream.managedJob`(`:119`)에
  이미 있다. 세 필드 모두 `string | null`이고 `null`은 "그 줄이 블록에 없음"이다.
- 앱이 쓸 잡은 `heartbeat_roles.rs:86`의 `role_managed_jobs`와 `heartbeat_dream::dream_job_with`가
  만든다. 앱 소유 필드는 `prompt`·`timeout`·`condition`·`notify`·`slug` 다섯이다.
- 파일의 잡 필드는 `parse_heartbeat`의 `job.field("...")`로 읽는다
  (`heartbeat_service.rs:446` 참고).
- 실제 `~/.claude/HEARTBEAT.md`의 역할 잡 `max_per`는 `8/24h`·`8/24h`·`16/24h`다. 검증 중 원복을
  빠뜨리면 이 저장소의 하트비트 구성이 망가진다.
