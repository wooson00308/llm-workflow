# 활동 전용 뷰를 신설하고 지금 작업 중 워커와 배너 입구를 만든다

SPEC-011의 R1·R2·R3·R4를 구현한다. 사이드바에 "활동" 메뉴와 전용 뷰를 만들고, 그 뷰의 "지금 작업 중"
섹션이 활성 lease를 빠짐없이 카드로 그린다. 오늘 화면의 배너는 요약으로 남기고 이 뷰로 가는 입구를
단다.

"최근 활동" 피드는 TASK-034다. 이 작업은 뷰 골격과 위쪽 섹션까지다.

## 의존성

- **선행: TASK-032.** 카드가 그려야 하는 `heartbeatAt`·`role`이 그 작업에서 화면까지 내려온다. 값이
  없으면 이 작업의 완료 조건 대부분을 만족할 수 없다.
- **TASK-034와 병행 금지.** 둘 다 `ActivityView.tsx`와 `App.css`를 만진다. 순서는 이 작업이 먼저다
  (TASK-034가 이 작업이 만든 뷰 안에 섹션을 더한다).
- **SPEC-009 계열 TASK-030(아직 `todo`)과 병행 금지.** `WorkspaceShell.tsx`와 `App.css`가 겹친다.
  순서는 어느 쪽이 먼저여도 된다.

## 범위

- `src/features/projects/components/ActivityView.tsx` — 새 파일.
- `src/features/projects/components/ActivityView.test.tsx` — 새 파일.
- `src/features/projects/components/WorkspaceShell.tsx` — 뷰 키·사이드바 메뉴·breadcrumb 라벨·배너.
- `src/features/projects/components/WorkspaceShell.test.tsx` — 메뉴·배너 테스트.
- `src/shared/ui/Icon.tsx` — 활동 메뉴 아이콘 하나.
- `src/App.css` — 활동 뷰와 배너 스타일.
- 그 외 파일은 건드리지 않는다. 특히 백엔드(`src-tauri/`)와 `domain/types.ts`는 이 작업에서 바뀌지
  않는다. `DevelopmentBoard.tsx`도 건드리지 않는다.

## 작업 내용

### 0. 먼저 읽을 제약

- **화면은 읽기 전용이다**(R8). 이 뷰에 쓰기 액션을 넘기지 않는다. props로 받는 것은 프로젝트 스냅샷과
  이동 콜백뿐이고, 그 콜백은 뷰 전환만 한다.
- **새 폴링을 만들지 않는다**(R8, 기획서 완료 조건 27). `setInterval`·`setTimeout`을 쓰지 않는다.
  남은 시간은 렌더 시점에 계산하고, 2.5초 주기 조회가 다시 렌더할 때 값이 갱신된다.
- **파일에 없는 값을 만들어 채우지 않는다**(R3, 기획서 완료 조건 9). 최초 시작 시각을 표시하지 않고
  "몇 분째 작업 중"을 추정하지 않는다. `heartbeatAt`을 시작 시각으로 부르는 문구를 쓰지 않는다.
- **역할은 값이 있을 때만 보여준다**(기획서 완료 조건 31). `agent` 문자열에서 역할을 잘라내지 않는다.
- 배너는 요약으로 남는다(R2). 워커 목록을 배너에서 펼치지 않는다.

### 1. 뷰 키와 사이드바 메뉴 (R1)

`WorkspaceShell.tsx`에서 세 자리를 고친다.

- `view` 상태의 유니온에 `"activity"`를 더한다(`:105`).
- `viewLabels`(`:71`)에 `activity: "활동"`을 더한다. breadcrumb이 `viewLabels[view]`를 쓰므로 이 한 줄이
  기획서 완료 조건 2를 만족시킨다. 위치는 `archive` 다음이다.
- `primary-nav`(`:230`)의 "기록" 버튼 **다음에** "활동" 버튼을 둔다. 선택 표시는 다른 메뉴와 같은
  `className={view === "activity" ? "active" : ""}` 규칙을 쓴다.

아이콘은 `Icon.tsx`에 `activity` 하나를 더해 쓴다. 기존 아이콘 목록에 활동을 뜻하는 것이 없고,
`spark`는 이미 "오늘"과 "연동"이 쓰고 있어 세 메뉴가 같은 그림이 된다. 맥박선 형태의 `path` 한 줄이면
충분하다.

렌더는 워크플로우와 무관한 화면(`integrations`) 옆에 둔다. 위 섹션이 프로젝트 전역이라 워크플로우가
없어도 그릴 것이 있다.

```tsx
{view === "activity" && (
  <ActivityView
    onOpenDocument={(result) => void openSearchResult(result)}
    project={project}
    workflow={workflow}
  />
)}
```

### 2. 배너를 입구로 만든다 (R2)

지금 배너(`:316`~`:322`)는 `div`이고 누를 곳이 없다. 이것을 누를 수 있는 요소로 바꾸고 활동 뷰를 연다.

- 구성은 유지한다: 대표 한 명의 `agent`, `taskId ?? "워크플로우 작업"`, "마이그레이션 보호 활성" 문구,
  `{n} active` 뱃지.
- 여기에 "자세히 보기" 같은 입구 표시를 더한다. 누르면 활동 뷰가 열린다는 사실이 문구로 읽혀야 한다.
  아이콘만으로 알리지 않는다.
- 배너 전체를 `button`으로 바꾼다. 안에 다른 누를 수 있는 요소를 넣지 않으므로 중첩 문제가 없고,
  키보드 조작(R9)이 따로 붙이는 것 없이 성립한다.
- 대표를 고르는 기준은 지금 그대로 `activeLeases[0]`이다. 백엔드가 `expires_at` 오름차순으로 정렬해
  내려보내고 카드 목록도 같은 배열을 순서대로 그리므로, 배너의 대표와 뷰의 첫 카드가 같은 lease를
  가리킨다(기획서 완료 조건 5). 뷰에서 목록을 다시 정렬하지 않는다.
- 활성 lease가 없으면 배너는 지금처럼 나타나지 않는다(기획서 완료 조건 4). 빈 상태는 전용 뷰가
  책임진다.

### 3. "지금 작업 중" 섹션 (R3)

`ActivityView`가 받는 props는 셋이다.

```tsx
interface Props {
  onOpenDocument(result: {
    item: WorkflowItemSummary;
    kind: SearchItemKind;
    workflow: WorkflowSummary;
  }): void;
  project: ProjectSummary;
  /** 선택된 워크플로우. 문서 해석의 우선순위에 쓴다. 없을 수 있다. */
  workflow: WorkflowSummary | undefined;
}
```

- `project.activeLeases`를 **전부** 카드로 그린다. 개수를 자르지 않는다(기획서 완료 조건 6).
- 목록은 `ul`/`li`로 그리고 섹션에 제목을 둔다(R9, 기획서 완료 조건 29).
- 카드 하나가 보여주는 값:
  - 에이전트 이름(`agent`).
  - 역할. `role`이 `planner`·`architect`·`developer`면 각각 "기획자"·"아키텍트"·"개발자"로 부른다.
    그 밖의 값은 원문 그대로 보여준다 — 계약을 어긴 세션을 드러내는 것이 이 화면의 목적이라 앱이
    모르는 값을 숨기지 않는다. `null`이면 역할 칸 자체를 그리지 않는다.
  - 붙잡은 문서(아래 4번).
  - 마지막 심장박동 시각. `heartbeatAt`을 로컬 시각으로 표시하고, 라벨에 "마지막 심장박동"처럼 그것이
    무엇인지 적는다. "시작"이라고 부르지 않는다.
  - 만료까지 남은 시간. `expiresAt - 지금`을 분 단위로 표시한다. 1분 미만이면 "1분 미만 남음",
    0 이하이면 "곧 만료"로 적는다(주기 조회 사이에 만료가 지나갈 수 있다). 이 값에 `aria-live`를
    붙이지 않는다 — 주기적으로 바뀌는 값이 보조 기술에 반복해 읽히면 안 된다(R9).
- 활성 lease가 하나도 없으면 "지금은 조용합니다"에 해당하는 빈 상태를 그린다. 빈 목록 껍데기를 남기지
  않는다(기획서 완료 조건 10).
- 읽지 못한 lease는 애초에 배열에 없다. 화면은 받은 것만 그리고 그 사실로 섹션을 비우거나 오류를 내지
  않는다(기획서 완료 조건 11의 화면 몫).

### 4. 붙잡은 문서를 이름으로 말한다 (R4)

`taskId`를 프로젝트 안의 문서로 해석하는 함수를 `ActivityView.tsx` 안에 둔다.

```tsx
function resolveTarget(project: ProjectSummary, selected: string | undefined, id: string):
  { item: WorkflowItemSummary; kind: SearchItemKind; workflow: WorkflowSummary } | null
```

- 찾는 순서는 **선택된 워크플로우 먼저, 그다음 `project.workflows` 등록 순서**다. 문서 번호는
  워크플로우마다 따로 매겨져서 `SPEC-001`이 여러 워크플로우에 동시에 있을 수 있다. 순서를 정하지 않으면
  같은 화면이 조회 때마다 다른 워크플로우를 가리킬 수 있다.
- 한 워크플로우 안에서는 `ideas` → `specs` → `tasks` 순으로 본다. 식별자 접두사가 달라 실제로 겹치지
  않지만 순서를 고정해 둔다.
- 해석되면 문서 종류(아이디어·기획서·개발 작업)와 제목을 함께 보여주고, 그 문서가 속한 워크플로우
  이름도 카드에서 읽히게 한다(기획서 완료 조건 13). lease는 프로젝트 전역이라 선택하지 않은
  워크플로우의 워커도 이 목록에 들어온다.
- 해석되지 않으면(결정 문서를 물었거나 문서가 사라진 경우) 식별자만 보여주고 누를 수 있는 요소를 만들지
  않는다(기획서 완료 조건 14).
- `taskId`가 `null`이면 배너와 같은 문구 "워크플로우 작업"을 쓴다(기획서 완료 조건 15).
- 이동은 `onOpenDocument`로 넘긴다. `WorkspaceShell`이 그것을 `openSearchResult`(`:193`)에 연결하므로
  프로젝트 검색과 같은 경로가 된다(R4 마지막 항목). 활동 뷰가 자기만의 이동 규칙을 만들지 않는다.

### 5. 스타일

`App.css`에 활동 뷰 스타일을 더한다. 기존 파일의 한 줄 규칙 표기를 따른다.

- 배너(`.agent-activity`, `:155`~`:161`)는 `button`이 되므로 `border`·`background`·`text-align`·`cursor`를
  버튼 기본값 위에 다시 적어야 지금 모습이 유지된다. 색과 여백 값은 바꾸지 않는다.
- 워커 카드·빈 상태 클래스를 새로 만든다. 사건 색만으로 뜻을 만들지 않는다(R9).

### 6. 테스트

`ActivityView.test.tsx`:

- lease 셋 이상인 스냅샷에서 카드가 lease 수만큼 그려진다. (기획서 완료 조건 6)
- 카드 하나에 에이전트 이름·붙잡은 문서·마지막 심장박동 시각·남은 시간 네 값이 모두 나타난다.
  (기획서 완료 조건 7)
- 화면 어디에도 최초 시작 시각이 없고 심장박동이 "시작"으로 불리지 않는다. (기획서 완료 조건 9)
- `role`이 `architect`면 "아키텍트"가 보이고, `role`이 `null`인 lease는 역할 칸 없이 정상으로 그려진다.
  계약 밖 값(`"reviewer"`)은 원문 그대로 보인다. (기획서 완료 조건 31의 화면 몫)
- 활성 lease가 없으면 빈 상태 문구가 보이고 목록이 없다. (기획서 완료 조건 10)
- 아이디어·기획서·개발 작업을 각각 물고 있는 lease에서 문서 종류·제목이 보이고, 눌렀을 때
  `onOpenDocument`가 그 문서와 종류로 호출된다. (기획서 완료 조건 12)
- 워크플로우가 둘인 스냅샷에서 다른 워크플로우의 문서를 문 lease가 그 워크플로우 이름을 보여준다.
  같은 id가 두 워크플로우에 있으면 선택된 워크플로우 쪽으로 해석된다. (기획서 완료 조건 13)
- 존재하지 않는 문서 id(`DECISION-XXXX`)를 문 lease는 식별자만 보이고 누를 수 있는 요소가 없다.
  (기획서 완료 조건 14)
- `taskId`가 `null`이면 "워크플로우 작업"이 보인다. (기획서 완료 조건 15)
- 남은 시간은 고정된 시스템 시각(`vi.setSystemTime`)으로 검증한다. 렌더 후 `vi.getTimerCount()`가
  `0`이다 — 이 뷰는 자기 타이머를 만들지 않는다. (기획서 완료 조건 27의 화면 몫)
- 렌더와 카드 조작으로 호출되는 콜백은 `onOpenDocument`뿐이다. 쓰기 액션 props가 없다는 것을 타입과
  테스트가 함께 고정한다. (기획서 완료 조건 25·26의 화면 몫)

`WorkspaceShell.test.tsx`:

- 사이드바의 "활동"을 누르면 활동 뷰가 열리고 breadcrumb에 "활동"이 보인다.
  (기획서 완료 조건 1·2)
- 활성 lease가 있는 프로젝트에서 배너의 입구를 누르면 활동 뷰가 열린다. (기획서 완료 조건 3)
- 활성 lease가 없으면 배너가 없다. (기획서 완료 조건 4)
- 활성 lease가 둘 이상일 때 배너가 가리키는 에이전트와 활동 뷰 첫 카드의 에이전트가 같다.
  (기획서 완료 조건 5)
- 기존 메뉴 테스트가 수정 없이 통과한다.

## 완료 조건

1. 사이드바에 "활동" 메뉴가 있고, 주요 메뉴의 마지막(기록 다음)이며, 선택하면 전용 뷰가 열리고 선택
   상태가 표시된다. (기획서 완료 조건 1)
2. breadcrumb이 활동 뷰에서 "활동"을 보여준다. (기획서 완료 조건 2)
3. 오늘 화면 배너에서 활동 뷰로 갈 수 있고 그 입구가 문구로 읽힌다. (기획서 완료 조건 3)
4. 활성 lease가 없으면 배너가 나타나지 않는다. (기획서 완료 조건 4)
5. 배너의 대표 워커와 전용 뷰의 첫 카드가 같은 lease를 가리킨다. (기획서 완료 조건 5)
6. 활성 lease가 여럿이면 전부 카드로 그려진다. (기획서 완료 조건 6)
7. 각 카드가 에이전트 이름·붙잡은 문서·마지막 심장박동 시각·남은 시간을 보여준다.
   (기획서 완료 조건 7)
8. 추정으로 채운 값이 화면에 없다. (기획서 완료 조건 9)
9. 활성 lease가 없으면 빈 상태가 보인다. (기획서 완료 조건 10)
10. `taskId` 해석 성공·실패·없음 세 경우가 각각 이동 가능·식별자만·"워크플로우 작업"으로 그려진다.
    (기획서 완료 조건 12·14·15)
11. 해석된 문서의 워크플로우 이름이 카드에서 보인다. (기획서 완료 조건 13)
12. 이동이 프로젝트 검색과 같은 경로를 쓴다. (R4)
13. 역할 값이 있으면 보이고 없으면 칸이 비며, 값이 없는 lease도 정상으로 그려진다.
    (기획서 완료 조건 31의 화면 몫)
14. 활동 뷰가 파일을 쓰지 않고 새 타이머를 만들지 않는다. (기획서 완료 조건 25·26·27의 화면 몫)
15. 메뉴·배너 입구·워커 카드를 키보드로 조작할 수 있고 목록 구조가 보조 기술에 드러난다.
    (기획서 완료 조건 29의 이 작업 몫)
16. `npm run check`가 통과하고 기존 프론트엔드 테스트가 수정 없이 통과한다. (기획서 완료 조건 32)

## 검증 절차

```sh

```

- "최근 활동" 피드와 그에 딸린 잘림·빈 상태 고지. TASK-034다.

- 읽지 못한 lease 파일이 있다는 사실을 알리는 것. 기획서가 다루지 않았다.

  제외 범위다.
