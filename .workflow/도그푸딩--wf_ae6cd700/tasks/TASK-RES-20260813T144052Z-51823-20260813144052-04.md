# 첫 실행 행동 앞에 동의 관문을 두고 동의 상태와 철회를 화면에 붙인다

## 결정권자 요약

### 제안

프로젝트에서 처음으로 자동 배정을 켜거나 직접 배정을 확정할 때 실행 권한 고지를 보여 주고, 사용자가
직접 선택한 동의를 받은 뒤에만 그 행동을 이어 간다.

### 현재

동의 관문과 고지와 철회는 에이전트 화면 안에 모두 구현되어 있다. 다만 이 화면들은 사용자가 왼쪽 메뉴의
에이전트를 눌러야 열리므로, 자동 배정을 이미 켜 둔 기존 사용자는 동의를 요구받는 자리를 만나지 못한다.

### 변경 후

두 행동의 마지막 확인 안에 같은 고지와 확인 항목이 놓인다. 자동 배정을 이미 켜 둔 프로젝트를 열면
처음 보이는 화면에서 바로 동의 필요를 알리고 그 자리에서 동의를 받는다. 동의한 뒤에는 역할이나 실행
도구가 바뀌어도 다시 묻지 않고, 고급 설정에서 동의 상태를 보고 철회할 수 있다.

### 사용자 결과

사용자는 처음 실행하기 전에 무엇을 허용하는지 읽고 스스로 고른다. 취소하면 아무것도 시작되지 않고,
동의가 필요한 상태는 설치 필요나 로그인 필요와 다른 안내로 구분되어 보인다. 자동 배정을 이미 켜 둔
사용자는 에이전트 화면을 찾아 들어가지 않아도 세션이 멈춘 이유를 알고 그 자리에서 동의할 수 있다.

### 영향 범위

- 변경: 자동 배정 켜기와 직접 배정 시작의 마지막 확인, 프로젝트를 연 직후 화면의 동의 필요 알림,
  고급 설정의 동의 상태와 철회, 시작하지 못한 이유의 표시
- 유지: 여러 유료 세션 확인과 과금 경로 확인, 기획 승인과 품질 확인 관문, 실행 취소와 일시 정지

### 비용과 위험

동의는 필수 전제를 이해했다는 기록이지 권한을 줄이는 장치가 아니다. 고지가 실제 권한보다 좁게 읽히면
사용자는 잘못된 기대를 갖게 되므로, 다섯 가지 사실을 빠짐없이 한 화면에 담는다.

### 결정 요청

동의 기록이 없는 프로젝트에서 자동 배정을 켜고 직접 배정을 시작할 때 고지와 동의를 먼저 만나는지,
동의한 뒤에는 다시 묻지 않는지, 고급 설정에서 동의 상태를 보고 철회할 수 있는지를 확인한다. 자동
배정을 켜 둔 채 동의를 철회하고 프로젝트를 다시 열었을 때, 왼쪽 메뉴를 누르지 않아도 첫 화면에서
동의 필요를 보고 그 자리에서 동의할 수 있는지도 함께 확인한다.

## 범위 사전 검사

이 작업이 다루는 값은 둘이다. 백엔드가 설정 조회에 실어 주는 동의 상태가 화면까지 오는 경로와, 실행
환경이 동의 부족으로 시작을 거절했다는 사실이 화면까지 오는 경로다. 두 경로를 앱의 현재 코드에서
확인했다.

- 값 경로: 완료 조건 1·5·6의 동의 상태는 앞 작업이 설정 조회 응답에 실어 준다. 앱 안에서 그 값이 처음
  들어오는 자리는 `src/features/projects/infrastructure/tauriProjectGateway.ts`의
  `readAgentRuntimePolicy`인데, 이 함수는 응답을 통째로 그대로 돌려주므로 값을 고르지 않는다. 값이
  사라지는 자리는 `src/features/projects/domain/types.ts`의 `AgentPolicySnapshot`이다. 이 인터페이스에
  대응 필드가 없으면 화면이 값을 읽을 수 없으므로 여기를 편집한다. 그다음
  `src/features/projects/application/useProjectWorkspace.ts`가 그 응답을 `agentRuntime.policy`에 그대로
  담고, `src/features/projects/components/agents/AgentRuntimeView.tsx`가 그 값을 읽어 자동 배정 토글과
  고급 설정을 그리며, `src/features/projects/components/agents/AgentRunDashboard.tsx`가 직접 배정
  대화상자를 그린다. 세 파일 모두 편집한다.
- 값 경로: 완료 조건 1·3·7의 동의와 철회 호출은 반대 방향이다. 화면이 부르는 자리는
  `AgentRuntimeView.tsx`와 `AgentRunDashboard.tsx`이고, 두 화면이 함께 쓰는 동작 묶음은 `types.ts`의
  `AgentRuntimeActions`에 선언되며 실제 구현은 `useProjectWorkspace.ts`에 있고, 실행 환경까지 가는
  마지막 자리는 `tauriProjectGateway.ts`다. 네 파일 모두 편집한다. 앞 작업이 만든 두 커맨드가 이미
  등록돼 있으므로 그 아래로는 편집할 자리가 없다.
- 값 경로: 완료 조건 8의 동의 부족 표시는 실행 환경의 응답에서 온다. 직접 배정 시작의 응답은
  `types.ts`의 `AgentRunStartOutcome`에 이미 대기 목록 자리가 있지만 값의 모양이 정해져 있지 않고,
  `useProjectWorkspace.ts`의 `startAgentRun`은 지금 시작 목록이 비어 있어도 성공으로 보고 대화상자를
  닫는다. 그래서 두 파일을 편집해 대기 사유를 화면이 읽을 수 있게 한다. 재시도의 동의 부족은 실패

- 값 경로: 완료 조건 4의 고지 문구와 그 버전은 이 작업이 새로 만든다. 문구와 버전 상수는

  파일에 흩어지면 어떤 문구에 동의했는지가 기록과 어긋난다. 직접 배정 대화상자는 같은 상수를 읽어

## 현재 상태

에이전트 화면의 자동 배정 스위치를 켜면 참여 역할을 고르는 확인 화면이 열리고, 확인하면 정책이 저장돼
자동 배정이 켜진다. 직접 배정은 역할과 대상을 고른 뒤 시작 조건을 확인하고 배정을 시작한다. 고급 설정은
역할 정책, 실행 환경 상태, 실행 도구 진단, 기존 설정 이전을 보여 준다. 세 곳 어디에도 실행 권한 고지와
동의 상태는 없다.

앞선 세션이 완료 조건 1부터 12까지를 구현했고 자동 검사도 함께 남겼다. 다만 동의를 요구하는 자리가
모두 에이전트 화면 안에 있어서, 자동 배정을 이미 켜 둔 사용자는 왼쪽 메뉴에서 에이전트를 누르기 전에는
동의 요구를 만나지 못한다. 프로젝트를 열었을 때 처음 보이는 화면에는 동의 관련 표시가 하나도 없고,
그 화면을 그리는 `src/features/projects/components/WorkspaceShell.tsx`는 동의 상태를 읽지 않는다.

## 변경 범위

1. 설정 조회 응답의 동의 값을 화면 타입에 더한다. 필드 이름은 앞 작업이 고정한 다섯 개를 그대로 쓴다.
   상태 값은 `granted`, `required`, `unsupported`, `unreadable` 넷이다.
2. 동의와 철회를 부르는 동작을 화면 동작 묶음에 더하고 호출 계층에 구현한다. 성공하면 설정을 다시 읽어
   화면의 동의 상태를 최신으로 만든다.
3. 고지 문구와 고지 버전 상수를 한 자리에 만든다. 첫 버전은 1이며 실행 환경이 요구하는 버전과 같다.
   문구에는 다음 다섯 가지가 모두 들어간다.
   - 역할 세션은 앱을 닫아도 백그라운드에서 병렬로 동작할 수 있다.
   - 세션은 작업마다 다시 묻지 않고 파일을 읽고 만들고 수정하거나 삭제하며 명령을 실행할 수 있다.
   - 세션은 운영체제 사용자 계정과 실행 도구가 허용하는 네트워크와 인증 환경을 사용할 수 있다.
   - 이 권한은 에이전트 기능의 필수 전제이며 제한 모드는 제공하지 않는다.
   - 사용자 승인과 품질 확인처럼 워크플로가 사람에게 남긴 판단 관문은 계속 사람이 수행한다.
4. 자동 배정 켜기 확인 안에 동의 관문을 둔다. 동의 상태가 `granted`가 아니면 고지와 확인 항목을 보여
   주고, 확인 항목은 미리 선택하지 않으며 고르기 전에는 계속 버튼을 사용할 수 없게 한다. 계속 버튼
   이름은 "동의하고 자동 배정 켜기"다. 동의가 기록되면 이어서 기존 저장을 수행한다. 취소하면 동의도
   저장도 하지 않는다.
5. 직접 배정 확정 안에 같은 관문을 둔다. 계속 버튼 이름은 "동의하고 직접 배정 시작"이며, 동의가
   기록되면 이어서 기존 시작을 수행한다. 취소하면 실행을 시작하지 않는다.
6. 고급 설정에 동의 상태 자리를 만든다. 동의 여부, 동의 시각, 적용 중인 고지 버전을 보여 주고, 고지
   전문을 다시 읽을 수 있게 하며, 철회 버튼을 둔다. 철회 확인 화면은 이미 실행 중인 세션은 계속되며
   개별 실행 취소로 끝낼 수 있다는 사실과, 다시 실행하려면 최신 고지에 다시 동의해야 한다는 사실을
   알린다.
7. 동의 상태가 `unsupported`이거나 `unreadable`이면 동의 관문을 열지 않고 두 행동을 시작하지 않는다.
   `unsupported`는 실행 환경 업데이트를 안내하고, `unreadable`은 사유와 함께 다시 확인을 안내한다.
8. 실행 환경이 동의 부족으로 시작을 거절한 경우를 화면에 표시한다. 직접 배정 시작의 대기 사유와
   재시도의 사유 코드가 모두 "실행 권한 동의 필요"로 보이고, 그 자리에서 동의 화면을 열 수 있게 한다.
   설치 필요, 로그인 필요, 권한 부족과 다른 문구를 쓴다.
9. 동의를 기록하지 못하면 조용히 넘어가지 않고 사유를 보여 준다. 요구 고지 버전이 앱의 고지 버전보다
   높아 거절된 경우에는 앱 업데이트가 필요하다는 뜻으로 안내한다.
10. 자동 배정이 이미 켜져 있는데 동의 상태가 `required`인 프로젝트에서는 에이전트 화면에 "실행 권한
    동의 필요"를 표시하고, 그 자리에서 동의하면 별도의 설정 저장 없이 배정이 재개되게 한다.
11. 프로젝트를 연 직후의 화면에도 같은 알림 자리를 만든다. `WorkspaceShell.tsx`가 이미 받고 있는
    에이전트 상태에서 자동 배정 여부와 동의 상태를 읽어, 자동 배정이 켜져 있고 동의 상태가 `required`일
    때만 기존 호환성·오류·관리 규칙 배너와 같은 자리에 "실행 권한 동의 필요"를 그린다. 이 자리의 버튼은
    화면을 옮기지 않고 `AgentRuntimeView.tsx`가 내보내는 동의 전용 대화상자를 그대로 열어, 동의만 남기고
    정책은 저장하지 않는다. 고지 문구와 확인 항목과 동의 호출은 모두 기존 것을 재사용하고 새로 만들지
    않는다. 사용자가 에이전트 화면을 보고 있는 동안에는 이 알림을 그리지 않는다. 그 화면이 이미 완료
    조건 10의 같은 안내를 담고 있어 두 번 보일 이유가 없다.

## 범위 밖

- 여러 유료 세션 확인과 과금 경로 확인의 통합이나 축소
- 기획 승인, 품질 확인, 실행 취소 확인의 재설계
- 실행 중 세션을 철회로 종료하는 기능
- 실행 환경의 기록과 집행, 앱 백엔드 커맨드
- 도구 호출마다 승인을 받는 모드나 일부 권한만 고르는 모드

## 완료 조건

1. 동의 상태가 `required`인 프로젝트에서 자동 배정 스위치를 켜면 고지와 확인 항목이 먼저 나타난다.
   확인 항목은 처음에 선택돼 있지 않고, 고르기 전에는 계속 버튼을 누를 수 없으며, 계속 버튼 이름은
   "동의하고 자동 배정 켜기"다.
2. 그 화면에서 취소하면 동의가 기록되지 않고 자동 배정도 켜지지 않는다. 정책 저장 호출이 일어나지
   않는다.
3. 같은 상태에서 직접 배정을 확정하면 같은 고지가 나타나고 계속 버튼 이름이 "동의하고 직접 배정
   시작"이다. 취소하면 실행 시작 호출이 일어나지 않는다.
4. 고지 화면에 변경 범위 3의 다섯 가지 사실이 모두 적혀 있다.
5. 동의 상태가 `granted`이면 자동 배정 켜기와 직접 배정 확정에서 고지가 나타나지 않고 기존 흐름이
   그대로 진행된다. 역할이나 실행 도구를 바꿔도 다시 묻지 않는다.
6. 고급 설정에서 동의 여부와 동의 시각과 고지 버전을 확인할 수 있고, 고지 전문을 다시 읽을 수 있다.
7. 고급 설정의 철회를 확인하면 철회 호출이 일어나고, 확인 화면이 실행 중 세션은 계속된다는 사실과
   개별 취소로 끝낼 수 있다는 사실을 알린다. 철회 뒤 자동 배정 켜기와 직접 배정은 다시 고지를
   보여 준다.
8. 직접 배정 시작 응답이 아무 실행도 시작하지 않고 동의 부족을 대기 사유로 알리면, 대화상자가 닫히지
   않고 "실행 권한 동의 필요"를 보여 주며 동의 화면으로 갈 수 있다. 재시도가 같은 사유로 거절된
   경우에도 같은 문구가 보인다. 두 문구 모두 설치 필요, 로그인 필요, 권한 부족의 문구와 다르다.
9. 동의 상태가 `unsupported`이거나 `unreadable`이면 자동 배정 켜기와 직접 배정 확정이 진행되지 않고,
   두 경우에 서로 다른 안내가 보인다. 어느 경우에도 동의한 것으로 다루지 않는다.
10. 동의 기록에 실패하면 실패 사유가 화면에 남고 그 행동이 이어지지 않는다.
11. 자동 배정이 켜져 있고 동의 상태가 `required`인 프로젝트를 열면 "실행 권한 동의 필요"가 보이고,
    그 자리에서 동의하면 정책 저장 없이 동의만 기록된다.
12. 동의 관문을 통과해도 자동 배정 확인의 여러 유료 세션 안내와 실행 도구의 과금 경로 확인 표시가
    그대로 남는다. 실행 권한 동의가 그 두 확인을 대신하지 않는다.
13. 자동 배정이 켜져 있고 동의 상태가 `required`인 프로젝트를 열면, 왼쪽 메뉴에서 에이전트를 누르지
    않아도 처음 보이는 화면에 "실행 권한 동의 필요"가 보인다. 그 자리의 버튼을 누르면 고지 다섯 문장과
    선택되지 않은 확인 항목이 있는 동의 화면이 열리고, 확인 항목을 고르고 동의하면 동의 기록 호출만
    일어나며 정책 저장 호출은 일어나지 않는다. 동의가 기록되면 이 표시가 사라진다.
14. 자동 배정이 꺼져 있거나 동의 상태가 `required`가 아니면 완료 조건 13의 표시가 나타나지 않는다.
    에이전트 화면을 보고 있는 동안에도 나타나지 않으며, 그때는 완료 조건 10의 표시만 보인다.

## 검증 단계

1. 화면 검사에 동의 상태별 자동 배정 켜기 흐름을 추가하고 실행한다. 완료 조건 1·2·5·9·11을 확인한다.
   명령: `npm run test -- AgentRuntimeView`
2. 직접 배정 확정과 대기 사유 표시 검사를 추가하고 실행한다. 완료 조건 3·8을 확인한다.
   명령: `npm run test -- AgentRuntimeView`
3. 동의와 철회 호출이 실제로 어떤 인자로 나가는지, 성공 뒤 설정을 다시 읽는지를 호출 계층 검사로
   확인한다. 완료 조건 7·10을 함께 확인한다.
   명령: `npm run test -- useProjectWorkspace`
4. 고지 문구에 다섯 가지 사실이 모두 있는지 검사로 확인한다. 완료 조건 4를 확인한다.
   명령: `npm run test -- AgentRuntimeView`
5. 동의를 마친 뒤에도 여러 유료 세션 안내와 과금 경로 확인 표시가 남아 있는지 검사로 확인한다.
   완료 조건 12를 확인한다. 명령: `npm run test -- AgentRuntimeView`
6. 작업 공간 껍데기 검사에 동의 필요 알림 검사를 추가하고 실행한다. 자동 배정이 켜지고 동의 상태가
   `required`인 고정값에서 첫 화면에 알림이 보이는지, 버튼을 눌러 연 동의 화면에서 동의했을 때
   `grantConsent`만 불리고 `save`는 불리지 않는지, 자동 배정이 꺼졌거나 동의 상태가 `granted`인
   고정값과 에이전트 화면을 연 상태에서는 알림이 없는지를 확인한다. 완료 조건 13·14를 확인한다.
   명령: `npm run test -- WorkspaceShell`
7. 앱 전체 검사를 실행한다. 명령: `npm run check`

## 확인 동선

동의 기록이 없는 프로젝트가 출발점이다. 이미 동의한 프로젝트라면 고급 설정에서 먼저 철회하고 시작한다.

1. 에이전트 화면에서 자동 배정 스위치를 켠다. 자동 배정 켜기 확인 창 안에 "실행 권한 고지"와 다섯
   문장이 먼저 보이고, "위 내용을 읽고 실행 권한에 동의합니다"가 선택되지 않은 상태이며, 계속 버튼은
   "동의하고 자동 배정 켜기"이고 누를 수 없다.
2. 그 창에서 취소를 누른다. 자동 배정이 켜지지 않고 동의도 남지 않는다. 고급 설정의 실행 권한 동의는
   그대로 "동의 필요"다.
3. 다시 스위치를 켜고 확인 항목을 고른 뒤 "동의하고 자동 배정 켜기"를 누른다. 자동 배정이 켜지고,
   고급 설정의 실행 권한 동의가 "동의함"으로 바뀌며 동의 시각과 고지 버전 1이 보인다.
4. 직접 배정을 연다. 고지가 나오지 않고 기존처럼 작업을 고르고 시작 조건을 확인하는 흐름이 이어진다.
   참여 역할이나 실행 도구를 바꿔도 다시 묻지 않는다.
5. 고급 설정 > 실행 권한 동의에서 "고지 전문 다시 읽기"를 펼친다. 3에서 동의한 다섯 문장이 같은
   내용으로 보인다.
6. 같은 자리에서 "동의 철회"를 누른다. 확인 창이 이미 실행 중인 세션은 계속되며 실행 취소로 끝낼 수
   있다는 것과, 다시 실행하려면 최신 고지에 다시 동의해야 한다는 것을 알린다. 철회하면 자동 배정
   켜기와 직접 배정 확정에서 고지가 다시 나온다.
7. 자동 배정을 켜 둔 채 6의 철회를 하면 에이전트 화면에 "실행 권한 동의 필요"가 보인다. 그 자리에서
   "고지 읽고 동의"를 눌러 동의하면 설정을 저장하지 않고 동의만 남는다.
8. 7의 상태를 그대로 두고 왼쪽 메뉴에서 "오늘"을 누른다. 에이전트 화면을 벗어나도 첫 화면 위쪽의
   호환성·오류 배너와 같은 자리에 "실행 권한 동의 필요"가 보인다. 프로젝트를 닫았다 다시 열어도
   왼쪽 메뉴의 에이전트를 누르지 않은 채 같은 자리에서 이 알림을 만난다.
9. 8의 알림에서 "고지 읽고 동의"를 누른다. 고지 다섯 문장과 선택되지 않은 확인 항목이 있는 동의
   화면이 열린다. 확인 항목을 고르고 동의하면 알림이 사라지고, 고급 설정의 실행 권한 동의가
   "동의함"으로 바뀐다. 자동 배정 스위치는 켜진 그대로이고 다시 저장되지 않는다.
10. 에이전트 화면으로 돌아가면 "실행 권한 동의 필요"가 한 곳에만 보인다. 첫 화면의 알림과 에이전트
    화면의 안내가 함께 보이지 않는다.

실행 환경이 시작을 거절하는 두 경우와 동의 상태를 읽지 못하는 두 경우는 손으로 만들기 어려워 자동
검사로 확인했다. 아래 명령의 결과를 보는 것으로 이 부분의 확인을 갈음한다.

```
npm run test -- AgentRuntimeView
npm run test -- useProjectWorkspace
npm run test -- WorkspaceShell
```
