# 서비스 연결만 남은 계획의 확인 창이 연결을 말한다

## 결정권자 요약

### 제안

실행 환경이 이미 설치되어 있고 관리형 서비스 연결만 남은 계획에서, 확인 창의 제목과 안내 문장이
설치가 아니라 서비스 연결을 말하게 한다.

### 현재

확인 창은 설치, 업데이트, 복구, 내려받기 네 가지 계획에 같은 제목 하나와 같은 안내 문장 하나를
쓴다. 그래서 런타임이 이미 설치되어 있고 서비스만 연결하면 되는 기기에서도 실행 환경 변경이라는
제목이 먼저 읽힌다. 버전 줄도 두 값을 화살표 양쪽에 그대로 적기 때문에, 버전이 달라지지 않는
계획에서는 같은 버전이 두 번 보인다. 서비스에 무엇을 하는지는 별도 줄에 적혀 있지만 제목과 버전
줄이 먼저 읽히므로, 사용자는 설치를 다시 하는 것으로 오해한다. 2026-08-18 Windows 새 기기에서
실측한 내용이다.

### 변경 후

설치된 버전과 앱에 포함된 버전이 같고 서비스에 할 일이 새 연결뿐인 계획에서는, 확인 창의 제목과
안내 문장이 관리형 서비스 연결을 말하고 설치라는 말을 쓰지 않는다. 버전이 달라지지 않는 계획에서는
버전 줄이 같은 값을 두 번 적는 대신 현재 버전을 유지한다는 사실을 밝힌다. 버전이 실제로 바뀌는
계획의 문구는 지금 그대로여서, 설치와 업데이트를 하던 사용자가 보는 화면은 달라지지 않는다.

### 비용과 위험

확인 창의 문구만 달라진다. 계획을 만드는 절차, 적용이 부르는 명령, 서비스에 할 일을 판정하는
규칙은 손대지 않는다. 문구를 고르는 조건이 하나 늘어나므로, 조건에 해당하지 않는 계획이 새 문구를
쓰게 되면 오히려 오해를 만든다. 그래서 두 값이 모두 있고 서로 같을 때만 새 문구를 쓰고, 값이 없는
경우는 지금 문구를 그대로 쓴다. 표시만 바꾸므로 되돌리기도 표시를 되돌리는 것으로 끝난다.

## 현재 코드 상태

행 번호는 이 작업을 만든 시점의 것이다. 이 작업은 TASK-S067-01과 TASK-S068-01 뒤에 오고 두 작업이
같은 화면 파일을 고치므로, 개발자는 행 번호가 아니라 아래에 적은 이름으로 자리를 찾는다.

확인 창은 `src/features/projects/components/agents/AgentRuntimeView.tsx` 345행
`RuntimePlanDialog`가 그린다.

- 창의 접근성 이름은 `실행 환경 변경 확인`이고, 제목은 `실행 환경 변경`이며, 그 아래 안내 문장은
  "실행 중인 세션은 유지하고 앱이 관리하는 런타임만 변경합니다."다. 네 계획이 이 셋을 함께 쓴다.
- 버전 줄은 계획 종류에 따라 둘로 갈린다. 설치와 내려받기는 설치 버전과 앱에 포함된 버전을 화살표
  양쪽에 적고, 설치 버전이 없으면 왼쪽에 `설치 안 됨`을 적는다. 업데이트와 복구는 설치 버전과 목표
  버전을 같은 방식으로 적고, 목표 버전이 없으면 오른쪽에 `현재 버전 복구`를 적는다.
- 서비스 줄은 설치와 내려받기에서만 나오고, 377행 `serviceActionLabel`이 네 처분을 사용자 문구로
  옮긴다. 새 연결에 해당하는 값은 `register`이고 문구는 "관리형 서비스를 새로 연결"이다.
- 계획 값의 모양은 `src/features/projects/domain/types.ts` 1375행 `AgentInstallPlan`과 1406행
  `AgentUpdatePlan`이다. 앞의 것은 설치 버전과 앱에 포함된 버전과 서비스 처분을 모두 싣고, 뒤의
  것은 설치 버전과 목표 버전을 싣는다. 서비스 처분은 1369행 `AgentInstallServiceAction`의 네 값
  중 하나다.
- 서비스 처분을 정하는 자리는
  `src-tauri/src/application/agent_runtime_install_service.rs` 504행 `service_action`이다. 서비스가
  등록되어 있지 않으면 `register`, 등록되어 있고 실행 파일이 관리형 launcher와 같으면
  `already_managed`, 등록되어 있고 다르면 `migration_required`, 등록 여부를 읽지 못하면 `unknown`을
  낸다. 이 판정은 이 작업이 고치지 않는다.
- 화면 검사는 `src/features/projects/components/agents/AgentRuntimeView.test.tsx` 313행에 있다.
  설치 버전 0.8.3과 앱에 포함된 버전 0.9.0, 처분 `migration_required`로 만든 계획에서 창의 접근성
  이름이 `실행 환경 변경 확인`이고 버전 줄이 `0.8.3 → 0.9.0`임을 확인한다. 이 계획은 버전이 바뀌고
  처분도 새 연결이 아니므로 이번 변경 뒤에도 같은 문구를 써야 한다.

## 완료 조건

- C1. 계획 종류가 설치나 내려받기이고, 설치 버전과 앱에 포함된 버전이 모두 있으면서 서로 같고,
  서비스 처분이 `register`이면 확인 창의 제목과 안내 문장이 관리형 서비스 연결을 말한다(R04).
  제목과 안내 문장에 설치라는 말을 쓰지 않는다. 창의 접근성 이름도 이 경우에는 연결을 말하는
  이름으로 둔다.
- C2. C1에 해당하지 않는 모든 계획은 지금의 제목, 안내 문장, 접근성 이름을 그대로 쓴다(R04).
  버전이 실제로 바뀌는 계획의 문구가 하나도 달라지지 않는다.
- C3. 버전 줄은 비교할 두 값이 모두 있고 서로 같으면 화살표를 쓰지 않고 현재 버전을 유지한다는
  사실을 그 버전과 함께 적는다(R04). 비교하는 두 값은 설치와 내려받기에서는 설치 버전과 앱에
  포함된 버전이고, 업데이트와 복구에서는 설치 버전과 목표 버전이다.
- C4. 두 값 중 하나라도 없거나 두 값이 다르면 버전 줄은 지금 문구를 그대로 쓴다(R04). 설치 버전이
  없을 때의 `설치 안 됨`과 `확인 안 됨`, 목표 버전이 없을 때의 `현재 버전 복구`가 지금과 같이
  나온다.
- C5. 서비스 줄과 그 문구는 바꾸지 않는다. 네 처분의 사용자 문구가 지금과 같고, 기존 외부 서비스를
  보존한다는 안내도 지금 조건 그대로 나온다.
- C6. 계획을 만드는 절차와 적용 절차를 바꾸지 않는다(R05). 계획을 부르는 조작, 적용이 부르는
  게이트웨이 함수와 인자, 취소 동작이 지금과 같다.
- C7. TASK-S068-01이 만든 결과 화면의 문구와 동작은 바꾸지 않는다. 이 작업은 적용 전 계획 화면만
  고친다.
- C8. 확인 창의 문구에 명령어, 파일 경로, 코드 식별자를 내지 않는다.
- C9. 다음 검사를 `AgentRuntimeView.test.tsx`에 더한다.
  - 설치 버전과 앱에 포함된 버전이 같고 처분이 `register`인 설치 계획에서, 창의 제목과 안내 문장에
    설치라는 말이 없고 서비스 연결을 말하는 문구가 보인다.
  - 같은 계획에서 버전 줄이 화살표로 같은 값을 두 번 적지 않고 현재 버전을 유지한다는 문구를
    보여준다.
  - 설치 버전이 없는 설치 계획에서 지금과 같이 `설치 안 됨`이 왼쪽에 오는 버전 줄이 나오고 제목이
    지금 문구 그대로다.
  - 설치 버전과 목표 버전이 같은 복구 계획에서 버전 줄이 현재 버전을 유지한다는 문구를 보여주고,
    제목은 지금 문구 그대로다.
- C10. 기존 검사의 확인 의도를 약화시키지 않는다. 313행의 검사가 확인하는 접근성 이름과 버전 줄과
  서비스 문구를 그대로 둔다.
- C11. 선언한 두 파일 밖의 파일은 바뀌지 않는다. `src-tauri` 아래와 `.workflow` 아래에 변경이 없고,
  `src/App.css`도 바뀌지 않는다.

## 범위 사전 검사

이 작업이 바꾸는 값은 확인 창이 그리는 문구 셋이다. 제목과 접근성 이름, 안내 문장, 버전 줄이다.
셋 다 화면에서 계산되며 새 데이터가 백엔드에서 오지 않는다는 것을 각 hop의 현재 코드로 확인했다.

- 값 경로: 문구를 고르는 조건이 되는 설치 버전과 앱에 포함된 버전(C1, C3, C4). 만드는 자리는
  `src-tauri/src/application/agent_runtime_install_service.rs`의 계획 생성이고, 설치 버전은 기기
  조회 결과에서, 앱에 포함된 버전은 번들 manifest에서 온다. hop은 넷이다. (1) 도메인 계획 구조가
  두 값을 필드로 싣는다. 편집이 필요 없다. (2) 화면 타입
  `src/features/projects/domain/types.ts` 1375행 `AgentInstallPlan`의 `installedVersion`과
  `bundledVersion`, 1406행 `AgentUpdatePlan`의 `installedVersion`과 `targetVersion`. 네 값이 모두
  선택적 문자열이거나 문자열이라 비교에 필요한 것이 이미 있다. 편집이 필요 없다. (3)
  `src/features/projects/application/useProjectWorkspace.ts`의 계획 보관. 계획 값을 그대로 상태에
  넣고 화면에 넘기므로 이 hop은 값을 무변경으로 나른다. 편집이 필요 없다. (4) 화면 조립부
  `src/features/projects/components/agents/AgentRuntimeView.tsx` 345행 `RuntimePlanDialog`. 지금
  두 값을 화살표 양쪽에 그대로 적고 있으므로 편집이 필요하다. 선언에 들어 있다.
- 값 경로: 서비스 처분(C1). 만드는 자리는 같은 Rust 파일 504행 `service_action`이다. hop은 셋이다.
  (1) 그 함수가 등록 여부와 실행 파일 경로로 네 값 중 하나를 낸다. 본문을 열어 확인했고 등록되지
  않은 기기가 `register`를 받는다는 것이 이번 조건의 근거다. 편집이 필요 없다. (2) 화면 타입
  1369행 `AgentInstallServiceAction`이 네 값을 그대로 싣는다. 편집이 필요 없다. (3) 화면 조립부가
  지금은 이 값을 서비스 줄에만 쓰고 있고, 이번에 제목을 고르는 조건으로도 읽는다. 편집이 필요하고
  선언에 들어 있다.
- 값 경로: 확인 창이 보여주는 제목과 접근성 이름과 안내 문장(C1, C2). 만드는 자리는 화면 조립부
  하나뿐이다. hop은 둘이다. (1) 345행이 세 문구를 상수로 적고 있다. 편집이 필요하고 선언에 들어
  있다. (2) 이 문구를 읽는 소비자는 사용자와 화면 검사다. 검사는
  `AgentRuntimeView.test.tsx` 313행이 접근성 이름으로 창을 찾으므로, C1이 이름을 바꾸는 경우가 그
  검사의 계획과 겹치지 않는지 확인했다. 그 검사의 계획은 버전이 0.8.3에서 0.9.0으로 바뀌고 처분이
  `migration_required`라 C1의 조건 셋 중 둘을 만족하지 않는다. 그래서 이름이 그대로 유지되고 검사도
  그대로 통과한다. 검사 파일은 C9가 새 검사를 더하므로 선언에 들어 있다.

선언에서 뺀 파일과 근거를 정리한다.

- `src-tauri` 아래 전부: 계획 값에 필요한 세 값이 이미 실려 온다. 서비스 처분 판정과 계획 생성은
  기획서가 제외 범위로 적었고 이 작업의 완료 조건도 그것을 요구하지 않는다.
- `src/features/projects/domain/types.ts`: 비교에 쓰는 네 필드가 이미 있고 새 필드가 필요 없다.
- `src/features/projects/application/useProjectWorkspace.ts`: 계획을 상태에 그대로 넣어 화면에
  넘긴다. 문구는 화면에서만 정해지므로 편집할 것이 없다.
- `src/App.css`: 새 요소를 만들지 않고 지금 버전 줄과 안내 문장이 쓰는 선언을 그대로 쓴다. 문구
  길이만 달라지므로 스타일을 더할 이유가 없다.
- `src/features/projects/components/agents/AgentRunDashboard.tsx`: 이 작업은 실행 환경이 돌려준
  사유 문장을 다루지 않으므로 변환 규칙을 열 이유가 없다.
