# 구조화된 요약이 반응형 결정 보드로 열린다

## 결정권자 요약

정확한 구조를 가진 요약이 현재, 변경 후와 사용자 결과를 잇는 결정 보드로 열린다.
변경과 유지 영역을 나눴고 실제 위험이 있을 때만 이름이 있는 경고를 표시한다.
작은 창은 같은 순서를 한 열로 쌓으며 원문 보기와 기존 평문 폴백도 그대로 유지한다.
전용 검사 19개와 전체 검사 914개가 통과했으며 사용자는 아래 동선으로 화면을 확인한다.

## 확인 동선

기획서 화면에서 SPEC-052를 열면 `제안`부터 `결정 요청`까지 결정 보드가 기본 화면에 나타난다.
창 너비를 700픽셀보다 넓게 두면 변화 흐름 세 칸과 영향 범위 두 칸이 보이고, 더 좁히면 같은 제목
순서가 한 열로 쌓여야 한다. 긴 문장이 카드 밖으로 잘리거나 가로 스크롤을 만들지 않아야 한다.
`비용과 위험`은 제목과 문장이 있는 경고 영역으로 보인다. `원문 전문 보기`를 키보드로 누르면
SPEC-052의 `결정권자 요약`부터 본문 마지막까지 나타나고 `aria-expanded`가 참으로 바뀐다.
`요약만 보기`를 누르면 결정 보드로 돌아온다. 평문 요약 문서는 기존 Markdown 요약으로 열려야 한다.

## 목적

TASK-S052-02의 구조화 요약 모델을 전용 결정 보드로 표현하고 `DocumentReader`의 기본 요약 화면에
연결한다. 화면은 문서가 준 값만 배치하며 상태, 파생 작업 수, 결정 이력이나 행동 결과를 새로
만들거나 반복하지 않는다.

## 보드의 정보 구조

DOM과 보조 기술의 읽기 순서는 아래 순서 하나를 사용한다. CSS가 넓은 창에서 칸을 나누더라도 DOM
순서를 바꾸지 않는다.

1. 보드의 이름과 `제안` 값.
2. `현재`, `변경 후`, `사용자 결과`의 순서 있는 변화 흐름.
3. `변경`과 `유지`로 나뉜 영향 범위.
4. 값이 있을 때만 나타나는 `비용과 위험` 경고.
5. 마지막 `결정 요청` 영역.

각 영역은 텍스트 제목을 항상 표시한다. 색상과 장식은 보조 수단이며, 아이콘이나 의사 요소를 제거해도
제목, 순서와 내용이 남는다. 변화 흐름은 의미 있는 목록 구조를 사용하고 영향 범위는 두 이름과 값을
각각 연결한다. 위험 영역은 색상만으로 경고를 전달하지 않는다.

문서 값의 Markdown은 기존 안전한 렌더러를 재사용한다. raw HTML 플러그인을 추가하지 않고 문서가
쓴 HTML을 DOM으로 허용하지 않는다. 보드가 문자열을 HTML로 저장하거나 별도 정본을 만들지 않는다.

## 반응형과 원문 전환

넓은 영역에서는 변화 흐름과 영향 범위를 여러 칸으로 훑을 수 있다. 좁은 영역에서는 `현재`부터
`결정 요청`까지 한 열로 쌓인다. CSS grid의 시각 순서와 DOM 순서는 항상 같다. 내용이 길어져도
가로 스크롤이나 잘림 없이 줄바꿈된다.

구조 판정이 성공하면 `DocumentReader`의 기본 화면은 보드를 그린다. `원문 전문 보기`를 누르면
구조화 요약을 포함한 전체 Markdown 본문을 기존 렌더러로 그대로 그리고, 다시 누르면 같은 보드로
돌아온다. 토글의 `aria-expanded`, 문서를 바꿀 때 기본 요약으로 돌아오는 동작과 상태 비저장은
유지한다.

평문 요약이나 불완전한 구조는 기존 Markdown 요약 화면으로 폴백한다. 요약 절 자체가 없으면 전체
원문을 표시하고 토글을 만들지 않는 현재 동작을 유지한다. 오류·변환 안내나 빠진 값을 만들지 않는다.

## 완료 조건

1. 완전한 구조의 기본 화면이 제안, 세 단계 변화 흐름, 변경·유지 영향, 결정 요청을 정한 DOM 순서로
   표시한다. 같은 값을 중복 출력하지 않는다. (R1·R2)
2. 위험 값이 있을 때만 이름과 문장이 있는 경고 영역이 나타나며, 없을 때 제목·빈 카드·여백이 생기지
   않는다. (R1·R4)
3. 제목, 목록과 연결된 이름만으로 정보 계층과 위험 의미를 이해할 수 있고 접근 가능한 영역 이름을
   가진다. 아이콘과 색상은 필수 의미를 맡지 않는다. (R4)
4. 넓은 영역은 변화 흐름과 영향 범위를 여러 칸으로 표시하고, 좁은 화면은 같은 DOM 순서의 한 열로
   쌓인다. 긴 값이 잘리거나 가로 스크롤을 만들지 않는다. (R4)
5. 원문 토글을 열면 구조화 요약을 포함한 전체 Markdown 본문이 손실·재배치 없이 보이고, 닫으면
   보드로 돌아온다. 기존 토글의 키보드 조작과 `aria-expanded`가 유지된다. (R3·R4)
6. 평문 요약, 불완전 구조와 무요약 문서가 각각 현재의 Markdown 요약 또는 전체 원문 경로로
   폴백한다. 오류 문구와 자동 보완이 없다. (R3)
7. 문서 Markdown은 기존 안전한 렌더러를 거치며 raw HTML을 활성화하지 않는다. 네트워크, LLM,
   저장소, 요약 캐시, 이미지와 문서별 차트 데이터를 추가하지 않는다. (R3·R5)
8. 보드가 상태, 작업 수, 결정 이력이나 기존 화면 조작을 새로 그리지 않는다. (R2)
9. `npx vitest run src/features/projects/components/DecisionSummaryBoard.test.tsx
   src/features/projects/components/DocumentReader.test.tsx
   src/features/projects/components/decisionSummaryBoardLayout.test.ts`와 `npm run check`이 통과한다.
10. 기존 자동 검사가 삭제되거나 비활성화되지 않고 변경분은 범위 파일 안에 머문다.

## 검증 절차

1. 위험이 있는 구조와 없는 구조를 렌더해 영역, 순서, 중복 부재와 빈 위험 영역 부재를 확인한다.
2. 필수 항목이 하나 빠진 구조와 평문 요약으로 기존 Markdown 폴백을 확인한다.
3. 원문 토글을 키보드로 열고 닫아 전체 본문의 처음과 마지막 문장, 요약 절과 `aria-expanded`를
   확인한다.
4. CSS 규칙 검사로 넓은 grid와 좁은 한 열, 줄바꿈과 overflow 경계를 확인하고 앱에서 두 폭을 눈으로
   확인한다.
5. `npm run check`을 실행하고 변경분에 gateway, 저장소, 네트워크 호출, 새 패키지와 raw HTML
   활성화가 없는지 확인한다.
