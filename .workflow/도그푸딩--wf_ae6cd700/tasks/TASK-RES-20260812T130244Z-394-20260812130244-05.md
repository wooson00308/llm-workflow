# 실행 하나를 진단 번들로 저장하거나 복사한다

## 결정권자 요약

### 제안

실행 하나에 대해 개발자가 재현에 필요한 자료를 한 덩어리로 모아 파일로 저장하거나 클립보드에 복사하게 한다.

### 현재

문제가 생기면 사용자가 무엇을 전달해야 하는지 알 수 없고, 실행 정보와 이벤트와 진단 결과가 각각 다른 곳에 있다.

### 변경 후

실행 상세에서 한 번의 저장이나 복사로 실행 정보, 원본 이벤트, 그 시점의 진단 결과, 최근 오류가 한 덩어리로 나온다.

### 사용자 결과

문제를 알릴 때 무엇을 모아야 하는지 고민하지 않는다. 일부 항목을 읽지 못해도 읽은 부분은 나오고 빠진 것은 사유와
함께 적힌다.

### 영향 범위

- 변경: 실행 상세의 진단 자료 내보내기, 그 자료를 만드는 백엔드 표면
- 유지: 작업 지시와 인증 값을 보존하지 않는 원칙, 실행 배정과 취소와 재시도, 문서 상태와 사용자 판단 관문

### 비용과 위험

모으는 범위가 넓어지면 민감정보 비보존 경계가 무너진다. 이미 저장된 것만 모으고 새로 수집하지 않는다.
내보내기는 외부로 보내지 않으며 사용자가 직접 고른 때만 실행한다.

### 결정 요청

QA에서는 실행 하나를 저장과 복사 양쪽으로 내보내 두 결과의 규격 버전과 실행 내용이 같은지, 그리고 작업 지시와
인증 값과 도구에 넘긴 값이 결과 어디에도 없는지 확인한다.

## 범위 사전 검사

이 작업이 다루는 값은 다섯이다. 실행 메타정보, 원본 이벤트, 진단 결과, 최근 오류, 그리고 읽지 못한 항목의 사유다.
다섯 값이 어디서 오고 어디까지 가는지 실제 코드에서 확인했다.

- 값 경로: 완료 조건 2의 실행 메타정보는 `src-tauri/src/application/agent_runtime_status_service.rs`의 `inspect`가
  돌려주는 큐 상태 안의 실행 요약에서 나온다. 역할, provider, 상태, 대상, 시작과 종료 시각, 실패 단계와 사유가 이미
  그 구조에 있고 예약 결과 접두어는 앞선 작업이 더한다. provider 버전은 같은 파일이 부르는 provider 진단 결과가 담는다.
  번들을 조립하는 자리를 이 파일에 두므로 편집한다.
- 값 경로: 완료 조건 3의 원본 이벤트는 같은 파일의 `read_log`가 실행 식별자와 cursor로 읽는다. 런타임 저장 계층은 한 번에
  200건까지만 돌려주므로 한 번 호출로는 전체가 오지 않는다. 번들은 cursor가 더 나아가지 않을 때까지 이어 읽어야 전체를
  담는다. 이 반복은 새로 만들어야 하므로 같은 파일을 편집한다. 이벤트가 담은 순서와 시작 시각과 경과 초는 런타임이 이미
  기록한 값이며 번들은 그것을 그대로 옮긴다.
- 값 경로: 완료 조건 4의 진단 결과와 최근 오류는 같은 파일의 `inspect`가 이미 모으고 있다. provider 진단은 실패하면
  빈 값으로 떨어지고 최근 오류는 런타임 상태의 오류 배열에서 온다. 두 값 모두 읽지 못하는 경우가 있으므로 번들 조립에서
  성공과 실패를 구분해 기록한다. 런타임 진단 결과는 `src-tauri/src/commands/agent_runtime.rs`가 이미 부르는 런타임 조회에서
  오므로, 조립 함수가 그 값을 받도록 명령 자리에서 넘긴다. 명령을 더하고 값을 넘기기 위해 그 파일을 편집한다.
- 값 경로: 완료 조건 1의 두 결과가 같아야 한다는 조건은 저장과 복사가 같은 조립 함수를 한 번만 지나게 해서 충족한다.
  명령이 저장 위치를 받으면 조립한 내용을 그 위치에 쓰고, 받지 않으면 같은 내용을 문자열로 돌려준다. 화면은 돌려받은
  문자열을 기존 클립보드 모듈로 복사한다.
- 값 경로: 완료 조건 1·6의 화면 조작은 `src/features/projects/components/agents/AgentRunDashboard.tsx`의 실행 상세가
  맡고, 호출은 `src/features/projects/infrastructure/tauriProjectGateway.ts`가, 형태 선언은
  `src/features/projects/domain/types.ts`가, 상태 보관은 `src/features/projects/application/useProjectWorkspace.ts`가 맡는다.
  네 자리 모두 편집한다. 새 명령이 실제로 호출되려면 `src-tauri/src/lib.rs`의 명령 등록 목록에 올라야 하므로 그 파일도 편집한다.
- 값 경로: 완료 조건 1의 저장 위치 선택은 파일 대화상자가 맡는다. 저장소에는 파일 시스템 플러그인이 없고 대화상자
  플러그인만 있으므로, 위치는 화면이 대화상자로 고르고 쓰기는 백엔드 명령이 한다. `src-tauri/capabilities/default.json`은
  현재 대화상자의 기본 권한만 열어 두었으므로, 저장 대화상자가 그 기본 권한에 포함되는지 확인하고 포함되지 않으면 저장
  권한을 명시적으로 더한다. 확인 결과 이미 포함되어 있으면 이 파일은 편집하지 않는다.
- 검토했으나 제외한 것: `src/features/projects/infrastructure/clipboard.ts`는 문자열 하나를 복사하고 실패를 값으로
  돌려주는 기존 모듈이다. 이 작업에 필요한 동작을 이미 그대로 제공하므로 편집하지 않고 그대로 부른다.
- 검토했으나 제외한 것: 런타임 저장소는 건드리지 않는다. 번들은 런타임이 이미 저장한 것만 모으며, 새 필드를 저장하게
  하거나 조회 명령을 더하지 않는다.

## 현재 상태

실행 상세에는 내보내기가 없다. 실행 요약과 이벤트와 provider 진단과 최근 오류는 각각 다른 조회로만 얻을 수 있고,
한 덩어리로 묶는 자리가 없다. 사용자가 문제를 알릴 때 무엇을 모아 전달해야 하는지 앱이 알려 주지 않는다.

## 변경 범위

1. 실행 하나의 진단 번들을 조립하는 자리를 만든다. 결과는 하나의 버전화된 구조이며 다음을 담는다.
   실행 식별자와 프로젝트와 대상 문서, 역할, provider와 그 버전, 시작과 종료 시각, 상태, 실패 단계와 사유 코드.
   순서와 시각 근거를 보존한 런타임 원본 이벤트 전체. 내보내는 시점의 provider 진단 결과와 런타임 진단 결과.
   그 프로젝트의 최근 오류 기록과 각 기록의 시각과 단계와 사유 코드. 번들 규격 버전과 생성 시각. 읽지 못한 항목과 그 사유.
2. 이벤트는 cursor가 더 나아가지 않을 때까지 이어 읽어 전체를 담는다. 한 번의 조회로 끊지 않는다.
3. 진단과 오류를 읽지 못해도 번들 생성을 중단하지 않는다. 읽은 부분을 담고, 읽지 못한 항목의 이름과 사유를 번들 안에
   적는다. 성공으로 추측하거나 빈 값을 조용히 채우지 않는다.
4. 번들에 작업 지시, 프롬프트, 인증 값, 환경 변수, 도구 인자, 도구 결과 본문을 새로 수집하거나 싣지 않는다.
   이미 저장된 이벤트가 담은 값만 옮긴다.
5. 번들을 만드는 명령을 하나 더한다. 저장 위치를 받으면 조립한 내용을 그 위치에 쓰고, 받지 않으면 같은 내용을 문자열로
   돌려준다. 두 경로는 같은 조립 결과를 쓴다.
6. 실행 상세에 진단 번들 내보내기를 더한다. 활성 실행과 종료된 실행에서 모두 쓸 수 있고, 저장과 복사를 각각 고를 수 있다.
   저장 위치는 파일 대화상자로 고른다.
7. 내보내기는 사용자가 저장이나 복사를 고른 때만 실행한다. 화면을 여는 것만으로는 실행되지 않는다.
8. 내보내기는 외부 서비스로 보내지 않고 이슈를 만들지 않는다. 네트워크 호출을 더하지 않는다.
9. 내보내기 진행과 성공과 실패 표시에 필요한 화면 규칙을 `src/App.css`에 더한다.

## 범위 밖

- 전체 트랜스크립트, 표준 출력과 표준 오류, 도구 인자와 결과 본문을 새로 저장하는 기능
- 번들을 외부 이슈 추적기, 원격 서비스, 전자우편으로 보내는 기능
- 지난 실행의 진단 결과를 소급해서 복원하는 작업
- 실행 요약 카드의 다른 항목과 보고서 바로가기의 변경
- 실행 배정, 취소, 재시도, 문서 승인과 품질 확인의 의미 변경

## 완료 조건

1. 실행 하나를 파일로 저장한 결과와 클립보드로 복사한 결과가 같은 규격 버전과 같은 실행 내용을 가진다.
2. 번들에 실행 식별자와 프로젝트와 대상 문서와 역할과 provider와 버전, 상태와 실패 단계와 사유 코드, 시작과 종료 시각이
   들어 있다.
3. 이벤트가 런타임이 저장한 순서 그대로 들어 있고, 저장 계층의 한 번 조회 한도보다 많은 이벤트를 가진 실행에서도 전체가
   들어 있다.
4. provider 진단이나 최근 오류를 읽지 못한 상태에서도 번들이 만들어지고, 읽지 못한 항목의 이름과 사유가 번들 안에 적힌다.
5. 작업 지시, 프롬프트, 인증 값, 환경 변수, 도구 인자, 도구 결과 본문에 고유한 가짜 문자열을 넣은 뒤 번들 전체를 검색해도
   그 문자열이 없다.
6. 사용자가 저장이나 복사를 고르기 전에는 내보내기가 실행되지 않고, 고른 뒤에도 외부 업로드와 이슈 생성이 일어나지 않는다.
7. 활성 실행과 종료된 실행 양쪽에서 내보내기가 동작한다.
8. 저장 대화상자에 필요한 권한이 열려 있고, 저장을 취소하면 파일이 만들어지지 않는다.
9. 기존 실행 배정, 상태 조회, 취소, 재시도, 실행 요약 카드 표시 검사가 변경 전과 같은 결과로 통과한다.

## 검증 단계

1. 번들 조립 검사를 더해 완료 조건 2, 3, 4를 확인한다. 한도보다 많은 이벤트를 가진 가짜 런타임 응답으로 이어 읽기를
   확인한다. 명령: `cargo test --manifest-path src-tauri/Cargo.toml`
2. 완료 조건 5의 문자열 주입 검사를 더한다. 가짜 값을 실행 요청과 이벤트와 진단 응답에 넣고 조립한 번들 전체를 문자열로
   만들어 그 값이 없음을 단언한다. 명령: `cargo test --manifest-path src-tauri/Cargo.toml`
3. 정적 검사를 실행한다. 명령: `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets`
4. 화면 검사를 더해 완료 조건 1, 6, 7, 8을 확인한다. 저장 취소와 복사 실패의 표시를 함께 확인한다.
   명령: `npm run test`
5. 형식 검사와 빌드를 실행한다. 명령: `npm run check`

## 확인 동선

1. 에이전트 화면을 열고 `진행 중` 또는 `최근 종료` 목록에서 실행 하나를 눌러 실행 상세를 연다.
   이 시점에는 아직 아무것도 나가지 않아야 한다. 상세를 열기만 했을 때 저장 대화상자가 뜨거나
   내보내기 문구가 보이면 잘못된 것이다.
2. 상세 아래쪽 `진단 자료 저장`을 누른다. 저장 대화상자가 뜨고 기본 파일 이름이
   `<실행 ID>-diagnostics.json`이다. 위치를 고르면 `진단 자료를 파일에 담았습니다.`가 뜬다.
3. 같은 자리에서 `진단 자료 저장`을 다시 누르고 이번에는 대화상자를 취소한다. 파일이 만들어지지
   않고 화면에도 아무 문구가 남지 않아야 한다.
4. `진단 자료 복사`를 누른다. 대화상자 없이 `진단 자료를 클립보드에 담았습니다.`가 뜬다. 편집기에
   붙여 넣으면 2번에서 저장한 파일과 같은 `bundleVersion`과 같은 `runId`, 같은 실행 내용이 보인다.
   `generatedAt`만 다르다.
5. 저장한 파일을 열어 다음을 확인한다. 실행 식별자, 프로젝트, 대상 문서, 역할, provider와
   `providerVersion`, 상태, `failureStage`, 사유 코드, 시작과 종료 시각이 들어 있고, `events`에
   런타임이 저장한 순서 그대로 이벤트가 실려 있다. 이벤트가 200건을 넘는 실행에서도 뒤쪽이 잘리지
   않아야 한다.
6. 같은 파일에서 작업 지시, 프롬프트, 인증 값, 환경 변수, 도구 인자, 도구 결과 본문이 없는지 본다.
   `toolArgs`, `toolResult`, `prompt`, `env`, `apiKey` 같은 열쇠가 하나도 나오면 안 된다.
7. 진행 중인 실행과 종료된 실행 양쪽에서 2번과 4번이 모두 동작하는지 확인한다.
8. provider 진단을 읽지 못하는 상태(예: 실행 도구 미설치)에서도 내보내기가 되고, 파일의
   `unavailable`에 읽지 못한 항목 이름과 사유가 적히는지 확인한다.

자동 검사로 닫은 부분은 다음과 같다. 번들 조립·이어 읽기·읽지 못한 항목 기록·가짜 문자열 주입은
`cargo test --manifest-path src-tauri/Cargo.toml`이, 화면 조작과 저장 취소는 `npm run test`가
확인했다. 위 1~8번은 실제 런타임과 파일 대화상자가 있어야 하는 부분이라 사람이 본다.
