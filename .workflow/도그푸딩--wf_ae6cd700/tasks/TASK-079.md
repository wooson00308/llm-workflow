# 두 아이디어 입력창을 초안 저장소에 배선하고 동작을 테스트로 고정한다

SPEC-025 R1·R2·R3·R5·R6을 닫는다. 입력창의 글은 지금 `IdeaComposer`의 지역 상태 하나이고
(`IdeaComposer.tsx:12`) 두 화면 모두 조건부 렌더라 다른 메뉴를 누르는 순간 언마운트된다
(확인 사실 3). TASK-078이 만든 저장소를 그 자리에 배선한다.

## 의존성

- **선행 필수: TASK-078.** 초안 저장소 모듈을 import한다. 파일은 겹치지 않지만 모듈이 없으면 타입
  검사부터 실패한다.

- `WorkspaceShell.tsx`·`IdeaInbox.tsx`를 범위에 올린 미완료 작업은 열 건이고 그중 아홉이

- **줄 번호는 작업 트리 기준이다.** 저장소에 미커밋 변경이 많다. 앵커는 식별자로 찾는다.

## 설계

### 초안이 사는 자리

두 입력창이 동시에 보이는 일이 없고(확인 사실 3) 뷰 전환이 곧 언마운트·재마운트이므로, **컴포넌트가
마운트할 때 저장소에서 한 번 읽고 사용자가 고칠 때만 저장하는 방식**을 권한다. 이 저장소의 기존
어법이고(`IntegrationsView.tsx:35` 부근의 게으른 초기화, TASK-062가 같은 idiom을 썼다), 이렇게 하면
확인 필요 1번의 "두 입력창의 초안은 하나"가 저절로 성립한다 — 한쪽이 언마운트되고 다른 쪽이 마운트할
때 같은 키를 읽기 때문이다.

상태를 `WorkspaceShell`로 끌어올리는 방식도 요구사항을 만족시킬 수 있다. 어느 쪽을 고르든 아래
"반드시 성립해야 하는 것"이 전부 성립해야 하고, 고른 이유를 보고서에 한 줄 남긴다.

### R3의 실질 대상은 언마운트 동작이다

DECISION-5B7E9F14의 유의 사항 3번이 짚은 지점이다. 확인 사실 8대로 지금 두 자리의 동작이 이미
갈라져 있다.

- 인박스는 `WorkspaceShell.tsx:373`에 `key={workflow.directory}`가 걸려 있어 워크플로가 바뀌면
  통째로 다시 마운트된다. 그래서 초안도 지금 사라진다.
- 오늘 화면의 입력창에는 `key`가 없어(`:328`) 워크플로를 바꿔도 쓰던 글이 그대로 남는다.

게으른 초기화 방식을 고르면 **오늘 화면 쪽에도 워크플로 디렉터리를 `key`로 걸어야 R3이 성립한다.**
`key`가 없으면 워크플로를 바꿔도 재마운트가 일어나지 않아 이전 워크플로의 초안이 입력창에 그대로 떠
있고, 그대로 제출하면 잘못된 곳에 담긴다. 이것이 R3이 막으려는 사고다. `key`를 걸면 두 자리가 같은
규칙이 되고 R3 세 번째 항목("둘을 같은 규칙으로 맞춘다")도 함께 닫힌다.

워크플로가 없을 때(`workflow`가 `undefined`) `key` 값이 무엇이 되는지 확인한다. 그 상태에서는 읽을
초안도 없고 입력창도 비활성이다(확인 사실 12).

### 반드시 성립해야 하는 것

- **첫 마운트에서 읽은 값을 되쓰지 않는다.** 저장은 사용자가 입력창을 고칠 때만 한다. 이 규칙이
  깨지면 완료 조건 12가 무너진다 — 비활성 상태로 화면이 그려질 때 빈 값이 저장되어 사용자의 글이
  지워진다. 뷰를 잠깐 다녀오는 것만으로도 같은 일이 난다. **이 작업에서 가장 조용히 깨지기 쉬운
  지점이다.**
- 워크플로가 없으면 읽지도 쓰지도 않는다.
- 제출에 성공하면 지역 상태와 저장된 초안이 함께 없어진다. 지금은 `IdeaComposer.tsx:17`의
  `if (await onAdd(idea.trim())) setIdea("")`가 지역 상태만 비운다. 저장된 초안도 같은 시점에
  정리되어야 한다(R2 첫 항목).
- 제출에 실패하면 지역 상태와 저장된 초안이 둘 다 남는다. 확인 사실 5의 현행 규칙을 저장된 초안까지
  넓히는 것이 이 요구사항이다(R2 두 번째 항목).
- 사용자가 입력창을 직접 비우면 저장된 초안도 없어진다(R2 세 번째 항목). 사용자 편집으로 값이 빈
  문자열이 되는 경로이므로 저장 경로가 그대로 처리한다.
- 저장에 실패해도 그 순간 화면의 글은 그대로 있고 제출도 된다(R4). 저장소가 실패를 삼키므로
  자연히 성립하지만, 배선이 저장 결과를 보고 분기하면 깨진다.

### R5 — 비활성일 때

기획서가 "초안이 보이되 제출만 막히거나, 초안을 꺼내지 않거나 둘 중 하나로 일관되게"를 요구하고
결정을 열어 두었다. **아키텍트 판단으로 "초안이 보이되 제출만 막힌다"로 정한다.** 근거는 둘이다.
첫째, `textarea`가 이미 `disabled`라 사용자가 고칠 수 없으므로 보여줘도 사고가 나지 않고, 쓰기
권한이 돌아왔을 때 글이 거기 있다는 것을 사용자가 미리 안다. 둘째, 꺼내지 않는 쪽을 고르면 "권한이
없는 동안에는 초안이 없어 보인다"가 되어 R1의 약속과 화면이 어긋난다.

어느 쪽이든 **비활성 상태가 저장된 초안을 지우지 않는다**(R5 두 번째 항목, 완료 조건 12). 위
"첫 마운트에서 되쓰지 않는다" 규칙이 이것을 지킨다.

### 바꾸지 않는 것

`IdeaComposer.tsx:24`~`:33`의 라벨·입력 id·플레이스홀더를 한 글자도 고치지 않는다. compact 분기가
`quick-idea`/`idea-inbox-input`과 두 라벨 문구를 가르는 구조도 그대로다(R6, 완료 조건 15).
`maxLength={10_000}`(`:30`)도 그대로다(완료 조건 14). 공백만 있는 글을 막는 `:16`과 버튼 비활성
조건(`:39`)도 그대로다(완료 조건 13).

## 완료 조건

1. 인박스 입력창에 글을 쓰고 다른 메뉴를 다녀오면 그 글이 남아 있다. 검증: 뷰를 전환했다 돌아오는
   테스트. (SPEC-025 완료 조건 1)
2. 오늘 화면 빠른 입력창에서도 1번이 성립한다. (완료 조건 2)
3. 저장된 값이 있는 상태에서 화면을 처음 그리면 초안이 입력창에 있다. 앱을 다시 여는 경로다.
   (완료 조건 3)
4. 한쪽에서 쓴 글이 다른 쪽 입력창에도 보인다. 검증: 두 자리를 오가는 테스트. (완료 조건 4,
   확인 필요 1번)
5. 제출해 담기면 저장된 초안이 없어진다. 검증: 제출 성공 뒤 화면을 다시 그려 입력창이 비어 있는지
   확인한다. (완료 조건 5)
6. 제출에 실패하면 초안이 남는다. 검증: `onAdd`가 거짓을 돌려주는 테스트. (완료 조건 6)
7. 입력창을 직접 비우면 저장된 초안도 없어진다. 검증: 비운 뒤 화면을 다시 그려 확인한다.
   (완료 조건 7)
8. 워크플로를 바꾸면 그 워크플로의 초안이 보이고 다른 워크플로의 초안이 보이지 않는다. 검증:
   워크플로 둘을 오가는 테스트. **오늘 화면과 인박스 양쪽에서 확인한다** — 확인 사실 8대로 지금 두
   자리의 동작이 다르다. (완료 조건 8, R3)
9. 저장된 값이 없거나 깨졌으면 빈 입력창으로 시작하고 오류가 보이지 않는다. (완료 조건 9)
10. 저장이 실패해도 입력과 제출이 정상 동작한다. 검증: 쓰기가 던지는 저장소로 그린 테스트.
    (완료 조건 10)
11. 비활성 상태로 화면을 그린 뒤 다시 활성 상태로 그리면 초안이 남아 있다. (완료 조건 12, R5)
12. 공백만 있는 글은 제출되지 않고 버튼이 비활성이다. (완료 조건 13, R6)
13. `maxLength`가 그대로다. 검증: `IdeaComposer.tsx`의 그 값에 변경분이 없다. (완료 조건 14)
14. 라벨·입력 id·플레이스홀더가 그대로다. 검증: `IdeaComposer.tsx:24`~`:33`에 문구 변경분이 없다.
    (완료 조건 15)
15. 아이디어를 담는 흐름과 결과가 달라지지 않는다. 제출 성공 시 입력창이 비워지고 목록이 갱신된다.
    (R6)
16. 기존 자동화 테스트가 삭제되거나 비활성화되지 않았다. (완료 조건 16)
17. `npm run check`가 통과한다. (완료 조건 17)

## 범위 밖

- 초안 저장소 자체. TASK-078이 만들었다. 이 작업은 그 모듈을 고치지 않는다.
- 저장 실패를 사용자에게 알리는 표시. 확인 필요 3번이 "알리지 않는다"로 승인됐다. 완료 조건 11은
  대안을 승인한 경우에만 성립하는 항목이라 이 작업의 완료 조건에서 빠졌다.
- 초안 수명. 확인 필요 4번이 "두지 않는다"로 승인됐다.
- 아이디어 인박스의 다른 지역 상태. 선택된 아이디어(`IdeaInbox.tsx:59`)와 읽어 온 본문(`:74`)은
  확인 사실 15의 값들이고 대상이 아니다. `key={workflow.directory}`가 그것들을 초기화하는 현행
  동작도 그대로 둔다.
- 마지막으로 보던 뷰를 기억하는 일(확인 사실 14).
- 기획서·개발 작업 화면의 입력 폼.
- 커서 위치나 선택 영역의 복원. R1이 명시적으로 제외한다.
- 아이디어 제출 실패 시의 오류 표시 방식. 확인 사실 5의 현행 동작 그대로다.
- 입력 제약 변경(`maxLength`, 공백 검사).
- 여러 기기·여러 창 사이의 초안 동기화.
