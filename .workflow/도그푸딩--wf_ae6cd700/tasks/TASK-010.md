# 연동 공통 모델과 카드 골격 도입 (하트비트 카드 동작 변화 없음)

SPEC-003 R1의 "연동 섹션은 특정 연동에 종속되지 않는다"를 커맨드 계층과 화면에 반영한다. 이 작업에서 dream 카드는 아직 만들지 않는다. 연동이 하나뿐인 상태로 골격만 바꾸고, 화면에 보이는 것은 지금과 같아야 한다.

동작이 그대로여야 회귀를 이 작업에서 잡을 수 있다. dream을 같이 얹으면 화면이 달라진 이유가 골격 변경 때문인지 새 카드 때문인지 구분되지 않는다.

## 의존성

- TASK-008·TASK-009 선행 필수. 공통 잡 타입과 공통 설치 상태 타입을 쓴다.
- 병행 작업 없음. TASK-011·TASK-012가 같은 프론트 파일을 만진다.

## 범위

- `src-tauri/src/application/heartbeat_service.rs` — 연동 스냅샷을 만드는 서비스로 재구성한다.
- `src-tauri/src/commands/heartbeat.rs`, `src-tauri/src/lib.rs` — 조회 커맨드를 연동 스냅샷 하나로 바꾼다.
- `src/features/projects/domain/types.ts`
- `src/features/projects/infrastructure/tauriProjectGateway.ts`
- `src/features/projects/application/useProjectWorkspace.ts`
- `src/features/projects/components/SettingsView.tsx`와 여기서 갈라져 나올 연동 컴포넌트 파일
- `src/features/projects/components/SettingsView.test.tsx`, `src/features/projects/application/useProjectWorkspace.test.ts`
- 그 외 파일은 건드리지 않는다.

## 작업 내용

### 0. 먼저 읽을 제약

- 이 작업이 끝난 뒤 설정 화면의 연동 카드는 지금과 같은 문구·같은 동작이어야 한다. 배지 세 가지(`미설치`, `설치됨 · 데몬 미실행`, `설치됨 · 데몬 실행 중`), 판정 근거 문구, 설치 안내, 역할 잡 편집·확인·쓰기 흐름 전부 그대로다.
- 조회 경로는 아무것도 쓰지 않는다. 앱 시작·프로젝트 열기·자동 새로고침·설정 화면 진입에서 전역 파일이 바뀌면 안 된다.
- 기존 테스트를 지우거나 비활성화하지 않는다. 타입·목(mock) 이름 변경에 따른 수정은 허용한다. 단언 내용을 바꿔야 한다면 동작이 바뀐 것이므로 멈추고 보고한다.

### 1. 연동 스냅샷 커맨드 (R1)

- 조회 커맨드를 연동 하나짜리(`inspect_heartbeat`)에서 연동 스냅샷 하나를 돌려주는 형태로 바꾼다. 스냅샷은 플랫폼 지원 여부 같은 섹션 공통 값과 연동별 payload를 담는다.
- 이렇게 하는 이유: 연동마다 커맨드·게이트웨이 메서드·훅 상태·2.5초 폴링 호출이 하나씩 늘어나면, 세 번째 연동을 추가할 때 공통부를 계속 고쳐야 한다. R1의 판단 기준을 깬다.
- 플랫폼 지원 여부(`supported`)는 연동별 값이 아니라 섹션 공통 값으로 올린다. 기획서 확인 필요 2번의 승인된 제안대로 Windows에서는 연동 섹션 전체를 막는 현행을 유지한다. 연동별 플랫폼 분기를 만들지 않는다.
- 쓰기 커맨드(`install_heartbeat_jobs`)는 이 작업에서 이름과 시그니처를 바꾸지 않는다.

### 2. 공통 설치 상태를 화면 문구로 되돌리기

- TASK-009가 만든 공통 상태(미설치/설치됨)와 하트비트 부가 상태(데몬 실행 여부)로 기존 세 가지 배지 문구를 만든다.
- 판정 근거 문구도 그대로 유지한다. pid 파일 존재로만 판정하고 프로세스 생존은 확인하지 않는다는 사실이 계속 화면에 드러나야 한다.

### 3. 연동 카드 공통 골격 (R1)

프론트에서 연동 섹션과 카드 본문을 분리한다.

- 섹션은 내장 연동 목록을 순회해 카드를 그린다. 섹션 코드에 하트비트 전용 타입이나 문구가 남으면 안 된다.
- 공통 골격이 책임지는 것: 연동 이름, 한 줄 설명, 설치 상태 배지, 미설치 안내 자리, 중복 잡 경고, 읽기 실패 목록, 연동별 본문 자리.
- 연동별 본문(하트비트의 역할 잡 편집 UI 등)은 그 연동만 아는 컴포넌트에 둔다.
- 내장 연동 목록은 프론트가 가진 고정 배열이다. 동적 로딩은 하지 않는다. 이번에는 항목이 하나이고 TASK-011이 둘로 늘린다.
- 판단 기준: 세 번째 연동을 추가할 때 섹션·공통 골격·배지·경고 컴포넌트를 고치지 않고, 목록에 항목 하나와 본문 컴포넌트 하나만 추가하면 되어야 한다. 리뷰에서 이 경계를 설명할 수 있어야 한다.

### 4. 훅과 게이트웨이

- 게이트웨이는 스냅샷 조회 메서드 하나를 가진다. 연동마다 메서드를 늘리지 않는다.
- 훅의 상태도 스냅샷 하나로 유지한다. 조회 실패를 화면 전체 에러로 올리지 않는 현재 동작, 쓰기 실패 문구를 2.5초 조회가 지우지 않는 현재 동작을 그대로 유지한다.
- 2.5초 인터벌에 조회를 얹는 현재 방식을 유지한다. 새 감시 장치를 만들지 않는다.

### 5. 테스트

- 기존 `SettingsView.test.tsx`의 시나리오를 유지한다. 픽스처 형태가 스냅샷으로 바뀌는 것은 허용한다.
- 아래를 추가한다.
  - 연동 목록에 항목이 하나 있을 때 카드가 하나 그려진다.
  - 배지 문구 세 가지가 각 상태에서 기존과 같게 나온다.
  - 섹션 컴포넌트가 하트비트 전용 타입을 import하지 않는다. (컴파일 경계로 확인하거나 리뷰 항목으로 남긴다)
- `useProjectWorkspace.test.ts`가 스냅샷 조회로 바뀐 뒤에도 조회 실패·쓰기 실패 동작을 검증한다.

## 완료 조건

1. 설정 화면의 연동 섹션이 내장 연동 목록을 순회해 카드를 그리고, 섹션 코드에 하트비트 전용 타입·문구가 없다. (기획서 완료 조건 3)
2. 하트비트 카드의 배지 문구, 판정 근거 문구, 설치 안내, 역할 잡 편집·확인·쓰기 흐름이 이 변경 전과 같다. (기획서 완료 조건 13, R7)
3. 조회 커맨드가 연동 스냅샷 하나를 돌려주고, 플랫폼 지원 여부가 섹션 공통 값이다. (R1, 확인 필요 2번)
4. 조회 경로에 쓰기가 없다. 앱을 켜고 프로젝트를 열어 새로고침을 여러 번 거쳐도 `~/.claude/HEARTBEAT.md`가 바뀌지 않는다. (기획서 완료 조건 14)
5. SPEC-002에서 만든 프론트 테스트가 삭제·비활성화 없이 모두 통과한다. (기획서 완료 조건 13)
6. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`이 통과한다. (기획서 완료 조건 15)


## 참고 사실

- 현재 연동 카드는 `SettingsView.tsx`의 `HeartbeatIntegrationCard`와 `HeartbeatRoleJobs` 두 컴포넌트다. 카드 골격과 역할 잡 UI가 한 파일에 섞여 있다.
- `useProjectWorkspace.ts`의 2.5초 인터벌이 `inspect`와 `inspectHeartbeat`를 함께 호출한다.
- 조회 실패 시 `integration`을 `null`로 두고 `error`만 채우는 현재 동작이 있다. 화면은 "상태를 읽을 수 없음" 배지로 표시한다. 이 경로가 스냅샷으로 바뀐 뒤에도 유지되어야 한다.
- `lib.rs`의 `invoke_handler` 목록이 커맨드 등록 지점이다.
