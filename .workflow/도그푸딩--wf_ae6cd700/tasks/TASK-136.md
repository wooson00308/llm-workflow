# 사용자 정의 규칙 조회와 저장 상태를 작업 공간에 연결한다

## 결정권자 요약

프로젝트를 열면 사용자 정의 규칙 상태를 함께 읽고, 외부 파일 변경도 다음 조회에서 감지한다.
미리보기 준비와 저장, 다시 불러오기를 설정 화면에서 사용할 수 있는 작업 공간 동작으로 제공한다.
다른 프로그램이 파일을 바꾼 경우에는 자동 병합하거나 사용자의 편집 내용을 덮어쓰지 않는다.
형식 오류와 저장 충돌은 프로젝트 오류와 분리해 문서 탐색을 계속 사용할 수 있게 한다.
자동 조회는 사용자 규칙 파일을 읽기만 하며 저장 명령을 호출하지 않는다.
이 작업은 편집 화면을 만들지 않고 상태와 동작 계약만 연결한다.

## 목적

SPEC-048의 R2, R5, R6 프런트엔드 상태 부분을 구현한다. TASK-135의 조회, 미리보기 준비, 저장 명령을
타입 안전한 게이트웨이와 작업 공간 상태로 연결한다. TASK-133이 정리한 프로젝트 열기, 수동 새로 고침,
2.5초 자동 조회의 구분을 유지한다.

## 게이트웨이 계약

프런트엔드 도메인 타입은 TASK-135의 구조화된 값을 손실 없이 표현한다.

- 파일 상태: `absent`, `valid`, `invalid`, `future_schema`, `unsafe_file`
- 조회 결과: 파싱 값, 정확한 원문, 오류, 수정 시각, 내용 식별값
- 초안: 사용 여부, 세 역할 적용 범위, Markdown 본문
- 미리보기: 정확한 저장 파일, 고정된 수정 시각, 미리보기 식별값, 역할별 세 출처와 적용 여부
- 저장 결과: `saved`, `conflict`, `retry_required`와 최신 조회 상태

게이트웨이는 조회, 미리보기 준비, 저장을 서로 다른 메서드로 제공한다. 화면에서 파일 형식을 조립하거나
내용 식별값을 계산하지 않는다.

## 작업 공간 상태와 호출 시점

프로젝트 조회 오류와 별도로 다음 상태를 둔다.

- 마지막으로 읽은 사용자 규칙 파일 상태
- 조회, 미리보기 준비, 저장의 개별 진행 여부
- 마지막 미리보기 결과
- 마지막 저장 결과와 명령 호출 오류

현재 문서 규격 프로젝트를 열면 TASK-133의 관리 규칙 동기화가 끝난 뒤 사용자 규칙을 읽는다. 수동
새로 고침도 같은 순서를 사용한다. 관리 규칙 동기화가 충돌이나 재시도 상태여도 사용자 파일 조회가
안전하게 가능하면 조회한다. 사용자 파일 오류는 현재 프로젝트를 지우거나 일반 프로젝트 오류로 바꾸지
않는다.

2.5초 자동 조회에서는 사용자 규칙 조회만 실행하고 미리보기나 저장 명령을 호출하지 않는다. 내용
식별값이 같으면 기존 상태를 유지해 불필요한 화면 갱신을 피한다. 값이 달라지면 새 디스크 상태를
보존한다. 편집 초안은 이 훅이 소유하지 않으므로 자동 조회가 사용자의 입력을 바꿀 수 없다.

프로젝트를 전환하거나 닫으면 이전 프로젝트의 사용자 규칙 상태와 미리보기를 비운다. 늦게 끝난 이전
프로젝트의 조회, 미리보기, 저장 응답이 새 프로젝트 상태를 덮어쓰지 않도록 요청 세대를 확인한다.

## 화면에 제공할 동작

- 현재 구조화된 초안으로 미리보기를 준비한다.
- 마지막으로 읽은 내용 식별값과 준비된 미리보기를 사용해 저장한다.
- 파일을 명시적으로 다시 읽는다.
- 마지막 미리보기와 저장 알림을 지운다.

저장 성공 시 반환된 최신 조회 상태를 반영하고 미리보기를 비운다. `conflict`이면 백엔드가 반환한 최신
디스크 상태를 별도로 보존하되, 화면이 가진 초안을 바꾸지 않는다. `retry_required`이면 읽은 기준과
미리보기를 유지해 같은 내용을 다시 검토할 수 있게 한다. 어떤 경우에도 자동 재시도나 자동 덮어쓰기를
하지 않는다.

## 변경 범위

- `types.ts`: 사용자 규칙 파일, 초안, 미리보기, 저장 결과, 작업 공간 상태와 동작 타입.
- `tauriProjectGateway.ts`: 조회, 미리보기 준비, 저장 명령 연결.
- `useProjectWorkspace.ts`: 프로젝트 수명과 조회 주기에 맞춘 상태, 요청 세대, 화면 동작 제공.
- 훅 검사: 호출 순서, 외부 변경 감지, 상태 격리, 늦은 응답 무시, 무쓰기 자동 조회.

## 손대지 않는 것

- 백엔드 파일 형식과 저장 구현
- 설정 카드, 편집기, 역할 선택 화면
- 초안 자동 저장과 외부 변경 자동 병합
- 실행 중인 에이전트 세션
- 여러 규칙 문서와 전역 규칙

## 완료 조건

1. 현재 문서 규격 프로젝트를 열거나 수동 새로 고침하면 관리 규칙 동기화 뒤 사용자 파일을 한 번
   읽는다.
2. 2.5초 자동 조회는 사용자 파일 조회만 호출하고 미리보기와 저장을 호출하지 않는다.
3. 파일 내용 식별값이 바뀌면 새 디스크 상태가 반영되며, 같으면 기존 상태와 알림을 불필요하게
   초기화하지 않는다.
4. 사용자 파일의 형식 오류, 미래 스키마, 안전하지 않은 파일 상태에서도 프로젝트와 문서 조회가
   유지된다.
5. 미리보기 준비 요청과 저장 요청이 백엔드 계약을 손실 없이 전달하고 결과 종류를 합치지 않는다.
6. 저장 성공은 최신 파일 상태를 반영하고, 충돌은 외부 상태를 보존하며, 잠금 재시도 결과는 사용자의
   기준과 미리보기를 자동으로 바꾸지 않는다.
7. 프로젝트 전환 뒤 이전 프로젝트의 늦은 응답이 현재 상태를 덮어쓰지 않는다.
8. 자동 저장, 자동 병합, 충돌 뒤 자동 재시도를 하지 않는다.
9. 기존 프로젝트 열기, 수동 새로 고침, 자동 조회, 관리 규칙 동기화 상태가 유지된다.
10. 기존 자동 검사를 삭제하거나 약화하지 않고 프런트엔드 전체 검사가 통과한다.

## 검증 절차

1. 게이트웨이 호출 기록으로 프로젝트 열기와 수동 새로 고침의 관리 규칙 동기화 뒤 사용자 파일 조회
   순서를 확인한다.
2. 가짜 시간을 2.5초씩 진행해 사용자 파일 조회만 늘고 미리보기와 저장 호출 수는 그대로인지 확인한다.
3. 외부 파일 내용 식별값을 바꾼 응답과 같은 응답을 차례로 돌려 상태 보존 차이를 확인한다.
4. 정상, 없음, 형식 오류, 미래 스키마, 안전하지 않은 파일을 반환해 프로젝트 상태가 유지되는지
   확인한다.
5. 저장 성공, 동시 수정 충돌, 마이그레이션 잠금, 명령 오류를 각각 반환해 상태와 후속 동작을 확인한다.
6. 프로젝트를 전환한 뒤 이전 요청을 늦게 완료해 새 프로젝트 상태가 유지되는지 확인한다.
7. `npm run check`를 실행한다.
