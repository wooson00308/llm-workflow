# 레인 접힘을 화면에 붙이고 저장소와 잇는다

TASK-095가 그린 레인에 접기를 붙이고 TASK-094의 저장소에 잇는다. SPEC-029의 R6과 완료 조건 8·9의
화면 몫을 닫는다. 제품 코드 변경은 레인 헤더의 버튼 하나와 그 상태를 저장소에 오가게 하는 배선이
전부다.

## 의존성

`depends_on: [TASK-094, TASK-095]`. 둘 다 진짜 선행이다.

- **TASK-094는 이 작업이 부를 저장소다.** 없으면 저장할 곳이 없다.
- **TASK-095는 이 작업이 버튼을 붙일 레인 헤더다.** 없으면 붙일 자리가 없고, 같은
  `DevelopmentBoard.tsx`·`App.css`를 두 세션이 동시에 고치는 일도 이 순서가 막는다. 확인 사실 19가
  가리키는 겹침이 이 기획서 안에서는 이 한 쌍이다(SPEC-029 완료 조건 15).

## 범위

- `src/features/projects/components/DevelopmentBoard.tsx` — 레인 헤더의 접기 버튼과 저장소 배선.
- `src/features/projects/components/DevelopmentBoard.test.tsx` — 단언 추가. **기존 검사는 이름도
  내용도 고치지 않는다.** TASK-095가 더한 검사도 마찬가지다.
- `src/App.css` — 접힌 레인과 접기 버튼 규칙 추가.
- 그 외 파일은 건드리지 않는다. **저장소 파일도 고치지 않는다** — TASK-094가 완성해 둔 것을 부르기만
  한다. 부르는 쪽에서 모자란 것이 나오면 고치지 말고 보고서에 적는다.

저장소에 미커밋 변경이 크다. **줄 번호는 작업 트리 기준이고, 쓰기 직전에 대상 줄을 다시 읽는다.**
TASK-095가 같은 두 파일을 이미 고쳤으므로 자리가 밀려 있다.

## 작업 내용

### 상태와 배선

- `DevelopmentBoard`가 접힘 맵을 `useState`로 들고, 초기값을 `browserSpecLaneCollapseStore.load(
  workflow.directory)`로 채운다. `workflow.directory`는 이미 프롭으로 들어와 있다.
- 접기 버튼을 누르면 그 레인의 값을 뒤집어 상태와 저장소에 함께 쓴다. `DevelopmentBoard.tsx`의
  `applyPanelWidth`(`:224` 부근)가 쓰는 어법 — 상태를 바꾸고 같은 함수에서 저장 — 을 따른다.
- **워크플로가 바뀌면 그 워크플로의 값을 다시 읽는다.** `WorkspaceShell`이 이 컴포넌트를 워크플로마다
  다시 마운트하는지 착수 시 확인하고, 마운트가 유지되는 경로가 있으면 `workflow.directory`가 바뀌는
  것을 감지해 다시 읽는다. `CalendarView`의 `selectedMonth` 비교(`:455`~`:461`)가 이 파일에 이미 있는
  같은 성격의 어법이다. **확인 결과를 보고서에 적는다.**
- **미분류 레인의 키는 TASK-094가 내보낸 상수를 쓴다.** TASK-095가 이 파일 안에 둔 상수를 그
  상수로 바꿔 하나로 맞춘다. 두 곳에 같은 문자열이 남지 않게 한다.
- **모르는 키를 지우지 않는다.** 목록에서 빠진 레인의 저장값을 정리하는 코드를 쓰지 않는다. 확인 필요
  3번의 비용 항목이 요구하는 것이다 — 빠졌다 돌아온 레인의 접힘 상태가 남아 있어야 한다.
- **저장된 값이 지금 없는 기획서를 가리켜도 화면이 깨지지 않는다.** 렌더는 지금 있는 레인만 보므로
  그냥 무시된다. 별도 처리를 만들지 말고 그렇게 되는지만 검사로 고정한다.

### 화면

- 레인 헤더에 접기 버튼을 둔다. `aria-expanded`로 상태를 밝히고, 접힌 레인은 헤더만 남기고 보드
  격자를 그리지 않는다.
- **접혀도 헤더의 집계와 신호는 그대로 보인다.** 접기의 목적이 카드를 줄이는 것이지 사실을 감추는
  것이 아니다. 신호가 켜진 레인을 접어 두고도 "지금 통째로 QA 가능"이 보여야 한다.
- 카드를 그리지 않는 것으로 접는다. `display: none`으로 숨기는 것과 결과는 같지만, 접힌 레인 26개의
  카드를 계속 그리지 않는 편이 확인 사실 7의 2.5초 주기에서 낫다.
- CSS는 `.task-lane.collapsed`와 버튼 규칙을 더한다. 기존 규칙은 고치지 않고, 같은 선택자를 두 번
  쓰지 않는다(`src/test/cssRules.ts`의 판독기가 실패로 다룬다).

### 검사 (`DevelopmentBoard.test.tsx`)

`localStorage`를 쓰는 검사이므로 `afterEach`에서 지운다. 이 파일이 이미
`vi.unstubAllGlobals()`(`:30`)를 걸어 두었으니 그 옆에 맞춘다.

1. 레인을 접으면 카드가 사라지고 헤더는 남는다. 집계와 신호가 접힌 뒤에도 보인다.
2. 다시 펼치면 카드가 돌아온다.
3. **접힌 상태가 다시 마운트한 뒤에도 남는다.** `cleanup` 후 다시 `render`해서 확인한다.
   (완료 조건 8의 화면 몫)
4. 저장 키가 `workflow-labs.spec-lane-collapse.v1`이고 워크플로 디렉터리로 갈린다. 디렉터리가 다른
   워크플로를 그리면 접힘이 따라오지 않는다. (완료 조건 8)
5. 저장된 값이 지금 없는 기획서 id를 가리켜도 화면이 뜨고 나머지 레인이 정상이다. (R6 넷째 항목)
6. `localStorage`가 던져도 화면이 뜨고 접기 동작이 그대로다. 쓰기 실패에 오류 표시가 뜨지 않는다.
   (완료 조건 9)
7. 미분류 레인도 접힌다. 저장된 키가 기획서 id와 섞이지 않는다.

## 완료 조건

괄호 안은 SPEC-029의 완료 조건 번호다.

1. 레인을 접고 펼 수 있고 접힘 상태가 다시 열었을 때 남는다. 검증: 검사 1~3. (8)
2. 키가 `workflow-labs.*.v1` 계열이고 워크플로 디렉터리로 구분된다. 검증: 검사 4. (8)
3. 다른 저장소 넷의 값을 건드리지 않는다. 검증: TASK-094의 저장소 검사 + 이 작업이 저장소 파일을
   고치지 않았다는 것(`git diff`). (8)
4. 저장소 읽기 실패·파싱 실패·쓰기 실패에 화면이 깨지지 않는다. 검증: 검사 6. (9)
5. 저장된 값이 지금 없는 기획서를 가리켜도 화면이 깨지지 않는다. 검증: 검사 5. (R6 넷째 항목)
6. 접힌 레인의 집계와 신호가 그대로 보인다. 검증: 검사 1.
7. 묶기를 끈 보드·리스트·타임라인의 동작이 달라지지 않는다. 검증: 기존 검사가 수정 없이 통과한다.
   (13)
8. 기존 자동 테스트가 삭제되거나 비활성화되지 않는다. TASK-095가 더한 검사도 그대로 통과한다. 검증:
   `git diff`로 변경이 추가뿐임을 확인한다. (14)
9. 변경분에 Rust 파일·`types.ts`·저장소 파일이 없다.
10. `npm run check`가 통과한다. (16)

## 범위 밖

- **묶기 토글의 지속.** 기획서 제외 범위다. 접힘만 기억하고 토글은 기본값에서 시작한다.
- **레인 순서·표시 여부의 저장.** 그때그때 계산하는 값이다.
- **저장소 구현 수정.** TASK-094의 산출물이다. 모자라면 고치지 말고 보고서에 적는다.
- **확인 사실 17의 QA 패널 키 이름 정리.** 기획서 제외 범위다.
- **접힘 상태의 일괄 접기/펼치기 버튼.** 기획서가 요구하지 않았다.
- **스펙 간 의존 고지.** 승인된 확인 필요 2번이 잘랐다.
