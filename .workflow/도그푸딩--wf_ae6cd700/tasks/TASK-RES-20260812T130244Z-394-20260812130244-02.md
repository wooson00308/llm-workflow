# 실행과 결과 보고서를 잇는 읽기 전용 백엔드 표면을 만든다

## 결정권자 요약

### 제안

어떤 실행이 어떤 결과 보고서를 남겼는지 앱이 직접 확인하고, 그 보고서를 읽기 전용으로 내주는 표면을 만든다.

### 현재

앱은 보고서가 몇 개인지만 알고 어떤 실행이 무엇을 남겼는지는 모른다. 실행 상세에서 결과를 열 방법이 없다.

### 변경 후

앱이 실행 기록에 담긴 예약 정보로 그 실행의 보고서를 찾아 확인하고, 확인한 것만 목록과 본문으로 내준다.

### 사용자 결과

실행이 만든 결과를 앱 안에서 여는 길이 열린다. 확인되지 않으면 다른 실행의 보고서를 대신 보여 주지 않는다.
사용자가 만나는 화면은 다음 작업에서 붙인다.

### 영향 범위

- 변경: 실행 기록이 앱에 전달하는 예약 정보, 보고서 목록과 본문을 읽는 백엔드 표면
- 유지: 보고서 파일의 내용과 상태, 문서 승인과 품질 확인 관문, 실행 배정과 취소와 재시도

### 비용과 위험

연결을 넉넉하게 맞추면 다른 실행의 보고서가 섞여 나온다. 확인하지 못한 연결은 비워 두는 쪽을 기본으로 삼는다.

### 결정 요청

QA에서는 결과를 남긴 실행과 남기지 않은 실행을 각각 조회해, 남긴 쪽만 보고서가 나오고 남기지 않은 쪽에는
아무 보고서도 나오지 않는지 확인한다.

## 확인 동선

이 작업은 백엔드 조회만 만들었고 사용자가 열어 볼 화면은 만들지 않았다. 실행 요약에서 보고서를 여는
화면은 뒤따르는 작업이 붙인다. 그래서 이번 확인에는 눌러 볼 자리가 없고, 확인 도장은 아래 자동 검사
결과를 신뢰한다는 뜻이다.

검사를 직접 돌려 확인하려면 프로젝트 루트에서 다음 두 명령을 실행한다.

- `cargo test --manifest-path src-tauri/Cargo.toml`
  기대 결과: 실패 0건. 라이브러리 검사 732건과 통합 검사 20건이 통과한다.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets`
  기대 결과: 경고 0건.

이번 작업이 새로 더한 검사만 보려면 다음 명령을 실행한다.

- `cargo test --manifest-path src-tauri/Cargo.toml report_surface_tests`
  기대 결과: 7건 통과. 보고서 목록이 개수 집계와 일치하는지, 대상 문서 식별자만 있을 때와 예약 결과
  접두어만 있을 때와 둘 다 있을 때 연결이 각각 맞는지, 두 값이 모두 없으면 빈 목록이 나오는지,
  본문이 그대로 나오고 파일이 변경되지 않는지, 디렉터리를 벗어나는 파일 이름이 거절되는지를 확인한다.
- `cargo test --manifest-path src-tauri/Cargo.toml reservation_result_prefix`
  기대 결과: 라이브러리 1건과 통합 1건이 통과한다. 예약 결과 접두어가 있는 실행 행과 없는 실행 행이
  모두 오류 없이 읽히고, 없는 쪽은 값이 비어 있다.

결정 요청에 적힌 "결과를 남긴 실행과 남기지 않은 실행"의 구분은 위 검사 중 연결 판정 4건이 확인한다.
남기지 않은 쪽에 다른 실행의 보고서가 섞이지 않는지도 그 검사가 함께 확인한다.

## 범위 사전 검사

이 작업이 다루는 값은 둘이다. 실행 행의 예약 결과 접두어가 앱까지 오는 경로와, 보고서 문서가 목록과 본문으로
앱까지 오는 경로다. 두 경로를 실제 코드와 실제 파일 이름에서 확인했다.

- 값 경로: 완료 조건 1의 예약 결과 접두어는 런타임이 이미 만들고 저장한다. `../../Git/claude-heartbeat`의
  `agent_dispatch.py`에 있는 `_new_run_row`가 `resultPrefix` 키를 만들고 예약 성공 시 같은 파일에서 값을 채우며,
  `agent_store.py`의 `_run_for_state`가 저장 행 전체를 그대로 조회 응답에 싣는다. 런타임 계약 문서의 복구 절도 실행
  행이 이 값을 담는다고 이미 적고 있다. 따라서 런타임은 이 값을 변경 없이 나르며 이 작업의 범위 밖이다.
  값이 앱에서 사라지는 자리는 `src-tauri/src/domain/agent_runtime.rs`의 `RunSummary`다. 이 구조체에 대응 필드가 없어
  역직렬화가 값을 버리므로 여기를 편집한다. 같은 파일을 쓰는 `src-tauri/src/application/agent_runtime_status_service.rs`의
  `inspect`는 행을 통째로 `RunSummary`로 역직렬화할 뿐 키를 고르지 않으므로 편집 없이 새 필드를 나른다.
- 값 경로: 완료 조건 2·3의 보고서 목록은 `src-tauri/src/infrastructure/fs_project_repository.rs`가 만든다. 이 파일의
  `workflow_counts`는 현재 보고서 디렉터리의 마크다운 개수만 세고 파일 이름을 남기지 않으므로, 이름과 연결 근거를
  돌려주는 조회를 새로 더한다. 그 반환 형태는 `src-tauri/src/domain/project.rs`에 있어야 화면까지 같은 이름으로
  전달되므로 그 파일도 편집한다. 개수를 싣는 `WorkflowCounts`는 그대로 두며, 이 작업은 개수를 대체하지 않고 옆에 목록을
  더한다.
- 값 경로: 완료 조건 4의 보고서 본문은 `src-tauri/src/commands/projects.rs`가 화면에 내준다. 같은 파일의 `read_spec`,
  `read_task`, `read_idea`가 이미 문서 하나를 읽어 돌려주는 선례이고, 세 명령 모두 `src-tauri/src/lib.rs`의 명령 등록
  목록에 올라 있어야 호출된다. 두 파일 모두 새 명령을 위해 편집한다.
- 값 경로: 완료 조건 3의 연결 판정 근거는 실제 파일 이름에서 확인했다. 보고서 파일에는 앞머리 메타데이터가 없고
  이름이 유일한 식별 수단이다. 개발 작업 보고서는 대상 작업 식별자를 이름에 담고, 기획과 아키텍트 보고서는 그 실행이
  만든 문서 식별자를 담으며 그 식별자 안에 예약 결과 접두어가 들어 있다. 따라서 연결은 실행 행의 대상 식별자와 예약
  결과 접두어 두 값으로만 판정할 수 있고, 그 밖의 추측은 하지 않는다.
- 검토했으나 제외한 것: `src/features/projects/infrastructure/tauriProjectGateway.ts`와 화면 구성 요소는 이 작업의
  범위에 넣지 않는다. 이 작업의 완료 조건은 모두 백엔드 응답으로 확인할 수 있고, 화면 연결은 뒤따르는 작업이 같은
  파일들을 함께 고치므로 지금 손대면 겹침만 늘어난다.
- 검토했으나 제외한 것: `src-tauri/src/application/agent_runtime_status_service.rs`는 바로 위에서 확인한 대로 새 필드를
  이미 변경 없이 나른다. 편집이 필요 없으므로 선언에서 뺀다.

## 현재 상태

앱이 받는 실행 요약에는 실행 식별자, 프로젝트, 역할, provider, 상태, 대상 문서, 시작과 종료 시각, 실패 단계와 사유,
남은 정리 항목, 이전 실행 식별자가 있다. 예약 결과 접두어는 런타임 응답에 이미 들어 있지만 앱이 구조체로 옮기지
않아 버려진다. 보고서는 개수만 집계되고 파일 이름도 본문도 앱으로 오지 않는다.

## 변경 범위

1. 실행 요약에 예약 결과 접두어를 선택 값으로 추가한다. 값이 없는 구형 응답도 그대로 읽혀야 한다.
2. 워크플로 하나의 보고서 목록을 돌려주는 조회를 더한다. 항목은 파일 이름과 화면에 쓸 제목을 담는다.
3. 실행 하나에 연결된 보고서만 돌려주는 판정을 더한다. 입력은 그 실행의 대상 문서 식별자와 예약 결과 접두어이며,
   둘 중 어느 것도 없으면 빈 목록을 돌려준다. 이름이 두 값 중 하나를 담은 파일만 연결로 인정하고, 실제로 존재하는
   파일만 돌려준다. 다른 실행의 보고서를 채워 넣지 않는다.
4. 보고서 하나의 본문을 읽어 돌려주는 명령을 더한다. 기존 문서 읽기 명령과 같은 자리에 두고 같은 방식으로 등록한다.
   이 명령은 파일을 쓰지 않고 상태를 바꾸지 않는다.
5. 워크플로 디렉터리 밖의 경로를 파일 이름으로 받아 읽는 일이 없도록 입력을 검사한다.
6. 문서 규격 설명에 보고서 읽기 표면과 실행 연결 판정 근거를 적는다.

## 범위 밖

- 보고서 본문 편집, 삭제, 상태 변경
- 보고서 개수 집계의 제거나 의미 변경
- 화면 구성 요소, 화면과 백엔드를 잇는 호출 계층
- 실행 배정, 취소, 재시도, 문서 승인과 품질 확인의 의미 변경

## 완료 조건

1. 예약 결과 접두어를 담은 런타임 실행 행을 읽으면 그 값이 앱의 실행 요약까지 전달된다. 그 값이 없는 실행 행도
   오류 없이 읽히고 값은 비어 있다.
2. 보고서 목록 조회가 워크플로의 보고서 파일 이름을 모두 돌려주고, 개수 집계와 어긋나지 않는다.
3. 실행 연결 판정이 다음을 모두 만족한다. 대상 문서 식별자를 이름에 담은 보고서가 있으면 그 보고서를 돌려준다.
   예약 결과 접두어를 이름에 담은 보고서가 있으면 그 보고서를 돌려준다. 두 값 어디에도 해당하지 않는 보고서는
   돌려주지 않는다. 두 값이 모두 비어 있으면 빈 목록을 돌려준다.
4. 보고서 본문 읽기 명령이 파일 내용을 그대로 돌려주고, 호출 뒤에도 보고서 파일과 다른 워크플로 문서가 변경되지 않는다.
5. 워크플로 디렉터리를 벗어나는 파일 이름을 넘기면 읽지 않고 실패를 돌려준다.
6. 문서 규격 설명에 이 표면과 연결 판정 근거가 적혀 있다.

## 검증 단계

1. 실행 요약 역직렬화 검사를 추가하고 실행한다. 예약 결과 접두어가 있는 행과 없는 행을 모두 확인한다.
   명령: `cargo test --manifest-path src-tauri/Cargo.toml`
2. 임시 워크플로에 이름이 다른 보고서 여러 개를 만들고, 완료 조건 3의 네 경우를 각각 확인하는 검사를 추가한다.
   명령: `cargo test --manifest-path src-tauri/Cargo.toml`
3. 디렉터리를 벗어나는 파일 이름을 넘기는 검사를 추가하고 실패로 끝나는지 확인한다.
   명령: `cargo test --manifest-path src-tauri/Cargo.toml`
4. 정적 검사를 실행한다. 명령: `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets`
