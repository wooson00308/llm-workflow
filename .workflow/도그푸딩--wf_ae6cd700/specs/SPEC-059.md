# 끝난 작업 그룹을 개발 작업 화면 전체에서 감춘다

## 결정권자 요약

### 제안

품질 확인까지 끝난 작업 그룹을 개발 작업 화면의 모든 목록과 수치에서 감춘다. 지금은 작업 그룹별
보기 한 곳에서만 감춰지고 있어, 같은 화면의 다른 보기에는 끝난 일이 그대로 남아 있다.

### 현재

개발 작업 화면은 보기 방식이 세 가지이고, 그중 작업 그룹별 보기만 끝난 그룹을 빼고 그린다. 평면
보기와 리스트는 끝난 그룹의 작업까지 모두 그리고, 화면 위의 진행 중·막힘·완료 수치도 그 작업들을
함께 센다. 2026-08-16 기준으로 작업 186건 가운데 129건이 이미 끝난 그룹에 속해 있고, 완료 칸에는
그 129건이 계속 쌓여 있다. 남은 일은 사용자 품질 확인을 기다리는 그룹 18개뿐인데 화면 수치는 이
사실을 말해 주지 않는다.

### 변경 후

개발 작업 화면이 아직 끝나지 않은 일만 다룬다. 어떤 보기로 바꿔도 목록에 남는 것은 진행 중이거나
막혔거나 품질 확인을 기다리는 작업이고, 화면 위의 수치도 그 범위만 센다. 완료 칸은 지금 흐름에서
방금 끝난 작업만 보여주므로 어디까지 왔는지 한눈에 읽힌다. 끝난 그룹은 지금처럼 기록 화면에서
그대로 열어 본다.

### 비용과 위험

감춰지는 것은 목록의 표시뿐이고 문서는 하나도 바뀌지 않는다. 승인하지 않으면 지금 화면이 그대로
유지되며, 승인 후에도 기록 화면과 문서가 그대로 남아 있으므로 되돌리는 데 드는 비용은 표시 규칙
하나를 되돌리는 정도다. 위험은 사용자가 최근에 끝낸 작업을 개발 작업 화면에서 찾다가 못 찾는
경우이며, 감춘 건수와 기록 화면을 안내하는 문구로 대응한다.

## 기획 내용

### 문제

IDEA-A4F61778은 "개발 뷰에서 작업 그룹이 품질 확인까지 끝나면 감추는 것이 어떤지"를 묻는다. 질문
형태이므로 감출지 여부와 감추는 범위를 이 기획서에서 판단한다.

개발 작업 화면의 목적은 지금 무엇이 돌아가고 무엇이 막혀 있는지 보는 것이다. 끝난 그룹의 작업은 그
판단에 쓰이지 않는데도 목록의 대부분을 차지한다. 프로젝트가 오래될수록 완료 칸만 길어지고, 화면
위의 완료 수치는 누적 총계가 되어 "이번 흐름에서 어디까지 왔는지"를 읽을 수 없게 된다.

### 확인한 사실 (2026-08-16 기준)

- 개발 작업 화면의 보기는 보드, 리스트, 타임라인 세 가지다. 보드는 다시 작업 그룹별 보기와 평면
  보기로 나뉘고, 기본값은 작업 그룹별 보기다.
- 작업 그룹별 보기는 이미 완료와 자동 완료 상태의 그룹을 목록에서 제외하고, 아래에 "완료된 작업
  그룹 N개는 기록 화면에 있습니다"라는 안내를 한 줄 보여준다. 아이디어가 말한 감춤은 이 한 곳에서만
  구현돼 있다.
- 평면 보기와 리스트는 그룹을 보지 않고 작업 전체를 그린다. 그래서 같은 화면에서 보기만 바꾸면 방금
  사라졌던 작업들이 다시 나타난다.
- 화면 머리의 진행 중 수치, 그 아래 요약 띠의 진행 중·막힘·완료 수치, 표시 건수 모두 작업 전체를
  대상으로 센다.
- 작업 그룹 56개 가운데 38개가 이미 끝났다. 자동 확인 방식이 36개, 사용자 품질 확인을 통과한 것이
  2개다. 남은 18개는 모두 사용자 품질 확인을 기다리는 상태다.
- 작업 186건은 모두 완료 상태이며, 그중 129건이 위 38개 그룹에 속한다. 개발 작업 화면에서 판단에
  쓰이는 것은 나머지 57건이다.
- 위 수치는 문서를 직접 세어 얻은 값이다. 앱은 자동 확인 방식 그룹에 대해 확인 시점 이후 코드가
  바뀌었는지를 한 번 더 보고, 어긋나면 그 그룹을 개발 중으로 되돌린다. 그래서 화면에서 실제로
  감춰지는 건수는 이 값과 조금 다를 수 있다.
- 기록 화면은 이미 끝난 그룹의 정본 목록을 가지고 있다. 승인·폐기된 기획서와 함께 시간순으로
  나열하고, 그룹을 열면 확인 방식, 구성 버전, 사용자 확인 플로우, 포함된 작업 목록까지 보여준다.
  개발 작업 화면에서 감춰도 사용자가 잃는 정보는 없다.

### 감춤 기준으로 무엇을 쓰는가

이미 작업 그룹별 보기가 쓰고 있는 기준을 그대로 확장한다. 감추는 대상은 사용자 품질 확인을 통과한
그룹과 자동 확인으로 닫힌 그룹 두 가지다.

자동 확인으로 닫힌 그룹도 감추는 대상에 넣는다. 아이디어의 표현은 "품질 확인까지 끝나면"이지만, 두
상태 모두 사용자가 더 할 일이 없고 두 상태 모두 기록 화면의 완료된 기능 목록에 들어간다. 이미
작업 그룹별 보기가 두 상태를 같이 다루고 있으므로, 여기서 기준을 갈라 놓으면 보기마다 다른 목록이
나오는 지금 문제가 형태만 바뀌어 남는다.

사용자 품질 확인을 기다리는 그룹은 감추지 않는다. 그 그룹은 사용자의 결정이 남아 있는 일이고,
2026-08-16 기준 남은 18개 그룹이 모두 여기에 해당한다. 아키텍트 재분류를 기다리는 그룹도 감추지
않는다.

### 타임라인을 그대로 두는 이유

타임라인은 이 기획서의 감춤 대상에서 뺀다. 타임라인은 작업의 상태 변화 사건을 달력 위에 놓는
기록형 보기이고, 화면 스스로 전체 이력을 보여준다고 밝히고 있다. 끝난 그룹을 빼면 지나간 달이 거의
비어 버려 보기의 목적 자체가 사라진다.

이것은 기본 판단이다. 타임라인까지 함께 감추기를 원한다면 수정 요청으로 돌려보내면 된다.

### 소속을 확인할 수 없는 작업

감춤은 끝난 그룹에 속한다고 확인된 작업에만 적용한다. 소속 그룹을 찾을 수 없거나 그룹과 작업의
출처가 어긋나 소속을 확정할 수 없는 작업은 계속 보여준다. 그런 작업은 끝났다고 판단할 근거가
없으며, 감추면 사용자가 확인해야 할 구성 오류가 화면에서 사라진다.

## 요구사항 명세

- R1. 개발 작업 화면의 보드와 리스트는 같은 작업 범위를 대상으로 그린다. 그 범위는 끝난 작업 그룹에
  속하지 않는 작업이다. 보기를 바꿔도 목록에 나오는 작업의 집합은 달라지지 않는다.
- R2. 끝난 작업 그룹은 사용자 품질 확인을 통과한 그룹과 자동 확인으로 닫힌 그룹 두 가지다. 사용자
  품질 확인을 기다리는 그룹, 아키텍트 재분류를 기다리는 그룹, 구성 확인이 필요한 그룹, 아직 개발이
  남은 그룹은 감추지 않는다.
- R3. 화면 머리의 진행 중 수치와 요약 띠의 진행 중·막힘·완료 수치, 표시 건수는 R1의 범위만 센다.
  감춘 작업은 어느 수치에도 들어가지 않는다.
- R4. 검색과 상태 필터는 R1의 범위 안에서 동작한다. 감춘 작업은 검색어를 넣어도 개발 작업 화면의
  보드와 리스트에 나오지 않는다.
- R5. 소속 그룹을 확정할 수 없는 작업은 감추지 않는다.
- R6. 감춘 사실을 화면이 말한다. 감춘 그룹이 하나라도 있으면 보드와 리스트에 감춘 그룹의 개수와 그
  그룹들이 기록 화면에 있다는 안내를 보여준다. 문구는 작업 그룹별 보기가 지금 쓰는 안내와 같은
  내용으로 맞춘다.
- R7. 타임라인 보기는 바뀌지 않는다. 지금처럼 전체 이력을 그대로 보여준다.
- R8. 작업 상세 화면은 바뀌지 않는다. 감춤은 목록의 표시 범위일 뿐이며, 기록 화면에서 그룹을 열어
  포함된 작업을 보는 경로도 지금 그대로다.
- R9. 기록 화면은 바뀌지 않는다. 끝난 그룹의 정본 목록은 계속 기록 화면이 가진다.
- R10. 이 변경으로 어떤 문서 파일도 바뀌지 않는다. 작업 문서, 작업 그룹 문서, 결정 기록, 앱이
  설치하는 규칙 문언과 역할 계약은 그대로이며 규칙 버전도 오르지 않는다.

## 검수 기준

1. 개발 작업 화면에서 작업 그룹별 보기와 평면 보기를 번갈아 열면 두 보기에 같은 작업만 나온다.
2. 리스트 보기에도 끝난 그룹의 작업이 나오지 않는다.
3. 화면 위의 완료 수치와 표시 건수가 끝난 그룹의 작업을 빼고 세어진다. 2026-08-16 기준 데이터에서
   표시 건수가 186에서 57로 줄어든다.
4. 사용자 품질 확인을 기다리는 그룹의 작업은 모든 보기에 그대로 보인다.
5. 소속 그룹을 확정할 수 없는 작업은 모든 보기에 그대로 보인다.
6. 감춘 그룹이 있을 때 보드와 리스트 아래에 감춘 개수와 기록 화면 안내가 보인다. 감춘 그룹이 없으면
   그 안내가 나오지 않는다.
7. 검색어를 넣어도 감춘 작업이 보드와 리스트에 나오지 않는다.
8. 타임라인 보기의 표시 내용이 변경 전과 같다.
9. 기록 화면에서 끝난 그룹을 열면 확인 방식, 구성 버전, 사용자 확인 플로우, 포함된 작업 목록이
   변경 전과 같이 보인다.
10. 변경 전후로 문서 파일의 내용과 규칙 버전이 같다.

## 범위 밖

- 사용자가 감춤을 켜고 끄는 설정. 지금은 감출지 말지를 판단하는 단계이며, 설정을 먼저 만들면 판단을
  미루는 것이 된다.
- 감춘 그룹을 개발 작업 화면 안에서 다시 펼쳐 보는 별도 영역. 그 목록은 기록 화면이 이미 가지고
  있다.
- 안내 문구를 눌러 기록 화면으로 이동하는 입구화. 지금 안내는 문장 한 줄이며, 이 기획서는 그
  형태를 바꾸지 않는다.
- 타임라인 보기의 표시 범위 변경.
- 기록 화면의 구성과 정렬 변경.
- 작업 그룹의 상태 판정 규칙 변경. 어떤 그룹이 끝났는지는 지금 판정을 그대로 쓴다.

## 기대효과

- 개발 작업 화면이 지금 판단해야 할 일만 보여주므로, 보기를 바꿀 때마다 목록이 달라지는 혼란이
  사라진다.
- 완료 수치가 누적 총계가 아니라 지금 흐름의 진행도를 뜻하게 되어, 화면 위 수치만 보고 남은 일을
  가늠할 수 있다.
- 프로젝트가 오래되어 작업이 쌓여도 개발 작업 화면의 목록 길이가 남은 일의 양을 따라간다.
