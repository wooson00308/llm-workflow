# 에이전트 실행 기록을 사용자 요약과 진단 번들로 재설계한다

## 결정권자 요약

### 제안

실행 이벤트 나열을 사람이 읽는 실행 요약과 이상 신호로 바꾼다. 실행 상세에서 결과 보고서를 바로 열고,
문제가 생기면 실행 정보와 민감정보가 제거된 원본 이벤트를 한 개의 진단 번들로 저장하거나 복사한다.

### 현재

화면은 시작, 진행, 도구 이벤트의 종류를 줄단위로 나열한다. 런타임은 작업 지시와 인증 값을 보존하지 않으므로,
이 나열만으로는 사용자가 진행과 결과를 판단하기 어렵고 개발자에게 문제를 재현할 자료도 전달하기 어렵다.

### 변경 후

실행 상세는 대상, 경과 시간, 결과와 사유, 도구 사용 집계, 마지막 활동, 결과 보고서를 한 카드에 보여 준다.
개별 줄은 시작과 종료, 실패 상세, 일정 시간 활동이 없는 신호만 남기고, 전달용 진단 번들을 현재 정보로 만든다.

### 사용자 결과

사용자는 반복되는 종류 나열 대신 실행이 무엇을 했고 어떻게 끝났는지를 바로 읽는다. 문제가 생기면 한 번의 저장이나
복사로 개발자가 필요로 하는 진단 자료를 전달한다.

### 영향 범위

- 변경: 실행 상세 표시, 도구 이벤트의 정보 범위, 보고서 열람 표면, 진단 번들 내보내기
- 유지: 작업 지시와 인증 값을 보존하지 않는 원칙, 실행 배정과 취소와 재시도, 문서 상태와 사용자 판단 관문

### 비용과 위험

앱과 런타임의 계약을 함께 변경해야 한다. 진단 번들이 기존 민감정보 비보존 경계를 넓히지 않도록 도구 이름만 허용하고,
인자와 결과 내용을 저장과 표시와 내보내기 모두에서 제외해야 한다.

### 결정 요청

실행 기록을 사용자 요약과 이상 신호로 바꾸고, 보고서 열람과 진단 번들과 도구 이름 집계를 함께 도입할지 결정한다.
승인하지 않으면 현재의 종류 나열과 보고서 개수만 제공하는 표면이 그대로 남는다.

## 기획 내용

### 배경

IDEA-79A384D4는 2026-08-12에 실행 하나의 이벤트 흐름이 시작 1건, 진행 8건, 도구 22건으로
구성됐지만 화면에서는 이를 이벤트 종류 줄로만 읽을 수 있었다는 실측을 기록한다. 이 표시는 런타임의
민감정보 비보존 원칙과 결합하면 사용자 판단에도, 개발자 진단에도 충분하지 않다.

문제는 원본 트랜스크립트를 더 많이 저장해서 풀 수 없다. 작업 지시와 인증 값을 저장하지 않는 것은 런타임의
안전 경계이다. 따라서 이 기획은 이미 보존하는 정보를 사용자와 개발자의 판단 목적에 맞게 재구성한다.

### 확인한 현재 표면

- 실행 상세의 `safeEvent` 경로는 이벤트의 `kind`, `stage`, `status`, `message`, `detail` 문자열을
  골라 중간점으로 이어 붙인 뒤 순서 목록으로 보여 준다. 도구 이벤트가 많으면 같은 종류의 줄이 그대로 늘어난다.
- 앱의 `RunLogPage`는 실행 식별자, 해석하지 않는 이벤트 배열, 다음 cursor만 싣는다. 상태 서비스는 런타임이
  이미 민감정보를 제거했다는 계약 아래 이 이벤트를 그대로 전달한다.
- `RunSummary`에는 역할, provider, 상태, 대상, 시작과 종료 시각, 실패 단계와 사유가 있다. 실행별 마지막 활동,
  도구 집계, 결과 문서 참조는 없다.
- 프로젝트 요약의 `WorkflowCounts.reports`는 보고서 개수만 싣고, `WorkflowItems`는 아이디어와 기획서와 개발 작업만
  싣는다. 화면이 특정 실행의 결과 보고서를 열 수 있는 읽기 표면이 없다.
- 큐 상태는 최근 오류 배열과 provider 진단 결과를 가지고 있지만, 특정 실행의 원본 이벤트와 메타정보와 함께
  전달할 단일 내보내기 경로는 없다.

### 확정안

확정안은 사용자용 실행 요약, 개발자 전달용 진단 번들, 도구 이름만 담는 이벤트 확장 세 부분으로 구성된다.
요약이 사용자의 판단을 담당하고, 번들이 개발자 진단을 담당하며, 도구 이름이 두 표면에 필요한 최소 정보를 제공한다.

#### 사용자용 실행 요약과 이상 신호

실행 상세는 기본적으로 요약 카드 하나를 보여 준다. 카드는 대상 문서와 제목, 역할과 provider, 시작 시각과 경과 또는
소요 시간, 현재 상태나 종료 결과, 사유 문장, 총 도구 사용 횟수와 유형별 집계, 마지막 활동 시각을 한데 묶는다.

이벤트 줄은 시작, 성공과 실패와 취소를 포함한 종료, 민감정보 제거를 거친 실패 상세, 활성 실행의 활동 없음
신호만 남긴다. 진행과 도구 이벤트는 요약 집계에만 반영하고 개별 줄로 나열하지 않는다.

활성 실행에서 마지막 이벤트 후 5분간 새 이벤트가 없으면 `5분간 활동 없음`을 이상 신호로 보여 준다. 이것은 실패
판정이 아니라 사용자가 취소나 관찰을 판단하기 위한 신호다. 새 이벤트가 오면 신호를 즉시 제거하고 마지막 활동 시각을 갱신한다.

실행이 남긴 보고서가 있으면 요약 카드에 바로가기를 더한다. 연결은 화면이 파일 이름을 추측하지 않고 백엔드가 확인한
실행 결과 참조를 사용한다. 연결을 확인할 수 없으면 다른 실행의 보고서를 대신 보여 주지 않는다. 사용자는 바로가기에서 보고서를
읽기 전용으로 열 수 있다.

#### 개발자 전달용 진단 번들

실행 상세는 활성과 종료 상태에서 모두 `진단 번들 내보내기`를 제공한다. 같은 내용을 로컬 파일 하나로 저장하거나
클립보드에 복사할 수 있다. 내보내기는 이슈를 자동 업로드하거나 외부 서비스에 전송하지 않는다.

번들은 다음 정보를 하나의 버전화된 구조로 담는다.

1. 실행 식별자, 프로젝트와 대상 문서, 역할, provider와 그 버전, 시작과 종료 시각, 상태, 실패 단계와 사유 코드
2. 순서와 타임스탬프를 보존한 런타임 원본 이벤트 기록
3. 내보내는 시점의 provider 진단 결과와 런타임 진단 결과
4. 해당 프로젝트의 최근 오류 기록. 각 기록의 시각과 단계와 사유 코드를 포함한다.
5. 번들 규격 버전과 생성 시각, 읽지 못한 항목과 그 사유

원본 이벤트라는 말은 런타임이 저장한 민감정보 제거 후 이벤트를 뜻한다. 번들을 위해 작업 지시, 프롬프트, 인증 값,
환경 변수, 도구 인자와 도구 결과 본문을 새로 수집하지 않는다. 진단과 오류 항목을 읽지 못해도 읽을 수 있는 부분을 내보내고,
누락과 사유를 명시한다. 성공으로 추측하거나 빈 값을 조용히 채우지 않는다.

#### 도구 이름만 담는 이벤트

런타임의 공통 이벤트 계약은 도구 사용 이벤트에 선택적인 도구 이름을 담는다. Claude와 Codex 정규화 경로는 provider가 준
도구 사용 블록의 이름만 추출하고 인자와 입력과 결과 내용은 이벤트에 싣지 않는다.

화면은 알려진 도구 이름을 파일 읽기, 파일 편집, 명령 실행, 검색과 같은 안정적인 유형으로 묶어 횟수를 보여 준다. 알지 못하는
이름은 사용자 화면에 원문을 노출하지 않고 `기타`로 집계한다. 진단 번들에는 런타임이 허용한 이름 값만 남는다.

기존 이벤트처럼 도구 이름이 없는 기록도 계속 읽힌다. 이 경우 총 도구 횟수는 계산하되 유형별 집계는 `이름 없음`으로 분리해
새 정보가 있는 것처럼 추측하지 않는다.

### 요구사항 명세

#### 사용자 요약과 이상 신호

- R1. 실행 상세는 이벤트 전체 나열 대신 요약 카드를 기본 표면으로 제공한다.
- R2. 요약 카드는 대상 문서와 제목, 역할과 provider, 시작 시각과 경과 또는 소요 시간, 상태와 결과, 사유,
  총 도구 횟수와 유형별 횟수, 마지막 활동 시각을 보여 준다.
- R3. 진행과 도구 이벤트는 요약 집계에 반영하고 개별 줄로 나열하지 않는다.
- R4. 개별 줄은 시작, 종료, 민감정보를 제거한 실패 상세, 5분 활동 없음 신호만 보여 준다.
- R5. 활성 실행에서 마지막 이벤트 후 5분이 지나면 활동 없음 신호를 표시한다. 새 이벤트가 오면 제거하며 실패로 전환하지 않는다.
- R6. 로그나 상태를 읽지 못한 항목은 모름으로 표시하고 지난 값을 현재 사실로 추측하지 않는다.

#### 결과 보고서 열람

- R7. 백엔드는 보고서 개수와 별개로 읽기 전용 보고서 요약과 본문을 제공하는 표면을 만든다.
- R8. 특정 실행과 보고서의 연결은 백엔드가 확인하여 응답한다. 화면이 파일 이름이나 경로를 추측하지 않는다.
- R9. 실행에 연결된 보고서가 있으면 요약 카드에 바로가기를 보여 주고, 선택하면 앱 안에서 읽기 전용 본문을 연다.
- R10. 연결을 확인할 수 없으면 보고서가 없음을 만들어 내지 않고, 다른 실행의 보고서를 연결하지 않는다.

#### 도구 이름과 집계

- R11. 도구 이벤트는 도구 이름만 추가로 담을 수 있다. 도구 인자, 입력, 표준 출력과 결과 본문은 담지 않는다.
- R12. Claude와 Codex 정규화 경로가 같은 선택 필드를 사용하고, 알려진 이름은 안정적인 사용자 유형으로 묶어 횟수를 보여 준다.
- R13. 알지 못하는 도구 이름은 화면에서 `기타`로 표시하고, 이름이 없는 기존 이벤트는 `이름 없음`으로 집계한다.
- R14. 도구 이름이 없는 기존 이벤트와 알지 못하는 이벤트를 읽어도 실행 상세가 깨지지 않는다.

#### 진단 번들

- R15. 실행 상세는 로컬 파일 저장과 클립보드 복사를 제공하며, 두 결과는 같은 버전화된 진단 내용을 사용한다.
- R16. 번들은 실행과 provider 메타정보, 상태와 사유, 원본 이벤트, 내보내기 시점의 진단 결과, 최근 오류, 규격 버전과 생성 시각을 담는다.
- R17. 이벤트는 런타임이 저장한 순서와 타임스탬프를 보존하고, 진단과 오류 항목은 시각과 단계와 사유 코드를 포함한다.
- R18. 읽지 못한 진단과 오류는 번들 생성 전체를 막지 않고, 누락된 항목과 사유를 번들 안에 명시한다.
- R19. 번들 생성은 외부 업로드나 이슈 생성을 수행하지 않으며, 사용자가 저장과 복사 중 하나를 명시적으로 선택한 때만 실행한다.
- R20. 번들은 작업 지시, 프롬프트, 인증 값, 환경 변수, 도구 인자와 도구 결과 본문을 새로 수집하거나 싣지 않는다.

#### 보존할 계약

- R21. 실행 배정, 일시 정지, 취소, 재시도, 복구 필요 판정과 프로젝트별 실행 한도의 의미를 변경하지 않는다.
- R22. 문서 상태, 선점, 기획 승인과 사용자 품질 확인 관문을 변경하지 않는다.
- R23. 구형 런타임이 도구 이름이나 추가 진단을 제공하지 않아도 기본 요약과 실행 제어가 동작하고 부재를 모름으로 표시한다.

## 검수 기준

1. 시작 1건, 진행 8건, 도구 22건인 실행을 열면 개별 진행과 도구 30줄은 보이지 않고, 요약 카드에 도구 22회와 마지막 활동이 보인다.
2. 실행 중, 성공, 실패, 취소, 복구 필요 상태에서 대상과 시간과 결과와 사유가 각각 현재 사실과 일치한다.
3. 활성 실행의 마지막 이벤트 후 5분이 지나면 활동 없음 신호가 나타나고, 새 이벤트를 받으면 사라지며 실행 상태는 자동으로 실패가 되지 않는다.
4. 실패 이벤트의 세부 내용은 런타임이 제공한 민감정보 제거 후 전문으로 보이고, 성공 요약으로 바꾸어 표시하지 않는다.
5. 실행에 연결된 보고서가 있으면 요약 카드에서 열리고, 없거나 연결을 확인할 수 없으면 다른 실행의 보고서가 노출되지 않는다.
6. 보고서 바로가기를 선택하면 본문이 읽기 전용으로 열리고 보고서 파일이나 다른 워크플로 문서는 변경되지 않는다.
7. Claude와 Codex의 가짜 도구 이벤트에서 이름만 공통 필드에 남고 인자, 입력, 결과 내용과 가짜 인증 값은 이벤트와 앱 응답 전체에 없다.
8. 파일 편집, 명령 실행, 검색 도구를 섞으면 유형별 횟수와 총 횟수가 원본 이벤트와 같다.
9. 도구 이름이 없는 구형 이벤트는 총 횟수에 포함되고 이름 없음으로 분리되며, 알지 못하는 이름은 기타로 표시되고 화면이 깨지지 않는다.
10. 진단 번들을 파일로 저장한 결과와 클립보드에 복사한 결과가 같은 규격 버전과 실행 내용을 가진다.
11. 번들에 실행 메타정보, 사유 코드, 순서가 보존된 이벤트, 진단 결과, 최근 오류가 들어 있고 읽지 못한 항목은 누락 사유를 가진다.
12. 작업 지시, 프롬프트, 인증 값, 환경 변수, 도구 인자와 도구 결과 본문에 고유한 가짜 문자열을 주입한 뒤 이벤트, 요약, 보고서 표면, 진단 번들을 모두 검색해도 그 문자열이 없다.
13. provider 진단이나 최근 오류를 읽지 못한 상태에서도 번들의 읽을 수 있는 부분은 생성되고 누락과 사유가 적힌다.
14. 번들 저장과 복사는 사용자 조작 전에 실행되지 않고, 실행한 뒤에도 외부 업로드와 이슈 생성이 발생하지 않는다.
15. 구형 런타임 응답으로도 기본 요약과 시작과 종료 표시가 작동하고, 부재한 도구 이름과 진단을 만들어 내지 않는다.
16. 기존 배정, 상태 조회, 취소, 재시도, 일시 정지, 복구 필요 판단과 문서 승인과 품질 확인 검사가 변경 전과 같은 결과로 통과한다.

## 범위 밖

- 작업 지시, 전체 트랜스크립트, 표준 출력과 표준 오류, 도구 인자와 결과 본문을 새로 저장하는 기능
- 진단 번들을 외부 이슈 추적기, 원격 서비스, 이메일로 자동 전송하는 기능
- 보고서 본문을 편집하거나 상태를 바꾸는 기능
- 활동 없음 신호를 실패로 자동 전환하거나 자동으로 취소하는 기능
- 활동 없음 기준을 사용자가 프로젝트별로 설정하는 기능
- 기존 이벤트에 없는 도구 이름이나 과거 진단 결과를 소급해서 복원하는 작업
- 실행 배정, provider 수명, 취소와 재시도, 문서 상태 기계의 의미 변경

## 기대효과

- 사용자가 반복되는 이벤트 종류를 해석하지 않고 실행의 진행과 결과를 판단한다.
- 실행이 만든 보고서로 이동하는 경로가 짧어진다.
- 개발자는 재현에 필요한 정보를 한 번에 받고, 민감정보를 싣은 자료를 따로 수집할 필요가 줄어든다.
- 도구 이름만 보존하므로 실행의 성격을 알 수 있으면서도 기존 민감정보 비보존 경계를 유지한다.
