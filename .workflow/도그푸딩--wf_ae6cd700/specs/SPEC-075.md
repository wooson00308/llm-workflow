# 품질 확인 카드에 기능 소개의 첫 문장만 보여주기

## 결정권자 요약

### 제안

품질 확인 목록의 기능 카드에 기능 소개의 첫 문장 하나만 보여주고, 나머지 설명은 시작을 눌러
들어간 확인 화면에서만 보이게 한다.

### 현재

카드는 기능 소개 문단을 세 줄까지 보여준다. 기능 문서 70건을 실측하니 15건의 소개가 4문장에서
17문장, 203자에서 1024자에 이른다. 이 15건은 세 줄 상한에 걸려 문장 도중에 잘리고, 잘린 자리까지
읽어도 나오는 것은 대개 기능이 무엇인지가 아니라 왜 이 기능이 필요했는지에 대한 배경 설명이다.
그래서 사용자는 작은 글씨 세 줄을 읽지 않고 넘긴다.

### 변경 후

카드에는 소개의 첫 문장 하나만 실린다. 실측한 70건의 첫 문장은 27자에서 75자, 중앙값 33자이므로
어느 기능이든 문장이 잘리지 않고 끝까지 보인다. 확인 대기 목록을 훑을 때 기능 하나가 차지하는
글이 최대 1024자에서 최대 75자로 줄고, 카드마다 제목 한 줄과 문장 하나라는 같은 모양이 된다.
배경 설명이 필요한 사용자는 시작을 눌러 확인 화면에서 소개 전체를 그대로 읽는다.

### 비용과 위험

카드만 보고는 기능의 배경을 알 수 없게 된다. 소개 전체는 확인 화면과 완료 기록 화면에 지금과
똑같이 남고 기능 문서 파일도 손대지 않으므로, 되돌리려면 카드의 표시 규칙만 되돌리면 된다.
첫 문장이 기능의 변화가 아니라 상황 설명으로 시작하는 기능이 실측 70건 중 1건 있었고, 그런
기능의 카드는 지금보다 정보가 줄어든다. 이 기획서가 승인되지 않으면 카드는 지금처럼 소개
문단을 세 줄까지 계속 보여준다.

## 기획 내용

### 문제

품질 확인 목록의 기능 카드는 사용자가 확인을 시작할지 정하는 자리다. SPEC-066으로 카드에서
아키텍트의 내부 절을 걷어내고 사용자용 소개 문단만 최대 세 줄로 보여주도록 고쳤고, 그 변경은
반영되어 있다.

남은 문제는 소개 문단 자체의 길이다. 2026-08-19 기준 기능 문서 70건의 소개를 실측한 결과는
다음과 같다.

- 55건은 소개가 1문장에서 2문장이다. 이 기능들의 카드는 지금도 짧다.
- 15건은 소개가 4문장 이상이다. 길이는 203자에서 1024자, 문단 수는 4개에서 5개다.
- 가장 긴 GROUP-073은 5개 문단 17문장 1024자다.

긴 15건에서 카드에 보이는 세 줄은 소개의 앞부분일 뿐이고 문장 한가운데에서 말줄임으로 끊긴다.
게다가 이 소개들은 첫 문장에서 기능이 무엇인지 말한 뒤 둘째 문장부터 지금 무엇이 잘못되어
있는지를 설명하는 구성이라, 세 줄에 들어오는 나머지 분량은 확인을 시작할지 정하는 데 쓰이지
않는 배경이다. 사용자가 2026-08-19 실사용 소감으로 말한 "읽지 않고 지나친다"는 이 상태를
가리킨다.

### 해결 방향

카드에 쓰는 값을 "소개 문단의 첫 문장 하나"로 좁힌다.

첫 문장을 정하는 기준은 다음과 같다.

1. 소개 문단의 처음부터 읽어, 마침표와 물음표와 느낌표 중 하나가 나오고 그 뒤가 공백이거나
   소개의 끝이면 거기까지를 첫 문장으로 본다.
2. 소개 전체에 그런 자리가 없으면 소개 전체를 첫 문장으로 본다.
3. 소개가 비어 있으면 카드에 제목만 보여준다. 이는 SPEC-066이 정한 규칙 그대로다.

실측 70건 모두 1번 기준으로 첫 문장이 잡히고, 길이는 27자에서 75자, 중앙값 33자, 상위 10%가
54자다. 100자를 넘는 첫 문장은 없다.

첫 문장을 카드에 그리는 상한은 두 줄로 둔다. 위 실측의 최댓값 75자는 두 줄 안에 들어오므로
지금 저장소에 있는 어떤 기능도 카드에서 문장이 잘리지 않는다. 두 줄을 상한으로 남겨 두는 것은
앞으로 더 긴 첫 문장이 들어와도 카드 높이가 무너지지 않게 하기 위한 안전장치이며, 그 경우에만
말줄임이 보인다.

### 나머지 설명을 어디서 보여줄지

아이디어는 나머지 설명을 "확인을 시작한 뒤"에 보여줄지 "카드를 펼치는 조작 뒤"에 보여줄지를
기획에서 정하라고 했다. 이 기획서는 시작을 누른 뒤로 정하고, 카드에 펼치기 조작을 새로 만들지
않는다. 근거는 두 가지다.

첫째, 소개 전체를 보여주는 자리가 이미 있다. 시작을 눌러 들어간 확인 화면의 머리말과 완료 기록
화면의 기능 상세가 SPEC-066에서 소개 전체를 줄 수 제한 없이 보여주도록 정해졌고 그대로 동작한다.
같은 내용을 카드에서도 펼칠 수 있게 하면 같은 글이 두 자리에서 나온다.

둘째, 카드는 통째로 눌러서 확인을 시작하는 입구다. 그 안에 펼치기 조작을 하나 더 두면 사용자가
누를 곳이 둘이 되고, 어느 쪽을 눌러야 확인이 시작되는지가 카드마다 모호해진다.

펼치기 조작을 원하면 수정 요청으로 알려 주면 된다.

### 화면별 표시 기준

- 품질 확인 목록의 기능 카드: 소개의 첫 문장 하나를 최대 두 줄까지 보여준다. 넘치면 말줄임으로
  끊는다.
- 시작을 눌러 들어간 확인 화면의 머리말: 지금과 같다. 소개 전체를 줄 수 제한 없이, 문단 구분을
  살려 보여준다.
- 완료 기록 화면의 기능 상세: 지금과 같다. 확인 화면의 머리말과 같은 기준을 쓴다.
- 준비 중인 기능 목록: 지금도 소개를 보여주지 않는다. 이 기획서에서 바꾸지 않는다.

## 요구사항 명세

- R1. 품질 확인 목록의 기능 카드는 기능 소개의 첫 문장 하나만 보여준다. 첫 문장을 정하는 기준은
  위 "해결 방향"의 세 항목을 따른다.
- R2. 카드의 첫 문장은 최대 두 줄까지 보여주고, 넘치면 말줄임으로 끊는다.
- R3. 카드에 소개의 둘째 문장 이후는 어떤 형태로도 실리지 않는다.
- R4. 카드에는 소개를 펼치는 조작을 두지 않는다. 카드를 누르면 지금처럼 확인이 시작된다.
- R5. 시작을 눌러 들어간 확인 화면의 머리말과 완료 기록 화면의 기능 상세는 지금 보여주는 소개
  전체를 그대로 보여준다. 이 두 자리의 표시 기준은 이 변경으로 달라지지 않는다.
- R6. 소개가 비어 있는 기능의 카드는 제목만 보여준다. 빈 줄이나 자리표시 문구를 넣지 않는다.
- R7. 기존 기능 문서를 고치지 않는다. 문서를 고쳐야만 올바르게 보이는 방식은 이 기획서의 해법이
  아니다.

## 제외 범위

- 확인 화면과 완료 기록 화면의 소개 표시 기준은 바꾸지 않는다. SPEC-066이 정한 대로 둔다.
- 아키텍트가 기능 문서를 쓸 때 지키는 작성 지침은 바꾸지 않는다. 첫 문장이 기능의 변화가 아니라
  상황 설명으로 시작하는 문서가 실측 70건 중 1건 있었고, 그런 문서의 카드는 소개 자리가 약해진다.
  첫 문장에 무엇을 쓰라고 지침에 규정하는 일은 별도 아이디어로 다룬다.
- 기능 제목, 상태 표시, 준비 중인 기능 목록의 구성은 바꾸지 않는다.
- 확인 동선은 바꾸지 않는다. 사용자 확인 절차는 지금처럼 시작을 눌러야 열린다.
- 기능 문서에서 소개 문단을 뽑는 기준 자체는 바꾸지 않는다. 이 기획서는 뽑아 놓은 소개에서
  카드에 무엇을 실을지만 정한다.

## 완료 판정 기준

- A1. 소개가 4문장 이상인 기능을 품질 확인 목록에서 보면, 카드에 첫 문장 하나만 보이고 그 문장이
  마침표까지 온전히 보인다. 둘째 문장의 첫 낱말은 보이지 않는다.
- A2. 소개가 1문장인 기능의 카드는 이 변경 전후로 같은 글을 보여준다.
- A3. 확인 대기 목록에 소개가 긴 기능과 짧은 기능이 함께 있을 때, 두 카드의 높이가 같다.
- A4. 카드 어디에도 소개를 펼치는 조작이 없다. 카드를 누르면 확인 화면이 열린다.
- A5. 시작을 눌러 확인 화면에 들어가면 머리말에 소개 전체가 문단 구분과 함께 보인다. 완료 기록
  화면에서 기능 하나를 열어도 같은 기준으로 보인다.
- A6. 소개가 없는 기능의 카드에는 제목만 보이고 그 아래가 비어 있다.
- A7. 기존 기능 문서 70건의 파일 내용이 이 변경 전후로 같다.

## 기대효과

확인 대기 목록이 한눈에 읽히는 목록이 된다. 기능 하나가 제목 한 줄과 문장 하나로 정리되므로,
사용자는 카드를 훑는 것만으로 어떤 기능이 확인을 기다리는지 파악하고 그중 무엇부터 열지 고를 수
있다.

아키텍트가 기능 문서의 소개를 충실하게 쓸수록 카드가 나빠지던 관계가 완전히 끊어진다. SPEC-066은
내부 절을 카드에서 걷어냈지만 소개가 길어지는 것까지는 막지 못했다. 카드가 첫 문장만 가져가면
소개를 몇 문단으로 쓰든 카드의 모양은 같고, 길게 쓴 설명은 확인을 시작한 사용자에게 그대로
전달된다.
