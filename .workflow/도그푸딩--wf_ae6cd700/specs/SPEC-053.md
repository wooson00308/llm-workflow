# 막힌 작업의 사유와 재개 조건을 작업 패널에 표시한다

## 결정권자 요약

이 기획서는 진행이 멈춘 개발 작업의 실제 사유와 재개 조건을 오른쪽 패널에서 바로 읽게 합니다.
사용자가 결정할 것은 막힘 사유를 고정된 문서 절로 기록하는 방식과 기존 문서의 안전한 읽기 규칙입니다.
승인하면 현재 멈춘 이유, 필요한 해결, 재개 조건, 관련 대상을 작업을 열자마자 확인할 수 있습니다.
작성된 사유와 시스템이 계산한 의존 정보는 각각의 출처를 밝혀 한 문장으로 중복하지 않습니다.
형식이 없는 기존 문서는 기존 요약을 먼저 보이고, 값이 없으면 추측 대신 원문 위치를 안내합니다.
상태 전환 권한, 선행 판정, 임대 정리, 자동 요약과 기존 문서의 일괄 수정은 달라지지 않습니다.
승인하지 않으면 현행 상태명과 공통 안내만 보이는 경험이 유지됩니다.

## 기획 내용

개발 작업이 차단되면 현재 화면은 상태명과 공통 안내만 보여 준다. 사용자는 작업 문서 전체나 개발 보고서를
열어야만 왜 멈췄는지와 무엇이 충족돼야 다시 시작할 수 있는지 알 수 있다. TASK-S051-04는 이 문제가
드러난 사례다. 선행 작업이 아직 사용자 확인 대기이고, 예약 소유권과 실행 복구 계약이 준비되지 않아
개발을 이어 갈 수 없지만, 작업 상세의 오른쪽 패널에서는 그 사유를 읽을 수 없다.

이 기획서는 작성자가 남긴 현재의 차단 사유를 개발 작업 문서의 고정 절로 만들고, 현재 상태가 차단일 때
작업 상세 오른쪽 패널에서 그 절을 읽어 보여 준다. 화면은 문서가 쓴 내용을 요약하거나 원인을 추론하지
않는다. 정해진 제목과 라벨을 로컬에서 정확히 읽어 표시할 뿐이다.

이미 계산되는 선행 작업, 선언 형식, 파일 겹침의 구조 정보는 SPEC-039가 다룬 표시 범위다. 이번 기능은
그 판정 규칙을 바꾸지 않고 작성자 사유를 별도 출처로 보완한다. 구조 정보가 함께 보일 때도 작성자 사유를
다시 문장으로 조립하거나 같은 공통 안내를 반복하지 않는다.

### 막힌 사유의 문서 계약

현재 상태를 차단으로 바꾸는 작성자는 같은 문서 편집에서 본문에 아래 절을 작성하거나 갱신한다. 제목과
네 라벨은 정확히 한 번씩 쓴다. 값은 비워 두지 않는다.

```markdown
## 막힌 사유

- 막힌 지점: 지금 진행할 수 없는 구체적인 이유
- 필요한 해결: 누가 무엇을 제공하거나 바꿔야 하는지
- 재개 조건: 어떤 사실이 충족되면 개발을 다시 시작하는지
- 관련 대상: TASK-001, 외부 승인 대기
```

관련 대상이 없으면 값은 `없음`으로 쓴다. 여러 대상은 쉼표와 공백으로 나열한다. 그중 실제 개발 작업
식별자와 정확히 일치하는 값만 앱이 작업으로 확인한다. 외부 저장소, 사람, 승인, 문서처럼 작업이 아닌
값은 작성된 설명 그대로 남긴다.

차단을 해제할 때는 이 절을 삭제하지 않는다. 오른쪽 패널은 현재 상태가 차단일 때만 이를 현재 사유로
표시한다. 같은 작업이 다시 차단되면 네 값을 새 현재 사유로 갱신하고 문서의 갱신 시각도 함께 바꾼다.
이전 차단의 세부 사항은 당시 개발 보고서와 기존 상태 이력으로 남기며, 현재 사유 절을 여러 차단의
누적 기록으로 사용하지 않는다.

## 요구사항 명세

### R1. 차단 사유를 결정적으로 기록한다

- 현재 상태를 차단으로 전환하는 개발 작업은 `## 막힌 사유` 절과 네 개의 필수 라벨을 같은 편집에
  작성한다.
- 제목, 라벨, 목록 구조가 하나라도 빠지거나 반복되거나 값이 비어 있으면 구조화된 차단 사유로 인정하지
  않는다. 화면은 일부 값을 추측해 섞어 보여 주지 않는다.
- 관련 대상 값은 쉼표와 공백으로 나뉜 순서를 보존한다. 값 `없음`은 관련 대상이 없음을 뜻하며 링크나
  대체 문구를 만들지 않는다.
- 이 계약은 새로 차단되는 작업과 다시 차단되는 작업에 적용한다. 기존 작업 문서를 일괄 수정하지 않는다.

### R2. 현재 사유와 이전 기록의 역할을 구분한다

- 차단으로 전환할 때 상태, 상태 이력, 문서 갱신 시각, 막힌 사유 절은 같은 문서 편집에서 현재 사실로
  맞춰진다.
- 차단 상태 안에서 사유가 달라지면 네 값과 문서 갱신 시각을 함께 갱신한다.
- 차단 상태에서 벗어나도 마지막 막힌 사유 절은 보존한다. 현재 상태가 차단이 아닐 때는 이를 현재 사유로
  표시하지 않는다.
- 다시 차단될 때 본문 절은 현재 사실로 교체한다. 이전 차단의 상세 설명은 그 시점의 개발 보고서와
  append-only 상태 이력으로 추적하며, 본문에 오래된 사유를 쌓지 않는다.

### R3. 오른쪽 패널이 현재 차단 사유를 바로 보여 준다

- 대상은 개발 작업 상세의 오른쪽 패널이다. 현재 상태가 차단이면 패널은 `진행이 막혔습니다`라는 제목과
  막힌 지점, 필요한 해결, 재개 조건, 관련 대상을 정한 순서로 보여 준다.
- 구조화된 절의 문장은 축약, 번역, 추론, 자동 요약 없이 문서에 쓴 뜻을 유지해 표시한다. 이를 위해
  네트워크 요청이나 LLM 호출을 하지 않는다.
- 패널은 현재 문서에 기록된 갱신 시각을 차단 정보의 최신성으로 함께 보여 준다.
- 현재 상태가 QA 대기이면 기존 확인 동선, 메모, 완료·되돌리기 조작을 유지한다. 그 밖의 상태도 기존의
  상태 안내를 유지한다.

### R4. 관련 대상은 확인 가능한 만큼만 연결한다

- 관련 대상 값이 현재 워크플로의 실제 개발 작업 식별자와 정확히 일치하면, 패널은 그 작업의 제목과 현재
  상태를 함께 보여 주고 해당 작업을 열 수 있게 한다.
- 작업 문서가 없거나 외부 의존을 가리키는 값은 링크, 제목, 상태를 지어내지 않는다. 작성된 식별자와
  설명만 표시한다.
- 여러 관련 대상은 문서의 작성 순서대로 표시한다. 하나를 확인하지 못해도 다른 대상의 표시나 링크를
  막지 않는다.

### R5. 기존 차단 문서를 안전하게 읽는다

- 현재 차단 작업에 유효한 막힌 사유 절이 없으면 결정권자 요약 절을 폴백으로 보여 준다.
- 결정권자 요약도 없거나 읽을 수 없으면 사유를 추측하지 않고 `구조화된 막힘 사유가 없습니다`라고 알린
  뒤 원문을 확인할 수 있는 위치를 안내한다.
- 유효하지 않은 구조화 절은 R1의 폴백과 같은 방식으로 처리한다. 오류를 이유로 문서를 고치거나 차단
  상태를 바꾸지 않는다.
- 기존 문서의 본문, 과거 개발 보고서, 상태 이력은 이 기능을 위해 소급 변환하지 않는다.

### R6. 구조 정보와 작성자 사유를 중복하지 않는다

- 작성자 사유는 `작성된 막힘 사유`처럼 출처를 알 수 있는 영역에 표시한다. 앱이 이미 계산한 선행 작업,
  선언 형식, 파일 겹침 정보는 별도 구조 정보 영역으로 유지한다.
- 화면은 구조 정보를 근거로 작성자 사유를 새로 만들거나, 작성자 사유를 근거로 구조 판정을 바꾸지 않는다.
- 같은 의미를 되풀이하는 공통 차단 안내는 구조 정보와 작성자 사유 사이에 추가하지 않는다. 각 영역은
  자기 출처가 아는 사실만 말한다.
- 선행 작업 충족 여부, 순환과 누락 판정, 파일 겹침 판정과 작업 시작 가능 여부는 바뀌지 않는다.

### R7. 작은 화면에서도 사유와 조작을 잃지 않는다

- 넓은 화면에서는 현재 오른쪽 패널의 정보 계층 안에서 차단 사유를 읽는다.
- 작은 화면에서는 네 항목, 관련 대상, 구조 정보, 기존 조작이 한 열로 자연스럽게 쌓인다. 어느 항목도
  가로 잘림이나 색상만으로 의미를 전달하지 않는다.
- 키보드와 보조 기술 사용자는 제목, 네 항목, 관련 작업 링크, 원문 보기와 기존 조작에 화면의 읽기 순서로
  도달할 수 있다.

### R8. 차단 해제와 문서 정본의 권한은 유지한다

- 이 기획서는 패널에서 상태를 준비 상태로 되돌리거나 임대를 정리하는 조작을 추가하지 않는다. 차단 해제는
  기존 역할 계약과 상태 전이 절차를 따른다.
- 앱은 차단 사유 표시를 위해 개발 작업 문서, 결정 기록, 임대 파일을 쓰지 않는다. 문서의 유일한 정본은
  계속 Markdown 원문이다.
- 기존 QA 기록, 승인과 수정 요청, 목록 미리보기, 검색, 문서 원문 보기의 동작은 달라지지 않는다.

## 확인 필요

사용자는 아래 제안을 한꺼번에 승인하거나 수정 요청할 수 있다.

1. **고정 절과 네 필수 라벨을 첫 문서 계약으로 확정한다.**

   제안: 관련 대상까지 네 라벨을 모두 필수로 하고, 대상이 없으면 `없음`을 쓴다. 관련 작업은 쉼표와
   공백으로 나열하며 실제 작업 식별자와 정확히 맞는 값만 연결한다. 이 방식은 화면이 작성자 뜻을 추측하지
   않고도 누락과 외부 의존을 구분하게 한다.

   비용: 차단 전환을 작성하는 사람이 짧은 네 값을 반드시 정리해야 한다. 그러나 선택 라벨이나 자유 형식은
   기존 문서와 새 문서를 구별할 수 없고, 패널이 일부 정보만 임의로 보이게 만든다.

2. **기존 문서는 변환하지 않고 폴백으로 읽는다.**

   제안: 유효한 고정 절이 없는 현재 차단 작업은 결정권자 요약을 먼저 보이고, 요약도 없으면 구조화된
   사유가 없음을 알린 뒤 원문을 안내한다. 과거 차단의 상세는 개발 보고서와 상태 이력에 남긴다.

   비용: 옛 문서는 새 패널에서 네 항목을 모두 채우지 못할 수 있다. 대신 이력을 바꾸지 않고, 오래된
   문장에 새 의미를 부여하는 위험을 피한다.

3. **작성자 사유와 구조 정보는 출처를 나눠 함께 표시한다.**

   제안: 작성자 사유를 우선 표시하고, 앱이 계산한 선행·형식·겹침 정보는 별도 영역으로 둔다. 앱은 둘을
   결합해 원인을 판단하지 않는다.

   비용: 두 영역이 모두 있는 작업은 패널이 길어진다. 작은 화면에서는 같은 순서로 한 열에 쌓아 정보
   손실보다 출처 구분을 우선한다.

## 기대효과

- 사용자는 차단된 작업을 열자마자 왜 멈췄는지, 누가 무엇을 해결해야 하는지, 언제 재개할 수 있는지
  확인한다.
- 실제 관련 작업은 제목과 현재 상태를 함께 보여 주므로 선행 상태를 찾아 이동하는 횟수가 줄어든다.
- 작성자 사유와 시스템 판정이 섞이지 않아, 사용자는 앱이 아는 사실과 작성자가 기록한 판단을 구분한다.
- 기존 문서와 상태 전이 권한을 보존해 새 표시 기능이 워크플로 규칙이나 감사 이력을 바꾸지 않는다.

## 완료 조건

1. 네 라벨을 모두 갖춘 현재 차단 작업을 열면 오른쪽 패널에 제목, 네 값, 문서 갱신 시각이 정한 순서로
   보인다.
2. 관련 대상 중 실제 작업 식별자는 제목·상태·열기 동작을 제공하고, 외부 의존 또는 없는 작업은 작성된
   텍스트만 보인다.
3. 차단을 해제한 작업은 마지막 막힌 사유 절을 문서에 보존하지만 오른쪽 패널에서 현재 사유로 표시하지
   않는다. 다시 차단하면 새 네 값과 갱신 시각이 보인다.
4. 제목, 라벨, 값이 불완전한 차단 사유 절과 절이 전혀 없는 기존 차단 문서는 각각 결정권자 요약으로
   폴백한다.
5. 결정권자 요약도 없는 차단 문서는 구조화된 사유가 없다는 안내와 원문 확인 경로를 제공하며, 사유나
   관련 대상을 만들어 내지 않는다.
6. 선행·형식·겹침의 기존 판정과 표시가 유지되고, 작성자 사유와 같은 공통 문구가 두 영역에 반복되지
   않는다.
