# 연동을 설정에서 분리해 독립 사이드바 메뉴와 전용 뷰로 이전

## 기획 내용

지금 연동은 설정 화면 안의 카드 하나다. 설정 화면에는 앱 업데이트, 현재 프로젝트, 파일 감시가 먼저 오고 그 뒤에 연동 섹션이 붙는다. 섹션 안에서 하트비트와 드림 두 카드가 항상 펼쳐진 채 세로로 이어진다.

여기에 두 가지가 겹쳐 있다.

첫째, 성격이 다른 것이 한 화면에 섞였다. 앱 업데이트·프로젝트 정보·파일 감시는 확인하는 정보다. 반면 연동은 잡을 켜고 끄고 주기와 쿼터와 모델을 고쳐 저장하는 작업 화면이다. 사용자가 연동을 손보려고 설정에 들어가면 관심 없는 정보를 지나 스크롤해야 하고, 앱 설정을 보려던 사용자는 그 아래 큰 폼 두 개를 만난다.

둘째, 연동은 늘어난다. SPEC-002가 하트비트를, SPEC-003이 드림을 넣었고 각 카드는 역할 잡 3종 또는 dream 잡의 폼을 통째로 들고 있다. 지금 둘만으로도 화면을 채우는데, 설정 화면은 연동이 늘어날수록 아래로 계속 자란다.

그래서 연동을 사이드바의 독립 메뉴로 꺼내 전용 뷰가 담당하게 하고, 설정에는 앱 자체 설정만 남긴다. 전용 뷰에서 카드는 접을 수 있게 하되, 접혔다는 이유로 문제가 감춰지지 않도록 접힌 상태에서도 상태와 경고는 보이게 한다.

메뉴 이름은 "연동"으로 한다. 앱의 기존 명명 체계(아이디어·기획서·개발·기록·설정)와 같은 한국어 명사 결을 유지하고, SPEC-002 이후 화면 용어가 이미 "연동"이므로 사용자가 보던 말과 어긋나지 않는다. "플러그인"·"모듈"은 개발자 용어라 앱 전체 톤과 맞지 않아 배제한다.

### 확인 사실

- `SettingsView`는 설정 카드 그리드의 마지막 항목으로 `IntegrationSection`을 렌더한다. 그 앞의 세 카드가 앱 업데이트·현재 프로젝트·파일 감시다.
- `IntegrationSection`은 고정 배열 `registry`(`heartbeat`, `dream`)를 순회해 카드를 그리고, 플랫폼 미지원 경고는 카드마다 반복하지 않고 섹션 공통 위치에서 한 번만 보여준다.
- 카드 골격 `IntegrationCard`는 이미 이름·설명·상태 배지를 한 줄(`integration-item-head`)로 그리고, 그 아래에 연동별 본문·중복 잡 경고·읽기 실패 목록을 둔다. 접힘 요약에 필요한 재료는 이 골격에 이미 있다.
- 배지 문구는 연동마다 다르다. 하트비트는 `미설치` / `설치됨 · 데몬 실행 중` / `설치됨 · 데몬 미실행`, 드림은 `하트비트 필요` / `미설치` / `설치됨`이다. 상태를 아직 못 읽었으면 `확인 중`, 조회에 실패했으면 `상태를 읽을 수 없음`으로 골격이 대체한다.
- 사용자가 놓치면 안 되는 신호는 네 종류다. 섹션 조회 실패(`error`), 관리 블록 밖 중복 잡(`duplicateJobs`), 파일 읽기 실패(`readFailures`), 저장 실패(`writeError`). 앞의 셋은 골격이 그리고, 저장 실패는 각 연동 본문이 그린다.
- 카드 본문은 저장하지 않은 폼 상태를 들고 있다. 하트비트는 역할별 활성 여부·주기·쿼터·모델, 드림도 같은 성격의 값이다.
- 화면 전환은 `WorkspaceShell`의 `view` 상태 하나로 하고 이름은 `viewLabels`에 있다. 라우터는 없고 뷰 상태는 앱을 다시 열면 초기값으로 돌아간다.
- 설정·도움말은 선택된 워크플로우와 무관하게 렌더된다. 워크플로우 단계 화면(아이디어·기획서·개발·기록)만 워크플로우에 묶여 있다.
- 화면 상태를 브라우저 저장소에 기억한 선례가 있다. `DevelopmentBoard`의 QA 패널 너비와 최근 프로젝트 목록이 `localStorage`를 쓴다.

### 포함 범위

- 사이드바에 "연동" 메뉴를 추가하고 전용 뷰를 만든다.
- 설정 화면에서 연동 섹션을 제거한다.
- 전용 뷰에서 각 연동 카드에 펼침/닫기 토글을 둔다.
- 접힌 상태의 요약(상태 배지, 경고 유무)을 정의한다.
- 접힘 기본값과 기억 여부를 정한다.

### 제외 범위

- 카드 본문의 내용·문구, 배지 판정 규칙, 경고 판정 규칙 변경. 이 기획서는 위치와 접힘만 다루고 안에 있는 것은 그대로 옮긴다.
- 연동 추가·삭제·비활성화, 외부 연동 등록. `registry`는 앱 내장 고정 배열로 남는다.
- SPEC-004(모델 선택 UI)와 SPEC-005(재설치 시 편집값 보존)가 정의한 동작의 변경. 두 기획서의 결과물이 어느 화면에 있든 그대로 성립해야 한다.
- 설정 화면에 "연동은 전용 메뉴로 이동했습니다" 같은 안내를 남기는 것. 사이드바에 메뉴가 상시 보이고 사용자가 한 명인 로컬 앱이라, 한 번 보고 마는 문구를 화면에 남길 이유가 없다.
- breadcrumb 구조 개선. 설정·도움말이 워크플로우 이름을 breadcrumb에 함께 보여주는 현행 표시는 이 기획서의 대상이 아니다.
- 뷰 상태의 URL 반영이나 앱 재시작 후 마지막 화면 복원.
- 카드 정렬·검색·필터, 카드 접힘 전체 펼치기/접기 같은 일괄 조작.

## 요구사항 명세

### R1. 연동은 사이드바의 독립 메뉴다

- 사이드바에 "연동" 항목을 두고, 선택하면 연동 전용 뷰가 열린다. 다른 메뉴와 마찬가지로 현재 선택된 항목이 시각적으로 구분된다.
- 위치는 도움말·설정과 같은 하단 묶음으로 한다. 근거는 화면의 소속이다. 주요 메뉴의 다섯 항목은 모두 선택된 워크플로우의 문서 단계를 보여주지만, 연동은 워크플로우가 아니라 프로젝트와 사용자 환경(전역 설정 파일, 데몬)을 다룬다. 설정·도움말과 같은 층에 두어야 "워크플로우를 바꾸면 내용이 바뀌는 화면"과 섞이지 않는다.
- 연동 뷰는 선택된 워크플로우와 무관하게 동작한다. 워크플로우를 전환해도 연동 뷰의 내용은 바뀌지 않는다.
- 화면 이름 목록(breadcrumb 등 화면 제목을 쓰는 곳)에 "연동"이 포함된다. 이름이 빠져 빈 칸이나 다른 화면 이름이 보여서는 안 된다.

### R2. 전용 뷰는 지금 보이는 것을 그대로 보여준다

- 이동은 위치 변경이다. 하트비트·드림 카드의 본문, 배지, 설치 안내, 중복 잡 경고, 읽기 실패 목록, 저장 실패 표시는 문구와 판정 그대로 옮겨진다.
- 플랫폼 미지원 경고는 카드마다 반복하지 않고 뷰의 공통 위치에서 한 번만 보여준다. 현행 섹션 정책을 유지한다.
- 한 연동의 저장 실패 문구가 다른 연동 카드에 나타나지 않는다. 현행 격리 동작을 유지한다.
- 연동 목록은 앱 내장 고정 배열을 순회해 그린다. 새 연동이 추가될 때 뷰 골격을 고치지 않아도 되는 현행 구조를 유지한다.
- 화면 진입은 읽기다. 뷰를 열거나 카드를 펼치는 동작이 전역 설정 파일을 쓰지 않는다(SPEC-002 R6).

### R3. 설정에는 앱 자체 설정만 남는다

- 설정 화면에서 연동 섹션이 사라지고, 앱 업데이트·현재 프로젝트·파일 감시 세 카드는 그대로 남는다.
- 설정 화면의 설명 문구가 연동을 가리키지 않도록 남은 내용에 맞게 고친다. 화면에 없는 것을 설명하는 문장이 남아서는 안 된다.
- 설정 화면에서 연동 관련 조작을 할 수 없다. 두 화면에 같은 조작이 중복해 존재하지 않는다.

### R4. 카드는 접고 펼 수 있다

- 각 연동 카드에 펼침/닫기 토글을 둔다. 토글은 그 카드 하나에만 작용하고, 다른 카드의 상태를 바꾸지 않는다.
- 토글은 키보드로 조작할 수 있고, 지금 펼쳐져 있는지 접혀 있는지를 보조 기술이 읽을 수 있어야 한다.
- 접히면 카드 본문(폼, 설치 안내, 경고 상세)이 화면에서 감춰지고, 펼치면 다시 보인다.

### R5. 접힌 카드도 상태와 경고를 숨기지 않는다

- 접힌 상태에서 최소한 연동 이름과 상태 배지가 보인다. 배지 문구는 R2대로 현행 판정 그대로다.
- 경고가 하나라도 있으면(조회 실패, 중복 잡, 읽기 실패, 저장 실패) 접힌 상태에서 그 사실이 보인다. 상태 배지와 구분되어야 하며, 배지가 `설치됨`인데 경고가 접혀 감춰지는 상태가 있어서는 안 된다. 구체적인 표현 방식은 아키텍트가 정한다.
- 경고의 상세 내용(어떤 잡이 중복인지, 어떤 파일을 못 읽었는지)은 펼쳤을 때 보이면 된다. 접힘 요약이 책임지는 것은 "봐야 할 것이 있다"는 사실까지다.
- 플랫폼 미지원 경고는 카드 접힘과 무관하게 항상 보인다. 뷰 공통 위치에 있기 때문이다.

### R6. 기본은 접힘이고, 마지막 상태를 기억한다

- 사용자가 한 번도 조작하지 않은 연동 카드는 접힌 상태로 시작한다. 근거는 이 기획서의 동기 그대로다. 카드 하나가 크고 앞으로 늘어나므로, 전부 펼친 첫 화면은 목록으로서 쓸모가 없다. 접힌 첫 화면에서도 R5 덕분에 어느 연동이 미설치인지, 어디에 경고가 있는지는 보인다.
- 사용자가 펼치거나 접은 상태는 기억되어, 다른 화면에 갔다 오거나 앱을 다시 열어도 유지된다. 매번 같은 카드를 다시 펼치게 하지 않는다.
- 기억은 연동 단위다. 한 연동을 펼쳐 두었다고 다른 연동이 함께 펼쳐지지 않는다.
- 기억된 값을 읽지 못하거나 형식이 깨졌으면 기본값(접힘)으로 동작한다. 화면이 뜨지 않거나 오류를 사용자에게 보여서는 안 된다.
- 기억된 값이 이제 없는 연동을 가리키더라도 화면은 정상 동작한다.

### R7. 접기가 편집 중인 값을 잃게 하지 않는다

- 저장하지 않은 폼 값이 있는 카드를 접었다가 다시 펼치면 그 값이 그대로 있어야 한다. 접기는 표시를 바꾸는 동작이지 편집을 취소하는 동작이 아니다.
- 다른 화면(설정·오늘 등)에 갔다가 연동 뷰로 돌아왔을 때의 폼 초기화 동작은 현행과 같아도 된다. 이 요구는 같은 화면 안에서 접기 때문에 값이 사라지는 경우만 막는다.
- 사용자 편집값이 조용히 사라지지 않아야 한다는 점에서 SPEC-005와 같은 규칙이다. 화면 조작이 새로운 유실 경로를 만들어서는 안 된다.

## 확인 필요

사용자 결정이 필요한 항목이다. 승인 시 아래 제안대로 진행한다.

1. **메뉴 위치.** 주요 메뉴(오늘·아이디어·기획서·개발·기록) 안에 넣을지, 도움말·설정과 같은 하단 묶음에 넣을지의 선택이다.

   제안: 하단 묶음에 넣는다. 근거는 R1에 적은 소속이다. 주요 메뉴는 선택된 워크플로우에 따라 내용이 바뀌는 화면들이고, 연동은 워크플로우와 무관하다. 주요 메뉴에 섞으면 사용자가 워크플로우를 바꿔도 내용이 그대로인 항목 하나가 그 안에 생긴다. 반대 의견도 성립한다. 하단은 눈에 덜 띄어 새 메뉴를 못 찾을 수 있다는 점이다. 다만 지금 연동을 쓰는 사용자는 설정 안에서 찾아 쓰던 사람이라, 같은 층에서 옆으로 나오는 편이 오히려 찾기 쉽다고 본다.

2. **접힘 기본값.** 기본 접힘과 기본 펼침 중 무엇으로 시작할지의 선택이다.

   제안: 기본 접힘으로 한다. 근거는 아이디어가 토글을 요구한 이유 그대로다. 카드가 커서 둘만으로 화면이 찬다. 기본 펼침이면 토글이 있어도 첫 화면은 지금과 같다. 대신 R5로 접힌 상태에서도 미설치·경고가 드러나므로, 접힌 첫 화면이 정보를 감추지는 않는다. 대안으로 "경고나 미설치인 카드만 펼쳐서 시작"도 생각했지만 배제한다. 화면이 열릴 때마다 펼침 상태가 스스로 달라지면 사용자가 접어 둔 카드가 다음에 펼쳐져 있는 이유를 알기 어렵고, 기억(R6)과도 충돌한다.

## 기대효과

- 연동을 손보려는 사용자가 사이드바에서 한 번에 들어간다. 설정 화면을 지나 스크롤할 필요가 없다.
- 설정 화면이 앱 자체 설정만 담아 짧아지고, 화면의 성격이 하나로 정리된다.
- 연동이 늘어나도 커지는 곳은 전용 뷰 하나다. 설정 화면은 연동 수와 무관해진다.
- 접힘 목록이 기본이 되어, 연동이 여럿일 때 "지금 무엇이 설치되어 있고 어디에 문제가 있는가"를 한 화면에서 훑을 수 있다. 지금은 카드를 전부 지나쳐야 알 수 있다.
- 접힘 상태를 기억하므로 자주 만지는 연동만 펼쳐 두고 쓸 수 있다.

## 완료 조건

1. 사이드바에 "연동" 메뉴가 있고, 선택하면 연동 전용 뷰가 열리며 선택 상태가 표시된다. 검증: 화면에서 메뉴를 눌러 뷰 전환과 선택 표시를 확인한다.
2. 설정 화면에 연동 섹션이 없고, 앱 업데이트·현재 프로젝트·파일 감시 세 카드는 그대로 있다. 검증: 설정 화면을 열어 확인하고, 자동화 테스트로 설정 화면에 연동 카드가 없음을 확인한다.
3. 설정 화면의 설명 문구가 더 이상 연동을 가리키지 않는다. 검증: 설정 화면 문구를 읽어 확인한다.
4. 하트비트·드림 카드의 본문·배지·설치 안내·중복 잡 경고·읽기 실패 목록·저장 실패 표시가 이동 전과 같은 문구와 판정으로 동작한다. 검증: 기존 연동 동작을 검증하던 자동화 테스트가 새 화면 기준으로 유지되고 통과한다.
5. 플랫폼 미지원 경고가 뷰에서 한 번만 표시된다. 검증: 미지원 플랫폼 스냅샷으로 화면을 그려 경고가 하나인지 확인한다.
6. 한 연동의 저장 실패 문구가 다른 연동 카드에 나타나지 않는다. 검증: 한쪽 연동만 저장 실패한 상태의 테스트가 존재하고 통과한다.
7. 워크플로우를 전환해도 연동 뷰의 내용이 바뀌지 않는다. 검증: 워크플로우가 둘 이상인 프로젝트에서 전환 전후 화면을 대조한다.
8. 각 카드의 토글로 그 카드만 접히고 펼쳐진다. 검증: 두 카드가 있는 상태에서 한쪽을 접고 다른 쪽 상태가 그대로인지 확인한다.
9. 토글을 키보드로 조작할 수 있고 펼침 여부가 보조 기술에 노출된다. 검증: 키보드 조작 테스트와 접근성 속성 확인.
10. 접힌 카드에서 연동 이름과 상태 배지가 보인다. 검증: 접힌 상태의 화면을 자동화 테스트로 확인한다.
11. 경고가 있는 연동은 접힌 상태에서도 경고가 있다는 사실이 보이고, 그 표시가 상태 배지와 구분된다. 검증: 중복 잡·읽기 실패·저장 실패 각각을 재현해 접힌 상태의 화면을 확인한다.
12. 한 번도 조작하지 않은 카드는 접힌 상태로 시작한다. 검증: 저장된 상태가 없는 환경에서 뷰를 처음 열어 확인한다.
13. 펼치거나 접은 상태가 다른 화면을 다녀오거나 앱을 다시 연 뒤에도 유지된다. 검증: 카드를 펼친 뒤 화면 전환과 앱 재시작 후 상태를 확인한다.
14. 저장된 상태가 깨졌거나 없는 연동을 가리켜도 화면이 정상 동작하고 기본값으로 시작한다. 검증: 손상된 값을 넣은 상태에서 뷰를 열어 확인한다.
15. 저장하지 않은 폼 값이 있는 카드를 접었다 펼치면 값이 그대로 남는다. 검증: 주기 또는 쿼터를 고친 뒤 접었다 펴서 입력값을 대조한다.
16. 프론트엔드 테스트와 타입 검사가 통과한다. 검증: 저장소의 테스트·타입 검사 명령을 실행한다.
