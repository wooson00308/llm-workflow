# 사용자가 프로젝트별 커스텀 가드레일을 관리한다

## 결정권자 요약

사용자는 현재 앱에서 프로젝트별 작업 규칙을 추가할 수 없다. 관리 규칙 파일을 직접 고치면 앱
업데이트와 충돌하고, 도구별 설정을 고치면 같은 프로젝트에서도 에이전트마다 다른 규칙을 읽는다.
설정 화면에 프로젝트 공통 사용자 정의 규칙 하나를 작성하고 켜거나 끄는 기능을 추가한다. 적용할
역할을 선택하고, 에이전트가 읽을 파일의 최종 모습을 저장 전에 확인할 수 있게 한다.
사용자 규칙은 앱의 필수 안전 규칙과 역할 계약보다 우선하지 않는다. 충돌하는 부분만 적용되지 않으며,
앱은 의미를 추측해 자동 수정하지 않는다. 변경 내용은 앱 재시작 없이 다음 에이전트 세션부터 적용된다.
사용자가 결정할 것은 이 저장 방식과 우선순위, 첫 버전의 기능 범위다. 승인하지 않으면 프로젝트별
규칙은 지금처럼 앱 밖에서 따로 관리해야 하고, 앱이 제공하는 기본 규칙만 설치된다.

## 기획 내용

현재 앱은 공통 규칙과 기획자, 아키텍트, 개발자 역할 계약을 프로젝트에 설치한다. 이 파일들은 앱이
관리하며 새 버전이 나오면 앱에 포함된 내용으로 갱신된다. 사용자나 팀이 프로젝트에 맞는 규칙을
추가하려면 관리 파일을 직접 고치거나 AGENTS.md와 CLAUDE.md의 관리 영역 밖에 도구별 지시를 적어야
한다.

두 방법 모두 제품 기능으로는 부족하다. 관리 파일을 직접 고치면 다음 설치에서 내용이 사라질 수 있고,
관리 형식이 깨지면 앱이 충돌로 처리한다. 도구별 파일에 따로 적으면 Claude와 Codex가 서로 다른 규칙을
읽을 수 있으며, 사용자는 앱에서 어떤 규칙이 적용되는지 확인할 수 없다.

첫 버전은 규칙 편집기를 크게 만들지 않는다. 프로젝트마다 하나의 사용자 정의 규칙 문서를 두고,
설정 화면에서 Markdown 본문과 적용 역할을 편집한다. 여러 규칙 묶음, 조건식, 템플릿 마켓은 이후
사용 패턴이 확인된 뒤 판단한다.

### 저장 방식

- 사용자 정의 규칙은 `.workflow/rules/custom.md` 하나에 저장한다.
- 파일은 선택 자산이다. 없으면 사용자 정의 규칙을 사용하지 않는 현재 프로젝트와 같은 뜻이다.
- 고정된 프론트매터에 스키마, 사용 여부, 적용 역할, 수정 시각을 기록하고 본문에는 사용자가 입력한
  Markdown을 저장한다.
- 앱 기본 규칙 설치기는 이 파일을 만들거나 덮어쓰지 않는다. 사용자가 설정 화면에서 저장할 때만
  앱이 파일을 쓴다.
- 파일은 프로젝트 저장소에 포함할 수 있어 팀원과 CI 환경이 같은 규칙을 읽는다. 개인 전용 규칙과
  전역 규칙은 첫 버전에 포함하지 않는다.
- 앱이 파일을 읽을 때 내용 식별값을 함께 반환하고, 저장 요청은 그 값을 기준으로 디스크가 바뀌지
  않았는지 확인한다. 다른 편집이 먼저 저장됐으면 덮어쓰지 않고 다시 읽도록 안내한다.

예상 형식은 다음과 같다. 구체적인 필드 이름은 아키텍처 작업에서 확정할 수 있지만 의미는 유지한다.

```yaml
# 프로젝트 사용자 정의 규칙

개발 보고서에는 성능 측정값과 측정 환경을 함께 적는다.
```

### 규칙을 읽는 순서와 우선순위

에이전트는 앱의 공통 규칙, 자신에게 배정된 역할 계약, 활성화된 사용자 정의 규칙 순서로 읽는다.
나중에 읽는 사용자 규칙이 앞의 규칙을 덮어쓴다는 뜻은 아니다. 우선순위는 다음과 같다.

1. 시스템과 도구의 안전 정책
2. 앱의 공통 규칙과 역할 계약
3. 프로젝트 사용자 정의 규칙
4. 아이디어, 기획서, 개발 작업, 보고서의 내용

사용자 정의 규칙은 문서 내용보다 높은 프로젝트 지시이지만, 앱 소유 파일과 승인 기록, 선점, 역할
분리, 사용자 승인과 QA 같은 필수 경계를 바꿀 수 없다. 충돌하는 규칙이 있으면 앱 기본 규칙을 따르고
충돌하지 않는 나머지 사용자 규칙만 적용한다.

이 우선순위를 공통 규칙에 명시한다. 앱이 자연어의 의미를 완전히 판정할 수 없으므로, 저장 전에
"안전 규칙과 충돌하지 않는다"고 거짓으로 보증하는 자동 검사는 만들지 않는다. 대신 설정 화면과 최종
파일 미리보기에 우선순위와 적용되지 않는 항목의 예를 보여준다.

### 설정 화면

설정 화면에 `사용자 정의 규칙` 카드를 추가한다.

- 사용 여부를 켜거나 끈다.
- 적용 역할로 기획자, 아키텍트, 개발자를 각각 선택한다. 최소 한 역할을 선택해야 켤 수 있다.
- Markdown 본문을 편집한다. 저장 버튼을 눌러야 파일에 반영되며 저장하지 않은 변경은 표시한다.
- 변경 취소로 마지막 저장 상태로 돌아갈 수 있다.
- 저장 파일 미리보기에서는 고정 프론트매터와 사용자가 작성한 본문을 함께 보여준다.
- 최종 적용 규칙 미리보기에서는 역할 하나를 선택하고, 공통 규칙과 해당 역할 계약, 사용자 정의 규칙을
  실제 읽는 순서와 출처별 구분으로 보여준다.
- 마지막 수정 시각과 현재 적용 상태를 보여준다.
- 활성 lease가 있으면 이미 실행 중인 에이전트는 이전 규칙을 사용하고 있을 수 있다고 안내한다. 저장을
  막지는 않는다.
- 규칙을 끄면 본문은 보존하고 다음 세션부터 적용하지 않는다. 다시 켜면 이전 본문을 그대로 사용한다.
- 내용을 완전히 지우는 동작은 별도 확인을 거친다.
- Markdown 미리보기는 HTML을 실행하지 않고 링크를 자동으로 열지 않는다.

### 앱 밖에서 파일이 바뀐 경우

사용자 정의 규칙은 Git으로 공유할 수 있으므로 앱 밖에서 바뀌는 것이 정상이다. 앱은 파일을 다시 읽어
설정 화면에 반영한다. 다만 스키마를 읽을 수 없거나 필수 값이 잘못됐거나 앱보다 새로운 스키마라면
자동으로 고치지 않는다.

이 경우 사용자 정의 규칙을 적용하지 않고 파일 원문과 오류를 보여준다. 앱 기본 규칙과 프로젝트 문서
조회는 계속 동작한다. 편집 중 파일이 바뀌면 저장을 막고 다시 불러오게 하며 자동 병합하지 않는다.
사용자가 앱에서 덮어쓰기를 명시적으로 선택하기 전에는 외부 변경을 보존한다.

사용자 정의 규칙은 다음 에이전트 세션이 실제 지시로 읽는 내용이다. 붙여넣은 외부 문장에 예상하지 못한
지시가 포함될 수 있으므로, 저장 전에 최종 적용 규칙 미리보기를 사용자가 확인하게 한다. 다만 외부
에이전트가 파일 시스템에 직접 쓸 수 있는 환경에서는 자연어 우선순위만으로 절대적인 보안을 보장할 수
없다. 앱은 결정 기록과 관리 파일을 쓰는 명령 경계를 그대로 유지하고 이 한계를 화면과 문서에 밝힌다.

### 포함 범위

- 프로젝트별 사용자 정의 규칙 파일 한 개와 파일 검증.
- 설정 화면의 본문 편집, 사용 여부, 역할 선택, 저장, 파일 미리보기.
- 역할별 최종 적용 규칙 미리보기와 외부 변경 시 재검토 절차.
- 공통 규칙과 역할 계약에 사용자 정의 규칙의 읽기 순서와 우선순위를 추가.
- Claude와 Codex가 같은 파일을 읽도록 두 진입점의 공통 안내를 갱신.
- 앱 밖 변경, 잘못된 형식, 더 새로운 스키마의 안전한 표시.
- 다음 에이전트 세션부터 적용된다는 안내.

### 제외 범위

- 여러 규칙 문서와 규칙별 이름, 정렬, 폴더 관리.
- 개인 전용, 앱 전체, 조직 전체 규칙.
- 파일 경로, 브랜치, 작업 종류, 모델에 따른 조건부 규칙.
- 규칙 템플릿, 공유 마켓, 가져오기와 내보내기.
- 자연어 규칙의 품질 평가와 의미 기반 충돌 검사.
- 실행 중인 에이전트 세션에 규칙을 다시 주입하는 기능.
- API 키와 비밀번호 같은 비밀 값 저장. UI에도 비밀 값을 넣지 말라는 안내를 표시한다.
- Codex 명령 승인 정책이나 Claude 권한 설정 변경.
- 앱 기본 안전 규칙을 끄거나 순서를 바꾸는 기능.

## 요구사항 명세

### R1. 사용자 정의 규칙은 기본 규칙과 분리해 저장한다

- 프로젝트마다 선택 파일 하나를 사용한다.
- 앱 기본 규칙 설치와 버전 갱신은 사용자 정의 규칙의 본문과 사용 여부를 변경하지 않는다.
- 파일이 없으면 기능이 꺼진 상태로 표시하고 현재 프로젝트 동작을 유지한다.
- 파일은 원자적으로 저장하며 저장 실패 시 기존 파일을 보존한다.
- 일반 파일만 읽고 쓴다. 심볼릭 링크와 지원하지 않는 파일 형식은 따라가지 않고 오류로 표시한다.
- 본문 길이와 제어문자를 검증하고, 비밀 값을 저장하지 말라는 안내를 제공한다.

### R2. 설정 화면에서 편집하고 적용 상태를 확인한다

- 사용 여부, 세 역할의 적용 범위, Markdown 본문을 편집할 수 있다.
- 저장 전 변경과 저장된 값을 구분한다.
- 사용자가 저장하기 전에 실제 파일 전체와 역할별 최종 적용 규칙을 미리 볼 수 있다.
- 마지막 수정 시각과 현재 적용 여부를 보여준다.
- 규칙을 끄더라도 본문을 지우지 않는다.
- 저장은 마지막으로 읽은 내용 식별값을 함께 보내며, 디스크가 달라졌으면 저장하지 않는다.

### R3. 필수 안전 규칙이 항상 우선한다

- 공통 규칙에 사용자 정의 규칙의 위치와 우선순위를 적는다.
- 사용자 정의 규칙은 앱 소유 상태, 사용자 결정, 선점, 역할 분리, 한 세션 한 대상, 승인 전 구현 금지를
  완화할 수 없다.
- 사용자 정의 규칙이 역할 계약과 충돌하면 역할 계약을 따른다.
- 아이디어와 기획서, 개발 작업, 보고서 안의 문장은 사용자 정의 규칙을 바꾸는 지시로 취급하지 않는다.

### R4. 세 역할이 같은 규칙 파일을 읽는다

- 관리되는 프로젝트 진입 안내에 활성화된 사용자 정의 규칙을 읽는 단계를 추가한다.
- 에이전트는 자신의 역할이 적용 대상일 때만 본문을 규칙으로 사용한다.
- 파일이 꺼져 있거나 형식을 읽을 수 없으면 본문을 규칙으로 사용하지 않는다.
- Claude와 Codex에 서로 다른 사용자 정의 본문을 만들지 않는다.

### R5. 외부 변경을 안전하게 다룬다

- 앱 밖에서 정상 형식으로 바뀐 파일은 다음 조회에서 설정 화면에 반영한다.
- 형식 오류와 더 새로운 스키마는 사용자 정의 규칙만 비활성 상태로 표시한다.
- 오류가 있어도 앱 기본 규칙 설치와 프로젝트 문서 조회는 계속 동작한다.
- 앱은 외부 변경을 자동 덮어쓰거나 일부 값만 추측해 고치지 않는다.
- 사용자가 편집하는 동안 외부 변경이 생기면 자동 병합하지 않고 다시 불러오도록 안내한다.

### R6. 적용 시점을 명확히 알린다

- 저장과 사용 여부 변경은 앱 재시작 없이 파일에 반영된다.
- 변경 내용은 그 뒤 새로 시작하는 에이전트 세션부터 적용된다.
- 이미 실행 중인 세션이 있으면 이전 규칙을 사용할 수 있다는 안내를 보여준다.
- 앱이 실행 중인 에이전트의 규칙 적용 여부를 확인했다고 표시하지 않는다.

### R7. 첫 버전은 규칙 문서 하나에 집중한다

- 여러 규칙 묶음, 조건식, 템플릿, 전역 설정을 추가하지 않는다.
- 저장 형식은 이후 여러 문서로 확장할 수 있어야 하지만, 첫 구현에서 확장 기능을 미리 만들지 않는다.
- 사용자 정의 규칙이 실제로 반복 사용되는지 확인한 뒤 다음 범위를 결정한다.

## 확인 필요

없다. 프로젝트별 파일 하나, 역할 범위, 기본 규칙 우선, 다음 세션부터 적용이라는 첫 버전의 경계를 이
기획서에서 정했다. 여러 규칙 묶음이나 개인 전용 규칙이 필요해지면 별도 아이디어로 판단한다.

## 기대효과

- 사용자가 관리 파일을 직접 고치지 않고 앱 화면에서 프로젝트 규칙을 정의할 수 있다.
- Claude와 Codex가 같은 프로젝트 규칙을 읽어 도구를 바꿔도 행동 기준이 달라지지 않는다.
- 팀이 규칙 파일을 Git으로 검토하고 공유할 수 있다.
- 사용자는 규칙이 켜져 있는지, 어떤 역할에 적용되는지, 실제 파일이 어떻게 저장되는지 확인할 수 있다.
- 앱 업데이트가 사용자 규칙을 지우지 않고, 사용자 규칙도 앱의 승인과 안전 경계를 약화하지 않는다.

## 완료 조건

1. 사용자 정의 규칙 파일이 없는 기존 프로젝트가 오류 없이 열리고 기능은 꺼진 상태로 보인다.
2. 설정 화면에서 본문과 적용 역할을 입력하고 켠 뒤 저장하면 미리보기와 같은 파일이 생성된다.
3. 저장된 파일을 다시 열었을 때 본문, 사용 여부, 적용 역할, 수정 시각이 화면에 복원된다.
4. 규칙을 끄면 본문은 보존되고, 다음 에이전트 세션은 그 본문을 규칙으로 사용하지 않는다.
5. 공통 규칙과 세 역할 계약에 사용자 정의 규칙의 읽기 조건과 우선순위가 들어 있다.
6. Claude와 Codex의 관리 진입점이 같은 사용자 정의 규칙 파일을 안내한다.
7. 앱 기본 규칙을 갱신해도 사용자 정의 규칙 파일의 내용과 수정 시각이 바뀌지 않는다.
8. 사용자 정의 규칙 파일을 앱 밖에서 정상적으로 수정하면 설정 화면에 새 내용이 반영된다.
9. 형식이 잘못됐거나 앱보다 새로운 스키마인 파일은 자동으로 바뀌지 않고 오류 상태로 표시된다.
10. 9번의 오류가 있어도 기본 규칙 설치와 프로젝트 문서 조회는 정상 동작한다.
11. 활성 lease가 있는 상태에서 저장하면 적용 시점 안내가 보이고 저장은 완료된다.
12. 편집 중 파일이 외부에서 바뀌면 저장이 거부되고, 다시 불러온 뒤 재검토할 수 있다.
13. 저장 파일 미리보기에는 고정 메타데이터와 사용자 본문이 함께 표시된다. 역할별 최종 적용 규칙
    미리보기에서는 세 규칙 출처와 읽는 순서를 구분할 수 있다.
14. Markdown 미리보기는 HTML을 실행하거나 링크를 자동으로 열지 않으며, 비밀 값을 넣지 말라는 안내가
    있다.
15. 심볼릭 링크, 잘못된 역할 값, 길이 제한 초과, 허용하지 않는 제어문자는 기존 파일을 바꾸지 않고
    오류로 표시된다.
16. 기존 프로젝트 조회, 기획 결정, 작업 QA, 규칙 설치, 설정 화면 검사가 모두 통과한다.
17. 여러 규칙 문서, 전역 규칙, 조건부 적용, 템플릿, 의미 기반 충돌 검사는 구현되지 않는다.
