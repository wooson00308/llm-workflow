# 품질 확인 화면에 기능 소개 문단만 보여주기

## 결정권자 요약

### 제안

품질 확인 화면의 기능 카드에 작업 그룹 문서의 사용자용 소개 문단만 최대 세 줄로 보여주고, 아키텍트가 남긴 내부 절은 화면에서 내린다.

### 현재

카드에 그룹 문서 본문이 통째로 실린다. 사용자용 소개뿐 아니라 작업 분해 근거와 품질 확인 방식 설명까지 이어 붙고, 절 제목에 쓰인 마크다운 기호가 문장 사이에 그대로 노출되며, 문단 구분이 사라져 한 덩어리로 읽힌다. 가장 긴 그룹은 카드 한 장에 26줄, 1191자가 들어간다. 확인하러 온 사용자가 "이 기능이 무엇이고 무엇을 확인하면 되는가"를 찾기 어렵다.

### 변경 후

카드에는 기능 소개 문단만 최대 세 줄로 실린다. 같은 그룹 기준으로 26줄이 4줄, 1191자가 200자로 줄어든다. 카드 높이가 그룹마다 들쭉날쭉하지 않고 일정해져 확인 대기 목록을 위에서 아래로 훑는 것만으로 어떤 기능이 올라와 있는지 파악할 수 있다. 시작을 눌러 들어간 확인 화면과 완료 기록 화면도 같은 소개 문단만 보여주며, 여기서는 줄 수를 제한하지 않고 문단 구분을 살린다. 확인 동선은 지금과 같아서 시작을 눌러야 확인 절차가 열린다.

### 비용과 위험

아키텍트의 작업 분해 근거와 품질 확인 방식 설명은 앱 화면에서 더 이상 보이지 않는다. 이 내용은 그룹 문서 파일에 그대로 남으므로 필요하면 문서를 열어 읽을 수 있고, 문서를 고치는 변경이 아니라 표시 규칙만 바꾸는 변경이라 되돌리기도 표시 규칙을 되돌리는 것으로 끝난다. 기존 그룹 문서 59건을 모두 확인한 결과 새 규칙에서 소개 문단이 비는 그룹은 없어, 지금 보이던 설명이 사라지는 그룹은 생기지 않는다. 이 기획서가 승인되지 않으면 그룹 문서와 확인 동선은 지금 그대로 유지되고, 카드도 지금처럼 본문 전체를 계속 보여준다.

## 기획 내용

### 문제

품질 확인 화면은 모든 작업이 끝난 기능을 사용자가 직접 확인하는 자리다. 목록의 기능 카드는 제목 아래에 그룹 설명 한 줄을 붙이도록 만들어져 있지만, 실제로 붙는 값은 그룹 문서 본문 거의 전부다.

앱은 그룹 문서 본문에서 문서 제목 한 줄과 `## 기능 설명`이라는 제목 줄만 걷어내고, 사용자 확인 플로우 절을 뺀 나머지 줄을 전부 이어 붙여 설명으로 쓴다. 그래서 `## 품질 확인 방식`이나 `## 작업 구성` 같은 내부 절의 제목 줄과 본문이 함께 설명에 들어간다. 이 값은 서식 없는 글자로 그려지기 때문에 절 제목의 우물 정 기호가 문장 사이에 그대로 보이고, 문단을 나누던 빈 줄은 사라져 전체가 한 덩어리로 이어진다.

기존 그룹 문서 59건을 실측한 결과는 다음과 같다.

- 카드에 실리는 분량이 가장 큰 그룹은 GROUP-061로, 빈 줄을 뺀 26줄, 1191자다.
- 그다음은 18줄 765자, 14줄 555자, 10줄 1513자 순이다.
- 이 네 건은 모두 소개 문단 뒤에 내부 절을 둔 그룹이며, 내부 절이 카드에 실린 분량의 대부분을 차지한다.

### 해결 방향

앱이 카드에 쓰는 값을 "그룹 문서 본문 중 사용자용 소개 문단"으로 좁힌다. 소개 문단을 찾는 기준은 다음 두 가지이며, 앞의 기준이 맞으면 뒤의 기준은 보지 않는다.

1. 본문에 `## 기능 설명` 절이 있으면 그 절의 본문이 소개 문단이다. 다음 절 제목을 만나면 거기서 끝난다.
2. 그런 절이 없으면 문서 제목 다음부터 첫 번째 절 제목 앞까지가 소개 문단이다.

기존 문서 59건 중 55건은 첫 번째 기준에 해당하고 4건은 두 번째 기준에 해당한다. 두 기준을 모두 적용했을 때 소개 문단이 비는 문서는 없다.

소개 문단이 아닌 절은 어떤 화면에도 올리지 않는다. 사용자 확인 플로우 절은 지금처럼 시작을 누른 뒤에만 열리며, 이 기획서는 그 동선을 건드리지 않는다.

### 화면별 표시 기준

같은 소개 문단을 세 자리에서 쓰되 분량 기준만 다르다.

- 품질 확인 목록의 기능 카드: 소개 문단을 최대 세 줄까지 보여주고, 넘치면 말줄임으로 끊는다. 카드는 훑어보는 자리이므로 문단 구분을 살리지 않고 이어 쓴다.
- 시작을 눌러 들어간 확인 화면의 머리말: 소개 문단 전체를 보여주고 줄 수를 제한하지 않는다. 문단이 여럿이면 문단 구분이 보이게 그린다.
- 완료 기록 화면의 기능 상세: 확인 화면의 머리말과 같은 기준을 쓴다.

세 줄이라는 상한은 이 기획서가 정한 값이다. 실측한 소개 문단의 길이는 최소 33자, 중앙값 33자, 최대 327자이며, 세 줄이면 최대 길이의 소개도 대부분 들어가고 카드 높이는 일정하게 유지된다. 더 짧게 끊기를 원하면 수정 요청으로 알려 주면 된다.

## 요구사항 명세

- R1. 앱은 그룹 문서 본문에서 사용자용 소개 문단을 위 "해결 방향"의 두 기준으로 뽑는다. 소개 문단 뒤에 오는 절의 제목과 본문은 뽑지 않는다.
- R2. 품질 확인 목록의 기능 카드는 소개 문단을 최대 세 줄까지 보여주고, 넘치면 말줄임으로 끊는다.
- R3. 시작을 눌러 들어간 확인 화면의 머리말과 완료 기록 화면의 기능 상세는 소개 문단 전체를 보여주고, 문단이 여럿이면 문단 구분이 보이게 그린다.
- R4. 세 화면 어디에도 절 제목의 마크다운 기호가 글자 그대로 나오지 않는다.
- R5. 소개 문단을 뽑을 수 없는 그룹에서는 소개 자리를 비워 두고 제목만 보여준다. 빈 줄이나 자리표시 문구를 넣지 않는다.
- R6. 사용자 확인 플로우는 지금처럼 시작을 눌러야 열린다. 목록 카드에는 확인 플로우의 어떤 부분도 실리지 않는다.
- R7. 기존 그룹 문서를 고치지 않는다. 문서를 고쳐야만 올바르게 보이는 방식은 이 기획서의 해법이 아니다.

## 제외 범위

- 아키텍트가 그룹 문서를 쓸 때 지키는 작성 지침은 이 기획서에서 바꾸지 않는다. 지금 지침은 소개를 어느 절에 쓰라고 지정하지 않아 두 가지 형태가 함께 존재하며, R1의 두 번째 기준이 그 형태를 그대로 받아 준다. 작성 지침을 한 형태로 모으는 일은 별도 아이디어로 다룬다.
- 사용자 확인 플로우 절의 내용과 표시 방식은 바꾸지 않는다.
- 그룹 제목, 상태 표시, 준비 중인 기능 목록의 구성은 바꾸지 않는다.
- 개발 화면의 작업 상세에 있는 그룹 정보는 제목과 상태만 쓰고 있어 이 변경의 대상이 아니다.

## 완료 판정 기준

- A1. GROUP-061처럼 소개 문단 뒤에 내부 절을 둔 그룹을 품질 확인 목록에서 열면, 카드에 내부 절의 제목과 본문이 보이지 않고 소개 문단만 세 줄 이내로 보인다.
- A2. `## 기능 설명` 절을 쓰는 그룹과 쓰지 않는 그룹이 목록에 함께 있을 때, 두 종류 모두 카드에 소개 문단이 보인다. 어느 쪽도 소개가 비지 않는다.
- A3. 소개 문단이 세 줄을 넘는 그룹의 카드는 말줄임으로 끊기고, 카드 높이가 소개 길이가 짧은 그룹의 카드와 같다.
- A4. 시작을 누르면 확인 화면이 열리고, 머리말에 소개 문단 전체가 보이며 문단 구분이 유지된다. 내부 절은 여기에도 보이지 않는다.
- A5. 완료 기록 화면에서 기능 하나를 열면 A4와 같은 기준으로 소개 문단이 보인다.
- A6. 세 화면 어디에서도 우물 정 기호로 시작하는 절 제목이 글자 그대로 보이지 않는다.
- A7. 기존 그룹 문서 59건의 파일 내용이 이 변경 전후로 같다.

## 기대효과

품질 확인 목록이 "확인할 기능 목록"으로 읽힌다. 카드마다 높이가 같아 위에서 아래로 훑는 것만으로 무엇이 올라와 있는지 알 수 있고, 기능 이름과 한 문단짜리 소개라는 판단에 필요한 정보만 남는다.

아키텍트가 그룹 문서에 작업 분해 근거를 자세히 적을수록 사용자 화면이 나빠지던 관계가 끊어진다. 문서는 문서대로 충실하게 쓰고, 화면은 사용자가 볼 부분만 가져간다.
