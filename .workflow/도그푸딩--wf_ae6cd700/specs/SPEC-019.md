# 설치 가이드 접힘이 화면을 떠나도 남는다

## 기획 내용

연동 뷰에는 접히는 것이 두 겹으로 있다. 바깥은 연동 카드다. 카드 머리의 "펼치기/접기"로 하트비트·드림 카드를 각각 접어 두면 그 선택은 브라우저 저장소에 남아, 다른 메뉴를 다녀오든 앱을 다시 열든 그대로 유지된다. SPEC-006 R6이 그것을 요구했고 완료 조건 13번이 자동화 테스트로 고정해 두었다.

안쪽은 하트비트 카드의 설치 가이드다. 필수 단계가 남아 있는 동안 보이는 마법사에 "설치 가이드 접기/펼치기" 토글이 붙어 있다. 이 토글의 상태는 어디에도 남지 않는다. 마법사 컴포넌트의 지역 상태이고 초기값이 펼침이다. 연동 뷰는 조건부 렌더라서 다른 메뉴를 누르는 순간 통째로 언마운트되고, 돌아오면 새로 마운트되면서 가이드는 다시 펼쳐져 있다. 앱을 다시 열거나 프로젝트를 전환해도 같다.

그래서 사용자가 겪는 것은 "어떤 접기는 기억되고 어떤 접기는 기억되지 않는다"이다. 같은 화면, 같은 모양의 토글, 같은 낱말("접기"/"펼치기")인데 결과가 다르다. 카드 머리를 접어 두는 습관이 든 사용자일수록 안쪽 토글도 같게 동작하리라 기대하고, 매번 다시 접게 된다.

이 결함은 오해에서 나온 것이 아니라 요구가 없어서 생겼다. 설치 가이드의 접기 토글은 SPEC-016이 요구한 것이 아니다. SPEC-016은 마법사의 표시 조건(필수 단계가 남았는가)만 정했고, 사용자가 그 마법사를 접어 둔다는 이야기는 본문에도 완료 조건에도 없다. 토글은 구현 과정에서 "연동 카드의 접기와 같은 성질의 조작"이라며 더해졌고, 코드 주석이 그 사실을 그대로 적어 두었다. 같은 성질이라고 판단한 조작에 같은 성질의 기억은 따라오지 않았다.

바꿔야 할 것은 하나다. 마운트를 넘어서는 기억. 마운트가 유지되는 동안은 지금도 정상이다 — 접어 둔 가이드를 다음 스냅샷 갱신이 다시 펼치지 않고, 그 성질은 이미 테스트가 고정하고 있다. 접기가 언마운트가 아니라 `hidden`이라는 것, 접힌 채로도 "설치 가이드"와 "필수 단계 n/m 완료" 줄이 남는다는 것도 그대로 둔다. 이 기획서는 그 위에 기억만 얹는다.

### 확인 사실

2026-08-04 기준으로 작업 트리의 코드·테스트·기획서에서 직접 읽은 값이다. 추정으로 적은 항목은 없다.

1. 설치 가이드의 접힘 상태는 마법사 컴포넌트의 지역 상태다. `HeartbeatCard.tsx:411`의 `const [open, setOpen] = useState(true)`가 전부이고, 이 값을 저장소에 쓰는 코드는 없다.
2. 연동 카드의 펼침 상태는 저장된다. `IntegrationsView.tsx:35`가 `browserIntegrationCollapseStore.load()`로 초기값을 읽고, `:40`의 토글이 바뀐 값을 곧바로 `save()`한다. 키는 `workflow-labs.integration-collapse.v1`이다.
3. 연동 뷰는 조건부 렌더다. `WorkspaceShell.tsx:405`가 `view === "integrations" && <IntegrationsView …/>`로 그린다. 다른 메뉴를 고르면 언마운트되므로 뷰 안의 모든 지역 상태가 사라진다. 카드 펼침만 저장소에서 되살아난다.
4. 그 저장소는 실패를 삼킨다. `browserIntegrationCollapseStore`의 `load`는 값 없음·JSON 파싱 실패·객체 아님·접근 실패를 전부 빈 맵으로 돌리고, `save`도 실패를 삼킨다. 표시 상태를 못 읽었다고 화면이 뜨지 않는 쪽이 훨씬 나쁘다는 판단이 주석에 적혀 있다.
5. 가이드의 기본값은 펼침이고 테스트가 고정한다(`IntegrationsView.test.tsx`의 "starts expanded and counts only the finished required steps").
6. 마운트가 유지되는 동안의 기억은 이미 있다. "stays folded while the next snapshot refreshes the checks" 테스트가 접어 둔 가이드를 다음 스냅샷이 다시 펼치지 않는다는 것을 고정한다. 즉 결함은 마운트를 넘어서는 기억이 없다는 것 하나다.
7. 접기는 언마운트가 아니다. `hidden={!open}`으로 감추고 단계 목록을 DOM에 남긴다. 어느 단계를 복사했는지 같은 화면 상태가 접기 때문에 사라지지 않게 하려는 것이고, 연동 카드 본문도 같은 방식이다.
8. 마법사는 필수 단계가 모두 `done`이면 `null`을 반환한다(`HeartbeatCard.tsx:417`). 사라졌다가 다시 나타나면 지역 상태는 초기값인 펼침으로 돌아온다.
9. 설치 가이드의 접기 토글은 SPEC-016의 요구가 아니다. SPEC-016 본문과 완료 조건 어디에도 사용자가 마법사를 접는다는 요구가 없다. `HeartbeatCard.tsx:408`의 주석이 "연동 카드의 접기와 같은 성질이라 같은 idiom을 쓴다"고 그 유래를 적는다.
10. SPEC-006 R6은 카드 접힘에 대해 다섯 가지를 이미 정해 두었다. 조작하지 않은 카드는 접힘으로 시작, 마지막 상태를 기억, 기억은 연동 단위, 깨진 값이면 기본값으로 동작하고 오류를 보이지 않음, 이제 없는 연동을 가리키는 값이 남아도 정상 동작. 완료 조건 13번이 "다른 화면을 다녀오거나 앱을 다시 연 뒤에도 유지"를 검증한다.
11. 마법사의 네 단계는 전부 머신 전역 신호에서 나온다. `heartbeat_setup.rs:41`의 `setup_stages`가 받는 입력은 `heartbeat_home`, `user_home`, `HEARTBEAT.md` 읽기 결과, dream 스킬 설치 여부다. 프로젝트 경로는 판정에 들어가지 않으므로 프로젝트를 바꿔도 단계 상태는 같다.
12. 이 가이드를 만든 TASK-049(SPEC-016 파생)는 `qa_waiting`이다. 이 세션 시점에 `todo`나 `in_progress` 상태의 작업은 하나도 없고, 열린 작업 17건은 모두 `qa_waiting`이다.
13. 드림 카드에는 설치 가이드가 없다. 연동 뷰에서 사용자가 접을 수 있는 자리는 카드 둘과 하트비트 설치 가이드 하나뿐이다.

### 포함 범위

- 하트비트 설치 가이드의 접힘·펼침을 기억해, 다른 화면을 다녀오거나 앱을 다시 열어도 사용자가 고른 상태로 열리게 한다.
- 기억이 없거나 깨졌을 때의 기본값과 실패 처리를 카드 접힘과 같은 규칙으로 맞춘다.
- 마법사가 사라졌다 다시 나타날 때의 동작을 정한다.
- 위 동작을 자동화 테스트로 고정한다.

### 제외 범위

- 연동 카드 접힘의 동작 변경. 이미 요구대로 동작하므로 건드리지 않는다.
- 설치 가이드의 문구·단계 구성·단계 판정·자동 재확인. SPEC-016이 정한 것 그대로다.
- 마법사의 표시 조건. 필수 단계가 남아 있을 때만 보인다는 판정(SPEC-016 R8)은 그대로이고, 이 기획서의 기억은 보이는 마법사의 접힘만 다룬다.
- 복사 결과 표시(`copied`)와 역할 잡 편집 폼 값의 기억. 뷰를 떠날 때 초기화되는 현행 동작을 그대로 둔다. SPEC-006 R7이 이미 "다른 화면에 갔다 온 뒤의 폼 초기화는 현행과 같아도 된다"고 정했다.
- 드림 카드에 같은 가이드를 만드는 일.
- 표시 상태를 백엔드나 프로젝트 파일에 저장하는 것. 표시 상태는 지금처럼 앱 바깥으로 나가지 않는다.
- 접힘 상태의 동기화·내보내기·초기화 같은 관리 기능.

## 요구사항 명세

### R1. 설치 가이드의 접힘이 화면을 떠나도 남는다

- 사용자가 설치 가이드를 접어 두면, 다른 메뉴를 다녀오거나 앱을 다시 열어도 접힌 상태로 열린다. 펼침도 같다. 사용자가 마지막으로 고른 상태가 다음에 보이는 상태다.
- 한 번도 조작하지 않았으면 펼침으로 시작한다. 현행 기본값을 그대로 둔다. 마법사는 필수 단계가 남아 있을 때만 보이므로, 처음 보는 사용자에게는 펼쳐진 안내가 맞다.
- 기억은 설치 가이드 하나의 상태다. 연동 카드의 접힘과 별개 축이라 서로를 바꾸지 않는다. 하트비트 카드를 접었다 펴도 가이드는 사용자가 고른 상태 그대로다.
- 프로젝트를 바꿔도 같은 상태다(확인 필요 1번의 결정 범위). 네 단계가 전부 머신 전역 신호라 프로젝트마다 다른 가이드가 되지 않는다.

### R2. 기억을 읽지 못해도 화면은 정상이다

- 저장된 값이 없거나, 형식이 깨졌거나, 저장소에 접근할 수 없으면 기본값(펼침)으로 동작한다. 오류 문구를 사용자에게 보이지 않는다.
- 저장에 실패해도 그 자리의 토글은 그대로 동작한다. 이번에 고른 상태는 화면에 반영되고, 남지 않을 뿐이다.
- 이 규칙은 새로 만드는 것이 아니라 카드 접힘 기억이 이미 지키는 규칙과 같은 것이다. 표시 상태 하나 때문에 화면이 뜨지 않거나 사용자가 모르는 오류를 읽게 되는 쪽이 훨씬 나쁘다.
- 저장 수단은 아키텍트가 정한다. 카드 접힘이 쓰는 저장소를 넓힐지 별도의 키를 둘지 이 기획서는 정하지 않는다.

### R3. 마법사가 사라졌다 돌아와도 선택이 남는다

- 필수 단계가 모두 끝나 마법사가 사라진 뒤 다시 미완료가 되어 마법사가 돌아오면, 사용자가 마지막으로 고른 접힘 상태로 돌아온다(확인 필요 2번의 결정 범위).
- 스냅샷 갱신이 사용자의 선택을 되돌리지 않는다. 현행 성질이고 이 변경 뒤에도 유지한다.
- 마법사가 보이지 않는 동안 기억을 지우지 않는다. 지우면 필수 단계가 잠시 완료로 보였다 돌아오는 것만으로 사용자의 선택이 사라진다.

### R4. 표시만 바꾸는 조작이라는 성질을 유지한다

- 접기는 언마운트가 아니다. 접힌 상태에서도 "설치 가이드" 제목과 "필수 단계 n/m 완료" 요약, 다시 펼 수 있는 토글은 남는다.
- 접혀 있다는 이유로 단계 판정, 자동 재확인, 명령 복사, 카드 배지와 경고 표시가 달라지지 않는다.
- 펼침 여부가 보조 기술에 노출되는 현행 접근성 속성을 유지한다.
- 이 변경으로 기존 자동화 테스트를 삭제하거나 비활성화하지 않는다.

## 확인 필요

사용자 결정이 필요한 항목이다. 승인 시 아래 제안대로 진행한다.

1. **기억을 앱 전체 하나로 둘지, 프로젝트마다 따로 둘지.**

   제안: 앱 전체 하나로 둔다. 근거는 둘이다. 첫째, 가이드가 안내하는 네 단계가 전부 머신 전역이다(확인 사실 11번). `heartbeat` 패키지 설치, `heartbeat init`, 서비스 등록, dream 스킬 중 어느 것도 프로젝트를 바꾼다고 달라지지 않으므로, 프로젝트마다 따로 접어 둘 이유가 생기지 않는다. 둘째, 이미 있는 카드 접힘 기억도 프로젝트 구분 없이 하나다. 안쪽만 프로젝트별로 두면 같은 화면의 두 토글이 또 다른 방식으로 갈라진다.

   반대 근거: 프로젝트마다 창을 따로 쓰듯 일하는 사용자라면, 설치를 끝낸 프로젝트에서는 접어 두고 새로 붙인 프로젝트에서는 펼쳐 보고 싶을 수 있다. 다만 그 경우에도 단계 상태 자체는 두 프로젝트가 같으므로, 얻는 것은 "화면을 덜 본다"뿐이다.

2. **마법사가 사라졌다 다시 나타날 때 접힘을 유지할지, 펼쳐서 보여줄지.**

   제안: 유지한다(R3). 근거는 둘이다. 첫째, 기억의 뜻이 "사용자가 고른 상태"이므로, 앱이 판단해 되돌리기 시작하면 사용자는 자기가 접어 둔 것이 왜 펼쳐져 있는지 알 수 없다. SPEC-006이 "화면이 열릴 때마다 펼침 상태가 스스로 달라지면 안 된다"며 같은 이유로 상태 의존 자동 펼침을 배제했다. 둘째, 접힌 상태에서도 "필수 단계 n/m 완료" 요약이 남고 카드 배지와 경고 표시는 따로 있으므로, 접혀 있다고 해서 새로 생긴 문제가 감춰지지 않는다.

   반대 근거: 다 끝났던 설치가 깨져서 마법사가 돌아오는 것은 사용자가 몰랐던 사건이다. 그 순간만큼은 펼쳐서 보여주는 편이 친절하다는 주장이 가능하다. 뒤집기로 하면 R3이 "마법사가 다시 나타날 때는 펼침으로 시작한다"로 바뀌고, 기억은 같은 마법사가 계속 보이는 동안에만 유효해진다.

## 기대효과

- 같은 화면의 두 토글이 같게 동작한다. 지금은 카드 머리를 접으면 남고 그 안의 가이드를 접으면 사라져, 사용자가 어느 쪽이 기억되는지 따로 외워야 한다.
- 설치를 끝내지 못한 채 오래 쓰는 사용자가 가이드를 한 번 접어 두면 그걸로 끝난다. 지금은 연동 뷰에 들어올 때마다 다시 접어야 한다.
- 설치 단계가 확인 불가로 남는 플랫폼일수록 이득이 크다. macOS 밖에서는 3단계가 언제나 확인 불가라 마법사가 사라지지 않으므로, 그 사용자는 연동 뷰에 들어올 때마다 펼쳐진 가이드를 본다.
- 표시 상태를 기억하는 규칙이 화면 전체에서 하나가 된다. 다음에 접히는 자리가 생겼을 때 참고할 선례가 갈라져 있지 않다.

## 완료 조건

1. 설치 가이드를 접은 뒤 다른 메뉴를 다녀와도 접혀 있다. 검증: 연동 뷰를 떠났다 돌아오는 자동화 테스트로 확인한다.
2. 접은 뒤 앱을 다시 열어도 접혀 있다. 검증: 저장된 값이 있는 상태에서 뷰를 처음 그려 확인한다.
3. 펼친 상태도 같게 유지된다. 검증: 접었다가 다시 편 뒤 1·2번과 같은 경로로 확인한다.
4. 한 번도 조작하지 않았으면 펼침으로 시작한다. 검증: 저장된 값이 없는 환경에서 뷰를 처음 열어 확인하고, 기존 "starts expanded" 테스트가 수정 없이 통과하는지 확인한다.
5. 하트비트 카드를 접었다 펴도 가이드의 접힘 상태가 바뀌지 않는다. 검증: 카드 토글과 가이드 토글을 섞어 조작하는 테스트로 확인한다.
6. 가이드를 접어도 연동 카드의 펼침 기억이 바뀌지 않는다. 검증: 저장된 카드 접힘 값이 그대로인지 확인한다.
7. 저장된 값이 깨졌거나 형식이 다르면 기본값으로 동작하고 오류 문구가 보이지 않는다. 검증: 손상된 값을 넣은 상태에서 뷰를 열어 확인한다.
8. 저장소에 접근할 수 없어도 화면이 정상으로 그려지고 토글이 동작한다. 검증: 읽기·쓰기가 실패하는 환경으로 확인한다.
9. 마법사가 사라졌다 다시 나타나면 마지막으로 고른 접힘 상태로 돌아온다. 검증: 필수 단계를 모두 완료로 바꿔 마법사를 없앤 뒤 다시 미완료로 되돌리는 테스트로 확인한다.
10. 스냅샷 갱신이 접어 둔 가이드를 다시 펼치지 않는다. 검증: 기존 "stays folded while the next snapshot refreshes the checks" 테스트가 수정 없이 통과하는지 확인한다.
11. 접힌 상태에서 "설치 가이드" 제목, "필수 단계 n/m 완료" 요약, 다시 펼치는 토글이 보인다. 검증: 기존 접기 테스트가 수정 없이 통과하는지 확인한다.
12. 접혀 있어도 단계 판정·명령 복사·카드 배지·경고 표시가 달라지지 않는다. 검증: 접힌 상태에서 복사와 경고 표시를 확인하는 테스트로 확인한다.
13. 펼침 여부가 보조 기술에 노출되는 속성이 유지된다. 검증: `aria-expanded`와 `aria-controls`를 확인하는 기존 테스트가 통과하는지 확인한다.
14. 기존 자동화 테스트가 삭제되거나 비활성화되지 않는다. 검증: 테스트 목록 변경분을 확인한다.
15. `npm run check`가 통과한다.
