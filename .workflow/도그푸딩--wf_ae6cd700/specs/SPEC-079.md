# 확인이 끝난 실패 기록을 최근 종료 목록에서 접는다

## 결정권자 요약

### 제안

원인 파악과 조치가 끝난 실패 실행 기록을 사용자가 확인 처리하면, 최근 종료 목록에서는 접히고 전체 실행 기록에서는 확인 표시와 함께 그대로 남는다.

### 바뀌는 것

- 지금: 조치가 끝난 실패도 최근 종료 목록에 빨간 표시로 계속 남는다 → 앞으로: 확인한 실패는 접히고 접힌 건수만 한 줄로 남는다
- 지금: 이 실패를 이미 봤는지 화면 어디에도 적혀 있지 않다 → 앞으로: 전체 실행 기록의 확인한 줄에 확인함 표시가 붙는다
- 실행 하나를 열어 확인하는 방법과, 남은 실패를 한 번에 확인하는 방법을 함께 둔다

### 비용과 위험

- 확인 여부는 사람의 판단이므로, 조치가 실제로 끝나지 않은 실패를 접어 두면 그만큼 늦게 발견한다.
- 앱은 실행 기록을 지우지 않으며, 승인되지 않으면 목록은 지금처럼 모든 종료 기록을 그대로 보여준다.

## 기획 내용

### 사용자가 보는 문제

실행 화면의 최근 종료 구역은 끝난 실행 세 건을 최신순으로 보여주고, 각 줄 앞에 상태 점을 찍는다. 실패와 복구 필요 두 상태는 빨간 점이다. 전체 기록 버튼을 누르면 끝난 실행 전부가 같은 형식으로 나온다.

이 화면은 실패를 한 번 그리고 나면 그 뒤의 일을 반영하지 않는다. 사용자가 로그를 열어 원인을 규명하고 조치까지 끝내도, 다음에 실행 화면을 열면 같은 줄이 같은 빨간 점을 달고 그대로 서 있다. 화면만 보고는 방금 난 실패인지 지난주에 끝낸 실패인지 구별할 수 없다.

실제 손해는 여기서 나온다. 이번 주에만 두 번, 이미 규명이 끝난 기록을 사용자가 새 장애로 오인해 다시 문의했다. 확인에 드는 시간도 시간이지만, 빨간 표시가 조치와 무관하게 계속 남으면 사용자는 그 표시를 신뢰하지 않게 된다. 진짜 새 실패가 났을 때 알아보지 못하는 것이 더 큰 손해다.

### 왜 이렇게 되는가

목록의 표시는 실행의 종료 상태 하나만 보고 정해진다. 사용자가 그 기록을 보았는지, 조치했는지를 담는 값이 어디에도 없다. 사람이 한 일을 화면이 알 방법이 없으므로, 상태가 실패인 한 표시는 영원히 실패다.

그래서 이 기획서는 실행 기록을 고치지 않는다. 사용자가 그 기록을 확인했다는 사실을 앱이 따로 들고, 목록이 그 값을 함께 읽어 표시를 정한다.

### 확인 처리의 대상

확인 처리는 실패와 복구 필요, 두 상태로 끝난 실행 기록에만 붙는다. 지금 빨간 점이 붙는 상태가 이 둘이고, 사용자가 오인한다고 말한 표시도 이 빨간 점이다.

- 완료는 문제로 보이지 않으므로 대상이 아니다.
- 취소됨은 사용자가 스스로 끝낸 결과라 새 문제로 읽히지 않는다.
- 상태 확인 필요는 어떤 결과인지 아직 모르는 기록이다. 조치가 끝났다고 표시할 근거가 없으므로 대상에서 뺀다.

복구 필요를 포함한 이유는 그 상태가 사용자에게 남은 정리 작업을 요구하기 때문이다. 정리를 마친 기록이야말로 확인 처리가 필요한 전형이다. 다만 확인 처리는 남은 정리가 끝났다고 앱이 판정하는 것이 아니라 사용자가 끝냈다고 적어 두는 것이며, 상세 화면의 남은 정리 안내는 확인 처리 뒤에도 그대로 보인다.

### 확인하는 방법

개별과 일괄 두 가지를 둔다. 개별은 조치 직후의 자연스러운 동작이고, 일괄은 이미 쌓인 기록을 한 번에 정리하기 위한 것이다.

개별 확인은 실행 상세 화면에서 한다. 사용자는 원인을 보려고 이미 그 화면을 열어 로그와 결과 보고서를 읽으므로, 조치가 끝나는 자리와 확인하는 자리가 같아진다. 이미 확인한 기록에서는 같은 자리에 확인 해제가 놓여, 잘못 누른 경우와 판단이 바뀐 경우를 되돌린다.

일괄 확인은 최근 종료 구역 머리에 둔다. 대상은 그 시점 전체 실행 기록에 남아 있는 미확인 실패 기록 전부이며, 화면에 보이는 세 건으로 한정하지 않는다. 목록에 보이지 않는 오래된 실패가 남아 있으면 다음에 최근 종료가 그 기록을 다시 끌어올리기 때문이다. 되돌리기는 개별 해제뿐이므로, 누르기 전에 몇 건을 확인 처리하는지 묻는 창을 한 번 띄운다. 앱이 실행 취소와 재시도에서 쓰는 것과 같은 방식이다.

### 확인한 기록을 보여주는 방식

최근 종료 목록은 확인한 실패 기록을 빼고 세 건을 채운다. 흐리게 남기는 방식도 검토했지만, 이 목록은 세 줄뿐이라 흐린 줄이 자리를 차지하면 정작 봐야 할 새 실패가 밀려난다. 접는 쪽을 택한다.

- 확인한 실패가 하나라도 있으면 목록 아래에 확인한 실패 N건이라는 줄이 붙는다. 누르면 그 자리에서 펼쳐지고 다시 누르면 접힌다. 접힌 기록이 있다는 사실 자체는 화면에서 사라지지 않는다.
- 펼친 줄과 전체 실행 기록의 확인한 줄은 빨간 점 대신 회색 점을 쓰고, 뒤에 확인함 표시를 단다. 실패나 복구 필요라는 상태 문구는 그대로 둔다. 색만 경보에서 내리고 사실은 그대로 남긴다.
- 전체 실행 기록은 접지 않는다. 확인 여부와 무관하게 끝난 실행 전부를 지금처럼 보여주고, 확인한 줄에 표시만 덧붙인다. 아이디어가 말한 감사 용도를 받는 자리가 여기다.

이 변경으로 최근 종료 목록의 성격이 조금 바뀐다. 지금은 가장 최근 세 건이지만, 앞으로는 확인하지 않은 최근 세 건이 된다. 확인한 실패를 빼고 채우므로 며칠 전 기록이 목록에 남아 있을 수 있다. 구역 이름은 최근 종료 그대로 두고, 접힌 건수 줄이 그 차이를 설명한다.

### 화면에 이미 있는 확인이라는 말

같은 실행 화면에 확인 필요라는 구역이 이미 있다. 그쪽은 실행 도구나 파일 감시처럼 앱 쪽 문제를 모아 보여주는 자리이고, 이 기획서의 확인 처리와는 다른 뜻이다. 두 표현이 섞이지 않도록 이 기능이 화면에 쓰는 말은 확인함, 확인 해제, 확인한 실패 N건으로 고정한다. 확인 필요 구역의 문구와 동작은 건드리지 않는다.

### 확인 표시가 건드리지 않는 것

- 확인 표시는 앱이 따로 들고, 실행 기록 자체를 고치지 않는다. 워크플로 문서와 결정 기록에도 쓰지 않는다.
- 앱을 껐다 켜도 남는다. 창을 닫으면 사라지는 값이면 다음에 열 때 같은 실패가 다시 새 문제로 보이므로 문제가 그대로 남는다.
- 재시도로 새 실행이 생겨도 원래 기록의 확인 표시는 그대로다. 새 실행이 또 실패하면 그것은 아직 확인하지 않은 새 기록이며, 목록에 정상적으로 올라온다.
- 확인 처리는 표시에만 영향을 준다. 재시도, 복구, 배정, 자격 판정은 이 값을 읽지 않는다.

## 요구사항 명세

- R1. 확인 처리는 실패와 복구 필요 상태로 끝난 실행 기록에만 붙는다. 완료, 취소됨, 상태 확인 필요 기록에는 확인하는 방법을 제공하지 않는다.
- R2. 실행 상세 화면에서 대상 기록 하나를 확인 처리한다. 이미 확인한 기록에서는 같은 자리가 확인 해제로 바뀐다.
- R3. 최근 종료 구역에 일괄 확인을 둔다. 대상은 그 시점 실행 기록 전체에서 아직 확인하지 않은 실패와 복구 필요 기록 전부다.
- R4. 일괄 확인은 실행할 건수를 문장으로 밝히는 확인 창을 거친 뒤에만 적용한다. 미확인 대상이 없으면 일괄 확인을 그리지 않는다.
- R5. 최근 종료 목록은 확인한 기록을 제외한 뒤 최신순 세 건을 그린다. 세 건이라는 수는 지금 값을 그대로 쓴다.
- R6. 확인한 기록이 하나 이상이면 최근 종료 목록 아래에 그 건수를 적은 줄을 그린다. 이 줄은 펼치고 접을 수 있으며, 펼치면 확인한 기록이 그 자리에 나온다.
- R7. 확인한 기록의 상태 점은 회색으로 그리고 확인함 표시를 덧붙인다. 상태 문구는 실패, 복구 필요 그대로 둔다.
- R8. 전체 실행 기록은 확인 여부와 무관하게 끝난 실행 전부를 그린다. 확인한 줄에는 R7의 표시를 적용하고 그 밖의 형식은 지금과 같다.
- R9. 확인 표시는 앱이 프로젝트별로 보관하고 실행마다 구분한다. 앱을 다시 실행해도 유지된다.
- R10. 확인 표시를 쓰거나 지우는 동작이 실행 기록, 워크플로 문서, 결정 기록을 수정하지 않는다.
- R11. 확인 표시는 화면 표시에만 쓴다. 재시도, 복구, 배정, 역할 자격 판정은 이 값을 읽지 않는다.
- R12. 실행 기록에서 사라진 실행의 확인 표시는 함께 정리해, 보관하는 값이 계속 늘어나지 않게 한다.
- R13. 이 기능이 화면에 쓰는 말은 확인함, 확인 해제, 확인한 실패 N건으로 한다. 기존 확인 필요 구역의 문구와 동작은 바꾸지 않는다.
- R14. 확인하지 않은 실패 기록의 표시는 지금과 같다. 상태 점 색, 줄 구성, 소요 시간 표기, 상세 화면 진입 방식을 바꾸지 않는다.

## 제외 범위

- 실행 기록을 지우거나 오래된 기록을 정리하는 기능은 만들지 않는다. R12는 화면에서 사라진 실행에 딸린 표시만 다루며, 실행 기록 자체는 앱이 지우지 않는다.
- 시간이 지나면 저절로 접히는 자동 확인은 만들지 않는다. 조치가 끝났다는 판단은 사람만 한다.
- 실패 원인을 분석하거나 분류하는 기능은 다루지 않는다. 상세 화면의 사유, 도구 사용, 마지막 활동, 결과 보고서 표시는 지금 그대로다.
- 재시도와 복구 동작은 바꾸지 않는다. 복구 필요 기록의 남은 정리 안내도 그대로 둔다.
- 확인 처리를 알림이나 배지, 다른 화면의 요약 수치와 연동하지 않는다.
- 확인한 사람이나 확인한 시각을 화면에 노출하는 일은 다루지 않는다. 단일 사용자 환경이라 지금 필요가 확인되지 않는다.
- 진행 중, 배정 대기, 앱 밖 세션, 확인 필요 구역의 표시는 바꾸지 않는다.

## 완료 판정 기준

- A1. 실패로 끝난 실행을 상세 화면에서 확인 처리하면, 최근 종료 목록에서 그 줄이 사라지고 그 자리를 다음 종료 기록이 채운다.
- A2. A1의 상태에서 목록 아래에 확인한 실패 1건이라는 줄이 보이고, 그 줄을 누르면 방금 확인한 기록이 회색 점과 확인함 표시를 달고 나타난다. 다시 누르면 접힌다.
- A3. A2에서 펼친 줄의 상태 문구는 실패 그대로이고, 소요 시간과 역할 표기도 확인 전과 같다.
- A4. 확인한 기록을 상세 화면에서 확인 해제하면 최근 종료 목록에 다시 빨간 점으로 올라오고, 확인한 실패 건수 줄에서 빠진다.
- A5. 미확인 실패가 다섯 건이고 그중 두 건만 최근 종료 목록에 보이는 상태에서 일괄 확인을 실행하면, 확인 창에 다섯 건이라고 적히고 실행 뒤 다섯 건 모두가 확인한 실패로 잡힌다.
- A6. 미확인 실패와 복구 필요 기록이 하나도 없으면 최근 종료 구역에 일괄 확인이 그려지지 않는다.
- A7. 완료와 취소됨으로 끝난 기록의 상세 화면에는 확인 처리하는 방법이 없고, 목록 표시도 이 변경 전후로 같다.
- A8. 확인 처리를 한 뒤 앱을 종료하고 다시 열어도 그 기록은 확인한 상태로 남아 있다.
- A9. 전체 실행 기록을 열면 확인한 기록과 확인하지 않은 기록이 모두 보이고, 확인한 줄에만 확인함 표시가 붙어 있다.
- A10. 확인 처리와 확인 해제를 반복해도 실행 기록 파일과 워크플로 문서의 내용은 그 전후로 같다.
- A11. 복구 필요 기록을 확인 처리해도 상세 화면의 남은 정리 안내와 재시도는 그대로 동작한다.
- A12. 확인 처리를 한 번도 하지 않은 프로젝트의 실행 화면은 이 변경 전후로 같다.

## 기대효과

- 실행 화면의 빨간 표시가 아직 손대지 않은 실패만 가리키게 된다. 사용자가 목록을 열었을 때 판단할 대상이 곧 남은 일이다.
- 이미 규명이 끝난 기록을 새 장애로 오인해 다시 문의하는 왕복이 없어진다. 아이디어가 이번 주 두 번으로 적은 손해가 직접 사라진다.
- 기록을 지우지 않고도 목록이 조용해지므로, 감사 목적의 실행 이력은 전체 실행 기록에 그대로 남는다.
