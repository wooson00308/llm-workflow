# 프로젝트별 무인 에이전트 실행에 동의 관문을 둔다

## 결정권자 요약

### 제안

프로젝트에서 에이전트를 처음 실행하려 할 때, 세션이 사람의 건별 승인 없이 넓은 권한으로 동작한다는 사실을
명확히 알리고 프로젝트별 동의를 받는다.

### 현재

역할 세션은 앱을 닫은 뒤에도 병렬로 실행되고 파일 변경과 명령 실행을 개별 승인 없이 수행한다. 현재 시작 확인은
동시 유료 세션 가능성은 알리지만 이 권한과 무인 동작을 설명하거나 동의를 기록하지 않는다.

### 변경 후

자동 배정을 켜거나 직접 배정을 확정하는 첫 시점에 같은 동의 관문을 거친다. 앱이 닫혀 있어도 실행 환경이 동의
기록을 확인하며, 동의가 없거나 고지 내용이 바뀐 프로젝트에서는 새 세션을 시작하지 않는다.

### 사용자 결과

사용자는 처음 실행 전에 무엇을 허용하는지 알고 결정한다. 동의한 뒤에는 역할 세션마다 다시 묻지 않으며,
고급 설정에서 동의 상태를 확인하거나 철회할 수 있다.

### 영향 범위

- 변경: 프로젝트별 첫 실행 흐름, 자동 배정과 직접 배정의 시작 조건, 동의 기록과 철회, 기존 사용자의 전환 안내
- 유지: 건별 승인 없는 무인 실행, 사용자 승인과 품질 확인 관문, 실행 취소와 일시 정지, 인증과 비용 확인 절차

### 비용과 위험

앱 화면만 막아서는 앱 종료 뒤의 자동 배정을 통제할 수 없으므로 실행 환경 계약도 함께 바뀐다. 동의는 권한을
제한하는 보안 장치가 아니라 필수 전제를 이해했다는 기록이며, 철회해도 이미 실행 중인 세션은 자동 종료하지 않는다.

### 결정 요청

프로젝트별 최초 실행 전에 넓은 실행 권한과 무인 동작을 고지하고, 동의가 확인된 경우에만 새 세션을 시작하는
관문을 도입할지 결정한다. 승인하지 않으면 현재처럼 이 사실에 대한 명시적 동의 없이 세션을 시작할 수 있다.

## 기획 내용

### 배경

이 앱의 역할 세션은 백그라운드에서 병렬로 동작한다. 반복 실행을 켜면 사용자가 앱을 닫은 뒤에도 새 작업을
찾아 세션을 시작한다. 세션은 작업마다 사용자에게 도구 실행을 묻지 않고 파일을 변경하며 명령을 실행해야 한다.
따라서 제한된 권한과 전체 권한 중 하나를 고르는 선택지는 제품에 없다. 권한을 제한하면 이 제품이 약속한 무인
작업이 성립하지 않는다.

2026-08-13에 배포된 앱은 런타임 0.9.4를 포함하며, Claude 역할 세션도 이 무인 실행에 필요한 권한으로
시작한다. 현재 에이전트 화면은 자동 배정을 켤 때 여러 유료 세션이 동시에 실행될 수 있다고 알리지만, 세션이
어떤 권한으로 무엇을 할 수 있는지는 설명하지 않는다. 직접 배정도 같은 권한을 사용하지만 별도의 동의 기록이
없다.

이 기획의 목적은 권한을 선택하게 하는 것이 아니다. 실행에 필요한 전제를 첫 사용 전에 숨김없이 설명하고,
사용자가 이해하고 동의한 프로젝트에서만 새 역할 세션이 시작되게 하는 것이다.

### 제품 판단

#### 프로젝트마다 한 번 동의한다

동의 범위는 기기 전체, 실행 도구별, 역할별이 아니라 프로젝트별이다. 사용자가 허용하는 작업 대상과 자동 배정
정책은 프로젝트마다 다르고, 현재 실행 정책과 대기열도 프로젝트 단위로 분리돼 있다. 한 프로젝트의 동의가 다른
프로젝트의 실행을 열어서는 안 된다.

한 프로젝트 안에서는 Claude와 Codex, 기획자와 아키텍트와 개발자가 같은 동의를 공유한다. 역할이나 실행
도구를 바꿀 때마다 다시 묻지 않는다. 고지 내용의 의미가 바뀌어 새 동의 버전이 필요할 때만 다시 확인한다.

#### 설정 편집이 아니라 실행 가능한 행동에서 묻는다

실행을 시작하지 않는 역할별 실행 도구, 모델, 인원, 확인 주기 편집은 동의 없이 저장할 수 있다. 사용자가 실제로
새 세션을 시작할 수 있게 만드는 다음 두 행동이 최초 동의 시점이다.

1. 자동 배정을 켠다.
2. 직접 배정에서 대상을 확인하고 실행을 확정한다.

동의 화면은 사용자가 선택한 행동의 마지막 확인 안에 놓인다. 동의하고 계속하면 나머지 시작 조건을 다시 검사한
뒤 그 행동을 이어 간다. 취소하면 설정 초안은 보존하지만 자동 배정이나 직접 실행은 시작하지 않는다.

이 시점은 첫 배정이 이미 예약된 뒤에 묻는 것보다 안전하다. 동의가 없으면 대상 lease와 유료 실행을 만들지 않으며,
백그라운드 실행이 사용자의 응답을 기다리는 상태도 생기지 않는다.

#### 고지는 권한의 실제 범위를 축소해 말하지 않는다

동의 화면의 제목과 핵심 문구는 다음 의미를 모두 포함한다.

- 역할 세션은 앱을 닫아도 백그라운드에서 병렬로 동작할 수 있다.
- 세션은 작업마다 다시 묻지 않고 파일을 읽고 만들고 수정하거나 삭제하며 명령을 실행할 수 있다.
- 세션은 운영체제 사용자 계정과 실행 도구가 허용하는 네트워크와 인증 환경을 사용할 수 있다.
- 이 권한은 에이전트 기능의 필수 전제이며, 제한 모드는 제공하지 않는다.
- 사용자 승인과 품질 확인처럼 워크플로가 사람에게 남긴 판단 관문은 계속 사람이 수행한다.

권장 확인 문구는 “위 내용을 이해했으며 이 프로젝트에서 무인 에이전트 실행에 동의합니다”이다. 사용자는 이 항목을
직접 선택해야 계속할 수 있다. 미리 선택된 확인 항목, 닫기와 동의를 구분하기 어려운 버튼, 단순 안내 알림은 동의로
보지 않는다.

계속 버튼은 시작하려던 행동을 함께 이름으로 표시한다. 자동 배정에서는 “동의하고 자동 배정 켜기”, 직접
배정에서는 “동의하고 직접 배정 시작”으로 보여 준다. 동의가 추상적인 설정 저장이 아니라 어떤 실행을 여는지
버튼만 읽어도 알 수 있어야 한다.

#### 기록과 집행의 책임을 분리한다

앱은 동의 화면과 상태 확인, 철회 조작을 제공한다. 기록은 최소한 안정적인 프로젝트 식별자, 동의한 고지 버전,
동의 시각을 보존한다. 사용자가 본 문구를 나중에 식별할 수 있도록 고지 버전은 의미가 바뀔 때 갱신한다. 자유 입력,
전자 서명, 계정 신원 확인은 요구하지 않는다.

실행 환경은 새 세션을 시작하기 직전에 프로젝트의 유효한 동의를 확인한다. 자동 배정, 직접 배정, 재시도처럼 시작
경로가 달라도 같은 판단을 사용한다. 동의가 없거나 철회됐거나 요구하는 고지 버전보다 오래됐으면 대상을 예약하거나
실행 도구를 시작하지 않고 “실행 권한 동의 필요” 상태를 반환한다. 앱이 열려 있지 않아도 이 판단은 유지된다.

동의 기록의 구체적인 저장 위치, 필드 이름, 앱과 실행 환경 사이의 명령 형태는 아키텍트가 정한다. 단, 앱 로컬
화면에만 기록해 백그라운드 실행 환경이 확인하지 못하는 구조는 허용하지 않는다.

#### 상태 확인과 철회

고급 설정은 현재 프로젝트의 동의 여부, 동의 시각, 적용 중인 고지 버전을 보여 준다. 사용자는 같은 곳에서 고지
전문을 다시 읽고 동의를 철회할 수 있다.

철회는 해당 프로젝트의 새 자동 배정과 직접 배정과 재시도를 즉시 막는다. 이미 실행 중인 세션은 자동으로 종료하지
않는다. 실행 중 세션을 끝내려면 기존 개별 취소를 사용한다는 사실을 철회 확인 화면에서 알린다. 철회 뒤 다시
실행하려면 최신 고지에 새로 동의해야 한다.

### 기존 프로젝트 전환

업데이트 시점에 이미 실행 중인 세션은 계속 실행한다. 동의 관문 도입을 이유로 프로세스를 강제 종료하거나 lease를
반납하지 않는다.

기존 프로젝트에 유효한 동의 기록이 없으면 새 세션만 멈춘다. 자동 배정이 켜져 있던 프로젝트는 화면에 “실행 권한
동의 필요”를 표시하고, 사용자가 동의하기 전에는 실행 환경이 후속 작업을 배정하지 않는다. 사용자가 “동의하고 자동
배정 계속”을 누르면 최신 자격과 한도를 다시 확인한 뒤 배정을 재개한다. 취소하면 멈춘 상태를 유지한다.

이미 대기열에 있으나 실행 도구가 시작되지 않은 요청도 동의 전에는 시작하지 않는다. 동의 뒤에는 오래된 예약을
그대로 믿지 않고 현재 자격, lease, 범위 충돌과 실행 한도를 다시 확인한다.

### 기존 확인 절차와의 관계

- 동시 유료 세션과 Claude 과금 경로에 대한 기존 확인은 유지한다. 실행 권한 동의로 비용 확인을 대신하지 않는다.
- 기획서 승인과 개발 결과의 품질 확인은 계속 사용자 전용 관문이다. 넓은 실행 권한이 에이전트의 역할 권한을
  넓히지는 않는다.
- 프로젝트 일시 정지와 실행 취소의 의미는 유지한다. 동의 철회는 새 실행을 막는 조작이며 실행 중 프로세스를
  종료하는 조작이 아니다.
- 실행 도구 로그인과 운영체제 권한 부여는 각 실행 도구와 운영체제가 계속 맡는다. 이 동의가 실제 시스템 권한을
  새로 부여하지는 않는다.

## 요구사항 명세

### R1. 동의 범위를 프로젝트별로 분리한다

- 한 프로젝트의 동의는 그 프로젝트의 자동 배정, 직접 배정과 재시도에만 적용한다.
- 새 프로젝트에는 다른 프로젝트나 기기의 동의 상태를 복사하지 않는다.
- 같은 프로젝트에서는 역할과 실행 도구가 바뀌어도 유효한 최신 동의를 공유한다.

### R2. 첫 실행 가능 행동에서 명시적으로 동의받는다

- 동의하지 않은 프로젝트에서 자동 배정을 켜거나 직접 배정을 확정하면 실행 전에 동의 화면을 연다.
- 단순히 에이전트 화면을 열거나 실행을 시작하지 않는 설정을 저장할 때는 동의를 강요하지 않는다.
- 확인 항목은 기본으로 선택하지 않으며, 사용자가 직접 선택하기 전에는 계속 버튼을 사용할 수 없다.
- 취소하면 세션, 대상 예약과 유료 사용을 시작하지 않는다.

### R3. 무인 실행과 권한 범위를 한 화면에서 고지한다

- 앱 종료 뒤의 백그라운드 실행, 병렬 실행 가능성, 건별 승인 부재를 함께 설명한다.
- 파일 생성과 변경과 삭제, 명령 실행, 실행 도구에 허용된 네트워크와 인증 환경 사용 가능성을 명시한다.
- 제한 모드가 없고 이 동의가 기능 사용의 필수 전제임을 명시한다.
- 워크플로의 사용자 승인과 품질 확인 관문은 유지된다고 함께 설명한다.

### R4. 동의 기록을 버전화한다

- 기록은 프로젝트 식별자, 고지 버전, 동의 시각을 보존한다.
- 권한 범위나 무인 실행의 의미가 달라지면 고지 버전을 올리고 기존 동의를 유효하지 않은 것으로 판정한다.
- 맞춤법이나 레이아웃처럼 의미가 바뀌지 않는 수정은 불필요한 재동의를 만들지 않는다.

### R5. 모든 새 실행 경로를 같은 관문으로 막는다

- 실행 환경은 실행 도구를 시작하기 직전에 유효한 프로젝트 동의를 확인한다.
- 자동 배정, 직접 배정, 실패한 실행의 재시도에 같은 판단을 적용한다.
- 동의가 유효하지 않으면 대상 예약과 실행 도구 시작과 실행 한도 차감을 하지 않는다.
- 동의 부족은 실행 실패와 구분되는 대기 상태로 표시하고, 앱에서 동의 화면으로 이동할 수 있게 한다.

### R6. 앱이 닫혀 있어도 동의 조건을 지킨다

- 백그라운드 실행 환경이 동의 상태를 직접 확인할 수 있어야 한다.
- 앱 화면에서만 버튼을 비활성화하고 실행 환경은 계속 배정할 수 있는 구조를 금지한다.
- 동의 상태를 읽을 수 없으면 동의한 것으로 추정하지 않고 새 실행을 시작하지 않는다.

### R7. 철회와 기존 실행의 경계를 분명히 한다

- 고급 설정에서 동의 상태와 고지 전문을 확인하고 동의를 철회할 수 있다.
- 철회하면 해당 프로젝트의 새 자동 배정, 직접 배정과 재시도를 막는다.
- 철회는 이미 실행 중인 세션을 종료하지 않으며, 사용자가 기존 취소 기능으로 종료할 수 있음을 알린다.
- 철회 뒤 다시 실행하려면 최신 고지에 다시 동의해야 한다.

### R8. 기존 프로젝트를 안전하게 전환한다

- 업데이트 전에 시작한 세션은 동의 기록이 없다는 이유로 종료하지 않는다.
- 동의 기록이 없는 기존 프로젝트에서는 새 세션만 멈추고 원인을 “실행 권한 동의 필요”로 표시한다.
- 기존 자동 배정은 사용자가 동의하고 계속하기 전까지 후속 배정을 시작하지 않는다.
- 대기 중 요청은 동의 뒤 현재 자격과 lease와 범위 충돌과 실행 한도를 다시 확인한다.

### R9. 기존 사용자 관문을 합치거나 약화하지 않는다

- 실행 권한 동의와 동시 유료 세션 확인, 과금 경로 확인을 서로 다른 판단으로 유지한다.
- 실행 권한 동의가 기획서 승인, 품질 확인, 취소 확인을 대신하지 않는다.
- 동의 기록에 실행 도구 인증 정보, 비밀값, 전체 작업 지시를 저장하지 않는다.

### R10. 동의 상태를 진단할 수 있게 한다

- 앱은 프로젝트별 동의 여부, 동의 시각, 고지 버전을 표시한다.
- 실행 환경이 새 실행을 거절할 때 동의 부족을 설치 실패, 로그인 실패, 권한 부족과 구분한다.
- 다른 프로젝트의 동의 부족이 현재 프로젝트의 상태나 실행을 막지 않는다.

## 제외 범위

- 도구 호출이나 명령마다 사용자 승인을 받는 대화형 권한 모드
- 읽기 전용, 명령 금지, 네트워크 금지처럼 일부 권한만 고르는 제한 모드
- 운영체제 권한이나 실행 도구 로그인 권한을 앱이 대신 부여하는 기능
- 법적 전자 서명, 사용자 계정별 동의 이력이나 서버 동기화
- 기존 사용자 승인, 품질 확인, 비용 확인과 취소 관문의 재설계
- 동의 철회 시 실행 중인 세션을 일괄 종료하는 기능

## 완료 조건

1. 동의하지 않은 새 프로젝트에서 자동 배정을 켜면 고지와 선택되지 않은 확인 항목이 나타나고, 취소하면 설정
   초안만 남으며 세션과 대상 예약이 생기지 않는다.
2. 같은 프로젝트에서 처음 직접 배정을 확정해도 같은 고지가 나타나며, 동의하고 계속한 뒤에만 현재 자격을 다시
   확인하고 실행을 시작한다.
3. 다른 프로젝트에서 이미 동의했어도 새 프로젝트의 자동 배정과 직접 배정은 별도 동의 전까지 시작되지 않는다.
4. 동의 화면이 백그라운드와 병렬과 건별 승인 없는 실행, 파일 생성과 변경과 삭제, 명령 실행, 실행 도구에 허용된
   네트워크와 인증 환경, 제한 모드 부재, 사용자 판단 관문 유지를 모두 설명한다.
5. 유효한 동의가 있으면 같은 프로젝트의 다른 역할이나 다른 실행 도구를 사용할 때 다시 묻지 않는다.
6. 고지의 의미가 바뀌어 버전이 올라가면 기존 프로젝트는 새 동의 전까지 새 세션을 시작하지 않는다. 의미가 바뀌지
   않는 문구나 배치 수정은 재동의를 요구하지 않는다.
7. 앱을 종료한 상태에서 자동 배정 조건이 충족돼도 동의가 없거나 철회된 프로젝트는 대상 예약, 실행 도구 시작과
   실행 한도 차감이 없고 동의 필요 상태만 남는다.
8. 고급 설정에서 프로젝트의 동의 시각과 고지 버전을 확인하고 철회할 수 있다. 철회 직후 새 자동 배정과 직접 배정과
   재시도는 막히지만 이미 실행 중인 세션은 계속된다.
9. 기존 자동 배정 프로젝트를 동의 기록 없이 전환하면 실행 중 세션은 유지되고 후속 배정만 멈춘다. 동의하고 계속한
   뒤에는 오래된 예약을 재사용하지 않고 현재 자격과 lease와 충돌과 한도를 다시 확인한다.
10. 실행 권한 동의가 완료돼도 동시 유료 세션 확인과 과금 경로 확인이 필요한 상황에서는 기존 확인이 별도로 나타난다.
11. 동의 부족 상태가 설치 필요, 로그인 필요, 운영체제 권한 부족과 다른 이름과 안내로 표시되고, 해당 프로젝트의
    동의 화면으로 이동할 수 있다.
12. 앱과 실행 환경의 자동 검사에서 자동 배정, 직접 배정, 재시도, 앱 종료 뒤 배정, 철회, 고지 버전 변경과 기존
    실행 유지 시나리오가 통과한다.

## 기대효과

- 사용자는 에이전트가 넓은 권한으로 무인 동작한다는 핵심 전제를 첫 실행 전에 이해한다.
- 백그라운드 실행 환경도 같은 기록을 집행하므로 앱 화면을 우회하는 새 실행이 생기지 않는다.
- 프로젝트마다 실행 의사를 분리하면서 역할별 반복 확인과 도구별 중복 동의는 피한다.
- 권한 고지, 비용 확인, 워크플로 승인과 품질 확인의 목적이 섞이지 않아 각 관문에서 무엇을 결정하는지 분명해진다.

없다. 이 기획서는 프로젝트별 한 번 동의, 첫 실행 가능 행동에서의 확인, 앱과 실행 환경의 이중 집행, 철회 시
새 실행만 중단한다는 경계를 사용자 결정 대상으로 제시한다. 구체적인 기록 형식과 저장 위치와 명령 계약은 승인 뒤
아키텍트가 정한다.
