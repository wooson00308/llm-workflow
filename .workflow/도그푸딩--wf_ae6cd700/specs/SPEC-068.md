# 연결 계획을 적용한 결과를 화면이 보여준다

## 결정권자 요약

### 제안

실행 환경 계획을 적용한 뒤 단계별 결과를 화면에 보여주고, 실패한 단계에는 사유를 사용자 언어로 함께 표시한다.

### 현재

적용을 누르면 확인 창이 그대로 닫히고 화면에는 결과가 남지 않는다. 적용의 뒤편은 버전 설치, 실행기 전환, 서비스 연결 세 단계의 성공 여부와 실패 사유 문장까지 만들어 앱에 돌려주고 앱은 그 값을 보관하지만, 그것을 그리는 화면이 없다. 그래서 서비스 연결 단계만 실패한 적용도 성공한 적용과 똑같이 창이 닫히는 것으로 끝나고, 자동 배정 서비스 연결 필요 배너는 그대로 남는다. 사용자는 적용이 부분적으로 실패했다는 사실과 그 사유를 어디에서도 읽을 수 없다. 확인 창 자체도 계획의 종류를 구분하지 않아, 런타임이 이미 설치되어 있고 서비스 연결만 남은 기기에서도 실행 환경 변경이라는 제목과 같은 버전을 양쪽에 적은 버전 줄을 보여준다. 2026-08-18 Windows 새 기기에서 실측한 내용이다.

### 변경 후

적용이 끝나면 같은 창이 결과 화면으로 바뀌어 단계별 결과를 수행한 순서대로 보여준다. 성공한 단계는 완료로, 실패한 단계는 실패로 표시하고 그 아래에 사유를 사용자 언어로 적는다. 부분 실패는 성공과 구분해 표시하고, 자동 배정이 아직 연결 필요 상태로 남는다는 사실을 그 자리에서 함께 알린다. 창을 닫은 뒤에도 마지막 적용 결과를 실행 환경 상태 자리에서 다시 열어 읽을 수 있다. 런타임이 이미 설치되어 있고 서비스 연결만 남은 기기에서는 확인 창의 제목과 안내 문장이 설치가 아니라 서비스 연결을 말한다. 지금 Windows 기기에서 서비스 연결이 실패하는 사유도 이 표시를 통해 화면에 드러난다.

### 비용과 위험

적용 뒤 창이 곧바로 닫히지 않고 결과를 확인한 다음 닫는 동작이 한 번 늘어난다. 실패 사유는 런타임이 돌려준 문장을 사용자 언어로 옮겨 적으며, 옮길 규칙이 없는 문장은 원문 그대로 보여주므로 기술적인 문장이 노출될 수 있다. 적용 절차 자체는 손대지 않는다. 계획을 먼저 보여주고 확인받은 뒤에만 적용하는 순서, 계획이 오래되었는지 판정하는 방식, 단계 이름과 수행 순서, 실행 중인 세션 유지, 직접 배정과 실행 권한 동의와 자동 배정 토글 동선은 모두 지금 그대로 둔다. 화면 표시 규칙만 바뀌므로 되돌리기도 표시 규칙을 되돌리는 것으로 끝난다. 이 기획서가 승인되지 않으면 적용 결과는 계속 화면에 남지 않고, Windows 기기에서 서비스 연결이 왜 실패하는지도 계속 확인할 수 없다.

## 기획 내용

### 실측한 문제

2026-08-18 Windows 새 기기에서 관찰한 순서는 다음과 같다.

1. 에이전트 화면에 자동 배정 서비스 연결 필요 배너가 뜨고, 배너는 연결 계획 버튼을 제공한다.
2. 연결 계획을 누르면 확인 창이 열린다. 런타임은 이미 설치되어 있는데도 창의 제목은 실행 환경 변경이고, 버전 줄은 같은 버전을 화살표 양쪽에 적는다.
3. 적용을 누르면 창이 닫힌다.
4. 배너는 자동 배정 서비스 연결 필요 그대로 남는다.

사용자가 화면에서 얻는 정보는 "눌렀는데 그대로다"뿐이다. 적용이 어디까지 진행되었는지, 무엇이 실패했는지, 다음에 무엇을 하면 되는지는 전부 화면 밖에 있다.

### 코드에서 확인한 사실

- 적용은 단계 목록을 돌려준다. 각 단계는 이름과 상태를 가지고, 실패한 단계는 사유 문장을 함께 싣는다. 설치 계열 적용의 단계 이름은 버전 설치, 실행기 전환, 서비스 연결이다.
- 파일 설치가 끝났는데 뒤 단계가 실패하면 결과는 부분 성공으로 돌아오고, "설치본은 놓였지만 남은 단계가 있습니다"라는 설명이 함께 온다. 이것은 오류가 아니라 정상 응답이다.
- 앱 상태는 마지막 적용 결과를 보관하도록 이미 만들어져 있고 조회 주기가 이 값을 지우지도 않는다. 그러나 이 값을 읽어 그리는 화면이 한 곳도 없다.
- 적용이 예외로 실패한 경우에만 사유가 화면에 보인다. 이때는 확인 창이 다시 열리며 오류 문장을 표시한다. 정상 응답으로 돌아오는 부분 실패는 이 경로를 타지 않으므로 아무 표시도 남지 않는다.
- 서비스 연결 단계가 실패하면 서비스는 등록되지 않은 상태로 남고, 배너 판정은 등록 여부만 보므로 자동 배정 서비스 연결 필요를 계속 표시한다. 배너의 문장과 실패한 단계 사이에는 아무 연결도 없다.
- 확인 창은 네 가지 계획(설치, 업데이트, 복구, 내려받기)에 하나의 제목과 하나의 안내 문장을 쓴다. 서비스 처분은 별도 줄로 보여주지만, 제목과 버전 줄이 먼저 읽히므로 설치를 다시 하는 것처럼 보인다.

### 판단

문제는 계산이 아니라 표시에 있다. 필요한 값은 이미 만들어져 앱까지 도착해 있고, 화면이 그것을 그리지 않을 뿐이다. 그러므로 이 기획서는 적용의 동작을 바꾸지 않고 표시 규칙만 정한다.

결과 화면은 네 가지 계획이 함께 쓴다. 네 계획의 적용 결과가 단계 목록과 설명이라는 같은 구조로 돌아오고, 결과를 보여주지 않는 문제도 네 계획에 똑같이 있기 때문이다. 계획마다 다른 결과 화면을 만들 이유가 없다.

### 범위

- 적용 결과를 보여주는 화면과 그 문구.
- 실패한 단계의 사유를 사용자 언어로 옮기는 규칙.
- 적용 뒤 자동 배정이 연결 필요로 남는 경우의 안내 문장.
- 서비스 연결만 필요한 계획에서 확인 창이 쓰는 제목과 안내 문장.

### 제외 범위

- Windows 기기에서 서비스 연결이 실패하는 원인 자체의 수정. 이 표시로 사유가 확인된 뒤 별도 아이디어와 기획서로 잇는다. 아이디어 IDEA-52CC48B0이 그렇게 정했다.
- 적용 실패 뒤의 자동 재시도와 자동 복구.
- 런타임 계약, 단계 이름, 단계 수행 순서, 계획 지문 판정, 적용 절차의 변경.
- 배너가 실행 환경 상태를 판정하는 규칙의 변경.
- 실행 권한 동의, 자동 배정 토글, 직접 배정의 동선 변경.

## 요구사항 명세

### REQ-01 적용 결과를 단계별로 보여준다

- 적용이 끝나면 확인 창이 결과 화면으로 바뀐다. 결과를 확인한 뒤 사용자가 닫는다.
- 성공, 부분 실패, 실패 세 경우를 모두 표시한다. 세 경우는 화면에서 서로 구분된다.
- 단계는 적용이 수행한 순서대로 나열하고, 각 단계에 사용자 언어 이름과 결과 상태를 표시한다.
- 계획이 수행하지 않은 단계는 목록에 넣지 않는다. 돌아온 단계만 보여준다.
- 수용 기준: 버전 설치와 실행기 전환이 성공하고 서비스 연결이 실패한 적용에서, 세 단계가 순서대로 나타나고 앞의 둘은 완료로 마지막 하나는 실패로 표시된다.

### REQ-02 실패한 단계의 사유를 사용자 언어로 표시한다

- 실패한 단계에는 사유를 함께 표시한다.
- 사유 문장은 이미 화면에서 쓰는 사용자 언어 변환 규칙을 거쳐 표시한다. 변환 규칙이 없는 문장은 원문 그대로 보여준다.
- 사유가 비어 있는 실패 단계에는 사유를 확인하지 못했다는 사실을 표시한다. 자리를 비워 두지 않는다.
- 수용 기준: 사유가 실려 온 실패 단계와 사유가 비어 있는 실패 단계 모두에서, 그 단계 아래에 읽을 수 있는 문장이 하나 남는다.

### REQ-03 상태가 그대로인 이유를 화면에서 읽을 수 있다

- 적용 뒤에도 자동 배정이 연결 필요로 남는 경우, 결과 화면이 그 사실과 그렇게 된 단계를 문장으로 알린다.
- 마지막 적용 결과는 창을 닫은 뒤에도 실행 환경 상태 자리에서 다시 열어 읽을 수 있다. 다음 적용이 시작될 때까지 유지한다.
- 수용 기준: 서비스 연결이 실패한 뒤 배너가 연결 필요를 표시하는 동안, 사용자가 화면을 떠났다 돌아와도 마지막 적용의 단계별 결과와 실패 사유를 다시 읽을 수 있다.

### REQ-04 서비스 연결만 필요한 계획은 확인 창이 연결을 말한다

- 설치된 버전과 앱에 포함된 버전이 같고 서비스 처분이 새 연결인 계획에서, 확인 창의 제목과 안내 문장은 서비스 연결을 말한다. 설치라는 말을 쓰지 않는다.
- 버전이 바뀌지 않는 계획에서는 같은 버전을 화살표 양쪽에 적지 않고, 현재 버전을 유지한다는 사실을 밝힌다.
- 버전이 바뀌는 계획의 확인 창 문구는 지금 그대로 둔다.
- 수용 기준: 런타임이 설치되어 있고 서비스만 등록되지 않은 기기에서 연결 계획을 열면, 창의 제목과 안내 문장에 설치라는 말이 없고 버전 줄이 같은 값을 두 번 보여주지 않는다.

### REQ-05 적용 절차는 지금 그대로 둔다

- 계획을 먼저 만들어 보여주고 확인받은 뒤에만 적용하는 순서를 유지한다.
- 오래된 계획을 거절하고 같은 조작의 계획을 다시 만드는 지금의 처리를 유지한다.
- 예외로 실패한 적용의 사유 표시도 지금의 동작을 유지한다. 이 기획서는 그 자리를 없애지 않고 정상 응답의 부분 실패를 새로 표시한다.
- 수용 기준: 이 변경 전후로 적용이 호출하는 명령과 그 인자, 그리고 계획 재생성 동작이 같다.

## 기대효과

- 적용을 눌렀는데 상태가 그대로인 상황에서, 사용자가 무엇이 왜 실패했는지 화면에서 읽는다. 지금은 읽을 방법이 없다.
- 실패한 단계와 사유가 화면에 드러나므로, Windows 기기에서 서비스 연결이 실패하는 실제 원인을 사용자가 보고할 수 있고 후속 수정의 판단 기준이 생긴다.
- 이미 설치된 기기에서 연결만 필요한 사용자가 설치를 다시 하는 것으로 오해하지 않는다.
- 결과 화면을 네 계획이 함께 쓰므로, 업데이트와 복구와 내려받기에서도 같은 표시 공백이 함께 메워진다.

## 참고

- SPEC-067은 같은 에이전트 화면의 준비 단계 안내를 다루며 현재 사용자 검토 중이다. 두 기획서는 같은 화면 영역을 건드리므로, 두 기획서가 모두 승인되면 작업 순서를 정할 때 표시 자리가 겹치는지 확인해야 한다. 이 기획서는 배너의 판정 규칙과 준비 단계 동선을 바꾸지 않으므로 내용상 충돌하지는 않는다.
