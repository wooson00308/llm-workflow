# 사이드 메뉴에 대기·변경 표시 추가

## 결정권자 요약

### 제안

사이드 메뉴의 각 메뉴 이름 옆에, 지금 사용자의 결정을 기다리는 항목 수와 마지막으로 본 뒤 달라진 것이 있다는 사실을 표시한다.

### 현재

사이드 메뉴의 여섯 메뉴에는 아무 표시가 없다. 승인 대기 기획서가 생겼는지, 품질 확인이 열렸는지, 새 아이디어가 들어왔는지 알려면 메뉴를 하나씩 열어 봐야 한다. 사이드 메뉴에 숫자가 보이는 자리는 워크플로우 이름 옆의 작업 그룹 총 개수와 세션이 돌 때만 나타나는 실행 중 표시뿐이고, 둘 다 볼 것이 생겼다는 알림이 아니다.

### 변경 후

기획서와 품질 확인 메뉴에는 사용자의 결정을 기다리는 항목 수가 숫자로 붙고, 아이디어와 개발 메뉴에는 마지막으로 그 메뉴를 연 뒤 달라진 것이 있을 때만 점이 붙는다. 워크플로우가 여럿이면 지금 보고 있지 않은 워크플로우에도 대기 중인 결정이 있을 때 점이 붙는다. 사용자는 메뉴를 열어 보지 않고도 어디에 갈 곳이 있는지 사이드 메뉴 한 번 훑는 것으로 판단할 수 있고, 기다리는 결정이 없으면 화면에 아무 표시도 늘지 않는다.

### 비용과 위험

달라진 것을 가리는 기준은 문서가 마지막으로 바뀐 시각이다. 새로 만들어진 문서와 내용이 고쳐진 문서를 구분하지 않으므로, 기존 아이디어가 수정된 경우에도 점이 켜진다. 이 기본값을 택한 이유는 본문에 적었고, 새로 생긴 것만 세도록 바꾸려면 백엔드가 문서 생성 시각을 함께 넘겨야 한다. 마지막 확인 시점은 사용하는 컴퓨터에 남으므로 다른 컴퓨터에서는 공유되지 않는다. 문서 파일, 승인 절차, 결정 기록은 전혀 건드리지 않고 화면 표시만 늘어나므로, 승인하지 않으면 지금 화면 그대로 남고 승인 뒤에도 표시를 제거하면 원래대로 되돌아간다.

## 배경

IDEA-D3075A1B는 사이드 메뉴를 열어 보기 전에는 무엇이 생겼는지 알 수 없다는 문제를 제기한다. 아이디어가 확인한 현재 상태는 이번 기획에서 코드로 다시 확인했으며, 다음 사실이 이 기획의 판단 기준이다.

- 주 메뉴 여섯 개(오늘, 아이디어, 기획서, 개발, 품질 확인, 기록)에는 배지도 점도 없다.
- 워크플로우 목록의 각 항목은 작업 그룹 총 개수를 숫자로 보여 준다. 이 값은 누적 규모이지 확인이 필요한 항목 수가 아니다.
- 백엔드는 워크플로우마다 아이디어, 기획서, 결정, 작업 그룹, 작업, 보고서 여섯 가지 개수를 계산해 화면에 넘기지만 화면은 작업 그룹 수만 사용한다.
- 사용자의 결정을 기다리는 항목을 세는 계산은 이미 있다. 오늘 화면의 "내 선택 대기"가 승인 대기 기획서와 사용자 확인 모드의 품질 확인 준비 완료 기능을 합해 표시한다. 개발 화면과 품질 확인 작업대가 쓰는 판정을 그대로 불러 쓰므로 세 화면이 같은 수를 말한다.
- 사용자가 무엇을 마지막으로 확인했는지에 대한 기록은 어디에도 없다. "새로 생긴 것"을 가리려면 이 추적을 새로 만들어야 한다.
- 화면 상태를 브라우저 저장소에 남기는 방식은 이미 여러 곳에서 쓰고 있다. 아이디어 초안, 품질 확인 검토 초안, 기획서 레인 접힘 상태 등이 같은 저장소를 키로 나눠 쓰며, 값이 없거나 깨졌을 때 조용히 빈 상태로 돌아가는 처리도 정해져 있다.

## 두 가지 표시를 구분하는 이유

아이디어는 "지금 내 행동을 기다리는 것"과 "마지막 확인 이후 새로 생긴 것"을 구분해 보여 달라고 요구한다. 이 기획은 그 구분을 표시 형태로 나눈다.

- 사용자의 결정을 기다리는 항목은 숫자로 보여 준다. 몇 건이 밀려 있는지가 곧 사용자가 얼마나 시간을 써야 하는지이므로 개수 자체가 정보다.
- 마지막 확인 이후 달라진 것은 점으로만 보여 준다. 사용자가 직접 처리할 대상이 아니라 한 번 들여다볼 이유일 뿐이므로, 몇 건인지는 행동을 바꾸지 않는다. 숫자를 붙이면 결정 대기와 같은 무게로 읽혀 두 종류의 구분이 사라진다.

## 요구사항

### R1. 기획서 메뉴의 결정 대기 수

사이드 메뉴의 기획서 항목에 승인 대기 기획서 수를 숫자로 표시한다. 세는 대상은 선택된 워크플로우에서 상태가 사용자 검토인 기획서이며, 오늘 화면의 "내 선택 대기"가 쓰는 판정과 같은 값을 사용한다. 두 화면이 다른 수를 말해서는 안 된다.

### R2. 품질 확인 메뉴의 결정 대기 수

사이드 메뉴의 품질 확인 항목에 지금 확인할 수 있는 기능 수를 숫자로 표시한다. 세는 대상은 사용자 확인 모드이면서 품질 확인 준비가 끝난 작업 그룹이며, 여기서도 오늘 화면과 같은 판정을 사용한다. 아직 열 수 없는 기능은 수에 들어가지 않는다.

### R3. 아이디어·개발 메뉴의 변경 점

아이디어 메뉴와 개발 메뉴에는 숫자 대신 점 하나를 표시한다. 조건은 해당 메뉴가 다루는 문서 중 마지막 확인 시점보다 나중에 바뀐 것이 하나라도 있는 경우다. 아이디어 메뉴는 아이디어 문서를, 개발 메뉴는 작업 문서와 작업 그룹을 대상으로 삼는다. 점에는 개수를 붙이지 않는다.

### R4. 오늘·기록 메뉴는 표시하지 않는다

오늘 메뉴와 기록 메뉴에는 어떤 표시도 붙이지 않는다. 오늘 화면은 결정 대기를 이미 모아 보여 주는 화면이므로 같은 수를 메뉴에도 붙이면 중복이고, 기록은 이미 끝난 일을 보는 자리라 사용자를 부를 이유가 없다.

### R5. 마지막 확인 시점의 기록

메뉴를 열면 그 메뉴의 마지막 확인 시점을 그 순간으로 갱신한다. 기록은 워크플로우별로, 메뉴별로 따로 남긴다. 워크플로우를 바꾸면 그 워크플로우의 기록으로 판단하며, 한 메뉴를 열었다고 다른 메뉴의 점이 함께 꺼지지는 않는다. 저장 위치는 기존 화면 상태 저장과 같은 방식을 따르고, 값이 없거나 읽을 수 없을 때는 점을 켜지 않는다. 잘못된 알림을 한 번 보여 주는 쪽이 아무것도 보여 주지 않는 쪽보다 나쁘다.

### R6. 기록이 없는 첫 실행

특정 워크플로우와 메뉴에 대한 확인 기록이 없으면 점을 켜지 않고, 그 시점을 첫 기준으로 저장한다. 처음 프로젝트를 여는 사용자에게 그동안 쌓인 모든 문서가 변경으로 몰려 보이는 상태를 만들지 않기 위해서다.

### R7. 워크플로우 목록의 대기 점

워크플로우 목록에서, 지금 선택되지 않은 워크플로우에 사용자의 결정을 기다리는 항목이 있으면 이름 옆에 점을 표시한다. R1과 R2가 세는 것과 같은 대상을 합해 판단하며, 개수는 붙이지 않는다. 선택된 워크플로우는 주 메뉴가 이미 숫자로 말하고 있으므로 점을 붙이지 않는다. 지금 있는 작업 그룹 총 개수 표시는 그대로 둔다.

### R8. 0은 표시하지 않는다

셀 것이 없으면 배지 자리를 아예 그리지 않는다. 0이라는 숫자를 남기지 않으며, 점도 조건을 만족할 때만 나타난다. 기다리는 일이 없을 때 사이드 메뉴는 지금과 똑같이 보여야 한다.

### R9. 표시를 소리로도 읽을 수 있게 한다

숫자 배지와 점은 색과 모양만으로 뜻을 전달해서는 안 된다. 각 메뉴 버튼은 그 수와 상태를 함께 읽을 수 있는 이름을 갖는다. 예를 들어 승인 대기 기획서가 셋이면 버튼은 기획서 메뉴이면서 결정 대기가 셋이라는 사실을 함께 알린다.

## 표시 규칙 정리

| 메뉴 | 표시 | 판단 기준 |
| --- | --- | --- |
| 오늘 | 없음 | R4 |
| 아이디어 | 점 | 마지막 확인 이후 바뀐 아이디어 존재 |
| 기획서 | 숫자 | 승인 대기 기획서 수 |
| 개발 | 점 | 마지막 확인 이후 바뀐 작업·작업 그룹 존재 |
| 품질 확인 | 숫자 | 확인 가능한 기능 수 |
| 기록 | 없음 | R4 |
| 워크플로우 목록 항목 | 점 | 선택되지 않았고 결정 대기가 있음 |

## 선택한 기본값

기획 단계에서 열린 채로 남길 수 없는 선택이 하나 있어 다음과 같이 정했다. 사용자가 다르게 판단하면 이 기획서를 반려하면 된다.

- 무엇을 "달라진 것"으로 볼지: 문서가 마지막으로 바뀐 시각을 기준으로 삼는다. 백엔드가 화면에 넘기는 문서 요약에는 마지막 변경 시각만 있고 생성 시각은 없다. 생성 시각을 추가하려면 백엔드 자료 구조와 화면 자료 구조를 함께 바꿔야 하는데, 사용자가 얻는 이득은 "새 아이디어"와 "고쳐진 아이디어"를 가리는 것뿐이다. 두 경우 모두 한 번 열어 볼 이유가 된다고 보고 변경 시각 기준을 택했다.

## 제외 범위

- 오늘 화면의 내용과 구성은 바꾸지 않는다. 이 기획은 사이드 메뉴에만 표시를 더한다.
- 워크플로우 목록의 작업 그룹 총 개수 표시는 없애거나 다른 값으로 바꾸지 않는다.
- 운영체제 알림, 소리, 앱 아이콘 배지는 다루지 않는다.
- 확인 시점을 여러 컴퓨터 사이에서 맞추는 동기화는 다루지 않는다.
- 배지의 색상, 크기, 위치, 애니메이션 같은 시각 세부는 구현 단계에서 기존 화면 규칙에 맞춰 정한다.
- 워크플로우 문서 파일에는 아무것도 쓰지 않는다. 확인 시점은 화면 쪽 저장소에만 남는다.

## 수용 기준

- A1. 승인 대기 기획서가 두 건 있는 워크플로우를 선택하면 사이드 메뉴의 기획서 항목에 2가 보이고, 같은 순간 오늘 화면의 내 선택 대기가 세는 값과 어긋나지 않는다.
- A2. 확인 가능한 품질 확인 기능이 한 건 있으면 품질 확인 항목에 1이 보이고, 아직 열 수 없는 기능은 그 수에 들어가지 않는다.
- A3. 승인 대기 기획서와 확인 가능한 기능이 모두 없으면 두 메뉴에 배지가 그려지지 않는다. 0이 표시되지 않는다.
- A4. 아이디어 메뉴를 연 뒤 새 아이디어가 추가되면 아이디어 메뉴에 점이 나타나고, 그 메뉴를 다시 열면 점이 사라진다. 이때 개발 메뉴의 점은 영향을 받지 않는다.
- A5. 확인 기록이 없는 상태에서 프로젝트를 처음 열면 아이디어 메뉴와 개발 메뉴에 점이 켜지지 않는다.
- A6. 워크플로우를 A에서 B로 바꾸면 B의 확인 기록으로 점을 판단하고, 다시 A로 돌아오면 A의 판단이 그대로 유지된다.
- A7. 선택되지 않은 워크플로우에 승인 대기 기획서가 있으면 그 워크플로우 이름 옆에 점이 보이고, 작업 그룹 총 개수는 그대로 함께 보인다.
- A8. 배지가 있는 메뉴 버튼은 이름만 읽어도 어떤 메뉴이고 몇 건이 대기 중인지 알 수 있다.
- A9. 화면 상태 저장소를 읽을 수 없는 환경에서도 사이드 메뉴가 정상적으로 그려지고, 점만 켜지지 않는다.
