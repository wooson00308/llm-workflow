# 선택적 연동(플러그인) 개념 도입과 첫 연동 claude-heartbeat

## 기획 내용

LLM Workflow는 LLM을 실행하지 않는다. 그래서 "누가 언제 역할 세션을 깨우는가"는 사용자 환경의 몫이다. 지금은 그 구성을 사용자가 직접 한다. `~/.claude/HEARTBEAT.md`를 손으로 열어 잡 3개를 적고, 조건 스크립트를 저장소 어딘가에 두고, 프로젝트 경로를 slug로 변환해 적어 넣는다. 한 번 해보면 되는 일이지만, 손으로 적는 값이 많고 그중 하나만 틀려도 조용히 안 돌아간다.

이 기획서는 그 구성을 앱이 대신 써주는 "연동" 개념을 도입한다. 앱은 여전히 아무것도 실행하지 않는다. 파일 계약을 관리하고 상태를 보여줄 뿐이다. 지금까지 앱이 `AGENTS.md`의 관리 블록과 `.workflow/rules/`의 역할 계약을 소유해 온 것과 정확히 같은 방식으로, 하트비트 잡 정의와 조건 스크립트를 소유 자산으로 추가한다.

범위를 좁게 잡는다. 동적 플러그인 로딩은 하지 않는다. 연동은 앱에 내장된 것 하나(`claude-heartbeat`)뿐이고, 사용자는 그것을 켤지 말지만 고른다. 플러그인 아키텍처는 두 번째 연동이 실제로 생길 때 필요해지는 것이고, 지금 만들면 쓰이지 않는 추상화가 된다.

기존 승인분과의 관계를 밝혀 둔다. SPEC-001은 사용자가 스스로 하트비트를 구성하는 방법을 문서로 설명한다. 이 기획서는 같은 구성을 앱이 대신 써주는 기능이다. 문서는 여전히 필요하다. 앱을 쓰지 않고 CI나 다른 스케줄러로 돌리는 경로가 남아 있고, 앱이 무엇을 왜 쓰는지 읽을 곳이 있어야 한다. 두 산출물은 대체 관계가 아니다.

### 대상 도구 확인 사실

`claude-heartbeat`의 다음 동작을 실제 설치본에서 확인했고, 이 기획서는 그 위에 서 있다.

- 잡 설정 파일은 `~/.claude/HEARTBEAT.md` 하나다. 형식은 `## <잡 이름>` 헤더와 그 아래 `- key: value` 목록이다.
- 잡 필드는 `slug`, `prompt`, `interval`, `timeout`, `condition`, `notify`, `max_per`, `model`이다. 전역 설정(`tick`)은 첫 `##` 헤더보다 앞에 있어야 한다.
- 파서는 `## `로 시작하는 줄과 `- `로 시작하는 줄만 읽고 나머지는 무시한다. 따라서 HTML 주석 마커 줄을 넣어도 파싱이 깨지지 않는다.
- `condition`은 exit 0일 때만 잡을 실행하는 사전 검사이고, 프로젝트 cwd에서 실행된다. 그래서 상대 경로 조건 명령이 성립한다.
- 상태는 `~/.claude/heartbeat/state.json`에 잡 이름을 키로 기록된다(`last_run`, `last_result`, `last_duration`). 데몬 PID는 `~/.claude/heartbeat/heartbeat.pid`에 있다.
- `slug`는 프로젝트 경로의 `/`를 `-`로 바꾸고 앞에 `-`를 붙인 값이다. 역변환은 실제 디렉터리를 탐색하는 추정이므로, 앱은 정변환만 수행하고 결과를 사용자에게 그대로 보여준다.

### 포함 범위

- 설정 화면의 연동 섹션과 `claude-heartbeat` 연동 카드
- `~/.claude/HEARTBEAT.md` 앱 관리 마커 블록의 설치·갱신·제거
- 역할 잡 3종(기획자·아키텍트·개발자)의 기본값 제공과 편집
- 조건 스크립트를 앱 관리 자산으로 `.workflow/rules/`에 설치하고 버전 관리
- 하트비트 설치 여부·데몬 상태·잡별 마지막 실행 결과의 읽기 전용 표시

### 제외 범위

- 동적 플러그인 로딩, 서드파티 연동 등록 구조
- 앱이 하트비트를 설치·기동·중지하거나 잡을 즉시 실행하는 기능
- 앱이 LLM을 실행하는 기능
- `scripts/wf-eligible.sh`의 판정 로직 변경 — 현재 동작을 그대로 옮긴다
- 하트비트 로그 파일 뷰어, 실행 이력 그래프 등 관측 기능 확장
- SPEC-001의 산출물(`docs/heartbeat.md`)과 이 저장소 자체의 `scripts/wf-eligible.sh` 정리 — 아래 "확인 필요" 1번 참조
- `.workflow/rules/*.md` 역할 계약 본문 변경
- 마이그레이션 스키마 변경

## 요구사항 명세

### R1. 연동 섹션과 설치 상태 표시

- 설정 화면에 연동 섹션을 추가하고, 내장 연동 목록에 `claude-heartbeat` 한 개를 노출한다.
- 하트비트 설치 상태를 최소 세 가지로 구분해 표시한다: 미설치 / 설치됨·데몬 미실행 / 설치됨·데몬 실행 중.
- 미설치일 때는 설치 안내(설치 명령과 공식 문서 위치)만 보여준다. 앱이 설치를 대행하지 않는다.
- 설치됨일 때만 역할 잡 설치·관리 UI를 노출한다.
- 연동 목록은 앱 내장 항목의 고정 목록이다. 외부에서 연동을 추가로 등록하는 경로는 만들지 않는다.

### R2. 역할 잡 설치와 관리 블록 규약

- 설치 액션의 이름은 목적이 드러나야 한다(예: "이 프로젝트에 역할 잡 설치").
- 쓰기 대상은 `~/.claude/HEARTBEAT.md` 안의 앱 관리 마커 블록 하나뿐이다. 마커는 `AGENTS.md` 관리 블록과 같은 주석 마커 패턴을 따른다.
- 블록 밖의 사용자 잡과 전역 설정은 읽기만 하고 원문 그대로 보존한다.
- 관리 블록은 항상 파일 끝에 붙인다. 첫 `##` 헤더보다 앞에 삽입하지 않는다. 전역 설정 줄이 관리 잡의 필드로 흡수되어 `tick`이 조용히 무력화되는 것을 막기 위한 조건이다.
- 관리 블록 뒤에 사용자가 남긴 `- key: value` 줄이 이어지면 그 줄은 관리 블록의 마지막 잡에 흡수된다. 설치 시 이 상태를 감지하면 덮어쓰지 않고 사유와 함께 실패한다.
- 마커가 하나만 있거나 순서가 뒤집힌 손상 상태에서는 파일을 쓰지 않고 실패한다. 실패 시 원본은 바이트 단위로 그대로 남는다.
- 같은 입력으로 다시 실행하면 파일이 변하지 않는다(멱등).
- 잡 이름은 프로젝트마다 달라야 한다. 하트비트는 잡 이름을 상태 키로 쓰므로, 두 프로젝트에 설치했을 때 이름이 겹치면 실행 이력과 쿼터가 섞인다. 이름은 재설치해도 안정적이어야 하고, `heartbeat jobs` 출력에서 어느 프로젝트인지 알아볼 수 있어야 한다.

### R3. 역할 잡 기본값

- 설치 시 기획자·아키텍트·개발자 잡 3종을 아래 기본값으로 기록한다. 이 값은 현재 도그푸딩 구성에서 실사용 중인 값이다.

| 필드 | 기획자 | 아키텍트 | 개발자 |
| --- | --- | --- | --- |
| model | opus | opus | opus |
| interval | 30m | 30m | 20m |
| timeout | 20m | 20m | 30m |
| max_per | 4/24h | 4/24h | 6/24h |
| notify | all | all | all |
| condition | 설치된 조건 스크립트 `planner` | 동 `architect` | 동 `developer` |

- `slug`는 현재 프로젝트 루트 경로에서 규칙(`/` → `-`, 앞에 `-` 추가)대로 생성한다. 생성한 값을 UI에 그대로 보여주어 사용자가 눈으로 확인할 수 있게 한다.
- `prompt`는 역할마다 고정 문구로 앱이 소유한다. 각 문구는 세 가지를 반드시 포함한다: 하나의 역할로 고정, `.workflow` 공통 규칙과 해당 역할 계약 준수, 처리할 대상이 없으면 `NO_ELIGIBLE_WORK`만 보고하고 정지.
- `prompt`는 한 줄이어야 한다. 하트비트 파서가 줄 단위로 값을 읽기 때문이다.
- 기본 주기 값의 근거를 UI나 설명 문구에 남긴다: 한 세션이 수 분에서 수십 분 걸리므로 주기를 그보다 짧게 잡으면 조건 검사만 반복되고 중복 기동 위험만 늘어난다.

### R4. 조건 스크립트의 앱 관리 자산화

- 조건 스크립트를 `.workflow/rules/` 아래에 앱이 설치한다. 역할 계약 파일과 같은 소유 규칙을 적용한다.
- 판정 로직은 현재 `scripts/wf-eligible.sh`와 동일하다. 인자는 `planner` | `architect` | `developer`, 종료 코드는 `0`(대상 있음) / `1`(없음) / `2`(잘못된 사용법)이고, `.workflow/.runtime/migration.lock`이 있으면 역할과 무관하게 `1`이다.
- 스크립트 파일에 버전 표기를 두고 다음을 보장한다.
  - 파일이 없으면 설치한다.
  - 앱 관리 표기가 없는 파일이 그 경로에 있으면 덮어쓰지 않고 실패한다.
  - 파일의 버전이 앱이 아는 버전보다 높으면 덮어쓰지 않고 실패한다(다운그레이드 거부).
  - 그 외에는 앱 버전으로 맞춘다.
- 잡의 `condition`은 프로젝트 루트 기준 상대 경로로 이 설치본을 가리킨다. 하트비트가 조건을 프로젝트 cwd에서 실행하므로 상대 경로로 충분하다.
- 조건 스크립트 설치는 프로젝트 로컬 파일 쓰기이므로 역할 잡 설치 액션과 같은 사용자 액션 안에서 함께 수행한다.

### R5. 관리 UI

- 역할별 활성 토글을 제공한다. 끄면 해당 잡을 관리 블록에서 제거한다. 하트비트에는 비활성 상태 필드가 없으므로 "꺼짐"은 곧 "블록에 없음"이다.
- `interval`, `max_per`, `model`을 편집할 수 있다. 저장 전에 형식을 검증하고, 잘못된 값은 파일에 쓰지 않고 입력 위치에서 알린다.
  - `interval`: 숫자 + `s`|`m`|`h`|`d`
  - `max_per`: `<횟수>/<기간>` 형태이고 기간은 위와 같은 단위 표기
  - `model`: 공백 없는 한 줄 값
- 데몬 상태와 잡별 마지막 실행 결과를 표시한다. 출처는 하트비트 상태 파일이며 읽기 전용이다.
  - 표시 항목: 마지막 실행 시각, 마지막 결과, 소요 시간
  - 상태 파일이 없거나 해당 잡 기록이 없으면 "실행 기록 없음"으로 표시한다. 오류로 취급하지 않는다.
- 상태 표시는 앱의 기존 자동 새로고침 주기를 따른다. 이를 위해 별도 감시 장치를 새로 만들지 않는다.

### R6. 쓰기 안전

- `~/.claude/HEARTBEAT.md` 쓰기는 명시적 사용자 액션에서만 일어난다. 앱 시작, 프로젝트 열기, 자동 새로고침, 화면 진입은 전역 파일을 쓰지 않는다.
- 전역 파일에 쓰기 전에 대상 경로와 변경 내용의 요지를 사용자에게 보여주고 확인을 받는다.
- 앱은 하트비트 데몬을 시작·중지하지 않고, 잡을 즉시 실행하지 않는다.
- 앱은 `~/.claude/heartbeat/` 아래 상태 파일과 로그에 쓰지 않는다.
- 전역 파일 쓰기는 기존 프로젝트 파일 쓰기와 같은 원자적 저장 방식을 따른다. 쓰기 도중 실패해도 원본이 반쯤 덮이지 않아야 한다.

### R7. 중복 잡 감지

- 관리 블록 밖에 같은 `slug`를 쓰면서 조건 스크립트를 참조하는 잡이 이미 있으면 경고를 표시한다.
- 경고만 하고 자동으로 지우지 않는다. 사용자 잡은 앱 소유가 아니다.
- 경고 문구는 위험을 구체적으로 밝힌다: 같은 역할 잡이 둘이면 두 세션이 동시에 깨어나 하나는 lease 경합으로 `NO_ELIGIBLE_WORK`로 끝나고, 쿼터만 두 배로 소모된다.

## 확인 필요

사용자 결정이 필요한 항목이다. 승인 시 아래 제안대로 진행한다.

1. 조건 스크립트의 단일 원본 위치. 이 저장소에는 이미 `scripts/wf-eligible.sh`가 있고, 승인된 SPEC-001의 `docs/heartbeat.md`는 그 경로를 공식 인터페이스로 기술하도록 되어 있다(TASK-001·TASK-002는 아직 `todo`). 이 기획서대로 앱이 `.workflow/rules/`에 설치하면 이 저장소에는 같은 스크립트가 두 벌 존재하게 되고 시간이 지나면 갈라진다.

   제안: 앱 설치본(`.workflow/rules/`)을 원본으로 삼는다. 다만 이번 범위에서는 이 저장소의 `scripts/wf-eligible.sh` 제거나 `docs/heartbeat.md` 문구 수정을 하지 않는다. SPEC-001이 아직 구현 전이라 두 기획서의 구현 순서에 따라 결과가 달라지고, 승인된 기획서의 완료 조건을 이 기획서가 조용히 바꾸는 것은 옳지 않다. 정리는 두 산출물이 모두 존재하게 된 뒤 별도 아이디어로 다룬다.

2. Windows 지원 범위. 조건 명령은 셸 스크립트이고 앱은 Windows·Linux·macOS를 모두 배포한다. Windows에는 기본 `sh`가 없으므로 설치된 잡의 조건 검사가 실패한다(하트비트는 조건 검사 실패를 skip으로 처리하므로, 증상은 "아무 일도 일어나지 않음"이다).

   제안: 이번 범위에서는 POSIX `sh` 스크립트 하나만 설치하고, Windows에서는 연동 카드에 미지원 안내를 표시한 뒤 설치 액션을 막는다. Windows용 조건 스크립트는 수요가 확인되면 별도로 다룬다.

## 기대효과

- 하트비트 구성에서 사람이 손으로 적던 값(slug, 조건 경로, 프롬프트, 주기, 쿼터)이 앱이 생성하는 값이 되어, 오타로 조용히 안 돌아가는 실패가 사라진다.
- 조건 스크립트가 역할 계약과 같은 앱 관리 자산이 되어, 판정 기준이 바뀔 때 앱 업데이트만으로 모든 프로젝트에 전파된다.
- 사용자가 앱 안에서 데몬 상태와 마지막 실행 결과를 확인할 수 있어, "잡을 걸어 놨는데 도는지 모르겠다"를 파일을 뒤지지 않고 확인한다.
- 연동을 내장 고정 목록으로 시작해 두 번째 연동이 실제로 생기기 전까지 플러그인 추상화 비용을 지불하지 않는다.

## 완료 조건

1. 설정 화면에 연동 섹션이 있고, 하트비트 미설치 / 설치됨·데몬 미실행 / 설치됨·데몬 실행 중 세 상태가 서로 다르게 표시된다. 검증: 세 상태를 각각 재현하고 화면을 확인한다.
2. 역할 잡 설치 후 `~/.claude/HEARTBEAT.md`에 관리 마커 블록이 하나 생기고 그 안에 역할 잡 3종이 R3의 기본값으로 기록된다. 검증: 설치 전후 파일을 비교해 블록 밖 내용이 바이트 단위로 동일한지 확인하고, `heartbeat jobs`로 잡 3종이 인식되는지 확인한다.
3. 같은 설치를 두 번 실행해도 파일이 변하지 않는다. 검증: 두 번째 실행 전후 파일 해시가 같다.
4. 전역 설정(`- tick:`)이 있는 파일에 설치해도 그 값이 유지된다. 검증: `tick`이 있는 파일에 설치한 뒤 `heartbeat jobs` 또는 파싱 결과에서 tick 값이 그대로인지 확인한다.
5. 마커가 손상된 파일과 관리 블록 뒤에 사용자 `- key: value` 줄이 이어지는 파일에서는 설치가 실패하고 원본이 변경되지 않는다. 검증: 두 경우를 각각 만들어 실행하고 파일 해시가 유지되는지 확인한다.
6. `.workflow/rules/`에 조건 스크립트가 설치되고, 인자 3종과 종료 코드 `0`/`1`/`2`가 현재 `scripts/wf-eligible.sh`와 동일하게 동작한다. 검증: 설치본과 기존 스크립트를 같은 저장소 상태에서 각 역할로 실행해 종료 코드를 대조하고, 잘못된 인자로 `2`가 나오는지 확인한다.
7. 조건 스크립트 경로에 앱 관리 표기가 없는 파일이나 더 높은 버전의 파일이 있으면 설치가 실패하고 그 파일이 변경되지 않는다. 검증: 두 경우에 대한 자동화 테스트가 존재하고 통과한다.
8. 역할 토글을 끄면 해당 잡이 관리 블록에서 사라지고, 다시 켜면 같은 이름으로 복구된다. 검증: 토글 왕복 후 파일 내용이 최초 설치 결과와 같다.
9. `interval`·`max_per`·`model`에 잘못된 형식을 입력하면 파일에 쓰이지 않고 화면에서 사유가 표시된다. 검증: 각 필드의 잘못된 입력에 대한 테스트가 존재하고 통과한다.
10. 잡별 마지막 실행 시각·결과·소요 시간이 하트비트 상태 파일 내용과 일치하게 표시되고, 기록이 없으면 "실행 기록 없음"으로 표시된다. 검증: 상태 파일이 있는 경우와 없는 경우를 각각 확인한다.
11. 앱 시작·프로젝트 열기·자동 새로고침만으로는 `~/.claude/HEARTBEAT.md`가 변경되지 않는다. 검증: 설치 액션 없이 앱을 켜고 프로젝트를 열어 새로고침을 여러 번 거친 뒤 파일 수정 시각과 해시가 그대로인지 확인한다.
12. 관리 블록 밖에 같은 slug의 중복 역할 잡이 있으면 경고가 표시되고, 그 잡은 앱에 의해 수정되거나 삭제되지 않는다. 검증: 중복 잡을 만든 뒤 화면 경고를 확인하고 해당 줄이 그대로인지 확인한다.
13. `npm run check`와 `cargo test --manifest-path src-tauri/Cargo.toml`이 통과한다.
