# 프로젝트를 열 때 관리 규칙을 최신 상태로 맞춘다

## 결정권자 요약

앱이 새 규칙을 포함해도 기존 프로젝트에는 예전 규칙이 남을 수 있다. 실제로 이번 승인 두 건은 새
백엔드가 시작되기 직전에 처리돼, 앱 소스는 버전 13인데 프로젝트의 설치 규칙은 버전 12로 남았다.
프로젝트를 처음 열 때와 사용자가 새로 고침을 눌렀을 때 관리 규칙을 최신 상태로 맞춘다. 2.5초마다
실행되는 자동 조회는 계속 읽기만 하므로 불필요한 파일 쓰기가 생기지 않는다.
설정 화면에서는 설치된 버전과 앱이 제공하는 버전, 마지막 갱신 결과를 확인할 수 있게 한다. 충돌이
있으면 사용자 파일을 덮어쓰지 않고 프로젝트는 계속 열어 둔 채 해결이 필요한 이유를 보여준다.
사용자가 결정할 것은 이 동작과 화면 표시를 추가할지다. 승인하지 않으면 다음 기획 결정이나 작업 QA가
실행될 때까지 예전 규칙이 남을 수 있는 현재 동작이 유지된다.

## 기획 내용

앱이 관리하는 공통 규칙과 역할별 규칙은 실행 파일 안에 들어 있다. 새 앱 버전이나 개발 중 재빌드가
더 높은 규칙 버전을 포함해도, 이미 열린 프로젝트의 파일은 자동으로 갱신되지 않는다. 현재 설치 함수는
새 워크플로 생성, 기획 결정, 작업 QA를 기록할 때만 실행된다.

이번 도그푸딩에서 이 빈틈이 실제로 나타났다. TASK-130과 TASK-131의 QA 결정은
2026-08-06T09:18:15Z에 기록됐고, 버전 13을 포함한 새 개발 백엔드는 약 51초 뒤에 시작됐다. QA는
구버전 백엔드가 처리했기 때문에 `.workflow/rules/workflow.md`는 버전 12로 남았다. 새 백엔드가 실행된
뒤 프로젝트를 다시 열어도 조회만 수행하므로 파일은 바뀌지 않았다.

프로젝트 조회는 세 곳에서 함께 사용된다.

1. 최근 프로젝트나 폴더 선택으로 프로젝트를 열 때
2. 사용자가 상단의 새로 고침을 누를 때
3. 열린 프로젝트를 2.5초 간격으로 다시 읽을 때

세 번째 조회까지 규칙 설치를 수행하면 백그라운드 조회가 쓰기 동작으로 바뀐다. 따라서 명시적인 열기와
새로 고침에는 동기화를 포함하고, 주기 조회는 지금처럼 읽기 전용으로 유지해야 한다.

### 사용자에게 보이는 동작

- 프로젝트를 열면 앱이 프로젝트 정보를 읽은 뒤 관리 규칙의 설치 상태를 확인하고 필요한 갱신을 한 번
  수행한다.
- 사용자가 새로 고침을 누르면 같은 확인과 갱신을 다시 수행한다.
- 설정 화면에 관리 규칙 상태를 추가한다. 설치된 버전, 앱이 제공하는 버전, 마지막 갱신 결과를 보여준다.
- 갱신할 내용이 없으면 현재 상태라고 표시한다. 갱신에 성공하면 적용된 버전을 표시한다.
- 관리 마커 손상, 앱이 모르는 규칙 파일, 앱보다 높은 버전처럼 자동 갱신할 수 없는 상태에서는 파일을
  덮어쓰지 않는다. 프로젝트 화면은 유지하고 설정과 공통 오류 영역에 이유를 보여준다.
- 규칙은 새로 시작하는 에이전트 세션부터 적용된다고 안내한다. 이미 실행 중인 세션을 재시작하거나
  강제로 다시 읽게 하지는 않는다.

### 포함 범위

- 프로젝트 열기와 사용자의 새로 고침에서 앱 관리 규칙을 동기화한다.
- 공통 규칙, 역할별 규칙, 에이전트 진입점, 선점 헬퍼에 기존 설치 절차를 그대로 적용한다.
- 자동 조회와 사용자 동작을 구분해 자동 조회는 읽기 전용으로 유지한다.
- 프로젝트 설정에 관리 규칙의 설치 버전과 앱 제공 버전, 갱신 결과를 표시한다.
- 갱신 실패가 프로젝트 전체를 닫지 않도록 하고, 파일을 고쳐야 하는 이유를 사용자에게 알린다.
- 최초 설치, 같은 버전 재실행, 낮은 버전 갱신, 충돌, 앱보다 높은 버전의 기존 안전 동작을 보존한다.

### 제외 범위

- 사용자가 직접 규칙을 작성하는 커스텀 가드레일 UI. 이 기능은 IDEA-655ADA04에서 별도로 기획한다.
- 실행 중인 에이전트 세션의 규칙을 즉시 교체하는 기능.
- 앱이 관리하지 않는 파일을 자동으로 편집하거나 관리 파일의 충돌을 자동 해결하는 기능.
- 2.5초 자동 조회에서 파일을 갱신하는 기능.
- 앱 기본 규칙의 내용이나 역할별 처리 절차를 변경하는 작업.

## 요구사항 명세

### R1. 명시적인 프로젝트 열기와 새로 고침이 규칙을 동기화한다

- 최근 프로젝트 선택과 폴더 선택으로 프로젝트를 열 때 한 번 동기화한다.
- 상단 새로 고침을 누를 때 다시 동기화한다.
- 프로젝트가 유효한 현재 문서 규격일 때만 동기화한다. 초기화되지 않았거나 마이그레이션이 필요하거나
  더 새로운 문서 규격인 프로젝트에는 기존 호환성 판정을 적용한다.
- 마이그레이션 잠금이 있으면 규칙 파일을 쓰지 않고 잠금이 해제된 뒤 다시 시도할 수 있게 한다.

### R2. 주기 조회는 계속 읽기 전용이다

- 2.5초 간격의 자동 조회는 규칙 설치 함수를 호출하지 않는다.
- 자동 조회는 문서와 lease 변화를 화면에 반영하는 현재 역할만 수행한다.
- 자동 조회 중에는 관리 규칙, 역할별 규칙, 에이전트 진입점, 선점 헬퍼의 수정 시각이 바뀌지 않는다.

### R3. 기존 설치 안전 규칙을 재사용한다

- 새 동기화 경로가 별도의 덮어쓰기 규칙을 만들지 않고 현재 설치와 검증 절차를 사용한다.
- 파일이 없으면 만들고, 앱이 관리하는 낮은 버전이면 갱신하며, 내용과 버전이 같으면 쓰지 않는다.
- 관리 형식을 확인할 수 없거나 설치 버전이 앱보다 높으면 충돌로 처리하고 파일을 바꾸지 않는다.
- 한 파일의 충돌 때문에 앞에서 검사한 다른 관리 파일만 일부 갱신되는 일이 없도록, 변경 대상을 모두
  확인한 뒤 저장한다.

### R4. 실패해도 프로젝트를 읽을 수 있다

- 규칙 동기화 실패와 프로젝트 문서 조회 실패를 구분한다.
- 프로젝트 문서를 읽을 수 있다면 기존 화면을 유지한다.
- 사용자에게 어떤 관리 자산에서 왜 갱신이 멈췄는지 알려 주되, 해결되지 않은 충돌을 자동으로 고치지
  않는다.
- 마이그레이션 잠금처럼 나중에 다시 시도할 수 있는 상태와 파일 충돌처럼 사용자가 확인해야 하는 상태를
  구분한다.

### R5. 설정 화면에서 설치 상태를 확인할 수 있다

- 현재 프로젝트 카드와 별도로 관리 규칙 상태를 표시한다.
- 공통 규칙과 역할별 규칙의 설치 버전, 앱 제공 버전, 마지막 동기화 결과를 보여준다.
- 상태는 최소한 현재, 갱신됨, 재시도 필요, 충돌을 구분한다.
- 규칙 변경은 이미 실행 중인 에이전트가 아니라 다음에 시작하는 세션부터 적용된다고 적는다.

### R6. 커스텀 가드레일과 분리한다

- 이 작업은 앱이 제공하는 기본 관리 규칙의 배포 시점만 다룬다.
- 사용자 정의 규칙의 저장 형식, 우선순위, 편집 UI는 정하지 않는다.
- 이후 IDEA-655ADA04를 구현할 때도 앱의 필수 안전 규칙을 덮어쓰지 않는다는 경계는 유지한다.

## 확인 필요

없다. 자동 조회를 읽기 전용으로 유지하고, 충돌 시 프로젝트를 닫지 않으며, 커스텀 가드레일을 별도
기능으로 두는 방향까지 사용자 요청과 현재 구조에서 정할 수 있다.

## 기대효과

- 앱 업데이트나 개발 재빌드 직후에도 별도의 승인 작업을 만들지 않고 새 규칙을 기존 프로젝트에
  적용할 수 있다.
- 사용자는 재시작 여부를 추측하지 않고 설정 화면에서 실제 설치 상태를 확인할 수 있다.
- 규칙 충돌이 프로젝트 전체 접근을 막지 않으며, 앱이 사용자 파일을 임의로 덮어쓰지 않는다.
- 자동 조회는 계속 읽기 전용이라 2.5초마다 파일 수정 시각이 바뀌거나 Git 변경이 생기지 않는다.
- 커스텀 가드레일은 별도 기획으로 남아 기본 규칙 배포 수정의 범위를 키우지 않는다.

## 완료 조건

1. 새 앱 규칙 버전이 기존 프로젝트보다 높을 때, 프로젝트를 열면 관리 규칙이 새 버전으로 갱신된다.
2. 같은 상태에서 상단 새로 고침을 눌러도 같은 결과가 나온다.
3. 이미 최신인 관리 파일은 다시 쓰지 않으며 수정 시각도 바뀌지 않는다.
4. 2.5초 자동 조회를 여러 번 실행해도 관리 파일이 변경되지 않는다.
5. 관리 형식이 아니거나 앱보다 높은 규칙 버전이 있으면 해당 파일을 덮어쓰지 않는다.
6. 5번의 충돌이 있어도 프로젝트 문서를 읽을 수 있으면 화면은 열린 상태를 유지하고 실패 이유를
   보여준다.
7. 마이그레이션 잠금 중에는 규칙 파일을 쓰지 않고 재시도 가능한 상태를 보여준다.
8. 설정 화면에서 설치 버전, 앱 제공 버전, 마지막 동기화 결과와 다음 세션부터 적용된다는 안내를 볼 수
   있다.
9. 공통 규칙, 역할별 규칙, 에이전트 진입점, 선점 헬퍼의 기존 최초 설치와 업그레이드, 충돌 방어 검사가
   모두 통과한다.
10. 기존 기획 결정, 작업 QA, 새 워크플로 생성에서 수행하던 규칙 설치도 계속 동작한다.
11. 커스텀 가드레일 편집과 저장 기능은 이 변경에 포함되지 않는다.
