# 검증이 끝난 자동 확인 작업 그룹이 완료로 마감된다

자동 확인 방식의 작업 그룹은 속한 작업이 모두 검증 완료가 되면 완료로 마감된다. 그 뒤 저장소에
새 커밋이 들어와도 개발 중으로 되돌아가지 않는다. 지금 이 이유로 개발 중에 갇혀 있는 작업 그룹
하나는 사용자가 별도 조작을 하지 않아도 화면을 다시 열 때 완료로 정리된다. 사용자가 직접 확인하는
작업 그룹에서는 확인 도중 코드가 바뀐 제출을 기록하지 않는 지금의 보호를 그대로 두면서, 거절
뒤에 다시 확인해 제출할 수 있는 길을 연다.

## 품질 확인 방식

이 그룹은 사용자 품질 확인으로 완료한다. 바뀌는 결과가 개발 작업 화면과 기록 화면에서 사용자가
직접 보는 작업 그룹의 상태이고, 갇혀 있던 그룹이 실제로 완료로 정리되었는지는 화면을 열어 보는
것으로만 확인할 수 있다.

## 작업 구성

작업 둘로 나눴다. 첫 작업은 자동 확인 그룹의 완료 판정을 판정 시점의 코드 상태에서 내리게 하고,
둘째 작업은 사용자 확인 그룹의 재확인 경로를 연다.

두 작업은 순서가 있다. 둘째 작업은 첫 작업이 만드는 기준 기록 갱신 동작을 사용자 확인 쪽에서 함께
쓰고, 같은 파일의 같은 판정 자리를 손대므로 첫 작업이 끝난 뒤에 시작한다.

나눈 이유는 보호가 끊기는 구간을 만들지 않기 위해서다. 확인 도중 코드가 바뀐 제출을 기록하지 않는
보호는 사용자 확인 그룹에서 계속 유지되어야 하는데, 첫 작업이 사용자 확인 경로를 손대지 않고 자동
확인 경로만 바꾸므로 두 작업 사이에도 그 보호가 그대로 남는다. 첫 작업만 끝난 상태에서도 갇힌
그룹이 완료로 정리되는 결과는 이미 확인할 수 있다.

### QA-01 · 갇혀 있던 작업 그룹이 완료로 정리되었는지 확인한다

1. 개발 작업 화면을 연다.
   > 검증이 모두 끝났는데도 개발 중에 남아 있던 작업 그룹이 목록에서 사라졌다. 남아 있는 그룹은 아직
   > 개발이 진행 중이거나 품질 확인을 기다리는 그룹뿐이다.
2. 화면 위의 진행 중 수치와 표시 건수를 읽는다.
   > 완료로 정리된 그룹의 작업이 빠진 값이다. 진행 중 수치가 실제로 남은 일의 양을 가리킨다.
3. 기록 화면을 열어 방금 목록에서 사라진 작업 그룹을 찾아 펼친다.
   > 그 그룹이 완료로 표시되고, 포함된 작업이 모두 검증 완료로 보인다. 확인 방식은 자동 확인으로
   > 표시된다.
4. 개발 작업 화면으로 돌아가 화면을 다시 불러온다.
   > 완료로 정리된 그룹이 개발 중으로 되돌아오지 않는다. 여러 번 다시 열어도 그대로 유지된다.
5. 품질 확인 화면을 열어 확인 가능한 기능이 있으면 하나를 열고, 안내대로 확인한 뒤 결과를 제출한다.
   > 제출이 기록되고 그 기능이 확인 목록에서 사라진다.
6. 5번에서 확인 대상 코드가 그사이 바뀌었다는 안내와 함께 제출이 거절된 경우에만, 같은 기능을
   처음부터 다시 확인한 뒤 결과를 제출한다.
   > 이번에는 제출이 기록된다. 같은 안내가 반복되지 않는다.
