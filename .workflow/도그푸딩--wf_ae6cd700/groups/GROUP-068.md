# 실행 환경 계획을 적용한 결과를 화면에서 읽게 하기

## 기능 설명

실행 환경 계획을 적용하면 확인 창이 그대로 닫히지 않고 결과 화면으로 바뀐다. 적용이 수행한 단계가
순서대로 서고 각 단계에 완료, 건너뜀, 실패 중 하나가 붙으며, 실패한 단계 아래에는 왜 실패했는지가
사용자 언어로 적힌다. 사유가 실려 오지 않은 실패 단계에도 사유를 확인하지 못했다는 사실이 적혀
자리가 비지 않는다. 전체 결과는 성공, 부분 실패, 실패로 구분해 알린다.

적용 뒤에도 자동 배정이 연결 필요 상태로 남으면, 결과 화면이 그 사실과 그렇게 만든 단계를 한
문장으로 알린다. 창을 닫은 뒤에도 고급 설정의 실행 환경 자리에서 마지막 적용 결과를 다시 열어
읽을 수 있고, 다음 적용이 시작되면 이전 결과는 사라진다.

실행 환경이 이미 설치되어 있고 관리형 서비스 연결만 남은 기기에서는 확인 창의 제목과 안내 문장이
설치가 아니라 서비스 연결을 말한다. 버전이 달라지지 않는 계획에서는 같은 버전을 화살표 양쪽에 두
번 적지 않고 현재 버전을 유지한다는 사실을 밝힌다.

적용 절차 자체는 달라지지 않는다. 계획을 먼저 보여주고 확인받은 뒤에만 적용하는 순서, 적용이
부르는 명령과 인자, 오래된 계획을 거절하고 다시 만드는 처리, 예외로 실패한 적용의 지금 표시가
모두 그대로다.

## 품질 확인 방식

사용자 확인으로 둔다. 이 그룹이 바꾸는 것은 전부 사용자가 화면에서 직접 보는 결과다. 적용 뒤 창이
결과 화면으로 바뀌는지, 단계와 사유가 읽히는지, 창을 닫은 뒤 결과를 다시 열 수 있는지, 확인 창의
제목이 무엇을 말하는지는 저장소를 열지 않고도 앱 화면만으로 판단할 수 있다.

확인에 필요한 상태도 이미 있다. 2026-08-18 Windows 새 기기가 런타임은 설치되어 있고 관리형 서비스만
등록되지 않은 상태이며, 그 기기에서 연결 계획을 적용하면 서비스 연결 단계가 실패하는 것이 실측으로
확인되어 있다. 사용자가 상태를 따로 만들지 않아도 부분 실패와 실패 사유 표시를 그 자리에서 만난다.

기획서의 수용 기준 다섯 중 넷이 화면에서 눈으로 확인된다. 나머지 하나는 이 변경 전후로 적용이
호출하는 명령과 인자, 계획 재생성 동작이 같아야 한다는 REQ-05의 기준이며, 그것은 두 작업의 완료
조건과 자동 검증이 맡는다.

## 작업 구성

작업 둘로 나눴다. 경계는 사용자가 화면을 만나는 시점이다. 적용을 누르기 전에 읽는 계획 확인 화면과,
적용을 누른 뒤에 읽는 결과 화면은 서로 다른 순간에 서로 다른 판단을 돕는다.

첫 작업이 적용 뒤를 맡는다. 결과 화면, 단계별 표시, 실패 사유의 사용자 언어 변환, 남은 상태를
설명하는 문장, 창을 닫은 뒤 다시 여는 입구까지다. 기획서의 REQ-01, REQ-02, REQ-03이 여기에 속하고,
적용 절차를 그대로 둔다는 REQ-05도 이 작업이 지킨다. 이 작업은 화면 파일과 함께 앱 상태 파일도
고친다. "다음 적용이 시작될 때까지 유지한다"를 지키려면 적용이 시작되는 순간 이전 결과를 지워야
하고, 그 자리가 앱 상태 파일에 있기 때문이다. 지우지 않으면 예외로 끝난 적용 뒤에 이전 결과가
마지막 결과인 척 남는다.

둘째 작업이 적용 전을 맡는다. 서비스 연결만 남은 계획의 확인 창 제목과 안내 문장, 그리고 버전이
달라지지 않는 계획의 버전 줄이다. 기획서의 REQ-04가 여기에 속한다. 문구를 고르는 조건만 늘어나므로
새 스타일이 필요 없고, 화면 파일과 그 검사 파일 둘만 고친다.

두 작업 사이에는 순서를 두었다. 같은 화면 파일의 같은 확인 창 컴포넌트를 고치기 때문이다. 첫 작업이
그 컴포넌트에 결과 화면이라는 갈래를 새로 만들고, 둘째 작업은 그 위에 문구 조건을 얹는 작은 변경
이므로 첫 작업을 먼저 두었다. 반대로 두면 작은 변경이 곧바로 큰 구조 변경에 다시 실려야 한다.

이 그룹 밖의 순서도 붙는다. TASK-S067-01이 같은 화면 파일의 위쪽을 고쳐 준비 안내를 새로 세우고,
TASK-S063-02가 같은 검사 파일과 스타일 파일을 고친다. 그래서 첫 작업을 그 둘 뒤에 두었다. 둘째
작업은 첫 작업 뒤에 오므로 같은 순서를 함께 물려받는다.

## 이번 그룹이 다루지 않는 것

Windows 기기에서 서비스 연결이 실제로 왜 실패하는지, 그 원인 자체는 고치지 않는다. 이번 표시로
사유가 화면에 드러난 뒤 별도 아이디어와 기획서로 잇는다. 기획서와 그 출처 아이디어가 같은 판단을
적었다.

적용이 실패한 뒤의 자동 재시도와 자동 복구도 다루지 않는다. 결과를 읽고 다음에 무엇을 할지 정하는
것은 사용자의 판단으로 둔다.

실행 환경 판정 규칙은 그대로 둔다. 서비스 등록 여부로 자동 배정 연결 필요를 판정하는 지금 규칙을
바꾸지 않고, 결과 화면은 그 판정이 낸 값을 읽기만 한다.

### QA-01 · 연결 계획을 적용하고 결과 읽기

1. 자동 배정 서비스 연결이 아직 되지 않은 기기에서 앱을 열고 에이전트 화면을 연다.
   > 관리형 서비스를 연결하라는 안내와 연결 계획을 시작하는 버튼이 보인다.
2. 고급 설정을 열고 실행 환경 자리를 펼쳐 본 뒤 고급 설정을 닫는다.
   > 아직 적용을 한 적이 없으므로 마지막 적용 결과를 다시 여는 자리가 없다.
3. 에이전트 화면에서 연결 계획 버튼을 누른다.
   > 확인 창이 열리고 제목과 안내 문장이 관리형 서비스 연결을 말한다. 설치라는 말이 없고, 버전 줄은 같은 버전을 화살표 양쪽에 두 번 적는 대신 현재 버전을 유지한다고 알린다.
4. 확인 창에서 적용을 누른다.
   > 창이 닫히지 않고 같은 자리에서 결과 화면으로 바뀐다. 적용이 수행한 단계가 순서대로 서 있고 각 단계에 완료나 건너뜀이나 실패가 적혀 있으며, 전체 결과가 성공인지 부분 실패인지 실패인지 함께 적혀 있다.
5. 실패로 표시된 단계 아래 문장을 읽는다.
   > 왜 실패했는지 설명하는 문장이 있다. 사유를 확인하지 못한 경우에도 그 사실이 문장으로 적혀 있고 자리가 비어 있지 않다.
6. 결과 화면 아래쪽 안내를 읽는다.
   > 적용 뒤에도 자동 배정이 연결 필요 상태로 남았다면 그 사실과 어느 단계 때문인지가 한 문장으로 적혀 있다. 모든 단계가 성공했다면 이 문장이 없다.
7. 닫기를 눌러 결과 화면을 닫는다.
   > 창이 사라지고 에이전트 화면으로 돌아온다.
8. 다른 메뉴를 한 번 다녀온 뒤 에이전트 화면을 다시 연다.
   > 결과 화면이 저절로 다시 열리지 않는다.
9. 고급 설정을 열고 실행 환경 자리를 본다.
   > 마지막 적용 결과를 다시 여는 자리가 생겨 있고, 열면 4번과 5번에서 본 단계별 결과와 실패 사유가 그대로 보인다.
