# 사용자가 프로젝트별 커스텀 가드레일을 관리한다

## 기능 설명

기존 개발 작업을 기획서 기준의 작업 그룹으로 전환했습니다.

### QA-01 · 사용자 정의 규칙 파일과 적용 규칙 미리보기를 백엔드에 추가한다

이 작업은 화면 변경이 없는 백엔드 계약 작업이다. 설정 화면과 실제 편집 흐름은 TASK-136과 TASK-137이
연결한다.

1. 자동 검사에서 저장 파일 미리보기와 실제 저장 바이트가 같고 세 역할의 규칙 출처 순서가 같은지
   확인한다.
2. 외부 생성, 수정, 삭제, 심볼릭 링크 교체와 공용 잠금 경합에서 기존 파일을 보존하는지 확인한다.
3. 잘못된 사용자 파일이 있어도 프로젝트 조회와 관리 규칙 동기화가 성공하며 사용자 파일의 내용과
   수정 시각이 유지되는지 확인한다.
4. 설치되는 공통 규칙과 역할별 계약의 제공 버전이 14·9·8·9이고 사용자 규칙보다 우선하는지 확인한다.
5. Rust 전체 테스트 574개, 모든 대상의 정적 검사, 포맷 검사와 변경 공백 검사가 통과했다. 확인 도장은
   이 백엔드 계약과 검증 결과를 승인한다는 뜻이다.

### QA-02 · 사용자 정의 규칙 조회와 저장 상태를 작업 공간에 연결한다

이 작업은 화면을 만들지 않고 작업 공간 상태와 명령 호출 계약을 연결하므로 별도 화면 확인은 없다.
배포 빌드가 모두 통과한 결과를 확인한다는 뜻이다. 실제 설정 화면 동선은 TASK-137에서 확인한다.

### QA-03 · 설정에서 사용자 정의 규칙을 편집하고 최종 적용 내용을 확인한다

1. 개발 앱에서 이 저장소를 열고 사이드바 `설정`을 누른다. 기존 `관리 규칙` 카드 아래에 `사용자 정의
   규칙` 카드가 따로 보이고, API 키·비밀번호를 입력하지 말라는 안내와 다음 세션 적용 안내가 보인다.
2. `사용자 규칙 사용`을 켠 뒤 기획자·아키텍트·개발자 중 한 역할을 선택하고 Markdown 본문을 적는다.
   `저장하지 않은 변경이 있습니다`가 보이며 아직 `저장` 버튼은 비활성 상태여야 한다.
3. `미리보기 준비`를 누른다. 저장 파일 원문에 프론트매터와 본문이 함께 보이고, 역할 탭을 바꾸면 공통
   규칙, 해당 역할 계약, 사용자 정의 규칙이 1·2·3 순서와 적용 여부, 제외 사유를 함께 보여야 한다.
4. 미리보기에 일반 링크, `javascript:` 링크, HTML 태그와 외부 이미지를 본문으로 넣어도 클릭 가능한
   링크, 스크립트, 이미지가 생기지 않는지 확인한다. 미리보기를 준비한 뒤에만 `저장`이 활성화된다.
5. 본문을 완전히 비우고 `미리보기 준비`를 누르면 빈 본문 확인이 먼저 나오며, 확인 전에는 미리보기가
   바뀌지 않아야 한다. `변경 취소`는 파일을 다시 읽지 않고 마지막으로 불러온 값으로 돌아간다.
6. 저장한 뒤 앱을 재시작하지 않아도 카드의 마지막 수정 시각과 적용 상태가 갱신되고 `다음 에이전트
   세션부터 적용` 안내가 보여야 한다. 활성 lease가 있으면 이전 규칙을 사용할 수 있다는 안내가 추가되지만
   저장은 막히지 않아야 한다.
7. 편집 중 `.workflow/rules/custom.md`를 외부 편집기에서 바꾸고 약 2.5초 기다린다. 입력 중인 본문은
   유지되고 외부 변경 알림과 `다시 불러오기`가 나타나며 저장은 비활성화돼야 한다. 다시 불러오기는
   저장하지 않은 변경을 버릴지 한 번 더 확인해야 한다.
8. 형식이 잘못됐거나 더 새로운 스키마인 파일은 오류와 원문을 먼저 보여주고 `새 형식으로 덮어쓰기`
   확인 전에는 편집기를 보여주지 않아야 한다. 심볼릭 링크라면 덮어쓰기 버튼 없이 파일 시스템에서
   정리한 뒤 다시 불러오라고 안내해야 한다.
