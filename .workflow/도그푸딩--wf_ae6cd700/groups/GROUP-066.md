# 품질 확인 화면에 기능 소개 문단만 보여주기

품질 확인 목록의 기능 카드에 기능 소개 문단만 최대 세 줄로 실린다. 지금처럼 작업 분해 근거나
품질 확인 방식 설명이 카드에 따라 들어오지 않고, 절 제목에 쓰인 우물 정 기호도 글자 그대로
보이지 않는다. 카드 높이가 기능마다 같아져서 확인 대기 목록을 위에서 아래로 훑는 것만으로 어떤
기능이 올라와 있는지 알 수 있다.

시작을 눌러 들어간 확인 화면의 머리말과 완료 기록 화면의 기능 상세도 같은 소개 문단을 보여준다.
이 두 자리에서는 줄 수를 제한하지 않고 문단 구분을 살려서 그린다.

확인 동선은 지금과 같다. 사용자 확인 절차는 시작을 눌러야 열리고, 목록 카드에는 확인 절차의
어떤 부분도 실리지 않는다.

## 품질 확인 방식

사용자 확인으로 둔다. 이 그룹이 바꾸는 것은 전부 사용자가 화면에서 직접 보는 결과다. 카드에
무엇이 실리는지, 카드 높이가 고른지, 기능을 열었을 때 소개가 어떻게 보이는지는 저장소를 열지
않고도 앱 화면만으로 판단할 수 있다.

확인에 필요한 자료도 이미 저장소에 있다. 소개 뒤에 내부 절을 둔 기능 문서와 두지 않은 기능
문서가 함께 있고, 소개가 한 문단인 기능과 여러 문단인 기능도 함께 있다. 사용자가 따로 상태를
만들지 않아도 확인 대기 목록에서 두 형태를 모두 만난다.

기획서의 완료 판정 기준 일곱 항목 중 여섯이 화면에서 눈으로 확인된다. 나머지 하나는 기존 기능
문서가 이 변경 전후로 같아야 한다는 항목이며, 그것은 두 작업 모두 문서 파일을 고치지 않는다는
완료 조건과 자동 검증이 맡는다.

## 작업 구성

작업 둘로 나눴다. 경계는 기획서의 요구 묶음이 아니라 저장소에서 함께 움직여야 하는 코드 단위로
잡았다.

첫 작업이 값을 맡는다. 앱이 기능 문서 본문에서 무엇을 기능 설명으로 읽어 올지 정하는 규칙
하나다. 기획서의 R1과 R5, 그리고 문서를 고치지 않는다는 R7이 여기에 속한다. 소개를 찾는 두
단계 기준과, 뽑은 소개를 문단 단위로 정리하는 일을 한 함수 안에서 함께 처리한다. 이 둘을 나누지
않은 이유는 정리 결과가 곧 문단 구분을 화면까지 실어 나르는 수단이기 때문이다. 값 하나를 두
작업이 나눠 만들면 그 사이 상태가 무엇인지 아무도 설명할 수 없다.

둘째 작업이 표시를 맡는다. 카드의 줄 수 상한과 상세 자리의 문단 구분이다. R2와 R3이 여기에
속한다. 확인해 보니 세 화면이 모두 같은 두 가지 스타일 클래스를 이미 붙이고 있어서, 화면 구성
파일은 한 줄도 고치지 않고 스타일 선언 두 개만 고치면 된다. R4와 R6은 두 작업 중 어느 쪽도
새로 만들지 않는다. 절 제목이 글자 그대로 보이지 않는 것은 첫 작업이 값에서 절을 빼면 그대로
성립하고, 확인 절차가 시작을 눌러야 열리는 동선은 지금 코드가 이미 그렇게 되어 있어 두 작업
모두 건드리지 않는다.

두 작업 사이에는 순서를 두지 않았다. 파일이 겹치지 않고, 어느 쪽이 먼저 끝나도 화면이 지금보다
나빠지지 않기 때문이다. 둘째 작업만 끝난 상태에서는 카드가 지금 값 그대로 세 줄에서 끊긴다.
분량이 줄어드는 만큼 지금보다 낫고, 첫 작업이 끝나면 그 세 줄에 소개만 담긴다. 첫 작업만 끝난
상태에서는 카드에 소개만 실리되 줄 수 상한이 아직 없다.

첫 작업에는 이 그룹 밖의 순서가 붙는다. 이 작업이 고치는 저장소 읽기 파일을 GROUP-065와
GROUP-063의 작업 셋이 먼저 고치고 있어서, 그 셋 뒤에 두었다. 둘째 작업은 그 셋과 파일이 겹치지
않으므로 지금 바로 시작할 수 있다.

## 이번 그룹이 다루지 않는 것

아키텍트가 기능 문서를 쓸 때 소개를 어느 절에 쓸지 정하는 작성 지침은 바꾸지 않는다. 지금
지침이 그것을 지정하지 않아 두 형태가 함께 존재하지만, 이번 표시 규칙이 두 형태를 모두 받아
주므로 이번 승인에 묶을 이유가 없다. 기획서도 같은 판단을 제외 범위로 적었다.

소개 안에 굵게 표시 같은 다른 마크다운 기호가 들어 있을 때 그것을 서식으로 그리는 일도 다루지
않는다. 기획서는 절 제목 기호가 글자 그대로 보이지 않을 것만 요구한다. 저장소의 기능 문서 62건을
확인한 결과 소개 안에 목록이나 인용이나 표를 쓴 문서는 하나도 없어, 지금 이 판단으로 잘못
보이는 기능은 없다.

### QA-01 · 확인 대기 목록과 확인 화면에서 기능 소개 읽기

1. 앱에서 품질 확인 화면을 연다.
   > 확인 대기 목록에 기능 카드가 세로로 늘어서고, 카드마다 기능 이름 아래에 소개 문단이 최대
   > 세 줄로 보인다.
2. 목록을 위에서 아래로 훑으면서 카드 높이를 비교한다.
   > 소개가 긴 기능이든 짧은 기능이든 카드 높이가 서로 같다. 소개가 세 줄을 넘는 카드는 끝이
   > 말줄임으로 끊겨 있어 뒤에 더 있다는 것이 보인다.
3. 카드에 실린 소개 문장을 처음부터 끝까지 읽는다.
   > 그 기능이 무엇인지 설명하는 문장만 있다. 작업을 어떻게 나눴는지나 품질 확인을 어떤 방식으로
   > 하는지 설명하는 대목은 어느 카드에도 없다.
4. 카드에 우물 정 기호가 문장 사이에 섞여 있는지 살펴본다.
   > 우물 정 기호로 시작하는 제목 줄이 글자 그대로 보이는 카드가 하나도 없다.
5. 카드 하나에서 시작을 누른다.
   > 확인 화면이 열리고, 머리말에 그 기능의 소개 문단이 잘리지 않고 전부 보인다. 소개가 여러
   > 문단인 기능이면 문단 사이가 벌어져 구분되어 보인다.
6. 확인 화면의 머리말을 끝까지 읽고 그 아래 확인 절차로 넘어간다.
   > 머리말에도 작업 분해 근거나 품질 확인 방식 설명은 없다. 확인 절차는 시작을 누른 지금에야
   > 열려 있고, 목록으로 돌아가면 카드에는 그 절차가 보이지 않는다.
7. 확인을 마친 뒤 완료 기록 화면을 열고 기록된 기능 하나를 펼친다.
   > 기능 상세에 소개 문단이 확인 화면 머리말과 같은 기준으로 보인다. 줄 수 제한 없이 전부
   > 보이고 문단 구분이 살아 있으며, 내부 절은 여기에도 없다.
