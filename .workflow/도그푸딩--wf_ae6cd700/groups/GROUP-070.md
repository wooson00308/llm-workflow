# 앱 업데이트 직후에도 복구와 업데이트 적용이 끝까지 진행되게 하기

## 기능 설명

앱을 새 버전으로 올린 직후에도 복구 계획과 업데이트 계획을 한 번 적용하면 실행 환경이 정상 상태로
돌아온다. 지금은 두 경로가 실행 환경 파일이 버전 자리에 이미 놓여 있다고 전제하기 때문에, 앱만
올라가고 파일은 아직 놓이지 않은 기기에서 적용이 끝까지 진행되지 않는다.

이번 변경으로 복구 적용과 업데이트 적용은 시작할 때 버전 자리를 먼저 확인한다. 앱에 실린 버전의
파일이 그 자리에 없으면 설치 적용과 같은 검증을 거쳐 파일을 놓은 뒤 실행기 전환과 서비스 처리를
이어 간다. 파일이 이미 있으면 그 자리를 그대로 쓰고 지금과 같은 단계만 밟는다.

같은 경로를 쓰는 자리가 하나 더 있다. 앱은 앱에 실린 실행 환경이 설치본보다 새 버전이면, 실행 중인
작업이 없을 때 사용자가 누르지 않아도 갱신을 한 번 시도한다. 그 자동 갱신도 지금은 같은 이유로
끝까지 가지 못하므로, 이번 변경으로 함께 정상화된다. 그래서 앱을 올린 사용자는 대개 아무것도 누르지
않아도 실행 환경이 새 버전을 따라오는 것을 보게 되고, 실행 중인 작업 때문에 자동 갱신이 미뤄진
기기에서는 복구 계획을 한 번 적용하는 것으로 같은 결과에 이른다.

계획을 만드는 단계는 지금과 같이 버전 자리를 바꾸지 않는다. 버전 자리가 비어 있는 기기에서도
계획이 만들어지고, 만들지 못하는 경우에는 빈 계획 대신 사유를 담은 실패가 돌아온다.

적용 절차 자체는 달라지지 않는다. 계획을 먼저 보여주고 확인받은 뒤에만 적용하는 순서, 단계 이름과
수행 순서, 부분 실패를 부분 실패로 돌려주는 처리, 오래된 계획을 거절하는 처리, 내려받기 적용의
동작이 모두 그대로다. 데이터베이스와 프로젝트 설정 파일은 이 경로에서 여전히 열지 않는다.

## 품질 확인 방식

사용자 확인으로 둔다. 이 그룹이 고치는 실패는 사용자가 화면에서 직접 만나는 실패다. 앱을 새 버전으로
올린 기기에서 설치된 버전이 앱에 실린 버전을 따라오는지, 복구 버튼을 한 번 눌러 적용했을 때 실행
환경 상태가 정상으로 바뀌는지는 저장소를 열지 않고 앱 화면만으로 판단할 수 있다.

확인에 필요한 상태도 따로 만들 필요가 없다. 앱 배포물에 새 실행 환경 버전이 실릴 때마다 그 앱을
받은 기기가 반드시 이 상태를 한 번 지난다. 2026-08-18 macOS에서 앱을 0.1.22로 올린 뒤 실제로 이
상태를 만났고, 그때 복구가 진행되지 않는 것이 실측으로 확인되어 있다.

기획서의 수용 기준 다섯 중 셋은 화면에서 눈으로 확인된다. 복구 계획 한 번으로 실행 환경이 정상이
된다는 REQ-01의 기준, 복구와 업데이트 어느 쪽을 적용해도 결과가 같다는 REQ-02의 기준, 버전 자리가
비어 있어도 계획 확인 창이 열린다는 REQ-04의 기준이다. 나머지 둘은 눈으로 가릴 수 없다. 파일이 이미
있는 기기에서 적용이 돌려주는 단계 목록과 결과가 변경 전후로 같아야 한다는 REQ-03의 기준과, 단계
이름·수행 순서·거절 처리가 그대로여야 한다는 REQ-05의 기준은 작업의 완료 조건과 자동 검사가 맡는다.
계획을 여는 시점에 버전 자리가 아직 변하지 않았다는 사실도 자동 검사가 맡는다.

## 작업 구성

작업 하나로 뒀다. 고쳐야 할 자리가 한 곳이기 때문이다. 복구 적용은 업데이트 적용을 그대로 부르는 한
줄이어서 두 경로가 같은 함수 하나를 지나고, 기획서가 요구하는 버전 자리 확인과 파일 놓기는 모두 그
함수가 런타임을 부르기 직전에 들어간다. 계획 경로가 버전 자리를 바꾸지 않는다는 요구도 같은 파일의
같은 시험 묶음이 지킨다. 둘로 나누면 같은 파일을 두 작업이 고치게 되어 순서만 붙고 병렬로 얻는 것이
없다.

그룹 밖 순서도 붙지 않는다. 지금 끝나지 않은 다른 작업 가운데 이 작업이 선언한 파일을 선언한 것이
하나도 없다. 적용 결과를 화면에 보여주는 작업들은 화면 파일만 고치고, 이 작업은 백엔드 파일 하나만
고친다. 두 쪽은 같은 값을 서로 다른 자리에서 다루므로 어느 쪽이 먼저 들어가도 상관없다.

## 이번 그룹이 다루지 않는 것

적용 결과를 단계별로 화면에 보여주는 일과 실패 사유를 사용자 언어로 표시하는 일은 다루지 않는다.
SPEC-068이 그 자리를 맡고 있고, 기획서와 그 출처 아이디어가 같은 판단을 적었다. 그래서 이번 변경만
들어간 상태에서 적용이 실패로 끝나면 사용자는 여전히 사유를 읽지 못한다. 두 그룹이 모두 반영되면
그 공백도 사라진다.

적용이 실패한 뒤의 자동 재시도와 자동 복구도 다루지 않는다. 실행 환경 계약과 단계 이름, 단계 수행
순서, 내려받기 적용의 동작, 복구 필요와 업데이트 가능을 고르는 판정 규칙도 그대로 둔다.

실행기 자체가 없거나 부를 수 없는 기기의 복구도 다루지 않는다. 이번 기획서가 고치는 것은 버전
자리가 비어 있는 경우 하나다.

### QA-01 · 앱을 새 버전으로 올린 뒤 실행 환경이 되살아나는지 확인하기

1. 실행 환경 새 버전이 함께 실린 앱 배포물로 앱을 올린 뒤 앱을 열고 에이전트 화면을 연다.
   > 화면이 열리고 실행 환경 자리가 보인다.
2. 실행 환경 자리에서 앱에 포함된 버전과 설치된 버전을 나란히 읽는다. 곧바로 갈려 있으면 잠시 뒤 다시 읽는다.
   > 두 값이 같아진다. 앱을 올린 것만으로 설치된 버전이 새 버전을 따라왔다.
3. 실행 환경 상태 문구와 자동 배정 서비스 자리를 읽는다.
   > 실행 환경이 정상이라고 적혀 있고, 자동 배정이 연결 필요나 복구 필요로 남아 있지 않다.
4. 상태 문구가 아직 복구나 재시작이 필요하다고 말하면 그 자리의 복구 계획 버튼을 누른다. 이미 정상이면 이 단계와 다음 단계를 건너뛴다.
   > 확인 창이 열리고 무엇을 하려는지가 적혀 있다. 창이 열리지 않거나 내용이 없는 계획이 나오는 일은 없다.
5. 확인 창에서 적용을 누른 뒤 실행 환경 상태를 다시 읽는다.
   > 적용이 끝나고 상태가 정상으로 바뀐다. 설치 절차를 손으로 다시 밟지 않았다.
6. 프로젝트 하나에서 자동 배정이 새 실행을 집어 가는지 확인한다.
   > 앱을 올리기 전과 같이 자동 배정이 동작한다.
