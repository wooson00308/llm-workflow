# 에이전트 실행 기록을 사용자 요약과 진단 번들로 재설계한다

## 기능 설명

기존 개발 작업을 기획서 기준의 작업 그룹으로 전환했습니다.

### QA-01 · 런타임 도구 이벤트에 도구 이름만 싣는다

이 작업에는 눈으로 볼 화면이 없다. 도구 이름을 화면에 집계로 보여 주는 일은 다음 작업이 맡고, 이 작업은
런타임 기록에 이름을 남기는 데까지만 책임진다. 그래서 확인은 자동 검사로 닫았고, 확인 도장은 아래 숫자를
믿는다는 뜻이다.

직접 다시 돌려 보려면 `../../Git/claude-heartbeat`에서 다음을 실행한다.

  뽑히는지, 이름이 없으면 필드가 비는지, 이름이 있는 이벤트와 없는 이벤트가 섞여도 정규화가 실패하지
  않는지 확인한다.
  이름이 보존되는지, 이름이 없는 기록도 그대로 읽히는지 확인한다.
  전과 같다.

민감정보가 남지 않는지는 `test_stored_events_keep_the_tool_name_and_nothing_the_tool_was_given`가 확인한다.
이 검사는 도구 사용 블록의 입력에 가짜 인증 값과 가짜 명령 문자열을 넣고 저장까지 지나게 한 뒤, 저장된
이벤트 전체와 이벤트 파일과 데이터베이스 파일 원본에서 그 문자열과 블록 식별자를 찾아 없음을 단언한다.

### QA-02 · 실행과 결과 보고서를 잇는 읽기 전용 백엔드 표면을 만든다

이 작업은 백엔드 조회만 만들었고 사용자가 열어 볼 화면은 만들지 않았다. 실행 요약에서 보고서를 여는
화면은 뒤따르는 작업이 붙인다. 그래서 이번 확인에는 눌러 볼 자리가 없고, 확인 도장은 아래 자동 검사
결과를 신뢰한다는 뜻이다.

검사를 직접 돌려 확인하려면 프로젝트 루트에서 다음 두 명령을 실행한다.

  기대 결과: 실패 0건. 라이브러리 검사 732건과 통합 검사 20건이 통과한다.
  기대 결과: 경고 0건.

이번 작업이 새로 더한 검사만 보려면 다음 명령을 실행한다.

  기대 결과: 7건 통과. 보고서 목록이 개수 집계와 일치하는지, 대상 문서 식별자만 있을 때와 예약 결과
  접두어만 있을 때와 둘 다 있을 때 연결이 각각 맞는지, 두 값이 모두 없으면 빈 목록이 나오는지,
  본문이 그대로 나오고 파일이 변경되지 않는지, 디렉터리를 벗어나는 파일 이름이 거절되는지를 확인한다.
  기대 결과: 라이브러리 1건과 통합 1건이 통과한다. 예약 결과 접두어가 있는 실행 행과 없는 실행 행이
  모두 오류 없이 읽히고, 없는 쪽은 값이 비어 있다.

결정 요청에 적힌 "결과를 남긴 실행과 남기지 않은 실행"의 구분은 위 검사 중 연결 판정 4건이 확인한다.
남기지 않은 쪽에 다른 실행의 보고서가 섞이지 않는지도 그 검사가 함께 확인한다.

### QA-03 · 실행 상세를 이벤트 나열에서 요약 카드와 이상 신호로 바꾼다

에이전트 화면에서 실행 하나를 눌러 오른쪽 상세 서랍을 연다. 서랍 맨 위에 요약 카드 하나가 있고, 그 아래에
줄이 몇 개만 남는다.

1. 도구를 여러 번 쓴 실행을 연다. 개별 도구 줄과 진행 줄이 하나도 보이지 않고, 카드의 `도구 사용` 칸에
   `총 N회`와 `파일 읽기 3` 같은 유형별 칩이 보인다. N이 그 실행이 실제로 쓴 도구 횟수와 같은지 본다.
   유형별 칩의 숫자를 모두 더하면 N이 된다.
2. 같은 카드에서 `대상`·`역할`·`시작`·`경과`(끝난 실행은 `소요`)·`상태`·`사유`·`마지막 활동`이 그 실행의
   현재 사실과 맞는지 본다. 진행 중, 완료, 실패, 취소, 복구 필요 실행을 각각 하나씩 열어 확인한다.
3. 활동 없음 신호: 진행 중인 실행을 열어 둔 채 5분 이상 새 이벤트가 오지 않으면 줄 목록에
   `활동 없음 · N분째 조용함`이 나타난다. 그 실행이 다시 움직이면 이 줄이 사라지고 `마지막 활동` 시각이
   갱신된다. 이때 `상태`는 계속 `진행 중`이며 실패나 취소로 바뀌지 않는다. 상세를 닫으면 이어 읽기가 멈춘다.
4. 실패한 실행을 연다. `실패` 줄 아래에 런타임이 준 문장이 그대로 보이고 성공 요약이나 짧은 안내 문구로
   바뀌지 않는다. 문장 안에 토큰이나 비밀번호 형태의 값이 있으면 그 자리만 `[민감정보 제거됨]`으로 보인다.
5. 실행 기록을 읽지 못하는 상황에서는 `도구 사용`과 `마지막 활동`이 `모름`으로 보이고, 직전에 열었던 다른
   실행의 숫자가 그대로 남지 않는다.
6. 알지 못하는 도구 이름은 `기타`로, 도구 이름이 없는 옛 기록은 `이름 없음`으로 묶여 보이고, 도구 이름
   원문은 화면 어디에도 나타나지 않는다.

집계 계산과 시각 계산, 신호 판정, 이어 읽기의 시작과 정지는 자동 검사로 닫았다. 위 1~6은 화면에서 눈으로
확인할 수 있는 부분이고, 확인 도장은 그 화면과 아래 보고서의 검사 수치를 함께 믿는다는 뜻이다.

### QA-04 · 실행 요약에서 결과 보고서를 열어 읽는 길을 만든다

1. 에이전트 화면에서 보고서를 남긴 실행을 선택해 상세를 연다. 요약 카드에 「결과 보고서」 항목이 나타나고 그 실행이
   남긴 보고서 제목이 단추로 보이면 맞다. 이 저장소에서는 최근 종료 목록의 개발 작업 실행이 그런 실행이다.
2. 그 보고서 제목을 누른다. 앱 안에 보고서 화면이 열리고 파일에 적힌 본문이 그대로 보이면 맞다. 화면에 입력 칸과
   저장·수정·삭제 단추가 하나도 없어야 한다. 본문을 아직 읽는 중이면 「보고서를 읽는 중입니다」가, 읽지 못했으면
   「보고서를 읽지 못했습니다」와 그 사유가 보인다. 어느 경우에도 빈 본문이 대신 보이지 않는다.
3. Escape를 누른다. 보고서 화면만 닫히고 실행 상세는 그대로 열려 있으면 맞다. 한 번 더 누르면 상세가 닫힌다.
4. 보고서를 남기지 않은 실행의 상세를 연다. 「결과 보고서」 항목 자체가 나타나지 않고, 방금 본 다른 실행의 보고서
   제목이 이 카드에 남아 있지 않으면 맞다.
5. 보고서를 열어 본 뒤 파일이 그대로인지 확인한다. 프로젝트 루트에서 `git status`를 실행했을 때 `.workflow`의
   보고서 파일이 변경 목록에 새로 올라오지 않으면 맞다.

### QA-05 · 실행 하나를 진단 번들로 저장하거나 복사한다

1. 에이전트 화면을 열고 `진행 중` 또는 `최근 종료` 목록에서 실행 하나를 눌러 실행 상세를 연다.
   이 시점에는 아직 아무것도 나가지 않아야 한다. 상세를 열기만 했을 때 저장 대화상자가 뜨거나
   내보내기 문구가 보이면 잘못된 것이다.
2. 상세 아래쪽 `진단 자료 저장`을 누른다. 저장 대화상자가 뜨고 기본 파일 이름이
   `<실행 ID>-diagnostics.json`이다. 위치를 고르면 `진단 자료를 파일에 담았습니다.`가 뜬다.
3. 같은 자리에서 `진단 자료 저장`을 다시 누르고 이번에는 대화상자를 취소한다. 파일이 만들어지지
   않고 화면에도 아무 문구가 남지 않아야 한다.
4. `진단 자료 복사`를 누른다. 대화상자 없이 `진단 자료를 클립보드에 담았습니다.`가 뜬다. 편집기에
   붙여 넣으면 2번에서 저장한 파일과 같은 `bundleVersion`과 같은 `runId`, 같은 실행 내용이 보인다.
   `generatedAt`만 다르다.
5. 저장한 파일을 열어 다음을 확인한다. 실행 식별자, 프로젝트, 대상 문서, 역할, provider와
   `providerVersion`, 상태, `failureStage`, 사유 코드, 시작과 종료 시각이 들어 있고, `events`에
   런타임이 저장한 순서 그대로 이벤트가 실려 있다. 이벤트가 200건을 넘는 실행에서도 뒤쪽이 잘리지
   않아야 한다.
6. 같은 파일에서 작업 지시, 프롬프트, 인증 값, 환경 변수, 도구 인자, 도구 결과 본문이 없는지 본다.
   `toolArgs`, `toolResult`, `prompt`, `env`, `apiKey` 같은 열쇠가 하나도 나오면 안 된다.
7. 진행 중인 실행과 종료된 실행 양쪽에서 2번과 4번이 모두 동작하는지 확인한다.
8. provider 진단을 읽지 못하는 상태(예: 실행 도구 미설치)에서도 내보내기가 되고, 파일의
   `unavailable`에 읽지 못한 항목 이름과 사유가 적히는지 확인한다.

자동 검사로 닫은 부분은 다음과 같다. 번들 조립·이어 읽기·읽지 못한 항목 기록·가짜 문자열 주입은
확인했다. 위 1~8번은 실제 런타임과 파일 대화상자가 있어야 하는 부분이라 사람이 본다.
