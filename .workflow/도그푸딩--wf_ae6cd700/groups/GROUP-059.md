# 끝난 작업 그룹을 개발 작업 화면 전체에서 감춘다

개발 작업 화면이 아직 끝나지 않은 일만 다룬다. 품질 확인을 통과했거나 자동 확인으로 닫힌 작업
그룹의 작업은 보드의 작업 그룹별 보기, 보드의 평면 보기, 리스트 어디에도 나오지 않는다. 화면
머리의 진행 중 수치와 요약 띠의 진행 중·막힘·완료 수치, 표시 건수도 남은 작업만 센다. 감춘
그룹이 있으면 그 개수와 기록 화면에서 볼 수 있다는 안내를 화면이 알려 준다. 타임라인 보기와 기록
화면, 작업 상세 화면은 지금 그대로 둔다.

## 품질 확인 방식

이 그룹은 사용자 품질 확인으로 완료한다. 바뀌는 것이 개발 작업 화면에서 사용자가 직접 보는 목록과
수치이므로, 화면을 열어 보기를 바꿔 가며 같은 작업만 나오는지 확인하는 것이 유일하게 의미 있는
검증이다.

## 작업 구성

작업 하나로 구성했다. 끝난 그룹에 속한 작업을 가려내는 판단, 그 결과를 쓰는 목록과 수치, 감춘
그룹 수를 알리는 안내가 모두 개발 작업 화면 한 컴포넌트 안에서 만들어지고 소비된다. 감춘 그룹
수는 감춤 판단이 만드는 값과 같은 계산에서 나오므로, 나눠도 병렬로 진행할 수 없고 같은 값을 두
세션이 다시 유도하게 된다.

### QA-01 · 개발 작업 화면에서 끝난 일이 사라졌는지 확인한다

1. 개발 작업 화면을 연다.
   > 목록에 남아 있는 작업 그룹은 아직 품질 확인을 기다리거나 개발이 남은 그룹뿐이다. 이미 확인이
   > 끝난 그룹은 보이지 않는다.
2. 보기를 평면 보기로 바꾼다.
   > 방금 작업 그룹별 보기에서 본 작업과 똑같은 작업만 나온다. 끝난 그룹의 작업이 다시 나타나지
   > 않는다.
3. 보기를 리스트로 바꾼다.
   > 여기서도 같은 작업만 나온다. 세 보기의 목록이 서로 어긋나지 않는다.
4. 화면 위의 진행 중·막힘·완료 수치와 표시 건수를 읽는다.
   > 끝난 그룹의 작업을 뺀 값이다. 완료 칸이 그동안 쌓인 총계가 아니라 지금 흐름에서 끝낸 양을
   > 가리킨다.
5. 검색창에 이미 끝난 그룹에 속한 작업의 제목 일부를 넣는다.
   > 보드와 리스트 어디에도 그 작업이 나오지 않는다. 상태 필터를 바꿔도 마찬가지다.
6. 목록 아래 안내 문구를 읽는다.
   > 감춘 작업 그룹이 몇 개인지와 그 그룹들을 기록 화면에서 볼 수 있다는 안내가 보인다.
7. 보기를 타임라인으로 바꾼다.
   > 변경 전과 똑같이 지나간 달의 이력까지 그대로 보인다.
8. 기록 화면을 열어 끝난 작업 그룹 하나를 펼친다.
   > 확인 방식, 구성 버전, 사용자 확인 플로우, 포함된 작업 목록이 변경 전과 같이 보인다.
