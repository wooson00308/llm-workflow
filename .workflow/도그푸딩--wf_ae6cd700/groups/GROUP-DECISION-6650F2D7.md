# 프로젝트를 열 때 관리 규칙을 최신 상태로 맞춘다

## 기능 설명

기존 개발 작업을 기획서 기준의 작업 그룹으로 전환했습니다.

### QA-01 · 모든 관리 자산을 검사한 뒤 한 번의 명령으로 동기화한다

이 작업은 화면 변경이 없는 백엔드 계약 작업이다. 별도 동기화 명령의 화면 연결과 상태 표시는
후속 TASK-133과 TASK-134가 담당한다.

1. 자동 검사에서 전체 Rust 테스트 562개가 통과했는지 확인한다.
2. 포맷 검사와 모든 대상의 정적 검사가 경고 없이 통과했는지 확인한다.
3. 순차 저장 중 후속 변경 복원과 일곱 자산의 비 UTF-8 충돌 회귀 검사가 계속 포함됐다.
4. 열린 파일 핸들의 격리 후 쓰기, 원래 없던 경로의 외부 재생성, 두 복원 실패 후의 나머지 복원을 자동 검사가 재현한다.
5. 열린 핸들 경합으로 남긴 복구본의 위치가 기존 생성·결정·단건 QA·일괄 QA 오류에도 전달되는지 확인한다.
6. 사용자 확인 도장은 이 수치와 백엔드 계약을 승인한다는 뜻이다.

### QA-02 · 열기와 수동 새로 고침에서만 관리 규칙을 동기화한다

1. 현재 문서 규격 프로젝트를 폴더 선택과 최근 프로젝트 목록에서 각각 열면 프로젝트가 먼저 표시되고
   관리 규칙 동기화가 한 번 실행된다.
2. 상단 새로 고침을 누르면 프로젝트 조회 뒤 동기화가 한 번 더 실행되며, 두 단계가 끝날 때까지 진행
   표시가 유지된다.
3. 충돌이나 잠금 재시도, 명령 오류가 발생해도 열린 프로젝트와 최근 프로젝트 기록이 사라지지 않는다.
4. 자동 검사에서 2.5초 조회를 세 번 진행해도 동기화 호출은 추가되지 않고 마지막 결과가 유지됐다.
   격리 계약을 승인한다는 뜻이다.

### QA-03 · 설정에서 관리 규칙 버전과 마지막 동기화 결과를 보여준다

1. 개발 앱에서 이 저장소를 연 뒤 사이드바 아래 `설정`을 누른다. `현재 프로젝트` 카드와 별도로
   `관리 규칙` 카드가 보이고, 상태 줄에 `현재 상태` 또는 `갱신됨`이 표시된다.
2. 카드의 자산 목록에서 역할 계약 세 줄이 각자의 숫자를 그대로 보여주는지 확인한다. 이 커밋 시점의
   앱 제공 값은 공통 규칙 14, 기획자 9, 아키텍트 8, 개발자 9다. 세 역할을 하나의 숫자로 합쳐 보이면
   잘못된 것이다. `AGENTS 진입 안내`와 `CLAUDE 진입 안내`는 숫자 대신 `버전을 쓰지 않는 자산`으로
   표시돼야 한다.
3. 상단 새로 고침 버튼을 누른다. 카드의 `마지막 동기화` 값이 `수동 새로 고침`으로 바뀐다.
4. 충돌 재현: 편집기로 `.workflow/rules/roles/architect.md`의 `rules_version: 8`을
   `rules_version: 99`로 바꾸고 저장한 뒤 상단 새로 고침을 누른다.
   - 화면 위쪽에 `관리 규칙 충돌: 아키텍트 역할 계약` 알림이 뜨고, 프로젝트 오류 배너와 다른 색·다른
     문구로 보인다.
   - 알림이 있는 상태에서 사이드바의 `아이디어`, `개발`, `설정` 이동과 설정 카드의
     `다른 프로젝트 열기` 버튼이 그대로 동작한다.
   - 설정의 관리 규칙 카드에서 아키텍트 행이 `충돌`로 표시되고 백엔드가 준 이유 문장이 함께 보인다.
   - 알림이 뜬 채로 10초 이상 그대로 둔다. 2.5초 자동 조회가 여러 번 돌아도 알림과 카드 내용이
     사라지지 않아야 한다.
   - 확인이 끝나면 `rules_version: 99`를 원래 값 `8`로 되돌리고 새로 고침을 눌러 상태가 정상으로
     돌아오는지 본다.
5. 카드 아래 안내 문장이 "다음에 시작하는 에이전트 세션부터 적용된다"고 말하는지, 실행 중인 세션에
   적용됐다는 문장은 없는지 확인한다.
6. 자동 검사로 확인한 항목: 네 결과 상태의 문구 구분, 역할별 버전 표시, 충돌 자산 이름과 이유,
