# 사용 한도 보류가 이미 정해진 해제 시각보다 일찍 풀리지 않게 하기

## 기능 설명

실행 도구의 사용 한도 보류 기록을 다시 쓸 때, 이미 걸려 있는 보류의 해제 시각보다 이른 시각으로
보류를 줄이지 않는다.

지금은 같은 실행 도구에서 한도 종료가 다시 확인되면 새 값이 앞 값을 그대로 덮는다. 나중 실행이 해제
예정 시각을 싣지 못하면 종료 시각에서 한 시간 뒤라는 추정값이 대신 들어가고, 앞서 적혀 있던 더 늦은
실제 해제 시각이 사라진다. 그러면 보류가 실제보다 일찍 풀려서 아직 한도가 남은 도구에 자동 배정이
다시 들어가고, 그 세션들은 시작하자마자 같은 이유로 끝난다.

이번 변경은 두 자리를 고친다. 첫째, 보류 기록을 쓰는 자리가 이미 있는 기록의 해제 시각을 먼저
읽는다. 그 시각이 아직 지나지 않았고 새로 정한 시각보다 늦거나 같으면 파일을 다시 쓰지 않는다. 새로
정한 시각이 더 늦으면 그 시각까지 보류를 연장한다. 해제 시각이 이미 지난 기록은 보류가 아니므로 새
한도 종료가 그 자리를 대신한다.

둘째, 한 번의 실행 목록 확인에서 같은 실행 도구의 한도 종료가 여럿 보일 때 그 가운데 가장 늦은 해제
시각이 보류가 되게 한다. 지금은 가장 늦게 끝난 실행 하나만 골라 기록에 보내므로, 먼저 끝난 실행이
실어 온 더 늦은 실제 해제 시각이 파일에 닿지 못한다. 덮어쓰기와는 원인이 다르지만 사용자가 겪는
결과는 같다.

기존 시각을 유지할 때는 파일을 다시 쓰지 않는다. 그래서 기록에 남는 실행 식별자와 기록 시각, 그리고
실제 해제 시각인지 추정값인지를 구분하는 값은 지금 걸려 있는 보류를 만든 실행의 값으로 남는다.

기록의 형식과 놓이는 자리, 보류 판정, 화면 표시, 자동 배정 설정값, 역할·실행 도구 대응표는 바뀌지
않는다. 같은 실행이 다시 확인될 때 보류를 연장하지 않는 지금 규칙도 그대로 둔다. 화면이 같은 실행
행을 2.5초마다 다시 보내기 때문에 있는 규칙이다.

## 품질 확인 방식

이 그룹은 자동 검증으로 완료한다. GROUP-071과 같은 이유다.

이 기능이 반응하는 입력은 실행 기록에 실린 한도 도달 구분값과 해제 예정 시각인데, 그 값을 만들어
싣는 일은 아직 실행 환경 쪽에서 하지 않는다. 저장소를 확인해 보니 실행 환경 자산과 스크립트 어디에도
그 구분값을 내보내는 자리가 없다. 즉 이 그룹의 작업이 반영된 뒤에도 사용자의 기기에서는 보류가 한
번도 걸리지 않는다. 사용자에게 보류 화면을 열어 확인해 달라고 요구하면 만들어 낼 수 없는 상태를
확인해 달라는 요청이 되고, 실제로 계정 한도를 소진해 재현하는 방법은 확인 절차로 삼을 수 없다.

기획서의 인수 조건 열 가운데 아홉이 이 상태를 전제한다. 남는 하나인 열째 조건은 역할·실행 도구
대응표 파일의 본문이 변경 전후로 같아야 한다는 것인데, 파일 본문을 비교하는 일은 개발자가 아닌
사람이 화면에서 할 수 있는 확인이 아니다.

그래서 열 조건을 모두 자동 검증이 덮는다. 어느 인수 조건을 어느 검사가 덮는지는 작업 문서의 완료
조건에 조건 번호로 적었다.

## 작업 구성

작업을 하나로 둔다.

고칠 자리는 보류 기록을 쓰는 함수와, 그 함수에 어느 실행 행을 보낼지 고르는 함수 둘이다. 두 함수는
서로 다른 파일에 있지만 한 판정을 나눠 갖고 있어서, 한쪽만 고치면 기획서가 요구하는 결과가 나오지
않는다. 고르는 쪽만 고쳐서 같은 도구의 한도 종료를 여럿 보내면, 쓰는 쪽이 아직 덮어쓰기를 하므로
마지막에 도착한 행의 값이 남는다. 어느 행이 마지막인지는 기획서가 정한 기준과 아무 관계가 없다.
그래서 두 자리를 한 작업에서 함께 고친다.

작업이 하나이므로 그룹 안의 순서는 없다. 이 그룹을 짤 때 이 워크플로의 개발 작업은 모두 확인 완료
상태였고, 이 작업이 고치는 두 파일을 잡고 있는 다른 작업이 없어서 그룹 밖 순서도 붙이지 않았다.

## 이번 그룹이 다루지 않는 것

해제 예정 시각을 실행 기록에 실어 보내는 실행 환경 쪽 작업은 다루지 않는다. SPEC-071이 후속으로
넘긴 그대로다. 해제 예정 시각이 없을 때 쓰는 추정 대기 시간의 값 자체를 조정하는 일도 다루지 않는다.

역할·실행 도구 대응표의 기록 순서를 바꾸거나 약속 문구를 고치는 일은 다루지 않는다. 기획서가 지금
코드에서는 그 문제가 재현되지 않는다고 확인했고, 이 그룹은 그 자리를 유지 대상으로만 본다.

한도 대기 상태의 화면 문구와 배정 조건 판정 자체, 사용자가 보류를 직접 해제하거나 연장하는 기능,
보류 기록을 여러 기기 사이에 맞추는 일도 다루지 않는다. 만료된 기록을 지우거나 고치는 일도 하지
않는다. 해제 시각이 지나면 보류는 저절로 풀린다.
