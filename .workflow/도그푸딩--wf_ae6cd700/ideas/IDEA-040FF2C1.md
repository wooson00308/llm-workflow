커밋 컷·릴리스 절차에 "PR CI 전 매트릭스 그린 확인 후 병합"을 규범으로 편입하자. 이 저장소는 로컬 게이트(cargo test·fmt·clippy·npm run check) 그린을 컷의 기준으로 써 왔는데, v0.1.9 릴리스에서 로컬 그린이 CI 그린을 보장하지 않는다는 것이 서로 다른 세 경로로 실증됐다.

세 경로 (2026-08-06 실측, PR #19):

1. OS 조건부 컴파일 — 테스트 모듈이 `#[cfg(unix)]`로 갈려 있어 macOS 로컬에서는 윈도우 타깃의 미사용 import·상수(clippy `-D warnings` 에러 4건)가 원리상 잡히지 않는다. 직전 릴리스에서도 같은 패턴이 터져 후속 PR #18로 수습한 전례가 있다.
2. 런타임 버전 차이 — 로컬 node 25에서는 테스트 환경 localStorage 저장이 조용히 무산돼 테스트 격리 누락이 숨었고, CI의 node 22에서는 실제로 저장돼 상태가 새며 3건이 실패했다. 로컬 반복 실행으로는 절대 재현되지 않았다.
3. 플랫폼별 설치 자산 — 대조 테스트 헬퍼가 sh 경로를 하드코딩해 윈도우(ps1만 설치됨)에서 스크립트가 실행조차 안 됐고, 로컬(macOS)에서는 sh가 있으니 통과했다.

셋 다 병합 전에 잡혔지만, 잡힌 이유는 릴리스 세션이 직전 릴리스의 수습 전례(#17이 CI 안 기다리고 병합 → #18 즉시 수습)를 찾아 스스로 CI를 기다렸기 때문이다. 즉 지금 이 안전망은 세션의 재량이지 규범이 아니다.

기획 판단이 필요한 자리:

- 이 규범이 앉을 자리. 컷 절차는 지금 개발 로그의 관례로만 존재한다. 계약 문서(workflow.md)는 세션 일반의 규칙이라 릴리스 절차의 자리가 아닐 수 있고, docs/ 운영 문서 또는 별도 릴리스 체크리스트가 후보다. 어디에 적어야 다음 컷 세션이 반드시 읽게 되는지가 판정 기준.
- 표현. "병합은 PR CI 전 매트릭스 그린 확인 후" 한 줄이 본체이고, 로컬 게이트의 위상(빠른 사전 신호이지 병합 근거가 아님)을 함께 갈라 적을 것.
- 플레이크와의 상호작용. 비결정적 테스트(IDEA-22F8EA3F)가 남아 있는 동안 "그린 확인"이 재실행 도박이 되지 않게, 같은 커밋 재실행의 허용 기준도 한 줄 필요하다.
