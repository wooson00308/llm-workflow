에이전트 실행 로그를 "kind 나열"에서 사람이 읽는 실행 요약과 개발자 전달용 진단 번들로 재설계하자.

배경 (2026-08-12 실측): 실행 하나의 이벤트 스트림이 {started 1, progress 8, tool 22}뿐이고, 화면은 이걸 "kind: tool" 줄로 그대로 나열한다. 런타임이 프롬프트·시크릿 비보존 원칙으로 내용을 의도적으로 버리기 때문에, 이 나열로는 사용자도 개발자도 아무것도 판단할 수 없다.

제안 세 갈래:

1. 화면 로그 = 요약 + 이상 신호. 실행 상세에 이벤트 나열 대신 요약 카드 하나 — 대상 문서, 시작·경과, 결과와 사유 문장, "도구 사용 N회 · 마지막 활동 M초 전" 집계. 개별 줄로 보여줄 것은 시작·종료·실패 detail 전문·"N분간 활동 없음" 정지 신호뿐이다. 판단거리는 로그가 아니라 산출물이므로, 실행이 남긴 리포트 문서 바로가기를 함께 단다 (현재 프로젝트 요약 payload에 reports가 없어 백엔드 표면 추가 필요).

2. 진단 내보내기 버튼. 실행 메타(역할·프로바이더·버전·사유 코드) + 이벤트 원본 JSONL + 런타임 진단 결과 + 최근 에러 기록을 파일 하나로 저장/복사. 이슈가 생기면 사용자는 이 파일만 개발자에게 전달하면 된다. 시크릿 비보존 원칙은 원본이 이미 지키므로 번들도 그대로 유지된다.

3. (런타임, claude-heartbeat) tool 이벤트에 도구 "이름"만 싣기 — 인자 제외. 이름은 고정 어휘라 시크릿 위험이 없고, "tool 22회"가 "파일 편집 9 · 명령 실행 7 · 검색 6"이 된다. NormalizedLine에 tool 필드 추가, claude/codex normalize_line에서 tool_use 블록의 name 추출.
