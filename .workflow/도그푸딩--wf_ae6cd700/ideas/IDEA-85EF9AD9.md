멀쩡한 사용자 확인 절차가 "구성 확인 필요"로 잘못 판정되는 것을 고치고 싶다. 실측 사례는 GROUP-070이다. 확인 동선이 전부 화면을 열고 버튼을 누르고 문구를 읽는 사용자 행동인데도 구성 오류로 떠서 품질 확인을 열 수 없다.

원인은 판정 코드로 재현해 확정했다. 사용자 확인 절차인지 가리는 판정은 본문에 "눈에 보이는 결과"를 뜻하는 낱말 목록이 있는지로 정하는데, 이 목록이 낱말의 특정 활용형만 안다. 예를 들어 목록에 있는 "보이"는 "보이고", "보입니다"에는 맞지만 "보인다"에는 맞지 않는다 — 한글은 음절 단위 글자라 "보인다"에 "보이"라는 문자열이 들어 있지 않기 때문이다. GROUP-070의 기대 문장들("보인다", "적혀 있다", "같아진다", "바뀐다")은 전부 자연스러운 관찰 서술인데 목록의 어떤 낱말과도 겹치지 않아 통째로 탈락했다.

원하는 것: 자연스러운 한국어 관찰 서술이 이 판정을 통과해야 한다. 활용형을 더 넓게 다루든(예: 어간 기준 대조), 낱말 목록을 보강하든, 판정 실패 시 무엇이 부족했는지 그룹 화면에 사유를 보여 주든 — 방식은 기획에서 정한다. 최소한 판정이 왜 떨어졌는지 모른 채 "구성 확인 필요"만 보이는 지금 상태는 벗어나야 한다. 급한 개별 해소로 GROUP-070의 문장을 낱말 목록에 맞춰 고치는 일은 아키텍트 몫의 별도 조치다.
