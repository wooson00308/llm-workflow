결정권자 검토 화면의 가독성을 높인다. 현재는 결정권자 요약 절을 원문에서 분리해 기본으로 보여 주고 원문 전문을 토글 뒤에 두는 기능까지 구현돼 있지만, 요약도 일반 Markdown 본문과 같은 렌더러와 타이포그래피를 사용한다. 결정할 내용, 승인 시 변화, 유지되는 것과 위험이 한 문단 안에 이어지면 요약 분량이 짧아도 빠르게 훑기 어렵다.

Markdown을 HTML로 바꾸는 데 LLM을 사용하지 않는 방향은 타당하다. 다만 앱은 이미 react-markdown으로 Markdown을 브라우저에서 HTML 요소로 변환하므로, 별도 HTML 파일을 생성·저장하는 도구를 추가할 필요는 없다. 저장 HTML을 정본과 함께 두면 두 파일의 내용이 어긋나고, 테마·반응형·접근성 변경 때 생성물을 다시 만드는 비용이 생긴다. 문서가 넣은 raw HTML을 허용하면 보안 경계도 넓어진다.

제안은 Markdown을 유일한 정본으로 유지하고, 결정권자 요약만 고정된 구조로 작성한 뒤 앱이 전용 템플릿으로 결정적으로 렌더링하는 것이다. 이 변환에는 네트워크나 LLM 호출이 없으므로 토큰 비용도 없다. 목표는 글을 보기 좋게 다시 배치하는 데 그치지 않는다. 사용자가 긴 문장을 읽기 전에 화면의 형태만 보고 "지금 이런 문제가 있고, 이렇게 바꾸려 하며, 승인하면 이 결과를 얻는구나"를 이해하는 결정 보드를 만든다.

새 요약 형식의 후보는 다음과 같다. 화면은 이 값을 모두 본문처럼 세로로 늘어놓지 않고, 고정된 시각 문법으로 바꾼다.

- 한 줄 제안: 이 기획의 정체성을 한 문장으로 표현한 값.
- 현재: 사용자가 지금 겪는 문제 또는 제약.
- 변경 후: 승인하면 제품이나 운영 방식이 어떻게 달라지는지.
- 사용자 결과: 변경 뒤 사용자가 직접 얻는 가치.
- 영향 범위: 바뀌는 영역과 바뀌지 않는 영역을 구분하는 짧은 표식.
- 비용·위험: 범위, 마이그레이션, 호환성, 운영 부담처럼 결정 전에 알아야 할 값.
- 결정 요청: 사용자가 지금 승인하거나 수정할 핵심 선택.

전용 화면의 첫 모습은 다음 계층을 갖는다.

1. 위쪽에는 한 줄 제안과 현재 상태를 나타내는 상태 표식을 둔다.
2. 가운데에는 "현재 → 변경 후 → 사용자 결과" 세 단계를 아이콘과 방향으로 연결해 보여 준다. 긴 설명이 아니라 각 단계의 핵심 문장 하나만 사용한다.
3. 그 아래에는 영향 범위를 칩이나 작은 묶음으로 보여 주어 어떤 영역이 움직이고 어떤 영역이 그대로인지 한눈에 구분한다.
4. 비용·위험은 경고 영역으로 분리하되, 위험이 없으면 빈 영역을 만들지 않는다. 색상만으로 의미를 전달하지 않고 제목·아이콘·문장을 함께 사용한다.
5. 마지막에는 사용자가 지금 내려야 하는 결정과 승인·수정 요청·폐기 조작을 같은 시야 안에 둔다.

문서마다 임의의 차트나 그림을 생성하지 않는다. 고정된 현재·변경·결과 흐름, 영향 범위, 위험 표식만 사용해야 여러 기획서를 빠르게 넘겨 봐도 같은 위치에서 같은 의미를 찾을 수 있다. 시각 요소는 장식이 아니라 Markdown의 구조화된 필드를 표현하는 문법이다.

앱은 위 라벨을 임의의 문장 분석으로 추측하지 않고 계약이 정한 정확한 Markdown 구조만 읽는다. 구조가 있는 새 문서는 네 영역을 카드, 정의 목록 또는 비교 레이아웃으로 보여 주고, 기존처럼 평문 요약만 있는 문서는 지금 Markdown 화면으로 폴백한다. 기존 문서를 소급 변경하지 않으며 원문 전문 토글도 유지한다.

화면에서는 다음 가독성 요소를 함께 검토한다.

- 결정 요청을 문서 제목 아래 가장 먼저 보이는 강조 영역으로 둔다.
- 현재와 변경 후를 방향이 있는 비교로 보여 주고, 사용자 결과를 그 흐름의 종착점으로 강조한다.
- 바뀌는 영역과 바뀌지 않는 영역을 영향 범위 표식으로 분리한다.
- 비용·위험이 없더라도 빈 카드를 만들지 않고, 값이 있으면 승인 조작 가까이에 표시한다.
- 본문 글자 크기와 행 길이를 결정권자 화면에 맞게 조정한다. 현재 일반 Markdown 본문의 12픽셀 스타일을 그대로 재사용하지 않는다.
- 작은 창에서는 한 열로 자연스럽게 쌓이고, 키보드·스크린 리더에서도 읽기 순서가 유지된다.
- 상태, 파생 작업 수, 결정 이력과 요약 카드가 같은 사실을 중복해 말하지 않게 한다.
- 아이콘이나 색을 제거해도 제목과 문장만으로 같은 의미가 유지되게 한다.

HTML 내보내기가 필요하다면 저장 정본으로 만들지 않고 같은 렌더러에서 인쇄·공유용 HTML을 일회성으로 생성하는 기능으로 분리한다. 첫 범위는 앱 안의 결정권자 화면 가독성 개선이며, 외부 공유와 PDF 내보내기는 수요가 확인된 뒤 검토한다.

기획 단계에서 정할 것은 구조화 Markdown의 정확한 문법, 기존 결정권자 요약 계약과의 호환 방식, 기획서·개발 작업·보고서 중 적용할 문서 종류, 고정된 "현재 → 변경 후 → 사용자 결과" 시각 문법, 영향 범위 표식, 작은 화면과 접근성 기준이다. SPEC-038과 SPEC-039가 만든 요약 절·원문 토글·무요약 폴백은 기반으로 유지하고, 이 아이디어는 그 위에 한눈에 이해하는 정보 구조와 표현 계층을 추가한다.
