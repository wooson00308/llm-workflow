연동 카드에서 하트비트 데몬을 켜고 끌 수 있게 하자. 지금 데몬 정지·재가동은 사용자가 터미널에서 launchctl을 직접 치는 수동 절차다.

실측된 페인이다. 커밋 컷 절차가 "데몬 정지 → 게이트 실측 → 커밋 → 재가동"을 요구해서(2026-08-04·08-05 두 컷 모두), 사용자가 매번 `launchctl bootout gui/501/com.catze.dream-heartbeat`와 `launchctl bootstrap gui/501 ~/Library/LaunchAgents/...plist`를 손으로 쳤다. 08-05 컷에서는 정지 타이밍을 놓쳐 세션 여러 개가 더 뜬 채 밤새 돌았고, 그중 하나(TASK-104)가 도중에 죽어 고아가 됐다.

선례와 재료:
1. 앱이 데몬 명령을 실행하는 길은 SPEC-020의 "지금 실행"이 이미 열었다. 원클릭 실행형 기능의 신중선(SPEC-024 확인 필요 3번 계열)은 "판정"과 "대행"에 대한 것이었고, 서비스 켜고 끄기는 사용자가 지금도 손으로 하는 행위의 버튼화다.
2. 서비스 감지·상태 표시는 연동 카드에 이미 있다(설치 여부·실행 기록). launchd 라벨 감지 코드와 실설치 라벨(com.catze.dream-heartbeat)의 불일치가 2026-08-04 검수에서 지적된 적 있으므로(앱이 미등록으로 오판), 토글이 쓰는 라벨 원천을 그 지적과 함께 재확인해야 한다.
3. 데몬 plist는 KeepAlive라 프로세스 kill로는 안 꺼진다. 끄기는 bootout, 켜기는 bootstrap 단위여야 한다.

기획 판단이 필요한 자리:
- 끄기 직전 라이브 세션 표시. 활동 뷰가 lease를 이미 보여주므로(SPEC-011), "지금 끄면 세션 N개가 중단됩니다" 류의 고지가 가능하다. 08-05의 TASK-104 고아 사례가 이 고지의 가치를 보여준다. 강제 종료할지, 드레이닝을 기다릴지, 고지만 할지는 기획 몫.
- 플랫폼 경계. launchctl은 macOS뿐이다. SPEC-034가 "macOS 밖은 앱이 방법을 알지 못한다"로 말한 선례를 따르면 된다.
- 데몬 쪽 선행 없음(launchctl 직접 실행으로 성립). 단, 끄고 켜는 행위가 데몬 코드-프로세스 불일치(08-05 체크아웃 사건)와 만나는 지점은 업데이트 기능(IDEA-A44C6F75) 쪽 몫이다.

등록 경위: 2026-08-05(KST) TL 세션에서 사용자 지시로 등록. 사용자 원문 취지 — "하트비트 자체를 키고 끄는 기능을 넣으면 좋을 것 같다".
