연동 카드가 하트비트 데몬의 업데이트 필요를 알려주고 갱신 방법을 안내하게 하자.

배경 사실: 앱은 Tauri 업데이터로 자동 갱신되지만 하트비트 데몬은 자동 업데이트 채널이 없다(현재는 git pull + launchctl 재시작 수동 절차). 그래서 앱-데몬 버전 스큐가 구조적으로 생긴다. 지금 그 스큐의 신호는 TASK-084의 "실행 기록 없음" 경고 하나인데, 이것은 사후적·간접적이다 — 잡이 안 돌고 나서야 뜨고, 문구가 "하트비트를 갱신하세요"라고 말하면서 무엇을 어떻게 갱신하는지는 앱 어디에도 없다.

제안(앱 화면 몫만):
1. 연동 카드에 데몬 갱신 안내를 둔다 — 최소한 084 경고가 뜬 자리에서 갱신 절차(또는 명령)를 보여주고 복사할 수 있게. 실행 실패 표시의 명령 복사 경로(SPEC-020 R6)가 같은 꼴의 선례다.
2. 가능하면 "업데이트 필요" 상태의 선제 표시 — 단, 여기 긴장이 하나 있다. 설치 판정에 데몬 버전을 쓰는 안은 SPEC-024 확인 필요 3번에서 부결됐다(버전 문자열은 거짓말할 수 있다는 이유). 그 결정은 "판정"에 대한 것이고 "정보 표시"는 별개일 수 있으나, 같은 논거가 적용되는지가 이 기획서의 첫 확인 필요다. 버전 원천 후보: `heartbeat --version` 실행(앱이 데몬 명령을 실행하는 선례는 SPEC-020의 "지금 실행"으로 이미 생겼다), 또는 state.json에 데몬이 자기 버전을 적게 하는 계약 확장(데몬 저장소 몫).
3. 앱이 갱신을 대신 실행하는 것은 신중히 — "앱이 heartbeat migrate를 대신 실행하지 않는다"(SPEC-024 R5)는 같은 계열의 부결 선례가 있다. 1차 범위는 표시·안내·복사까지가 안전하고, 실행 버튼은 확인 필요로 올리는 편이 맞다.

범위 밖: 데몬 쪽 배포 채널(brew/pip, `heartbeat update` 명령 등)과 자동 업데이트 구현 — claude-heartbeat 저장소 프로덕트화 백로그(2026-08-03 사용자 결정, docs/planning/2026-08-04-productization.md).
