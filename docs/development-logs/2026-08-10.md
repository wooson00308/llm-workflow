# 2026-08-10 개발 기록

## blocked 에이전트 복구 경로와 대형 프로젝트 조회 병목 직접 수리

- 범위: 사용자의 직접 수정 지시에 따라 새 idea/spec/task를 만들지 않고 기존 blocked 분류·수동 재개 구현을 이어서 완성했다.
- 결정: `definition_error`는 architect의 `blocked_task`, 나머지 분류와 미분류 blocked는 developer 대상으로 라우팅한다. 기존 사용자 revision request가 있으면 호환을 위해 먼저 처리하고, lease·선행·scope 겹침 판정은 그대로 적용한다.
- 결정: blocked 상세의 사용자 해결 근거 입력과 재개 버튼을 제거하고 에이전트 처리 안내로 바꿨다. 백엔드 `task-resume@1` API와 과거 `resumed` 사건 표시는 기존 기록 호환을 위해 유지했다.
- 성능: 프로젝트 조회가 task마다 모든 decision YAML을 다시 읽던 구조를 workflow당 한 번의 revision-request 스캔과 task graph join으로 바꿨다. 큰 저장소에서 작업 수×결정 수로 늘던 읽기가 작업 수+결정 수로 줄었다.
- 관리 자산: 공통 규칙 v21, architect/developer v15, 조건 스크립트 v15로 올리고 제품 원본과 이 프로젝트의 설치 사본을 같은 바이트로 맞췄다.
- 변경 영역: Rust 저장소·역할 판정·sh/PowerShell 조건 스크립트·관리 자산, blocked 상세에서 최상위 App까지의 프런트 배선과 관련 검사.
- 검증: `cargo test --lib` 701건, `cargo clippy --lib --tests -- -D warnings`, `npm run check` 902건과 typecheck/build, 변경 Rust 파일 rustfmt, `git diff --check`, 설치된 sh 구문 검사가 통과했다.
- 확인: 실제 설치 사본에서 architect는 대기 대상 없음, developer는 `TASK-S051-11`과 `TASK-S055-04`를 후보로 반환했다. 앱 GUI 재실행 성능 체감 확인은 앱을 닫아 둔 사용자 상황을 보존해 수행하지 않았다.
- 후속: TASK-S055-04는 현재 정책과 충돌하는 “사용자 재개 조작 유지” 조건을 그대로 구현하지 않는다. 기존 11개 값 경로와 저장·사건 구현을 재사용하되 최신 blocked 정책을 기준으로 남은 정의 수정 요청 UI만 이어서 구현해야 한다.

## 에이전트 화면을 작업 중심 정보 구조로 재설계

- 범위: 사용자 지시에 따라 새 workflow 작업·결정·lease 없이 에이전트 화면 UX를 직접 개선했다.
- 레퍼런스: GitHub Actions의 실행 요약→작업 상세 구조, Cursor Background Agents·GitHub Copilot Agents·Devin의 세션 중심 탐색을 비교했다. 공통점인 “실행 중인 작업을 첫 객체로 두고 설정·로그는 단계적으로 연다”를 이 앱의 로컬 역할 정책 계약에 맞게 적용했다.
- 결정: 기본 화면을 `작업`으로 두고 새 작업 시작, 진행·최근 세션, 새 배정 제어만 남겼다. 역할 정책, 실행 도구 상태, 기존 설정 가져오기는 `설정` 탭으로 분리했다.
- 결정: 실행 기록이 없을 때 4개의 0 통계와 8열 역할 표를 그리지 않고 안내 하나만 보여준다. 기록이 생긴 경우에만 실행·대기 요약과 세션 카드를 노출한다.
- 결정: 역할 정책은 세 폼을 동시에 펼치지 않고 역할 탭에서 하나씩 편집한다. 프로젝트·기기 동시 실행 한도는 별도 짧은 영역으로 묶고 기존 이중 저장 확인과 런타임 계약은 유지했다.

- 문구: 준비 완료 상태에는 확인된 버전 사실만 표시한다. 실행·앱 번들 값이 없을 때 `확인 불가`를 실패처럼 나열하지 않으며, provider가 0개인 경우도 `0개 도구 준비됨` 대신 `진단 기록 없음`으로 구분한다.
- 변경 영역: `AgentRuntimeView.tsx`, `AgentRunDashboard.tsx`, `AgentRoleSettings.tsx`, Agents CSS, 컴포넌트 회귀 검사.

## 에이전트 최초 설정·자동 실행 준비 UX 직접 개선

- 범위: 사용자의 직접 수정 지시에 따라 새 workflow 작업·결정·lease 없이 에이전트 최초 설정, 실행 준비, 모델 선택, 런타임 오류 표현을 개선했다.
- 최초 설정: 저장된 프로젝트 정책이 없을 때 `plan.read`를 호출하지 않는다. 내부 `project_not_configured` 오류와 빈 큐를 숨기고 기본 설정 확인→저장 한 경로만 안내한다.
- 실행 준비: 사용자가 별도 “시작 가능 여부 확인” 버튼을 누르지 않아도 선택 역할·배정 방식·인원·대상이 바뀌면 읽기 전용 계획을 자동 갱신한다. 화면에서 선택한 한 역할만 요청하도록 고쳐, 세 역할을 함께 보내던 기존 불일치도 제거했다. 실제 provider 시작은 `에이전트 시작` 단일 버튼 전까지 실행되지 않는다.
- 설정: 모델 주관식 입력을 공급자별 선택으로 교체했다. Claude는 기본값과 `opus`·`sonnet`·`haiku`·`fable`, Codex는 기본값과 `gpt-5.6`·`gpt-5.6-terra`·`gpt-5.6-luna`를 제공한다. 기존 목록 밖 저장값은 읽기 손실 없이 현재 값으로 보존한다. 설정 저장은 변경이 있을 때 한 번만 누르며, 미변경 저장은 비활성화한다.
- 오류 계약: 런타임이 stderr로 보낸 구조화 실패 봉투를 `OffContract`로 오분류하던 판독을 수정했다. `project_not_configured`는 “아직 설정이 없음” 안내로 변환하고, 정말 파싱할 수 없는 응답만 원문을 보존하는 계약 밖 오류로 남긴다.
- 정보 구조: 실행 준비에서 내부 project id·원시 만료 시각·6열 표를 제거하고 역할별 시작 수·대상·제외 사유와 프로젝트/기기 여유만 카드로 보여준다. 계획 취소 버튼도 제거해 편집→자동 재계획→최종 시작 한 흐름으로 줄였다.
- 반응형: 창 전체가 아니라 에이전트 본문 폭을 기준으로 정책 폼이 4열→2열→1열로 바뀌도록 container query를 추가했다. 940px 최소 창에서 모델·실행 방식·인원 필드가 두 줄로 재배치되고 가로 넘침이 없음을 실제 앱에서 확인했다.
- 검증: Agents 집중 검사 58건, 전체 프런트 28파일·917건과 typecheck/production build, Rust 본체 710건, Clippy `-D warnings`, rustfmt, 런타임 계약 검증, `git diff --check`, 최신 debug macOS `.app`·`.dmg` 빌드가 통과했다.
- 시각 확인: 구버전 프로세스를 종료하고 최신 debug 앱을 다시 열었다. 최초 설정 화면에서 원문 오류와 수동 계획 버튼이 사라진 것, 설정 탭의 모델 선택지, 940px 최소 창의 2열 재배치를 확인했다. 정책 저장과 에이전트 실행은 누르지 않았고 앱은 최신 설정 화면에 열어 두었다.
