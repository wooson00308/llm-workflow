# 2026-08-10 개발 기록

## blocked 에이전트 복구 경로와 대형 프로젝트 조회 병목 직접 수리

- 범위: 사용자의 직접 수정 지시에 따라 새 idea/spec/task를 만들지 않고 기존 blocked 분류·수동 재개 구현을 이어서 완성했다.
- 결정: `definition_error`는 architect의 `blocked_task`, 나머지 분류와 미분류 blocked는 developer 대상으로 라우팅한다. 기존 사용자 revision request가 있으면 호환을 위해 먼저 처리하고, lease·선행·scope 겹침 판정은 그대로 적용한다.
- 결정: blocked 상세의 사용자 해결 근거 입력과 재개 버튼을 제거하고 에이전트 처리 안내로 바꿨다. 백엔드 `task-resume@1` API와 과거 `resumed` 사건 표시는 기존 기록 호환을 위해 유지했다.
- 성능: 프로젝트 조회가 task마다 모든 decision YAML을 다시 읽던 구조를 workflow당 한 번의 revision-request 스캔과 task graph join으로 바꿨다. 큰 저장소에서 작업 수×결정 수로 늘던 읽기가 작업 수+결정 수로 줄었다.
- 관리 자산: 공통 규칙 v21, architect/developer v15, 조건 스크립트 v15로 올리고 제품 원본과 이 프로젝트의 설치 사본을 같은 바이트로 맞췄다.
- 변경 영역: Rust 저장소·역할 판정·sh/PowerShell 조건 스크립트·관리 자산, blocked 상세에서 최상위 App까지의 프런트 배선과 관련 검사.
- 검증: `cargo test --lib` 701건, `cargo clippy --lib --tests -- -D warnings`, `npm run check` 902건과 typecheck/build, 변경 Rust 파일 rustfmt, `git diff --check`, 설치된 sh 구문 검사가 통과했다.
- 확인: 실제 설치 사본에서 architect는 대기 대상 없음, developer는 `TASK-S051-11`과 `TASK-S055-04`를 후보로 반환했다. 앱 GUI 재실행 성능 체감 확인은 앱을 닫아 둔 사용자 상황을 보존해 수행하지 않았다.
- 후속: TASK-S055-04는 현재 정책과 충돌하는 “사용자 재개 조작 유지” 조건을 그대로 구현하지 않는다. 기존 11개 값 경로와 저장·사건 구현을 재사용하되 최신 blocked 정책을 기준으로 남은 정의 수정 요청 UI만 이어서 구현해야 한다.

## 개발·QA 보드 정보 구조 직접 개선

- 범위: 사용자 지시에 따라 새 workflow 작업·결정·lease 없이 개발 보드의 기본 UX를 직접 개선했다.
- 결정: QA 작업 카드를 사용자 행동 단위로 쓰지 않는다. 같은 `sourceSpecId`의 작업이 모두 `completed` 또는 `qa_waiting`일 때만 기능 QA 세션 하나를 만들고, `todo`·`in_progress`·`blocked`·규격 밖 상태가 남은 기획서는 사용자 QA에서 숨긴다.
- 결정: 확인 동선이 화면 없음·자동 검사 전용이라고 명시한 작업만 자동 검증 근거로 접는다. 모호한 작업은 직접 확인 단계에 남기며, 기능 확인 완료는 세션에 속한 QA 작업 전체를 기존 batch API 한 번으로 기록한다.
- 결정: 950px 고정 보드를 제거하고 창 너비에 맞춰 열을 재배치한다. 기능 QA 목록과 단계·메모·완료 영역은 콘텐츠 기반 최소 폭을 해제하고 좁은 창에서도 한 흐름으로 읽히게 했다.
- 변경 영역: `DevelopmentBoard.tsx`, 개발 보드 CSS, 컴포넌트·CSS 회귀 검사.
- 검증: 집중 검사 93건, 전체 프런트 28파일·910건, typecheck·production build, 최신 debug macOS 앱 빌드와 1180×760 실제 화면 검사가 통과했다.
- 결과: 현재 QA 10건은 준비된 SPEC-051 기능 세션 1개(직접 확인 4단계·자동 검증 3건)로 보인다. 아직 todo가 남은 SPEC-055는 노출되지 않는다. 1180px 기본 창과 940px 최소 창에서 목록·상세·완료 영역을 직접 검사했고 사용자 QA 기록은 만들지 않았다.
