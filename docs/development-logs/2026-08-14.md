# 2026-08-14 개발 기록

## 핫픽스: 품질 확인 작업대 조작 불가와 스크롤 레이아웃

- 범위: 사용자 지시로 워크플로 밖에서 품질 확인 세션의 버튼 피드백, 고정 요약 겹침, 항목 목록과 결과 조작 배치를 복구한다.
- 보호: `.workflow` 문서와 사용자 QA 결정은 수정하지 않는다. 기존 작업 트리 변경을 보존하고 QA 전용 컴포넌트와 스타일만 수술적으로 수정한다.
- 성공 기준: 항목 결과 버튼의 선택 상태가 즉시 보이고, 스크롤 중 요약이 본문을 덮지 않으며, 목록을 접으면 상세가 전체 폭을 쓰고 결과·항목 이동 조작에 긴 문서를 다시 훑지 않고 접근할 수 있어야 한다.
- 검증: QA 컴포넌트 회귀 테스트, 타입 검사, 프로덕션 빌드, 새 Tauri debug 번들의 실제 스크롤 검수를 수행한다.
- 원인: 결과 버튼의 눌림 상태를 표현하는 스타일이 없었다. 확인함은 선택 전에도 초록색이었고 문제 있음은 눌러도 외형이 바뀌지 않아 조작이 실패한 것처럼 보였다. 세션 요약은 전체 페이지 스크롤에 고정되고 상세 본문은 높이 제한이 없어 요약 겹침과 긴 왕복 스크롤이 함께 발생했다.
- 변경: `QaSessionView.tsx`에서 문제 있음 선택 시 메모로 초점을 옮기고, 항목 전환 시 상세 스크롤을 처음으로 돌린다. 항목 목록은 제목과 상태만 표시하며 접힘 상태를 레이아웃 클래스에 반영했다. 상세의 확인 동선과 보조 정보만 별도 스크롤 영역에 넣었다.
- 변경: `QaWorkbench.css`에서 세션 요약의 고정을 제거하고, 항목 목록과 상세를 제한 높이의 작업대로 만들었다. 결과와 항목 이동은 스크롤 영역 밖에 유지하고, 두 결과 버튼의 선택 상태를 색과 외곽선으로 구분했다. 목록을 접으면 상세가 전체 폭을 쓰며 긴 명령은 줄바꿈한다.
- 검사: QA 회귀 테스트 45건 통과, 전체 프런트 테스트 571건 통과·42건 건너뜀, 타입 검사 통과, 프로덕션 빌드 통과, Tauri debug 앱·DMG 번들 생성 통과.
- 실기 검수: 새 debug 앱에서 QA 세션을 열어 본문과 목록의 독립 스크롤, 결과·메모·이전·다음의 상시 노출, 문제 있음 선택 표시, 목록 접기 후 전체 폭 확장을 확인했다.
- 남은 위험: 980px 이하 반응형은 자동 검사와 빌드로 확인했으며 이번 실기 검수 창에서는 데스크톱 폭만 확인했다. 번들 크기 경고는 기존과 같은 500kB 초과 경고로 이번 핫픽스 범위 밖이다.

## 핫픽스 후속: 품질 확인 UX 정보 구조 정리

- 범위: 사용자 지시로 같은 워크플로 밖 핫픽스를 이어서 진행했다. 대기열, 기능 상세, 항목 목록 펼침·접힘, 항목 전환, 긴 확인 동선, 판정과 하단 진행 영역을 실제 Tauri 앱에서 다시 검수했다.
- 판단: 기능을 열면 긴 확인 범위 문서가 작업대보다 먼저 나타나고, 현재 상태와 안내 라벨이 중복되며, 항목 목록의 순서와 상태를 빠르게 훑기 어려웠다. 비활성 제출 버튼도 활성 주요 행동처럼 보여 다음 행동을 오해하게 했다.
- 변경: 기능 제목과 전체 항목 수만 남긴 압축 헤더를 만들고, 기능 설명과 전체 확인 범위는 기본 접힘 상세로 옮겼다. 세션 진행률 막대, 항목 번호와 상태 배지, 현재 항목 번호·상태, 판정 라벨을 추가하고 목록 폭을 300px로 조정했다.
- 변경: 제출 전 검토 영역을 별도 패널로 묶고, 남은 항목 안내·비활성 제출·임시 검토 버리기의 정렬과 위계를 정리했다. 비활성 제출은 중립색으로 표시한다.
- 검사: QA 회귀 테스트 45건 통과, 전체 프런트 테스트 571건 통과·42건 건너뜀, 타입 검사와 프로덕션 빌드 통과, Tauri debug 앱·DMG 번들 생성 통과, `git diff --check` 통과.
- 실기 검수: 새 debug 앱에서 기능을 열자마자 작업대가 첫 화면에 들어오는지, 범위 상세의 펼침·접힘, 목록·본문 독립 스크롤, 저장된 문제 있음 상태의 붉은 피드백, 하단 비활성 제출 패널을 확인했다. 사용자 임시 검토 값과 `.workflow` 상태는 변경하지 않았다.
- 남은 위험: 최종 제출 화면은 사용자 임시 검토를 인위적으로 채우지 않기 위해 이번 실기 검수에서 열지 않았고, 기존 컴포넌트 회귀 테스트로 확인했다. 번들 크기 경고는 기존과 동일하다.

## 핫픽스: 참조 패턴 기반 품질 확인 레이아웃 재설계

## 핫픽스: 비개발자용 QA와 AI 내부 검증 분리

- 범위: 사용자 QA 작업대에서 터미널 명령과 자동 검사 결과를 판정 대상으로 올리지 않고, 화면을 보며 조작할 수 있는 항목만 남겼다. 사용자 임시 검토와 `.workflow` 상태는 수정하지 않았다.
- 원인: 기존 도메인 계약이 자동 근거 항목도 사용자 목록과 전체 건수에 유지했고, 화면 없는 작업을 가리는 문구 판정도 일부 표현만 알아보았다. 그 결과 `눌러 볼 화면이 없다`, `화면을 바꾸지 않는 것이 성공 기준` 같은 내부 작업이 일반 QA로 분류됐다.
- 변경: 화면이 없거나 터미널·저장소 검증만 요구하는 작업은 사용자 QA 항목과 `내 선택 대기`에서 제외한다. 대기열에는 사용자의 직접 확인 수와 참고용 `AI 내부 검증` 수만 표시한다.
- 변경: 화면 조작형 확인 동선 안에 섞인 `npx`, `npm`, `cargo`, `vitest`, 저장소 경로, 자동 검사 결과와 코드 블록은 렌더링하지 않는다. 기술 문서를 다시 노출하던 작업 원문 보기도 사용자 QA 화면에서 제거했다.
- 변경: `대기열로 돌아가기`를 기능 제목과 같은 행에서 빼고 제목 위 첫 줄에 단독 배치했다.
- 검사: 관련 회귀 테스트 57건, 전체 프런트 테스트 572건 통과·42건 건너뜀, 타입 검사, 프로덕션 빌드, Tauri debug 앱·DMG 번들 생성을 통과했다.
- 실기 검수: 새 debug 앱을 강제 새로 고침한 뒤 대상 기능의 6개 작업이 사용자 항목 4개와 AI 내부 검증 2개로 분리되는 것을 확인했다. 4개 사용자 목록과 현재 확인 동선에 터미널 명령이 없고, 뒤로가기가 제목 위에 놓이는 것도 확인했다.
- 남은 위험: 분류의 정본은 현재 작업 요약의 평문 표현이다. 개발 역할 계약이 구조화된 `사용자 화면 QA`와 `AI 검증` 필드를 제공하기 전까지는 새 표현이 생길 때 판정 문구를 보완해야 한다.

## 핫픽스: 품질 확인 보조 패널 위계와 콘텐츠 레일 통합

- 범위: 기능 설명과 항목 목록의 버튼 위계, 펼침 상태, 패널 폭과 목록 읽기 순서를 정리했다. 사용자 임시 검토와 `.workflow` 상태는 수정하지 않았다.
- 원인: 기능 화면 바깥 셸은 900px인데 문서·진행률·푸터만 760px로 좁혀져 있었고, 나중에 추가한 목록과 기능 설명에는 같은 폭 규칙이 적용되지 않았다. 두 조작도 같은 전역 보조 버튼을 쓰고 서로 다른 컴포넌트에서 독립 상태를 가져 동시에 열릴 수 있었다.
- 변경: 헤더, 기능 설명, 진행률, 항목 목록, 현재 문서, 푸터와 최종 검토를 760px 콘텐츠 레일로 통일했다. 항목 목록은 1열 task list로 바꾸고 상태를 행 오른쪽에 정렬했다.
- 변경: 기능 설명은 제목 아래의 작은 텍스트 disclosure로 낮추고, 항목 목록은 진행률 옆의 컴팩트한 보조 버튼으로 유지했다. 패널 안의 중복 닫기와 반복 건수 안내를 제거했다.
- 변경: 기능 설명과 항목 목록 상태를 기능 범위 컴포넌트 한 곳에서 관리해 둘 중 하나만 열리게 했다. 직접 렌더링되는 세션 검사를 위해 목록 상태는 선택적으로 자체 관리할 수 있게 유지했다.
- 검사: 관련 회귀 테스트 58건, 전체 프런트 테스트 573건 통과·42건 건너뜀, 타입 검사, 프로덕션 빌드, Tauri debug 앱·DMG 번들 생성을 통과했다.
- 실기 검수: 새 debug 앱에서 기본 화면, 760px 단일 열 목록, 기능 설명 패널을 확인했다. 목록과 현재 문서의 좌우선이 일치하고 기능 설명을 열면 목록이 즉시 닫히며, 기능 설명을 닫으면 기본 집중 화면으로 돌아오는 것을 확인했다.
- 남은 위험: 기능 설명과 현재 문서는 각각 내부 스크롤을 가지므로 좁은 창의 실제 체감은 별도 반응형 실기 검수가 한 번 더 필요하다. 기존 500kB 초과 번들 경고는 이번 핫픽스 범위 밖이다.

## 구조 개편: 작업 그룹 중심 워크플로우 v2

- 범위: 사용자 승인 단위를 개발 태스크에서 승인된 기획서의 작업 그룹으로 옮기고, 태스크 완료를 AI 자동검증 상태로 분리한다.
- 보호: 기존 QA 핫픽스와 에이전트 런타임 관련 작업 트리 변경, 실제 `.workflow` 문서와 사용자 결정 기록을 보존한다. 제품 코드와 제공 규칙만 변경한다.
- 핵심 결정: 그룹 QA 시나리오는 아키텍트가 작성하며, 반려는 기존 태스크 일괄 롤백이 아니라 새 수정 태스크 분해로 처리한다. 프로젝트는 백업 가능한 스키마 v2 마이그레이션으로 일괄 전환한다.
- 성공 기준: 그룹 준비·개발·자동검증·사용자 QA·반려 재분류 상태가 한 정본에서 파생되고, 사용자 QA에는 비개발자용 그룹 시나리오만 나타나며, Rust·역할 스크립트·프런트 판정과 실제 Tauri 화면이 일치해야 한다.
- 구현: `groups/`와 `workflow-labs/work-group@1`, `group-qa-decision@1` 계약을 추가하고 태스크 상태를 `todo | in_progress | blocked | verified`로 제한했다. 그룹 표시 상태는 승인·반려·준비·막힘·개발·사용자 QA·자동검증·구성 오류 순으로 한 곳에서 파생한다.
- 구현: 그룹 QA 제출은 revision·updated_at·시나리오 집합·사용자 모드·전체 태스크 verified를 재검사하고 결정 문서 하나만 원자 기록한다. request_id 재시도는 기존 결정을 반환하며 태스크 상태는 변경하지 않는다.
- 구현: v1 프로젝트를 결정→기획서→태스크 기준의 결정적 그룹으로 변환하고, 기존 QA 감사 기록을 보존한다. 프로젝트·워크플로 문서와 관리 규칙·역할·예약 헬퍼를 하나의 잠금·백업·복구 경계에서 v2로 전환한다.
- 구현: 아키텍트는 그룹 반려→태스크 정의 수정→중단된 preparing 복구→신규 승인 분해 순으로 작업한다. 개발자는 최신 승인 쌍과 active 그룹의 원천·revision이 맞는 태스크만 선점하고 자동검증 뒤 verified로 끝낸다. Rust·POSIX·PowerShell 판정 계약을 같은 fixture로 맞췄다.
- 구현: 개발 화면은 작업 그룹 보드를 기본값으로 사용하고 평면 태스크 보기를 보조 전환으로 남겼다. 태스크 상세은 AI 자동검증 상태와 유효한 소속 그룹만 보여주며 원문·터미널·의존·겹침·사용자 도장을 제거했다.
- 구현: 품질 확인은 backend `workGroups`의 비개발자용 시나리오만 사용한다. 임시 저장 키는 workflow+group+revision+scenario로 격리하고, 기능 설명과 항목 목록은 서로 배타적인 disclosure로 유지한다. 워크플로 전환 시 QA와 태스크 상세 상태도 함께 격리한다.
- 안전성: 사용자 QA 문장은 화면·행동·가시 결과를 모두 요구하고 제목과 본문에서 CLI 지시를 차단한다. `켜고 저장`, `다른 화면에서 돌아오기`, `그대로 보여야/선택되어야` 같은 자연스러운 한국어는 허용하고 `docker compose`, `curl`, `npx`, `cargo` 등 내부 절차는 거절하는 회귀를 고정했다.
- 자동 검사: 프런트 29개 파일 480건 통과·42건 건너뜀, 타입 검사와 프로덕션 빌드 통과. Rust 단위 782건과 런타임 E2E 20건 통과, `cargo fmt --check`, `git diff --check` 통과. Tauri debug `.app` 번들 생성까지 통과했다.
