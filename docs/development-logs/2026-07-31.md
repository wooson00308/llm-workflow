## v0.1.1 공개 배포 복구

- 범위: 실패한 첫 태그 릴리스를 진단하고 기존 앱 updater가 접근할 수 있는 공개 릴리스를 만든다.
- 결정: 사용자 승인에 따라 저장소를 public으로 전환해 기존 GitHub Releases updater endpoint를 유지한다.
- 원인: macOS job은 잘못된 Developer ID 인증서를 keychain에 import하는 단계에서 실패했다. 로컬에 대체 인증서가 없어 첫 배포는 Tauri updater 서명만 적용한 unsigned macOS 번들로 진행한다.
- 변경: Apple 코드 서명 환경 변수 주입을 제거하고 앱 버전을 `0.1.1`로 올렸다.
- 검증: `GITHUB_REF_NAME=v0.1.1 npm run release:verify`, 프런트엔드 검사 10개, production build, Rust 포맷·Clippy·테스트 20개를 통과했다.
- 배포: PR #2를 CI 4개 통과 후 병합하고 `v0.1.1` 태그를 생성했다. 릴리스 Actions의 Linux, Windows, macOS job이 모두 성공해 공개 릴리스를 게시했다.
- 배포 검증: 공개 `latest.json`이 HTTP 200과 버전 `0.1.1`을 반환하고, 11개 플랫폼 매핑과 모든 updater 서명이 존재한다. macOS DMG의 앱 버전은 `0.1.1`, 실행 파일은 x86_64/arm64 universal이다.
- 링크: [Workflow Labs v0.1.1](https://github.com/wooson00308/workflow-labs/releases/tag/v0.1.1), [릴리스 실행](https://github.com/wooson00308/workflow-labs/actions/runs/30558043868)
- 위험: macOS 번들은 ad-hoc 서명 상태여서 신규 설치 시 Gatekeeper 경고가 나타날 수 있다. 정식 배포 전 Developer ID 서명과 notarization 복구가 필요하다.

## 개발 작업 다중 뷰

- 범위: 개발 작업에 공통 검색·상태 필터와 보드·리스트·월간 캘린더 전환을 추가한다.
- 결정: 캘린더는 수정 시각을 일정으로 오해하지 않도록 선택적 `due_at: YYYY-MM-DD`를 사용하고, 날짜가 없는 작업은 일정 미지정으로 분리한다.
- 결정: 개발 화면은 흐름에 집중하도록 완료 작업을 최근 3개만 보여주고, 기록 화면에는 전체 완료 이력을 유지한다.
- 변경: 작업 제목·ID·본문 검색과 상태 필터를 세 뷰에 공통 적용하고 필터 초기화, 월 이동·오늘 이동, 일정 미지정 목록을 구현했다. 전체 이력 화면의 명칭은 역할에 맞게 `보관함`에서 `기록`으로 바꿨다.
- 계약: Rust 요약 파서와 TypeScript 모델, 신규 워크플로우 README·에이전트 규칙·파일 계약에 선택적 `due_at`을 연결했다.
- 검증: 프런트엔드 테스트 14개와 production build, Rust 포맷·Clippy·테스트 21개를 통과했다. 로컬 브라우저에서 보드·리스트·캘린더 레이아웃과 콘솔 오류 없음도 확인했다.
- 유의: 기존 작업에는 `due_at`이 없으므로 캘린더의 일정 미지정 영역에 표시된다. 날짜는 Markdown frontmatter에서 관리한다.
