- 링크: [Workflow Labs v0.1.1](https://github.com/wooson00308/workflow-labs/releases/tag/v0.1.1), [릴리스 실행](https://github.com/wooson00308/workflow-labs/actions/runs/30558043868)

## 개발 작업 다중 뷰

- 범위: 개발 작업에 공통 검색·상태 필터와 보드·리스트·월간 캘린더 전환을 추가한다.
- 결정: 캘린더는 수정 시각을 일정으로 오해하지 않도록 선택적 `due_at: YYYY-MM-DD`를 사용하고, 날짜가 없는 작업은 일정 미지정으로 분리한다.
- 결정: 개발 화면은 흐름에 집중하도록 완료 작업을 최근 3개만 보여주고, 기록 화면에는 전체 완료 이력을 유지한다.
- 변경: 작업 제목·ID·본문 검색과 상태 필터를 세 뷰에 공통 적용하고 필터 초기화, 월 이동·오늘 이동, 일정 미지정 목록을 구현했다. 전체 이력 화면의 명칭은 역할에 맞게 `보관함`에서 `기록`으로 바꿨다.
- 계약: Rust 요약 파서와 TypeScript 모델, 신규 워크플로우 README·에이전트 규칙·파일 계약에 선택적 `due_at`을 연결했다.
- 검증: 프런트엔드 테스트 14개와 production build, Rust 포맷·Clippy·테스트 21개를 통과했다. 로컬 브라우저에서 보드·리스트·캘린더 레이아웃과 콘솔 오류 없음도 확인했다.
- 유의: 기존 작업에는 `due_at`이 없으므로 캘린더의 일정 미지정 영역에 표시된다. 날짜는 Markdown frontmatter에서 관리한다.

## 상단 도구·설정 및 브랜드 정비

- 범위: 상단 새로고침과 프로젝트 검색, 사이드바 설정을 실제 상호작용으로 연결하고 오늘 화면의 단계 안내 영역을 정리한다. 정식 제품명과 앱 아이콘도 함께 검토한다.
- 결정: 프로젝트 검색은 현재 프로젝트의 모든 워크플로우에서 아이디어·기획서·개발 작업을 찾는 `⌘/Ctrl+K` 검색으로 구현한다.
- 결정: 설정은 아직 존재하지 않는 환경설정을 가장하지 않고, 앱 업데이트·프로젝트 경로·문서 호환성·파일 감시 상태를 확인하고 프로젝트를 전환하는 화면으로 구성한다.
- 변경: 새로고침 아이콘을 단순한 원형 화살표로 교체하고 실행 중 회전·비활성화 피드백을 추가했다. 단계 안내는 별도 칸 대신 `단계 카드를 선택해 전용 화면으로 이동`하는 작은 안내 칩으로 정리했다.
- 변경: 아이디어·기획서·개발 작업을 통합 검색해 해당 전용 화면으로 이동하는 검색 대화상자와 실제 설정 화면을 추가했다.
- 브랜드 검토: 기존 `Workflow Labs`와 `LLMflow`의 동명 서비스 충돌을 확인했다. 최종 제품명은 역할이 명확하고 검색 충돌을 줄이는 `LLM Workflow`, 저장소명은 `llm-workflow`로 정하고 4단계 노드형 A 아이콘을 적용한다.
- 검증: 프런트엔드 테스트 17개, 타입 검사, production build, `git diff --check`를 통과했다. 로컬 브라우저에서 새로고침 진행 상태, 검색 결과 이동, 설정 화면, 반응형 단계 안내를 직접 확인했다.

## LLM Workflow v0.1.3

- 범위: 앱 브랜드와 아이콘을 확정하고, 기획서 수정 요청부터 개발 작업 상세·사용자 QA까지 이어지는 결정 흐름을 완성해 `v0.1.3`으로 배포한다.
- 결정: 기획자·PA·개발자를 별도 역할 계약으로 생성하고 각 세션은 한 역할과 한 작업만 수행하도록 제한한다. 자동 스케줄링은 이번 범위에서 제외한다.
- 변경: 기획서에 `수정 요청` 결정을 추가하고, 개발 작업 전체를 상세 화면으로 연결했다. QA 대기 작업에서는 테스트 플로우를 입력해 `확인 완료` 또는 `수정 요청`을 기록하며, 수정 요청은 작업을 개발 준비 상태로 되돌린다.
- 변경: 상단 새로고침·통합 프로젝트 검색·설정 화면을 실제 동작으로 연결하고, 작은 라벨의 최소 글자 크기를 11px 이상으로 높였다. 제품명·패키지명·아이콘은 `LLM Workflow` 기준으로 교체하되 기존 updater와 파일 스키마 식별자는 호환성을 위해 유지했다.
- 검증: 프런트엔드 테스트 21개와 production build, Rust 포맷·Clippy·테스트 26개를 통과했다. 로컬 브라우저에서 보드·리스트·캘린더의 상세 진입, QA 메모 필수 조건, 수정 요청 복귀와 글자 크기 레이아웃을 확인했다.
- 후속: GitHub 저장소를 `llm-workflow`로 변경하고 `v0.1.3` 릴리스 산출물과 기존 updater URL 리디렉션을 확인한다.
