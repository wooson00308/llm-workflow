  - 이력 파싱은 전부 관대하게. `history`가 없거나, 시퀀스가 아니거나, 항목의 `at`·`kind`가 계약과 어긋나면 그 항목만 버리고 읽기는 성공한다. `read_markdown_summaries`가 `Err`인 문서를 통째로 건너뛰므로, 파싱 실패를 오류로 만들면 작업이 목록에서 사라진다.

  - `events`는 `Vec`(항상 존재), TypeScript는 `events?`(선택). 후자 덕분에 기존 프론트엔드 테스트 픽스처를 한 줄도 고치지 않았다.

- 1건 — 하트비트 카드 설치 가이드(마법사)를 접고 펼 수 있게: 머리 줄("설치 가이드 · 필수 단계 N/3 완료" + 토글 버튼) 신설, 본문은 `hidden` 토글(언마운트 대신 — 복사 표시 등 화면 상태 보존). TASK-020 카드 접기 idiom(aria-expanded·aria-controls) 재사용, 기본 펼침, 렌더 조건·대행 안 함 문구·자동 재감지·R11(실행 버튼 금지) 무변경. 요약이 확인 불가(unknown)를 완료로도 남은 일로도 세지 않는다(SPEC-016 R4 준수).
- 2건 — 한도 "제한 없음" 선택 시 드롭다운이 가로로 늘어나는 문제: 사용자 진단(아래 안내 문구의 길이가 폭을 민다)이 실측으로 확인됐다 — 헤드리스 Chrome 재현에서 select 폭 444px(제한 없음) vs 141px(한도 지정). App.css 2줄로 수정(`.heartbeat-job-field`에 `max-width: 240px`, select에 `align-self: flex-start`) → 두 모드 모두 72px 동일. 역할 잡·dream 잡 폼이 공용 `MaxPerField.tsx`를 쓰므로 한 번에 양쪽 해결(작업 전 TL 전제 "두 카드는 코드 비공유"는 이 폼에 한해 틀렸음이 확인됨). 같은 규칙이 ModelField의 "직접 입력" 증상도 함께 잡았다.
- 테스트: 버튼 목록 단정 정당 갱신(토글 1 + 복사 4, R11 성질은 오히려 확장) + 접기 신규 3건. 삭제·약화 없음.
- 게이트(에이전트 보고 수치): npm run check — tsc 통과, vitest 334/334 (직전 331 + 신규 3), 빌드 성공. 백엔드 무변경이라 cargo 생략.
- 사용자 확인 포인트: (1) 가이드 접기/펼치기·접힘 유지, (2) "제한 없음" 드롭다운 폭, (3) "한도 지정" 드롭다운도 함께 좁아진 부수 효과(어색하면 select 규칙 한 줄만 빼서 되돌림 가능). 리스크: 접힘 상태에선 대행 안 함 문구가 안 보인다 — R11 해석상 문제되면 머리 줄로 승격 필요.
