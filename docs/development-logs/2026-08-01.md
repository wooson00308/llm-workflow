# 2026-08-01 개발 로그

## 병렬 세션 선점(claim-first) 프로토콜과 아이디어 채택 표시

- 범위: 병렬 LLM 세션이 같은 아이디어·기획서·작업을 동시에 잡는 레이스를 막기 위해 "작업 전 선점 마킹"을 계약으로 강제한다. 아이디어 인박스에는 기획서로 채택된 아이디어 표시를 추가한다.
- 결정: lease 파일명을 대상 문서 id(`leases/<문서-id>.yml`)로 통일하고 배타적 생성으로 클레임한다. 파일시스템 원자성으로 동시 선점 중 한쪽은 반드시 실패한다. 선점 직후 기획서는 `draft` 스켈레톤, 작업은 `in_progress`를 먼저 기록한 뒤 실작업을 시작한다.
- 결정: 기획서 frontmatter에 `source_idea_id`를 도입해 출처 아이디어를 참조한다. 미처리 아이디어 판정 기준이자 채택 표시의 근거다. 앱은 파일을 바꾸지 않고 읽기 시점에 `adopted` 상태를 파생한다.
- 변경: `project_instructions.rs` 공통 규칙 v3(섹션 4를 클레임 프로토콜로 재작성)과 역할 계약 v2(기획자·아키텍트·개발자 각 Claim first 섹션) — 기존 프로젝트는 다음 결정 시 자동 갱신된다. `fs_project_repository.rs`에 `adopted_idea_ids` 파생 로직, `IdeaInbox`에 채택 아이콘·태그·미리보기 pill, `docs/file-contract.md` 동기화.
- 검증: 프런트 테스트 26개, Rust 테스트 27개(채택 파생 테스트 신설), fmt·clippy 통과.
- 후속: lease 만료 교체(만료 lease 삭제 후 재생성) 구간은 원자적이지 않음 — 실사용에서 문제 되면 앱 중재 클레임 검토.
